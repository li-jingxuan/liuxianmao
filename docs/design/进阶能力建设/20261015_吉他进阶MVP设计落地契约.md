# 吉他进阶 MVP 设计落地契约

日期：2026-10-15；实施验收更新：2026-10-16。范围：吉他进阶独立 MVP 的界面、状态、交互入口和实现边界。

## 1. 设计结论

本轮设计围绕一条可验收的学习闭环展开：

> 学习路径 → 理论小节 → 练习作答 → 综合考试 → 结果反馈 → 错题复习

设计模块与现有曲谱编辑器并列，不替换编辑器首页，也不把课程功能塞入编辑器属性侧栏。学习模块以自己的布局、导航和进度状态为主；曲谱能力只作为理论/练习中的只读谱例使用。

本次实现先落地 MVP v1：学习路径、一个开放模块、一节理论和一个单选练习。综合考试、考试结果、错题复习和完整进度页虽然已有设计稿，但属于后续路线，不作为 v1 验收条件。

## 3. 状态和组件契约

### 3.1 学习路径

- 总览必须显示总体进度、四个模块状态和继续学习入口。
- 模块状态至少包含“未开始、学习中、已完成”；未开始模块不使用不可解释的灰色锁死。
- 阶段考试在四个模块完成前显示前置条件，明确列出未完成模块。
- 继续学习根据最近一次未完成理论/练习定位，不能只跳回固定首页。

### 3.2 理论学习

- 理论页必须同时展示学习目标、核心概念、谱例、易错点。
- 谱例区域为只读；从谱例进入编辑器属于后续能力，不在 MVP 设计范围内。
- “完成本节”是明确主操作；完成后提供下一节或进入练习。
- 内容较长时，正文滚动，标题和返回路径保持可见。

### 3.3 练习作答

- 题目容器需要展示模块、题号/练习进度、题干和作答区。
- 用户未提交前可修改答案；提交后锁定本题答案，展示正确/错误、正确答案和解析。
- 错误反馈不只显示“答错”，必须关联理论小节或复习动作。
- 练习允许重新练习，不清除历史完成状态。

### 3.4 综合考试

- 考试共 12 题，顶部显示完成数、剩余数和当前题号。
- 题号导航区分已答、当前、未答，不以颜色作为唯一语义。
- 退出考试前需要保留暂存状态，并明确“继续考试”入口。
- 提交前未答题必须有提示；提交后不允许静默修改本次答卷。

### 3.5 结果与进度

- 结果页同时显示总分、及格线、通过状态、模块分数、最近一次和最好成绩。
- 错题按知识模块归类，至少展示题目、用户答案、正确答案、解析和进入复习动作。
- 进度页需要区分理论完成、练习完成和考试成绩，不能用一个百分比掩盖不同状态。
- 本地持久化异常使用错误提示和重试/重置入口；不得把异常状态显示成空白进度。

## 4. 响应式约束

- 1440 宽度：保留左侧学习导航和主内容区；学习路径使用双列模块卡片。
- 1024 宽度：侧栏收纳为窄导航，模块卡片切为单列或两列，主操作保持可见。
- 低高度窗口：内容区独立滚动，继续学习、提交和保存考试动作不被长内容推出视口。
- 不使用固定高度裁切理论正文、题目解析或成绩详情。

## 5. 数据与实现边界

- 静态内容、教学谱例和默认配置集中放在 `data/guitar-advanced/` 的 `.ts` JSON 对象；React UI 位于 `components/GuitarAdvanced/`，纯逻辑位于 `lib/guitar-advanced/`，进度使用 `stores/` 中的独立 Zustand store。
- 页面容器读取统一数据入口并将数据传给组件；组件不直接绑定 `.data.ts`。后续 `servers/` 只能从服务端入口调用，客户端不直接导入该层。
- 教学谱例通过 `lib/guitar-advanced/score-example-adapter.ts` 适配现有 `lxm-editor` 文档并经过正式 loader 校验；理论页只读展示，不创建编辑会话、不修改 `editorStore`。
- 实际用户进度不写回源码，后续内容读取和进度存储可以分别迁移。
- 持久化 key 使用版本号，例如 `lxm-guitar-advanced-progress:v1`。
- 题目评分使用纯函数，页面组件不直接散落答案判断逻辑。
- 学习状态不写入现有曲谱文档，曲谱 schema 不因 MVP 学习模块升级。
- 所有页面状态需支持刷新恢复；当前浏览器是唯一承诺的数据范围。

## 6. 设计验收

设计进入实现前，至少确认：

1. 四个模块、8 个理论小节、6 个练习和 12 道考试题的范围一致。
2. 理论、练习、考试、结果和错题复习之间都有明确入口。
3. 已答、未答、正确、错误、完成、未开始和本地存储异常均有可识别状态。
4. 1440 桌面稿与 1024 窄窗口稿不存在主操作丢失或内容遮挡。
5. 静态设计稿不宣称已经验证真实运行时行为。

## 7. MVP v1 实施范围说明

2026-10-16 完成的 MVP v1 只实现学习路径、一个开放模块、一节理论和一个单选练习；综合考试、结果、错题复习和完整进度页属于后续路线。设计稿的完整闭环仍作为产品目标和后续验收依据，不能据此宣称本次已经交付完整 MVP。

v1 已按本契约完成桌面与窄窗口浏览器抽查，并验证理论完成、单选反馈、重做及刷新恢复。详细工程回归结果见 [MVP v1 实施验收](../../mvp/进阶能力建设/20261016_吉他进阶MVP_v1实施验收.md)。
