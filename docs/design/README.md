## 6. 推荐阅读路径与冲突处理

1. **确认任务**：本总纲 → 主技术方案 → 当前阶段细化方案；需要回溯范围时再读范围分析。
2. **进入实现**：最新代码落地复审 → 对应画面的 `implementation-review.json` 条目 → 主方案第 18–21 节完整契约及审查项。
3. **对照视觉**：视觉规范 → Ant Design 映射文档 → 对应 PNG → 画面行为修订。
4. **准备交付**：主方案的验收与功能保留矩阵 → 对应阶段的实际截图、测试和验收稿 → 更新总纲进度。

各类资料职责如下：

- 范围和实施顺序以当前主技术方案及其后续补充条款为依据；旧的功能全景不扩大本轮范围。
- 领域行为以真实命令契约、最新代码复审和逐画面修订为依据；PNG 表达页面布局，不能覆盖独立简谱、草稿、历史与成品输出规则。
- 通用控件及视觉 token 以视觉规范和 Ant Design 映射为依据；谱面几何继续消费核心 layout/scene。
- 完成状态以实际提交及对应验收证据为依据。旧文档中“尚未实现”等描述保留其代码基线语境，例如最新复审基于 `585e705`，四栏目后来已在 `0b17ba7` 完成。
- 遇到上述依据仍无法消解的冲突，在主方案登记 `UI-Dxx` 和处理结论，再回填画面清单与验收记录。
