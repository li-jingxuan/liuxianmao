# UI 阶段 6：响应式与多浏览器完整验收技术方案

文档分类：03_技术方案 · [返回 UI 重构总纲](../README.md)

日期：2026-10-18。状态：**已实施并完成 Chrome 最终验收；Edge/Firefox 与 Safari/真实 IME 按环境边界保留 blocked/manual**。阶段 1–4 的功能与 Chrome 证据作为输入；阶段 5 图片导出流程已纳入最终矩阵。阶段 6 负责跨浏览器、响应式、真实输入法、长谱和多页输出的综合验证，不重新实现音乐领域命令。

## 1. 目标与边界

阶段 6 要回答四个问题：

1. 编辑器在 Chrome、Edge、Firefox、Safari 中是否保留同一套命令、草稿、Modal、焦点和 Undo 语义。
2. 1280/1024/768 宽度、650px 高度、200% 系统缩放下，输入节点和高频操作是否仍可达。
3. 真实中文 IME 组合输入期间，Enter、Escape、切页签、切目标和异步提交是否保持安全边界。
4. 100 小节、长歌名、长列表、多页 A4 PNG 和下载失败/取消路径是否保持正确。

本阶段不扩展曲谱库、云同步、播放或新音乐算法；如果发现 core 规则错误，先记录可复现用例，只有影响验收闭环的缺陷才在本阶段修复。

## 3. 测试分层与可复现输入

### S6-A：环境矩阵和基线

- 固定当前源码快照、构建命令、服务器 URL、测试 fixture 和浏览器版本。
- 生成环境清单、功能组清单和结果状态：`passed`、`failed`、`blocked`、`manual`。
- 所有自动化脚本监听 `pageerror`、非已知 favicon 404 的 console error、下载失败和未处理 Promise。
- 每次运行单独输出 JSON，不覆盖历史报告；截图文件名包含浏览器、视口和测试组。

### S6-B：响应式和缩放

| 尺寸/模式 | 必测路径 |
| --- | --- |
| 1440×900 | 默认工作区、四栏目、技巧/小节/拍点/连音入口、图片预览 |
| 1280×800 | 谱面与属性并列，工具菜单、复制、Modal 和底部动作 |
| 1024×768 | 上下分区，属性区滚动，草稿 owner 不卸载 |
| 768×900 | 更多工具搜索、参数区、键盘到达和焦点恢复 |
| 1280×650 | 工具区、谱面、属性区独立滚动，最后一个动作可见 |
| 原生 200% | 720×406 CSS 视口、Modal 边界、Select 候选、Tab/Shift+Tab/Escape |

每种尺寸验证同一输入元素 DOM 身份、raw 草稿、活动目标、选区和 Modal 请求不因布局变化而重建或丢失。

### S6-C：键盘、无障碍和真实 IME

自动化路径：

- Tab/Shift+Tab 遍历工具、属性、Select、Modal 和生成/取消/下载按钮。
- Escape 的层级顺序：Select 候选 → 当前工具/Modal → 草稿保护；组合输入期间不取消业务动作。
- Modal 确认期间背景快捷键不执行；关闭后焦点回到仍存在的触发器或定义好的 fallback。
- disabled 控件的原因可被可见 Tooltip、包装节点或 live region 读取。

人工 IME 路径：

- 中文拼音组合中输入单拍歌词和连续歌词。
- 候选未确认时按 Enter，不应用歌词、不切目标、不跳下一拍。
- 候选未确认时按 Escape，只取消组合输入，不关闭表单或 Modal。
- `compositionend` 后再执行 Enter、Shift+Enter、Tab、切页签和切目标。
- IME 组合期间打开影响确认、切换窗口或触发输出，草稿和焦点保持。

人工结果必须记录输入法名称、系统版本、浏览器、操作步骤和视频/截图路径。

### S6-D：长谱、分页和输出

使用 100 小节混合 fixture，覆盖：歌词、独立简谱、和弦、16 类技巧、跨小节关系、连音组、拍号变化和空内容行。

- 首次加载、布局和滚动不抛异常；每小节只出现一次且顺序稳定。
- 选择首/中/尾小节后，属性侧栏、状态栏和返回焦点位置正确。
- 长歌名、长作者名、长段落标记和长 Select 列表不覆盖动作。
- A4 多页预览页码、页缩略图、字体加载、生成进度、取消、单页生成、全部生成和下载正确。
- 取消或会话替换后不得出现迟到下载、迟到进度或旧 Blob URL 泄漏。
- 导出成品不含 hover、选区、输入框、空位框、工具栏和 Modal；JSON 往返保持文档语义。

### S6-E：全量回归和证据归档

- 对 61 张设计稿中阶段 1–5 已实施画面，以及 S01–S07 补充状态执行对应功能组；阶段 6 的 07-01–04 另存响应式证据。
- 每张截图关联浏览器、尺寸、测试组、fixture、命令/状态断言和报告行号。

- 只有所有非人工、非环境阻塞项通过后，阶段 6 才能标记“自动化与环境验收通过”；人工 IME 和不可用浏览器必须保留为独立未决项。

## 5. 缺陷分级和处理

- **P0**：跨浏览器造成文档破坏、错误提交、旧目标写入、新旧会话串写或成品污染；必须修复后再继续矩阵。
- **P1**：关键功能不可达、Modal/键盘焦点逃逸、下载/取消错误、长谱分页错乱；修复后重跑受影响矩阵。
- **P2**：布局溢出、提示缺失、局部字体或视觉差异；记录并在不影响行为时单独安排。
- **环境阻塞**：浏览器或真实 IME 无法运行；保留复现环境，不降级为通过。

### 9.2 本轮发现并修复

1. **图片 Modal Esc 焦点还原失效（P1）**：StrictMode 的模拟卸载提前调用还原并把 `focusRestored` 置位，真正关闭时不再执行；随后 AntD portal 清理把焦点留在 `body`。改为卸载后延后判定、仅在组件确已卸载且没有新对话框接管时还原，帧级时间线验证焦点稳定回到“导出 A4 图片”。
2. **堆叠布局双层滚动（P2）**：≤900 视口下工作区与设置栏同时滚动，200% 时生成按钮被裁切约 4px。堆叠时设置栏改为自然高度，由工作区单一滚动，并断言生成按钮完整位于滚动视口内。
3. **200% 用例与 S02 闸门冲突**：旧用例遗留未应用的单音符音高草稿，图片导出被正确阻断。用例改为先显式放弃悬置草稿，再验证导出，同时把 S02 纳入 200% 证据。
4. **证据描述修正**：1024 视口图片 Modal 为三栏，仅 ≤900 视口堆叠；检查项和截图命名已更正。
