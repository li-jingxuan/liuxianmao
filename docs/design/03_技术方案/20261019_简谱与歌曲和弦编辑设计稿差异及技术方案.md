# 简谱与歌曲和弦编辑设计稿差异及技术方案

日期：2026-10-19  
状态：已评审并实施  
范围：对照当前工作区与 `HEAD` 中“04 · 歌词简谱与和弦”设计稿，并提出后续 UI 实施方案。本文件记录设计差异、实施约束与最终落地结果。

## 1. 结论

本轮设计稿变更主要是简谱编辑工作流的紧凑化，并强化内容行入口的可见性。入口按钮和“首次应用才写入内容”的交互在当前实现中已经存在，本轮实施重点是核验其设计状态、可见性和边界行为，而不是重复开发入口。和弦专用画面没有检测到相对 `HEAD` 的变化，因此目前不能把本轮描述为“和弦编辑器重新设计”；和弦画面应作为现有行为参照，继续支持和弦名称、预设、六弦指法、横按、范围与错误反馈。

当前代码工作区存在用户已有的未提交更改，尤其是 `MusicTextSidebar.tsx` 中歌词覆盖选项与连续填词预览布局。本方案不覆盖或回退这些更改；实现阶段应在现有工作区基础上逐项评审。

## 3. 差异清单

| 区域 | 旧稿/既有表达 | 本轮设计稿 | 技术影响 |
| --- | --- | --- | --- |
| 简谱表单层级 | 定位、录入、节奏、范围与技巧操作纵向连续展开，信息说明占据较多常驻空间 | 定位与录入方式并列；内容输入前置；节奏字段成组；低频范围、音符技巧和范围复用折叠 | 主要为展示层重排；必须继续使用现有 draft、plan、校验和命令调用，不复制音乐领域状态 |
| 简谱输入 | 单音组或连续输入可编辑，但帮助与预览区域相对分散 | 输入框默认两行；保留一行速记；详细说明通过问号入口打开 | 帮助浮层只读，不提交、不改目标、不清草稿；实现键盘开关和焦点恢复 |
| 节奏模板 | 自定义成员字段纵向占位；连音条件字段与常规字段层级不够紧凑 | 自定义成员按“音序/时值/附点”三列排列；连音比例紧随模板；失败状态替换成功预览 | 表单字段仍由模板类型决定；校验失败保留输入，禁用应用 |
| 录入范围 | 既有事件与新增范围展示结构差异不明显 | 已有事件范围默认折叠并显示摘要；新增时间范围默认展开起点、覆盖时长 | 折叠只影响呈现；切换展开状态不得改变 range draft |
| 预览与提交 | 预览、覆盖确认与操作区间距较大或不在同一视觉流程 | 预览/错误 → 覆盖选项 → 删除、取消、应用，操作紧随表单内容 | 保持原有命令边界、撤销能力和覆盖默认值；操作不迁移为固定底栏 |
| 内容行入口 | 入口不够显著，依赖已有行或无目标提示继续操作 | 歌词/简谱切换栏下明确展示“添加歌词行”“添加简谱行”并排入口 | 入口当前已存在；需核验顺序、禁用/复用状态及窄屏呈现，保留现有草稿闸门与首次应用写入规则 |
| 和弦编辑 | 预设/六弦指法、横按及高级操作有明确设计稿 | 对应 06、07、09 号稿未变化 | 不提出和弦交互改版；保持现有组件及 `SetChordSymbol` / `RemoveChordSymbol` 行为作为回归基线 |

## 4. 目标与非目标

### 目标

1. 让常用简谱编辑和应用动作在标准窗口首屏可达，减少低频属性对输入流程的干扰。
2. 给简谱编辑提供清晰的无目标引导、模板时长校验和覆盖保护。
3. 保持段落面板的歌词/简谱行入口清晰可见，并验证首次应用前不写入虚假音乐数据。
4. 在重排过程中保持领域逻辑、文档 schema、命令历史及导出行为不变。
5. 保持和弦编辑既有能力不退化，并用当前和弦稿作为回归依据。

### 非目标

- 不改变简谱音高/时值/技巧语义，不把 TAB 与简谱编辑绑定。
- 不调整歌词分词、覆盖与谱尾整批校验规则。
- 不调整和弦数据结构、指法预设、横按模型或和弦渲染。
- 不新增服务端 API、持久化字段或 schema 版本。
- 不将面板折叠态、问号浮层开关写入曲谱内容。

## 5. 建议技术方案

### 5.1 组件职责

继续由 `MusicTextSidebar` 负责目标选择、歌词/简谱模式切换、draft 生命周期和提交动作；将密集表单区域按职责拆分为可复用的小型呈现组件，建议边界如下：

- `ContentRowActions`：添加歌词行、添加/切换简谱行；通过现有段落创建/复用回调执行，不直接构造音乐事件。
- `NumberedEditorForm`：简谱定位、录入模式、文本、模板、时值、范围、预览与覆盖选项。组件只接收受控值、状态和回调。
- `NumberedAdvancedSections`：音符技巧与范围复用两个折叠组；折叠状态为局部 UI state。
- `InlineHelpPopover`（如项目内已有通用帮助组件则复用）：问号触发、Esc/外部点击关闭、关闭后焦点归还入口。
- 和弦继续由现有 `ChordEditor` 负责，避免把简谱表单布局条件耦合进和弦组件。

拆分应以降低 `MusicTextSidebar` 的条件分支复杂度为目的，不为每个字段新建组件，也不改变 draft 的单一事实来源。

### 5.2 状态和提交边界

- 业务 draft、目标对象和预览计划继续由现有状态流程管理；新增的折叠态、帮助开关只存在于 React 本地 UI state。
- 展开/收起、打开帮助、切换非破坏性查看状态不得调用 apply/delete 命令，也不得清空草稿。
- 简谱文本应用、当前音符时值应用、单音高应用、记号操作仍保持独立命令范围，不能因按钮重新排布合并提交。
- 覆盖开关仅影响计划通过校验后的写入结果；模板/时长/范围非法时保留用户输入与错误原因，禁用应用。
- 首次创建内容行不产生音符、休止或空和弦占位；内容由用户首次应用时写入。
- 和弦编辑维持单目标原子应用；名称、指法、横按属性验证失败时保留 draft 并禁止提交。

### 5.3 布局实现

- 简谱侧栏按设计的 440px 基准宽度及 20px 水平内边距实现，使用 Ant Design 表单控件和项目现有设计 token；两列字段使用 CSS Grid，避免固定控件宽度溢出。
- 主路径按“定位 → 输入 → 节奏 → 范围 → 预览/错误 → 覆盖 → 操作”排序。单音组与连续输入共用骨架，通过模式配置显示对应标签和字段。
- 新增范围默认展开起点、时长；已有事件默认折叠并显示范围摘要。长文本通过省略与可访问完整值解决，不压缩控件可读性。
- `音符技巧`、`范围复用`用独立折叠容器控制；展开内容进入侧栏自身滚动流，不固定主表单按钮到底部。
- 在 1280/1024/768px 布局及低高度窗口中，内容行入口仍位于段落内容表单上方；遵循既有窄窗口设计稿调整侧栏/底部属性区，不引入第二套状态逻辑。
- 禁用状态必须同时使用禁用语义与可读原因；不可只依赖颜色表达。

### 5.4 内容行创建规则

1. 现有“添加歌词行”入口为当前谱行选择尚未使用的段号；达到 4 段时提示用户编辑已有段号。验收应确认重复点击与目标变化不会重复创建内容。
2. 现有“添加简谱行”入口定位到简谱编辑目标；简谱行唯一，已有时复用。入口动作只打开/切换编辑目标，第一次成功应用时才产生简谱事件。
3. 当前 `addParagraph` 会优先采用有效目标，否则回退到首轨首小节首拍；若曲谱没有可用拍点则显示“请先添加拍点”。设计稿的无目标状态应与此实际规则核对，避免承诺无拍点时可完成写入。
4. 行入口产生的目标切换必须继续经过 `request` 草稿闸门；被草稿确认拦截时不得先改目标、段号或谱面 selection。

### 5.5 辅助说明与可访问性

- 简谱标签旁问号用按钮语义，名称为“简谱输入规则”；支持 Tab 聚焦、Enter/Space 打开、Esc 关闭，关闭后焦点回到按钮。
- Popover 内容与已有简谱输入语法、模板和覆盖规则一致；简短速记仍保留在输入框附近，详细规则不得再作为常驻大提示块。
- 折叠标题可由键盘操作并暴露 `aria-expanded` 与关联内容；展开态变化不移动到失焦状态。
- 输入、计划错误、覆盖数量变化通过现有表单错误呈现；避免每次键入都由读屏器重复播报整段预览。

## 6. 主要风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 只改布局时误清空或错配简谱 draft | 保留现有 target key / draft reducer 流程；折叠 state 与业务状态隔离；覆盖目标切换和返回草稿用例 |
| 折叠后隐藏校验错误或应用入口 | 错误所属区域自动展开或在摘要处显示错误状态；焦点定位到首个无效字段 |
| 模板切换导致成员时值、连音比例丢失 | 沿用当前模板转换规则；转换不可逆时保留已有草稿或由现有保护流程处理，不在呈现组件自行重置 |
| 内容行入口意外产生空音乐内容或绕过目标保护 | 复用现有目标定位与草稿闸门；验证首次应用前无内容命令，草稿确认前 selection/目标不变 |
| 简谱布局条件污染和弦面板 | `ChordEditor` 保持独立挂载与布局；简谱新增 CSS class 限定作用域；增加和弦基线回归 |
| 窄窗口中双列控件截断 | Grid 在窄断点退化为单列；对标题、摘要、按钮文字及 Popover 做实窗检查 |
| 用户现存未提交修改冲突 | 实施前先审查工作区现存改动，按文件/区块增量修改，不执行覆盖式生成或回滚 |

## 7. 实施步骤建议

1. 先核实设计稿索引、对应 PNG 与当前工作区更改一致；锁定 04、05、08、10、12–15 号状态及窄窗口约束，并确认 08 号无目标文案与“首轨首拍回退/无拍点提示”的实际行为一致。
2. 盘点现有 `MusicTextSidebar`、`NumberedEditor` 的 draft/plan/command 流程，以及 `ChordEditor` 输入输出契约；先确定最小呈现层改造范围，避免无必要地拆分组件。
3. 对现有内容行入口做契约核验：歌词段号分配、四段上限、简谱唯一行复用、无拍点提示及草稿确认期间不提前改变目标。只有存在设计差异时才修改入口。
4. 实现简谱紧凑布局、范围与高级区折叠、规则 Popover 与自定义成员三列表格；复用既有校验与提交回调，并确认不同简谱目标间折叠态是否重置符合预期。
5. 做交互、响应式和和弦回归；通过后更新设计实施清单与验收记录。

## 8. 验收标准

- 单音组、连续录入、无目标、已有目标、新增时间范围、自定义成员时值和连音时长错误均与对应稿一致。
- 标准桌面尺寸下常用输入和提交路径清晰可达；低频区默认折叠，展开后侧栏滚动正常。
- 折叠、帮助开关、模板切换和目标切换均按草稿保护规则运行；取消不写入曲谱，应用与撤销结果正确。
- 覆盖默认为关闭；预览、覆盖数量和错误原因与实际 plan 一致；非法计划不能提交。
- 歌词段号最多 4 段且按当前谱行未使用段号分配；简谱行唯一且可复用；入口只切换/定位编辑目标，首次成功应用前不产生占位音乐事件；无可用拍点时反馈与实际能力一致。
- 入口触发的目标切换经过统一草稿闸门；草稿待确认时目标、段号和谱面 selection 均不提前变化。
- 和弦预设、名称、六弦数据、横按设置、跨度/调弦错误与应用/删除行为保持原样。
- 1280px、1024px、768px 与低高度场景下无控件溢出、遮挡或不可达入口；问号 Popover 与折叠组件可键盘使用。
- 文档内容、schema、导入导出和渲染输出没有非预期差异；UI 帮助和折叠状态不进入持久化内容。

## 9. 补充核对点

- `NumberedEditor` 当前把“录入方式”放在“当前简谱事件”之前，并在无有效事件/窗口时只显示提示；新稿提出两者同行且无目标时仍展示可用模式选择。实现需确认无目标态是否可以选择模式，以及模式切换仅修改编辑模式、不构造目标或音乐事件。
- 新稿以固定高度侧栏和内容区内联提交为主；工作台在容器宽度低于 1200px 时已切为纵向工作区，低高度时也会改变滚动与 sticky 行为。简谱内联动作需在桌面、窄宽、低高度三类容器中分别验证，不能直接复用歌曲设置的 sticky 动作样式。
- 当前简谱编辑器有独立的 `pending` 影响确认流程（例如时值变更可能覆盖后续事件）和草稿记录/输出阻塞机制。表单折叠、切目标、应用与离开时必须保留这两层保护；取消影响确认不得误删原草稿。
- 模板选择当前会重置选择目标/结束 tick（例如设为起点后 960 tick）。紧凑重排不应意外改变此既有规则；模板切换后的范围摘要和错误恢复需要按设计稿实际演示状态核实。
- 需要分别定义：新增范围的展开状态、已有事件范围的折叠摘要，以及目标切换后展开状态是否按目标记忆。建议初版采用每个 NumberedEditor 面板会话的局部默认值：已有事件折叠、新增范围展开；状态不进入文档和 undo 历史。

## 10. 实施结果

已按确认范围完成简谱面板的呈现调整；和弦编辑器保持原实现与行为。

- `NumberedEditor`：当前事件与录入方式并排；无目标时仍可切换录入方式；输入框改为两行并提供速记提示和输入规则 Popover；简谱时值/附点并列、自定义成员时值/附点并列；录入范围、音符技巧、范围复用分别折叠。
- 折叠状态与帮助状态只保存在组件本地 UI state；业务草稿、计划、影响确认和命令提交链路未改。已有事件的录入范围默认收起，新建时间范围默认展开；范围复用和音符技巧默认收起。
- 内容行入口已经存在，本轮未重复实现；保留目标切换统一经过草稿闸门、歌词段号最多 4 段、简谱唯一行复用及无拍点提示。
- 和弦组件与 06、07、09 号设计稿无差异，因此未改动和弦数据或交互。

验证：`pnpm --filter @liuxianmao/website type-check`、针对 `NumberedEditor.tsx` 的 ESLint、`pnpm --filter @liuxianmao/website test -- numbered-editor`（26 个测试文件、165 项通过）、`pnpm --filter @liuxianmao/website build` 与 `git diff --check` 均通过。
