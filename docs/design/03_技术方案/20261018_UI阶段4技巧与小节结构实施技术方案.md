# UI 阶段 4：技巧与小节结构实施技术方案

文档分类：03_技术方案 · [返回 UI 重构总纲](../README.md)

日期：2026-10-18。状态：**S4-A～E 功能实现与 Chrome 验收通过**。前置阶段 1–3 的自动化及浏览器结论见[阶段 3 验收](../04_实施验收/20261018_UI阶段3歌词简谱与和弦属性表单实施验收.md)；真实系统中文 IME 由用户后续人工复核，本方案不将它算作已验收。阶段 4 方案以 UI 迁移和接线为主，不改 schema 或音乐规则；本次回溯发现范围复制的简谱连接遗漏尚未从 core 对外报告，阶段 4 需补齐该结果元数据与测试，不能由 UI 静默丢弃。

## 1. 目标与范围

阶段 4 覆盖设计稿分类 `05 · 技巧与小节结构` 的 12 张画面，完成 16 类 TAB 技巧、关系/范围目标、技巧参数、小节属性与复用、拍点粘贴、连音组、小节线、影响确认与撤销反馈的界面收口。

主要工作是将已有工具的状态、确认和焦点行为收敛到阶段 1–3 的稳定 owner/异步提交契约中，并按设计稿展示真实 core planner 的结果。核心规则当前已经存在，除非实施时发现可复现的缺陷并单独立项，不在阶段 4 重写领域算法、schema、持久化 ID 分配或谱面几何。

不在本阶段：图片导出流程（阶段 5）、全量响应式/多浏览器/长谱最终验收（阶段 6）、真实系统 IME 人工签字、曲谱库保存/同步、播放/缩放等产品能力。

## 4. 阶段契约

### 4.1 目标身份、预览和并发

- 所有延迟确认保存完整 `EditorSessionVersion`（文档引用/revision、`sessionId`、`sessionVersion`）及目标 track/measure/beat/note/technique ID。选择改变时按命令定义阻断、重定位或失效，不能静默改目标。
- 显示影响确认时，文档或目标版本改变即关闭旧确认并重新规划。重规划后如 effects、plan key、目标或 overwrite 许可有变化，展示新内容并要求再次确认；绝不沿用旧确认授权。
- busy 时拒绝重复确认、取消和会话迁移；真实执行失败保留原选择/表单输入并显示 core message；unmount/会话替换必须 settle 调用方并释放锁。
- 一次用户动作最多一次领域命令。确认只执行最新完整 command；不循环多次调用命令制造表面原子性。
- 若使用 native `<dialog>`，其内部 Escape/Tab 必须在对话框本层处理，不能由背景草稿保护逻辑先截获；优先沿用受控 `EditorModalHost`。

### 4.2 技巧参数与目标

16 类技巧为：hammerOn、pullOff、slideUp、slideDown、bend、vibrato、naturalHarmonic、artificialHarmonic、palmMute、tie、tapping、trill、strum、arpeggio、pickStroke、letRing。中文标签和分组消费 `TECHNIQUE_OPTIONS`；不得另造不同数量的按钮目录。

| 技巧类型 | 稳定目标与提交字段 | 表单字段/范围 |
| --- | --- | --- |
| hammerOn / pullOff / slideUp / slideDown / tie | `fromNoteId` + `toNoteId` | 起点/目标 Note；方向及 Tie 同音规则由 core 校验 |
| bend | `fromNoteId` | `semitones: 1 | 2` |
| vibrato / naturalHarmonic / artificialHarmonic / tapping | `fromNoteId` | 无额外参数 |
| trill | `fromNoteId` | `auxiliaryFret` 整数品位 |
| strum | `beatId` | 连续弦 `minString/maxString` + `stroke: up/down` |
| arpeggio | `beatId` | 连续弦 `minString/maxString` + `direction: ascending/descending` |
| pickStroke | `beatId` | `stroke: up/down` |
| palmMute / letRing | `fromBeatId` + `toBeatId` | 起止 Beat 区间 |

所有 16 类都是 TAB 技巧。简谱选区存在时不得把简谱位置转换成 TAB Note/Beat 命令目标；无合法 TAB selection 时禁用 picker，并说明需要的目标形态。

- 首次新增：用户先选择类型/参数，再对当前稳定 selection 建立 draft；成功返回后选择新的 technique ID。取消新增不改文档或 selection。
- 既有技巧编辑：通过 `selectedTechniqueId` 加载现存字段，参数变化保持在 UI draft；Update 命令保持 ID，Remove 走同一受控提交入口。类型切换必须由用户在 picker 明确选择；core 的 `UpdateTechnique` 支持以新 discriminant 替换旧参数并保留原 technique ID，因此一次更新即可完成，禁止拆成删除+新增。
- 类型参数按判别联合逐类显示：bend 1/2 半音；trill `auxiliaryFret`；strum 的上下拨 `stroke` 与连续弦范围；arpeggio 的 ascending/descending 与连续弦范围；pickStroke 单拍方向；关系技巧两个 Note 端点；palmMute/letRing 两个 Beat 端点。无参数类型不显示无关字段。
- 单音技巧目标是合法 Note；H/P/slide/tie 的端点合法性、弦/品位/音序/相邻性完全服从 `validateTechnique`。P.M./Let Ring 使用稳定 Beat 区间。提示可解释规则，但最终 core error 原样显示并关联字段。
- 注意视觉文案的方向映射：弦号递增方向、down/up stroke 与 ascending/descending pitch 是不同语义，禁止共用未经转换的方向字段。

### 4.3 结构命令与影响

#### 预检查、确认和应用的唯一流程

当前通用 command adapter 会尝试一次 store 命令；`NUMBERED_IMPACT_REQUIRED` 才弹 `structure-impact` Modal，拍点粘贴由自己的 controller 处理覆盖/影响确认。`applyScoreCommand` 是纯函数，能在不提交 store、不写历史的情况下规划文档并返回 effects。因此阶段 4 对于需要先看影响的操作，采用“纯候选 → 预览/确认 → 核对完整版本和目标 → 单次 store execute”的流程；禁止先 store execute 后用另一个命令补救。

| 操作 | 是否必须提交前确认 | 候选/确认依据 | 应用后反馈 |
| --- | --- | --- | --- |
| 新增/更新技巧 | 通常不需二次确认；保存前展示目标、类型和参数摘要 | 受控 technique draft + `validateTechnique`/纯 `applyScoreCommand` 结果 | 技巧选择和谱面更新；失败保留表单值 |
| 显式删除一条技巧 | 不需重复确认；这是明确的单对象删除 | technique ID 必须仍存在且与选择一致 | 已删除提示与 Undo；stale 不删除新选择对象 |
| 一般拍号/拍点/连音等可逆结构修改 | 不做通用确认；core 返回 `NUMBERED_IMPACT_REQUIRED` 时才显示简谱 mark 确认。其他 effects 作为提交后说明 | 失败 impact ID 及确认字段来自 core；完整版本/目标失效需重新规划 | 一次提交；展示实际 effects 和 Undo |
| 拍点覆盖/插入粘贴 | `planBeatPaste.requiresConfirmation` 为真时必须确认；覆盖控制 checkbox 必须明确勾选 | `planBeatPaste` 的完整计划、确认 key、clipboard version 和层范围 | 已粘贴/被影响项摘要和 Undo |
| 删除小节 | 必须确认；预览编号及会删除的 TAB 拍/音符、歌词、和弦、简谱事件/marks、TAB/简谱 Tuplet、技巧和影响数量 | 先在原文档上纯调用 `applyScoreCommand(RemoveMeasure)`；若返回 `NUMBERED_IMPACT_REQUIRED`，将 removed mark IDs 纳入同一删除预览。最终 command 一次带 `expectedRevision` 和完整已确认 mark ID 提交；last measure 仍由 core 拒绝 | 取消零历史；成功后聚焦相邻仍存在的小节；Undo 恢复整小节和关联实体 |
| 整小节范围复制 | 插入操作，不覆盖原谱；无跨界关系遗漏时直接插入；存在技巧/简谱连接遗漏时先展示预览并确认一次 | `CopyMeasureRange` 纯候选及 `measures.copied`/`technique.omitted`/`numbered.mark.omitted` effects；如需确认则绑定版本、源起止和锚点 | 取消零历史；成功显示插入数量和遗漏；Undo 一次移除整批副本 |

删除小节、包含跨边界关系遗漏的整小节范围复制和需要许可的 paste overwrite 使用提交前影响 Modal，必须含“将发生什么”、明确取消/确认、busy 锁和焦点循环；普通拍号、拆合、Tuplet 与技巧 Add/Update/Remove 不因存在普通可逆 effects 自动弹 Modal。核心 `NUMBERED_IMPACT_REQUIRED` 仍强制确认。Modal 打开期间，Escape/Tab 不得落到背景编辑保护或背景工具。取消/过期/命令失败不改变文档、history 或 selection；确认回调再次校验 `sameEditorVersion`、目标 ID 和 selection/numberedSelection 快照。过期时关闭旧候选，不保留 checkbox/许可，用户重新请求后再看新预览。成功只执行一个最终领域命令；纯候选阶段创建的 ID 必须由相同 document+command 的确定性 core factory 生成，若不能保证候选与提交一致，则不要显示候选实体 ID，只比较摘要和 revision。

`EditorImpactNotice` 是**提交后**可展开的影响结果和撤销入口，不等同于提交前确认 Modal。结构动作可能出现的两个 UI 阶段分别是：有需用户批准的破坏性/跨域效果时先显示确认；命令成功后再显示真实 effects 与 Undo。普通效果只在提交后展示，可通过 Undo 撤销对应的完整文档命令；effects 本身是临时 store 状态，撤销/重做会清空，不进入文档历史。普通可撤销效果不重复弹确认。


拍号/小节容量同时影响 TAB 与独立简谱。小节属性命令属于两谱共用结构；TAB 拍点结构命令只操作明确的 TAB Beat。所有小节/拍点修改都消费 core 候选和 effects。

范围复制与拍点粘贴的谱层入口不同：小节范围复制的 `CopyMeasureRange` 固定复制完整小节（两谱和关联内容）；拍点剪贴板由 `BeatClipboard.layers` 选择 `tab` 或 `both`，简谱时间范围复制仍使用独立简谱剪贴板。不能把 R08 的拍点粘贴层开关误加到小节范围复制。

- 拍号：沿用既有可编辑拍号白名单和 scope；目标小节/直到下一个既有变化点的规则由核心解析。可能改变拍点容量或简谱事件的结果先预览。
- 小节线：六种右侧边界和谱首 `repeatStart` 分别使用稳定 boundary reference。谱尾无后继小节时禁用 repeatStart/repeatBoth；谱首功能只在首小节可见/可用；core 仍是最终裁决。
- 小节复制：保留 UI-D08 已验收的来源起止、插入位置和受保护导航；复制整个 measure，不提供层选择。现有命令会重新生成小节/Beat/Note/歌词/和弦/Tuplet/简谱实体 ID，并复制范围内可映射技巧和简谱连接。跨范围技巧或简谱 mark 不猜端点；通过 `technique.omitted` / `numbered.mark.omitted` effects 明确反馈（简谱遗漏 effect 是本阶段要补齐的 core 结果元数据）。目标是插入，不覆盖原小节；非法来源/锚点整条拒绝。
- 拍点拆分/合并：selection 是 TAB 单元格选择，不接受 `numberedSelection` 作为 beat command 输入。预览展示真实 command result effects；部分 Tuplet、Tie 或非法目标由 core 拒绝，不对选区部分应用。
- TAB 连音组：复用 `LXM_TUPLET_RATIOS` 六比值、`resolveTupletSelection` 和 `SetTuplet/RemoveTuplet`。清楚显示成员数、同小节连续、同书写时值/附点等禁用原因。简谱模板/范围替换仍走其原本 ratio contract。
- 拍点插入/覆盖粘贴：沿用 `BeatPasteController` 单一 clipboard 和 `planBeatPaste`。预览标明剪贴板层（仅 TAB/双谱）、完整六弦、目标、时值、替换拍数、歌词/和弦/简谱/技巧/mark 影响及源范围关系遗漏。允许确认的 command 携带精确 `expectedConfirmationKey` 与 overwrite consent；plan/key、目标、完整会话版本或 clipboard version 任一与执行前候选不一致就重规划并重置覆盖勾选，要求重新确认。
- 技巧因结构/覆盖失效而被清理，使用 `technique.removed`/`technique.omitted`，指出编辑前小节、技巧类型与缘由。成功命令只有一个文档 history 项；`effects` 在 store 中作为当前结果展示，Undo 恢复文档并清空该展示状态，不声称 effects 自身进入历史快照。确认前不产生历史记录。

### 4.4 错误、取消、导航和焦点

- Modal 取消/关闭/过期：零 document 写入、零 history、selection 和 draft 按 owner 约定保留或复位。
- 命令失败/拒绝：不部分修改；保留用户可编辑的输入，公告可读 core 错误，焦点定位到错误字段或仍有效的目标。
- 应用成功：保留仍存在的 stable selection/technique ID；目标被删除或结构改变时采用 command `nextFocus` 或明确 fallback，不指向已删除对象。
- 自动关闭或导航仅发生在最终结果为 applied/noop 且目标版本仍有效后。阻断、stale、cancelled、failed 均不得继续导航。
- 所有可见禁用状态提供键盘可读原因；菜单关闭、断点变化与无关状态更新不得清除参数 draft 或改变业务目标。

## 7. 风险与处理

- **能力已存在被误当作迁移已完成**：保留工具实现，但用本阶段逐画面/状态/命令证据确认；旧按钮存在不等于确认、版本保护、焦点和 undo 已验收。
- **结构命令连带影响两谱**：所有候选与 impacts 均来自 core；确认后使用同一命令，不由 React 复制 tick/标记清理算法。
- **技巧选择器与参数 owner 被拆散**：参数 draft 归稳定 technique owner；picker 关闭、工具栏收纳或无关 React 更新不可重置。
- **过期影响确认误用旧授权**：比较完整会话版本、稳定目标、confirmation key；任一变化重算并要求新的明确确认。
- **S3 人工 IME 尚未完成**：阶段 4 可使用阶段 3 已通过的自动化结果继续方案/实施；不把真实 IME 标作阶段 4 的既成结果，阶段 6 统一登记人工验收状态。
- **误扩 scope 到阶段 5/6**：图像导出仅以现有回归不退化为限；完整导出流程、多浏览器和长谱统一放到其指定阶段。
