## 3. 页面结构与状态归属

### 3.1 根布局

根布局按正常文档流排列：

```text
EditorSession（现有会话 key）
└── EditorSessionRuntime（现有稳定实例）
    ├── EditorShell
    │   ├── EditorHeader：品牌、已提交曲名、视图、JSON 与图片入口
    │   ├── EditorToolbar：历史、音符、结构/连音/技巧分组
    │   ├── 反馈区：导入通知、布局提示、命令影响、错误
    │   ├── 工作区：pageViewport + MusicTextSidebar（同一组实例）
    │   └── EditorStatusBar：位置、选区、草稿、输入状态
    └── EditorModalHost（现有统一宿主）
```

- `EditorShell` 继续持有布局密度、和弦图显示、谱面布局/命中、品位计时器及键盘/指针交互。
- 头部曲名读取已提交 document；歌曲表单中的未应用标题不提前改头部或谱面标题。草稿只显示“待处理草稿”，不把它称为“未保存到曲谱库”。
- 头部不渲染没有真实目标的“曲谱管理”返回或库保存按钮，沿用 UI-D01。
- 首次进入及文件替换重建后，一级栏目调整为“选区”，对应 03-01；`kind` 仍可为 `score`，隐藏的歌曲设置继续挂载。旧验收稿“默认歌曲”是上一切片行为，不作为本阶段默认值。
- 位置与草稿只有一份 `aria-live` 摘要；顶部错误使用 `role="alert"`。不在头部、工具带和底部重复播报同一状态。

### 3.2 模块职责与改动文件

下列文件按职责分离实施，实际交付和验证范围以验收记录为准。

| 文件/模块 | 职责 | 不能承接的职责 |
| --- | --- | --- |
| `EditorHeader.tsx`（新增） | 品牌、标题、视图菜单及已有输出入口的排列 | 保存状态机、管理路由、音乐命令 |
| `EditorToolbar.tsx`（新增） | 稳定工具分组、可用性提示、音乐资产与按钮表达；消费现有 store 和命令适配 | 音乐时值算法、复制规划、独立草稿存储 |
| `editor-tool-state.ts`（新增） | 从真实文档和核心选区解析结果派生启用状态与原因 | 根据像素推导选区、直接修改 document |
| `ScoreSettings.tsx`（现有） | 保留单一草稿 owner、controller、分组应用、组合态和协调器登记 | 把草稿交给 Form 再维护另一套副本 |
| `ScoreSettingsForm.tsx`（新增） | 受控字段、Form.Item、分组动作、作用范围与错误显示 | 直接 execute、维护独立的内容 baseline |

| `index.tsx` / `index.module.scss` | 组装上述区域，调整分区和滚动；共享已有键盘命令入口 | 因断点改变 key 或卸载业务 owner |
| `app/providers.tsx` / `app/page.module.scss` | 复用现有主题，校正根容器高度和布局约束 | 扩展产品业务 |

优先提取现有行为，避免让新的工具模块和谱面键盘入口各维护一份同义命令构造。单纯移动 JSX 时保留原有命令回调；确需共享适配逻辑时，让两种入口调用同一实现。

## 4. 视觉、尺寸与滚动契约

- 通用控件继续使用已安装的 Ant Design 6.4.4；正文、品牌、背景、边框从现有 ConfigProvider token 映射到编辑器 CSS 变量，消除旧 SCSS 的第二套冲突颜色。
- 通用控件高 32px，紧凑图标工具可用 24px；通用圆角 6px，面板不超过 8px。音乐符号继续使用现有资产。
- 头部以 56px 为常规基准，工具带以 40px 为最小基准，状态带以 28px 为最小基准；长标题截断并提供完整文本，动作不被挤出。小尺寸允许区域增高，不能靠固定总高度裁掉控件。
- 常规右侧属性宽 344px；谱面外侧留白约 24px。纸张保留既有 210mm 宽度与核心布局，窄窗口横向滚动，不缩放 SVG 冒充新的缩放能力。
- 移除 `.toolbarButton { display: inline-grid }` 对 Ant Design Button 的布局覆盖；图标与文字用组件自己的布局或 inline-flex，避免文字落到按钮底部。
- 收紧侧栏全局 `button/input/select` 后代选择器，改为具体区域样式，避免覆盖 AntD Tabs、Select、InputNumber 与弹层子控件。

布局仅以编辑器**容器宽度**为依据，使用 container query；阶段 1 不同时维护另一套 JS 断点状态。

| 容器宽度/窗口场景 | 工作区布局 | 滚动和 owner 要求 |
| --- | --- | --- |
| `width >= 1200px`；目标 1440×900、1280×800 | 谱面与 344px 属性区并列 | 谱面和表单各自滚动，底部状态带可见 |
| `900px <= width < 1200px`；目标 1024×768 | 上谱面、下属性区 | 工作区剩余高度约按 55:45 分配，两区 `min-height: 0` |
| `width < 900px`；目标 768×900 | 紧凑头部、上下属性分区 | 阶段 1 工具分组可换行并独立滚动；阶段 2 再接入完整“更多工具” |
| 高度 650px；200% 页面缩放回归 | 由实际容器宽度决定分栏 | 工具带可滚动，表单正文滚动；常规面板动作sticky，低于600px可用高度的上下分区保留最小可操作高度并由工作区滚动，动作回到文档流，不覆盖最后字段 |

底部属性区在 grid/flex 文档流内，不使用覆盖谱面的固定抽屉模拟。宽度变化只改 CSS 排列；不改变 session key、表单 key、TAB 选区、简谱目标或草稿目录。

## 5. 工具分组和禁用矩阵

### 5.1 分组与阶段边界

顺序固定为：历史 → 音符/时值/附点 → 小节 → 拍点 → 连音 → 技巧。头部提供视图与文件/输出。

阶段 1 先形成稳定分组与区域边界，保留现有高级控件和预览实例。阶段 2 才将高级操作完整迁入菜单及紧凑“更多工具”。不能用宽度条件在 inline 控件和另一个菜单控件之间直接切换，导致 `BeatToolbar.preview` 或技巧参数被销毁；阶段 2 接入前先将相应状态留在稳定 owner 中。

### 5.2 共用规则

- 下表表达入口条件；最终合法性仍由核心命令/规划裁决。UI 不为“提前禁用”重写音乐规则。
- 沿用 `musicTextEditing` 对 TAB 修改工具的保护；帮助和视图允许使用，历史仍按原行为处理。Modal 活动时背景编辑入口隔离。
- 不把 `drafts.isOutputBlocked()` 直接用作所有工具的 disabled，否则粘贴预览会把自己的应用按钮也锁住。
- 谱面立即编辑动作继续先取消等待中的品位计时任务；不能让旧数字在点击新工具后迟到提交。
- 禁用控件保留 Tooltip，组内说明可被键盘读取；disabled 按钮本身不能成为唯一的解释入口。

| 工具/动作 | 入口条件或禁用原因 | 行为与来源 |
| --- | --- | --- |
| 撤销/重做 | `canUndo` / `canRedo`；无可用历史则禁用 | store 历史；不新增历史快照 |
| 六种时值、0/1/2 附点 | 核心解析选区恰有一拍；多弦同拍允许，多拍禁用 | `SetBeatRhythm`，不只修改范围 focus |
| 闷音 X / 删除音符 | 有合法 TAB 选区 | 矩形设置/删除命令；删除不表示整拍休止 |
| 休止 / 恢复 | 合法非空拍范围 | `SetBeatKindRange` 作用整拍全部弦；恢复不还原旧音符 |
| 新增/删除当前小节 | 唯一目标小节；最后一小节不能删除 | 既有插入/删除命令；不在 UI 拼接文档 |
| 复制小节范围 | 合法连续小节范围 | `CopyMeasureRange`，保留谱层与遗漏影响 |
| 当前小节拍号 | 有合法 focus 小节；只提交现有可编辑拍号 | `SetTimeSignature`，沿用 `untilNextChange` |
| 小节线 / 谱首反复 | 有 focus；谱首反复只对第一小节；谱尾禁用开始/双向反复 | 完整六类右边界，使用 `SetBarlineBoundary` |
| 拆分拍点 | 单拍选区 | 核心 `SplitBeat`；持续音规则由核心处理 |
| 合并拍点 | 同一小节的多拍范围 | 核心检查合法休止/Tie 持续音；失败展示原因 |
| 复制拍点 | 同一小节连续范围 | 双谱/仅 TAB 选项保留，调用现有 clipboard |
| 预览粘贴 | 有 clipboard 和目标拍 | `planBeatPaste`，显示真实影响与 confirmationKey |
| 应用粘贴 | 已有预览；需要覆盖确认时必须勾选 | 重新核验核心计划；取消/过期不写历史 |
| 六种连音比例 | `resolveTupletSelection` 成功且拍数等于 ratio.actual | 不按按钮是否可见推断可用性；两个五连音保持可区分 |
| 删除连音组 | 核心解析结果含现有 group | `RemoveTuplet` |
| 添加/更新技巧 | 有选区；既有 buildDraft 解析 Note/Beat/范围及参数 | 保留 16 类与类型参数，最终调用核心规则 |
| 删除技巧 | 有可解析的 selectedTechniqueId | 删除原对象，不把取消选择当作删除 |
| 密度/指法图/帮助 | 已加载文档；帮助保留品位输入期间的既有保护 | 视图状态不写音乐历史 |
| JSON 导入/导出、A4 图片 | 现有即时检查与协调器均允许，且无活动 Modal | 原文件/图片控制器负责读取、快照、失效与输出 |

类型参数保留：关系技巧从真实同弦音符构造目标；扫弦/琶音要求单拍多弦；推弦保留半音/全音；颤音奏保留辅助品位；方向术语保留原有“上/下”和“上行/下行”区别。本阶段不缩减为只有“添加技巧”的入口。

## 6. 真实快捷键清单

依据 [editor-interaction.ts](../../../apps/website/components/EditorShell/editor-interaction.ts)、[EditorShell](../../../apps/website/components/EditorShell/index.tsx) 和 [MusicTextSidebar](../../../apps/website/components/EditorShell/MusicTextSidebar.tsx)，帮助弹层与 Tooltip 使用同一份展示数据；本阶段不新增 Ctrl+S、播放、缩放等快捷键。

| 输入 | 生效位置 | 行为 |
| --- | --- | --- |
| 方向键 / Shift+方向键 | TAB 谱面焦点 | 导航 / 扩展选区 |
| 点击 / 拖动 / Shift 扩展 | 谱面 | 使用核心命中结果定位，不按 DOM 字形下标改选区 |
| 0–24 | TAB 谱面焦点 | 两位品位；1、2 前缀等待 600ms，其余合法输入立即提交 |
| X | TAB 谱面焦点 | 设置闷音 |
| Backspace / Delete | TAB 谱面焦点 | 删除矩形选区音符 |
| R / Shift+R | TAB 谱面焦点 | 整拍休止 / 取消休止 |
| Ctrl/⌘+Z | 编辑器非文本控件焦点 | 撤销；文本框保留浏览器原生撤销 |
| Ctrl/⌘+Shift+Z；Ctrl+Y | 编辑器非文本控件焦点 | 重做 |
| Esc | TAB 或文字编辑 | TAB 清除输入并收拢选区；文字编辑先走原草稿请求 |

| Tab / Shift+Tab | 页面及弹层 | 正常焦点顺序；Modal 和原草稿确认区域维持自身焦点约束 |

Input、textarea、Select 内部输入和中文组合态优先交还表单。新 AntD Select 的键盘事件不能冒泡触发谱面编辑；菜单关闭后恢复触发元素焦点，不能无条件聚焦 SVG。

## 7. 歌曲设置 Form 与提交契约

### 7.1 唯一草稿 owner

`ScoreSettings` 保留现有 `value/initial/document/measureId` 状态及 `ScoreSettingsController`。`ScoreSettingsForm` 仅接收受控字段、分组错误和回调，Form.Item 负责布局与反馈；不再用带 name 的 Form 字段维护第二套可编辑数据。

四组各使用独立 Form 提交入口；避免嵌套 form。通过表单提交回调调用原分组适配，输入只改草稿。设置组件继续常驻，切栏目使用 hidden；不增加 `key={activeTab}`，不用断点重建 Form。

### 7.2 字段映射与语义

| 字段/操作 | Ant Design 表达 | 数据与校验契约 |
| --- | --- | --- |
| 歌曲名称、编谱作者 | Input + Form.Item | title/arranger 原文草稿；核心上限 128/64，允许空值。不得照搬“新建名称必填”到编辑设置 |
| 调性 | Select | `LXM_KEY_SIGNATURES` 与 null；不把 null 改成字符串“未设置”写入文档 |
| 基础拍号 | Select + 作用范围说明 | 来自第一小节；只提交现有四种可编辑拍号，当前白名单外值只读展示 |
| Capo | InputNumber 的受控适配 + Form.Item | owner 保留字符串草稿；空值不能变成 0，整数范围仍为 0–12；不通过 blur 自动夹到合法值掩盖错误 |
| 段落标记 | Input + 目标小节说明 | 当前 focus 小节，单行最多 32；空白清除；无目标时禁用，不清掉其他设置草稿 |
| 小节复用 | 三个 Select + 独立提交动作 | 起止/插入位置使用稳定 measure ID；“谱首”映射 undefined，不和内容设置混用 apply |

Capo 的控件适配必须覆盖原始输入、清空、小数、越界和步进；输入中的临时文本不能仅留在组件内部而让协调器误报“无草稿”。若控件行为无法满足原文保持，应先修正适配或登记控件偏差，不能更改领域值或静默取整。

### 7.3 分组提交

| 提交组 | 命令 | 成功后的草稿处理 |
| --- | --- | --- |
| info | `SetNotationInfo` | 只用规范化结果更新 title/arranger/keySignature；保留其他组草稿 |
| signature | `SetTimeSignature`，首小节及 `untilNextChange` | 更新 signature，重算作用范围，保留其他组草稿 |
| capo | `SetCapo` | 更新 capo，保留其他组草稿 |
| label | `SetSectionLabel` | 更新当前目标的 label，保留其他组草稿 |
| 小节复用 | `CopyMeasureRange` | 先要求设置草稿已处理；失败保留起止选择和明确错误 |

提交过程固定为：捕获真实 session/document 版本 → 使用现有 `planSettingsCommands` 规划 → 在隔离文档上用 `applyScoreCommand` 预验证 → 版本仍有效才调用原 commit → 按成功结果刷新本组 baseline。

- 预验证失败不执行任何命令；错误由相应分组 Alert/Form.Item 展示，输入原文保留。错误分组无法精确到字段时不伪造字段级规则。
- no-op 清理旧错误但不增加历史。每个成功领域命令一条历史；多个设置组不宣称一个原子事务。
- controller 的全部设置应用仍保留给既有草稿保护流程使用，先预验证全部候选再逐命令执行；它不是自动应用全量歌词/简谱草稿。
- 若预验证要求额外音乐影响确认，保持核心错误与草稿，不把“已打开确认”当成成功；本阶段不扩大跨多组的自动确认流程。相关确认完整迁移仍按阶段 4 执行。
- 宿主回调或文档替换造成的中断要停止剩余提交，按实际成功组更新 baseline，保留未提交组；不能回滚新会话内容或把全部草稿标成已应用。
- IME 组合态禁止应用/丢弃/切目标；普通失焦、浏览视图菜单和宽度变化不能 resetFields 或重读覆盖草稿。

## 12. 开工回溯补充（2026-10-16）

对照真实 store、原表单和打印层再次回溯后，补充以下实施约束：

1. **宿主同步重入与部分成功**：每条设置命令提交前后同时核验 document 引用、stateVersion、sessionId、sessionVersion。宿主回调再编辑或替换文档时停止后续命令；已经成功的组按真实结果更新，未提交字段保留原文。不用文档 ID 或 revision 代替会话版本，也不承诺跨命令回滚。
2. **局部标记锁定目标**：段落标记一旦变脏，沿用原 measureId；选区移动不把草稿迁到新小节。目标消失时拒绝提交；标记干净后才跟随 focus。小节复用的失效选项显示明确提示，不静默替换为首小节。
3. **数值控件原文**：Capo 的 `onInput` 同步字符串到 owner，禁用失焦归一化；步进单独同步。空、非数字、小数、越界必须在真实浏览器失焦和应用后验证，不能只以纯函数测试代替组件适配证据。
4. **稳定高级工具容器**：阶段 1 使用四个固定 Popover 容器组织原有小节/拍点/连音/技巧控件，首次打开后保留内容。断点只改变排列；粘贴预览与技巧参数不因为关菜单或窗口重排被卸载。阶段 2 继续负责控件深化、完整禁用说明和紧凑“更多工具”，本次不把该阶段提前标成完成。
5. **打印与输出边界**：新增头部、工具带、反馈、状态带和编辑工作区均在 print 媒体下隐藏，只复用已有成品打印层。JSON/A4 继续走原控制器；视图变化不增加音乐历史，原始草稿不进入输出快照。
6. **证据分层**：自动化组合事件、真实系统 IME、真实浏览器页面缩放分别记录；尚未执行的人工路径明确保留，不用截图尺寸或合成事件替代。

本次补充不改变领域命令、文档 schema、核心谱面坐标或阶段 2–6 的交付范围。
