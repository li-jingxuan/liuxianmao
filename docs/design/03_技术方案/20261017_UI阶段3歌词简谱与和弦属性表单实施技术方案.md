## 4. 目标身份、草稿和提交契约

### 4.1 三类目标

- 歌词：`trackId/measureId/beatId/verse`，段号 1–4；同拍换弦不换歌词对象。
- 和弦：`trackId/measureId/beatId`，名称、diagram、strings/barres 为同一草稿；显示方式沿用现有“有图 nameAndDiagram、无图 name”提交行为。
- 简谱：先经 `resolveNumberedEditorTarget`，已有对象为 event/item，空位为 `tick/endTick`；`numberedDraftKey` 沿用真实事件/item 或时间窗口。TAB 入口只转换一次，后续不拿残留 TAB focus 当简谱目标。

页面栏目、活动音乐对象、键盘焦点、TAB selection 和草稿各自管理。浏览页签不激活音乐编辑、不抢回旧对象；明确激活简谱后，TAB 的品位、休止、拆合、连音和技巧仍禁用并解释作用域。返回 TAB 走原 `returnToScore/request`，不能只改提示文案。

### 4.2 草稿与恢复

| 触发                              | 行为                                                                                                                                  | 文档/历史                                        |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| 同一目标重复点击                  | 保留原草稿，只恢复相应可见控件焦点                                                                                                    | 零提交                                           |
| 简谱 A→B→A                        | 缓存并恢复 raw/initial、模板、范围、时值/附点、覆盖、ratio、自定义成员及 itemDraft 等现有 snapshot 字段，补存目标当时的模式与草稿基线 | 零提交；非模态提示、返回编辑及本会话不再提示保留 |
| 歌词/和弦换目标、换模式或跨类型   | 原三分支保护；继续留原目标，放弃只处理确认范围，应用必须等待真正成功                                                                  | 打开确认或候选不等于成功                         |
| 断点、滚动、折叠、Select 开关     | 同一 owner 与字段值保留，隐藏组不可 Tab 到达                                                                                          | 零提交                                           |
| 外部文档/会话替换、撤销或实体删除 | 沿用当前外部变更清理路径并给出目标失效说明；可控替换先过全量草稿闸门                                                                  | 旧回调不写入新会话；不把草稿偷偷移到邻近实体     |

不将 draft 放进 document/history。登记的 version 对应草稿实际基线；不能仅在重渲染时给旧输入换上最新版本。自身命令成功后，只更新该命令实际提交字段的基线，其他目标缓存按 4.5 核对依赖后保留，不直接清空或无条件刷新版本。

### 4.3 分组应用与导航终态（S3-A 首先解决）

实施前 `NumberedEditorController.apply(): boolean` 主要提交内容，时值和 item 音高有独立动作；pending 记号确认也可能只返回 false。实施前必须逐一核对：仅修改时值/item、多个分组同时修改、确认后成功、确认取消、核心 no-op。不能让“内容应用成功或 no-op”代表所有分组都处理完毕而丢弃别的输入。

在原提交 Seam 明确异步结果，保留歌曲设置等其他模块的同步调用方式；下例是设计契约，不是已导出类型：

```ts
type NumberedDraftGroup = "content" | "rhythm" | "itemPitch";
type PropertyApplyResult =
  | {
      status: "applied" | "noop";
      group: NumberedDraftGroup;
      remainingDirtyGroups: NumberedDraftGroup[];
    }
  | { status: "cancelled" | "blocked" | "stale"; message: string };

// 等待已有影响确认真正结束；返回 applied/noop 才允许验证并执行待导航动作。
type ApplyPropertyDraft = (context: {
  group: NumberedDraftGroup;
  isCurrent: () => boolean;
}) => Promise<PropertyApplyResult>;
```

明确内容动作只提交内容；事件时值及单 item 音高分别提交。“应用并切换”只在恰有一组待提交且该组校验通过时可用，明确显示将应用的组名；仅时值/item 修改也调用对应组，不能继续调用内容 apply。多组同时修改时禁用该按钮并提示先在对应分组处理，不能自动循环执行多个音乐命令伪装为原子事务。零修改但仍有输入激活保护时，继续/放弃可结束编辑，不为解除保护制造音乐命令。普通字段无需为了这段契约全部异步化。

Sidebar 保存单个待导航动作；确认期间不换栏目/目标。成功后重新核验 session、实体及未处理草稿，再导航一次；取消、失败、过期保持原输入和可见焦点。草稿协调器的单项 apply 使用同一结果，不绕过确认或另建提交锁。由内容/时值/item 的真实修改决定 dirty，不能只用 `raw !== initial`，也不能提交一组后重置所有分组。

### 4.4 分组基线、生命周期与即时动作

| 分组      | 字段归属与基线                                           | 成功/no-op 后的处理                                                                             |
| --------- | -------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 内容      | raw；创建/模板命令使用的窗口、模板、覆盖、成员时值和比例 | 从实际提交操作和结果重建该组基线；已应用模板可保留为下一次输入偏好，不能因非 uniform 永久 dirty |
| 事件时值  | 已有事件的 base/dots，独立于模板成员时值                 | 只更新该事件时值基线；不把当前 raw 设为 initial                                                 |
| item 音高 | 明确 itemId 对应的 token/八度/升降                       | 只更新该 item 基线；其余 item、内容和模板输入保持                                               |

现有 base/dots 同时用于创建模板和已有事件时值，必须拆开字段归属或提供明确的上下文映射；已有事件均匀改内容并不消费模板时值。只选择 item/记号终点、打开折叠或停用模板中的 ratio 不是音乐修改；这些准备状态仍随 snapshot 恢复，不能凭非默认值使表单永久 dirty。语法错误的实际输入必须登记，即使尚不能生成操作。

自身命令会递增 `stateVersion`，实施前 `NumberedEditor` 的 key 包含该值。S3-A 必须移除此类“每次提交重建全部输入”的依赖，或在重建前完整保存、核对并恢复其余分组；优先保持会话内同目标 owner 稳定，按明确的成功回执更新基线。仅删除 key 不够，还须处理目标/item 被替换后的合法性和旧 effect。不得通过改 store 版本递增规则规避问题。

所有简谱写操作，包括拆合、删除、连音移除、记号和粘贴，都走同一提交入口与依赖检查。若将替换/删除其他未提交分组或缓存所依赖的对象，先阻断并定位待处理草稿，不能顺带 reset；确认音乐记号影响不等于授权放弃 UI 输入。可证明互不影响的动作可继续，执行后按组保留输入。歌词/和弦“删除当前实体”明确会放弃该实体当前表单修改，按钮及保护说明写清范围；不清理别的缓存。

每个修改组提供“恢复此组”动作，只从当前文档重读该组并清除其错误，其他组不变；冲突提示可定位到对应组。这样同事件的内容/item 冲突可由用户处理，不因只有全局取消而陷入互相阻断。全局“放弃并切换”仍明确作用于当前目标，隐藏缓存仅由逐项/全量明确丢弃处理。

### 4.5 缓存版本与自身提交后的协调

每个缓存除了原 snapshot，还需绑定真实 target、模式、创建/最后核对的完整 `EditorSessionVersion` 及所依赖的文档字段快照。模式不只读全局 `numberedMode`：B 切换录入方式后返回 A，仍恢复 A 暂存时的解释方式；切换模式的保护只处理当前目标。

提交前对当前其他分组及全部缓存做依赖检查；结果按以下规则处理：

1. 目标及读取的内容、时值、范围、item/连接引用都未受本次命令影响：保留原值与 initial，经前后依赖相等及核心重新规划确认后，记录这次核对并推进基线版本。普通 render 不得推进。
2. 命令将覆盖、重建 item、删除事件或改变缓存读取范围：提交前阻断，提示先返回该草稿处理/明确丢弃。无法证明独立时保守阻断，不把旧 item 自动绑定到新 item，不把旧时间窗自动挪到邻近事件。
3. 提交失败、取消、过期：不删缓存、不推进任何基线；no-op 只处理已核验的对应组，不清空其余字段。外部变更仍走 4.2 的失效清理及说明。

依赖检查仅比较命令/候选涉及的文档数据，音乐合法性仍交给 core。可先对复杂范围操作采用保守的小节/轨道依赖范围，并在界面说明阻断原因，不复制一套音乐规划器。缓存登记继续 `canApply=false`；返回编辑恢复可见栏目、目标、模式和错误后再允许单项应用。

## 5. 歌词表单

模式和段号使用既有 Select，两列在可用空间不足时改为单列。单拍正文沿用 Input（UI-D09）；连续模式使用 TextArea，但输入语法仍只接受半角/全角空格分隔，`_` 跳拍，换行/制表符按核心解析报错。段号、正文、覆盖许可和原目标共同参与保护。

预览直接消费 `parseLyricSequence` / `planLyricSequence` 的 rows、issue、changes、overwrites：每行显示序号、小节/拍点、原词、新词及新增/覆盖/相同/跳过/错误状态。越界行保留错误位置，不截断成“部分可以应用”。按真实 Beat 顺序包含休止并可跨小节；输入项数不能代替将修改数。

沿用当前歌词草稿**默认允许覆盖**的既有行为，清楚展示覆盖数和 Checkbox；不因简谱覆盖默认关闭而一起改掉歌词默认值。取消勾选后按核心计划保护原词。字段错误附近给出说明，整批错误用 Alert，动作区保持可达。

| 动作         | 命令/语义                                                                |
| ------------ | ------------------------------------------------------------------------ |
| 单拍应用     | `SetLyric`；规范化及长度校验沿用 core                                    |
| 应用并下一拍 | 单拍成功后按真实曲谱顺序定位下一拍；最后一拍保留当前目标并说明已到谱尾   |
| 连续应用     | `SetLyricSequence`；校验通过才整批一次命令，失败/no-op 不增加历史        |
| 删除歌词     | `RemoveLyric`；仅当前段/当前实体，保留当前拍点；连续模式不伪装成批量删除 |

Enter/Shift+Enter 沿用单拍约定；TextArea、Select 与 IME 的 Enter 各按原语义处理。候选确认键和 compositionend 后短时间内的 Enter 不提交音乐。

## 6. 独立简谱表单与预览

### 6.1 控件与命令对应

保留 uniform、前八后十六、前十六后八、三连音、六类比例、自定义成员时值等已有入口。六种书写时值与 0–2 附点沿用；比例和容量由 `editNumberedTrack` 计算，UI 不做另一套 tick 运算。

内容、事件时值、单 item 音高分别标明应用动作（UI-D04），可分组折叠高级入口，但不能删掉拆合、记号、范围复制/粘贴。04-10 的八度/升降字段必须先明确 item；只有一颗 item 可直接选中，多音组须显示被编辑成员。输入和预览沿用 token 解析/规范化，再组装原命令，不自己计算音高规则。

### 6.2 预览呈现与固定验例

`numbered-preview.ts` 接受原操作、原 track 和 `editNumberedTrack(..., true)` 的结果，将候选事件及 overwrittenEventIds、releasedRange、removedMarkIds、changedMarkIds 映射成视图；失败直接保留核心 message。跨小节均匀改内容的预览遍历实际受影响的小节，不按当前 `start/end` 截掉后续结果。

按命令区分行与统计：`sequence.set` 没有完整的逐行/覆盖清单，需将原有事件序列与输入 set/skip 对应后读取候选值；`overwrittenEventIds` 不能当成连续改内容的全部覆盖计数。`event.set` 对齐目标 event/item；范围替换/时值操作结合原、候选事件与核心窗口元数据；记号动作列出关系影响。明确区分跳过、同值 no-op、修改已有内容、删除被覆盖事件和释放空位，不统一叫“覆盖”。预览生成的临时 ID 不视为已提交实体，应用仍由 store 在相同基线上重新规划；不得直接把候选 track 写回文档。

每行显示小节/分数拍位、音组、成员书写时值/附点、比例及新增/保留/覆盖/释放状态；连接遗漏与目标记号影响分别统计。使用 `formatNumberedBeatPosition`，起点为第 1 拍。

固定前八后十六验例：4/4 的 0–960 tick 窗口，八分/十六分/十六分，起点为 0/480/720；位置显示第 1 拍、第 1 拍+1/2、第 1 拍+3/4。已有事件均匀模式另用不等时值、跨小节事件，证明保留原时值。缩短释放空位后不补简谱休止，点击该空位可继续新建；成品不显示空位框。

### 6.3 影响确认

继续复用 core 候选及当前确认流程，保留原始文档、完整会话版本、目标与操作快照；确认提交带 `expectedRevision` 及 `confirmedRemovedMarkIds/confirmedChangedMarkIds`。版本/实体变化要重新规划，不能只比较会随撤销回退的 revision。

一次请求绑定 requestId、原始版本、目标、组名、冻结操作和输入代次；`idle → planning → awaitingImpact（如需）→ committing → settled`，不需确认时直接提交。确认期间锁定这次操作所用字段及导航，重复点击、协调器应用与表单按钮共用 owner 的单次执行锁。Esc、取消、关闭、卸载、会话替换及校验失败都必须结算 Promise 并释放锁；过期只给出重新预览入口，不自动提交新候选。确认后的提交也必须执行普通成功路径，不能只关闭 dialog 而漏更新该组基线/导航结果。

调用方接线如下：

| 调用方                              | 终态处理                                                                                                                                  |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 分组按钮/保护区                     | await 原 owner 的同一请求；取消/blocked/stale 保留输入，成功后按回执检查剩余分组；待导航只执行一次                                        |
| `EditorDraftCoordinator` 单项 apply | 保留现有 `applied/blocked/stale` Interface，在 Sidebar 适配 applied/noop 为 applied，其余按 blocked/stale 映射；不能把 Promise 当 boolean |
| 歌词/和弦/歌曲同步 apply            | 在导航适配层规范化同步结果；不要求把各控件、命令 execute 全部改成异步                                                                     |

写入前同时检查调用方 `isCurrent()` 与 owner 的请求/输入代次、完整版本；自身提交成功后以回执的结果版本判断待导航，不能用提交前版本要求成功后的文档仍相等。协调器当前以登记实例身份判断 `isCurrent`，而 `useEditorDraftRecords` 会重登记：打开确认、busy 通知等普通渲染不能使尚未更改的请求误过期。S3-A 稳定登记实例或接入显式请求失效机制，真实输入/目标/版本变化才撤销该请求；不能简单删掉身份检查。

显示“删除 N 个 / 迁移 M 个记号”，取消零修改，成功内容和影响一起撤销。明确删除记号本身不再重复弹间接影响确认。阶段 3 为分组应用/导航补齐终态接线，原生确认的完整视觉统一仍留阶段 4；不得同时出现两个处理同一请求的确认 owner。影响 dialog 打开时，底层草稿三分支区不同时声明第二个活动 `aria-modal`，其操作不可达；关闭后按待导航终态恢复确认区或原字段焦点。阶段 2 的 AntD Modal 焦点检查不能替代该原生 dialog 的单独检查。

## 7. 和弦表单与内容行

### 7.1 和弦

名称与预设保持两列；起始品位和高级说明另行分组。真实指法图位于六弦表上方，不用截图或静态图代替 `layoutChordDiagram/ChordDiagramView`。预设用 `copyChordPreset`，字段变化只 `onChange` 本地 draft；应用才 `SetChordSymbol`，删除用 `RemoveChordSymbol`。

六弦按 1–6 保存，品位 x/0/1–24，空弦和禁奏不保留手指编号，普通手指为 1–4 或未指定。横按保持四字段及最多四条，范围、冲突和跨度只消费 `validateChordDiagram`。InputNumber 清空保留非法草稿，展示为空并禁用提交，不把空白转成 0 或失焦自动钳制。

起始品位 1–20 只改观察窗口；指法自身超过五格与品位落在窗口之外是不同错误，不能提示移动窗口能够修复任意跨度。非标准调弦禁用常用预设但保留自定义编辑，既有指法不自动转置。

“清除指法图”先在草稿置 diagram=null、保留名称，按已有统一应用提交；取消可放弃该草稿。删除整个标记才是独立删除命令。当前没有“隐藏图但保留 diagram”的独立 UI 契约，本阶段沿用当前显示语义；不暗加该动作或复制一份显示草稿。

### 7.2 内容行和无目标状态

`addParagraph` 优先真实有效起点，并按该起点的 `trackId` 查找轨道；仅无目标时回退首轨。不能使用有效目标的 measureId，却在首轨统计段号。歌词/和弦依赖真实 Beat；无目标的歌词入口定位首轨第一个有 Beat 的小节，无合法起点给说明。简谱优先使用独立事件/时间窗，必要时使用既有 TAB 入口转换；合法简谱目标不因没有 TAB Beat 而失效，无法解析有效独立时间窗时再显示空态，不能制造虚构 Beat。

歌词按当前 layout 中目标所在谱行已有段号取 1–4 中空缺值；布局尚未给出谱行时禁用添加并解释，不以空列表误判可新增第 1 段。已有四段提示继续编辑原段，不能新增第 5 段。请求建立时冻结目标/段号，受保护导航通过后再次核验存在性；断点重排、折叠或等待确认不自动改段号。该规则修正现有入口的目标解析，不扩展多轨管理界面。

添加行只打开编辑、首次应用才写文档。简谱只有一套独立 voice，空位来自现有布局与命中；不新建假 TAB Beat、补休止或持久化“显示编辑行”偏好来模拟空态。
