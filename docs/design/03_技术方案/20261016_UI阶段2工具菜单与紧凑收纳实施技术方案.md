## 3. 模块、接口与状态归属

按 `codebase-design` 的 Module/Interface/Seam 原则，将版本核验和预览生命周期集中在一个 Module 内。普通按钮只发送意图，不要求每个调用方各自按顺序检查 session、剪贴板和确认键。

| Module / 文件                                                                       | Interface 与职责                                                              | 状态归属                                                       |
| ----------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- | -------------------------------------------------------------- |
| `EditorToolbar.tsx`                                                                 | 组织历史、高频工具和高级入口，调用原 `onAction/execute`                       | 不复制音乐内容或预览草稿                                       |
| `editor-tool-catalog.ts`                                                            | 工具 ID、组、中文名称、搜索词和详情位置；快捷键说明复用 `editor-shortcuts.ts` | 静态元数据，不存命令闭包/文档快照                              |
| `editor-tool-state.ts`                                                              | 从真实文档、核心选区解析和编辑保护派生 availability/current/summary           | 纯派生；核心命令最终裁决                                       |
| `EditorToolPanelHost.tsx`                                                           | 四组入口与更多工具共用一份稳定弹出内容，负责开关和可见焦点                    | 活动组、搜索词、导航意图                                       |
| `beat-paste-controller.ts`                                                          | 准备/模式/确认/应用/取消及失效，接受 store 和命令 Adapter                     | 复制偏好、候选、捕获版本和确认状态的唯一 owner                 |
| `BeatToolbar.tsx` / `BeatPastePreview.tsx`                                          | 菜单表达与受控预览表单，消费同一控制器                                        | 不重复持有可提交候选；退出动画仅保留呈现快照                   |
| `NoteToolDetails.tsx`、`TupletToolDetails.tsx`、`TupletToolbar.tsx`                 | 选区栏目详细状态和工具菜单，调用共享动作                                      | 音乐值只读派生；待应用连音比例为单一工具准备状态，见第 13.3 节 |
| `MeasureToolDetails.tsx`                                                            | 05-01/11 的小节属性、六类右边界列表与谱尾说明；段落/范围复用按 UI-D08 导航    | 当前值只读派生；不复制歌曲字段草稿                             |
| `TechniqueToolbar.tsx` / `TechniqueTypePicker.tsx` / `technique-type-controller.ts` | 稳定参数 owner、临时类型选择及分组视图；使用原 buildDraft/submit/remove       | 参数不受菜单、断点、搜索结果的挂载影响                         |
| `MusicTextSidebar.tsx`                                                              | 原 request 闸门加工具详情/歌曲字段导航                                        | 原有栏目、目标和草稿继续在这里管理                             |
| `editor-modal-controller.ts` / `EditorModalHost.tsx`                                | 新增有类型的 `beat-paste`、`technique-type` 请求，复用单一宿主                | 统一 busy、版本、取消与 afterClose 焦点                        |

不另建全局工具 Zustand store。预览控制器在稳定的 `EditorToolbar` 层创建一次，由上层现有session key控制生命周期；Runtime继续提供同一草稿协调器和Modal宿主。依赖通过 Interface 注入，会话替换整体清理。注入的命令Adapter使用稳定回调并在执行时读真实session，不捕获旧render的selection/document；不能每次render重建控制器或积累订阅。订阅清理与会话卸载绑定。

宽窄视图在真实的 Seam 上只改变入口和呈现，调用同一组动作。不能复制两份 BeatToolbar、两份技巧 Form 或两个预览控制器，再用 CSS 隐藏其中一份。

## 4. 宽窄入口与稳定呈现

### 4.1 布局规则

| 编辑器容器宽度 | 工具带                                                     | 详细区域                                               |
| -------------- | ---------------------------------------------------------- | ------------------------------------------------------ |
| `>=1200px`     | 历史 → 音符/附点/闷音/休止/恢复/删除 → 小节/拍点/连音/技巧 | 440px侧栏；音符/小节/连音详情进入选区栏目              |
| `900–1199px`   | 同样四组入口；允许受控换行，不能剪掉入口                   | 沿用阶段1上下分区                                      |
| `<900px`       | 高频工具保留；四个高级入口收为“更多工具”                   | 同一选区/歌曲 owner 在底部；更多工具可搜索、可键盘到达 |

恢复、删除、双附点不能因原紧凑 PNG 没画全而消失。常规768宽首先保留整组高频工具；更低可用宽度允许工具带内部换行/滚动，禁止页面横向溢出。高级四类只显示一个“更多工具”入口。

继续使用阶段1的 CSS 容器查询作为唯一断点来源。需要 JS 更新 popup 锚点或焦点时，从触发区计算样式中的布局标记读取当前呈现方式，不再维护另一份900/1200阈值。

### 4.2 弹出内容保持

采用一个稳定的高级工具弹出宿主，宽屏四按钮和紧凑更多按钮都调用 `open(group, actionId?)`。Popover 包裹稳定触发区；宽屏打开时按被点击按钮相对触发区的偏移对齐，紧凑时对齐更多按钮。使用现有 AntD 的 align/溢出调整与公开 ref.forceAlign，不引入新的浮层定位依赖。

弹出内容首次挂载后保持同一父级和顺序；组切换使用 hidden，不更改会话/参数/草稿 key。字段 owner 必须先提到稳定层，再接入新容器。位置偏移只依据真实 DOM 尺寸，不按截图像素写死；滚动/断点变化时重新对齐。

更多工具的搜索仅过滤入口目录：按“小节线/拍号/复制/覆盖/连音/推弦”等词定位组及动作。选择搜索结果只打开相应区域并聚焦，不立即执行删除、粘贴或改时值。搜索过滤不能卸载参数视图或清空草稿；禁用项仍可被查到，并显示原因。

## 5. 工具规则与当前值

### 5.1 通用约束

- 区分 TAB 选区、独立简谱目标、可见栏目、浏览器焦点。激活简谱不能使用残留 TAB focus 执行拆合、TAB连音或技巧；本阶段沿用 `musicTextEditing` 并补足调用前目标检查。
- “可以浏览工具”与“可以提交音乐”分开。无选区、文字编辑中允许打开解释和查找入口；修改动作 disabled。Modal活动/处理中不能打开另一个工具弹层。
- availability 的硬条件只用核心 resolver、实体是否存在和白名单。容量、Tie完整性、部分Tuplet等仍由核心检查；不在每次render中对所有技巧/动作执行完整文档预演。
- 每次音乐动作先取消等待中的品位输入，再读取最新目标；禁用与说明一致。既有真正提交命令复用 Shell/核心，成功一条历史，失败/no-op不新增历史。
- `isOutputBlocked()` 只负责输出，不能成为预览自己的应用按钮的 disabled。自己的预览登记和自己的Modal不得把应用入口锁死。

### 5.2 入口矩阵

| 动作              | 必要条件与显示                                                                  | 最终分派                                                |
| ----------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------- |
| 时值/0–2附点      | 合法单拍，可多弦；显示真实 base/dots，多拍不给伪当前值；所属TAB连音限制明确提示 | `SetBeatRhythm`                                         |
| 闷音/删除所选音符 | 合法TAB单元格范围；删除只清所选弦音符                                           | 原矩形命令                                              |
| 休止/取消休止     | 合法拍范围，作用整拍全部弦；混合范围显示“混合状态”                              | `SetBeatKindRange`；取消休止不恢复旧音符                |
| 新增/删除小节     | 唯一目标小节；仅剩一个小节时禁删                                                | `InsertMeasure` / `RemoveMeasure`                       |
| 直接复制小节      | 连续小节范围；复制到所选范围末小节之后，明确这是新建副本                        | `CopyMeasureRange`；不是系统剪贴板                      |
| 局部拍号          | 合法focus小节、现有四种白名单；显示影响至下一拍号变化点                         | `SetTimeSignature(untilNextChange)`；不同于歌曲基础拍号 |
| 小节线            | 合法focus；六类中文全名+图形，反映核心真实边界                                  | `SetBarlineBoundary`                                    |
| 谱首反复          | 只有第一小节；独立“无/开始反复”                                                 | 同命令的 trackStart；不伪造前一小节                     |
| 拆分拍点          | 合法单拍；拒绝部分连音等情况时显示核心原因                                      | `SplitBeat`                                             |
| 合并拍点          | 同小节连续多拍，结构入口条件满足；休止/Tie规则交核心                            | `MergeBeats`                                            |

| 插入/覆盖粘贴     | 有有效拍点剪贴板和TAB目标，再由核心规划                                         | `planBeatPaste` → `PasteBeats`                          |
| TAB连音           | `resolveTupletSelection`成功，成员数符合actual；六比例始终可见                  | `SetTuplet` / `RemoveTuplet`                            |
| 技巧选择          | 可浏览全部16类，显示当前目标适用性；添加/更新仍走原buildDraft                   | 技巧原命令，不用于独立简谱                              |

谱尾右边界禁用“开始反复/双向反复”，其余类型按核心规则；普通边界的规范化及相邻小节同步由核心处理。unsupported当前拍号只读显示，不自动改成4/4。连音2:3、3:2、4:3、5:4、5:3、6:4使用既有资产并保留完整比例文字；非法混合时值/重叠/嵌套不能被UI强制通过。

### 5.3 详细状态与小节字段

音符与TAB连音详情显示在“选区”栏目，符合03-08/05-03的区域关系；工具带保留快速入口。详细面板只是同一动作的另一个 Adapter，不另存音乐值。切到此栏目必须走原 request 闸门；被草稿/IME阻止时保留原栏目，不能先改 activeKey。

小节菜单展示目标小节、当前段落摘要、局部拍号和右边界。“编辑段落标记”“配置小节范围复制”经原保护流程定位歌曲 Form 的已有字段；直接复制当前范围仍是单独快捷动作。本文登记 **UI-D08：小节局部字段复用歌曲owner**，避免在菜单维护第二套段落/复制草稿。原标记dirty时仍绑定原measureId，不能为跳转方便迁到新选区。

## 6. 拍点粘贴：准备、确认、提交与失效

### 6.1 控制器 Interface

控制器接受真实 session、统一 execute 和 beforeAction 等依赖；调用方通过一个意图入口操作。以下为当前 `BeatPasteIntent` 的操作形状，完整导出以 `beat-paste-controller.ts` 为准：

```ts
type BeatPasteIntent =
  | { type: "prepare" | "mode"; mode: "insert" | "overwrite" }
  | { type: "layers"; layers: "tab" | "both" }
  | { type: "confirm"; checked: boolean }
  | { type: "apply" | "cancel" | "focus" };

// getSnapshot返回不可变快照，只有真实状态变化才替换引用。
// request内部完成校验，外部不能直接设置candidate或绕过确认。
// UI 通过 getSnapshot / subscribe / request 消费状态；
// start / invalidate 用于生命周期与外部保护变化，canApply 提供应用条件。
```

复制谱层偏好保留在同一稳定工具owner中，但剪贴板实际谱层以 `getBeatClipboard().layers` 为准。改变“下次复制的谱层”不会改写已复制载荷；要换谱层需重新复制。预览内不提供一个伪装成能转换现有剪贴板的谱层开关。

### 6.2 候选快照

prepare捕获：完整EditorSessionVersion、clipboardVersion、规范化TAB选区/目标引用、一次读取的BeatClipboard副本、mode、成功核心plan及confirmationKey。字符串ID用于定位，不能代替完整版本；clipboardVersion当前也会随另一类剪贴板更新，保守失效可以接受，但不能漏检拍点载荷变化。

草稿记录的version直接使用这次候选捕获的版本，不能在重渲染时改成“当前版本”，让旧候选获得新的有效期。原父级BeatToolbar的版本/选区key在显式失效机制通过测试后移除；owner只随真实session key重建。

展示模型直接取核心 `BeatPastePlan`：count、durationLabel、replacedBeats/Lyrics/Numbered/Chords、removedTechniques/NumberedMarks、effects。单列“仅六线谱/双谱”，区分新复制内容与目标被替换内容；跨范围遗漏取clipboard.omissions/numberedOmissions及effects，不自己推算音乐时长或记号数量。

### 6.3 状态转换

| 事件                                     | 结果                                                                       | 文档/历史    |
| ---------------------------------------- | -------------------------------------------------------------------------- | ------------ |
| 无载荷/无目标/核心规划失败               | 菜单内可读错误，不创建可应用候选或打开空Modal                              | 不变         |
| 成功prepare                              | 打开统一预览Modal，登记一条beatPaste草稿，confirmed=false                  | 不变         |
| 插入↔覆盖                                | 对捕获目标重新规划、替换候选及确认键，清除确认；失败保留可读错误并禁用应用 | 不变         |
| 需要覆盖确认但未勾选                     | 应用禁用，给出理由；只使用核心requiresConfirmation                         | 不变         |
| 应用                                     | 再核完整版本、剪贴板版本、目标及核心plan/key；有效才提交一次PasteBeats     | 成功一条历史 |
| 核心提交失败                             | 保留Modal与错误，允许取消；清除旧确认，重新规划后再确认                    | 无部分修改   |
| 取消预览                                 | 清候选/确认和草稿登记，保留剪贴板及复制偏好                                | 不变         |
| 关闭工具菜单/切高级组/宽度变化           | 保留owner；未进入Modal的参数不重置                                         | 不变         |
| 文档/undo/redo/宿主换谱/目标或剪贴板变化 | 候选失效、清确认；关闭旧Modal并显示“请重新预览”，解除旧草稿登记            | 不提交       |
| 密度/指法图/滚动变化                     | 继续使用同一有效候选                                                       | 不变         |

失效提示可以保留旧摘要用于说明，但旧摘要不是可应用草稿，不得永久阻塞输出。宿主换会话后旧回调不向新会话写错误。busy内自己的成功命令造成版本变化，应按成功结果关闭，不能被订阅误当成外部失效。

确认在真正execute前完成最后核验，核心再用expectedConfirmationKey拒绝过期计划；不靠同revision或同文档ID判定有效。store的宿主回调同步重入后，不追加第二条命令或自动重新打开旧预览。成功后撤销必须同时恢复音乐内容与关联影响。

## 7. 类型选择与弹层接线

技巧类型选择按PNG分为音符连接5类、音高修饰6类、演奏方向/范围5类，共16类。选择器只持有本次临时type；“下一步：参数”才写回稳定参数owner、关闭选择Modal并打开既有参数区域，不在选类型时提交AddTechnique。取消或Esc丢弃本次临时选择，保持进入前的类型和参数。

已有方向、半音/全音、辅助品位、关系音符和范围参数继续可用；重新开菜单、更多工具搜索或宽度变化不重置。`selectedTechniqueId`改变所表达的编辑对象时，仍沿用原有明确重载语义。类型/参数属于工具准备状态，不能未经设计就全部注册为音乐内容草稿，影响现有输出行为。

`EditorModalRequest`扩成有类型的判别联合：旧help/structure请求保持兼容；beat-paste请求引用稳定预览控制器，technique-type请求引用受控选择意图。禁止加入任意HTML字符串、eval或与领域无关的万能弹层注册系统。Host只渲染、处理busy/关闭和焦点，不读取核心文档拼命令。

预览切mode的动态摘要由同一控制器订阅更新，不另复制到Modal message。预览应用通过控制器 request({type: "apply"}) 入口，复用 Modal confirm 路径的同一 busy 锁；成功才能关闭，失败保留。Modal活动时禁用背景工具和历史快捷键，单一宿主不能被另一个请求覆盖。

粘贴确认类Modal的遮罩/Esc不取消，通过“取消预览”或关闭叉号明确退出；技巧选择是非提交选择器，提供关闭/取消并允许非组合态Esc。下一步交接使用一个绑定modal id与session的意图，afterClose后再聚焦参数，不叠加第二个Modal。公共结构影响确认的完整视觉迁移仍留阶段4，现有回调不被绕开。

## 8. 草稿、导航与焦点

在 `MusicTextController` 增加一个有类型的工具导航请求，目标仅含“音符详情/小节属性/小节线/连音详情/歌曲段落/歌曲复制范围”，内部复用现有SidebarAction与待处理意图。返回值沿用现有 `SelectionRequestResult` 的accepted/pending/blocked，其中pending表示等待原草稿确认；只有真正接受或后续确认成功后，才切栏目并在布局提交后focus。不得把“已打开草稿确认”报告成导航成功。

- 粘贴草稿定位先打开所属预览Modal，等可见再focus；其他Modal/busy占用时返回阻止原因。
- 开浏览菜单不改TAB选区，不激活最近简谱/TAB目标。菜单中的Select/Input方向键、中文组合输入和文本撤销保留原生行为。
- 更多工具的入口列表支持Tab、Enter/Space、Esc；富控件区域使用正常表单/region语义，不把Input、Select塞进伪role=menuitem。
- 禁用按钮的Tooltip挂在可聚焦说明入口/包装上，并在组内提供可读原因；键盘不能只能靠hover得知禁用原因。已有快捷键描述继续引用editor-shortcuts，不新增未经实现的复制粘贴、保存或播放快捷键。
- Esc先关最内层Select，再关工具面板；组合输入时不关。Modal使用自己的关闭策略，保留阶段1帮助Esc修复，不能让保留portal抢走上层弹层事件。
- 关闭后恢复最近可见的触发器；跨断点原按钮隐藏时回到更多按钮或对应宽屏组按钮，不能聚焦display:none节点。点击外部表单关闭菜单时不抢走新输入焦点。
- 若激活的是将被隐藏的入口，布局变化后转到可见等价入口；若焦点位于仍可见的同一参数字段，保持原焦点和输入。

### 13.3 各工具的完整表达与提交时机

**小节。** 菜单按 05-09 排列：当前小节后新增 → 直接复制当前小节/所选连续范围 → 配置复制范围… → 删除当前小节 → 小节属性… → 段落标记…。单小节与范围直接复制的文案随真实选择变化，明确副本插入位置；不将两种复制误称为系统剪贴板。属性入口导航到选区详情，而不是要求用户在菜单内找齐所有字段。局部拍号/右边界按原即时命令语义提交；谱首反复独立显示当前值。05-11 保留六行边界选择、谱尾 Alert；不能只提供一个下拉框便勾选该画面完成。段落仅元数据，不增加谱面绘制；段落和可配置范围复用在详情中显示摘要及跳转，按 UI-D08 保留歌曲 Form 的唯一 owner。

**拍点。** 按 05-10 纵向排列拆分、合并、复制、目标前插入…、目标起覆盖…；另加谱层选项和当前剪贴板摘要。两个粘贴入口直接 prepare 对应模式，均只打开预览；Modal 内切模式重新规划。显示轨道、小节/拍点位置、选中拍数及“包含全部弦”，反向框选使用规范化顺序。失败的复制不覆盖上一次有效剪贴板，失败的预览不清掉载荷。

**音符与连音。** 音符当前休止/音符/混合状态取真实 Beat；无效或多拍时值不伪装成四分音符，无附点是实际可选项。混合音符/闷音只展示混合，不让高亮暗示全选区已同值。六比例显示完整比例与数量原因。05-03 详情采用“选择候选比例 → 应用 X:Y 连音”，选择本身零文档修改；待选比例属于稳定工具准备状态，不登记为音乐内容草稿。既有菜单快速应用保留，明确写“应用 X:Y”，复用同一命令 Adapter，不出现看似选择卡却立即提交的行为。选区变化时重新解析候选可用性，失效则清除待选并说明；仅断点/菜单开关不清除。真实当前组与待选比例分开高亮，删除当前组直接执行，合法 no-op 不增加历史。

**详情导航。** `selectionDetail` 使用音符/小节属性/小节线/连音的有类型判别值；栏目、详情和焦点在受保护请求被接受后一起更新。歌曲跳转需为 ScoreSettingsController 补充有类型字段定位能力；不能依赖文本查询/延时猜测 DOM。请求捕获 session 与目标 ID，确认完成后重新验证实体；实体已删则拒绝旧跳转并保留可读说明。已有原目标段落草稿保持原 measureId；不能为了显示新选区而重新绑定它。

普通命令成功后关闭所属菜单并恢复可见触发器；核心失败保留当前工具和可读错误；复制成功可留菜单便于继续粘贴。导航仅在 accepted 后关菜单；pending 时让原保护流程接管，不提前切栏目。Modal 打开前关闭工具浮层，Modal 的逻辑返回位置仍为原组/更多入口，不是已经隐藏的菜单内按钮。

### 13.4 预览、结构影响与登记的接线补充

代码依据：Shell `execute` 在 `NUMBERED_IMPACT_REQUIRED` 时尝试另开 `structure-impact` 并立即返回第一次失败；核心 `commands.ts` 的 `finalize` 对非 numbered 命令还会核对 `confirmedRemovedMarkIds`。因此 `PasteBeats.allowOverwrite=true` 和确认键并不能自动替代公共结构影响确认；当前单 Modal 宿主也不能在粘贴 Modal 内直接叠开结构 Modal。

控制器依赖须补齐 `getInteractionContext()`：返回 Shell 当前活动对象、编辑保护状态和有效目标；这些不是 store selection 或 `musicTextEditing` 单个布尔值能替代的。另注入稳定的命令 Adapter、drafts、modals 与 beforeAction；读取上下文使用最新 ref/getter，不捕获旧 render。store 变更由控制器订阅；Shell 接受活动对象/目标变更时同步通知控制器失效，不能只等下一次 apply 才检查，也不能仅等待 effect 更新。快照通过 useSyncExternalStore 消费；订阅、草稿登记和 Modal 请求必须随 session 释放。

实施采用以下契约，不改核心音乐规则：

1. 为本阶段动作增加命令 Adapter，明确提交来源及影响承接方。普通拆合/小节动作沿用公共确认；需要等待确认的调用以 Promise/完成回调返回最终 applied/no-op/cancelled/blocked/stale，而不是将“弹层已打开”当成功。原同步调用者保持兼容，不全仓改成异步接口。
2. 粘贴使用同一 Adapter 的“调用者承接影响”分支。收到 `NUMBERED_IMPACT_REQUIRED` 时不另开 Modal、不自动重试；在现有粘贴预览补充核心返回的删除/变更记号说明与 ID 快照，清除勾选，等待重新确认。确认后带 `expectedRevision`、核心返回的确认 ID 及原 `expectedConfirmationKey` 提交；仍要再次校验候选完整版本。新影响不得套用旧勾选。
3. `requiresConfirmation` 取核心计划；追加结构影响单独表示 `needsImpactConfirmation`，应用条件为两类所需确认均满足。取消、关闭叉号与“取消预览”等价且零修改；遮罩和 Esc 不取消。busy 时关闭、切模式、勾选与重复应用全部禁用。这里补齐原第 7 节未写清的叉号语义。
4. 控制器内部最少区分 idle/ready/planning-error/needs-impact/applying/stale，并维护候选 generation。所有回调绑定 generation、modal id、session；错误/取消/失效清确认，旧回调只能结束自己的请求，不得清掉后来创建的候选或发布到新会话。失败若版本已变，走 stale；版本未变才允许当前 Modal 内重新规划。
5. prepare 在 beforeAction 和目标保护真正完成后捕获快照；发生等待时不能拿等待前的 selection 当新目标。再次 apply 同步检查真实活动编辑对象、完整选区（含两端 trackId/measureId/beatId/string）、候选版本与 clipboardVersion；不是只比 focus beatId。
6. 候选发布为可用状态时同步登记唯一 beatPaste 草稿；若 Modal 打开被其他请求拒绝，回滚本次候选与登记并报告占用原因。取消/失效/会话释放同步注销；若采用 React hook，必须以同一控制器登记为权威，消除 prepare 到 effect 之间输出检查漏读的窗口。不要按 render 反复重发“当前版本”登记；候选模式/确认更新保持同一登记身份，解除函数只能注销自己的代次。
7. 输出继续被未完成预览阻止。候选自己的 apply 允许自身登记和自身 Modal，仍检查其他编辑保护；不能调用包含自身的全量输出闸门造成自锁。控制器与 Modal 共享一次应用的 busy 锁，草稿协调器的 apply 也必须走相同入口。
8. 自己提交成功引起 document/selection 更新时先按本次执行结果收尾，不能先弹“预览过期”。处理完成功后再允许新请求；宿主同步重入产生的另一个会话不得接收旧成功提示。成功焦点使用核心 nextFocus，取消/失败保留原选区；候选清除不删除剪贴板。

预览统计按 plan 原字段分别显示拍点、歌词、独立简谱、和弦、TAB 技巧及简谱记号；0 明确显示 0。`omissions` 是源复制时未带入的跨范围连接，`removedTechniques/removedNumberedMarks` 是目标清理，必须分开描述，不能相加后都叫“将删除”。“仅六线谱”不承诺目标简谱绝不会受公共时间结构影响，实际影响仍按 plan/核心结果展示。

### 13.5 技巧选择与既有编辑能力

按源码枚举固定集合：连接为 hammerOn/pullOff/slideUp/slideDown/tie；音高修饰为 bend/vibrato/naturalHarmonic/artificialHarmonic/tapping/trill；方向范围为 strum/arpeggio/pickStroke/palmMute/letRing。目录与参数类型共用同一份枚举映射，禁止两份手工列表漂移。

类型选择请求需区分“新增技巧”与“更改已有技巧类型”。点选谱面已有技巧后仍能更新/删除原 techniqueId；只有用户明确选择“新增”才清除编辑对象，不能让“下一步”误更新旧技巧或意外新建重复技巧。取消类型选择恢复进入前对象及全部参数。已选技巧被删除/换谱/撤销导致不存在时按实体重新解析，禁止仅凭旧 ID 继续更新。

选择 Modal 捕获会话和目标版本；外部改变目标或文档时失效，不能将临时类型交给新目标。afterClose 的参数交接先于普通焦点恢复，绑定 modal id 和一次性交接令牌；不能先恢复背景再异步抢焦点。普通取消则恢复可见组入口。重新选同类型保留方向/幅度/辅助品位；类型切换沿用已有默认值，不因渲染顺序重置无关参数。

本阶段保留原关系/范围解析：反向框选按时间排序、单点连接沿原同弦下一音规则，扫弦/琶音至少同拍多弦，范围技巧按真实两端；最终合法性仍交核心。适用性不足的类型仍展示全名和原因，“下一步”不能绕过必要目标校验；深层音乐校验失败在参数区显示。参数完整视觉延期到阶段 4，现有新增/更新/删除及所有参数回归不得延期。

### 13.6 弹层、输入与紧凑搜索

- `blocked` 拆成浏览能力、提交能力及原因，不将 musicTextEditing 直接传给整个工具宿主当禁开开关。TAB 专属动作须核验真实 active object；公共小节操作沿用明确小节目标和原保护；若来源为简谱活动对象，使用其 measureId，不把残留 TAB focus 当成目标，也不迁移 TAB 选区。暂存简谱、歌曲草稿不会因打开工具而被清掉；导航到 TAB 继续走 request。
- 初次进入工具输入/搜索/Modal 前取消等待中的品位输入及其 timer，零文档提交；不是仅清可见数字。等待 600ms 后也不能在背后提交旧品位。使用自己的搜索文本撤销和 Select 方向键，不能触发编辑器全局历史/导航。
- 未显示组同时 hidden/inert，排除 Tab 和辅助技术遍历；保留组件挂载不代表保留隐藏键盘入口。Select popup 属于组内逻辑交互，选项点击不得被外部点击判断提前关面板。Esc 优先交最内层；组合态检查组合事件与原生 isComposing，组合确认的 Enter 不执行搜索结果。
- 更多工具默认显示四组目录；按中文名/别名/快捷键描述过滤，不增加拼音依赖。空白搜索恢复目录；无结果显示可读 Empty 与清空入口。首次打开搜索获得焦点；Tab 顺序为搜索、可见结果、当前组表单。Enter 仅定位单个当前结果，多个结果不猜测执行，任何结果均不直接改音乐。
- 搜索切换组和宽窄切换保持参数 owner。隐藏 DOM 中的输入不能成为“返回编辑成功”的证明；焦点定位返回 accepted 要有真实可见元素。浏览器缩放/窗口改变后从容器 CSS 标记读取呈现模式，重新测量并 forceAlign；本机 AntD 6.4.4 的 Popover ref 已核对暴露 forceAlign，实际触发区域对齐仍需 S2-D 浏览器验证。对齐失败时仍保留同一内容 owner，不能通过重挂载修复。
- 清理旧 .toolPopover 的统一横排宽度、旧工具字体覆盖和无调用样式；音乐几何、命中、滚动和打印 CSS 按引用核查后保留。保持一份交互参数实例；允许多个无本地草稿的只读摘要消费同一控制器。
