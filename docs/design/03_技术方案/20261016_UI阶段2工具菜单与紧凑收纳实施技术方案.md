## 3. 模块、接口与状态归属

按 `codebase-design` 的 Module/Interface/Seam 原则，将版本核验和预览生命周期集中在一个 Module 内。普通按钮只发送意图，不要求每个调用方各自按顺序检查 session、剪贴板和确认键。

| Module / 拟文件 | Interface 与职责 | 状态归属 |
| --- | --- | --- |
| `EditorToolbar.tsx` | 组织历史、高频工具和高级入口，调用原 `onAction/execute` | 不复制音乐内容或预览草稿 |
| `editor-tool-catalog.ts`（拟新增） | 工具ID、组、中文名称、搜索词、快捷键引用和详情位置 | 静态元数据，不存命令闭包/文档快照 |
| `editor-tool-state.ts` | 从真实文档、核心选区解析和编辑保护派生 availability/current/summary | 纯派生；核心命令最终裁决 |
| `EditorToolPanelHost.tsx`（拟新增） | 四组入口与更多工具共用一份稳定弹出内容，负责开关和可见焦点 | openGroup、搜索词、导航意图 |
| `beat-paste-controller.ts`（拟新增） | 准备/模式/确认/应用/取消及失效，接受 store 和命令 Adapter | 复制偏好、候选、捕获版本和确认状态的唯一 owner |
| `BeatToolbar.tsx` / `BeatPastePreview.tsx`（后者拟新增） | 菜单表达与受控预览表单，消费同一控制器 | 不再各存 preview/confirmed 副本 |
| `NoteToolDetails.tsx`（拟新增）、`TupletToolbar.tsx` | 选区栏目详细状态，调用共享动作 | 只读状态；无需独立内容草稿 |
| `TechniqueToolbar.tsx` / `TechniqueTypePicker.tsx`（后者拟新增） | 稳定参数 owner 和分组类型选择；使用原 buildDraft/submit/remove | 参数不受菜单、断点、搜索结果的挂载影响 |
| `MusicTextSidebar.tsx` | 原 request 闸门加工具详情/歌曲字段导航 | 原有栏目、目标和草稿继续在这里管理 |
| `editor-modal-controller.ts` / `EditorModalHost.tsx` | 新增有类型的 `beat-paste`、`technique-type` 请求，复用单一宿主 | 统一 busy、版本、取消与 afterClose 焦点 |

不另建全局工具 Zustand store。预览控制器在稳定的 `EditorToolbar` 层创建一次，由上层现有session key控制生命周期；Runtime继续提供同一草稿协调器和Modal宿主。依赖通过 Interface 注入，会话替换整体清理。注入的命令Adapter使用稳定回调并在执行时读真实session，不捕获旧render的selection/document；不能每次render重建控制器或积累订阅。订阅清理与会话卸载绑定。

宽窄视图在真实的 Seam 上只改变入口和呈现，调用同一组动作。不能复制两份 BeatToolbar、两份技巧 Form 或两个预览控制器，再用 CSS 隐藏其中一份。

## 4. 宽窄入口与稳定呈现

### 4.1 布局规则

| 编辑器容器宽度 | 工具带 | 详细区域 |
| --- | --- | --- |
| `>=1200px` | 历史 → 音符/附点/闷音/休止/恢复/删除 → 小节/拍点/连音/技巧 | 344px侧栏；音符/连音详情进入选区栏目 |
| `900–1199px` | 同样四组入口；允许受控换行，不能剪掉入口 | 沿用阶段1上下分区 |
| `<900px` | 高频工具保留；四个高级入口收为“更多工具” | 同一选区/歌曲 owner 在底部；更多工具可搜索、可键盘到达 |

恢复、删除、双附点不能因原紧凑 PNG 没画全而消失。常规768宽首先保留整组高频工具；更低可用宽度允许工具带内部换行/滚动，禁止页面横向溢出。高级四类只显示一个“更多工具”入口。

继续使用阶段1的 CSS 容器查询作为唯一断点来源。需要 JS 更新 popup 锚点或焦点时，从触发区计算样式中的布局标记读取当前呈现方式，不再维护另一份900/1200阈值。

### 4.2 弹出内容保持

采用一个稳定的高级工具弹出宿主，宽屏四按钮和紧凑更多按钮都调用 `open(group, actionId?)`。Popover 包裹稳定触发区；宽屏打开时按被点击按钮相对触发区的偏移对齐，紧凑时对齐更多按钮。使用现有 AntD 的 align/溢出调整与公开 ref.forceAlign，不引入新的浮层定位依赖。

弹出内容首次挂载后保持同一父级和顺序；组切换使用 hidden，不更改会话/参数/草稿 key。字段 owner 必须先提到稳定层，再接入新容器。位置偏移只依据真实 DOM 尺寸，不按截图像素写死；滚动/断点变化时重新对齐。

更多工具的搜索仅过滤入口目录：按“小节线/拍号/复制/覆盖/连音/推弦”等词定位组及动作。选择搜索结果只打开相应区域并聚焦，不立即执行删除、粘贴或改时值。搜索过滤不能卸载参数视图或清空草稿；禁用项仍可被查到，并显示原因。

## 5. 工具规则与当前值

### 5.1 通用约束

- 区分 TAB 选区、独立简谱目标、可见栏目、浏览器焦点。激活简谱不能使用残留 TAB focus 执行拆合、TAB连音或技巧；本阶段沿用 `musicTextEditing` 并补足调用前目标检查。
- “可以浏览工具”与“可以提交音乐”分开。无选区、文字编辑中允许打开解释和查找入口；修改动作 disabled。Modal活动/处理中不能打开另一个工具弹层。
- availability 的硬条件只用核心 resolver、实体是否存在和白名单。容量、Tie完整性、部分Tuplet等仍由核心检查；不在每次render中对所有技巧/动作执行完整文档预演。
- 每次音乐动作先取消等待中的品位输入，再读取最新目标；禁用与说明一致。既有真正提交命令复用 Shell/核心，成功一条历史，失败/no-op不新增历史。
- `isOutputBlocked()` 只负责输出，不能成为预览自己的应用按钮的 disabled。自己的预览登记和自己的Modal不得把应用入口锁死。

### 5.2 入口矩阵

| 动作 | 必要条件与显示 | 最终分派 |
| --- | --- | --- |
| 时值/0–2附点 | 合法单拍，可多弦；显示真实 base/dots，多拍不给伪当前值；所属TAB连音限制明确提示 | `SetBeatRhythm` |
| 闷音/删除所选音符 | 合法TAB单元格范围；删除只清所选弦音符 | 原矩形命令 |
| 休止/取消休止 | 合法拍范围，作用整拍全部弦；混合范围显示“混合状态” | `SetBeatKindRange`；取消休止不恢复旧音符 |
| 新增/删除小节 | 唯一目标小节；仅剩一个小节时禁删 | `InsertMeasure` / `RemoveMeasure` |
| 直接复制小节 | 连续小节范围；复制到所选范围末小节之后，明确这是新建副本 | `CopyMeasureRange`；不是系统剪贴板 |
| 局部拍号 | 合法focus小节、现有四种白名单；显示影响至下一拍号变化点 | `SetTimeSignature(untilNextChange)`；不同于歌曲基础拍号 |
| 小节线 | 合法focus；六类中文全名+图形，反映核心真实边界 | `SetBarlineBoundary` |
| 谱首反复 | 只有第一小节；独立“无/开始反复” | 同命令的 trackStart；不伪造前一小节 |
| 拆分拍点 | 合法单拍；拒绝部分连音等情况时显示核心原因 | `SplitBeat` |
| 合并拍点 | 同小节连续多拍，结构入口条件满足；休止/Tie规则交核心 | `MergeBeats` |
| 拍点复制 | 同小节连续范围，明确“双谱/仅六线谱”，均含所选拍全部弦 | store.copyBeats；复制不进入音乐历史 |
| 插入/覆盖粘贴 | 有有效拍点剪贴板和TAB目标，再由核心规划 | `planBeatPaste` → `PasteBeats` |
| TAB连音 | `resolveTupletSelection`成功，成员数符合actual；六比例始终可见 | `SetTuplet` / `RemoveTuplet` |
| 技巧选择 | 可浏览全部16类，显示当前目标适用性；添加/更新仍走原buildDraft | 技巧原命令，不用于独立简谱 |

谱尾右边界禁用“开始反复/双向反复”，其余类型按核心规则；普通边界的规范化及相邻小节同步由核心处理。unsupported当前拍号只读显示，不自动改成4/4。连音2:3、3:2、4:3、5:4、5:3、6:4使用既有资产并保留完整比例文字；非法混合时值/重叠/嵌套不能被UI强制通过。

### 5.3 详细状态与小节字段

音符与TAB连音详情显示在“选区”栏目，符合03-08/05-03的区域关系；工具带保留快速入口。详细面板只是同一动作的另一个 Adapter，不另存音乐值。切到此栏目必须走原 request 闸门；被草稿/IME阻止时保留原栏目，不能先改 activeKey。

小节菜单展示目标小节、当前段落摘要、局部拍号和右边界。“编辑段落标记”“配置小节范围复制”经原保护流程定位歌曲 Form 的已有字段；直接复制当前范围仍是单独快捷动作。本文登记 **UI-D08：小节局部字段复用歌曲owner**，避免在菜单维护第二套段落/复制草稿。原标记dirty时仍绑定原measureId，不能为跳转方便迁到新选区。

## 6. 拍点粘贴：准备、确认、提交与失效

### 6.1 控制器 Interface

控制器接受真实session、统一execute和beforeAction依赖；调用方通过一个意图入口操作。以下是拟实现的Interface形状，不是当前已导出的接口：

```ts
type BeatPasteIntent =
  | { type: "prepare"; mode: "insert" | "overwrite" }
  | { type: "mode"; mode: "insert" | "overwrite" }
  | { type: "confirm"; checked: boolean }
  | { type: "apply" | "cancel" | "focus" };

// getSnapshot返回不可变快照，只有真实状态变化才替换引用。
// request内部完成校验，外部不能直接设置candidate或绕过确认。
// getSnapshot / subscribe / request组成控制器唯一公开Interface。
```

复制谱层偏好保留在同一稳定工具owner中，但剪贴板实际谱层以 `getBeatClipboard().layers` 为准。改变“下次复制的谱层”不会改写已复制载荷；要换谱层需重新复制。预览内不提供一个伪装成能转换现有剪贴板的谱层开关。

### 6.2 候选快照

prepare捕获：完整EditorSessionVersion、clipboardVersion、规范化TAB选区/目标引用、一次读取的BeatClipboard副本、mode、成功核心plan及confirmationKey。字符串ID用于定位，不能代替完整版本；clipboardVersion当前也会随另一类剪贴板更新，保守失效可以接受，但不能漏检拍点载荷变化。

草稿记录的version直接使用这次候选捕获的版本，不能在重渲染时改成“当前版本”，让旧候选获得新的有效期。原父级BeatToolbar的版本/选区key在显式失效机制通过测试后移除；owner只随真实session key重建。

展示模型直接取核心 `BeatPastePlan`：count、durationLabel、replacedBeats/Lyrics/Numbered/Chords、removedTechniques/NumberedMarks、effects。单列“仅六线谱/双谱”，区分新复制内容与目标被替换内容；跨范围遗漏取clipboard.omissions/numberedOmissions及effects，不自己推算音乐时长或记号数量。

### 6.3 状态转换

| 事件 | 结果 | 文档/历史 |
| --- | --- | --- |
| 无载荷/无目标/核心规划失败 | 菜单内可读错误，不创建可应用候选或打开空Modal | 不变 |
| 成功prepare | 打开统一预览Modal，登记一条beatPaste草稿，confirmed=false | 不变 |
| 插入↔覆盖 | 对捕获目标重新规划、替换候选及确认键，清除确认；失败保留可读错误并禁用应用 | 不变 |
| 需要覆盖确认但未勾选 | 应用禁用，给出理由；只使用核心requiresConfirmation | 不变 |
| 应用 | 再核完整版本、剪贴板版本、目标及核心plan/key；有效才提交一次PasteBeats | 成功一条历史 |
| 核心提交失败 | 保留Modal与错误，允许取消；清除旧确认，重新规划后再确认 | 无部分修改 |
| 取消预览 | 清候选/确认和草稿登记，保留剪贴板及复制偏好 | 不变 |
| 关闭工具菜单/切高级组/宽度变化 | 保留owner；未进入Modal的参数不重置 | 不变 |
| 文档/undo/redo/宿主换谱/目标或剪贴板变化 | 候选失效、清确认；关闭旧Modal并显示“请重新预览”，解除旧草稿登记 | 不提交 |
| 密度/指法图/滚动变化 | 继续使用同一有效候选 | 不变 |

失效提示可以保留旧摘要用于说明，但旧摘要不是可应用草稿，不得永久阻塞输出。宿主换会话后旧回调不向新会话写错误。busy内自己的成功命令造成版本变化，应按成功结果关闭，不能被订阅误当成外部失效。

确认在真正execute前完成最后核验，核心再用expectedConfirmationKey拒绝过期计划；不靠同revision或同文档ID判定有效。store的宿主回调同步重入后，不追加第二条命令或自动重新打开旧预览。成功后撤销必须同时恢复音乐内容与关联影响。

## 7. 类型选择与弹层接线

技巧类型选择按PNG分为音符连接5类、音高修饰6类、演奏方向/范围5类，共16类。选择器只持有本次临时type；“下一步：参数”才写回稳定参数owner、关闭选择Modal并打开既有参数区域，不在选类型时提交AddTechnique。取消或Esc丢弃本次临时选择，保持进入前的类型和参数。

已有方向、半音/全音、辅助品位、关系音符和范围参数继续可用；重新开菜单、更多工具搜索或宽度变化不重置。`selectedTechniqueId`改变所表达的编辑对象时，仍沿用原有明确重载语义。类型/参数属于工具准备状态，不能未经设计就全部注册为音乐内容草稿，影响现有输出行为。

`EditorModalRequest`扩成有类型的判别联合：旧help/structure请求保持兼容；beat-paste请求引用稳定预览控制器，technique-type请求引用受控选择意图。禁止加入任意HTML字符串、eval或与领域无关的万能弹层注册系统。Host只渲染、处理busy/关闭和焦点，不读取核心文档拼命令。

预览切mode的动态摘要由同一控制器订阅更新，不另复制到Modal message。预览应用复用controller.confirm路径的busy锁；成功才能关闭，失败保留。Modal活动时禁用背景工具和历史快捷键，单一宿主不能被另一个请求覆盖。

粘贴确认类Modal的遮罩/Esc不取消，通过“取消预览”明确退出；技巧选择是非提交选择器，提供关闭/取消并允许非组合态Esc。下一步交接使用一个绑定modal id与session的意图，afterClose后再聚焦参数，不叠加第二个Modal。公共结构影响确认的完整视觉迁移仍留阶段4，现有回调不被绕开。

## 8. 草稿、导航与焦点

在 `MusicTextController` 增加一个有类型的工具导航请求，目标仅含“音符详情/连音详情/歌曲段落/歌曲复制范围”，内部复用现有SidebarAction与待处理意图。返回值沿用现有 `SelectionRequestResult` 的accepted/pending/blocked，其中pending表示等待原草稿确认；只有真正接受或后续确认成功后，才切栏目并在布局提交后focus。不得把“已打开草稿确认”报告成导航成功。

- 粘贴草稿定位先打开所属预览Modal，等可见再focus；其他Modal/busy占用时返回阻止原因。
- 开浏览菜单不改TAB选区，不激活最近简谱/TAB目标。菜单中的Select/Input方向键、中文组合输入和文本撤销保留原生行为。
- 更多工具的入口列表支持Tab、Enter/Space、Esc；富控件区域使用正常表单/region语义，不把Input、Select塞进伪role=menuitem。
- 禁用按钮的Tooltip挂在可聚焦说明入口/包装上，并在组内提供可读原因；键盘不能只能靠hover得知禁用原因。已有快捷键描述继续引用editor-shortcuts，不新增未经实现的复制粘贴、保存或播放快捷键。
- Esc先关最内层Select，再关工具面板；组合输入时不关。Modal使用自己的关闭策略，保留阶段1帮助Esc修复，不能让保留portal抢走上层弹层事件。
- 关闭后恢复最近可见的触发器；跨断点原按钮隐藏时回到更多按钮或对应宽屏组按钮，不能聚焦display:none节点。点击外部表单关闭菜单时不抢走新输入焦点。
- 若激活的是将被隐藏的入口，布局变化后转到可见等价入口；若焦点位于仍可见的同一参数字段，保持原焦点和输入。
