## 1. 目标与范围

### 1.1 目标

本次重构严格对照现有 UI 设计稿，重构六线猫的**编辑工作区**，重点解决工具密度、属性面板层级、编辑态反馈、草稿保护、谱面选区、导出状态和窄窗口布局的一致性问题。

重构必须满足两个前提：

1. 设计稿只改变 UI 组织、视觉和交互表达，不改变已经存在的音乐领域语义。
2. 已有功能必须保留；若设计稿示例与当前领域模型、命令约束或无障碍行为冲突，不能静默删减，必须登记缺陷、采用可解释的替代方案，并在最终验收稿中说明。

## 3. 设计到代码映射

### 3.1 页面骨架

设计稿的编辑器页面固定拆成五个区域：

1. **应用头部**：品牌/返回/曲谱标题/保存与导出入口。管理和保存业务按钮本轮只保留现有文件与图片导出入口，不新增曲谱库动作。
2. **编辑工具带**：撤销/重做、节奏与附点、休止、拍点结构、小节、连音、技巧、视图和文件/图片操作。
3. **状态反馈带**：位置、选区统计、草稿/影响/错误/布局提示。
4. **谱面工作区**：A4 纸张、SVG 音乐场景、选区/hover/focus 层和独立滚动。
5. **属性侧栏**：选区、段落、和弦、歌曲四栏目；面板内部控件保持挂载稳定，不能用断点切换卸载草稿 owner。

第一阶段先完成 2–5 的结构和样式；应用头部只在当前已有能力范围内整理，不引入管理/保存库语义。

### 3.2 属性侧栏四栏目

| 设计栏目 | 现有内部目标          | UI 内容                                       | 保留要求                                               |
| -------- | --------------------- | --------------------------------------------- | ------------------------------------------------------ |
| 选区     | TAB selection / focus | 位置、弦/拍/小节、范围统计、当前工具可用性    | 只读展示不写历史；不把简谱焦点伪装成 TAB 选区          |
| 段落     | `lyric` / `numbered`  | 歌词、简谱子页签、添加行、单拍/连续模式、预览 | 保持简谱独立目标和 A/B 草稿暂存                        |
| 和弦     | `chord`               | 名称、显示方式、预设、六弦表、横按、预览      | 图名清除与删除标记分开；校验失败不提交                 |
| 歌曲     | `score`               | 歌曲信息、基础拍号、Capo、段落标记、小节复用  | 表单草稿与已应用文档分离；多个表单组应用必须先整体规划 |

Tabs 的 `activeKey` 由业务状态受控。请求先经过 `MusicTextSidebar.request` 或新的等价协调器，只有请求被接受后才改变视觉 active 状态。

### 3.3 顶栏工具分组

工具不再以单层平铺方式堆满一行，按以下组拆分：

| 工具组     | 内容                                             | 设计稿来源                    | 行为要求                                        |
| ---------- | ------------------------------------------------ | ----------------------------- | ----------------------------------------------- |
| 历史       | 撤销、重做                                       | 03-01、03-06                  | disabled 原因可理解，快捷键保持                 |
| 音符       | 全/二/四/八/十六/三十二分、附点、闷音、休止/恢复 | 03-08                         | 单拍/范围禁用规则来自核心命令                   |
| 小节与拍点 | 拆分、合并、复制、插入/覆盖预览、小节线、拍号    | 03-05、05-01、05-02、05-09–11 | 预览独立呈现，确认后一次提交                    |
| 连音       | 2:3、3:2、4:3、5:4、5:3、6:4、删除               | 05-03                         | 显示当前选区数量和不可用原因                    |
| 技巧       | 16 类选择、参数、添加/更新/删除                  | 05-04–08、05-12               | 按 Note/Beat/范围展示不同参数，方向术语保持准确 |
| 视图       | 紧凑/舒适、和弦图显示、快捷键帮助                | 03-06、03-07                  | 视图偏好不进入音乐历史                          |

高频音符工具保持一行优先；其余组在窄窗口进入 Dropdown/More 菜单，但菜单必须能键盘访问、保留 disabled 原因和当前状态。

## 4. 状态与数据契约

### 4.1 三层状态不可混合

1. **领域文档状态**：由 `editor-store.document` 和 core command 更新，进入音乐历史。
2. **编辑草稿状态**：歌词/简谱/和弦/歌曲设置/品位输入/粘贴预览等尚未应用的内容，由稳定组件或会话协调器持有。
3. **瞬时视图状态**：active tab、hover、焦点、滚动、选中的技巧/简谱标记、图片预览进度，不进入音乐历史。

设计稿迁移不能通过重新挂载面板清理第 2 层状态。断点变化、Tabs 切换和 Modal 开关必须保持 draft owner、目标 key 和输入焦点意图。

### 4.2 草稿保护

必须保留并扩展现有保护语义：

- 当前草稿未应用时，切换其他编辑类型先提供应用/放弃/继续编辑。
- 简谱目标 A → B 可以暂存 A 并切换到 B，不统一弹三选项；返回 A 恢复 raw 文本、模板、时值、范围、覆盖设置和 item 草稿。
- 多处简谱草稿存在时，输出、文件替换和未来导航必须列出具体位置，不能用一个布尔值代替。
- IME composition 期间不提交、不切模式、不切目标。
- 应用失败、确认过期或文档发生变化时保持原草稿和原目标，不执行后续导航。

### 4.3 命令边界

React 组件只负责：

- 读取稳定目标和当前文档。
- 生成表单草稿和用户可理解的预览。
- 调用 core planner/command。
- 展示错误、影响和确认。

React 组件不得负责：

- 自行展开小节/拍点时间。
- 自行决定简谱与 TAB 的对齐或事件归属。
- 自行删除或迁移记号而不经过影响规划。
- 通过循环调用多个 command 冒充原子批量事务。

## 5. 视觉实现约束

### 5.1 Ant Design 基线

使用当前安装的 Ant Design 6.4.4 和 `@ant-design/icons`：

- `ConfigProvider` 统一 locale、主题和 token。
- 通用按钮使用 `Button`，图标按钮必须有 `Tooltip` 和 `aria-label`。
- 表单使用 `Form`、`Input`、`InputNumber`、`Select`、`Segmented`、`Checkbox`、`Switch`。
- 状态使用 `Alert` 或带语义颜色的状态区，不用孤立色块。
- 结构确认、快捷键帮助、文件确认和影响预览使用受控 `Modal`；保留焦点约束、Esc 取消和 busy 锁定。
- Tabs 不销毁未激活面板；不使用销毁面板替代草稿恢复。
- AntD 6.4.4 使用支持的 `size="small|medium|large"`；不使用已废弃的 `middle`。

音乐专用图标继续使用 `MusicAssetIcon`、Bravura 和核心 scene；不能以通用图标替代音符、连音或技巧符号。

### 5.2 视觉 token

| Token          | 值                                |
| -------------- | --------------------------------- |
| 主操作         | `#285BE0`                         |
| 正文           | `#202838`                         |
| 次级文字       | `#626E82`                         |
| 工作区背景     | `#F4F6FA`                         |
| 容器背景       | `#FFFFFF`                         |
| 边框           | `#D9D9D9`                         |
| 成功/警告/危险 | `#19734F` / `#92600C` / `#BC3547` |
| 控件高         | 24 / 32 / 40                      |
| 圆角           | 控件 6，面板/Modal 8 以内         |

必须保留字体、字重、间距、禁用态、focus ring、错误态和提示态的可见差异。重要正文和说明文字目标对比度不低于 4.5:1。

### 5.3 谱面视觉边界

- 谱面数字、歌词、简谱、和弦和记号不铺不透明白底块，只使用核心计算的白描边净空。
- 单格焦点使用细轮廓，范围使用薄蓝叠层和端点柄；hover 弱于 focus，不覆盖正式选区。
- TAB 符干靠近最下方品位数字，不停在最下方弦线外；实际几何由 layout 提供。
- 简谱不显示 TAB 专用 H/P 和 TAB 技巧关联线；简谱的时值、连梁、八度点、升降号、连音和连线独立绘制。
- 编辑空位、焦点、hover 和选区不进入 presentation/PNG。

### 7.1 缺陷编号

登记字段：

| 字段     | 要求                                                         |
| -------- | ------------------------------------------------------------ |
| 编号     | 稳定 ID，例如 `UI-D01`                                       |
| 画面     | PNG 路径和状态名称                                           |
| 设计要求 | 原图/文字规格的准确描述                                      |

### 7.2 当前预登记风险

以下问题实施时必须确认，暂不直接判定为最终缺陷：

- 设计稿将多个高频工具压在单层顶栏，窄窗口需要改为分组/更多菜单，否则会导致操作不可达。
- 设计稿中的固定像素谱面间距不能覆盖当前核心 layout 的字形测量和独立简谱节奏；必须优先保证命中和对齐。
- 设计稿部分简谱画面可能暗示统一应用动作，但当前命令区分音组内容、成员时值和单 item 音高，不能合并为一个未定义按钮。
- 原生 `dialog` 的视觉可以迁移到 AntD Modal，但焦点、IME、文档版本和确认过期语义必须保留。
- 设计稿某些面板在 1024/768 断点下视觉上像是重新挂载；实现不能因此清掉草稿或重置目标。

若确认这些是设计稿缺陷，必须在最终验收稿中按编号列出，说明保留的能力和视觉差异。

## 11. 2026-10-15 回溯复审结论

### 11.1 总体可行性

本方案整体**可落地，但不是直接替换 CSS 或逐个替换原生按钮的低风险任务**。现有代码已经具备领域命令、核心 layout、命中测试、草稿状态和图片输出基础，因而不需要重写音乐算法；但要达到设计稿要求，必须先补齐 UI 宿主层的状态和生命周期契约。

可行性分级：

| 范围                                               | 可行性 | 结论                                                                     |
| -------------------------------------------------- | ------ | ------------------------------------------------------------------------ |
| Ant Design 主题、工具分组、Tabs、Tooltip、表单外观 | 高     | 可在现有组件边界内实施，不需要改 core                                    |
| 歌曲/歌词/和弦表单迁移                             | 高     | 需要保留现有 draft 与 command planner，表单只替换视图层                  |
| 简谱独立属性与多状态                               | 中高   | core 能力已存在，但必须补稳定草稿协调和目标恢复测试                      |
| 技巧/拍点/小节结构状态                             | 中高   | 命令和 planner 已存在；影响确认、过期预览和弹层焦点需要统一宿主          |
| 图片导出四态                                       | 高     | 现有 controller 已有取消、字体变化和会话失效逻辑，主要是 Modal/布局迁移  |
| 1024/768/650px 响应式                              | 中     | CSS 可实现，但必须经过真实浏览器截图和键盘路径验收，不能只靠静态样式判断 |
| PNG 级谱面几何逐像素复刻                           | 不承诺 | 设计稿是静态表达，正式几何必须以核心 layout、字形测量和命中边界为准      |

### 11.2 必须先冻结的五个基础契约

#### A. 顶部“保存”不能伪造

设计稿顶部有保存语义，但本轮明确不实现曲谱库保存和保存控制器。因此编辑工作区顶部只能呈现当前已有的 JSON 导出、A4 图片导出和编辑状态；不能放置一个点击后无真实持久化效果的“保存”按钮。

如需保留视觉位置，必须使用“导出曲谱”或“导出图片”等真实动作，并在 `UI-D01` 中记录设计稿与本轮业务范围的差异。

#### B. 全量草稿不能继续只用布尔闸门

当前 `MusicTextController.isOutputBlocked()` 只能回答“是否阻止输出”，不能提供多草稿位置、错误、应用能力和恢复焦点。阶段 3 的表单迁移和阶段 5 的图片输出都依赖下列最小宿主接口：

完整契约统一见第 18.2 节。草稿类型统一使用 `beatPaste`，动作统一通过异步 `request` 分派，避免旧版 focus/discard/discardAll 接口与完整契约同时维护。

首版不实现“自动应用全部草稿”。输出、文件替换或离开时，若有多处草稿，应列出位置并逐项返回处理；全部处理完成后重新发起原动作。

#### C. 面板和 Modal 必须有稳定 owner

`Tabs`、响应式上下分区和 Modal 迁移不能通过卸载 React 子树来清理状态。每个表单/编辑器实例必须以稳定目标 key 挂载，至少保留：

- 业务目标身份：TAB cell、lyric verse、numbered event/item/time window、chord beat。
- draft raw 值、模板、范围、覆盖设置和错误。
- pending action、焦点目的地、IME 状态。
- 当前文档 `stateVersion/sessionVersion`，用于拒绝迟到提交。

#### D. 所有影响确认必须绑定文档版本

结构修改、简谱记号迁移、拍点粘贴和技巧影响确认都必须带：

- 预览生成时的文档引用/版本。
- 受影响对象的稳定 ID。
- 重新规划所需的原始命令输入。

确认时若文档或会话版本变化，Modal 关闭当前确认并提示重新预览；不得把旧的 `confirmed` 状态直接提交。

#### E. 谱面视觉只能校准 scene/layout，不能由 UI 重新绘制

PNG 中的 2px/3px 间距、端线高度和字形位置只能作为视觉目标。正式实现必须继续使用：

- `buildLayout` / `score-scene` 的坐标。
- 字体实际测量和音乐资源。
- `hitTestLayout`、`hitTestMusicText` 和现有 selection geometry。

如果 PNG 与核心 layout 冲突，优先保证音符可读性、命中准确性、TAB/简谱同 tick 对齐和成品输出一致，并登记 `UI-D02`，不能用 transform 视觉补偿破坏命中。

## 13. 设计稿逐组回溯补充

### 13.1 `03 · 编辑工作台` 的遗漏处理

- 默认态需要补充“应用头部不显示伪保存按钮”的约束。
- 两位品位草稿必须同时验收：输入中可见、600ms 后提交、切换/取消不迟到提交。
- 范围选择需要在属性面板显示作用范围和混合值；单拍专用时值/附点在多拍范围明确禁用。
- 歌曲设置的五个表单组必须保持独立提交语义，不能为了 Form 统一提交而改变历史粒度。
- 视图与排版中的紧凑/舒适是视图偏好，不进入音乐 command history；`editing/presentation` 是内部用途，不暴露成用户开关。
- 快捷键帮助必须显示真实当前快捷键，不允许文案与 `editor-interaction.ts` 分叉。

### 13.2 `04 · 歌词简谱与和弦` 的遗漏处理

- 歌词单拍 Enter/Shift+Enter 语义、连续预览跳过项、覆盖项和谱尾整批拒绝要逐项保留。
- 简谱必须把“应用音组内容”“应用当前音符时值”“应用单 item 音高”拆成明确动作；不能统一成一个“应用简谱”。
- 简谱 A→B 是暂存/恢复，不是普通三选项保护；其他编辑类型切换仍经过保护。
- 简谱缩短时值产生空位，空位不是休止；扩展时值若覆盖部分事件或 Tuplet 必须拒绝并保留草稿。
- 和弦清除指法图、删除整个和弦标记、改名称必须是不同动作；预设只在标准调弦下可用，非标准调弦仍能查看/编辑。

### 13.3 `05 · 技巧与小节结构` 的遗漏处理

- 16 类技巧选择器不能只显示名称；每种类型的目标范围、方向、幅度和辅助品位必须由领域规则决定。
- 小节线六类值、谱首开始反复、谱尾禁用和当前小节边界必须在 UI 中可解释。
- 拍点复制必须显式选择 `双谱/仅六线谱`；不能因 UI 默认值而复制简谱或技巧。
- 粘贴预览中的替换小节、歌词、简谱、和弦、技巧和简谱标记数量必须来自 core planner；不能由 UI 拼统计。
- 影响确认和撤销必须保持一次领域历史；取消和过期确认不写部分修改。

### 13.4 `06 · 图片导出与异常` 的遗漏处理

- 预览页缩略图点击只改变 inspected page，不修改音乐选区或文档。
- 生成中禁止关闭/绕过草稿和字体保护；取消后释放 AbortController、Blob URL 和迟到结果。
- 下载按钮只在编码成功且 URL 有效后可用；下载不改变曲谱保存状态。
- 预览与 PNG 必须消费 presentation scene，不能直接截图编辑 SVG。

### 13.5 `07 · 窄窗口适配` 的遗漏处理

- 1024 上下分区时属性表单实例不能重建，尤其不能清除简谱 A/B 草稿。
- 650px 高时固定动作栏不能遮挡输入框、预览底栏或错误提示；面板和谱面各自滚动。
- 768 紧凑模式必须保证所有能力仍有入口，隐藏到更多菜单的工具需要可搜索/可键盘访问。
- Dropdown/Select/Modal 的 popup 容器必须在滚动容器和遮罩层级下实测，不允许统一挂到可能被裁剪的父节点。

5. 未应用草稿、焦点和活动对象没有因组件重挂载而丢失。
6. 新发现的设计偏差已登记 `UI-Dxx`，没有把差异隐藏在 CSS 或文案中。

阶段 1 的最小交付不再只是“页面能显示”，而是：

- 默认态、歌曲设置、视图排版三个画面结构与稿一致。

- 1024/768 断点下歌曲设置切换不丢草稿。

## 17. 复审后的实施结论

本方案可以进入实施，但建议先按以下顺序落地：

1. 先建立 `EditorDraftCoordinator`、`EditorStatusBar`、`EditorModalHost` 的最小宿主契约和测试。
2. 再实施阶段 1 的编辑器骨架、顶栏分组和歌曲设置表单。
3. 阶段 1 通过真实截图和草稿/焦点验收后，再进入歌词、简谱和和弦表单迁移。

## 18. 基础契约补充：可直接编码的版本

### 18.1 契约 owner 与生命周期

| 契约                     | 创建位置                                                          | 生命周期                                                          | 不能做的事                                        |
| ------------------------ | ----------------------------------------------------------------- | ----------------------------------------------------------------- | ------------------------------------------------- |
| `EditorDraftCoordinator` | `EditorSession` 内带会话 key 的 `EditorSessionRuntime` 中惰性创建 | 当前 session 存活期间稳定；`replaceDocument` 成功后整体销毁并重建 | 不能由某个侧栏 Tab 私有持有；不能在断点变化时重建 |
| `EditorModalHost`        | `EditorSessionRuntime` 内部 context                               | 当前 session 存活期间稳定                                         | 不能让每个工具各自维护全局快捷键/焦点锁           |
| `EditorLayoutModel`      | `EditorShell` 根据 document/layout 派生                           | 跟随文档和 viewport 更新                                          | 不能把 CSS 断点写入音乐文档或历史                 |
| `EditorStore`            | 现有 session store                                                | 当前编辑会话                                                      | 不保存 UI 草稿、滚动、hover 和 Modal 状态         |
| `ScoreScene`             | 现有 layout/scene pipeline                                        | 由 document、density、presentation/editing 目的派生               | 不能由 UI 组件手动拼接音乐坐标                    |

`EditorSession` 仍然是会话边界。只有外部文件替换、会话替换或明确的文档重载才允许改变 `sessionVersion` 并销毁旧 UI；普通 Tabs、Modal、响应式分区和工具收纳都不得改变它。

### 18.2 Draft Coordinator 完整契约

以下为 2026-10-16 复审修订后的宿主契约；实际类型维护在 `editor-draft-coordinator.ts`，版本比较维护在 `editor-session-version.ts`：

```ts
type EditorDraftKind =
  | "fret"
  | "settings"
  | "lyric"
  | "numbered"
  | "chord"
  | "beatPaste";
type EditorDraftApplyResult = "applied" | "blocked" | "stale";
type EditorSessionVersion = Pick<
  EditorStoreState,
  "document" | "stateVersion" | "sessionId" | "sessionVersion"
>;
type EditorDraftAction =
  | { type: "focus" | "apply" | "discard"; id: string }
  | { type: "discardAll"; confirmation?: number };
type EditorDraftActionResult =
  | { status: "accepted"; discarded: number }
  | { status: "blocked"; reason: string }
  | { status: "stale" }
  | { status: "needs-confirmation"; ids: string[]; confirmation: number };

interface EditorDraftRecord {
  id: string;
  kind: EditorDraftKind;
  targetKey: string;
  label: string;
  dirty: boolean;
  composing: boolean;
  canApply: boolean;
  error: string | null;
  version: EditorSessionVersion;
  focus: () => boolean;
  apply: (context: {
    isCurrent: () => boolean;
  }) => EditorDraftApplyResult | Promise<EditorDraftApplyResult>;
  discard: () => boolean;
}

interface EditorDraftCoordinator {
  register(record: EditorDraftRecord): () => void;
  inspect(): {
    composing: boolean;
    busy: boolean;
    pending: EditorDraftRecord[];
  };
  request(action: EditorDraftAction): Promise<EditorDraftActionResult>;
  isOutputBlocked(): boolean;
  subscribe(listener: () => void): () => void;
  getSnapshot(): number;
}
```

实际 owner 映射：

| 现有状态                 | 注册 id 规则                                       | apply/discard 责任                                                             |
| ------------------------ | -------------------------------------------------- | ------------------------------------------------------------------------------ |
| `EditorShell.fretDraft`  | `fret:${trackId}/${measureId}/${beatId}/${string}` | 保留现有 600ms 自动提交器；首批协调器只汇总、定位和取消，不新增手动 apply 路径 |
| `ScoreSettings`          | `settings:${sessionId}`                            | 调用 `planSettingsCommands`，先整体预验证再逐命令提交；失败保持表单            |
| `MusicTextSidebar.draft` | `music:${kind}:${targetKey}`                       | 保留现有 lyric/chord apply 和 target 保护                                      |
| `numberedDrafts`         | `numbered:${numberedDraftKey}`                     | 每个 event/item/time window 独立暂存、恢复、丢弃                               |
| `BeatToolbar.preview`    | `beatPaste:${confirmationKey}`                     | 由 core `planBeatPaste` 重新验证，过期不得提交                                 |

注册规则：

1. dirty 为 false 的记录可以注册，但 `inspect()` 默认只返回 dirty、composing 或有错误的记录。
2. 登记时捕获 `document`、`stateVersion`、`sessionId`、`sessionVersion`；调用前比对完整版本，异步 owner 真正提交前再次调用 `isCurrent()`。成功提交自身引起的文档版本变化不能被误判为 `stale`；返回结果时仍拒绝会话已替换的迟到结果。
3. `discardAll` 首次返回待处理 ID 与目录版本确认 token；任何登记更新、单项处理或 token 消费都使旧确认失效。确认后返回实际丢弃数量；处理过程中若 owner 改变其他登记立即停止。首批不提供全量丢弃 UI，后续必须由明确确认弹层承载，不能静默清空。
4. 草稿内容继续由原 owner 暂存和恢复，协调器只登记能力与摘要；简谱 A→B 时原 owner 先保存 A 的输入及目标。相同 ID 的新登记替换旧登记，返回的清理函数仅能删除自己对应的登记实例；不再提供独立 `update` 方法。
5. 文件导入/导出和图片输出共用 coordinator 与原有即时检查，覆盖 effect 登记前的短暂窗口。面向用户的替换先通过输出闸门；宿主显式 `replaceDocument` 保留原有外部替换语义，成功后整个带 key 的 runtime 重建，不把旧草稿迁入新文档。

### 18.3 Modal Host 完整契约

```ts
interface EditorModalRequest {
  kind: "keyboard-help" | "structure-impact";
  title: string;
  message: string;
  version?: EditorSessionVersion;
  confirm?: (context: {
    isCurrent: () => boolean;
  }) => boolean | Promise<boolean>;
  onClose?: (reason: "cancel" | "resolved" | "stale") => void;
}
interface EditorModalController {
  open(request: EditorModalRequest): number | null;
  close(id: number, reason: "cancel" | "resolved" | "stale"): boolean;
  confirm(id: number): Promise<boolean>;
  invalidate(): void;
  restoreFocus(): void;
}
```

首批只接入快捷键帮助和公共结构影响确认，已有歌词/简谱/文件/图片弹层保留原 owner，后续按阶段逐个适配相应 kind。`ScoreFileCandidate` 等原草案中的占位类型不作为本批可编译契约。宿主保存请求版本和确认回调，领域命令与影响 ID 由调用方构造，避免宿主复制领域规划。

Modal Host 必须统一负责：

- 打开时记录触发元素，在关闭动画结束后恢复焦点；触发元素已移除时回退谱面，新弹层已打开时不恢复旧焦点。
- 确认类 Modal 禁止遮罩和 Esc 关闭，通过明确取消按钮退出；帮助弹层允许 Esc。busy 期间禁用取消、关闭和重复确认；背景编辑快捷键在所有活动 Modal 期间隔离。
- 待确认期间版本过期即关闭旧确认；busy 期间由提交前 `isCurrent()` 和确认结果判断，防止自己的成功命令触发误失效。旧会话异步回调不得向新会话写入错误提示。
- Modal 内的 Select/Dropdown 选择不被滚动容器裁剪。
- 取消只关闭 UI，不写领域历史；确认只允许 core command 成功后关闭。

### 18.4 布局与响应式契约

`EditorLayoutModel` 只输出布局模式，不持有业务状态：

```ts
type EditorLayoutMode = "wide" | "stacked" | "compact";

interface EditorLayoutModel {
  mode: EditorLayoutMode;
  showInlineToolbar: boolean;
  showMoreMenu: boolean;
  sidebarPlacement: "right" | "bottom";
  pageScrollOwner: "page" | "workspace";

```

目标尺寸：

- 1280×800：`wide`，谱面与侧栏并列。
- 1024×768：`stacked`，属性侧栏位于底部。
- 768×900：`compact`，非高频工具进入更多菜单，属性区保持可编辑。
- 任意目标高度 650px：工具、谱面和属性区独立滚动，底部动作不遮挡当前输入。

断点只改变 DOM/CSS 布局，不改变 `EditorSession`、draft record、target key、selection 或 history。
