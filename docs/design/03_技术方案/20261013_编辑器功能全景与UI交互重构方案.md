## 1. 分析依据与产品定位

依据当前工作区代码、MVP v5.1–v7 文档以及 localhost:3000 实际界面。工作区已有大量未提交改动，本方案以当前文件为准，不覆盖已有工作。浏览器实例与最新工作区可能存在更新时差，谱面细节以最新已授权方案及布局源码为准。

六线猫目前是单轨吉他谱编辑器：TAB 与简谱共用小节/拍号和联合时间网格，但简谱使用独立事件与时值；歌词和和弦仍锚定 TAB Beat。已有命令历史、原生文件导入/下载与 A4 图片输出，作品管理与播放尚未形成用户流程。

本轮目标：减少工具寻找和视线切换成本，明确当前编辑对象、操作作用范围、未提交草稿和结果反馈，让现有能力形成可理解、可连续使用的工作台。

## 3. 保留的功能边界

- 本轮以 UI 与交互重构为主。播放、音频输出、多轨、云端作品库、协作、账号与作品管理不纳入默认设计范围。
- 当前产品图片交付采用 PNG/ZIP；已有原生 JSON 文件导入/下载须保留，新作品库保存/打开属于新增业务层。已有成品打印投影不等于系统打印或纸张效果已验收，也不新增 PDF 承诺。
- 单小节重复记号仍是待审方案，不画成现有可操作工具。
- 最新谱行顺序：和弦名称/指法图 → 六线谱及节奏/技巧 → 简谱 → 歌词。不恢复已移除的谱面说明标签。
- 调弦入口、视图缩放、收起侧栏属于建议新增交互，需要在设计说明中明确标注；第一批以现有功能闭环为准。
- 跨边界技巧、连音合法性、时值容量等继续由核心命令决定，设计不会承诺领域模型不支持的操作。

## 4. 当前界面的问题与依据

### 4.1 工具缺少作用域层级

`EditorShell` 同一个可换行 toolbar 混合时值、拍点、小节、连音、技巧、视图与导出。初始无选区时大片禁用控件仍占空间；当前运行截图中工具已换成三行，随后还有较长快捷键说明。

建议将全局操作、常用输入、选区属性分层。工具状态不仅“可用/禁用”，还要解释“需要选中同小节三拍”等条件。

### 4.2 自适应切换过早占用高度

现有容器宽度低于 1320px 时，工作区切换上下布局，属性面板最多占约 45% 高度。实际 1280×720 界面下，大块属性面板与多行工具叠加，首屏谱面可视范围明显缩小。

建议常规笔记本仍优先右侧属性；更窄窗口改为可调整高度的底部面板，谱面与表单都可操作，打开属性不遮蔽全部目标拍。

### 4.3 全局设置与局部结构操作混杂

歌曲设置中包含段落标记与小节范围复制，顶栏又有小节复制，用户需要跨位置理解相同业务。基础拍号与当前小节拍号也容易混淆。

建议“歌曲设置”只承载歌曲/轨道属性，“小节”承载拍号、右边界与复用；段落字段暂按原语义保留，不用它创建谱面可视段落导航。

### 4.4 连续录入的阅读负担

歌词/简谱已有预览与事务保护，但语法说明、输入、覆盖开关与长表格同时铺开。两者的布局、动作位置、覆盖默认值不同，切换时需要重新寻找。

建议共用“起点 → 输入 → 对应预览 → 应用”视觉顺序；预览可滚动且保持标题与统计可见；覆盖默认行为保持原样并明确显示。

### 4.5 草稿保护需要可预期

现有保护是重要能力。移动工具后必须继续说明当前未应用内容；不能让切页签、选拍、撤销、关闭、导出分别呈现相互矛盾的草稿处理。

需要确认的切换使用“应用并继续 / 放弃并继续 / 继续编辑”。简谱目标之间切换改为暂存/恢复，不重复弹确认。保存/离开检查全部暂存目标，多处草稿逐项定位处理；无有效草稿时应用按钮禁用并解释原因；确认过程中不允许后台编辑绕过保护。

## 5. 建议的信息架构

采用浅色、专业、内容优先的记谱工作台。保留现有蓝色品牌语义，以白色谱面与低对比灰色工作区区分编辑内容和操作界面。

| 区域 | 内容 | 设计原则 |
| --- | --- | --- |
| 文档栏，约 52px | 六线猫、歌曲名称、撤销/重做、视图、快捷键帮助、导出图片 | 高频全局操作固定；宿主保存信息仅在有真实能力时接入 |
| 输入工具栏，约 48px | 时值、附点、闷音、休止；拍点/小节/技巧/连音入口 | 常用输入可直接点击；更多操作在明确分组中渐进展开 |
| 谱面工作区 | A4 编辑视图、选区、光标、同拍文本高亮、滚动 | 稳定保持谱面焦点，不因选择工具意外滚走目标 |
| 属性面板，约 320–360px | “当前选区 / 段落编辑 / 和弦 / 歌曲设置”；段落内部歌词/简谱 | 展示当前对象与位置；输入、预览和固定底部动作一致 |
| 状态栏，约 28px | 当前小节/拍点/弦、选区数量、输入草稿、操作结果 | 简短可见；详细快捷键与影响清单按需展开 |

上述尺寸是设计起点，制作设计稿时根据实际谱面和中文文本校准。优先比较 1440×900 与 1280×800，两者均需提供可工作的编辑面积；1024×768 提供底部属性分区；768 宽提供紧凑适配示意。手机完整制谱不作为本轮验收门槛。

属性页签与“当前选区”的新增组织方式需用户确认。本方案建议使用这四个入口，减少谱面工具和文本面板之间的往返。

## 6. 必须明确的交互契约

1. **TAB 输入**：选格后键入数字；待完成的两位输入显示在光标附近及状态栏；0–24 之外不写入；点击工具时按既有语义处理草稿，不能保存半截值。
2. **选区操作**：显示单格/多格/拍范围/小节范围；标明复制拍点包含全部六弦，即使当前只选择部分弦。时值不设计成多拍批量改值。
3. **技巧**：选择技巧类别后只显示所需参数；同弦关系类提示目标要求；点击已有技巧显示“更新/删除”，不与新增混淆；P.M. 与 x 用不同名称和图标语义。
4. **小节复制**：先选择来源范围及插入位置，给出“复制第 2–4 小节至第 8 小节后”；说明跨复制边界技巧可能遗漏；提交后可撤销。
5. **拍点粘贴**：插入/覆盖切换时重新预览；展示替换拍数、歌词/简谱/和弦数和技巧清理数；需覆盖确认时显式确认；目标改变使旧预览失效。
6. **歌词/简谱**：单拍与连续模式入口明确；预览点击位置与谱面高亮联动；语法错误和谱尾不足定位到对应项；批量失败不部分写入；应用成功是一条可撤销编辑。
7. **未提交草稿**：简谱目标间切换暂存/恢复；其他模式/页签/编辑类型切换经草稿保护；离开/输出处理全部缓存。聚焦输入不触发谱面数字与删除快捷键；IME 组合期间不误提交。具体接口缺口见最新复审第 5 节。
8. **导出**：有未应用草稿时定位到处理入口；打开后锁定已提交快照；预览准备、生成进度、可取消、成功下载、失败重试分别设计；关闭后恢复合理焦点。
9. **反馈**：字段错误靠近字段，操作结果在状态区；影响详情包含自动压缩时值及清理技巧等信息；撤销/重做入口全局唯一且显示实际可用状态。
10. **键盘可用性**：所有图标有文字标签与 Tooltip；Tab 可达；弹层 Esc 关闭并还原焦点；禁用原因不只靠颜色；表单与谱面历史按既有规则协调。

## 8. 视觉基础与制作约束

- 当前 UI 字体：Arial / PingFang SC / Microsoft YaHei；谱面还使用 Bravura 音乐字体及 Georgia/Times New Roman。Figma 字体以实际可用字体核对，不默认改用 Inter；若音乐字体不可用则使用已有可编辑 SVG 资产并记录替代边界。
- 从现有 CSS 颜色变量建立语义 token：背景、面板、文本、次级文本、边框、品牌色、选区、危险、警告、成功。新增尺寸与字阶作为重构设计 token 标明，不当作已有实现。
- 控件覆盖默认/悬停/按下/选中/禁用/焦点；表单覆盖空值/输入/未应用/错误；预览行覆盖新增/覆盖/保留/错误。
- 优先复用可用 Figma 设计库；无匹配库时建立本地组件与变量。先检查相关 Code Connect、目标文件已有组件、可用库，再开始页面制作。
- 可复用组件至少包括工具按钮、分组入口、Tabs、字段、目标位置标签、预览行、固定动作栏、消息、草稿确认、导出进度和页缩略图。

- 设计稿中所有关键按钮和文案保持中文；同类动作命名统一。

## 9. 可点击原型与验收

核心原型路径：

1. 默认工作台 → 选拍 → 品位/时值 → 修改技巧 → 查看影响 → 撤销。
2. 选拍 → 段落/歌词 → 连续录入 → 点击预览定位 → 应用 → 切简谱。
3. 选拍 → 和弦预设 → 改弦品位/横按 → 应用 → 隐藏/恢复指法图。
4. 选范围 → 复制拍点 → 覆盖预览 → 确认 → 应用 → 撤销。
5. 歌词草稿 → 切页签 → 三选项保护 → 返回或继续。
6. 导出图片 → A4 预览 → 生成全部 → 进度/取消或完成 → 下载图片包。

点击原型只演示有限场景，不执行真实品位输入、领域合法性计算或 PNG 编码；设计说明记录真实实现应遵守的规则。

验收标准：功能矩阵每行对应至少一个界面/说明；关键状态有明确动作；原型链接可达且能返回；中文文案无占位；选区/字段焦点清楚；常规笔记本可同时查看谱面和属性；整体 UI 由可编辑图层及组件构成；截图检查无溢出、重叠与错误字体；交付文件 URL、关键 frame 链接及覆盖清单。

## 11. 用户确认后的范围补充：新建、保存与曲谱管理

用户已确认前述方案，并明确要求加入三类业务界面。第 3 节中作品流程排除条款由此补充取代；以下为待实现的交互设计，不代表当前产品已有持久化功能。

- 曲谱管理作为入口：全部曲谱、最近编辑、收藏、分类；搜索歌名/作者，筛选与排序，卡片/列表视图；空库、无搜索结果、加载失败；曲谱打开、重命名、复制、删除确认与结果反馈。
- 新建：填写曲谱名称、作者、调性、基础拍号、Capo 与初始小节数；默认标准六弦吉他；创建后进入编辑器，新曲谱显示“尚未保存”。调弦的高级配置作为独立扩展提案，不改变默认创建路径。
- 保存：手动保存；首次保存核对名称与分类；后续更新当前曲谱；保存中、成功、失败重试、名称冲突；不显示虚假的云端同步状态。曲谱内容保存包含音乐数据，指法图显示/排版密度等视图偏好与内容保存分开说明。
- 离开保护：当歌曲内容有未保存修改，返回管理/新建/打开另一曲谱前提供“保存并继续 / 放弃修改 / 继续编辑”；若存在表单未应用草稿，先解决草稿，再保存已提交文档。保存失败不执行原定离开动作。
- 持久化介质由后续实现方案决定，本轮采用“曲谱库保存”产品语义，不承诺服务器、账号、离线自动保存或多人协作。
- 增加约 10 组业务状态画板及闭环原型：管理 → 新建 → 编辑 → 首次保存 → 管理 → 再打开；编辑未保存 → 离开确认 → 保存失败/成功；管理 → 重命名/复制/删除。
- 默认视觉沿用浅色专业工作台。Figma 未提供当前 Arial/PingFang SC/Microsoft YaHei 字体，设计稿改用可用的 Noto Sans SC 并在交付中注明；音乐图标使用项目矢量 SVG，谱面为可编辑文本与线条，不使用整页截图。
