## 4. 简谱控件到真实命令的映射

| 控件/操作 | 当前入口 | 必须显示的限制/结果 |
| --- | --- | --- |
| 已有音组内容 | `numbered.event.set` | 单音组一项，`+` 表示同时音，最多 8 音；保留稳定 item 身份的单音修改使用 itemId |
| 已有事件连续改内容 | `numbered.sequence.set` | 以已有事件序列定位，`_` 跳过；事件不足整批拒绝；保留已有时值 |
| 新增/节奏模板 | `numbered.range.replace` | startTick/endTick、每项 rhythm 和可选 ratio；不跨小节；覆盖默认关闭 |
| 改当前音符时值 | `numbered.event.setRhythm` | 显示释放/覆盖范围；无合法候选时禁用；扩展不能截断部分事件 |
| 前八后十六验例 | `numbered.range.replace`，四分拍范围 | 4/4：0–960 ticks，八/十六/十六，起点 0/480/720；预览显示第1拍、第1拍+1/2、第1拍+3/4 |
| 单 item 的八度/升降 | `numbered.event.set` + itemId | 显式选择音符 item；不把整个 `1+3+5` 音组的八度隐含改成同一个值 |
| 拆分/合并/删除 | `numbered.event.split/merge/remove` | 连音、事件连续性及记号引用由核心验证；非法动作不产生历史 |
| 连音组 | range.replace 的 ratio、`numbered.tuplet.remove` | 仅六类比例，非整数 tick 拒绝；不能将 TAB `tuplet.set` 用到简谱 |
| Tie / Slur / Fermata | `numbered.mark.add/update/remove` | Tie 使用 item 端点且同音；Slur 使用事件端点；Fermata 锚定事件；跨行绘制由核心处理 |
| 范围复制/粘贴 | store 的 `copyNumberedRange`、`numbered.range.paste` | 独立简谱剪贴板；插入/覆盖不同；展示跨范围连接遗漏；范围插入限一小节 |

预览调用 `editNumberedTrack(..., true)`，提交经 `applyScoreCommand`/store execute。候选中的 overwrittenEventIds、releasedRange、removedMarkIds、changedMarkIds 是预览的来源，不能按输入项数自行猜计数。现有简谱候选预览不是完整表格 ViewModel；表格行的呈现适配仍要实现，但不能复制领域校验算法。

影响确认绑定原始文档与 `expectedRevision`，提交带 `confirmedRemovedMarkIds/confirmedChangedMarkIds`。确认时旧候选失效必须重新规划。删除记号本身是明确命令，不应再弹重复的间接影响确认。

## 5. 草稿到宿主业务的接口缺口与设计

### 5.1 当前边界

`MusicTextController` 当前仅暴露 `isOutputBlocked/open/select/returnToScore`。`isOutputBlocked` 包含 IME、确认中、输入激活、当前草稿、暂存简谱草稿、设置草稿；它是输出闸门，不是“有未保存音乐修改”的判断，也不是“应用全部草稿”的接口。`onEditingChange` 同样不能替代全量草稿检查。

简谱 cache key 使用 trackId/measureId/eventId/itemId 或 tick/endTick，不能只用 beatId。当前自身提交只移除相应目标缓存；其他缓存不会自动全部提交。外部文档变化会清空缓存，`EditorSession` 的 sessionId/sessionVersion 变化会重建外壳；因此离开保护必须在 replaceDocument/卸载之前执行。

### 5.2 待实现的最小协调契约

新增一个由会话拥有的草稿协调器，统一供保存、导航、导入与导出调用；以下是实施要求，不是现有已导出接口：

- `inspectDrafts()` 返回组合态/处理中标志、当前草稿和暂存目标列表；每项包含稳定目标、位置文案、dirty、是否可应用、错误原因，不能只返回布尔值。
- `focusDraft(id)` 恢复相应输入和焦点；`discardDraft(id)` 只丢弃明确的一项；外部跳转的“放弃全部草稿并继续”必须明确展示数量和范围。
- 首版不设计一键跨目标自动应用：应用一项可能改变时长或其他草稿目标。提示用户逐项返回、重新校验并应用，全部处理后再重新发起保存/导出/离开。没有原子批量规划之前，不能把若干独立命令的循环包装成“整批成功”。
- 当前只有一个有效草稿时，三选项可以继续使用；“应用并继续”还须等待记号影响确认真正提交成功，不能因打开了确认弹层就导航。
- 已有草稿与本地保存 dirty 分开：处理全部草稿 → 捕获已提交内容 → 持久化 → 成功更新保存基线 → 执行单个待处理导航。失败/取消任何一级都停止后续流程。

## 6. 保存与曲谱库的落地条件

沿用原落地契约的 libraryId/storeVersion、原子内容与索引写入、成功快照基线、双层离开保护。额外冻结以下约束进入正式技术方案：

1. `documentRevision` 可随撤销回退；仅用于音乐命令候选校验。存储冲突使用独立 storeVersion，不能共享。
2. 新建工厂产出 schema 8 的合法休止 TAB 与空 numberedVoice/numberedMarks，不复制示例谱的音乐或实体 ID。核心有休止构造工具，但完整业务新建工厂仍需新增。
3. 下载 JSON 不等于保存到曲谱库；导入文件不自动创建库记录、不因 score.id 相同就覆盖现有记录。首版导入进入未持久化作品，首次保存明确创建新的 libraryId。
4. 曲谱库 loader 不隐式升级旧记录；保留源数据并给出版本错误。文件导入有单独显式升级流程，两条入口不能混写。
5. 首次保存若允许改名称，需明确这是待保存候选的音乐内容修改。建议首版在保存事务成功后才提交对应名称及基线；若名称走既有领域命令提前应用，失败时保留这条可撤销修改且仍为未保存。正式方案必须选定一种，不能由表单随意直改 document。
6. IndexedDB 的名称唯一检查、expectedStoreVersion 检查与写入处于同一事务；失败保留文档与基线；不能先查后分事务写。保存中使用真实不定进度，不能按计时器伪造百分比。
7. metadata 与音乐内容职责分开：收藏/最近不进入音乐 history；重命名同时更新文档标题与索引；副本的新作品身份、引用完整性和重复名称规则需要实际验证。

## 7. Ant Design 和布局实施约束

- 本机依赖为 antd 6.4.4；CLI 查询 Tabs 6.4.4，并核对安装包声明。没有发现需要升级 antd 的前置条件。通用图标需增加 `@ant-design/icons` 直接依赖；当前通过 lucide 使用的图标需逐步迁移。
- `Tabs` 的 activeKey 先经过 request/草稿闸门再提交；不把 onChange 当成可无条件切换的事实。稳定上层保存缓存，forceRender/destroyOnHidden 不替代业务草稿恢复。
- `Form` preserve 只保字段值，不保存 pending action、目标身份、时值模板或临时连接终点。不能把拆合/记号动作和表单 onFinish 混成一个未定义的提交。
- 把原生 dialog 迁移为 Modal 时保留文档令牌、影响确认、IME 与焦点；确认区的背景工具和快捷键均要锁定。输出闸门包含确认中的状态。
- 新四栏目是设计目标，不宣称当前已有“当前选区”面板。先拆职责再移动字段；歌曲/局部小节拍号分清作用域。表单实例不能随 1024/768 断点切换而重建。
- 1440/1280 并列、1024 上下分区、768 更多工具是布局目标，仍须容器宽度、独立滚动、200% 缩放和低高度实测。不得通过缩放编辑 SVG 冒充已经解决命中与响应式问题。
- 谱面字号、字形测量、命中、八度点、连线和空位几何全部消费核心结果。原稿中固定 2px/3px 是视觉示意，不取代最新 layout 的字形净空和弧高算法。
