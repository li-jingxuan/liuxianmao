日期：2026-10-19。状态：用户明确要求继续修复后已实施，完整截图与多弦回归通过。

## 多技巧复核与实施范围

用户补充第五弦 2→3、第二弦 1→3 先后添加 H 的完整截图，并明确要求多场景验证后修复。本次按该明确指令继续实施，不再重复请求确认。新增真实命令回归已复现：正序第五弦上移 36，反序上移 72，证明还存在技巧之间的碰撞和顺序耦合。除下述局部标签宽度方案外，将技巧之间的弧线/文字按实际图元检测，保持弧线与目标弦的定位关系；测试覆盖前后两张截图、添加顺序、相邻技巧、双位品位和断行。

## 结论

上次拆分弧线与标签碰撞框的修改只解决了简化谱例的误报，没有解决完整紧凑谱面的真实标签碰撞。截图中技巧仍绑定第四弦 1→2 品，H 的横向位置正好也对应第一弦 3→1 品，因此整段上移后会产生“加到第一弦”的视觉结果。

本次完整保留默认曲谱的和弦、歌词、简谱、其他技巧及断行，在第 7 小节的第 5、6 颗八分音符补入第四弦 1、2 品，通过真实 SetNote / AddTechnique 命令复现。包含上次局部修复的工作区仍然失败。

## 准确原因与对照

1. 技巧保存的 `fromNoteId / toNoteId` 对应第四弦，未发生音符引用改绑。
2. 自然弧线本身没有碰到第一弦数字，H 标签却同时与第一弦 3、1 的字形/描边范围相交。
3. `assignLanes` 发现 H 碰撞后，调用 `translateTechniqueSegment` 将弧线和文字整体上移，每次 12 个逻辑单位；截图对应谱例最终上移 3 层、共 36，弧线端点也随之脱离第四弦。
4. 上次只改了“是否真的碰撞”，没有改变“标签碰撞时仍抬走整条弧线”的策略，也没有给 H/P 的必要宽度建立间距约束。

数值为核心布局逻辑单位：

| 对照                                         | 两音中心距 | 上方数字之间的净空 | H 含描边宽度 | 上移层数 |
| -------------------------------------------- | ---------: | -----------------: | -----------: | -------: |
| 完整谱面，紧凑                               |      16.42 |               3.62 |         7.85 |        3 |
| 完整谱面，舒适                               |      40.02 |              27.22 |         7.85 |        0 |
| 独立小节，紧凑                               |      24.00 |              11.20 |         7.85 |        0 |
| 完整谱面，仅为目标两音预留标签宽度的诊断原型 |      26.34 |              13.54 |         7.85 |        0 |

自然几何与同一谱行其他技巧没有重叠，排除了 Let Ring 等既有技巧导致这次上移。额外垂直间距已经是 0，继续改这个值不能提供缺少的横向标签空间。

独立小节的净空足够放下 H，这就是上次测试通过、截图中的完整乐谱仍失败的原因。诊断原型中断行仍为 3 + 4 + 1，但其他内容更拥挤时不能据此保证永不改变断行。

## 修复方案与影响

保持当前记谱样式：弧线端点位于目标品位中心上方，H/P 位于弧线上方。

1. **建立标签宽度约束。** 在断行前，以实际字形估算和描边尺寸计算 H/P 所需空间，复用既有 TechniqueInsets / 最小列宽接口，为不足的连接跨度局部预留宽度。延音线没有标签，不增加此项约束；不整体切换为舒适排版。
2. **分清标签冲突与弧线冲突。** H/P 与上方数字冲突应先通过标签位置及局部间距解决，不能仅为标签冲突将整段跨弦平移。弧线真实碰撞仍需检查。
3. **共用尺寸计算。** 间距预留与最终模板使用相同字体、描边及净空规则，避免再出现“模板已改，排版约束仍旧”的差异。不能把本例的 26.34 硬编码成所有技巧的固定宽度。
4. **按完整谱面验收。** 使用本次完整截图谱例，覆盖紧凑/舒适、编辑/成品、单/双位品位、H/P、其他上方音符、跨小节及跨行。断言目标 ID 正确之外，还要断言弧线仍贴近目标弦、H/P 不遮字、命中与导出一致。
5. **核对实际测试目录。** 最终同步到主工作区后，对同一完整谱例再做页面验收，保留主目录其他未提交修改。

主要影响位置为 `technique-spacing.ts` 的横向占位生成、`technique-layout.ts` 的标签与避让策略，以及两套现有横向排版流程的回归。风险主要是局部扩宽导致全行空间重新分配，必要时改变断行或分页；需要允许局部间距重新分配，不能再要求增加 H/P 后所有横坐标完全不变。

## 最终实现与验收

- `technique-spacing.ts`：H/P 标签宽度含实际描边，参与断行前的局部最小间距；相邻弦有字形时再预留内收端点和两段弧翼的空间。无障碍且无标签的延音线不额外扩宽。
- `technique-geometry.ts`：二次曲线分成 16 段子曲线控制点凸包，分别检测弧线与标签；不再把二者间的空白视为墨迹。
- `technique-curve-placement.ts`：弧线真实端点保持原弦 Y；优先保留中心端点，只有中心被相邻弦字形占用才局部内收。必要时调整弧高，H/P 可使用 8px 内嵌标签，弧线在文字两侧断开。共享端点的连续技巧允许正常接续，不互相抬升。
- `technique-layout.ts`：弧线先按自然弦位从上向下布置，其他技巧再避让；摆脱技巧生成 ID 和添加顺序的影响。原本的 P.M./Let Ring 等说明技巧仍走原有 lane 规则。
- `layout-constants.ts`：`LXM_TECHNIQUE_CURVE_FRET_GAP_Y = 0` 是弧线到品位白色描边外缘的垂直净空调节处，保留中文标记。

新增 103 条核心密集谱面测试和 2 条共享导出图元测试。覆盖本次及上次完整截图、反向添加并比较最终几何、六弦所有两两组合、六弦同时添加、H/P/延音线、单/双位品位、紧凑/舒适、编辑/成品、320px 窄谱行、纯 TAB 与简谱共享时间网格、同弦连续 H 共享端点、H 与延音线混用、标签命中、输入文档不可变。既有跨小节/跨行与技巧规范谱测试也通过。

实际浏览器导入完整谱例，确认第二弦与第五弦三条 H 正确保留在各自弦位；另导入六弦 12→14 同时击弦检查内嵌标签，均已保存截图。网页 SVG 和图片 Canvas 使用相同 scene 图元，测试核对路径和文字坐标一致。

验证：全仓库 79 个测试文件、804 项测试通过；编辑器和网站 TypeScript 检查通过，编辑器 ESLint 通过。网站的空歌词编辑位测试显式设置 `purpose: "editing"`，避免依赖恰好同谱行的其它歌词撑出空编辑位。

预防本类回归：除技巧引用 ID 外，持续检查最终路径两端的弦位、可见图元碰撞和添加顺序无关性。
