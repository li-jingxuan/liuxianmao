## 1. 需求来源与目标

来源：[六线猫 bugfix · 需求工作表](https://pcnhehlhivqu.feishu.cn/wiki/UEivw1G7Liuaqnk20d1cqCoxnHb?sheet=tcgLfi)，通过 `lark-cli` 以用户身份读取，sheet_id `tcgLfi`，revision 513，实际位置 **A49:I49**，编号 **REQ-048**。原文：

> 设计六线谱：新增、导入、导出功能了，暂时先不保存到云端，保证流程：
> 新增/导入曲谱 -> 编辑曲谱 -> 导出曲谱（.json\ png\打印）

D49 要求交互设计稿为“是”；状态、待确认口径、验收标准、两列参考图及备注均为空。下文参数、文案及异常处理属于本轮设计建议，并非飞书已经确认的条款。

用户应能从空白曲谱或电脑上的原生 JSON 开始写谱，完成编辑后带走可继续编辑的 JSON，或用于查看与分享的 PNG、打印结果。全程无需登录和云端保存。

## 2. 本期范围

- 首页新增“新建曲谱”“导入曲谱”两个直接入口，保留现有吉他进阶入口。
- 编辑器提供文件菜单及醒目的“导出”按钮，覆盖新建、导入、导出 JSON、PNG、打印、返回首页。
- 原生 JSON 是完整可编辑曲谱的交换和备份格式；PNG 和打印是视觉输出。
- 新建／导入成功后进入现有编辑器，保留既有六线谱、简谱、歌词、和弦等能力。
- 替换当前曲谱或主动离开前，对尚未导出为 JSON 的内容提供保护。
- 导入错误、导出错误、取消、处理中和重试均有明确反馈。

本期不新增账号、云端保存、云端曲谱列表、分享链接、多人协作、自动同步、自动本地恢复或最近打开列表。MusicXML、MIDI、图片识谱及其他第三方 JSON 不在本期导入范围。PDF 使用浏览器打印中的“另存为 PDF”，不新增独立 PDF 转换器。

## 3. 入口及视觉方案

沿用现有 design-v2 蓝白工作台：操作蓝 `#1677ff`、文字 `#26364a`、辅助文字 `#63748a`、背景 `#f4f6fa`、面板与谱纸 `#ffffff`、危险操作 `#ff4d4f`。中文采用系统字体，主体 14px、辅助 12px、标题 20～24px，控件约 32～36px，间距 8／12／16／24px。

首页以六根弦的谱面示意为主视觉，操作集中在“新建曲谱”和“导入曲谱”；无需虚构空的“我的曲谱”。编辑器以实际 3000 页面为基线：约 58px 顶栏，左侧蓝色文字品牌、曲名及“吉他弹唱谱”副题，右侧吉他进阶、紧凑文件入口、导出主按钮及 JSON 状态。删除旧原型额外一整行文件菜单与云端提醒，给谱面保留空间。文件入口保留文字名称，音乐工具栏继续以真实产品的符号与图标为主。

正式编辑器沿用现有 1400px 最小桌面宽度。本次审稿页的导航、首页和弹窗可随窄屏重排；这不意味着本期新增完整手机写谱支持。

文件菜单提供新建、导入 JSON、返回首页，导出入口提供 JSON、PNG 图片和打印，进入各自对应的输出界面。音乐工具栏保持单行，沿用撤销／重做、时值、附点、常用技巧、小节、节奏型、连音、和弦及侧栏开关的结构。左侧保留窄历史入口，中间为灰色画布与白色 A4 谱纸，右侧使用“选区／简谱与歌词／和弦／歌曲”四个页签；右下角保留 125% 缩放。旧原型的修改音符、追加小节等演示按钮移入评审工具区，不冒充产品新增常驻操作。

原型中的编辑工具仅演示与本需求有关的状态，不证明完整音乐命令接入。当前产品已有草稿输出阻断，但尚无“当前已提交文档是否导出为 JSON”的基线状态及离开保护；新增状态必须与现状区分。

## 4. 新建曲谱

弹窗标题“新建曲谱”，主要操作“创建曲谱”，次要操作“取消”。新建是在确认创建后才替换当前文档；打开弹窗、填写或取消都不清空当前谱面。

弹窗适当加宽，约 560～580px，曲名单独占满第一行；第二行为编谱作者／调性，第三行为拍号／调弦。标签、输入和按钮统一对齐，控件约 40px，内容留白约 24～28px。去掉所有“？”及帮助浮层、数字 1 音高和独立大小调控件、主音记法控件、调性结果行以及常驻说明；只呈现五个字段及取消／创建按钮。默认四空小节、无云端保存等信息保留在方案及编辑器，不在表单重复展示。此版替代 v1.1 的独立音高输入及 v1.2 的问号说明方案。

初始设置建议：

- 曲名：默认“未命名曲谱”，可修改。空白输入回退默认名，不将空格当作有效曲名。
- 编谱作者：可选，默认空，单行最多 64 个字符；使用现有 `score.arranger` 字段。留空时谱面、PNG 和打印不显示作者行，不填入虚构作者。
- 拍号：4/4（默认）、3/4、6/8；后续在编辑器中修改拍号。
- 调性：一个完整调性选择器，默认 C 大调，按大调／小调分组，共提供十二种大调和十二种小调。选项包含主音及模式，如 C 大调、G 大调、A 小调、F♯ 小调，不能仅选择“大调／小调”而缺少主音。
- 数字 1 音高：不再单独输入或在新建弹窗回显；创建时从完整调性推导。**推导前提是固定记法：本期新建大调主音记 1、小调主音记 6。** 大调的数字 1 等于主音；小调的数字 1 为主音上方三个半音（关系大调）。例如 C 大调 → `1=C`，G 大调 → `1=G`，A 小调 → `1=C`，E 小调 → `1=G`，F♯ 小调 → `1=A`。存储使用现有十二种 `score.keySignature` 规范拼写，明确调性保留主音拼写；不能用“大／小调”两个模式值独自推导。
- 小调记法边界：新建不再提供主音记 1 的选择，以减少表单负担。导入已有主音记 1 的曲谱仍保留文件值，不按新建默认值改写，原编辑器的既有能力不随本设计删减。
- 调弦：本期默认标准调弦 E2／A2／D3／G3／B3／E4；默认变调夹 0，不在首屏增加额外配置。
- 初始谱面：建议四个空小节，延续所选拍号。空小节中的待填位置不得自动变成已经写入的休止符或预置旋律。

创建后关闭弹窗，进入编辑器，将焦点定位到第一小节可编辑位置。曲名、已填写作者、拍号、推导的数字 1 音高及调性可在谱头与信息栏查看，小调同时保留主音记法，文件状态为“待导出 JSON”。创建时成组写入 `score.arranger`、`score.keySignature` 与 `score.meta["lxm:tonality"]`，使用现有调性推导及一致性校验；这是从已明确的调性和固定记法推导音高，不是从 `1=C` 反推大小调。不自动下载，不生成云端记录。校验失败就近说明并保留输入；中文输入法组合期间 Enter 不提交。现有核心协议没有独立 tempo／BPM 字段，本期不新增速度设置或擅自在原生文件中写入该字段。

## 5. 导入曲谱

弹窗标题“导入曲谱”。支持选择文件和拖入文件，同一时间处理一个原生 JSON；选择控件明确标注“.json · 六线猫原生曲谱”。拖拽只是快捷入口，键盘用户始终可点击选择。

导入分为三个阶段：

1. **读取与校验**：检查文件大小、可读取性、JSON 语法、原生格式标记、版本和曲谱结构；处理中禁用重复提交，取消不影响当前文档。复用现有 `lxm-tab-score`、当前 v8 协议及 v4～v7 升级入口，界面标注最大 10 MiB。网站仅允许单轨且至少一小节。已有资源预算继续生效，不接受语法正确但资源规模不受控的 JSON。
2. **打开前预览**：显示文件名、曲名、作者（空值显示“未填写”）、拍号、小节数量、数字 1 音高和可识别的调性。此时只读取文件，不替换当前谱面。提供“重新选择”和“打开曲谱”。旧 v4～v7 成功升级时说明“将升级后打开，原文件不会被覆盖”。文件名不得直接充当可信曲名；没有明确调性资料的已有文件保留“大小调未确认”，不把数字 1 音高擅自补成大调。
3. **确认打开**：若当前有待导出内容，先走第 8 节保护。确认后一次性替换整个文档、重置历史、选区与旧草稿；成功后显示“已导入 [文件名]”。

空曲名显示“未命名曲谱”；元数据使用文本呈现，不将 JSON 中的字符串作为 HTML。浏览器取消选择文件后保持原状，可再次选择同名文件。

失败反馈必须对应原因：

- 不是原生文件：“请选择六线猫导出的 JSON 曲谱。当前不支持 MusicXML、MIDI 或其他 JSON。”
- JSON 损坏：“文件内容无法读取，请重新选择原始 JSON 文件。”
- 版本不支持：“此文件版本暂不支持，请使用兼容版本导出的曲谱。”不能静默丢弃不认识的字段后勉强打开。
- 结构错误：给出可读的概括；技术字段路径可放可展开详情，避免挤满弹窗。
- 超出当前大小限制：展示实际限制及文件大小；沿用现有文件能力，不在设计稿中凭空承诺大文件支持。

任何失败都不替换、清空或部分写入当前曲谱。导入已有 JSON 后，文件本身是可恢复基线；用户尚未修改时不重复提示导出。

## 6. 编辑及文件状态

曲谱音乐内容、曲名、作者、拍号、数字 1 音高、调性与记法、调弦、歌词、和弦及影响输出的谱面设置变化计入文档版本。选区、滚动、缩放、侧栏展开等纯视图操作不计入。

建议显示三个状态：

- 新建或编辑后：“待导出 JSON”。提示“请导出 JSON，以便下次继续编辑”。
- 刚导入且未编辑：“与导入文件一致”。提示原文件可再次打开，但后续修改不会覆盖原文件。
- 当前版本发起 JSON 下载后：“JSON 已导出”。提示“当前版本已发起下载，请确认文件已下载；继续修改后需重新导出”。不使用“已保存到电脑”的绝对表述。

导出状态只描述当前快照。导出期间又发生修改时，完成的是旧快照，当前版本仍“待导出 JSON”。撤销回到与导入／导出基线完全一致的内容时可恢复基线状态；不单靠累计修改次数判断。

“未应用表单输入”独立处理：仍有和弦／简谱／歌词或设置草稿时，本提案建议导出引导用户先应用或取消，不默默应用，也不导出与眼前输入不一致的结果。离开文本目标时是否丢弃沿用当前已确认规则；本需求不恢复已经取消的旧草稿。源码现状并非所有草稿都阻断：部分歌曲信息、变调夹及拍号草稿在既有输出入口会先丢弃。本提案将文件输出前的处理收敛为显式提示，此处属于待评审的行为调整，不能称为已具备的保障。

## 7. 导出面板

顶部导出入口区分 JSON、PNG 和打印，直接到对应界面。JSON 使用紧凑确认面板；PNG／打印沿用当前产品成熟的页面预览结构。输出统一基于已应用曲谱，展示由曲名派生的文件名，复用现有命名规则，扩展名由输出类型固定；清理文件系统不支持的字符，空名回退“未命名曲谱”。浏览器下载设置允许时可选择位置或改名，本期不增加第二套独立文件名编辑状态。删除旧原型巨大文件卡、重复用途警告及弹窗内的实现说明；成功／取消／失败模拟控件属于外层评审工具。

### 7.1 JSON 曲谱

紧凑面板仅显示曲名／文件名、一行“下次导入继续编辑”和取消／导出 JSON。复用现有原生格式，保留音符、歌词、和弦、作者与曲谱设置，不能另造只包含可见 TAB 音符的简化 JSON。

导出冻结点击时的文档快照，下载名沿用 `曲名.lxm.json`；校验与序列化成功后发起下载。浏览器交接成功的反馈为“已发起 JSON 下载”，允许再次下载；异常时显示原因并保持当前谱面与待导出状态。JSON 导出不覆盖用户电脑上的原文件，不暗示能更新上次选中的路径。

### 7.2 PNG 图片

参考实际产品“A4 图片预览”，采用左页缩略图、中部大预览、右输出设置三栏，显示总页数，点击缩略图切换页。输出设置只保留全部／当前页范围、尺寸及必要的生成状态。预览使用既有 A4 打印排版，空白边距与背景沿用现有输出设置；不导出编辑器按钮、选区高亮或缩放控件。

保留现有“生成 → 下载”的两阶段：未生成时主按钮为生成图片，处理中显示进度与取消，生成成功后才提供下载 PNG／ZIP；失败可就地重试，取消不冒充完成。切换输出范围、当前页输出的目标页或文档内容后，不得把旧生成结果当成新目标；仅浏览缩略图且未改变输出目标时不要求生产重新生成整谱。原型可保守重置生成状态，但不能暗示生产当前所有翻页都必须重新生成。原型只模拟这些状态，不把模拟生成当作生产验证。

复用已有 A4、300 DPI 图片输出及 ZIP 打包能力：可下载当前页 PNG；整谱多页以 ZIP 下载，包内沿用页序命名 `曲名_001.png`、`曲名_002.png`。显示总页数、生成及打包进度，不将长谱拉成一张无限高图。单页曲谱可直接下载 PNG，失败后保留预览和重试入口，不清除当前文档。

PNG 成功不清除“待导出 JSON”。首次使用时可在输出说明中提醒：“图片用于分享；需要继续编辑，请同时导出 JSON。”

### 7.3 打印

显示打印排版预览、页数和提示“在打印窗口中可选择打印机或另存为 PDF”。主按钮“打开打印窗口”，在用户点击后调用浏览器打印能力。A4、页边距、背景、分页、清除编辑态与已有打印输出保持一致。

打开系统窗口后不宣称“已打印”。返回后提示“已关闭打印窗口，可继续编辑或重新打印”；无法判断用户确认还是取消时采用中性文案。打印不清除“待导出 JSON”。

## 8. 替换与离开保护

覆盖动作包括：确认新建、确认打开已校验的导入文件、返回首页及应用内导航离开编辑器。先完成新文件／设置的准备和校验，再询问是否离开；用户取消文件选择或新建表单时不弹无关提醒。

若当前文档有待导出 JSON 的内容，显示确认层：

> 离开前导出曲谱？
>
> “[曲名]”还有未导出的修改。导出 JSON 后可继续编辑。

使用约 480px 的简短确认框，只保留当前曲名、即将执行的动作和一两行正文。操作：“继续编辑”（默认安全焦点）、“不导出并继续”（明确危险操作）、“导出 JSON”（主要动作）。删除旧原型大图标、重复云端／图片用途提醒、绿色卡片及技术说明。

确认框中的“导出 JSON”先发起下载，保留原曲谱与确认层，正文就地更新为下载已发起，主按钮变为“已下载，继续”；用户也可继续编辑或重新下载。下载取消或失败不能自动执行原动作。浏览器通常无法验证文件是否最终写入磁盘，此两步确认将决定权交还用户。重试下载时不重复执行新建／导入。

应用内离开先处理受保护的未应用草稿，再判断已提交文档的 JSON 基线。即使刚导入且已提交内容未改动，仍不能绕过当前活动草稿；沿用实际产品“返回编辑／明确放弃”的机制。处理草稿后回到编辑器，由用户重新发起原操作，不自动应用草稿、不用延迟回调突然导出或跳转。重新发起时再检查 JSON 基线。既有文本目标切换的丢弃规则保持，不恢复离开的旧输入。

浏览器刷新、关闭标签页或离开站点使用标准 `beforeunload` 提示，在待导出或存在受保护的活动草稿时注册。浏览器限制自定义文案与触发条件，不能承诺关闭时自动导出或必定弹窗。

导入校验和导出任务与文档版本绑定。确认层期间取消操作则清除待执行意图；不能在之后一次普通导出成功时突然跳转。新建／导入在最终确认前保持原谱完整。若校验候选之后当前文档发生变化，候选过期，需要重新选择／校验，不能用旧候选覆盖新编辑；即使随后撤销，也不绕过版本复核。

## 9. 可访问性与异常状态

所有弹窗提供可访问标题、字段标签、错误关联及可见焦点；打开后焦点进入弹窗，Tab 不穿透背景，关闭后返回原入口。Esc 关闭未提交弹窗，取消保护层视为继续编辑。异步期间不允许重复提交，并提供明确状态；取消后忽略已经过期的读取结果。

拖拽区同时提供原生文件选择按钮；仅图标按钮有中文名称。错误不只通过红色表达，成功反馈使用一个礼貌播报区，避免焦点被提示抢走。窄屏弹窗不超出视口，内容可滚动、底部按钮可达。

## 10. 验收条件

1. 首页和编辑器两处均能新建／导入；取消不改变旧谱，新建成功得到明确设置下的空谱。
2. 真实原生 JSON 导入后继续编辑，再导出 JSON 再导入，音符、时值、技巧、歌词、和弦及设置语义一致；编辑历史、临时选区和草稿不冒充曲谱数据。
3. JSON 损坏、不支持版本、错误结构、超大文件、读取失败均不会损伤旧谱；同名文件可重选。
4. 替换和离开只针对当前待导出文档提示；三种确认路径、取消、下载失败和再次重试均保持目标正确，不执行两次。
5. 编辑后标待导出；PNG、打开或取消打印窗口、缩放与选区不会错误改变 JSON 状态；导出旧快照不能把新修改标成已导出。
6. 未应用表单阻断产品入口的 JSON、PNG 和打印操作，用户处理完后重新发起输出；未提交的字样不漏入文件。浏览器菜单打印／Ctrl+P 目前直接消费已提交打印层，本期不承诺自定义弹窗可阻断系统快捷键；该路径只输出已提交内容，用户仍需从产品打印入口处理草稿和检查预览。
7. PNG 和打印与已有 A4 排版一致；长谱分页无截断，图中没有编辑态；当前页 PNG、整谱 ZIP 及失败重试可用。
8. 中文曲名和非法文件名字符处理正常，原生 JSON 导出名使用既有 `曲名.lxm.json`（清理非法字符、导出文件名主体截断至 80 个字符；曲名字段本身按现有 128 字符限制校验），v8 正常往返，v4～v7 升级有提示；其他版本与格式拒绝。
9. 键盘完成新建、选文件、导出和保护层操作，Esc／焦点返回／错误播报符合第 9 节。
10. 无登录前置、云端保存请求、虚假已保存提示；静态原型的演示成功不能当作上述生产验收通过。
11. 新建默认 C 大调，自动得到 `1=C`；完整大调选择按主音推导，小调固定记 6 并按关系大调推导。二十四个调性选项均无冲突，已有小调记 1 的导入值不被覆盖。弹窗没有数字 1 音高、独立大小调、记法、问号或结果提示行，曲名独占一行。作者可空、最多 64 字，中文与 HTML 特殊字符安全显示；填写后在谱头及输出保留，空作者不占谱面行。JSON 往返保留作者、数字 1 音高及明确调性。
