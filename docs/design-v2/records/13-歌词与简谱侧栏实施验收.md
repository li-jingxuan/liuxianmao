# REQ-007～016 · 歌词与简谱侧栏实施验收

状态：**已完成（REQ-007～016）**。用户确认[设计规格](../specs/13-歌词与简谱侧栏设计.md)后授权实施，产品实现与下述验证已完成，用户已明确同意将这十项标记为完成。沿用“不提交、不 push”的要求；工作区其他会话的改动没有回退或纳入提交。

## 实际行为

- 简谱和歌词均使用单行连续输入，侧栏与谱面气泡共享草稿。应用后停留当前位置，切换目标丢弃未应用内容，关闭浮窗保留当前草稿。保留输入法组合输入、结束冷却和版本检查。
- 简谱输入旁保留“应用”；下方一排六种时值、单附点和延音，提供悬停／键盘名称提示。附点与横线使用既有 Bravura 音乐字体，点击延音以 `-` 替换当前正文并立即应用。
- 八度与变音常驻展开，只修改谱面明确点选的单音成员；多音中其他成员保留。正文未应用时禁止属性修改，避免覆盖共享草稿。
- 移除单音组切换、重复节奏与范围表单、拆分合并、连接管理、专用复制粘贴、移除事件区域及简谱底部操作栏。歌词侧栏保留紧凑恢复／应用，气泡保留输入、关闭和应用。
- 歌词空输入、纯空格与 `_` 清空映射位置，普通空格只分词，多字词整体写入。清空通过移除对应段的歌词对象表示，不存储空字符或占位字符；编辑占位不进入成品输出。
- 歌词段落下拉框只显示已有段落；添加后选中新空白段，最多四段，保持谱面位置，支持撤销和重做。文档 `score.meta.lyricVerseCount` 记录空段落；旧文档同时按已有歌词推断段数，无需升级文件版本。

## 关键实现

简谱复用现有自动覆盖规划 `numbered.sequence.overwrite` 及提交器，保留跨事件边界、连音组、歌词和记号保护。属性动作复用命令校验与既有影响确认；涉及移动、压缩或记号变化时仍需确认后原子提交。自身替换重建成员 ID 时在原输入会话内重绑，撤销／重做后恢复有效成员与输入，防止丢失刚应用的完整连续内容。

歌词解析、规划与提交同步改为 `set | clear`；共享文本校验仍对和弦名称保持非空要求。新增 `lyric.verse.add` 命令及 `getLyricVerseCount()`，通过真实编辑器历史保存段落，不使用无法撤销的界面本地计数。

产品沿用现有编辑器的窄屏面板收纳方式，布局受宿主可用宽度限制；独立原型继续作为交互参考。
