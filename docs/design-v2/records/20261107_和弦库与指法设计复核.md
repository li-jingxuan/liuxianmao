## 最新复核结论：v2.2

用户要求再次充分对齐方案与设计，限制本轮为设计资料。本次对照代码进行两路独立只读审查，再修订文档与 HTML 原型；未改动产品代码、实际目录数据或现有产品测试。以下早期复核与 01–08 图片保留当时状态；本节、最新浏览器报告和 09–10 图片为后续修订依据。

### 已补齐的实施接缝

1. **设置导航会丢和弦草稿**：[MusicTextSidebar](../../../apps/website/components/EditorShell/MusicTextSidebar.tsx#L1560) 的普通设置 focus 会执行 tab 离开流程、失效 owner 并清 draft。方案第 7.4 节改为专用 suspend/resume，保留 draft/initial/目标/身份，暂停草稿仍登记并阻断输出；普通用户切栏目继续沿用既有规则。
2. **只改标题即可清掉整组冲突**：[ScoreSettings.update](../../../apps/website/components/EditorShell/ScoreSettings.tsx#L164) 会在任一字段编辑时刷新基线。方案第 3.6 节要求同步改造 update，显式核对整组后才认可新基线；状态稿展示“仅改标题仍阻止提交”。
3. **Modal 关闭动画出现互斥空隙**：[editor-modal-controller](../../../apps/website/components/EditorShell/editor-modal-controller.ts#L48) 立即清 current，且 cancel 不保留 afterClose。方案第 7.1 节定义独立 handoff、closing 状态与请求 id 校验，动画期间持续锁定；库→自定义/设置不得依赖普通 cancel 回调。
4. **调性 raw 对象会被引用比较误判**：[score-settings-draft](../../../apps/website/components/EditorShell/score-settings-draft.ts#L48) 当前字段是简单值。方案第 3.6 节明确 raw 的存在性/内容基线、独立 preserve/delete/set 意图、派生 reader 不入 dirty；命令计划与错误归组一起接入 SetScoreInfo。
5. **Modal token 无法取得实际登记 owner**：[useEditorDraftRecords](../../../apps/website/components/EditorShell/EditorSessionRuntime.tsx#L82) 原 handle 仅能失效。方案第 3.2 节明确最小扩展身份捕获/校验，登记与回填共用同一 owner，禁止两套代次各自失效。
6. **缩短/换指横按缺少旧范围清理**：方案第 8.2 节明确先移除本条旧描述、必要清理失去解释的旧重复指号、保留品位，再构造新范围并统一验证；不同品位合法重叠不一概拒绝。一次操作、一次局部撤销。
7. **HTTP 状态未出稿，快照冻结会锁死首载**：补首次加载、重试、旧快照、引用移除状态；无快照 Modal 可接收首次合法结果，已有快照则本次固定版本。补请求总超时/流式大小限制/迟到结果、同源目录限制与缓存约定，第三方地址切换仍留未来。
8. **导入与网络未就绪的引用混淆**：系统引用暂不可解析时保留并说明，不当作坏图或自动删除；用户收藏引用必须自洽。预览绑定本机 revision，确认替换再次检查，导入文件的 revision 不作为本机并发基线。

这些是未来产品实施必须遵守的约定，本轮没有实现上述核心能力。第 11 节已追加相应验收路径，尤其保留现有结构/粘贴/技巧 Modal 和普通切栏目行为的回归要求。

## 本轮反馈与修订

用户要求“更多”内的调性标记与当前曲谱一致；同时指定旧 `docs/design/` 已完结，后续资料统一使用 `docs/design-v2/`。

本轮已迁移和弦原型、设计说明、截图和技术方案，旧位置不保留第二份活动稿。项目根 README、旧 design 归档提示、design-v2 README 及网页导航已更新。

回查代码发现，现有 `score.keySignature` 仅表达简谱数字 1 的音高，不含大小调。v1 的固定“C 大调 · 常用”、独立记忆 `lastKey` 和默认 major 均不能代表当前曲谱。本轮修订为：

- “更多”的调性来源固定为当前已提交曲谱；默认推荐仅列调内三和弦与七和弦，小调补充分组另列。
- “我的常用”是用户快捷配置，不随调性改写；跨调搜索另标全库结果。
- 和弦库默认跟随曲谱，临时浏览其他调时明确标注，重开恢复跟随。
- 补充歌曲调性设置，主音、大小调、小调简谱 1/6 记法形成一次应用；设置草稿不提前影响推荐。
- 技术方案采用现有 `score.meta` 扩展点保存已确认调性，保留 schema v8，补齐旧谱、未知扩展、资料冲突、命令原子性及撤销规则。
- 缺少原型指法的候选预先禁用并解释，不在点击后才报告无法使用。

## 原型浏览器检查

以下为对独立 HTML 原型的实际操作，不能替代未来产品集成测试：

1. 切换“审查样谱”为 G 大调，打开“更多”：标题显示“曲谱 G 大调”，基准 `1=G`，候选包含 G、Am、Bm、C、D、Em、F#dim 及对应七和弦。
2. 切换 A 小调（主音记 6）：标题显示 A 小调，基准仍为 `1=C · 6=A`，没有误显示 C 大调；和声小调 E、E7、G#dim、G#dim7 单独分组。
3. 旧谱只有 `1=G`：显示“大小调未确认”，不列猜测的 G 大调和弦，保留搜索、设置和完整库入口。
4. 从未确认旧谱打开设置，编辑 A 小调但未应用时，谱首仍保持旧状态；应用后显示 `1=C · 6=A · A 小调`，一次原型撤销返回未确认的 `1=G`。该撤销只验证页面内模型，未验证产品主历史。
5. C 大调曲谱内临时浏览 G 大调：横幅显示“临时浏览 G 大调，曲谱仍为 C 大调”；关闭重开完整库恢复跟随 C 大调。
6. C 大调下搜索 E7：显示全库搜索结果，来源仍为当前曲谱，不将 E7 当作 C 大调调内推荐。后续微调将搜索态副标题写作“曲谱基准”，避免残留“本调推荐”字样。
7. 查看 390 × 844 窄屏的 A 小调“更多”：四列候选、和声小调补充、说明及底部入口都在视口内；候选按钮最右约 325px，底部约 821px，没有裁掉操作入口。
