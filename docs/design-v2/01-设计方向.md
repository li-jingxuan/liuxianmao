# 右侧编辑台：设计方向与自审

状态：第一轮提案，等待讨论；不作为产品实施授权。范围为六线猫右侧侧边栏及其与谱面气泡的关系。

## 产品与设计目标

六线猫是吉他六线谱、独立简谱、歌词和和弦的网页编辑器。本次服务正在谱面上逐拍编写、检查和修正曲谱的用户。核心任务是：确认正在编辑的对象，在附近完成常用输入，看清影响，再应用到曲谱。

当前宽屏右栏 440px，有「选区 / 段落 / 和弦 / 歌曲」四页；歌词、简谱气泡与完整侧栏共享同目标的局部输入。切换文字目标、页签、歌词段号、模式或结束编辑直接丢弃未应用输入；仅收起侧栏不结束会话时保留。和弦及歌曲设置仍保留离开确认，当前未应用输入仍阻断导出。本方案以当前工作区为基线。

## 第一遍：两个结构方向

方向 A：保留四个任务入口，内部改成对象上下文、任务表单和明确的提交区。整体左对齐，音乐预览按时间从左向右排列。推荐此方向：熟悉的入口继续可用，同时消除长表单的阅读负担。

```text
┌──────────────────────────────────────┐
│ 编辑台                        收起    │
│ 选区   简谱与歌词   和弦   歌曲        │
├──────────────────────────────────────┤
│ 简谱事件      第 2 小节 · 第 1 拍      │
│ 简谱 / 歌词                  定位谱面 │
├──────────────────────────────────────┤
│ 先录入：模式、正文                    │
│ 再看结果：音符、节拍、影响范围         │
│ 节奏与范围 / 音高与连接 / 复制与粘贴  │
│                                      │
├──────────────────────────────────────┤
│ 未应用：替换 3 个音符                 │
│ 恢复本次修改             应用简谱内容 │
└──────────────────────────────────────┘
```

方向 B：只保留自动跟随选区的单检查器，任务入口全部由对象决定。入口更少，但空白谱面时难以发现歌词、简谱和歌曲；主动切换任务也不稳定。本轮不推荐。

```text
┌──────────────────────────────────────┐
│ 当前对象：简谱事件               更多 │
│ 对象内容与属性                        │
│ 随谱面选择整体替换                     │
└──────────────────────────────────────┘
```

## 色彩与字体

保留品牌联系，六个核心颜色：纸白 `#FFFFFF`、工作灰 `#F4F6FA`、墨蓝 `#202838`、交互蓝 `#285BE0`、预览浅蓝 `#EDF3FF`、状态赭 `#92600C`。次级文字 `#626E82`、边界 `#DCE2EC`、错误 `#BC3547`、成功 `#19734F` 延续现有语义色，不能仅凭色彩表达状态。

界面正文用系统中文无衬线：`"PingFang SC", "Microsoft YaHei", Arial, sans-serif`。不为侧栏新增字体下载。音乐数字预览使用 Georgia，正式谱面继续使用既有音乐字体和渲染资源。标题 18/24px，模块 14/20px，正文 13/20px，帮助 12/18px；主要按钮 13/20px。音符数字 26/32px，强调音符和节拍关系而不是装饰标题。

用户已确定最小产品视口宽度为 **1440px**，本轮只设计桌面。侧栏固定 400px，与谱面始终并排；按评审移除四角展开按钮及宽度切换，标题右侧只保留收起按钮。更大窗口只扩展谱面区域和留白，不改变侧栏结构。主动收起侧栏释放谱面空间，重新打开保留同会话输入。不再提供抽屉、底部编辑区或移动布局。原型附真实 1440 × 900 产品视口基准稿；评审板的单栏画框只展示部件。

常规控件 32–36px 高、圆角 6px；面板不加卡片阴影；内嵌预览 10px 圆角，用面积和音乐内容形成识别。内边距 20px，控件间距 8/12px，任务组间距 24px。页签、对象定位和底部动作常驻，表单只有一个主要滚动区。

## 第二遍：针对六线猫的自审修订

初稿容易变成通用属性表单，因此作以下修订：

1. 移除顶部概览数字和通用统计卡片，改成真实的小节、拍位、音符对象定位。
2. 只把「节拍映射预览」作为最有记忆点的部分；其余区域安静、紧凑，不铺装饰渐变或成排卡片。
3. 产品文案使用「简谱内容 / 时值 / 单个音高」，明确三组独立应用；输入在应用前仅属于当前编辑会话。
4. 不把全部高级功能藏在一个折叠区，按「节奏与范围 / 音高与连接 / 复制与粘贴」组织，并保留独立应用语义。
5. 文字编辑底部提示离开会丢弃未应用输入；同目标重复激活、气泡与侧栏切换及仅收起侧栏保留输入。和弦及歌曲设置保留确认；导出检查当前输入。
6. 歌词与简谱共用时间预览语言，但歌词显示字词和音符映射，和弦显示六弦指法，歌曲显示全曲范围；避免把四类任务套成同一种表单。

## 证据与技能使用

现状浏览器：通过 `browser-skill` 新建独立 Agent Window，读取 `http://localhost:3000/` 并截图。当前扩展不支持 `cooperate sync` 协议；未绕过控制限制点击产品。交互事实以当前源码与已有测试材料交叉确认。

主要来源：`MusicTextSidebar.tsx`、`NumberedEditor.tsx`、`LyricFormView.tsx`、`ChordEditor.tsx`、`ScoreSettingsForm.tsx`、`index.module.scss`；历史规范见 `../design/README.md` 和 `../design/02_规范与复审/20261013_AntDesign设计回归与组件映射.md`。

本轮行为与验证回溯见 [04-功能回溯](./04-功能回溯.md)：`music-text-draft.ts` 的 `resolveSidebarRequest`、`MusicTextSidebar.tsx`、`NumberedEditor.tsx` 与 `music-text-sidebar.test.ts` 为当前依据。第一版跨目标暂存、待处理列表及文字切换确认设计已撤回。

`ui-ux-pro-max` 检索：`contextual inspector progressive disclosure` 返回无关的实时角标/标题结果，收窄为 `disclosure complex settings` 无匹配；没有可验证的数据集匹配，本稿的渐进展开为通用设计判断。Next.js 表单状态搜索返回服务端提交建议，与本地音乐命令无关，不采用；改查 React 状态，采用表单使用局部状态、避免将高频字段放入全局 Context 的建议。

已验证的 UX 结果：`focus not obscured` 返回焦点不被遮挡的 AA/AAA 规则；设计以焦点完整可见为目标，不混淆等级。`error summary validation` 返回可聚焦错误摘要；多错误提交保留字段错误并聚焦可链接摘要。技能未匹配的内容不冒充数据集结论。

通用组件后续继续复用 Ant Design，音乐图元沿用既有 SVG / scene / layout。HTML 原型只是离线设计表达，未引入产品依赖或变更业务模型。
