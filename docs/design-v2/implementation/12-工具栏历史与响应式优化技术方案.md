### 2.1 目标与保护

工具顺序为撤销重做、时值、附点、**休止**、**H/P/S/下扫/上扫/下琶音/上琶音**、完整技巧菜单及其他工具。S 与 H/P 使用相同字母样式，hover／focus 提示“滑音”，替代上下滑音两个箭头快捷。上述快捷在各宽度保持直接展示，极窄窗口使用工具行内部滚动，不隐藏到菜单。快捷与完整菜单共用领域解析、禁用原因和最终命令适配器，不复制一套音乐规则。休止使用已加载的 Bravura 音乐字体四分休止字形。撤销/重做图标 16px，其余技巧图标 22px，按钮热区保持 36px（粗指针 44px）。

按用户最新红框修订：休止、快捷技巧和完整技巧入口仅显示记谱符号／SVG，不展示“休止、滑音、扫弦、琶音、技巧”等文字或“常用技巧”组标题；H/P 保留记谱字母。按钮统一等宽、居中、相同热区，图标移除文字后不缩小可操作面积。完整技巧入口采用可识别的音乐技巧符号，保留菜单展开状态与 `aria-haspopup`。红框外的小节、拍点、更多继续使用文字。

符号按钮提供准确 `aria-label`，hover／键盘 focus 展示名称 Tooltip，休止同时展示既有快捷键；提示与按钮以 `aria-describedby` 关联，移开、失焦、点击或 Escape 时关闭，不拦截点击与焦点。提示放在独立浮层中，靠视口边缘翻转／限位，不能被工具栏滚动区裁切。禁用原因通过现有可聚焦提示包装或状态说明提供，不恢复常驻文字。触屏沿用按钮、具名技巧菜单和参数面板完成动作，不将长按或 hover 设为必经步骤。

TAB 快捷入口以实时有效的 TAB 目标为前提；简谱焦点激活（`numberedSelection` 或活动简谱目标）时禁用休止及上述吉他技巧，明确提示“请先选择 TAB 目标”，不得作用于 store 保留的旧 TAB 选区。既有简谱时值／附点仍按原谱层契约运行，不为本期新增简谱休止语义。目标无效、模态框打开、受保护草稿未处理时，沿用现有阻断及提示。

点击前与异步确认后都核对 `sessionId/sessionVersion`、文档对象、`stateVersion`、TAB／简谱选区及活动目标签名；不能只比对可被撤销复用的 `documentRevision`，也不能使用打开菜单时捕获的旧文档提交。新快捷统一接入工具动作与 `editor-command-adapter → store.execute` 的保护链，不直接改文档；实际提交处再次执行简谱闸门，不能仅禁用按钮。用户触发音乐动作时沿用现有品位草稿处理；仅查看历史或改变布局不清草稿。

若既有品位草稿处理先完成一次合法文档提交，须在该提交之后重新捕获版本并解析工具目标，再进入本次命令保护；不要拿处理前版本误拒这条合法链路。等待期间出现其他文档／目标变更则使原意图失效，要求重新触发，不能静默追随新选区；owner 显式交接允许的变化也须在交接结束后建立新基准。

### 2.2 休止切换

- 解析连续 Beat 范围：全部为休止时单击提交 `kind:"notes"`，否则（含混合状态）统一提交 `kind:"rest"`；一次操作一条 `SetBeatKindRange`，不逐拍循环。
- 仅“全部休止”显示按下态，混合状态在说明中标识；`aria-pressed` 与状态一致。
- 休止作用于范围内整拍全部弦，与框选弦数无关；会清除音符并按领域规则处理失效技巧。取消休止只得到空的普通拍，**不会恢复旧音符，恢复须撤销**。按钮说明及影响详情必须明确此行为。
- 不改既有键盘设置／取消休止的语义；按钮独立实现切换，不把现有 `rest` 动作悄悄改成 toggle。

### 2.3 技巧快捷

| 入口 | 用户动作与命令合同 |
| --- | --- |
| H／P | 无需额外用户参数；按现有时间排序规则解析起音、显式终音或同弦下一音，校验成功后直接 `AddTechnique`，携带实际 `fromNoteId/toNoteId`。音乐规则仍由 core 最终裁决；不满足时禁用或反馈，不创建半成品 |
| S 滑音 | 参考 H/P 单击直接提交，不打开参数弹窗。按时间排序解析同弦起止音，终音品位较高提交 `slideUp`，较低提交 `slideDown`；同品位、跨弦、无起音或无下一音时禁用并说明原因；重复完全相同的技巧为 no-op。谱面在既有滑音斜线之上增加 S，沿用技巧文本样式、碰撞及命中边界，跨行仅首段显示字母 |
| 下扫／上扫快捷 | 两个方向图标同时显示，分别直接提交 `stroke:"down"/"up"`，不打开参数面板。范围由当前同拍多弦选区解析，不足时禁用并说明原因，不隐式扩成全弦。无同拍扫弦／琶音时添加；已有时按实际目标技巧 ID 原子替换，重复同方向及范围为 no-op。当前方向以 `aria-pressed` 和高亮呈现，两者互斥 |
| 下琶音／上琶音快捷 | 两个方向图标同时展示，直接提交 `direction:"ascending"/"descending"`，与下扫／上扫使用相同演奏及箭头方向。范围取当前同拍多弦选区；同拍已有扫弦或琶音直接替换，重复参数为 no-op，不打开参数面板 |
| 更多技巧中的扫弦 | 保留原有参数窗口、方向选择和提交操作，不因为增加两个快捷按钮而删改窗口 |
| 完整技巧菜单 | 保留全部 16 类及现有窗口、选择和对象编辑能力；不额外新增搜索／分类改造。快捷不因 `selectedTechniqueId` 存在而意外更新其他目标；上下扫及上下琶音替换实际目标拍的扫弦／琶音 |

上下扫及上下琶音的最终命令合同：从最新文档按 `trackId + beatId` 查找同拍 `strum/arpeggio`，没有时发 `AddTechnique`；有时发 `UpdateTechnique({trackId, techniqueId:existing.id, technique:draft})`。完整 draft 按新类型替换并保留原 ID，不带旧类型字段，不拆成 Remove + Add。范围使用现有 `minString/maxString`，反向框选规范化后仍满足 `1 <= minString < maxString <= 6`；范围改变就替换为当前范围，不求并集。异步等待后目标对象失效须终止，不自动回退成新建。完整参数流程也在领域命令层执行相同替换：Add 保留目标拍现存技巧 ID；Update 保留被编辑 ID、移除目标拍冲突项。候选先校验，失败不改变原对象；导入校验继续约束同拍只保存一个扫弦或琶音。

扫弦按下态读取当前目标拍的实际 `strum.stroke`，不记忆上次点击；没有扫弦时两者均不按下，琶音也不冒充某个扫弦方向。相同方向但选区范围不同仍会更新范围，只有类型、拍、范围及方向均一致才是 no-op。休止拍上的状态按源数据推导：扫弦／琶音只隐藏同拍休止显示，不改变 `beat.kind`、不清休止源数据；删除技巧后恢复休止显示。

**已确认的 core 缺口**：`commands.ts` 的 `editTechnique` 使用 `JSON.stringify` 比较 Add／Update 的参数；仅对象字段顺序不同，重复 Add 会误报冲突，Update 会误增修订。实施时必须改成按各技巧类型的领域字段判等，忽略属性插入顺序及 ID，并保留“重复 Add 在冲突矩阵之前识别”的顺序；不将一般 `TECHNIQUE_CONFLICT` 吞成 no-op。真正 no-op 返回 `changed:false`，不分配 ID、不增加修订、不入历史、不清 future。这是必要的最小 core 修复，不新增命令或文档 schema。

演奏方向与屏幕方向的映射沿用 `technique-layout.ts`：TAB 低音弦位于视觉下方，**下扫 `stroke:"down"` 从低音弦侧指向高音弦侧，箭头视觉向上；上扫 `stroke:"up"` 反向，箭头视觉向下**。图标、Tooltip、`aria-label`、命令值和谱面必须一致，不能根据英文 down/up 直接猜 SVG 方向，也不翻转领域谱面来适应按钮。原型箭头随本次复核校正。

H/P 快捷最小合同限定同弦选区，多弦选区禁用并提示“请选择同一根弦上的音符”。解析器按时间排序完整单元格端点，不得排序 Beat 后仍拼接原始 anchor/focus 弦号，正反向选择须得到同一目标。单点或所选终点无音时查询同弦下一音；已有显式终音却违反下一音、休止或音高规则时反馈失败，不静默换音。共用解析器改动须回归现有更多技巧行为，不顺带改写其他连接技巧的范围语义。

S 滑音按起终音品位推导方向，只有上下扫/上下琶音由点击按钮明确指定方向，均直接提交而不打开参数弹窗。滑音与 H/P 共用同弦起终音解析：单点寻找同弦下一音，反向框选按时间排序；跨弦、无下一音或同品位则禁用。完整技巧保留默认值和参数流程，已有技巧编辑加载真实参数。未应用技巧参数在关闭、切换目标或离开技巧工具时默认丢弃，不提供“丢弃参数更改”按钮，不弹应用／丢弃确认；再次打开读取已应用值。仅改变布局且面板仍打开时保留当前输入。组合输入或提交期间仍延迟关闭。

现有草稿协调器尚不包含技巧参数，现有参数面板的 IME 判断也不能保护全部外部关闭路径；不得假定调用现有接口即可满足上一条。新增参数意图需补齐 owner、目标签名、dirty、composing／组合结束缓冲及 busy 状态，接入协调器或等价的统一接口，覆盖切换类型／目标／新建与编辑模式及外部关闭。owner 自己的显式“添加／应用”可提交自身草稿，其他 owner 的保护继续生效，避免新增 dirty 闸门使自身永远无法提交。

## 3. 左侧历史与反馈

### 3.1 信息与状态

左侧保留 `40px` rail，默认收起；历史主体宽 `272px`，与 rail 分列。打开后显示操作名、提交时目标摘要、当前节点、已撤销节点和可展开影响详情。即使 `effects=[]`，真正改变文档的操作也有记录；无附带影响时无需额外详情入口。点击“影响详情”只展开／收起内容，不更换文档、不修改选区、不移动历史游标。历史底部的撤销／重做与工具栏使用同一处理器和可用性保护。

已撤销项保留在列表中并显示“已撤销”，不能仅依赖淡色；当前节点标记在最后一个仍已应用的条目，全部撤销时标记保留范围起点。历史裁切后起点命名为“更早状态（保留范围起点）”，避免声称可回到原始文档。条目目标是提交时的记录；对象删除或编号改变后不拿当前文档重新计算旧小节号，不承诺可定位。

逻辑时间顺序为 `[...pastEntries, ...futureEntries]`，UI 反向展示，最新操作在上；不要单独反转 future 后再拼接。例：A、B、C 提交后撤销 C，顶部为“C · 已撤销”，其下“B · 当前”，再下 A。起点独立于操作条目，空历史显示“暂无操作”；另存 `baselineAdvanced` 标记是否曾裁掉最早快照，全部撤销也不能将这个标记复位。past 与 future 的操作总数不超过 100，撤销本身不新增记录。

分叉删除的 future 条目及上限裁掉的条目，应同步清理其展开 ID 和反馈入口；不能复用旧 ID 指向新条目。撤销后条目仍在保留范围内时，已有详情可继续查看并明确“已撤销”，但不重发提交反馈。撤销／重做复用 store 当前的选区协调规则：校正现有目标、清失效对象，不恢复历史选区、滚动或输入草稿。

### 3.2 store metadata 与快照一致性

建议保留现有文档快照数组，新增平行的 `pastEntries/futureEntries`，统一由一个 history 转换函数原子更新；对 UI 暴露只读列表 selector，避免泄露全部快照。建议条目形状：

```ts
type HistoryEntry = {
  id: string;                 // 会话内唯一 entry id，不是 documentRevision
  label: string;              // 人可读操作名，未知命令有兜底文案
  target: {
    summary: string;          // 提交前文档中的位置摘要
    trackId?: string;
    measureIds?: string[];
    beatIds?: string[];
    objectIds?: string[];
  };
  effects: ILXMCommandEffect[];
};
```

`pastEntries[i]` 描述从 `past[i]` 到 `past[i+1]`（末项到当前文档）的一次已应用转换；`futureEntries[0]` 描述当前文档到 `future[0]`，后续 `futureEntries[i]` 描述 `future[i-1] → future[i]`。entry 与操作绑定，不随撤销重做生成新 ID。metadata 是会话 UI 信息，不存选区、布局、滚动、输入草稿，不写 `ILXMDocument`、JSON schema、导出文件或 localStorage。

| 事件 | 快照与 metadata 的同一事务 |
| --- | --- |
| `execute` 成功且 `changed` | 从命令与提交前文档生成 label/target，复制本次结果 effects；原文档与 entry 同时加入 past，均 `.slice(-HISTORY_LIMIT)`；同时清空两套 future |
| no-op／失败／取消／过期预览 | 不新增、不移动、不裁切历史；尤其 no-op 不截断 future |
| undo | 弹出最后一个 past 快照与 entry；当前文档与该 entry 同时前插 future；原样保存 metadata |
| redo | 移出首个 future 快照与 entry；当前文档与该 entry 加入 past 并同步裁切；原样保存 metadata |
| 导入／替换／切换文档成功 | 清空全部快照、metadata、瞬时反馈与展开状态，沿用 sessionVersion 边界；失败导入不清历史 |
| 复制到剪贴板 | 不修改文档，不入历史；遗漏信息走独立反馈。整小节“复制并插入”属于文档变化，正常入历史 |

断言：`pastEntries.length===past.length<=100`、`futureEntries.length===future.length`；跨 undo/redo／分叉后仍一致，entry/effects 不被后续命令覆盖。文档修订号可能在撤销后复用，不可充当 entry ID。未来若扩展公共 API，要同步调整 `EditorStore`、`EditorStoreState` 和 selector 类型，不能只改内部数组。

实施约束：

- metadata 在 store 的唯一 `execute` 提交入口生成，覆盖侧栏、快捷键、宿主直接调用及所有命令类型；不能只在工具栏点击处理器补记。使用 store 实例身份、会话边界与单调序号组合生成 ID，undo/redo 不递增生成 entry。
- label/target 从提交前文档与实际命令解析；新增对象等无提交前位置的操作使用所属轨道／小节或通用摘要，不杜撰位置。只保存展示所需位置，不复制整份文档、完整命令或歌词等输入内容。未知命令退化为“编辑曲谱”，未知目标退化为“当前曲谱”。
- metadata 构建失败采用兜底条目，不能让已经成功的音乐命令丢失提交或漏记历史。entry、目标数组与 effects 取独立快照；反馈和宿主回调不能通过共享可变引用篡改历史。
- 单次 `set` 同时发布文档、历史、metadata、可撤销状态及本次反馈事件；保持现有 `stateVersion`、选区协调与返回值语义。随后才调用现有宿主 `onChange`，每次真实提交／undo／redo 各一次。宿主回调抛错只报告错误，不回滚、重记或重复提交；no-op／失败／普通复制不发文档 change。
- 只读历史 selector 不暴露文档快照，保持引用稳定；历史关闭时不逐次渲染全部详情。总条目最多 100，影响正文按需展开，避免每次指针选区变化都克隆／遍历历史文档。

### 3.3 全局黄条迁移

移除 `index.tsx` 中全局 `EditorImpactNotice` 挂载。提取影响摘要／详情的纯呈现或格式化函数，供历史详情、短时反馈和现有 preview 复用；`BeatPastePreview` 的预览、结构影响确认、版本过期校验及提交前确认全部保留。错误／导入／导出提示仍各自负责，不统一塞入历史。

有附带 effects 的提交显示 **4 秒**短时反馈，可手动关闭；提供“查看影响”打开左侧历史并展开对应 entry。反馈不占工作台固定行，使用 `role="status"`，不抢焦点；4 秒计时与清理归独立反馈 owner，不修改历史内容。无 effects 的提交无需额外打扰，仍有历史记录。

复制 omissions 显示同样时长的短时反馈，“查看详情”打开**非历史详情**，不指向某条虚构历史。详情打开后使用独立快照，不随 toast 消失；可手动关闭，换文档清理。采用带独立事件 ID、来源（command／clipboard）、entryId（可选）、effects 的反馈对象，避免依赖 `effects` 引用变化判断新事件；复制覆盖 store.effects 或 undo/redo 清 effects 都不得抹去已有历史详情。反馈关闭／超时后留在历史的只有真实文档提交。

反馈事件由对应成功分支显式产生，复制失败、无 omissions、no-op 及错误不从残留 effects 生成新提示。连续反馈只显示最新一条，事件 ID 与会话边界共同保护计时器／关闭回调，旧回调不能清除新提示；替换文档或卸载时取消计时。反馈“查看影响”执行时再次按 entry ID 查找；已被分叉或裁切移除时清理入口，不跳到其他条目。若窄屏草稿保护暂不允许打开历史，保留当前详情请求，保护解除后再按 ID 核对，不提前标记为已打开。

影响呈现需区分预览、已提交、已撤销及复制遗漏语境。复制详情不能沿用“本次编辑／可撤销”，历史已撤销条目不能仍声称影响正在生效；位置沿用 effect 的原始编号，未知 effect 类型有通用兜底。4 秒到时只关闭反馈，不关闭用户已打开的详情、不抢焦点；焦点或指针停留在反馈上时暂停自动关闭，离开后继续，保证“查看影响”可操作。

## 4. 工作区布局适配

### 4.1 宽度合同

布局宽度 `W` 统一取编辑器宿主容器的可用 CSS 内容宽度；独占页面时自然跟随 CSS viewport，嵌入时不能改用 `window.innerWidth`。测量对象位于 rail／历史／属性分列之外，打开面板不能反过来改变断点输入而产生振荡。不依据显示器物理分辨率或 DPR。沿用现有 px 尺寸基线，断点切换只调整呈现，不产生文档命令。

| 可用宽度 | 历史 | 属性与工具 |
| --- | --- | --- |
| `>=1600px` | rail 常驻，展开后历史可参与 Grid 占列 | 可与右侧 `352px` 属性栏并列；超宽条件下属性栏最多 `384px` |
| `1200px <= W < 1600px` | `272px` 左浮层，从工具栏下工作区顶部展开，不覆盖工具栏 | 右侧约 `352px` 常规栏；打开历史覆盖部分谱面，不挤出外层横滚 |
| `960px <= W < 1200px` | 左浮层 | 右侧默认收起，按需抽屉；受可用空间约束，互斥开启两侧面板，保留各自草稿 |
| `<960px` | rail 保留，面板宽受容器约束 | 工具分两行，休止与完整技巧入口保持可达；H/P/滑音/上下扫/琶音继续直接展示，必要时所在工具行内部横滚；低频结构工具收纳到“更多”；历史／属性一次只打开一个 |

建议 Grid 主列 `minmax(0,1fr)`，布局相关祖先及 Flex 子项补 `min-width:0; min-height:0`；rail、历史、属性分别有尺寸 token。常规属性栏目标宽度 `clamp(352px, 0.24 * W, 384px)`，通过相同宿主容器查询或测量结果表达，不能直接用 `24vw` 使嵌入布局脱离 W。窄容器抽屉宽度不超过工作区，面板从工具栏之后的工作区定位，独立纵向滚动；浮层不从全屏顶部起算。不能以 `body overflow:hidden` 掩盖仍存在的宽内容。

当前右栏为 400px，352–384px 是本稿新增的尺寸提案，属于后续方案整体审阅范围，不能把原型验证视为已批准产品收窄。若按本稿实施，必须同步核验现有选区、简谱／歌词、和弦、歌曲、小节和技巧参数的内容宽度，调整局部换行／栅格，保留所有字段、错误提示及底部操作；不能只替换外壳 width。下拉、气泡、确认窗口及内部滚动也要受宿主边界约束，宽模式可用不代表抽屉模式已验收。

`MusicTextSidebar` 及参数 owner 保持单实例挂载，用 CSS／受控状态切换栏与抽屉，避免通过两套 JSX、变化 key 或断点条件渲染重建草稿。纯布局折叠或隐藏且未结束编辑会话时，输入留在原 owner，不自动保存到文档。若输入法组合或现有 `canCollapse/isTransitionBlocked` 不允许隐藏，延迟关闭并保留属性面板可见，历史延后打开；组合结束后重新核对会话与当前请求，不能提交组合中的半成品。

草稿需区分“改变呈现”和“离开编辑位置”：和弦、歌词、简谱实际切换目标／页签／段号／模式或结束编辑，按 v2 直接丢弃未应用输入，回到原位置读取已应用值；同目标重入或仅隐藏仍保留。歌曲及小节 settings 的离开确认继续有效，技巧参数按其现有 owner 协调，不推广成所有输入统一确认。本方案中的“保留草稿”只指纯布局变化，不能复活已离开位置的旧输入；输入法、确认及导出阻断沿用现有合同。

窄屏关闭／Escape 还原触发器焦点；若触发器因断点变化已隐藏，回到同功能可见入口或工作区焦点。模态抽屉约束焦点并使背景不可交互；隐藏的常驻面板应从 Tab 顺序和可访问树移除，不能只有视觉隐藏。rail 按钮具有名称及 `aria-expanded/controls`。

外壳统一管理历史／属性／参数及提交前确认的浮层优先级，覆盖结构确认、粘贴预览、技巧选择、输出阻断、图片导出及文字气泡等独立入口，不能只扩展现有三个请求类型的 modal 控制器就宣称完成。顶层 Modal 打开时暂停底层抽屉的焦点约束，使背景抽屉及无关 portal 不可交互；关闭后恢复仍可见的原上下文。Escape 只由当前最上层且允许关闭的菜单／弹层处理，不顺带关闭底层参数、抽屉或文字会话；既有 busy／禁止关闭规则保留。

参数控件的下拉／Tooltip portal 需位于当前可交互域，避免被抽屉遮罩或 inert 区域吞掉，也避免被面板滚动区裁切。宽模式非模态侧栏不启用背景 inert；仅因断点改变呈现不能额外触发业务关闭／结束编辑回调。

### 4.2 现有尺寸与谱面几何边界

- 字号、间距、控件、面板和断点沿用现有 px 基线，只调整本轮新增入口及面板所需的局部布局，不修改根字号、全局主题单位或 Ant Design 字号体系。
- 使用现有布局能力及必要的宿主宽度测量判断工具收纳。若需 ResizeObserver，按帧合并更新，避免布局振荡；不扩展为全局字体缩放工程。
- CSS px 不等于设备物理像素。DPR 只影响栅格清晰度等输出，不决定应用断点。
- SVG 保持现有 layout/viewBox 逻辑单位；DOM 浮层和命中依赖当前 CTM／逆矩阵。打印保持 A4 的 mm 几何；导出 PNG 像素与分辨率策略独立，不把界面尺寸或浏览器缩放写入导出尺寸。

### 4.3 谱面适配

删除 `.editor` 的 `min-width:1440px`，改造外层 `.editorContentContainer` 横向滚动来源；页面外壳无横向滚动，**谱面视口内部允许横向滚动**。纸张显示尺寸与核心音乐排版分离，保留现有谱面坐标体系。

谱面自动适应容器宽度，界面不再显示“适合宽度”／“100%”操作。内部继续使用 fit 几何，根据谱面容器内宽及留白重新计算显示缩放，不改拍号、时值、节奏、文档修订或导出基准。下述 actual 仅为内部基准与独立几何测试模式。现有密度和核心排版策略不因面板展开而自动改变。视觉变换、DOM 浮层、选区、悬停和指针命中必须使用同一实际矩阵，禁止再叠加手工 DPR／zoom 偏移补偿。

默认模式为 fit。actual 固定使用当前常规纸面基线：纸张 `780 CSS px`（border-box）、左右各 `42px` 内边距，标准内容宽 `696px`；逻辑单位到 CSS px 的倍率固定为 `k = 696 / A4_CONTENT_WIDTH`。现有 `>=1600px` 将纸宽改成 800px 的媒体规则不再改变此基准，避免“100%”随断点变化。actual 的附加显示缩放 `s=1`；本期不新增任意倍率滑杆或音乐密度自适应。

fit 以完整可见包围宽度 B 计算，包含纸面及现有超宽 SVG，不只取 780px；至少满足 `B >= max(780, 84 + k * lxmLayout.width)`，再覆盖实际可见边界。设 C 为谱面视口扣除滚动条后的内宽，2g 为额外两侧留白，则 `sFit = min(1, (C - 2g) / B)`，仅在尺寸有效时计算。fit 允许缩小、不自动放大；超宽布局在 actual 中内部横滚，在 fit 中整体适配，不改变 core 排版宽度。浏览器缩放和 DPR 不参与 k 或 s。

显示变换必须同步占位：每页外层占据完整包围盒缩放后的宽高，内部纸面／SVG 以左上为原点应用同一缩放，不能只 `transform:scale` 却仍让未缩放纸面撑开父级。多页间距、谱面内部滚动、DOM 浮层和实际 CTM 一起核对；模式／倍率变化显式触发浮层重定位，不能仅依赖可能不响应 transform 的 ResizeObserver。重新计算 fit 时保留当前可见页及逻辑位置，避免展开面板后跳回谱首。进行中的拖选若几何变化，安全取消或重新测量，不能用旧矩阵完成编辑。

屏幕缩放及占位样式只作用于编辑舞台；打印仅呈现独立 `ScorePrintLayer`，打印媒体规则隐藏 rail、历史、抽屉、遮罩、反馈及全部交互 portal，包含挂载在工作区外的气泡／Popover／Modal，覆盖浏览器原生打印，不能只隐藏 `.editorWorkspace`。PNG 与打印继续从已提交文档构建既有 `purpose:"presentation"` 布局，不读取屏幕 DOM、fit／actual 倍率或滚动位置；草稿输出闸门、版本校验、字体准备及取消合同保留。回归实际打印预览和 PNG，而不只检查屏幕截图。

## 7. 实施前关注点

本次复核已将以下缺口纳入实施合同，当前只补方案／原型，不表示产品已具备这些能力：

- 技巧命令先补字段判等回归，再落地上下扫的 Add／Update 分流；按钮箭头沿用演奏方向映射，不能从英文名称猜屏幕朝向。
- 历史 metadata 与文档快照集中提交；覆盖直接 store 调用、宿主异常、全部撤销及分叉／裁切，不能用当前 effects 拼列表。
- 新快捷意图补齐参数 owner 与 IME 保护，明确区分新建和已选对象编辑；更多技巧窗口的默认值与提交流程保留。
- 布局隐藏保留输入，实际离开编辑位置执行 v2 当前规则；属性保护可能延迟窄屏面板互斥，不能以丢草稿或自动应用解决。
- 固定纸宽、工具收纳与面板占位一起核验；隐藏外层溢出不足以满足适配。单位迁移和全局字号改进继续移出本轮。

## 8. 实际实现与回溯

谱面 Backspace/Delete 通过 `resolveScoreDeleteCommand` 按当前对象分发。选中技巧时只发对应 ID 的 `RemoveTechnique`，不把技巧映射的 TAB 区间当成音符删除范围；没有技巧选中时才使用 `RemoveNotesInRect`。失效技巧 ID 不回退删音符，提交复用版本、输入法/草稿及模态保护。

本次用户指令授权按方案及交互稿实施，设计阶段“另开实施任务”的前提已满足。没有修改文档 schema、导出基准、根字号或全局主题单位；应用接入不等同于完成真实 IME、浏览器原生 200% 缩放及多浏览器人工验收。

### 8.1 数据提交与领域规则

- `stores/editor-history.ts` 将快照与 `pastEntries/futureEntries/baselineAdvanced` 放入同一 history 转换；`editor-store.ts` 唯一 execute 成功分支生成提交前位置摘要与会话内单调 ID。UI 读取稳定 `historyEntries/historyView`，不会拿到文档快照。metadata、目标数组、effects 和反馈均保留独立冻结快照，宿主回调参数亦隔离。
- 提交、撤销、重做与分叉在单次 Zustand 发布中同步文档和历史；失败/no-op/普通复制不入历史，no-op 保留 future。导入成功按 `sessionVersion` 清理；失败保留原会话。100 条裁切与全撤销后仍保存裁切起点标记。
- `core/technique-equality.ts` 按各类型领域字段判等，忽略 ID 与属性插入顺序；重复 Add 仍在冲突矩阵前识别。上下扫从最新目标拍解析 Add/Update，Update 保留技巧 ID 并完整替换 draft，未吞并普通冲突。

### 8.2 工具与 owner

- `editor-technique-target.ts` 共用目标解析；`editor-tool-actions.ts` 新增独立 `restToggle/quickTechnique`，保留键盘 rest/restore 原语义。H/P 限定同弦，单点按下一音解析，反向选区使用完整端点排序；上下扫范围使用规范化多弦选区。
- `EditorToolSymbolButton` 使用具名符号、等宽热区、按下态及独立 Tooltip portal；滑音改为单个 S 快捷，与 H/P 一致，悬停提示“滑音”，按起终音品位自动确定方向并直接提交；扫弦与琶音仍提供上下两个快捷。谱面滑音增加 S 标记并保留方向斜线。休止符使用 Bravura `U+E4E5`。撤销/重做图标独立缩小到 16px，不改变按钮热区。更多技巧和既有对象编辑继续读取自身默认/实际参数。
- 参数宿主由固定定位 portal 保持同一参数树挂载，按宿主内容宽度和可见边界限位；实现上不再依赖原 Ant Popover 的 viewport 限位。Select 下拉挂在参数域内，参数正文独立纵向滚动，断点/关闭只改变呈现。
- `technique-parameter-owner.ts` 内部跟踪 dirty，但协调器仅登记组合输入、结束缓冲和 busy，不将未应用参数作为离开确认条件。宿主关闭或切换工具调用 discard，重读已应用值；输入法期间暂缓关闭，自身显式提交与其他 owner 的保护继续生效。参数目标及意图通过会话版本、文档对象、stateVersion 与目标签名再次核对。
- 外壳与 `editor-command-adapter.ts` 在提交前及异步确认内再次执行目标/版本保护；活动简谱焦点即使仍保留 TAB 选区，也不能通过新增快捷提交 TAB 休止或技巧。

输入补充合同：简谱单音与连续录入的正文输入均支持 Enter 应用，连续简谱侧栏用 Shift+Enter 换行；原 Ctrl/⌘+Enter 兼容。歌词单点 Enter 沿用“应用并下一处”、Shift+Enter 仅应用，连续歌词 Enter 整批应用；和弦名称与指法数字字段 Enter 应用当前和弦。歌曲/小节设置文本或数字字段 Enter 应用当前组，技巧参数 Enter 对应添加/更新；Select 和按钮保留自身键盘行为，不因 Enter 触发复制或删除。所有入口沿用组合输入及结束冷却、busy、有效性和目标版本检查，重复 keydown 不重复提交。

TAB 的 `fret: "x"` 表示未指定品位的弹奏标记，保留现有 schema 与 X 键输入，不再因 x 拒绝连接技巧、单音技巧、续音、拆分或合并，也不在数字转 x 时清理仍合法的技巧。仅两端均为数字时比较音高方向及同品位；同弦、顺序、邻接和冲突检查保留。快捷 S 遇 x 时使用默认上滑方向，完整技巧菜单可指定上下方向。扫弦/琶音范围内 x 与数字统一显示规则。和弦指法图的禁奏 x 属于独立数据语义，保留其指法校验。

### 8.3 历史与反馈

- `EditorHistoryPanel` 只查看 metadata，列表按完整逻辑时间一次反向显示；已撤销、当前节点及裁切起点均有文字。展开影响不改变文档或选区；底部与工具栏共用历史处理器，分叉/裁切清理失效详情 ID。
- `EditorFeedbackController` 独立管理 4 秒剩余时长、悬停/焦点暂停、会话与事件 ID。command 反馈打开真实历史条目，clipboard 打开独立快照；反馈超时不关闭已打开详情，隐藏时保留待打开请求。旧计时器不能清除新反馈。
- 仅移除外壳全局黄条；`EditorImpactDetails` 复用影响呈现并区分预览/提交/已撤销/复制。粘贴预览及提交前影响确认保留。

### 8.4 布局与几何

- `use-editor-host-width.ts` 观察编辑器根内容盒并按帧合并；`data-layout` 驱动 959/960、1199/1200、1599/1600 边界，rail/历史/属性列不反向影响宿主断点。属性树保持单实例，纯隐藏不调用业务离开/提交；IME 或 busy 阻断隐藏时保留面板并延迟请求。
- `use-workspace-overlays.ts` 统一观察实际模态域，覆盖运行时确认、独立输出与内联确认，暂停底层抽屉约束并隔离背景；窄屏抽屉处理焦点循环、Escape 和可见触发器恢复。属性 Select/Tooltip 使用属性域内 portal。打印通过独立 print layer 白名单隔离全部交互 portal。
- `score-view.ts/use-score-view.ts` 固定 `k=696/A4_CONTENT_WIDTH`，纸面基准 780px；应用自动 fit，移除模式切换按钮，内部几何测试仍保留 actual 模式。stage 同步缩放后占位，纸面和 SVG 共用实际矩阵；倍率变化取消拖选并显式触发浮层重定位，保留可见逻辑中心。PNG/打印继续使用 presentation 布局。
- `system-layout.ts` 按固有小节宽度贪心分行，下一小节放不下就换行；每行（含单小节行和末行）的正文目标宽度为 `Math.max(staffWidthLimit, pendingWidth)`。剩余空间按各小节 `intrinsicContentWidth` 比例分配，固定行头、padding 与小节间隔不参与伸展，最后一小节吸收浮点误差以锁定右边界。移除简谱 editing/presentation 的整行伸展上限与稀疏行上限；小节按最终宽度重新计算音符、简谱、歌词及技巧坐标，符号字号不变。单个固有超宽小节保持原宽度，不压缩音乐内容；编辑和成品用途的净空差异继续保留。
