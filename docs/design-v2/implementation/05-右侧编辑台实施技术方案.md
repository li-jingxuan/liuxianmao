# 右侧编辑台 v2 实施技术方案

> 历史方案：本文保留当时契约；最新离开规则以 [README](../README.md) 及 [10 · 和弦快捷气泡](../specs/10-和弦快捷气泡.md) 为准。和弦未应用输入现为离开丢弃，歌曲及小节设置仍确认。

本文基于[最终交互规格](../specs/02-交互规格.md)、[1440px 桌面基准稿](../prototypes/editor/desktop.html)及当前工作区源码编写。交付范围是实施方案；产品实现、测试执行和发布另行进行。源码依据包含当前未提交修改，实施前需重新核对，不能用旧分支覆盖这些行为。

## 1. 目标与实施边界

将现有右栏重组为「选区 / 简谱与歌词 / 和弦 / 歌曲」四入口，在不更换音乐引擎和命令体系的前提下，建立稳定的对象定位、节拍映射预览、任务分组和明确的应用动作。

- 产品仅覆盖宽度 ≥1440px 的桌面窗口，1440 × 900 为视觉基准；侧栏固定 **400px，含边框**，与谱面并排。保留收起，不提供全屏、展开或宽度切换按钮。
- 小于 1440px 维持桌面最小画布，允许横向查看，不增加移动布局、抽屉或底部编辑区。较低桌面高度由正文滚动解决。
- 歌词、简谱更换目标、页签、模式、段号或结束编辑，直接丢弃未应用输入；重复激活相同业务目标保留。不得恢复跨目标暂存、待处理历史列表、返回旧输入或文字离开确认。
- 和弦、歌曲设置及迁移后的段落标记保留离开确认。当前未应用输入仍阻断输出；已离开并丢弃的文字输入不再阻断。
- 简谱 `content / rhythm / itemPitch` 三组独立提交，不提供跨组应用全部；共享预览不代表合并命令。
- 收起侧栏、隐藏气泡不结束会话；气泡和侧栏继续共享同目标输入。结束文字编辑则执行离开规则。
- 沿用 Next.js、React 19、Ant Design 6、SCSS、Zustand 和 `@liuxianmao/lxm-editor`。不新增后台服务、存储协议、自动保存、草稿持久化或音乐算法。

独立 HTML 原型中的解析、固定曲谱、演示撤销、成功提示和部分按钮说明不能移植为产品逻辑。音乐预览和写入必须消费现有领域规划、真实命令结果及撤销历史。

### 2.1 必须显式处理的代码与设计差异

1. **覆盖默认值分开处理。** `NumberedEditor` 当前 `overwrite=true`，本轮沿用并明确显示状态，不按历史规格改成关闭。`readMusicTextDraft` 当前为歌词设 `allowOverwrite=true`；按最终规格 §5 改为新建歌词会话默认 `false`，用户明确允许后才替换连续规划标出的已有歌词。重复激活同一目标不重置开关，切目标按新会话初始化。单点编辑与明确删除沿用既有命令语义，不用连续模式的覆盖开关阻断用户编辑当前词。
2. **成员切换也执行文字离开政策。** 当前简谱成员选择在 `itemPitchDirty` 时拒绝切换；目标规格要求切成员直接丢弃。将其接入带新 `itemId` 的目标请求，同目标保持，换成员放弃当前文字会话未应用组并按真实数据初始化。连接操作的起止候选选择仍是当前会话参数，不应误当作编辑目标切换。
3. **和弦显示模式纳入脏判断。** 当前 `musicTextDraftValue` 对和弦仅序列化 `draft.chord.chord`，没有包含外层 `display`。设计要求名称、指法及显示配置一起应用，需将 `display` 纳入同一比较、基线与登记；仅改显示模式也必须受到确认和输出保护。
4. **外部更新与自身提交分开处理。** 当前简谱依靠 `externalNumberedVersion` 等 key 更新 owner。自身成功提交不得重挂载并清空其他组；外部更新使目标失效时，按规格撤去可提交预览并保留当前原文供查看，不依靠无条件重挂载删除输入。该保留仅属于当前失效会话，下一次显式离开即丢弃，不构成历史缓存。

这些均是待实施差量，不能将现有测试或原型检查描述为已验证此目标行为。

本轮回溯再明确三项实现约束：现有简谱 `apply()` 已拒绝多个脏组，并非已有“应用全部”；真正要补的是组级自动前进策略。现有设置在 `document` 引用改变时直接重新初始化，尚不满足保留未完成输入的外部更新策略。现有 `restoreGroup` 已在简谱组件内部实现，需要暴露接口并核对恢复基线，不能再实现另一套重置逻辑。具体落地见 §3.4、§6.5–6.6、§7.3。

## 3. 组件与状态归属

### 3.1 最小拆分

保留 `MusicTextSidebar` 为对外控制器和导航仲裁入口，不同时重写全部编辑逻辑。新增组件只承担稳定的呈现边界：

```text
EditorShell（谱面、布局测量、sidebarCollapsed）
└─ MusicTextSidebar（导航请求、当前目标、歌词/和弦输入）
   ├─ SidebarFrame
   │  ├─ 编辑台标题与收起按钮
   │  ├─ 四页签
   │  ├─ SidebarObjectContext
   │  ├─ 正文滚动区：各任务视图
   │  └─ 常驻动作宿主
   ├─ NumberedEditor（唯一简谱 owner，完整视图 + 快捷气泡）
   ├─ LyricFormView（两个受控表面，共用侧栏中的 draft）
   ├─ ChordEditor（受控视图）
   ├─ ScoreSettings（稳定 owner）
   │  ├─ ScoreSettingsForm（全曲字段）
   │  └─ MeasureSettingsForm（段落标记、范围复制）
   └─ 现有浮层位置管理 / 当前输入登记 / 影响确认
```

建议新增 `SidebarFrame.tsx`、`SidebarObjectContext.tsx`、`sidebar-context.ts`、`BeatMappingPreview.tsx`、`SidebarActionBar.tsx`、`MeasureSettingsForm.tsx` 与 `SidebarFrame.module.scss`。不要求为每个折叠组另建容器或全局 store。现有 `NumberedEditor` 内部状态先保留，避免视图改造同时改变提交时序。

内部 `propertyTab="paragraph"` 可保持兼容，只将显示名改为「简谱与歌词」；`SidebarTab` 仍表达业务 kind。无需为了文案全面改名 target、action 和旧测试中的内部键。选区子入口保留 `note / measure / tuplet`；`barline` 导航归入小节，并聚焦边界组。

### 3.2 状态清单

| 状态 | owner | 生命周期与约束 |
| --- | --- | --- |
| 已应用曲谱、选区、撤销、剪贴板、版本 | 既有 editor session store | 写谱只经原提交路径；视图不持有另一份 document |

### 3.3 挂载、收起与 Portal

`MusicTextSidebar` 始终挂载。收起隐藏的是侧栏视觉框架，不是整个控制器及 owner 树；不能写成 `{!collapsed && <MusicTextSidebar />}`。框架隐藏后移除侧栏控件的 Tab 可达性，将焦点放到谱面上明确的「打开编辑台」按钮。再次打开仅恢复可见性、原任务和输入，不再次执行 `open(target)` 或读谱初始化。

简谱继续由同一 `NumberedEditor` 通过 `createPortal` 渲染气泡；歌词继续两个受控视图共用 `draft`。气泡 DOM 宿主不能放在被 `hidden` 的侧栏视觉容器内。隐藏侧栏不应通过祖先 `inert` 意外禁用仍可见的气泡。模态层打开时则同时禁用两个输入表面。

底部动作由当前 owner 渲染到 `SidebarFrame` 的稳定 actions 宿主，事件仍调用 owner 的原提交函数。正文与底部不各自维护 `dirty/canApply`。Portal 变更宿主可能重建视图节点，因此宿主保持稳定；字段不得因普通预览更新改变 key。跨表面转移焦点只在明确的「完整设置」、错误定位或返回编辑动作中发生。

### 3.4 宿主、controller 与可读状态接口

以下为**待新增的接口约束示意**，并非当前代码已经导出的类型。实施时复用现有 `NumberedDraftGroup / SettingsGroup / NumberedPropertyApplyResult / SelectionRequestResult`，不要创建含义相同的新枚举。

```ts
type SidebarHosts = {
  songBody: HTMLElement | null;
  measureBody: HTMLElement | null;
  actions: HTMLElement | null;
};
type GroupStatus = {
  dirty: boolean;
  canApply: boolean;
  blockedReason: string | null;
};
// 补入现有 NumberedEditorController：
// applyGroup(group, isCurrent?, options?: { advance?: boolean })
//   => Promise<NumberedPropertyApplyResult>
// restoreGroup(group) => boolean
// readStatus() => { groups, busy, composing, targetKey, generation }
// ScoreSettingsController 同样补 applyGroup / restoreGroup / groups，
// 保留其同步 boolean 返回契约，不为接动作区强行改成异步。
```

`restoreGroup` 返回 false 表示组合输入、确认或提交中未执行，调用者不能先显示“已恢复”。简谱内部已有同名方法，将其抽成唯一回调并增加闸门，再挂 controller。`readStatus()` 从 owner 最新有效引用读取；父级渲染用回调订阅状态，事件处理用同步读取，避免只读上一帧的 `onDirty` boolean。

宿主由稳定 callback ref 登记；初次渲染为 null 时 owner 已可存在，只延迟渲染对应 Portal。宿主必须是固定节点，不能以 activeTab 或 previewKey 为 key；小节宿主放在其常驻 hidden 容器中，不藏在 `if (!measure) return` 之后。无有效小节时由视图显示空态，owner 仍保留待处理输入。非当前任务不向公共动作槽渲染按钮，不能靠按钮上 `display:none` 掩盖多 owner 同时占槽。

`editorWorkspace` 的可见 grid 子项仍只有谱面容器与侧栏框架；分离控制器时不得增加第三个占宽包装节点。owner 可以作为无布局的逻辑组件存在，所有表单通过稳定宿主呈现。只要求当前文字会话跨收起/预览/自身提交稳定；真正接受换目标、换模式或换 session 时可销毁并重新初始化，不为“稳定”保留已离开的 owner。

每个表面登记自己的根节点和字段 ref，至少区分 `sidebar / popover / song / measure / actions`。`ScoreSettings` 当前的 `container.contains()` 与 `container.querySelector()` 只认识 owner 的 DOM 后代，迁移到 Portal 后必须改为显式表面引用，不能继续拿空 owner 容器寻找字段。简谱原 `root.querySelector()` 同样按正文宿主执行。

React Portal 的合成事件仍沿 React 父树冒泡；DOM 包含关系、原生事件和 CSS 祖先关系不会跟随。owner 的组合输入保护只计入一次，两个表面调用相同 start/end/observeKey；动作槽提交也要检查保护。下拉的 `getPopupContainer` 不得指向被收起或设为 inert 的框架；沿用现有弹层层级并检查遮挡。

## 4. 桌面外壳与视觉落实

编辑器外层设置 `min-width:1440px`；页面祖先保留可达的水平溢出，防止小窗口被 `overflow:hidden` 截断。不要给全站所有页面增加最小宽度。`editorWorkspace` 使用：

```scss
.editorWorkspace {
  display: grid;
  grid-template-columns: minmax(0, 1fr) 400px;
  min-width: 0;
  min-height: 0;
}
.editorWorkspace[data-sidebar-collapsed="true"] {
  grid-template-columns: minmax(0, 1fr);
}
.sidebarFrame {
  display: flex;
  flex-direction: column;
  min-width: 0;
  min-height: 0;
  overflow: hidden;
}
.sidebarBody {
  flex: 1;
  min-height: 0;
  overflow-y: auto;
  scroll-padding-block: 12px;
}
// 标题、页签、对象条与动作区 flex-shrink: 0；边框计入 400px。
```

以上为目标结构示意，实施时合并现有规则，不能简单追加覆盖。移除 `score-editor width < 1200px` 下与侧栏上下重排有关的规则，并检查低高度规则是否仍把侧栏改成第二行；打印、图片导出和独立弹窗布局保留原契约。

标题、页签、对象条和底部动作位于主滚动区之外。删除现有正文/表单多层 `overflow:auto` 带来的纵向双滚动；允许节拍图和长差异表单独横向滚动。底部只显示当前任务具体动作和其他脏组导航，不把所有高级操作常驻到底部。

用现有主题变量和 Ant Design 控件实现原型的间距、边界、文字层级及可见焦点。四页签在 400px 内完整显示中文标签，可去掉冗余图标，不靠省略主标签解决宽度问题。预览数字、弦号、拍位使用等宽数字；普通字段保留现有易读字号，不照搬原型中偏小的提示字号。

侧栏收起/打开后使用实际容器尺寸重新计算谱面与气泡位置，沿用已有测量和浮层观察机制，不硬编码 `viewportWidth - 400` 作为谱面宽度。更宽窗口只增加谱面可用区域。截图基准为 1440 × 900，补充 1920 × 1080 及 1440 × 720 的低高度检查。

## 5. 对象定位与只读预览

### 5.1 对象条

新增纯派生函数 `deriveSidebarContext`，输入当前 document、业务编辑目标、TAB/简谱选区、小节显式目标及检查项，输出可读对象名、位置、作用范围、有效性和定位目标。输出结构是 UI view model，不能转存为音乐目标。

- 歌词：`trackId + measureId + eventId + verse`，合法空白位置使用既有 `tick/endTick` 解析；不能从 TAB 弦号推断歌词位置。
- 简谱：区分事件、`itemId` 成员与连续输入范围；沿用 `resolveNumberedEditorTarget`、`numberedTargetKey`，不能把同一 TAB 拍里的不同简谱事件合并。
- 和弦：`trackId + measureId + beatId`，明确标注 TAB；弦号可用于谱面选取，但不制造新的和弦业务对象。
- 小节：使用 `MeasureToolTarget`，段落标记有未应用值时显示其原 owner 目标；与当前谱面不同则提示「正在编辑原位置」。
- 歌曲：显示「整首歌曲」；基础拍号另列实际影响区间。范围、连音组显示起止与成员/比例。

小节序号从当前轨道数组解析，简谱拍位使用 `formatNumberedBeatPosition` 及该小节拍号，不用数组下标冒充拍位。无效 ID 显示失效原因，不回退到邻近对象或第一个小节。

「定位谱面」新增独立只读回调，复用现有 layout/scene 的包围盒和 `revealFloatingTarget` 的滚动计算。现有 `revealFloatingTarget` 可用于文字目标；TAB、小节、连音范围补充相应布局引用。定位只滚动和短暂描边，不调用 `select/open/onScoreSelection`，不提交，不把焦点从输入框转移到谱面。「切换到当前选区」则必须走导航请求，两者分开。

### 5.2 节拍映射

`BeatMappingPreview` 只消费 owner 生成的展示行，建议行字段为稳定 key、真实目标、位置文本、旧值、新值、状态、节奏信息与可检查性。适配器将现有类型转成展示行，不在组件里重新解析音乐。

简谱数据来源为 `editNumberedTrack` 的当前候选、`buildNumberedPreviewRows`、`nextFocus` 及领域返回的移动、覆盖、缩短和记号影响。横向位置用 tick/范围比例表达；纯字符数、空格数和演示节拍均不能用于计算影响摘要。`overwritePreview` 仅说明未获覆盖许可时的潜在影响，不能让 `canApply` 绕过原始操作的校验。

歌词数据来源为 `parseLyricSequence / planLyricSequence` 及其 `rows / changes / overwrites`。音符、原词、新词、跳过、错误和超谱尾状态同时保留；连续 `_` 显示保留原词。检查某行仅更新 inspection 和谱面提示，不改变整批起点。

输入非法或不完整时显示当前错误，撤下当前可提交节拍图；不得用上一次合法结果配上当前输入。输入过程中不写 store、不生成撤销记录。规划结果应依赖目标、原文、模式/范围、覆盖设置及当前 document；继续使用现有 memo，先不引入 worker 或虚拟列表。组合输入期间不重建字段；结束组合后再进行完整校验。

### 5.3 预览适配的数据边界

建议按下列字段适配展示数据，具体类型定义在视图模块；音乐标识仍使用原领域类型：

```ts
type PreviewPosition = {
  trackId: string;
  measureId: string;
  startTick: number;
  endTick: number;
};
type MappingRow = {
  key: string;
  before: string;
  after: string;
  positionLabel: string;
  status: string; // 实现时收敛为原状态联合，保留 remove/release/error
  sourcePosition: PreviewPosition | null;
  plannedPosition: PreviewPosition | null;
  canInspect: boolean;
};
```

当前 `NumberedPreviewRow` 已含 `measureId / startTick / endTick / before / after / rhythm / status / impact`，但没有独立 eventId；不能拆解复合 `key` 字符串充当事件标识。适配时在 owner 内结合 beforeTrack、candidate 和操作的真实 ID 关联，并保留原位置与规划位置。仅移动未改音高的事件也必须显示位移；`same` 文字状态不等于“没有时间影响”。删除与 release 行仍显示旧范围和释放信息。

候选新建事件的 ID 尚未写入当前 document，不能对其调用 `open(target)` 或假装谱面已存在。inspection 以当前真实小节与 tick 范围定位，描边属于临时预览层；无可解析原谱位置的行禁用定位并说明“应用后出现”。定位接口接收只读位置引用，与业务 `MusicTextTarget` 分开。

歌词的 `plan.rows[].beatNumber` 当前是事件/位置顺序号，不能显示成音乐拍位。对 `eventId` 查真实事件 tick，对空白位置取 `tick/endTick`，再用所在小节的拍号格式化；没有目标的超谱尾行只有错误，没有虚构拍位。跨小节预览按真实小节顺序分段，每段 tick 从该小节起算，不能把不同小节的局部 tick 直接排序在同一标尺上。

区分两类错误：解析失败或目标失效时撤下可提交预览；仅缺覆盖许可且规划仍返回完整 rows 时，保留标注“待允许覆盖”的影响预览，应用禁用。不要因 `issue !== null` 一律藏掉用户需要确认的覆盖条目。摘要数量取领域结果，歌词 `same/skip` 不计入覆盖，`changes=0` 不制造写谱历史。

## 6. 导航、提交与输出契约

### 6.1 统一请求顺序

所有会改变编辑目标的操作继续进入 `MusicTextSidebar.request`，包括页签、子任务、谱面对象、段号、模式、成员选择、结束编辑和工具跳转。请求处理顺序为：

1. 检查组合输入与结束冷却、提交锁、活动模态层和已有确认；受阻时保持受控页签、目标和谱面选择不变。
2. 根据规范化的完整业务目标和模式判定重复请求；同目标、同页签、同模式保持输入。
3. 检查仍需保护的设置/段落标记及和弦；有修改则显示既有确认。文字离开直接丢弃不能跳过这一检查。
4. 请求接受后才清理离开的文字输入和当前登记，再更新选区、业务目标、可见任务及 owner 初始化。
5. 按动作来源恢复焦点；预览 inspection 和收起按钮不进入上述离开流程。

当前 `resolveSidebarRequest` 有同 kind 的 `ignore` 分支，实际页签变更还需结合 `propertyTab` 判断；不能把「同为 score」当作歌曲到选区无需确认，也不能让点当前页签清空输入。`selection / numberedSelection / activeObject` 的变更由接受动作统一完成，禁止先改谱面高亮再等待确认。

实际需修复两个入口：`cancelTextEditing()` 当前直接 `perform({ type:"close" })`，而 close 执行分支会放弃设置；应改为 `request(close)`，仍由文字直接丢弃政策处理，但先保护其他设置。页签判重比较可见任务 `propertyTab + 子任务 + kind + mode`，再检查是否真离开；不能仅因 `kind` 相同就返回 ignore。已经确认接受的内部执行函数才允许调用 perform，UI 不直接调用。

目标判重也不能比较未经解析的输入对象。新增纯函数 `normalizeMusicTextTarget(document, target)`：歌词先经 `resolveLyricPosition` 转为事件或合法时间窗，verse 缺省归一为 1；简谱经现有 resolver/key；和弦仅比较轨道、小节、TAB 拍 ID。忽略歌词/和弦附带的 TAB 弦号，不让同位置“eventId 表示”和“tick 表示”误判为不同目标。归一化仅解析身份，不读入或覆盖当前输入；解析失败按失效请求拒绝，不回退到别的对象。

| 动作 | 歌词/简谱有未应用值 | 和弦/设置有未应用值 |
| --- | --- | --- |
| 真正换目标、页签、模式、段号或成员 | 接受后直接丢弃；非法输入和多脏组同样处理 | 按任务确认；取消保持原状态 |
| 同完整目标、当前模式/页签 | 保留 | 保留 |
| 展开组、检查预览项、定位谱面 | 保留，不换提交目标 | 保留 |
| 收起侧栏、隐藏气泡 | 保留，不结束会话 | 保留 |
| 结束文字编辑 | 丢弃；若另有设置脏值先处理其确认 | 结束当前受保护任务仍确认 |
| 导出 | 阻断，处理后用户重试 | 阻断，处理后用户重试 |
| IME 中请求会结束编辑的操作 | 阻止 | 阻止 |

取消确认返回原输入表面。待执行目标带现有 session/version 或等效有效性检查；确认期间目标删除、换文档或版本变化，不执行旧请求。不要借新 UI 建立第二套通用导航状态机。

将当前只保存 action 的 pending 扩为 `PendingNavigation { action, expectedVersion, ownerGeneration }`，`expectedVersion` 使用 `captureEditorVersion` 的完整快照，确认前调用 `sameEditorVersion` 并复核目的目标；仅 `sameEditorSession` 或“ID 仍存在”不足以证明旧导航有效。若用户选择先应用当前受保护任务，再切换，则应用确实成功且仍属原 owner 后，用成功结果对应的最新版本更新 expectedVersion，再验证目的目标。期间另有外部变更则终止旧导航，不把自己的正常提交误判为 stale，也不无限接受任意新版本。

### 6.2 简谱独立提交

沿用 `createNumberedSubmission` 和 `checkNumberedDraftDependencies`。底部「应用简谱内容」调用 `applyContent`，「应用时值」「应用单音符音高」调用对应 `applyGroup`；现有 controller 的 `apply()` 只允许零个或一个脏组，多个组时已返回 blocked。新底部继续使用明确组接口，不把兼容方法包装成跨组按钮。

暴露 `restoreGroup(group)` controller 方法，将现有组内恢复逻辑提升为可复用回调，供正文和底部共同调用。现有 `discard()` 是整个当前会话重置，用于明确离开/丢弃，不能拿来实现「恢复本组」。未成功组继续保留原文和基线依赖。内容组恢复还需核对模板/范围/覆盖配置：当前内部实现会设回若干默认值，不能把这个行为误称为恢复最近一次已应用的完整配置；目标实现应保存结构化的组基线，恢复该基线，不反向解析用于比较的 fingerprint 字符串。

统一流水线为：构建该组操作 → 最新版本规划 → 依赖校验 → 必要的影响确认 → 再验版本与目标 → 原 `commit` → 按 `applied/noop/blocked/cancelled/stale` 更新。只在真实成功后刷新该组基线；取消、失败或过期均不清脏值。确认中的按钮与气泡共享原提交锁，一次手势最多执行一次命令。输入推进使用核心返回焦点，不能猜下一拍。

「新录入时值」偏好与「当前事件时值」分开。正文应用不能用模板覆盖已有事件时值。均分、等分持续音、连接和粘贴仍是独立命令，执行前检查其他组依赖；折叠组不改变合法性。延音线按成员、连音线按事件，继续使用现有核心约束。

### 6.3 歌词与和弦

歌词继续由侧栏持有输入、映射和 apply 逻辑。单点 Enter 应用并下一处、Shift+Enter 仅应用；未修改时导航不创建空歌词；连续 Ctrl/Cmd+Enter 提交一次整批规划，任何错误整批拒绝。已有四段、空白合法位置、跳休止、64 字/256 位置限制及换行/制表符拒绝均保留。预览覆盖数量不等于授权覆盖。

和弦继续受控，预设只更新草稿；按项目现有指法图组件/图元绘制草稿，不从名称猜音高。六弦、横按、观察窗口和显示配置均进入当前和弦独立提交。禁奏/空弦清手指、最多四横按、端点合法性和非标准调弦禁预设沿用 `validateChordDiagram` 及现有规则。清除指法图保留名称，删除已有和弦是另一项明确命令。

### 6.4 当前输入与输出

继续使用 `useEditorDraftRecords` 登记当前 owner，结合 `isOutputBlocked` 与运行时状态检查覆盖文件/图片等既有输出入口。正文非法、其他简谱脏组、设置脏值、组合输入、提交/影响确认均不得从新外壳绕过。

登记随已接受的文字离开同步失效；下一次输出检查读取当前状态，不等待旧 effect 才判断。`NumberedEditorSnapshot` 是当前输入的只读快照，不得保存成按目标 Map。`OutputBlockedModal` 可展示此刻活动 owner/分组的阻断原因及「返回当前编辑」，不增加工具栏待处理入口或已离开位置记录。保留既有明确放弃能力时仍需用户操作，不因打开导出自动放弃。

处理完成后关闭提示，由用户重新发起导出；不在旧回调里自动继续。返回编辑需先打开侧栏并定位相应组；设置的段落标记返回「选区 → 小节」，全曲字段返回「歌曲」。

### 6.5 单组成功与自动前进的冲突处理

当前 `NumberedEditor` 内部 `applyGroup` 默认 `advance=true`，`onSuccess` 会将 `result.nextNumberedFocus` 转成下一目标，再由 effect 触发父级导航。因此“单组成功后保留其他组”不能只靠 `onSuccess` 中少调用几个 setter 保证；接着发生的目标导航仍会清空它们。

明确采用以下策略：

1. 内容录入可请求自动前进；时值组和成员音高组的主要按钮默认留在原目标，controller 对这两组传 `advance=false`。
2. 内容提交前只要另有脏组，就把本次提交的实际 advance 固定为 false；提交成功后再次读取组状态，仍有任一未应用组也不触发下一目标。受依赖保护而 blocked 的提交不进入前进路径。
3. 没有其他脏组且核心确实返回下一焦点时，先完成成功组重基、释放锁和当前登记更新，再发起一次有效的目标转换。无下一焦点则留在原目标并显示谱尾状态。
4. 影响确认等待期间冻结本次组、操作、版本、输入代次和 advance 选项；重复按键或另一表面的点击不能改写原请求。取消和 stale 不导航。

不要为了保留其他组而把它们暂存到下一目标，也不要把明确离开策略改成确认。显式用户换目标仍直接丢弃；这里限制的是提交程序自动触发的前进。新增用例必须证明：“内容 + 仍兼容的时值修改 → 应用内容 → 仍在原目标且时值未应用”，以及“仅内容修改 → 正常按核心焦点继续录入”。

### 6.6 版本、重基与失效生命周期

区分文档内容变化和编辑会话替换。保存几个输入字段到 ref 不能代替版本检查。所有异步确认同时校验当前 session、文档版本、目标和输入代次；inspection、分组展开和普通滚动不递增输入代次，真正改值/目标/模式才递增。

| 来源 | owner 处理 | 可提交性与旧回调 |
| --- | --- | --- |
| 当前组自己的成功命令 | 标识为自身提交，读取真实结果，重基成功组及未修改字段 | 不重挂载；保留兼容的其他脏组；旧候选失效 |
| 同 session 的撤销/重做或其他命令 | 读取新文档，比较当前组依赖；干净字段跟随，脏字段保留原文 | 依赖未变可重算；已变显示冲突，用户恢复或重新确认输入后再规划，禁止自动重放 |
| 当前事件/成员/小节被删除 | 当前会话进入失效状态，保留原文及原位置说明 | 撤去提交候选，禁止旧提交；显式离开后丢弃，不自动选邻近对象 |
| 换文件、重置会话或新 session | 按既有 session 外层 owner 生命周期清理所有旧记录/Portal/确认 | 旧输入不得进入新文档；新 session 按新数据初始化 |

因此前文“外部失效保留原文”只指**同一 session** 的当前输入，不跨文件保留。失效状态不是可恢复历史栈；仅提供查看原文、恢复/结束及重新选取的现有入口。若保留原文需要展示在空态中，必须在 `if (!track || !measure)` 的提前返回之前接住失效会话。

设置 owner 当前在 `state.document !== document` 时全量 `fresh()`，本轮要按上表替换为受控重基。`rebaseSettingsDraft` 可保留未提交组的值，但仍需逐组比较旧 initial 与新字段，标记同字段冲突；不能把外部新值静默设为 baseline 后直接覆盖。换 session 则允许重新挂载，不能把“稳定 owner”理解成永远不销毁。

同字段冲突不新增离开确认或自动合并。将该组标记为需要重新检查，保留原文并禁用旧候选；恢复该组会读取最新已应用值，用户核对后真正修改该组字段则形成新的输入代次并按最新文档重算。单纯重新渲染、定位或再次点击旧应用按钮不解除冲突。其他未冲突的组仍可按依赖规则独立处理。

失败与取消的 UI 处理统一：`blocked` 展示原校验；`cancelled` 保留值且不显示成功；`stale` 撤旧候选并要求重验；`noop` 只重基明确处理的组，不增加 history、不清其他组。回调返回时先验会话，失效 owner 不再调用焦点、setMessage 或更新新任务状态。

### 6.7 当前登记的同步失效与所有入口接线

现有 `useEditorDraftRecords` 在 `useEffect` 中注册和释放，coordinator 的 `register()` 返回单条释放函数；因此 §6.4 的“同步失效”是**需要实现的接口差量**。不能只在离开时 setState 或等卸载 cleanup，也不能只清父级 numberedDirty。

为登记增加 owner 实例 token 和输入会话 generation，hook 暴露同步 `invalidateOwner()` 句柄，或在 coordinator 中增加等效的带 token 失效方法。该能力只清当前 owner 的记录；设置四组共用其设置 token，当前文字 owner 与设置 token 分开。record 的释放函数必须校验注册实例 token，旧 cleanup 不得按同一个 record.id 删除较新的登记。

接受真正离开的动作按以下顺序执行，整个转换由原请求仲裁入口负责：

1. 所有 IME、锁、确认和目标检查通过，确定本次确实接受；尚待确认时什么也不失效。
2. 同步撤销离开输入的提交许可/输入 generation，调用该 owner 的登记失效句柄；旧 effect 即使随后运行，也因捕获的 generation 过期而不能重新登记。
3. 同步更新用于 `readStatus/isOutputBlocked` 的活动 owner 引用，标记旧文字会话不再活动。协调器与 controller 是两条检查通路，二者都不能继续返回旧 dirty。
4. 丢弃旧文字值，更新受控选区/目标/任务并初始化新的文字会话；新登记只能携带新 generation。真实新 dirty 状态仍需阻断输出，不能因清旧登记出现一次漏检。

只收起、inspection、重复激活不调用失效。清理不得在 React render 中执行；外部 store 的通知与句柄创建遵循现有运行时订阅边界。StrictMode 的 effect 重跑也需保持单个有效登记，旧 owner promise 和 cleanup 均不具备删除新 owner 状态的权限。R10 同时断言两条输出检查结果与旧 effect 迟到，不依赖主动刷新界面。

接线范围明确覆盖：

| 入口/返回路径 | 必须补齐的调用 |
| --- | --- |
| 图片导出 | 继续读 coordinator + controller，阻断时打开现有输入提示；不先创建导出快照 |
| 文件导出 | `ScoreFileControls` 增加 `onBlocked(intent)` 回调，交由 EditorShell 打开同一当前输入提示；实际输出仍只序列化已应用文档 |
| 文件导入/替换文档 | 沿用原入口阻断；文件读取完成、最终接受前再次检查当前输入与完整版本。读取期间出现编辑则拒绝旧导入结果，不能当作普通文字目标导航自动丢弃 |
| 返回当前编辑 | 关闭阻断提示 → 显式打开侧栏 → 经任务路由显示当前组 → 节点可见后 focus；不要以旧 `onOpen` 的现有语义猜测其会打开新框架 |

为收起状态单独提供 `onExpandSidebar`，与现有用于清除谱面交互的 `onOpen` 区分。record 的 focus 回调必须调用新的展开路径；只把字段 focus 过去不能打开 hidden 框架。图片/文件处理结束均要求用户重新发起原动作，不保存待续跑的导出或导入闭包。

## 7. 小节表单迁移的具体方案

采用 **保留单个 `ScoreSettings` owner、拆受控视图** 的方式。该 owner 在侧栏框架外稳定挂载，分别向歌曲视图宿主和小节视图宿主渲染表单；隐藏和收起不卸载 owner，不在两个栏目各实例化一个 `ScoreSettings`。本轮不把设置草稿搬进全局 store。

### 7.1 字段和命令归属

| 项目 | 目标位置 | 状态和执行方式 |
| --- | --- | --- |
| 标题、作者、调性 | 歌曲信息组 | 保留 `SettingsGroup="info"`、`SetNotationInfo` |
| 基础拍号 | 歌曲基础拍号组 | 保留 `signature`，以首小节发出 `SetTimeSignature(scope="untilNextChange")` |
| Capo | 歌曲变调夹组 | 保留 `capo`、`SetCapo`，空字符串不转 0 |
| 段落标记 | 选区 → 小节 | 保留 `label`、原小节 ID 与 `SetSectionLabel` |
| 局部拍号 | 选区 → 小节 | 当前已在此处；沿用工具 `signature` action，不复用基础拍号草稿 |
| 起止小节、插入位置 | 选区 → 小节 → 范围复制 | 保留 `SettingsCopyRange` 参数与 `CopyMeasureRange`，经 `executeTool` |

基础拍号与局部拍号虽然使用同一核心命令类型，起点不同，不能共用一个 UI 字段。局部选择沿用当前立即执行的工具语义并明确「选择后生效」；原型的分组应用区不意味着需给所有小节按钮新增草稿。

复制参数不是尚未写入曲谱的内容草稿，修改参数不单独阻断导出、不生成离开确认。复制执行仍在设置 dirty 或组合输入时受阻；先沿用现有保守保护范围，不在迁移时放松。范围内外连接遗漏、结构影响和取消行为由 adapter/core 返回，禁止视图直接深拷贝小节。

### 7.2 owner、目标与焦点

`ScoreSettingsForm` 移除 label/copy 表单，新增 `MeasureSettingsForm` 复用原字段 ID 和受控 props；不使用 Ant Form 的 `initialValues/name` 再存一份值。owner 保留 `state.value / initial / issues / copy`、composition、版本检查、`submitSettingsDraft / rebaseSettingsDraft`。先保持 `ScoreSettingsDraft` 和 `SettingsGroup` 类型兼容，避免迁移时同时改数据模型。

controller 补充按组 `applyGroup`、`restoreGroup`、组状态查询和可指定组的 `focus`；保留旧方法供现有调用方过渡。`focusField("label"|"copy")` 改为通过受保护导航打开「选区 → 小节」再在 DOM 可见后定位；不能继续硬设 `propertyTab="song"`。`section/copy` 的工具导航也映射至此。

owner 以实际原小节 ID 提交标记。干净 label 可跟随已接受的新小节；有脏 label 时先确认，未接受前不更换 owner 目标。复制参数使用稳定小节 ID，删除来源/终点后显示失效项并禁用执行，不自动替换为首小节。当前设置实现主要读取首轨；本轮沿用现有单轨约束，不宣称增加多轨设置支持。

仅切换到同一 owner 的另一已显示组、展开折叠或定位字段，不是离开，不丢值。显式换到其他一级任务，或切换脏 label 的目标小节，仍走设置离开确认。外部变化导致无法定位时禁止旧提交，并保留可查看输入/错误，不移写到当前选区。

全曲设置继续独立应用，底部不增加“应用整首歌曲所有设置”。现有设置确认涉及多脏组时显示「返回分别处理 / 放弃并切换 / 继续编辑」，不把三个简谱组纳入其中。保留 legacy `apply()` 供既有协调路径使用时，也不能将其包装成新的跨组主要动作。

### 7.3 设置按组状态、目标与命令的接线

每组 dirty 使用 `settingsKeys[group]` 比较 value/initial；`canApply` 需要组合输入/忙碌保护及 `prepareSettingsSubmission(..., group)` 的实际校验结果，不能沿用单个 `dirty && !composing` 冒充各组可应用。`restoreGroup` 只恢复该组字段、清该组错误，重新计算其他组合法性；`discard()` 仍为明确放弃整个设置 owner。

小节表单的显式目标输入来自 `detailTarget` 或**已接受**的选区，不能在迁移后只保留 `selection.focus.measureId`。owner 的已绑定 `measureId` 与希望进入的 `requestedMeasureId` 分开：脏 label 未获确认前，控件标签、提交参数、定位和错误都用已绑定 ID；确认接受后才更新它。基础拍号永远从首小节读取，不随该局部 ID 改变。

局部拍号和小节结构动作通过原 `handleToolbarAction/executeTool` 发出，执行前读取最新设置状态；若任一受影响设置组未处理，显示具体组并返回处理，不能因操作位于同一小节面板而跳过闸门。复制继续先阻止任一 settings dirty，不另发“顺便应用 label”的命令。点击后设置本地 busy，禁用第二次复制与目标变更；在 finally 释放，任何过期结果先验 session。复制的结构确认仍只由 adapter 管理，不再套一层表单确认。

返回编辑与错误定位使用明确的 `group / field / target` 请求：`info/signature/capo` 路由到歌曲，`label/copy` 路由到小节；先完成受保护导航，再打开侧栏、展开组，最后在对应宿主可见的 layout effect 中定位字段。`focus()` 无组参数时优先上次活动脏组，否则第一个脏组，最后才回默认全曲入口。父级只知 settingsDirty、不知具体组的旧流程必须改用此接口。

当前 `ScoreSettings` 只登记一条泛称“歌曲设置”的 record。目标方案按四个 `SettingsGroup` 分别登记，记录 ID 使用当前 session + owner + group，label 的 targetKey 带原小节；`copy` 参数不登记为 dirty record。四条 record 共用一个 owner，`apply/discard/focus` 分别绑定组级方法，避免协调器遍历时重复执行全量 apply/discard。组变干净可保留干净登记或移除，输出仅显示当前脏组，不出现跨目标条目。

迁移顺序固定为：先给 owner 增加组方法/多表面引用 → 接入常驻双宿主 → 移动受控视图 → 改 section/copy/focus 路由 → 改登记 → 删除旧表单位置。每步检查页面只有一个 `settings-label` 和一组 copy 字段；不要让“临时兼容”同时渲染两份相同 ID 控件。

## 8. 焦点、IME、错误和可访问性

- 保留现有 `shouldIgnoreMusicTextKey`、settings composition 和结束冷却机制，不用一个通用 `onKeyDown` 覆盖已有规则。组件拆分或 Portal 后，两个输入表面都必须被同一 owner 的组合输入保护覆盖。
- 输入时仅更新受控值和预览，不通过每次 render 的 effect 自动 focus。显式跨表面转移时，记录文本选区，目标节点可见后恢复；原节点已删除时退回组标题/正文入口。
- 气泡和侧栏字段 ID 带 surface 前缀，label、描述与错误各自正确关联。隐藏视图用 `hidden/inert` 排除 Tab；不要把只隐藏的字段仍留在键盘顺序中。
- 页签采用受控 Tabs，方向键/Home/End 触发相同请求；不先改变选中样式。选区三个子入口沿用同一规则。
- Escape 优先关闭下拉、菜单和确认层；在文字输入层才结束编辑并丢弃。组合输入期间不得借 Escape 离开。文本框内复制、粘贴、撤销保留文本语义，不透传为谱面命令。
- 底部和字段共享同一错误源；失败保留输入，摘要能展开并定位错误组。不可应用原因显示文本，禁用按钮旁提供可读说明。预览不只依靠颜色表达变化。
- 状态区用适量 `role="status"` 公告提交结果，不逐键朗读整张映射。高亮与焦点轮廓分开，布局过渡遵守 reduced motion。

### 8.1 收起与组合输入、确认层的处理顺序

收起不丢输入，但会隐藏当前 DOM 并移动焦点，因此也可能结束原生 IME。若侧栏字段正在 composition 或结束冷却中，收起按钮保留可见说明并暂不可执行，不通过 blur 强行结束候选；组合结束后用户再操作，不排队偷偷收起。如果组合发生在仍可见的气泡中，可仅隐藏侧栏，不能移动气泡焦点或重建气泡。

已有 inline 离开确认、简谱原生 dialog 或结构影响 Modal 打开时，不允许收起其承载框架；先完成或取消当前确认。确认不是第三份表单，取消后按发起表面恢复焦点。程序调用收起也经过相同闸门，不能仅靠禁用图标按钮。

收起时焦点原本在侧栏才转移到重新打开按钮；焦点已经在气泡或谱面则保持。打开侧栏时仅显式触发的“完整设置/返回编辑”聚焦具体字段；普通打开恢复已记住的有效控件或组入口，节点失效则选可见入口，不回旧位置重建输入。

只读「定位谱面」和 inspection 的鼠标操作需要在 pointerdown 阶段避免把焦点从当前文本框移走，不能只在 onClick 结束后重新 focus；后者已经可能打断 IME。键盘激活这些按钮时保持按钮自身可访问焦点，不强行拉回输入。程序滚动采用 preventScroll/定向容器滚动的组合，避免同时滚动正文和整页。

设置字段修改只清理所属组的过期错误，并重算相关依赖错误；不能继续用当前 `update()` 的 `setIssues({})` 顺手清掉其他组错误。全局 stale 错误在确实重新校验后清理，错误摘要与动作区始终读取同一份结果。

| 简谱内容、时值、成员音高分别修改和应用 | 仅指定组写谱，其他未应用组保留；依赖冲突指出具体组；恢复只恢复指定组 |
| 简谱单音/同时音、范围/模板、均分与自选时值 | 现有解析与范围规则保留；预览来自规划；模板不覆盖已存在事件时值 |
| 简谱移动/缩短/记号影响 | 提交前显示真实影响；取消不写谱；确认过期不执行旧命令；两表面重复点击只执行一次 |
| 延音线、连音线、连音组与等分持续音 | 目标和术语各自正确，非法关系给出现有原因，不借离散动作提交其他组 |
| 简谱范围复制、覆盖/插入粘贴 | 读已应用谱，空剪贴板可解释；真实遗漏/覆盖/移动摘要；不清空无关脏组 |
| 歌词单点与四段 | 独立简谱归属；Enter/Shift+Enter、末尾、未改导航和明确删除正确，不受 TAB 换弦影响 |
| 连续歌词：空格、全角空格、`_`、休止、空白位置 | 领域映射逐项一致；`_` 保留原词，不创建简谱音符；检查预览不换起点 |
| 歌词覆盖、64字/256位置、换行/制表符/超谱尾 | 默认保护已有歌词；错误整批不写；允许后按当前规划覆盖；非法原文可编辑 |
| 和弦名称、预设、六弦、手指、横按、起始品位与 display | 修改仅入草稿，真实校验；显示模式单改也计脏；应用一次只写当前 TAB 和弦 |
| 非标准调弦 | 常用预设暂停，可自定义；已有指法不自动改写；未生成虚假声音推断 |
| 歌曲信息、基础拍号、Capo 独立应用 | 作用范围正确、空 Capo 不当 0；不可编辑拍号只读；调性不隐式转调 |
| 段落标记跨小节导航、失效小节 | 绑定原小节；有脏值先确认；取消不切目标；失效不写新小节 |
| 局部拍号、小节线/谱首反复、范围复制 | 原命令语义与谱尾限制保留；结构影响经 adapter；取消不产生半次操作 |
| 和弦/设置离开与取消 | 继续编辑恢复原页签、目标、输入；文字直接丢弃不能跳过仍存在的设置保护 |
| 双表面与「完整设置」 | 实时同值、同预览、同锁；同步不抢焦点；显式转移才恢复目标字段 |
| 中文 IME、键盘、Select 弹层 | 候选 Enter 不提交；组合中不离开；文本撤销不撤谱；Escape 按层关闭 |
| 当前输入输出检查 | 任一当前脏组阻断；返回对应新位置；不自动应用/丢弃/继续输出，无旧目标记录 |
| 自身提交、撤销/重做、换文档及外部目标删除 | 自身提交不重建 owner；外部失效撤预览、保留当前可查看原文；旧确认不写新文档 |
| 文件/图片导出、打印 | 仍使用已应用文档及原输出管线，侧栏布局样式不污染独立输出 |

浏览器验收同时检查 console/pageerror、实际 document 与 historyDepth，不能只以成功提示或截图判断写谱正确。真实中文输入法需人工补验，脚本派发 composition 事件仅验证事件处理分支。

### 11.3 补充回归脚本与精确断言

这些是实施阶段需补入现有测试的场景，本轮文档修订没有执行产品测试。

| 编号 | 最小操作序列 | 关键断言 |
| --- | --- | --- |
| R01 | 同事件准备兼容的 content/rhythm 脏值，应用 content | document 仅更新内容；history 仅该命令的实际变化；目标不前进；rhythm 原文与 dirty 保留 |
| R02 | 仅内容脏，应用后核心返回 nextFocus | 成功组与登记先重基，再导航一次；无旧当前记录；没有用户目标 Map 或旧输入恢复 |
| R03 | 打开影响确认，再在另一表面重复提交/改输入，随后取消或令版本变化 | 不改变原请求 advance；最多一项有效命令；旧候选不能确认；取消不清输入 |
| R04 | 以自选模板/范围应用内容，再改该组并恢复 | 恢复最近已应用的结构化组基线；时值/音高组不变；恢复不增加历史 |
| R05 | label 在小节 A 未应用，从显式详情进入 B，取消确认后再接受放弃 | 取消时标题/定位/提交 ID 全是 A；接受后才改成 B；只存在一个 label 字段 |
| R06 | label 和 capo 分别未应用，从输出提示返回 label，恢复 label | 打开小节视图并聚焦字段；capo 仍脏仍阻断；没有全量 discard 副作用 |
| R07 | owner 保持挂载，将全曲/小节表单分别渲染到 Portal 后输入中文、定位错误和收起 | 两处保护均生效；能找到迁移字段；候选不会因收起丢失；气泡组合输入不被无关侧栏抢焦点 |
| R08 | 预览包含新建、移动、删除、release、跨小节行和歌词覆盖保护 | 不向当前曲谱查询候选新 ID；位移前后位置准确；各小节分段；无许可仍能查看覆盖而不能提交 |
| R09 | 同 session 删除目标、撤销/重做，再切到新文件 | 同会话失效输入可查看且不能提交；新文件中无旧输入/旧登记；旧 promise 不写错误或抢焦点 |
| R10 | 接受文字离开后，在 React effect 尚未补跑的调用序列里立即检查输出 | 已离开文本不再阻断；仍有 settings 脏组则继续阻断；不依赖定时器猜同步完成 |
| R11 | 同一歌词位置先以 tick 窗口进入、再以 eventId 进入，默认/显式第1段和不同附带弦号重复进入 | 规范化后相同身份，不丢输入/光标；不同段号和不同真实事件仍正常触发离开 |
| R12 | settings 未应用时从文字结束入口退出，随后在确认期间改变文档但保留目的 ID | 不绕过设置保护；取消保持原任务；仅 ID 仍存在不能让旧版本导航落地 |
| R13 | 文件导入读取期间新增输入/替换 session；文件导出受阻后返回已收起的侧栏 | 旧导入结果拒绝替换；导出使用同一提示；侧栏确实展开到正确组；处理后不自动续跑 |

R01 应挑选通过既有依赖校验的值；存在冲突时应验证 blocked 并保留输入，而非修改核心让测试强行成功。R03、R09 使用可控的确认终态与版本变更，不用固定 sleep。浏览器里补测实际 400px 外宽、收起无多余 grid 列、单主滚动与重复字段 ID；不要把 DOM 结构快照作为唯一通过条件。

## 12. 风险、完成定义与交付记录

最高风险是 owner 被页签/收起重挂载、迁移后小节 ID 漂移、底部接错跨组提交、Portal 脱离 IME 事件保护，以及旧版外部更新 key 清掉尚需展示的输入。分别由稳定 owner、显式目标、组接口、双表面组合输入检查和自身/外部更新分流解决，相关断言在对应切片内完成。

现有设置批量提交可能在多条命令之间遇到版本变化；继续按 `submittedGroups` 重基并保留未完成字段，不承诺跨组事务原子性。歌词整批应用和单个领域命令的原子行为仍由原核心保证，不能用 UI 成功文案掩盖部分完成。

实施完成需同时满足：本方案差量与矩阵通过、既有音乐功能无回归、真实浏览器共享输入/焦点验证、必要检查通过、最终桌面截图与规格差异登记齐全。发布或合并由后续实施任务决定。

本次只核对源码与设计并生成技术方案；未修改产品代码，未运行上述产品测试。既有原型的模拟 DOM 检查与截图证据继续见[评审核对](../records/03-评审核对.md)，其通过结论不代表本文实现验收。
