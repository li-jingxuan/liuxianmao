## 设计基线

使用 `ui-ux-pro-max` 与 `frontend-design`，沿用当前编辑器的白色谱纸、灰蓝画布和蓝色操作色，系统中文字体、本地音乐 SVG；桌面编辑器保留现有 1400px 最小宽度。本轮不通过调整正式产品路由来展示设计。

拟用核心色：纸白 `#FFFFFF`、工作灰 `#F4F6FA`、墨蓝 `#202838`、交互蓝 `#285BE0`、选择浅蓝 `#EDF3FF`、错误红 `#BC3547`。控件 32～36px 高，间距 8／12／16px，名称输入与应用同行；库列表独立滚动、详情固定；指板是自定义指法弹窗的主视觉。

技能检索首轮 `music editor compact controls` 返回影音深色首页建议，与当前编辑器不符，未采用；收窄为 `desktop editing tool minimal`，采用其简洁工具布局原则，颜色与字体服从项目现有规范。`keyboard focus modal` 命中可见焦点与焦点不被遮挡；Next.js 表单搜索的服务端提交建议不适合本地编辑器，改查 React 局部表单状态后采用相关建议。

## 已确认的行为

1. **连续选区采用范围编辑。** 简谱以完整事件为单位，`1+3` 同时发声算一组；歌词限定当前段。拖选、Shift 扩选、跨小节、跨排版行，不跨轨道、不混选 TAB。支持整段回显、替换与清空；输入不能越过选区，短输入剩余位置留空；本轮不扩大为批量八度、变音等属性编辑。键盘沿用 TAB 的左右导航、Shift 扩选与 Esc 折叠到焦点的习惯。
2. **不处理旧谱兼容，正式实现时修正 mock 调性数据。** 技术事实：`1=C` 只表示数字 1 的音高，不能独立区分 C 大调与主音记 6 的 A 小调；现有 `score.meta["lxm:tonality"]` 已有明确的主音、大小调与小调记法。原型直接使用明确 C 大调、G 大调、A 小调示例；快捷项读取已应用曲谱调性。库内临时浏览其他调性不修改曲谱。
3. **和弦统一显式应用。** 名称、快捷和弦、和弦库选用、自定义指法完成与显示方式统一更新草稿，由名称右侧“应用”写入谱面；删除按钮例外，立即删除并清空名称。气泡与侧栏共享草稿，自定义取消不修改父草稿，完成只回填。
4. **“更多配置”打开精简和弦库。** 仅保留“全部和弦／我的指法”；快捷列表自动跟随调性，不再保留手工增删排序配置。

其余实现口径沿用当前规则：简谱 `_` 表示跳过，歌词 `_` 表示留空；范围输入为空表示清空所选范围，时值和歌词锚点保留。歌词仍跳过休止和延音，不混合不同歌词段。原型用固定事件演示范围，不能作为正式节奏排版验收。

自定义指法采用 `1` 食指、`2` 中指、`3` 无名指、`4` 小指、`T` 拇指，`0` 取消手指指定；手指默认未指定，同指重复不判冲突。结构错误仍保留（例如品位不合法），header 仅显示最新错误。

首轮需求与设计回查补充：调性分类复用正式和弦目录，不能将小调中的属大三和弦／属七和弦标成自然小调调内项。统一“按弦手指”在已有选中对象时编辑它，无选中时可显式指定下一次新建手指，不能从上次选中对象意外继承。切换文本目标沿用当前正式会话规则（离开文本目标丢弃未应用输入，组合输入／弹窗仍阻止切换，歌曲设置仍有离开保护），不新增自动应用。
