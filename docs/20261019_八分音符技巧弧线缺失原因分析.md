# 八分音符技巧弧线缺失原因分析

日期：2026-10-19。修复已完成；下文复现数据记录修复前行为，最终方案采用品位数字中心锚点与纵向净空。

## 结论

已复现 4/4 拍相邻八分音符之间的延音线、击弦和勾弦弧线退化。新增技巧命令成功，领域数据与 SVG 路径均存在，但旧端点策略要求横向完全避开两端品位字形、白色描边和间隔，未利用数字上方的空间；紧凑排版下绘制逻辑将终点钳制到起点，曲线三个点的横坐标相同，无法形成正常弧线。

触发条件是旧策略的横向避让过度，并非对 4/4 拍的特殊限制。多小节紧凑排版更容易触发，两位品位比一位品位更容易触发。

## 原因链路

1. 页面 `apps/website/components/EditorShell/index.tsx` 默认使用 `compact` 密度。
2. `packages/lxm-editor/src/layout/technique-spacing.ts` 的 `buildTechniqueInsets` 已为推弦、揉弦、滑音等预留横向空间，却未为 `tie`、`hammerOn`、`pullOff` 预留最小弧线跨度。单独添加这些技巧后，返回的占位 Map 仍为空。
3. `packages/lxm-editor/src/layout/technique-layout.ts` 的旧弧线模板将起点放在前音品位完整边界右侧 2 个逻辑单位，终点放在后音完整边界左侧 2 个逻辑单位。
4. 旧模板使用 `x2 = Math.max(startX, endX)`。当终点小于起点时，起点、控制点、终点的横坐标全部相同。改变纵向 lane 无法恢复水平跨度。

两位品位的边界宽度由 `getFretTextBounds` 计算：`2 × 12 × 0.65 + 2 × 2.5 = 20.6`。因此音符中心距至少要大于 `20.6 + 2 × 2 = 24.6`，才可能产生非零弧线跨度；清晰可读还需要额外长度。

## 复现与单变量对照

构造无歌词、简谱和和弦的 4/4 小节：前两拍点为同弦 12 品八分音符，后接三个四分音符拍点，时间位置为 `0、480、960、1920、2880`；通过真实 `AddTechnique` 命令添加延音线，再以 A4 内容宽度执行 `buildLayout`。

下表数值均为核心布局逻辑单位，取两位小数：

| 对照条件                   | 音符中心距 | 扣除两端净空后的跨度 | 结果     |
| -------------------------- | ---------: | -------------------: | -------- |
| 单小节，紧凑，两个八分音符 |      24.00 |                -0.60 | 钳制为 0 |
| 八小节，紧凑，两个八分音符 |      17.25 |                -7.35 | 钳制为 0 |
| 八小节，舒适，两个八分音符 |      36.65 |                12.05 | 正常弧线 |
| 八小节，紧凑，四分音符对照 |      30.56 |                 5.96 | 非零弧线 |

最小复现生成的路径为：

```text
M 62.3 116.6 Q 62.3 110.6 62.3 116.6
```

临时诊断覆盖 `tie / hammerOn / pullOff`、第 1 / 3 / 6 弦和单 / 双位品位。断言仅检查路径存在时会通过；增加“终点横坐标大于起点”的断言后，单小节 18 个用例中 9 个失败，八小节紧凑谱例中 18 个全部失败。另有 12 组密度、节奏和小节数量对照确认上述几何关系。诊断用临时测试已清理，未将已知失败断言加入正式测试集。

## 最终修复方案与风险评估

影响局限于 `tie / hammerOn / pullOff` 的技巧几何，评估为风险可控的局部修复。实现保持现有音符间距，使用以下规则：

1. 真实端点的横坐标对齐各自品位数字中心，以完整音符中心距作为弧线跨度。
2. 端点纵坐标高于本行品位字形及白色描边，额外保留 2 个逻辑单位间隔，并计入弧线本身的半线宽。
3. 跨行时只调整真实音符端点，续接端保持原谱行安全边界；每行分别读取本行锚点高度。
4. H/P 标签居中置于曲线控制点范围上方，计入标签白色描边，避免遮盖弧顶。
5. 继续使用现有碰撞避让、命中范围、谱行扩高、分页和共享渲染流程。

主要视觉影响是相关谱行可能略微增高，以容纳上方弧线和标签。测试确认音符横坐标、小节宽度和断行不受影响，文档数据不被布局修改；滑音、推弦等其他技巧维持原有锚点策略。编辑、预览与图片导出统一消费核心布局。
