# REQ-089 编辑器 GitHub 开源与中文 README

**目标**　外部开发者能从公开仓库判断授权范围、选择接入方式并完成本地运行。

## 交付与验收

1. 明确公开源码范围、许可证和第三方素材声明。核对谱例、音色、字体、图标的再分发依据，检查拟公开文件及其历史中的内部配置。
2. 中文 README 首屏包含产品说明、实谱截图、Web 与桌面入口，以及 React、独立 Core 两条接入路径。写明依赖版本、安装、开发、测试与问题反馈方式。
3. 新环境按 README 从公开仓库检出、安装、构建并运行示例。逐个验证两个 npm 包、版本化 API 文档与 GitHub Release 的链接；发布页列出实际可下载的平台制品、版本和校验值。

**待确认**　GitHub 组织、源码许可证、素材授权和维护人。包与平台制品由 REQ-090 至 REQ-093 提供。[开源与三端交付方案](../../首发筹备/02-开源与三端交付.md)

## GitHub 与 npm 发版

飞书 REQ-009 使用以下发版规则。

- `main` 用于日常合并。需要让正式版本修补与新功能并行时，再维护 `release/1.0` 分支。每个对外版本用 Git tag 标记具体提交，如 `v1.0.0-rc.1`、`v1.0.0`、`v1.0.1`。GitHub Release 绑定对应 tag，列出变更、支持平台、安装包、SHA-256、npm 包和 API 文档。
- 双包先生成 tarball，在仓库外验证。需要让外部开发者试装时，在开源与分发条件满足后，先发 Core，再发依赖它的 React。两个候选包对齐版本，如 `1.0.0-rc.1`，使用 npm `next` dist-tag。
- 建议正式版从同一发布提交构建。先验证 Core 的 `1.0.0` 可安装，再验证 React 的 `1.0.0` 自动拉取匹配 Core，两包通过后再切换到 `latest`。GitHub Release 随已通过签名、实装与跨端验收的桌面制品发布。
