# REQ-096 六线猫曲谱文件

产品验收已完成。 [飞书需求](https://pcnhehlhivqu.feishu.cn/wiki/UEivw1G7Liuaqnk20d1cqCoxnHb?sheet=tcgLfi&range=A89) · [曲谱文件设计基线](../../design-baseline/score-files.md)

## 确认方案

- 六线猫原生曲谱统一导出为 `{曲谱名}_{yyMMdd}.lxm`。日期取浏览器本地的导出当天，曲谱名沿用现有清理规则和未命名回退。编辑器主动导出和未导出离开提示里的下载使用同一文件名规则。
- `.lxm` 文件沿用现有 UTF-8 JSON 文档、Schema 标识和版本 8。浏览器继续按 JSON 内容类型生成下载。文件扩展名与文档版本分别管理，旧版 v4–v7 仍按现有流程升级后打开。
- 首页和编辑器的文件选择器、拖放导入只接受 `.lxm`，扩展名大小写等效。导入沿用 10 MiB 上限、内容格式及版本校验、预览和确认换谱。
- 沿用现有菜单与弹窗布局，统一顶栏、导出弹窗、离开确认和导入说明里的曲谱名称。Web 先接入，桌面版后续沿用此文件约定。

## 验收标准

1. 在 `/editor` 修改曲谱，经「导出 → 六线猫专用谱(.lxm)」下载，核对文件名中的曲谱名和本地日期。回到首页用选择文件导入，再从编辑器拖放同一文件，预览正常并能恢复修改。
2. 将有效曲谱内容分别保存为 `.lxm.json` 和 `.json`，确认两种扩展名均会被拒绝。用 `.lxm` 承载 v4–v7 旧谱内容验证升级提示与打开结果。
3. 导入损坏、错误版本或超过 10 MiB 的曲谱时显示对应提示，当前曲谱仍在。仅将其他 JSON 改名为 `.lxm` 也应被拒绝。
4. 修改后触发离开确认，在弹窗中下载 `.lxm`，确认待导出状态更新，并可继续原操作。

## 验证记录

Chromium 实页验证了正常导出、离开确认下载、曲名清理和本地跨年日期。首页选择和编辑器拖放均可恢复曲谱，`.LXM` 可打开，`.json` 与 `.lxm.json` 会被拒绝。已检查损坏、非曲谱及超限文件的提示。REQ-048 浏览器文件流程回归通过，系统原生文件选择器的实际筛选待跨浏览器验收。
