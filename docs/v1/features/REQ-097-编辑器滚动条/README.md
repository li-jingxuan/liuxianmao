# REQ-097 编辑器滚动条

产品验收已完成，经典模式默认可见滑块定为 2 px。 [飞书需求](https://pcnhehlhivqu.feishu.cn/wiki/UEivw1G7Liuaqnk20d1cqCoxnHb?sheet=tcgLfi&range=A90) · [可操作原型](prototype/index.html) · [编辑器设计基线](../../design-baseline/editor.md)

## 设计方案

截图圈出的主谱面和右侧属性正文各自滚动，共用一套浅灰圆角滑块。评审反馈希望再减弱边缘的视觉干扰。新版用同一层半透明灰蓝，让滑块在白色侧栏和浅灰谱面底上都接近各自背景。默认保留细线提示滚动位置，长谱和长列表仍有可找的拖动入口。

- **主谱面。** 纵向滚动条位于谱面右缘，贴着侧栏分隔线左侧。谱面放大并产生横向溢出时，底部横向条使用同一套样式。缩放控件固定在谱面右下，原有 16 px 边距外再留出竖轨净空，出现横轨时向上避让。滚到最底或最右仍能查看最后一处谱面内容。
- **右侧属性栏。** 滑块只对应页签与对象摘要下方、页脚上方的正文。一级页签、对象摘要和页脚保持在各自位置。「音符／小节」切换、连音和节奏模板随正文滚动。展开模板沿用该滚动区。
- **尺寸和状态。** 经典模式下，12 px 操作槽保持透明，可见滑块在各状态均为 2 px。默认以 18% 灰蓝叠加底色，悬停用 `#98A4B4`、键盘聚焦用 `#7E899C`、拖动用 `#65758C`。交互只改变颜色，位置和形状保持稳定。滑块长度按可见内容比例变化，最小原生滑块长度以 32 px 为目标。正文不足一屏时无滑块，经典模式预留槽宽，使展开和折叠前后正文对齐。
- **输入和系统差异。** 方案使用各区域现有的原生滚动容器。滚轮、触控板、拖动和键盘滚动沿用浏览器行为。经典模式保留滚动槽，覆盖式模式以浏览器和系统的显隐及尺寸为准。只支持标准滚动条样式的浏览器使用原生窄条，键盘聚焦时加深滑块。系统偏好高对比度时显示更清晰的滑块，强制颜色模式使用系统滚动条。

## 对稿路径

1. 在至少 1440 px 宽的浏览器中打开原型。在同一滚动位置切换「4 px」和「2 px」，对比两处滑块的粗细。两档使用同一套颜色和拖动范围。
2. 鼠标在谱面或侧栏正文中移动时，滑块保持浅色。鼠标移到滑块上时颜色加深，鼠标移入移出时滑块没有横向跳动。拖动两条滑块时只有对应区域移动。一级页签、对象摘要、页脚和缩放都留在原位。Tab 聚焦任一滚动区后，按 Page Down 或 End 可继续浏览。
3. 切换「侧栏内容不足一屏」，核对无滑块且正文宽度稳定。点「编辑面板」收起和展开侧栏，谱面滚动条跟随谱面右缘。
4. 点「＋」将谱面放大到 200%，测试横向滚动和右下角缩放避让。点「重置视图」回到初始状态。

## 实施与验收

谱面沿用 `[data-score-viewport]`，右侧样式限定在实际属性正文 `#music-text-fields`。Chromium 经典滚动槽可能把指针按下传给谱面容器，实现按原生槽的实测尺寸识别横、纵滚动条，拖动时保留选区和侧栏位置。

交互稿使用需求截图中的谱面局部及代表性选区工具，专用于滚动对稿。浏览器和系统的覆盖式滚动条、触控板惯性和强制颜色表现列入实页验收。

在 `/editor` 打开《理想》，选中 TAB 音符，展开右栏拍内和整小节节奏模板。分别拖动谱面与右栏的滑块，检查两区独立滚动、选区和侧栏固定区稳定。用 Tab 聚焦谱面或右栏正文中的控件后按 Page Down，核对键盘滚动。放大至 200%，核对横向条、缩放控件避让和谱尾可达。拖动谱面滑块后，点谱面空白工作区可照常清除选区。

Chromium 实页已在 1440×720、1440×900 和 1710×951 通过上述检查，以及短内容宽度、末项可达和强制颜色回退检查。缩放锚点和试听自动跟随回归通过。真实系统覆盖式滚动条和 Firefox、Safari 显示效果待跨环境验收。

2 px 版本已在同样三组视口复验。两区滑块均可从透明槽边缘拖动。原型的 4 px 与 2 px 切换保留两区滚动位置，截图像素与标注宽度一致。
