**v1.0 待验收。** 用户断网启动六线猫时先看到这台电脑上的谱库，可以新建、导入或打开已有曲谱。编辑后保存并返回，下次启动仍能找到原件。下方保留设计评审稿 1 和原型。需求来自飞书 **v1.0 子表 D9eELE 第 18 行**。 [飞书原文](https://pcnhehlhivqu.feishu.cn/wiki/UEivw1G7Liuaqnk20d1cqCoxnHb?sheet=D9eELE&range=A18:J18)

## 本轮请确认的三项决定

| 决定 | 原型采用的口径 | 对用户的影响 |
| --- | --- | --- |
| 启动首页 | 新装时空库起步。已有条目显示「全部曲谱」，另展示最近实际打开的最多三份谱。一次打开进入同窗编辑器。 | 首页即可新建或导入。卡片用于继续上次工作，完整列表可按曲名、编配或文件名查找。示例馆藏仅供评审。 |
| 文件存放和导入 | **为用户选定的原件建本地索引。** 用户决定文件位置；导入确认后登记原件，保存写回原件。 | 现有曲谱不用搬家或再次复制。若原件被移动或所在卷离线，条目仍保留，用户可接回磁盘或重新定位。 |
| 首版管理 | 新建、导入、打开、重命名库内显示名、从谱库移除，以及缺失文件重新定位。移除仅删索引。 | 曲谱不会因整理列表而丢失。原件可再导入。批量操作、收藏分类、文件夹管理和删除磁盘文件可另行评审。 |

另一种存储选择是每次导入都复制到应用管理的资料夹。这样移动外部原件不影响馆藏，但用户之后会持有两份可独立修改的谱，保存目标、库副本的备份及删除都需要额外约定。本稿建议采用原件索引，以保留桌面端按用户选择的位置打开、保存、另存的习惯。以上三项均待产品确认。

## 首页和文件回路

1. **启动。** 保留六线猫品牌与原生窗口。全部曲谱默认按最后成功保存时间倒序，打开文件只更新「最近打开」。同一文件在两处共用条目。启动时可先用本地索引展示曲名、编配、调式、拍号和时间，打开时复核实际文件。没有最近记录时直接展示完整列表。空库显示双入口；搜索无结果时提供「清除搜索」。
2. **新建。** 必填曲名，编配选填，默认 C 大调、4/4、标准调弦、四个空小节。进入编辑器后首次保存仍需选择 `.lxm` 路径，写入成功后才登记。放弃未保存的新谱直接返回，取消首次保存则留在编辑器。
3. **导入。** 在谱库选单个文件，校验后预览谱内曲名、编配、拍号、小节数、原文件名与位置。确认「加入谱库」后停在列表。相同规范路径重新选择时仅更新现有记录，重名的不同路径各自登记。旧版可预览及迁移，覆盖旧件要再确认。取消选择、取消预览或文件损坏均保持原状态。原型内置可用、旧版及损坏三类虚拟文件。
4. **打开。** 点击整行、曲名或最近谱册，在同一个窗口打开一份谱。已登记文件无需重复选路径。系统「文件 → 打开…」及 `⌘O` / `Ctrl+O` 仍经过预览和换谱保护，确认并成功打开后加入索引。原生打开直接进入编辑器，首页导入允许先整理、多次登记再开始编辑。
5. **编辑与返回。** 在右侧「歌曲」修改曲名、编配或速度，点「应用更改」，再保存。仍有表单草稿时，先回到歌曲设置或放弃输入；已应用但未写盘时，返回提供「继续编辑」「不保存并继续」「保存并继续」。写入成功后才导航；写入失败可重试、另存或留在编辑器。单纯浏览或已保存时直接返回。系统关闭、退出、换谱继续共用原有离开保护。
6. **重开。** 返回后刷新 HTML，或关闭并重新打开同一文件及场景，首页恢复馆藏。打开该曲并核对编辑值。编辑器内的「另存为」成功后绑定新路径，新文件加入列表，同时保留原件条目。取消或失败时保留原绑定。

### 用户究竟改了哪一个名字

| 名称 | 显示与修改位置 | 保存后的结果 |
| --- | --- | --- |
| 谱内曲名 | 纸面标题、歌曲设置、导入预览 | 「应用更改」并保存后写入原件。尚未自定义显示名时，谱库标题一起更新。 |
| 库内显示名 | 列表、最近打开、管理菜单中的「重命名显示名…」 | 只改这台电脑的索引。文件名和谱内曲名都保留。移除后重新导入，以谱内曲名重新登记。 |
| 磁盘文件名 | 列表第二行，选择、保存和移除对话框内的路径 | 新建首次保存由用户命名。「另存为」可指定其他名字与路径。文件内容的曲名可以和文件名不同。 |

**移除确认。** 列表右端 `… → 从谱库移除…` 显示馆内名称、原文件名和所在路径，确认按钮为「仅从谱库移除」。取消保留条目；确认后同时从最近打开与列表移除。对移位或离线的文件也仅解除登记，可以重新导入原件。

**文件移位或磁盘离线。** 打开失败显示上次登记的完整位置。接回磁盘可「重试」，移动过的文件可「重新定位…」，核对预览后更新旧条目的位置、保留显示名并进入编辑器。选择已被另一条目登记的文件时提示重新选择。取消保留旧条目。评审可从「原型选项 → 下次打开时模拟文件移位」触发，随后选同名文件在「归档」中的新位置。演示卷始终在线，重新挂载后的成功读取待桌面实装验证。

**实现时需要覆盖的恢复路径。** 外部改写、只读、磁盘满或文件占用时，沿用宿主失败反馈，保留修改，允许重新打开或另存。写入期间发生新编辑，依当前快照判断是否允许返回。谱文件与索引是两次落盘；建议先完成原件写入，再原子更新索引。索引失败时分别告知「原件已保存」及「登记失败」，允许重试登记。历史安装没有索引时从空库启动，由用户导入既有文件，不扫描磁盘。

## 评审走查

| 路径 | 预期 |
| --- | --- |
| 两端分别打开「空库起步」→ 新建 → 填曲名 → 返回 → 保存并继续 | 明确空态；保存位置可取消。完成后新条目出现，刷新仍可打开。 |
| 点击《理想》→ 修改速度 → 应用更改 → 返回 | 继续编辑留在纸面，放弃后重开仍是旧速度，保存并继续后重开是新速度。 |
| 修改歌曲设置但未点应用 → 返回 | 先处理未应用输入，再处理已提交未保存的谱。 |
| 导入「清晨前奏.lxm」→ 预览 → 取消或确认 → 再次导入 | 取消无新增，确认后列表可打开，重复导入同一路径只有一条。 |
| 导入「未完成的传输.lxm」或「旧练习谱.lxm」 | 损坏文件可重新选择；旧谱保存有升级覆盖、取消和另存选项。 |
| 重命名显示名 → 移除 → 核对路径 → 取消 → 再确认 → 重新导入 | 取消保留条目；确认后只移除索引。可从同一路径再打开原件，原先保存的内容仍在。 |
| 在编辑器模拟下次写入失败 → 保存并继续 → 重试 | 失败时仍在编辑器，未丢失更改；重试成功才返回。 |
| 触发文件移位演练 → 打开 → 重新定位 → 选择同一文件的新位置 → 确认 | 核对名称、编配、路径后打开；库内显示名与条目数保留。 |

### 原型自测结果

使用 Playwright 驱动 Google Chrome 158.0.8127.37，以 `file://` 加载 HTML，设置离线和 1440 × 900 视口。在 macOS 与 Windows 两种窗口预览中分别走通了上表各项，并验证搜索无结果、重新导入去重、定位时误选已登记文件、首次保存取消、另存后绑定新文件以及平台快捷键。浏览器控制台错误、页面脚本异常、资源加载失败、HTTP 请求均为 0。两种窗口的馆藏、空库和编辑器均无页面级横向溢出。

另用独立的持久浏览器配置，将《理想》的速度改为 128 BPM，保存并返回，再完全退出 Chrome。用同一配置断网重启后，两种平台预览均先进入谱库，重新打开文件可读到 128 BPM。此记录验证浏览器原型的状态回路，产品验收仍需分别在 Windows 11 x64 和 macOS 14 arm64 安装包上执行。

**原型边界。** HTML 使用本地图片、脚本和系统字体。文件选择器中的目录、`.lxm` 内容、磁盘错误和系统窗框均为模拟；所有写入只发生在浏览器演示数据中。允许本地存储的浏览器通过 `localStorage` 在同一 HTML 路径、同一浏览器配置与场景下恢复。禁用存储时状态栏提示仅保留本次演示。清理该原型的站点数据会重置演示。真实 OS 文件读写、原生快捷键分发、完整谱面编辑、磁盘权限与两端安装包断网冷启动属于实施后的验收。
