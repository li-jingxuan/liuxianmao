# 六线猫 v1.0 桌面版技术方案

**实现中。** REQ-006 交付 Windows x64 安装包，REQ-007 交付 macOS arm64 安装包。两端共用一个 Electron 应用，复用现有 React 写谱工作区与 Core。首发用户可以在断网时新建、打开、编辑、试听、保存曲谱和输出成品，再把同一份 `.lxm` 交给 Web 或另一桌面端继续修改。[飞书 v1.0 需求表，第 2、8、9 行](https://pcnhehlhivqu.feishu.cn/wiki/UEivw1G7Liuaqnk20d1cqCoxnHb?sheet=D9eELE) · [Windows 专题](README.md) · [macOS 专题](../REQ-093-macOS桌面版/README.md)

## 1. 实现边界

在工作区新增 `apps/desktop`。Vite 构建独立 renderer，使用 React 包根入口的 `LxmEditor` 和 `createEditorSession`。桌面和 Web 都启用 `fullPage`，加载共享的控件及页面样式。主谱面和属性正文各自滚动，窄于 1400px 的窗口可横向浏览完整工作区。启动打开空会话，显示现有写谱工作区和新建、打开入口。应用采用单实例、单编辑窗口，一次编辑一份谱。Next.js 首页、学习内容和在线路由继续由网站提供。系统文件关联和自动更新留待后续需求评估，首发通过应用内打开和手动下载安装完成交换与升级。

| 层 | 职责 |
| --- | --- |
| React 与 Core | 延用编辑、撤销重做、试听、节拍器、文件预校验与迁移、草稿协调、排版和成品生成。给 React 新增可选的宿主文件与输出适配，以及让原生菜单和窗口请求进入同一工作流的入口。组件默认提供 Web 实现。 |
| Electron renderer | 挂载编辑器，衔接宿主接口与 preload。应用菜单、工具栏和 `Ctrl/⌘+O`、`Ctrl/⌘+S` 等快捷键复用同一套动作和结果提示，每次触发只执行一次。 |
| Electron main / preload | 主进程处理窗口、系统菜单、打开和保存对话框、读写磁盘及打印。preload 提供限定操作的类型化接口。磁盘目标由主进程持有，renderer 只获得显示文件名和绑定本窗口的不透明文件标识。 |

按当前提交，REQ-004/005 已有 `1.0.0` 候选 tarball，飞书显示待验收。现有会话可挂载编辑器，也能读取已提交快照。完整的导入预览、草稿保护和保存基线目前在组件内部，光靠 `replaceDocument()` 和 `getDocument()` 会绕过这些流程。桌面验证可以使用工作区候选产物，进入发布候选时使用同一提交重建的双包，并走查新增适配与 Web 默认路径。[React 接入指南](../../../../packages/lxm-editor-react/README.md#接入-electron) · [当前文件流程](../../../../packages/lxm-editor-react/src/EditorShell/output/use-score-file-flow.ts)

## 2. 文件与退出保护

**打开。** 系统对话框选择一个 `.lxm`。主进程实际校验扩展名和 10 MiB 大小上限，拒绝 `.json`、`.lxm.json`。renderer 复用 React 的严格 UTF-8 解码、JSON 解析、结构和规模预检、Schema 4–7 迁移、Schema 8 语义校验与元数据预览。确认换谱并处理未保存内容后，再提交文档和来源标识。取消选择、取消预览、解析失败或版本不支持时，当前谱、历史和保存目标都保留。桌面新建谱首次保存时选路径。来自旧版的谱保存时写 Schema 8，并在覆盖旧文件前提示格式升级，支持另存副本。[曲谱文件基线](../../design-baseline/score-files.md) · [现有校验与序列化](../../../../packages/lxm-editor-react/src/EditorShell/output/score-file.ts)

**保存与另存。** 「保存」写当前绑定文件，首次保存和「另存为」打开系统对话框。目标统一用 `.lxm` 后缀，复用现有序列化与大小校验。主进程按目标串行写入，先在同目录写临时文件，完整写入后再替换目标。验证 Windows 和 macOS 的实际替换行为，遇到无权限、磁盘空间不足或文件被占用时给可读反馈，保留原文件和未保存状态，允许重试或另存。记录打开和写入时的文件版本，发现目标已被外部修改时提示重新打开或另存，避免静默覆盖。

**保存结果。** 发起写入时记录会话代次和文档快照。主进程确认成功后，React 才更新该快照的保存基线，继续按曲谱内容判断待保存状态，撤销回保存内容时可恢复为已保存。写入期间继续编辑时，新增修改保持待保存。迟到的旧会话回执不修改新会话的路径或基线。另存成功后，新目标绑定当前会话。系统对话框取消和写入失败都保留原目标。[当前会话与文件基线](../../../../packages/lxm-editor-react/src/stores/editor-store.ts)

**换谱、关闭与退出。** 未应用表单草稿和已提交但未保存的曲谱分别检查。先复用编辑器的草稿定位或放弃流程，随后提供「保存并继续」「不保存」「取消」。选择保存后，写入成功且当前曲谱回到已保存状态才继续原操作。主进程拦截普通关闭和 macOS 应用退出，等 renderer 对本次请求明确放行，重复请求合并。

## 3. 离线资源、PNG 和打印

- 安装包从 `app://editor/` 加载生产构建。应用协议仅提供随包资源，支持相对路径、动态模块、Fetch 和本地字体。窗口开启 sandbox 和 context isolation，关闭 Node 集成。校验 IPC 来源、入参、数据大小和文件标识的窗口归属，限制导航和新窗口。生产构建检查外部请求，离线验收从空缓存首次启动开始。[Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security)
- React 候选包已包含 Bravura、和弦库和 54 个木吉他采样的 OGG／AAC 两套异步模块。桌面沿用包的默认资源。资源插件已统一系统路径与 Vite 模块 ID 的分隔符。Windows 原生构建待核对生成块、断网和弦搜索及首播。许可证和来源声明随制品交付。[资源构建配置](../../../../packages/lxm-editor-react/vite.config.ts#L33) · [React 资源说明](../../../../packages/lxm-editor-react/README.md#使用自定义资源目录)
- 沿用 A4 PNG 当前页或全谱导出，多页 ZIP 继续走现有生成任务，由桌面宿主选择输出路径并报告写入结果。打印复用 A4 分页与预览，预览挂载且字体就绪后异步调用原生打印对话框，成功、取消、失败后均清理预览打印状态。验证多页分页、实际纸张和系统可用的 PDF 输出。PNG、ZIP 和打印只读取已提交的谱面，曲谱保存状态按 `.lxm` 写入结果计算。[成品基线](../../design-baseline/score-files.md#a4-图片和打印)

## 4. 安装包与发布

桌面使用 Electron 45.4.1、Electron Builder 26.18.0 和 Vite。两平台从同一候选 tag 和锁文件构建，在各自平台运行 `pnpm --filter '@liuxianmao/desktop...' -r run build`，再用 `pnpm --filter @liuxianmao/desktop dist:win` 或 `pnpm --filter @liuxianmao/desktop dist:mac` 打包。签名校验通过后记录安装包的 SHA-256。Woodpecker 负责 Web 部署。[桌面打包配置](../../../../apps/desktop/electron-builder.yml) · [Woodpecker 配置](../../../../.woodpecker.yaml) · [NSIS 打包](https://www.electron.build/docs/nsis/) · [macOS 打包](https://www.electron.build/docs/mac/)

## 5. 分工、估算与完成条件

可先用占位窗口并行验证两平台打包、断网加载随包资源和原生文件对话框，并落实真机与签名条件。React 组件候选包通过验收后，桌面应用接入候选组件。

| 阶段 | 负责方向 | 预计人日 | 完成条件 |
| --- | --- | --- | --- |
| 离线验证 | 桌面构建与发布 | 2–3 | 真实 React renderer 在两种架构的内部安装包中启动，离线可加载字体、和弦与音色。验证签名工具链和可用测试设备。 |
| 文件闭环 | 编辑器与桌面宿主 | 4–6 | 原生打开、保存、另存、关闭和退出共用编辑器保护流程，Web 文件与编辑回归通过。覆盖并发编辑、旧会话回执、写入失败和取消。 |
| 成品与签名 RC | 桌面构建与发布 | 3–4 | PNG／ZIP 和 A4 打印通过，两平台从同一候选 tag 产出签名制品，保存版本、提交、验签和校验值。 |
| 跨端与实机验收 | 两平台验收 | 2–3 | 每个平台完成下载、安装、断网重启、写谱、重开、覆盖安装和卸载检查。三端同谱往返通过。 |

合计 **11–16 人日**，为评审估算。签名资质开通和设备到位的等待时间另计。发布方向可与文件适配并行准备；双包候选验收和两个已签名安装包的实机结果共同决定首发放行。

用一份可再分发的谱例，包含六线谱、和弦、简谱、歌词和多页排版。Windows、macOS、Web 两两互开，覆盖六个交换方向，比较文档内容、编辑结果、分页和试听。另验 Schema 4–7 样本、相同谱内容改名为 `.json` 或 `.lxm.json` 后被拒绝、损坏或超限文件、中文和含空格路径、长路径错误反馈、无写权限、目标被外部修改、保存中继续编辑、关闭时的三个选项、重复启动时的单实例行为和异常退出后重启。记录提交号、制品哈希、Electron 及操作系统版本和复现步骤。谱面以 1440px 设计基线检查。[v1.0 文件与成品基线](../../design-baseline/score-files.md)
