# 让搜索用户和生成式问答找到六线猫

**首发目标**　搜索「在线六线谱编辑器」的人能看到一份谱并开始编辑；搜索「React 吉他谱编辑器」的人能找到安装方法和适用版本。百度优先验证中文内容在国内可访问、可发现，Google 同步覆盖产品词与开发者长尾词。GEO 在本计划中指让生成式搜索引擎能准确理解、引用公开资料。

## 页面各自回答什么问题

| 搜索或提问示例 | 权威入口 | 准备公开的答案 |
| --- | --- | --- |
| 在线怎么写六线谱、配和弦？ | 官网首页 | 建议标题「六线猫｜在线吉他六线谱编辑器」，首屏正文写清 TAB、和弦、简谱和歌词，展示带说明的实谱图，并链接编辑器 |
| 吉他谱怎么继续修改？怎么发给学生？ | 首页「写谱与导出」段落 | `.lxm.json` 用于恢复编辑；PNG 用于发图；打印界面可输出纸谱。用实拍图和同一份原创示例解释两种文件的区别 |
| 六线猫有哪些桌面版？ | 首页下载区与对应 GitHub Release | 写明已发布的系统、架构、版本号及更新日期；链接指向对应制品，历史版本保留在发布记录 |
| React 如何嵌入？纯 JS 可以自定义工具栏吗？ | GitHub README → 对应版本的示例、API 文档 | 分别说明依赖、安装、最小用法、输入输出和兼容版本。包名与示例均以实际制品为准 |

首页与编辑器是此次网站交付页面，搜索问答可放入现有工作流段落。详细的技术答案先由开源文档承载。从国内网络实测官网、文档及下载链接可达性；首页保留足够的中文说明，让想试用的人可以直接进入 Web。[当前首页](../../../apps/website/app/page.tsx) · [现有站点元信息](../../../apps/website/app/layout.tsx)

## 上线前：先确认爬虫能读到什么

1. **页面内容。** 网站开发为首页和编辑页分别写准确的标题与描述。首页首个 HTML 响应应已包含产品名、可编辑的内容、原谱与导出示例的说明以及真实链接。编辑页可保留交互工作台，首页负责承载可检索说明。用关闭 JavaScript 的浏览器阅读首页，再打开脚本走一遍「搜索落地 → 开始编辑」。
2. **站点地址。** 确定正式域名与部署子路径，生成绝对 canonical 和 sitemap 中的正式 URL。`robots.txt` 放在域名根，允许抓取公开内容并指向 sitemap；若在子路径部署，与域名维护者核对规则作用范围。链接从带渠道参数的首页访问时，canonical 仍归到同一个正式地址。[项目部署路径配置](../../../apps/website/next.config.ts) · [Google 站点地图指南](https://developers.google.com/search/docs/crawling-indexing/sitemaps/overview?hl=zh-cn)
3. **索引范围。** sitemap 只列本次希望展示且可索引的正式页面。测试页、预览环境与非首发入口另定访问及索引策略。需要去索引的公开页面应允许爬虫读取 `noindex`；从 sitemap 移除本身不足以移除索引。检查候选域名迁移、重定向、缓存和 CDN 是否影响正式 URL。
4. **实测记录。** 发布当天从国内和海外各访问一次首页、编辑器及主要资源，记录最终状态码、标题、canonical、下载入口及加载失败项。Google Search Console 验证域名、提交 sitemap，用网址检查工具复核渲染与索引状态；百度搜索资源平台完成站点验证，按账号可用权限提交核心 URL，回查抓取诊断与索引趋势。分别记录「已提交」「已抓取」「已索引」的日期。[百度搜索资源平台](https://ziyuan.baidu.com/) · [Google Search Console](https://search.google.com/search-console/about)

## GEO：把容易答错的问题写清楚

给官网、README、npm 和视频说明统一使用「六线猫」以及实际包名，明确网页、桌面、组件、内核之间的关系。围绕用户的原话组织小标题，每段用一两句可独立引用的结论开头，再给步骤、版本和证据。例如，「怎样把谱发给学生，同时留一份能改的？」可直接回答：「导出 `.lxm.json` 留作下次编辑，再导出 A4 PNG 发给学生。重新打开时从首页导入原生曲谱文件。」[曲谱文件与成品基线](../design-baseline/score-files.md)

内容负责人每周用固定问题分别抽查一个可用的中文联网问答服务和 Google 可用的 AI 搜索体验。记录日期、地区、问题原文、实际回答、引用 URL，以及格式或平台说错之处。若引擎尚未引用，仍可检查自有页面是否清楚回答了问题；若多处说法冲突，先修正文档并同步发布记录。抽样结果只用于发现问题。Google 对 AI 搜索沿用既有搜索基础要求，优先保证页面可索引、事实可验证。[Google 关于 AI 搜索功能的说明](https://developers.google.com/search/docs/appearance/ai-features?hl=zh-cn)

## 上线后：根据哪个环节出了问题采取行动

| 节点 | 负责人和证据 | 如何判断下一步 |
| --- | --- | --- |
| 发布日 | 网站开发记录两家平台验证与提交结果、正式页面抓取检查；渠道负责人验证带参数的落地链接 | 无法抓取先查状态码、robots、子路径、境内访问；参数不应生成独立索引页 |
| 第 7 天 | 搜索负责人分引擎记录品牌词、功能词的可用展现、点击或索引数据，缺失项标记暂无数据；产品负责人汇总自然搜索访问、打开编辑器与首次成功导出 | 有展现少点击，复核标题与查询意图；有试用少导出，观察文件流程与设备分布 |
| 第 14、30 天 | 内容负责人复测固定问题，记录有无引用及答案准确度；按引擎、词组、落地页与上期比较 | 高频问题仍答错时补充可引用的例子；优先扩写带来实际试用的主题。搜索排名、索引速度和 AI 引用保留为观察结果 |

统计只需访问来源、页面、编辑或导出是否成功等汇总信息。曲名、歌词与曲谱文件内容留在用户的编辑会话中。下载、打开编辑器、成功导出分别计数，以便区分好奇访问与实际使用。
