# 六线猫 v1 开源与三端交付

六线猫 v1 拟在 GitHub 开源，提供 React 编辑器包和可独立安装的 JavaScript Core，并交付 Web、Windows 和 macOS。本文记录仓库现状与首发建议，具体平台支持范围、许可和包名以首发评审为准。

## 仓库现状

| 项目 | 已确认的事实 |
| --- | --- |
| 源码与 README | 根 README 已有工作区命令和源码导航。仓库使用 pnpm 9.15.9 和 Turborepo。当前跟踪文件中未见根级许可证或 GitHub Actions 工作流。见 [根 README](../../../README.md) 和 [工作区配置](../../../package.json)。 |
| 编辑器包 | `@liuxianmao/lxm-editor` 当前为私有工作区包，版本 `0.1.0`，唯一入口指向 `src/index.ts`。`build` 仅生成声明文件，运行时依赖为 Zod。入口包含文档、命令、布局、场景、播放计划和内部谱例。见 [包配置](../../../packages/lxm-editor/package.json)、[构建配置](../../../packages/lxm-editor/tsconfig.build.json) 和 [入口清单](../../../packages/lxm-editor/src/index.ts)。 |

## GitHub 首发建议

- README 首屏写清六线猫解决什么问题、v1 支持的功能和平台，并提供在线体验、Windows/macOS 下载、React 快速接入、JavaScript Core 快速接入和 API 文档入口。功能清单以通过验收的交付范围为准。截图和示例谱使用可公开再分发的内容。
- 开发者章节给出 Node、pnpm 版本及安装、启动、构建、类型检查和测试命令。在全新克隆中验证 README 的命令和链接，用示例值说明可选配置。故障报告模板可要求附版本、操作系统、复现步骤和可分享的最小谱例。
- 确认源码许可证与第三方素材清单，公开仓库随附许可证、第三方声明、贡献说明、安全问题报告入口和首发变更日志。对拟公开的文件、文档链接、附件以及计划带出的 Git 历史做审查。公开内容采用可独立构建的源码与示例配置。发现已进入历史的凭证时，先轮换，再处理待公开历史。
- GitHub Release 用同一版本页汇总变更、Web 地址、桌面安装包、适用平台和 SHA-256，并链接两个 npm 包及对应 API 文档。构建失败或签名未通过的平台先保留在候选阶段。

## npm 包与集成方式（建议）

沿用 `@liuxianmao/lxm-editor` 作为独立 Core 的候选包名，React 包暂用 `@liuxianmao/lxm-editor-react`。公开前核实 npm scope 权限和包名可用性。两包使用同一份 Core 实现。

| 安装方式 | 拟公开的契约 |
| --- | --- |
| 仅安装 React 包 | React 包把 Core 列为普通运行时依赖，安装时自动带入匹配版本，并从 React 包的公开入口重导出批准的 Core API 和类型。消费者只装 React 包即可编写自己的工具栏。`react`、`react-dom` 作为 peer dependencies，支持范围按外部项目实测填写。 |
| 仅安装 Core | 提供能在 Node 与浏览器打包器直接消费的 JavaScript 和 `.d.ts`，纯 JavaScript 可直接调用。只需文档、命令、布局、命中、场景或播放计划的消费者可单装 Core，安装树和运行入口均独立于 React、Next.js、Electron 和浏览器全局对象。 |
| 同时安装两包 | 首发同版本发布，React 包精确依赖配套 Core。外部项目验收直接导入与重导出的一致性，检查重复 Core 副本以及类型或运行时对象不一致的问题。 |

- 首发优先发布 ESM，使用 `exports` 指向实际产物和类型声明，资产与 CSS 如需单独引用则给出显式入口。CommonJS 支持由真实消费者需求和实测决定。npm `files` 采用白名单，包含所需运行文件、类型、README、许可证和必要资产。Core 的 JSON 导入与扩展名解析以外部 Node 实跑为准。
- React 包建议提供可直接挂载的编辑器、可替换的工具栏与宿主适配入口。对外明确 CSS 加载、样式作用域、客户端渲染边界，以及卸载时如何回收监听、计时器、音频和导出任务。Next.js 路由、全局 Provider 和站点状态从网站接入层传入。

## 公共 API 文档与自定义 UI 验收（建议）

需求中的「OpenAPI 文档」建议交付为**按版本可查的 JS Core 公共 API 手册**。开发者实际调用的是本地 JS 函数、类型和事件，手册应从「怎样做一个自己的编辑器」讲起，并能按符号查阅。若后续提供 HTTP 服务，再用 OpenAPI Specification 描述网络接口。

在冻结 1.0 接口前，由内核和应用开发逐项登记「界面操作 → Core 公开入口 → 宿主职责 → 文档示例 → 验收用例」。例如，点击一个弦格后改品位涉及命中、命令、变更通知和撤销；播放按钮涉及播放计划与宿主音频输出。用官方 React 组件完成整张清单的走查，纯 JS 示例抽验一条完整路径。凡是实现官方组件仍需私有导入或复制业务规则的项目，补齐公开入口及示例后再冻结版本。

先从现有入口整理 v1 公开 API 白名单。对每个承诺支持的符号记录导入路径、签名和关联类型、参数默认值与单位、返回结果、失败分支、运行环境、兼容版本和可运行示例。对有状态 API 写清所有权、调用顺序、更新与清理时机。API 索引可从声明文件生成，集成指南和失败处理示例随版本维护。

| 文档章节 | 首发须讲清的内容 |
| --- | --- |
| 数据与加载 | `ILXMDocument`、ID 关系、Schema 校验与语义校验的职责，`loadDocument` 的成功与错误结构。当前谱文件 Schema 是 **8**，`loadDocument` 读取当前版本，旧 Schema 4–7 走显式 `upgradeDocumentToCurrent`。区分应用的 `.lxm.json` 文件流程和 Core 的 JSON 字符串接口，说明 10 MiB 与结构、谱规模预检目前属于网站文件层。见 [文档加载](../../../packages/lxm-editor/src/core/document/loader.ts)、[Schema 常量](../../../packages/lxm-editor/src/core/constants.ts) 和 [文件层](../../../apps/website/components/EditorShell/output/score-file.ts)。 |
| 编辑命令 | 用 `ILXMScoreCommand`、`applyScoreCommand` 和命令枚举组织六线谱、节奏、简谱、歌词、和弦、技巧和小节编辑示例。说明 `expectedRevision` 如何处理过期目标，危险变更如何确认，`changed`、`effects`、`nextFocus`、`nextNumberedFocus` 如何驱动宿主反馈，以及应用何时写入撤销历史。见 [命令定义](../../../packages/lxm-editor/src/core/commands/commands.ts)。 |
| 布局、命中和呈现 | 说明 `buildLayout` 目前使用第一条轨道，列出逻辑宽度、编辑与展示模式、缩放及坐标转换。用 `hitTestLayout` 和面向简谱、技巧的命中函数解释优先级、空命中和目标 ID，用 `layoutTabCellSelection`、`layoutTabCellCaret` 和 `buildScoreScene` 说明选区、光标与绘制图元如何组合。见 [布局入口](../../../packages/lxm-editor/src/layout/index.ts) 和 [场景类型](../../../packages/lxm-editor/src/presentation/scene-types.ts)。 |
| 播放 | 用 `createPlaybackPlan` 解释 BPM、ticks 与秒、反复段访问顺序、声音事件和告警。写清浏览器音频播放、用户手势、音色资源、暂停和停止的宿主职责。见 [播放计划](../../../packages/lxm-editor/src/core/playback/plan.ts)。 |
| React 接入与文件输出 | 待接口定稿后列出组件 Props、公开方法、事件、状态订阅及数据来源。用实例说明加载与重置、事件顺序、两个实例的隔离、工具栏替换、只读模式、文件打开与另存、图片与打印能力的支持范围。Web 与 Electron 的文件和打印适配由各宿主提供。 |

首发验收使用安装候选 tarball 的外部项目，示例代码仅通过文档列出的入口导入。每个示例记录使用的包版本、环境和运行结果。

1. **React 默认接入**。项目只安装 React 包和 peer，按 README 引入组件与样式，加载谱例，输入音符、保存、重新打开。用同一个公开入口调用 Core，检查 `react`/`react-dom` 的解析及宿主页面样式。
2. **React 自定义界面**。用宿主自己的按钮、工具栏和键盘事件替换默认操作面板。点选谱面后编辑品位、简谱或歌词，操作小节，完成撤销与重做。校验选区、光标和变更提示随命令结果更新。模拟过期命令、需要确认的编辑和无变化命令，核对反馈与历史。并列挂载两个实例，确认快捷键、文档与草稿状态分别归属各实例。
3. **纯 JavaScript 自定义界面**。Node ESM 直接导入 Core，走加载、编辑、序列化后回读、布局、场景和播放计划。浏览器示例用原生 DOM 控件和 SVG 渲染同一谱例，将屏幕坐标转换成布局坐标，点击命中、修改音符并重绘。验证缩放、边界点、空命中、坏文件和旧版谱升级；运行全过程使用公开入口。

## 版本与产物验证（建议）

1. 用同一提交构建所有候选产物。候选版本可用 `1.0.0-rc.1`，正式版为 `1.0.0`，Git tag 用 `v1.0.0`。桌面安装包、Web 构建标识和 Release 记录版本与提交。npm SemVer 与文档 `schemaVersion` 分开记录，Schema 兼容矩阵随 API 文档发布。
2. 在干净环境按锁文件安装，运行构建、lint、类型检查、单元与浏览器测试。用 `npm pack --dry-run` 核对内容，再对实际 `npm pack` tarball 检查元信息、导出映射、声明、样式和资源、许可证与包体积；排除 `workspace:*`、本地路径和未授权文件。用临时 registry 或本地 tarball 在仓库外独立安装两包，验证 React 自动拉入 Core、Core 单装、Node ESM、外部打包器和 TypeScript 类型解析。对照批准的符号清单检查 JS 与声明一致。
3. 候选包如发布到 registry，使用 `next` 等预发布 dist-tag 并按真实包名安装复验。正式版先验证 Core 已可下载，再验证 React，再将通过检查的版本设为 `latest`。保存包清单、哈希、构建日志和验收结果。npm 版本按不可覆盖的产物管理，发现问题时回退 dist-tag 并发修订版本；Web 保留可回滚的上一份镜像或部署产物。

## Web、Windows 和 macOS（建议）

| 端 | 建议的交付方式 | 发布前实际验证 |
| --- | --- | --- |
| Web | 复用 Next.js standalone，发布时带齐 `.next/static` 和 `public`，并记录构建使用的 `basePath`。用候选环境验证后切换正式 HTTPS 入口。对 HTML 与带内容哈希的静态资源采用各自的缓存策略。 | 根路径和拟部署的子路径均按实际配置打开首页、编辑器和范围内的路由，刷新深链接。检查字体、图标、和弦库、音频请求、下载与打印。用宣告支持的 Chrome、Edge、Safari 版本验收。 |
| Windows | Electron 由同一应用版本构建，首发建议提供签名的 x64 安装程序。若对外承诺 ARM64，则生成独立产物并实测。用 Windows 构建机完成打包、Authenticode 签名和时间戳。 | 用普通用户在声明支持的 Windows 版本验收安装、启动、中文路径、文件对话框、保存失败提示、覆盖安装、卸载和 SmartScreen 实际提示。 |
| macOS | 在 macOS 构建机生成 arm64 与 x64 DMG 或一份 Universal DMG，按实际架构覆盖宣告。使用 Developer ID 签名、Hardened Runtime、公证及装订公证票据，校验装订后的最终文件。 | 用 Apple Silicon 与 Intel 设备或对应的可靠测试环境，从浏览器下载后走 Gatekeeper、安装、启动、打开与保存曲谱、覆盖安装。验证最低支持的 macOS 版本及断网启动。 |

桌面首选复用 standalone 作为验证路线。Electron 启动随应用打包的本地服务，仅监听 loopback，使用临时端口并在健康检查通过后加载窗口，退出时回收进程。先在两种系统的候选安装包验证 Next 运行时、静态资源、和弦库、音频与服务生命周期，再锁定路线。如果改用静态导出，先逐条确认编辑器及纳入桌面范围的动态路由能离线生成或有等价入口。原生文件对话框通过最小 preload/IPC 接口提供，开启 `contextIsolation` 和沙箱，关闭 renderer 的 `nodeIntegration`，限制导航、验证调用来源和参数。自动更新如进入 v1 范围，另验更新签名、升级失败和回滚。

三个端用同一组合成谱例完成共同验收。打开有效谱和旧版谱，处理无效或超限文件，编辑六线谱、简谱与歌词，撤销重做，播放与停止，导出 `.lxm.json` 后交叉打开，并检查图片与打印结果。应用界面按当前设计基线从 1440px 起验。桌面补测完全断网运行、同时启动多个窗口、异常退出后重启、关闭时的未保存草稿提醒及本地文件权限。验收记录附提交号、产物哈希、操作系统、架构、浏览器或 Electron 版本、通过项和已知限制。见 [v1 设计基线](../design-baseline/README.md)。

## 首发依赖风险（建议）

| 风险 | 解决与验证 |
| --- | --- |
| 源码与资产再分发权 | 审查运行时和随产物分发的依赖、图标、字体、示例谱、和弦数据和音色。仓库样本说明标注 Meta Steel Guitar 为 CC0，记录了 OGG 原包和 M4A 转制来源。拟分发的音色保留来源与许可；对来源或授权待确认的素材先关闭分发或替换，再构建候选产物。见 [音色来源说明](../../../apps/website/public/assets/audio/meta-steel-guitar-v1/SOURCE.md)。 |
| Next、React 与 Electron 版本耦合 | 当前容器以 Node 22 为构建起点。按 Next standalone、Electron 运行时、声明工具链和 React peer 实测后确定支持矩阵。候选期固定实际安装版本，审查锁文件内的漏洞及兼容报告，升级后重跑 Core 与三端验收。见 [容器构建定义](../../../Dockerfile) 和 [锁文件](../../../pnpm-lock.yaml)。 |
| 资产路径、编码与离线播放 | 和弦库在构建前生成，音频引擎依赖 Web Audio。按平台验证资源可达、大小写、离线读取、OGG/M4A 解码、首播延迟、缺失或无法解码的提示。记录包体积与音频重复分发成本。见 [网站构建](../../../apps/website/package.json) 和 [音频资源加载](../../../apps/website/components/EditorShell/playback/samples.ts)。 |
| 安装可用性和发布权限 | 提前验证 GitHub 与 npm 发布权限、Windows 签名材料和 Apple 公证资格，凭证从发布环境注入。对最终安装包执行签名验证并从发布候选下载地址实装。平台或架构尚未通过时，在发布页写明支持范围。 |

首发评审需定下公开仓库范围与许可证、两包的名称与承诺的 API、Web 和桌面功能范围、浏览器及系统最低版本、CPU 架构、签名材料和发布负责人。用对应候选产物逐项验证后再对外宣布支持。
