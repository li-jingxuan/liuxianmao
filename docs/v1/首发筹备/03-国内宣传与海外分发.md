# 六线猫 v1.0 国内宣传与海外分发

国内首发由微信公众号和 Bilibili（下文简称 B 站）共同承担。公众号给读者一份可收藏、可转发的跟做教程，B 站用真实录屏展示从空白谱到成品的过程。YouTube 复用同一份录屏和谱例，面向搜索英文吉他制谱教程的用户补充分发。

首轮验证有写谱需求的人看完内容后，能否在电脑上录入一小节六线谱，并导出自己的谱。阅读、播放和收藏用于判断选题与表达，站内使用情况用于判断首发是否带来实际试用。

## 受众与渠道分工

| 优先级与渠道 | 受众与具体需求 | 内容职责 | 主行动 |
| --- | --- | --- | --- |
| 国内主渠道 · 微信公众号 | 需要制作弹唱讲义的吉他老师、社团教学者，以及常给琴友整理谱子的弹唱玩家 | 用步骤截图讲清如何把六线谱、简谱、歌词和和弦指法放在同一张谱上，留一张可对照的 A4 成品图 | 收藏教程，回电脑打开编辑器，试做一小节并导出 |
| 国内主渠道 · B 站 | 会读基本六线谱，想记下指弹片段、练习或弹唱编配的玩家 | 用实录展示输入品位、补和弦、试听与出图，保留关键操作过程，让观众能暂停跟做 | 按简介中的入口在电脑打开编辑器，照着第一小节录入 |
| 海外补充 · YouTube | 搜索 `guitar tab editor`、`how to write guitar tabs` 的自学吉他手和编配者 | 用英文标题、字幕和按钮释义讲 TAB 录入与 PNG 导出。画面保留真实界面，并在简介与开场字幕注明当前演示为简体中文界面 | 通过简介的独立链接访问，在桌面浏览器跟做 TAB 示例 |

一人可兼任以下角色。排期冲突时先保公众号正文和 B 站主片，YouTube 在国内首发素材确认后再排。

开发者是第二批受众。两个 npm 包和示例验证通过后，可在掘金发一篇《把六线猫嵌进 React，再用纯 JS 换一个工具栏》，从仓库外空项目演示两条接入路径，文末指向相同版本的 GitHub 示例。以读者遇到的安装问题和可复现的接入反馈判断是否值得做第二篇。此项可用文档示例改写，单独安排在国内主片之后。

| --- | --- |
| 首发负责人 | 确认 T 日、发布版能力和正式网址。维护选题表、各渠道入口和复盘决定 |

## 统一演示与宣传口径

选一段自写的 4/4 四小节练习，使用自写短句和自行录制的音频。先准备标准调弦下的 TAB 和简短和弦进行，第一小节可用五弦 `3`、四弦 `2`、三弦 `0`、二弦 `1` 四个四分音符。国内素材再给同一段谱加简谱、歌词和和弦指法，试听后展示 A4 成品。海外素材保留输入 TAB 和导出 PNG 两段，给简体中文按钮加英文释义。宣传素材以原创或已有明确使用授权的谱面、歌词、音频和图片为准。

- 入门镜头展示点选弦格、输入品位、核对节奏。国内进阶镜头展示在所选拍添加并应用和弦指法，以及从段落侧栏添加简谱和歌词。录屏前按实际发布构建复核按钮、操作顺序和成品。 [编辑工作台基线](../design-baseline/editor.md) · [和弦与指法基线](../design-baseline/chords.md)
- 试听称「木吉他试听」，示范已提交的 TAB。A4 成品可直接展示 PNG，想留待编辑时提示导出六线猫原生 JSON。若提到 PDF，写「从浏览器打印界面另存 PDF」。若提到导入，明确示例为六线猫原生 JSON。 [曲谱文件、成品与试听基线](../design-baseline/score-files.md)
- 首发素材使用 1440px 及以上桌面录屏，并在移动端常见入口旁提示「建议在电脑上跟做」。公开文案以发布版可走通的路径为准，附上真实成品和操作截图。 [v1.0 设计基线与发布口径](../design-baseline/README.md)

## 上线相对排期与内容样例

`T` 为正式版公开可访问、编辑和导出已走通的当天。以下时间以自然日计。上线日期调整时，随 T 顺延首发、海外补发和复盘，预热文案按已确认的日期表述。

| 时间 | 渠道与选题 | 可用样例与内容结构 |
| --- | --- | --- |
| T−7 至 T−3 | 准备公众号和 B 站共用素材 | 录制一条完整操作母版，截取「原始 TAB／叠加简谱歌词与和弦／A4 成品」三张图。完成首发稿与备选入口，预留字幕和桌面链接核对时间 |
| T−2 至 T−1 | 公众号预热、B 站动态，按产能选做一条 | 配同一段谱的前后对照图，示例「练琴时随手记下的四小节，怎么整理成一张带和弦和歌词的弹唱谱？」CTA 为收藏预告，首发后回来看完整步骤 |
| T | 公众号首发，《把四小节弹唱写成一张能打印的吉他谱》 | 开篇示例「练琴时记了几个品位，给学生时还要补拍子、和弦和歌词。用这四小节演示一遍从草稿到 A4 谱面。」依次放成品、录 TAB、加和弦和音乐文字、导出。文末示例「回到电脑打开六线猫，先照着图写第一小节，再导出一张 PNG。」 |
| T 至 T+1 | B 站主片，《从空白谱到 A4 成品｜吉他六线谱编辑实录》 | 约 3–5 分钟。前 10 秒展示成品并放一小段试听，随后新建、录入四个音、补充谱层、试听并导出。封面文字示例「四小节写成吉他谱」。简介或置顶评论写「想跟做的话，在电脑打开编辑器，先写视频里的第一小节。」 |
| T+3 至 T+7 | YouTube 补发，`How to Write Guitar Tabs and Export a PNG` | 从母版剪 2–3 分钟，成品开场，录入品位数字，展示 `导出 (Export) → PNG 图片 (PNG Image)` 对应画面。简介示例 `Try it on desktop. The editor shown here is in Simplified Chinese. Enter the four notes in the first bar, then export your tab as a PNG.` |
| T+7 至 T+14 | 国内答疑，选问题最集中的主渠道补一条 | 若集中在「怎么保存后继续改」，公众号用三图讲 JSON 与 PNG 各自用于什么。若集中在「怎么把和弦指法放上去」，B 站用约 60 秒录屏演示选拍、选指法、应用。依据真实问题定题 |
| T+30 | 汇总首月结果 | 对比题材、内容入口与试用行为，决定下月继续做入门、转做教学讲义场景，或先修正入口和跟做说明 |

## 转化、归因与复盘

**入口与参数。** 正式入口统一使用发布域名的首页 `/`，首页已有「打开编辑器」和「新建曲谱」入口。对跟做内容，核对发布版行为后也可直达 `/editor`，并在素材中说明直达时会打开示例谱、跟做请新建。公众号优先核对「阅读原文」可用性，B 站优先核对简介，YouTube 优先核对长视频简介。链接不便点击时，可在正文或画面放可复制网址，二维码只在页面规则允许且实际可扫时使用。随发布检查各渠道实际展示、电脑端访问和跳转是否保留参数。 [站内入口与默认示例](../design-baseline/score-files.md)

每条内容使用 `utm_campaign=v1_launch`，`utm_medium=organic_social`，`utm_source` 分别用 `wechat_oa`、`bilibili`、`youtube`，`utm_content` 用 `launch_article`、`launch_video`、`tab_tutorial_en` 等内容 ID。需要比较同一渠道的多个入口时，用 `launch_video_desc`、`launch_video_pin` 之类的独立值。记录发布日期、渠道、内容 ID、入口位置、目标路径与最终链接。参数用于标识来源，数据是否可见取决于站点现有统计或日志能力。

**观察口径。** 按同一内容、同一观察窗口记录下列数据，优先看数量和共同出现的反馈，再看比例。

| 环节 | 记录方式 | 判断依据 |
| --- | --- | --- |
| 内容触达 | 公众号阅读、收藏、分享及入口点击（有则记录）。B 站与 YouTube 记录播放、平均观看时长和可见的外链点击 | 同一平台内比较内容。按首个操作前后的留存和评论判断观众是否看到了可跟做的步骤 |
| 落地与进编辑器 | 若现有站内能力可用，按 UTM 统计落地会话与进入编辑器的会话。同一会话重复访问只计一次，直达编辑器同一次访问同时满足两项 | 进入编辑器率＝进入编辑器会话数 ÷ 落地会话数。按设备拆看可用数据，便于识别从手机阅读转到电脑体验的障碍 |
| 首次有效编辑 | 同一会话在一小节录入至少一个有效 TAB 品位并提交。打开默认谱、选择格子或播放示例均排除 | 有效编辑率＝有效编辑会话数 ÷ 进入编辑器会话数 |
| 带走成品 | 同一会话完成有效编辑后生成并发起 PNG 或原生 JSON 下载，合计每会话计一次，有条件再分格式。浏览器下载触发用于表示导出意图 | 导出率＝编辑后发起下载的会话数 ÷ 有效编辑会话数 |

有可靠站内事件时，用同一访问会话内的入口 UTM 关联后续动作。站点目前若只能看到带参数的请求，就记录分渠道落地请求数并注明统计口径，缺失的编辑与导出环节填「不可观测」。连落地来源也拿不到时，使用平台可见的外链点击以及评论中明确提到「打开过／写过／导出过」的自报反馈，反馈单列。转发后手输地址、跨设备和参数丢失统一保留为「来源未知」。样本较小时同时列出分子、分母与反馈原话中的问题类别，内部试跑数据排除在外。

**复盘节奏。** T+1 核对入口实际访问情况，优先处理打不开、错链和版本差异。T+7 摘要记录各渠道同龄数据，判断首个改动点。T+14 对公众号首发、B 站主片和海外补发各看发布后首 7 天的表现。T+30 汇总首月数据和重复出现的问题，每个渠道记一项继续做的内容或一项调整及对应负责人。

- 播放集中掉在第一步前，下条把成品和首个按键提前。阅读或播放有积累但入站少，先检查入口和「电脑跟做」提示的位置。
- 入站后有效编辑少，结合留言看是找不到新建入口、不会选弦格，还是手机阅读后难以回电脑。下一版教程只先改一个步骤，便于比较。
- 能编辑但导出少，检查观众是否看到了清晰的成品用途和导出步骤。若没有站内数据，在复盘里把这个判断记为待验证，并优先汇总主动反馈。

## 预算有限版本

以已有账号、电脑、录屏剪辑工具和统计能力为前提，按 **0 元新增现金、约 10–12 小时人力** 排首轮。一份原创四小节谱、一份桌面录屏、一张成品图贯穿三个渠道。

| 保留交付 | 预计人力 |
| --- | ---: |
| 谱例、发布版核对、桌面母版 | 3 小时 |
| 公众号首发一篇、B 站主片一条 | 4–5 小时 |
| 同源 YouTube 视频一条，英文标题、简介和字幕 | 1.5–2 小时 |
| 入口核对与首月复盘记录，分次完成 | 1.5–2 小时 |

预热和答疑视频按素材余量做，常见问题优先用现有正文或简介补充。首轮预算以自然分发为主，工时不足时保住国内图文和视频，海外顺延到字幕与访问路径核对完成后。
