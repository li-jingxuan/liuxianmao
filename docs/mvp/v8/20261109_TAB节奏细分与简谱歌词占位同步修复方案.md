# TAB 节奏细分与简谱、歌词占位同步修复方案（显式同步已撤销）

日期：2026-11-09。当前状态：**用户已撤销“细分简谱”“拆分并同步”两个操作，入口与专用实现已移除，见 §12。** 第 1～11 节为历史讨论、确认及实施记录，其中“已实施”“已接入”等表述不代表当前可用能力；旧验证结果也不代表当前回归结果。普通 TAB 修改、拆分继续保留独立简谱和歌词，本次不引入自动同步。

历史细节补充：曾补充选区、补音、空事件、预览、失败反馈和验证步骤。§10 中同时提供事后细分和“TAB 拆分并同步”两个显式入口的确认已由 §12 撤销；未引入“沿用 TAB 节奏”批量录入选项。

本方案合并两次反馈：① 4/4 小节中四分音符改成两个八分音符，简谱和歌词没有新增半拍入口；② 两个八分音符改成两个十六分音符加一个八分音符，简谱时值标注与新增拍点、占位不一致。

当时讨论的规则：**真正空白的输入位置自动派生；已有简谱音符或持久化空事件覆盖的位置，通过用户显式操作细分。** 该显式同步方案现已撤销；普通 TAB 编辑继续保留独立简谱和歌词，真空窗自动派生规则保持原样。

### 1.1 Bug A：四分改为两个八分，新增半拍没有简谱和歌词入口

基于 `EXAMPLE_MVP_7_2_DOCUMENT` 第一小节，原 TAB 与简谱均为四分音符，简谱已有歌词。依次对前两个 TAB Beat 执行 `beat.setRhythm(eighth)`，得到小节开头两个八分音符。

注意：这是现有时值修改命令的完整操作序列，不等同于直接调用 `beat.split`。第一次修改会重排后续 TAB 并补足小节，第二次修改才形成所需开头；本次关注第一拍 `[0,960)` 的最终结果。

| 对象 | 修改前 | 修改后实际状态 |
| --- | --- | --- |
| TAB 起点 | `0,960,1920,2880` | `0,480,960,1920,2880` |
| 简谱起点和时值 | 四分：`0,960,1920,2880` | 保持四分，完整覆盖小节 |
| 简谱空位 | 无 | 仍无，`480` 没有入口 |
| 歌词位置 | 绑定原简谱事件 | 原 eventId 和区间不变，`480` 没有独立位置 |

在 `480` 的简谱行点击返回空；歌词位置规划中没有 `480`，前一个歌词事件仍覆盖 `[0,960)`。此前命中复核还确认该处歌词点击会落在前一个“轻”，不能将其解释成新增填词入口。

证据：[修改前](../../../artifacts/rhythm-sync-20261109/A-before-quarter.png)、[修改后](../../../artifacts/rhythm-sync-20261109/A-after-eighths.png)。对应同名 `.lxm` 可用于导入复核。

### 1.2 Bug B：两个八分改为两个十六分加一个八分

基于示例第七小节，先用真实 `numbered.sequence.insert` 在 `[0,960)` 写入两个八分简谱音符，再依次将前两个 TAB Beat 改为十六分。TAB 开头变为：

```text
时间             0        240        480                    960
TAB              十六分    十六分     八分
当前简谱          八分──────────────── 八分──────────────────
缺失的输入位置              ↑ 240 被第一个简谱八分覆盖
```

实际保存的 TAB 前三个起点为 `0,240,480`，时值为 `sixteenth,sixteenth,eighth`；简谱仍是 `eighth@0,eighth@480`。`240` 没有空位、没有独立歌词位置，简谱行命中返回空。后续空位从 `960` 开始，所以“后面还有框”不能说明第一拍已经同步。

证据：[修改前](../../../artifacts/rhythm-sync-20261109/B-before-two-eighths.png)、[修改后](../../../artifacts/rhythm-sync-20261109/B-after-tab-sixteenth-sixteenth-eighth.png)。

### 1.3 减时线对照：须先检查实际简谱节奏

另建对照，通过 `numbered.range.replace` 明确写入 `sixteenth@0,sixteenth@240,eighth@480`。编辑布局和成品布局均得到正确结果：第一层共享减时线覆盖三个音；第二层只覆盖前两个十六分音，在第三个八分音之前结束。真实网站截图也符合该分组。

再用统一十六分模板输入五个数字，实际保存的是五个十六分，起点为 `0,240,480,720,960`；它们显示双层减时线符合自身数据，不能通过缩短某条线把其中一个改成八分音。

- [正确混合节奏截图](../../../artifacts/rhythm-sync-20261109/B-control-explicit-mixed-rhythm.png)
- [五个统一十六分对照截图](../../../artifacts/rhythm-sync-20261109/B-control-uniform-five-sixteenths.png)

**已证实的是时值数据与 TAB 细分不同步，并非已经证实减时线渲染器存在错误。** 用户截图中的连续数字和双线不能唯一还原输入操作。实施时须继续记录所用录入模式、目标区间、生成命令的 `rhythms`、保存事件和渲染几何，排查是否沿用了统一时值模板。若真实事件已是混合节奏而显示仍错，再单独修复减时线分组；不要依据 TAB 时值替换独立简谱的线条。

本节的 `range.replace` 只用于构造对照，不是建议的同步实现捷径。

## 2. 根因与已有契约

### 2.1 TAB、简谱、歌词的领域关系

- `core/commands.ts` 的 `setBeatRhythm` 调用 `core/rhythm-change.ts` 的 `changeMeasureBeatRhythm`，处理 TAB 时值、重排与小节容量。
- `core/beat-structure.ts` 的 `splitBeat` 处理 TAB 拆分及相关技巧，不改 `numberedVoice` 或 `lyrics`。
- 简谱事件保存独立的 `tick/rhythm`。`core/lyric-positions.ts` 的 `planLyricPositions` 以简谱 notes、gap 和真实空窗产生歌词位置；歌词引用简谱 eventId。
- `layout/numbered-rhythm-layout.ts` 根据实际简谱时值生成减时线，不以 TAB 的符干或连梁代替简谱时值。

所以现象不是重绘缓存未失效。TAB 新增了时间列，但该 tick 仍处在原有简谱事件内部，布局没有合法空位可以绘制。

### 2.2 必须区别三种“空”

| 状态 | 当前规划行为 | 本次规则 |
| --- | --- | --- |
| 无事件占用的真实空窗 | `planNumberedInputRanges` 已参考 TAB 起点细分 | 自动派生，保持简谱、歌词入口和命中一致 |
| 已保存的 `gap` | 按独立事件完整区间返回 | 显式细分，保留身份和全部段歌词 |
| 已有 notes 覆盖，但新增 TAB tick 上没有数字 | 属于音符持续区间 | 显式缩短原音并创建空尾段 |

仅填歌词也会使空窗持久化：`core/music-text-commands.ts` 的 `lyric.set` 可先创建 gap 作为歌词锚点。因此“简谱行看起来为空”不能作为自动覆盖依据；也没有持久化来源字段可以证明某个 gap 属于 TAB。

### 2.3 与旧方案的关系

[简谱独立时值与时间轴编辑技术方案](./20261030_简谱独立时值与时间轴编辑技术方案.md) §3.2、§5.1 曾暂不增加独立拆分按钮。本次补充的是用户明确选择的“按所选 TAB 节奏细分简谱”能力，保留普通独立编辑契约。以下既有回归必须继续通过：

- `tests/core/numbered-voice.test.ts`：普通 TAB 拆分不改简谱。
- `tests/layout/lyric-event-anchor.test.ts`：“修改 TAB 时值后歌词仍使用原简谱 tick”。

不要通过删除上述测试，或全局让歌词改绑 TAB Beat，来消除这两个复现。

## 3. 修复后的交互与可验收结果

### 3.1 真空窗自动更新

TAB 修改成功后，以最新文档重新计算真正未占用的时间窗。简谱输入、歌词位置、hover、焦点、点击和连续填词共用核心时间范围，几何从统一时间列插值获得。现有空窗细分能力已经存在，应先补齐回归与视图一致性检查，避免另造一份 UI 拍点数组。

无事件的空窗提示不因显示而写入文档；有内容覆盖的位置不伪装成可直接输入的空框。

### 3.2 已有内容通过明确入口细分

建议入口文案为“按所选 TAB 节奏细分简谱”。从已选 TAB 区间发起，在现有节奏操作区展示；新增内部拍点可提供解释提示，引导选择对应 TAB 区间。由于当前缺失位置本身不能命中，入口不能依赖用户先点击一个不存在的简谱空框。

预览说明作用区间、原音缩短、新增空位数、歌词保留位置，以及受影响连接记号。确认后一次提交。默认将新增尾段创建为独立 gap，便于随后单独填简谱或歌词；不复制原音高、歌词，不自动建立 tie。

操作结果示例：

| 场景 | 细分前 | 细分后 |
| --- | --- | --- |
| A：`[0,960)` | 四分 notes/gap，原 eventId=`e0` | `e0@0` 八分；新 gap `@480` 八分 |
| B：`[0,960)` | 八分 `e0@0`、八分 `e1@480` | `e0@0` 十六分；新 gap `@240` 十六分；`e1@480` 八分 |

两个场景都保留首段 eventId、原 items ID、全部段歌词。B 的第二个八分 `e1` 完整保留；后续简谱事件、歌词时间位置不移动。补入新 gap 后，才能得到三个实际音符组成的“十六分、十六分、八分”。细分本身不会自动产生第三个音高。

歌词原文只留在第一段；新 gap 为每个可编辑歌词段号提供入口，默认无词。点击新简谱空位准确命中新 gap，点击对应歌词行准确定位新 gap，不回退到前一音或前一字。

本次提供两个显式入口：① 对**已经改好的 TAB 区间**执行事后细分；② 对单个有效 TAB Beat 执行“TAB 拆分并同步”。事后细分产生一条新历史，此前独立 TAB 修改保留自己的历史；组合入口将两层修改合成一次核心命令，成功后一次撤销整体恢复，不能先提交 TAB 再提交简谱却宣称一次撤销。

### 3.3 混合节奏录入必须明确

继续提供原有统一时值输入，同时在节奏预览中明确每项实际节奏与作用区间。当前 `NumberedEditor.tsx` 存在 `uniform/custom/front8/back8` 分支，其中 `back8` 会生成 `[sixteenth,sixteenth,eighth]`；不能假定用户连续输入数字时自动选择了这个模板。

用户已确认本次不新增“沿用所选 TAB 节奏”的批量录入选项。本次完成现有模板的准确节奏预览，以及细分后按已有位置补音、保留各位置真实时值。统一模板生成的五个十六分仍按五个十六分处理；不能静默转成混合节奏。预览须显示数量、作用区间和剩余位置，内容超出可写位置时整批拒绝，不截断输入，也不重复最后一个时值。

以后若增加沿用 TAB 的批量录入，再单独定义所选节奏序列与输入项数量、覆盖策略、真空窗及 gap 的写入规则。本次不提前接入该入口或占位开关。

### 3.4 选区、补入内容和焦点

以下作为本次技术方案的具体实现约束：

- 同一 TAB Beat 上选择多根弦，只算一个时间区间；连续多个 Beat 取首拍起点至末拍有效结束。不根据弦数增加简谱位置，不借用其他轨道或小节的残留选区。
- 只选中一个新十六分拍，而其边界切穿已有八分简谱时，不自动扩大范围。提示“所选范围切穿已有简谱，请扩大到完整音符后重试”，保留原选择；用户可以选择覆盖整个原八分或第一拍的 TAB 范围。
- 新 gap 的 tick/rhythm 已确定。单点补音走保留事件身份的内容编辑，例如 `numbered.event.set`，不走只接受真空窗的 `numbered.sequence.insert`。补音默认继承 gap 时值，不沿用上次输入的四分、十六分等偏好覆盖它。
- 新 gap 先填歌词再补音，或者先补音再填歌词，最终必须落在同一个 eventId 上。补音生成新的 item ID，gap 的 eventId、已有歌词、tick/rhythm 保留。
- 多个已保存位置的连续补音，按位置逐项映射内容并保留各自时值；不得以统一模板重建刚刚细分的事件。真正空窗的连续输入仍沿用其原有录入规则。
- 同步成功后，以时间最早的新 gap 为返回焦点；没有新 gap 则保持当前目标。TAB 范围保留，便于核对；不在同步成功时额外打开歌词编辑器或抢走其他有效草稿的输入焦点。
- 新 gap 是持久化编辑位置，不是休止符 `0`，也不是延续符 `-`。编辑态显示输入提示；成品、打印、图片不绘制虚线框，不因空位自动产生数字或减时线，实际时间区间仍参与布局。
- 再次对同一版本相同范围细分，没有新增边界时提示“所选范围已按当前 TAB 节奏细分”，无文档写入、revision 变化或新历史。

### 3.5 预览中必须可核对的信息

预览放在现有编辑面板或相应操作表面，使用一个“应用细分”动作。选择入口本身只生成候选结果。需要展示：小节和拍内范围、变短的原音数量、新空位数量、保留的已有音与歌词，以及记号影响。A 的说明可为“原音缩为八分音符，后半拍新增一个空位；原歌词保留在前半拍”。B 可为“第一个八分音符拆为一个十六分音符和一个十六分空位，第二个八分音符保持原位”。

不需要让产品用户阅读 eventId、tick、revision 等实现字段；调试证据保留这些字段。带有原歌词的事件仍需明确说明“原词只留在首段”，不能用“歌词自动对齐”掩盖这一规则。

“取消”退出预览并保留当前谱和原选择；“应用”执行一次受版本保护的命令。预览过期后保留输入和选区信息，提示重新检查，不能自动切换到新文档或新目标继续应用。

## 4. 核心命令与原子规划

### 4.1 专用接口（已实施）

已新增 `numbered.range.alignToTab` 专用命令，语义为：按当前 TAB 边界细分指定简谱区间，保留每个原事件的第一段内容，新增段为空。它不改变 TAB。

```ts
// 已纳入 ILXMScoreCommand；track/measure/tick 字段须来自当前有效目标。
{
  type: "numbered.range.alignToTab",
  trackId,
  measureId,
  startTick,
  endTick,
  expectedRevision,
  // 连接记号的影响确认沿用既有命令机制。
}
```

核心从当前文档重新读取 TAB 边界，不信任 UI 传来的任意分段数组。预览与提交共用纯规划器，返回分段结果、保留/新增身份、记号影响、目标焦点；确认后的重算结果必须对应同一版本。

### 4.2 最小安全范围与算法

第一阶段支持同小节、非连音、原事件完整落入所选区间的 notes/gap；每个所需分段长度必须可由现有普通时值精确表示。只做细分，不合并不同原音或删除原歌词。

1. 校验文档版本、轨道、小节、容量、选区起止；区间端点必须是 TAB 节奏边界。
2. 按有效时值计算简谱占用区间，核查交叠事件。不能仅判断起点是否相等。区间若切穿已有事件，拒绝并提示扩大选区。
3. 收集 `[startTick,endTick)` 内 TAB 起点及终点。对每个原事件，保留原起止边界，将内部 TAB 边界加入后精确分段。原有简谱边界仍保留，不能为了匹配 TAB 合并音符。
4. 首段复用 eventId/items 和原内容，修改 rhythm；后续段生成新的 gap ID，不含 items/歌词/tie。真空窗保持派生，不强制实化整个选区。
5. 保留所有存活原事件上的歌词；检查每段全部 verse 引用。对关系和记号计算影响，不静默丢弃。
6. 构建隔离候选文档，执行 schema、semantic 和区间容量校验；全部成功后一次提交。没有新增边界则返回无变更，不制造空历史。

例如 B 取边界 `[0,240,480,960]`：细分 `e0` 的 `[0,480)`，不修改 `e1` 的 `[480,960)`。总长仍为 960，其他小节与简谱区间不动。

若选区同时含真空窗与完整事件，可只细分有新增内部边界的事件；不能把一个部分重叠事件当成空窗跳过。无法处理的任一成员使整次操作失败，不提交其余部分。

### 4.3 候选结果、失败分类与 ID 规则

纯规划器建议返回 `changed`、被缩短的事件 ID、按时间排序的新 gap、保持原位的事件、歌词保留摘要、记号影响和 `nextFocus`；字段名属于内部实现建议。预览展示与最终命令不能各自实现一遍分段算法。

预览生成的候选 ID 不作为 UI 长期锚点。重新规划必须从同一源文档创建 ID factory，提交前校验版本；不得让预览消耗全局 ID、写入文档或依赖运行时随机 ID。新事件 ID 在整个文档内唯一，不能简单采用 `原ID-240` 而不检查冲突。

建议区分以下失败原因，沿用现有错误类型或新增对应领域原因；中文提示面向用户，具体错误码在实现时确定：

- 无有效目标、范围不连续或跨小节：“请选择同一小节内连续的 TAB 拍点”。
- 切穿原事件：“所选范围切穿已有简谱，请扩大到完整音符后重试”。
- 不支持的时值、连音、休止/延续语义或关系：“此范围暂不支持同步细分”，并指明受影响对象。
- 文档或选择已变化：“谱面或选择已变化，请重新检查细分结果”。
- 最终校验失败：“未应用细分，请重新检查目标范围”；保留原文档和可恢复草稿，不提交部分结果。

未发生变化属于正常结果，不能作为失败重试并重复制造空历史。

### 4.4 现有命令能复用到哪里

| 现有能力 | 实际语义 | 本次处理 |
| --- | --- | --- |
| `numbered.event.setRhythm` | `timeline` 只有 `preservePositions/editTimeline`；缩短只释放尾窗 | 可抽取计算，不声称已有同步模式 |
| `numbered.event.split` | notes 第二段复制音高并加 tie；gap 可等分 | 可复用安全 gap 等分；notes 留空需要新规划规则 |
| `numbered.sequence.insert` | 填未占用窗口；已有 gap 也算占用 | 用于真正空窗，不覆盖持久化 gap |
| `numbered.range.replace` | 可重建 ID、清理旧歌词引用；空 set token 被拒绝 | 不作为保留身份的同步捷径 |

“持续音等分”属于现有 split 的另一种语义，不与本次“原音缩短、后段待录”混用。

整个操作使用一个 `createDocumentIdFactory(document)`，在候选对象上规划，最后调用一次 `finalize`；revision 增加一次，store `execute` 一次，产生一条历史。可参考 `commands.ts` 的 `lyrics.setSequence` 原子编排。组合 TAB 操作则先在同一候选分支规划 TAB，再规划简谱，两者成功才 finalize；禁止连续执行两条对外命令制造中间状态。

### 4.5 “TAB 拆分并同步”的明确范围

已新增组合命令 `beat.splitAndAlignNumbered`，参数包含 trackId、measureId、beatId 和可选 expectedRevision。当前阶段只处理单个有效 Beat 的精确等分，不接入任意 `beat.setRhythm`，不把多根弦选择误认为批量拆拍。

1. 从原文档解析目标 Beat 的完整区间 `[s,e)`，检查它与已有简谱占用的关系；如果区间切穿某个简谱事件，阻止组合操作，提示使用事后完整范围细分。不得扩大 TAB 拆分目标。
2. 在隔离候选 track 中复用 `splitBeat`，保留该操作已有的 TAB 音符复制、持续音 tie 和技巧迁移语义。组合入口的简谱侧仍是“首段保留、后段留空”，不向简谱复制 TAB 音高，不新增简谱 tie。若以后需要 TAB 两个独立起音，应由对应 TAB 编辑操作另行定义。
3. 在候选 TAB 上读取 `[s,e)` 的新边界，以同一 ID factory 调用简谱细分规划器；真空窗只随新 TAB 边界派生提示。只改动原区间，不移动后续事件。
4. 合并 TAB 技巧变化和简谱影响，展示统一预览。任一侧不支持或校验失败，原文档两层均不变；成功只 finalize/execute 一次。
5. 若简谱本已足够细，或者目标区间是真空窗，组合操作仍可成功：TAB 拆分是真实变更，不能因“简谱无新增事件”被整体判作 no-op。只有事后细分没有新增边界时才不产生历史。

示例：四分 TAB 与四分简谱在 `[0,960)` 对齐，一次组合操作得到两个 TAB 八分及“原简谱八分＋八分 gap”；再对首个八分执行组合操作，可得到第一拍 `0,240,480` 的“两十六分＋一八分”位置。后者若原简谱仍为未细分的四分音，则首八分区间切穿原事件，应阻止组合同步并引导按完整第一拍做事后细分。

## 5. 边界、记号和过期保护

### 5.1 第一阶段阻止的情况

- 任一待细分事件处于连音组，或 TAB 目标区间涉及当前规划器不支持的连音边界。
- 选择端点切穿原事件、跨小节，或目标区间与当前文档不符。
- 分段小于支持的最短时值，或所需长度不能精确表示；不近似取整。
- 内部新增 TAB 边界需要切分 `rest` 或 `continuation`。它们拥有音乐语义，不能被通用 notes/gap 规则改成空尾段；第一阶段阻止这种细分。没有内部新边界的休止或延续事件保持原样，不因出现在选区就被删除或重建。
- 原音连接、tie、slur、其他记号的迁移规则未定义。先阻止受影响成员并说明原因；已有影响确认机制覆盖且迁移规则明确时，预览后按规则处理。

单纯原音被缩短时不能把跨尾段的持续关系直接留在新空段上。不得只通过“ID 仍在”判断关系仍有相同音乐含义。

附点但非连音的事件按真实时长分段，只要每段可由现有普通时值精确表示即可支持；按标准时值匹配顺序选择确定写法，优先无附点的等长表示。同一 notes 事件包含多个同时发声的 items 时，全部 items 留在首段，不能将其中一个音移入新 gap。原事件仍占满整个选区而没有任何 TAB 内部边界时，保持不变。

第一阶段对受影响的 tie/slur 采用阻止策略，避免将原本持续到后段的含义悄悄缩短；只绑定原事件且语义不因本次细分变化的记号才可保留。记号迁移与确认如果需要新增音乐语义，作为后续能力单独定义，不能只增加确认弹窗便认为已解决。

### 5.2 确认时必须仍是同一个编辑版本

核心沿用 `expectedRevision` 守卫；UI 同时复用 `captureEditorVersion/sameEditorVersion` 的 document、stateVersion 和 session 身份，防止撤销后 revision 重复仍应用旧预览。入口沿用 command adapter、`createNumberedSubmission`、草稿协调和工具守卫，不新增一套并行提交锁。

预览期间换目标、换文档、撤销/重做、编辑输入、组件卸载，旧确认必须失效。失败、取消、过期、重复确认均不得写入；保留可恢复草稿，提示重新检查。

### 5.3 歌词草稿需要映射依赖检查

当前 `MusicTextSidebar.tsx` 外部变化检查主要比较 `fresh.initial`，`music-text-draft.ts` 的草稿值主要记录文本、模式和覆盖开关。细分后首 ID、原歌词文本可以不变，但连续填词的后续位置序列已改变；只比较文字会漏掉映射失效。

为连续歌词预览增加依赖指纹：包含实际使用的 track/measure、verse、模式，以及有序位置的 eventId/tick/endTick；覆盖跨小节的整个实际映射范围。位置序列变化即废弃旧预览，保留用户已输入文字，重新规划后再提交。单点歌词可继续锚定存活 eventId，但必须重算区间、几何与提交版本。

## 6. 布局、命中与时值标注一致性

所有正式图元读取实际简谱事件 tick/rhythm；占位读取 `planNumberedInputRanges`，歌词读取 `planLyricPositions`，共享同一份区间含义。编辑提示、命中、选框、连续录入、成品与导出不能分别按 TAB 下标计算位置。

同步 A 后 `480`、同步 B 后 `240` 的新 gap，须同时进入简谱空位布局及歌词位置规划；其 anchorX 从统一时间列获得。新 gap 不能命中前一音，真实文字优先命中规则继续保留。

对已填入的 `[sixteenth,sixteenth,eighth]`，验证第一层线跨三个音、第二层只跨前两个；对五个真实十六分音符，验证其双层线仍正确。不能为了让 bug 截图“看起来对齐”修改所有八分/十六分的线级映射。

### 8.1 两条必须走通的端到端验收

**流程 A：已改 TAB，修复已有旋律与歌词入口。**

1. 导入 `A-after-eighths.lxm`，选择覆盖 `[0,960)` 的两个 TAB 八分拍。此时原简谱第一音为四分、歌词“轻”绑定原 eventId。
2. 进入显式细分预览，核对一个原音缩短、一个新空位、原词保留；取消一次，确认文档、历史均未改变。
3. 重新预览并应用。核对原 eventId/items 与所有段歌词保留，新 gap 位于 `480`，`960` 之后简谱事件未动。
4. 点击新 gap，先填写一段歌词，再补入简谱音；核对单点补音后仍是八分，歌词未丢失。另建一次测试反向完成“先补音后填词”。
5. 保存再打开，检查新音和词位置；依次撤销补音、填词、细分，确认一次撤销细分恢复原四分；重做后状态一致。

**流程 B：两个八分，得到两个十六分加一个八分。**

1. 导入 `B-after-tab-sixteenth-sixteenth-eighth.lxm`，选择第一拍完整范围 `[0,960)`；预览必须只缩短 `e0`，完整保留 `e1@480`。
2. 应用后点击 `240` 的新 gap 补入一个音。即使上次统一录入偏好是八分或四分，当前补音也必须保持十六分，最终起点为 `0,240,480`。
3. 核对 `480` 的原音仍为八分、未被复制或移动；三音第一层线相连，第二层止于前两个音。
4. 在新位置填写歌词，检查新 eventId 命中；再测试预览期间撤销至同一 revision、换文档等情形，旧确认均不得提交。
5. 分别检查编辑态、成品、打印或导出，并保存重开；不存在依靠虚线提示遮盖错误数据的情况。

**流程 C：从原始谱一次拆分并同步。**

1. 导入 `A-before-quarter.lxm`，选择首个四分 TAB Beat，进入“TAB 拆分并同步”；预览同时展示 TAB 等分与简谱后半拍留空。
2. 应用后核对原区间总长、TAB 既有持续音技巧语义、简谱首 ID/items/歌词和 `480` gap；revision/history 各一次。一次撤销同时恢复 TAB、简谱与歌词，重做整体恢复。
3. 再对首个八分执行组合操作，核对第一拍两侧都具有 `0,240,480` 边界。简谱首段保留原音、`240` 为新 gap、`480` 原 gap 不动。
4. 分别构造连音、受影响简谱 tie、端点切穿原事件、最短时值及提交前版本变化，确认零部分写入。
5. 真空窗及简谱已有更细事件时，TAB 仍可合法拆分并形成一条历史；不得被简谱侧 no-op 吞掉。
