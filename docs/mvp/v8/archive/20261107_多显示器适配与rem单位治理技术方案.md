## 1. 结论与范围

采用“保留现有单位 + 按宿主容器比例分配空间 + 谱面有上限地自适应放大/缩小”。先解决宽屏利用率，rem 迁移不作为前置条件，不做全仓库 px 批量替换，本轮不引入 `postcss-pxtorem`。第 3 节的单位与 AntD 桥接是后续可选项，不是解决本次空白问题的必要工作。

建议以宿主 1600 CSS px 为增长起点：该宽度及以下，在能够容纳原布局时保留 400px 侧栏和原有 780/800px 纸宽；超过后让侧栏和谱面逐渐增长。头部 58px、工具栏 44px、控件字号和操作顺序保持原基线，不因屏幕宽而整体放大。此处阈值及上限是待截图验收的初始参数，不是用户已确认的视觉数值。响应式行为和可选单位迁移分别提交、分别验收。

CSS px 是逻辑像素。操作系统缩放、浏览器缩放和设备像素比共同影响最终显示，但布局应依据实际 CSS 可用宽高，而非显示器标称分辨率。rem 相对于根字号：默认根字号 16px 时，13px 改为 0.8125rem 并不会自动适配窄窗口。rem 解决尺寸体系和字体偏好的跟随，Grid/Flex 与容器查询解决布局，谱面缩放解决编辑内容的观看比例。

目标是各显示环境下内容可读、功能可达、操作位置正确，不承诺不同显示器上相同的物理厘米大小或逐像素相同的字体栅格。字体、系统渲染差异仍可能存在。

本次症状的直接原因是固定宽度与窗口增长脱节。例如 400px 在 1600px 内占 25%，在 2440px 内只占约 16.4%；改为 25rem 且根字号不变，占比仍然一样。应改变宽度的计算规则，而不是单独替换单位，也不通过按屏幕宽度修改根字号把所有控件一起放大。

本期保持：文档 schema、音乐排版逻辑、编辑密度、撤销重做、打印分页及 PNG 输出规格。暂不做随窗口重新断行、按 DPR 设置字号、屏幕物理尺寸校准或全局页面 transform。窄窗口覆盖功能可达及桌面浏览器缩放退化，不因此宣称已完成移动端触控编辑。

## 3. 单位和尺寸 token

### 3.1 使用边界

<!-- prettier-ignore -->
| 对象 | 使用方式 | 约束 |
| --- | --- | --- |
| DOM 字号、间距、圆角、按钮热区、常规面板宽度 | rem；局部图标可用 em | 按现有值 /16 转换，默认外观不变 |
| 页面及面板布局 | Grid/Flex、%、minmax、clamp、容器查询、dvh | min-width/min-height 0；分别定义滚动 owner |
| DOM 细边框 | 1px | 无需为单位统一而迁移 |
| SVG 字形、描边、选择框、命中范围、核心几何及字体度量 | 现有逻辑单位 | 不按 /16 迁移；含 SVG 用到的 SCSS 字号也需保留 |
| DOMRect、clientX/Y、浮窗定位、滚动量 | CSS px 数值 | 由实际布局测得；不得乘 DPR |
| 打印 | mm 与分页逻辑单位 | 保留固定 A4 规格 |
| PNG | 输出像素和 DPI | 固定输出策略，与屏幕 DPR、rem、缩放无关 |

根字号使用 `html { font-size: 100%; }`。保留 body 默认 13px 的视觉基线：`font-size: 0.8125rem`；正文行高优先使用无单位值。不使用 `vw` 或屏幕宽度脚本修改根字号，也不采用 62.5% 的 10px 根字号。

建议建立 `apps/website/lib/ui-size-tokens.ts`，维护语义尺寸的 rem 值与 AntD 基准数值，避免同一概念多处硬编码。全局 CSS 变量引用同一组定义；可先集中少量关键 token，不要求建立生成系统：

```scss
html {
  font-size: 100%;
}
:root {
  --ui-font-body: 0.8125rem; // 默认 13px
  --ui-font-label: 0.875rem; // 默认 14px
  --ui-space-sm: 0.5rem;
  --ui-space-md: 0.75rem;
  --ui-control-height: 2rem;
  --ui-sidebar-width: 25rem; // 默认 400px，保持现有基线
}
body {
  font-size: var(--ui-font-body);
}
```

迁移须按 DOM 界面选择器逐块进行，尤其不能转换 `.restLayer`、谱面描边、文字度量参数和 Canvas 绘图常量。CSS 表达式中的 px 是否迁移按实际语义决定，不能只凭文件后缀判断。

### 3.2 Ant Design 桥接

`ConfigProvider` 的数值 token 不接受统一改成 rem 字符串。仅修改 body 会造成原生文字和 AntD 组件比例脱节；开启 AntD CSS 变量本身也不等于 px 转 rem。

本阶段默认维持 ConfigProvider 的现有 token；根字号 16px 时 uiFactor 必须为 1，不能以单位治理为由改变默认主题。只有要完整支持非默认浏览器字体时，才在同一验收阶段接通数值桥接：`uiFactor = measuredRootRemPx / 16`，AntD 的字体、控件高度、padding/margin/size、圆角等尺寸 token 使用对应基准数值乘 uiFactor；颜色、字重、z-index、持续时间不参与缩放，borderWidth 保留 1。审计全局及组件级 override，特别是 Form labelFontSize、itemMarginBottom 和 verticalLabelPadding，后者可直接采用 rem 字符串。由 AntD 派生的 token 不再额外乘一次，只有显式设置的入口 token 需要换算。桥接未完成前，不宣称已完整支持默认字体放大，也不单独提供应用级全局字号开关。

实现一个不参与流式布局的 `width: 1rem` 测量节点，以 ResizeObserver 读实际 CSS 宽度。SSR 与首屏先按 16px，客户端测量后只在值变化时更新 provider；初始化前不依赖 window。观察的是 rem 尺寸，不读取 DPR 或物理屏幕宽度。浏览器原生缩放已缩放 CSS px，不能再次用缩放倍数乘 token。卸载清理 observer，更新不重建输入组件。

验收先覆盖本编辑器实际使用的 Button/Input/Select/Tabs/Form/Popover/Modal；不得用 `.ant-* { font-size: ... !important }` 作为全局替代方案。如某组件仍有独立固定尺寸，补对应组件 token 或受控样式并记录范围。

### 3.3 是否引入 postcss-pxtorem

结论：当前不需要。通常使用的包名是 [`postcss-pxtorem`](https://github.com/cuth/postcss-pxtorem)，不是 `pxtorem-postcss`；它是构建期单位转换工具，不提供响应式布局、谱面缩放或 AntD 主题同步能力。

当前 `apps/website/postcss.config.mjs` 仅启用 Tailwind 和 Autoprefixer，本阶段保持不变，不新增依赖和 lockfile 改动。理由如下：

- `index.module.scss` 同时包含 UI、SVG 字号/描边、浮窗及打印规则，按文件统一转换无法表达正确边界。即使只配置 font-size，也可能误转谱面字体。
- PostCSS 只处理进入其构建流水线的样式；AntD 运行时 CSS-in-JS、React 内联 style、JS 数值及核心绘图参数不会自动被转换。不能用一个插件替代两套尺寸体系的审计。
- Tailwind 已有 rem 工具类；全局插件会扩大其作用范围到生成 CSS 和任意 px 工具类。为解决少量 UI 尺寸引入全局转换，回归面超过收益。
- 默认配置主要针对字体相关属性，并非所有 px；反过来配置 `propList: ["*"]` 又会误伤需要固定逻辑单位的规则。

落地采用手动按组件迁移：13px→0.8125rem、32px→2rem、400px→25rem，保持选择器优先级、盒模型、默认行高和断点。小数精度至少保留到能精确表达现有整数 px /16；不要顺手把 13px 改成 14px、将已有固定行高改为另一种视觉比例，或合并有级联差异的规则。

若后续迁移量显著增加，再单独评估插件，并必须先拆出只含 DOM 界面的专用样式目录，采用绝对路径白名单，默认不转换其他文件；`exclude` 是排除匹配文件，不是 include 白名单。建议 rootValue 16、unitPrecision 5、mediaQuery false、minPixelValue 2，propList 显式列举允许属性，禁止全局 `*`。排除 node_modules、核心包、SVG/打印/导出样式及定位规则，检查构建后的 CSS，验证对 Tailwind 生成样式的实际影响。插件只负责白名单文件的语法替换，不能作为 AntD 桥接的替代。

配置检查还需注意：mediaQuery false 不代表忽略 `@media print` 内的声明；规则属性仍可能转换。也不能假设该选项覆盖 `@container`；布局阈值由单独白名单/构建产物检查保护。CSS Modules 选择器可能经过类名处理，不能只靠 `.paper` 等选择器黑名单兜底，更不能依赖 `Px/PX` 大小写逃逸作为长期约定。

## 4. 响应式布局

### 4.1 测量与宽度分级

移除 `.editor` 后置 min-width 1440px。宿主保持 width 100%、min-width/min-height 0，工作区主列 `minmax(0, 1fr)`；页面外层不再承担横滚，谱面视口允许双向滚动，属性内容内部纵向滚动。先清除溢出来源，再收紧外壳 overflow，不能用裁切掩盖工具不可达。

在编辑器宿主建立 inline-size container。纯视觉收纳使用 CSS 容器查询；需参与面板互斥的状态由同一宿主 ResizeObserver 驱动。本专项采用保留现状的降级顺序：

<!-- prettier-ignore -->
| 可用空间 | 布局合同 |
| --- | --- |
| 宿主 <=1600px 且能容纳现有布局 | 保留 400px 属性栏、780/800px 纸张和现有单行工具，不主动改布局 |
| 宿主 >1600px | 侧栏按容器比例增长，谱面按第 5 节 auto 模式有上限地放大；UI 字号/控件高度不随宽度增大 |
| 工具行不足 | 优先低频菜单收纳或工具区域内部滚动，不缩小文字和热区；仍不足才允许两行 |
| 主区和常规属性栏不能共同容纳 | 保留侧栏原宽意图，转工作区内覆盖面板，不把常规栏普遍改成 352px |
| 极窄窗口 | 覆盖面板最大宽不超过工作区可用宽减安全间距；一次打开一个面板，谱面提供适合宽度与内部滚动 |

布局阈值继续使用 CSS px，rem 决定控件自然大小。初始降级阈值由基线测量确定：普通谱主区最低宽 = 现有纸宽 + 视口左右实际 padding；加上属性栏、边框及未来 rail 后，空间不足才转覆盖。不能把正在缩小后的谱面宽度反过来作为阈值，避免模式来回振荡。工具收纳另外测量实际宽度，不能只依赖断点。CSS 与 JS 共用尺寸定义，模式切换保留少量迟滞或稳定测量，防止滚动条/边框引起反复开关。

常规属性栏使用 `clamp(400px, 25cqw, 640px)`，使其在普通宽度保持 400px，在宽屏接近宿主四分之一，在超宽屏停止增长。尺寸相对于编辑器宿主，不依据物理分辨率；若后续迁移 rem，再将最小/最大值等值替换为 25rem/40rem，不改变中间比例。覆盖面板最大宽为工作区可用宽减安全间距，定位在工具栏下方。

```scss
.editor {
  container-type: inline-size;
}
.editorWorkspace {
  display: grid;
  grid-template-columns: minmax(0, 1fr) clamp(400px, 25cqw, 640px);
}
```

此示例须与现有 collapsed 单列规则和窄屏覆盖模式共同接入，不能直接覆盖隐藏侧栏逻辑；container 必须是被布局元素的祖先，不能在同一元素上定义并读取自己的 cqw。常规模式中侧栏是 400/480/610/640px，分别对应宿主 1600/1920/2440/2560px；这些是同一公式的示例，不代表相应显示器的实际 CSS viewport。常规侧栏新增可拖动调宽可作为后续需求，首期无需为此新增偏好持久化。

面板变宽后让输入框、分组和已有多列字段使用可用宽度，不只增大面板内留白；不为填满空间自动改变字段顺序、放大文字或将所有表单变为多列。超过 640px 不继续拉长单行表单，主区域继续使用剩余空间；极宽窗口允许保留适量留白，交付目标是占比合理而非每个像素都被填满。关联方案若实施 352/384px 属性栏，须与本专项协调，不同时保留两套竞争宽度规则。

当前未实现历史栏，本专项不单独新增历史功能；接入时其 rail、面板宽度和打开状态必须进入同一容器测量链路。工具栏使用关联方案的实际溢出收纳，但其 H/P、滑音和上下扫等要求直接可见的快捷符号不得移入“更多”；空间不足提供工具区域内部滚动。Tooltip/Popover 保持 Portal，避免被滚动区域裁切。

### 4.2 草稿、焦点和低高度

复用单实例 MusicTextSidebar，切换栏/抽屉仅改变呈现，不条件挂载另一套表单、不改变 key。布局变化不得提交命令、清草稿或改变撤销栈。沿用 canCollapse、草稿协调器和输入法组合保护；阻止关闭时暂时保留覆盖面板，延后其他面板打开。

抽屉 Escape/关闭恢复触发器焦点；若采用模态模式，需约束焦点并使背景不可交互。仅改变宽度或谱面倍率不抢夺输入框焦点。

保留 100dvh，弹层 max-height 使用工作区或 visualViewport 可用高度并预留安全间距。默认字体下可用高度 <=650 CSS px 时，表单内容滚动，应用/取消入口仍可到达；工具栏行数增加时由 Flex 剩余空间分配谱面高度。消除所有“有 overflow auto 但祖先 min-height 阻止收缩”的路径。

## 5. 谱面独立缩放

### 5.1 状态和倍率定义

新增网站层 `use-score-viewport.ts`，只管理会话视图状态：

```ts
type ScoreViewState =
  | { mode: "auto" }
  | { mode: "baseline" }
  | { mode: "fit" }
  | { mode: "actual" }
  | { mode: "custom"; scale: number };
```

界面提供“自动适配”“适合宽度”“100%”及 50%–200% 预设/加减控制。默认 auto：普通宽度保留旧比例，宽屏有上限地放大，窄屏缩小；baseline 仅为内部保守兼容模式，不必增加常驻按钮。100% 使用 actual，用户选倍率切到 custom；fit 为显式选择的完整内容适配。状态归外壳，不写 ILXMDocument、命令历史、文件或导出快照，换文档恢复 auto。actual/custom 保持用户倍率、允许谱面内部横滚；auto/baseline/fit 随可用空间调整。不要拦截浏览器 Ctrl/Cmd +/- 或 Ctrl/Cmd 滚轮。

100% 定义为“当前产品基准显示比例”，Tooltip 说明不是物理尺寸，也不要求 1 逻辑单位 = 1 CSS px。保留现有窗口 >=1600px 使用 800px、其他使用 780px 的规则，本专项不顺带取消该既有行为。仍传 `systemWidth: A4_CONTENT_WIDTH`；窗口变化不重新断行、不修改 density。令 B 为该规则确定的普通外框宽，横向 42、纵向 35 为现有 CSS px 留白：

```text
Lw = layout.width；Lh = layout.height
q  = (B - 2 * 42) / A4_CONTENT_WIDTH // 保留当前 SVG 到 CSS 的比例
Fw = max(B, Lw * q + 2 * 42)
Fh = max(900, Lh * q + 2 * 35)
W  = viewport.clientWidth - 左右实际 padding
C  = editorHost.clientWidth  // 侧栏和主区共同所属的宿主宽度
baselineScale = min(1, W / B) // 超宽小节仍可内部横滚，延续现有行为
growth = clamp(1, C / 1600, 1.6) // 初始放大上限，截图验收后定值
autoScale = min(growth, W / B)  // 默认适配普通纸宽，超宽小节允许横滚
fitScale = min(1.6, W / Fw)     // 显式适配全部内容，宽屏允许放大
actualScale = 1
effectiveSvgScale = q * displayScale
```

displayScale 取当前模式对应倍率，custom 使用用户倍率。auto/baseline 不因一个超宽小节把全谱自动缩小；fit 适配包含超宽内容及留白的完整外框。自动放大上限初设为基准 160%，避免巨幅单页；用户 custom 仍可选 200%。auto/baseline/fit 不套 50% 下限，否则极窄窗口无法适配；倍率过小时保留放大入口，不把缩小后的编辑热区当作触控可用性承诺。仅在 W、C、基准尺寸为有限正值时计算；隐藏或未完成测量时沿用最后有效倍率，首屏暂用 1，禁止 NaN/Infinity。

普通谱在 auto、宿主 <=1600px 且空间足够时应复现现有外框宽、留白、SVG 有效比例和最小高度，不引入此前草案约 817.23px 的新基准外框。宿主 1920/2440/2560px 时，增长目标约为 120%/152.5%/160%，还须受 W/B 限制；这些是本次期望的大屏变化，不纳入“旧纸宽不变”的比较。超宽谱允许扩大白色背景和滚动占位以覆盖溢出内容。外框 aria-label 可调整为“乐谱编辑预览”，避免连续编辑 SVG 被误认为已分页的 A4 成品。

### 5.2 渲染与滚动

优先使用实际 CSS 宽高，不使用全页面 zoom/transform：

- `.paper` 的 border-box width/min-height 分别为 Fw/Fh × displayScale，padding 为现有留白 × displayScale。
- SVG 的 CSS width/height 分别为 Lw/Lh × effectiveSvgScale，viewBox 保持原值；与当前 A4 百分比 width 实现只保留一套，不叠加倍率。
- 外框增加 max-content 或显式宽度的滚动占位容器；内容比视口窄时居中，比视口宽时从左侧起排，避免 auto margin/居中导致左侧溢出无法滚到。
- UI 按钮、Popover 和工具栏保持正常 DOM 比例；不放入谱面缩放容器。SVG 内的选择层、音乐层使用同一 viewBox。

观察 `.pageViewport` 的实际可用尺寸，不监听整屏分辨率。ResizeObserver 更新按 RAF 合并，仅在有效值变化时 setState；可设置稳定滚动条占位以减少 fit 与滚动条宽度相互影响。不要在 observer 回调中反复读取与写入同一尺寸导致循环。

缩放前记录可见选中目标的逻辑坐标及相对视口位置；无可见目标时记录视口中心对应逻辑点。缩放提交后在 layout effect 中通过新 CTM 获取屏幕位置，按位置差调整 scrollLeft/scrollTop 并限制到合法范围；fit 横向以完整外框可见为优先，纵向尽量保留锚点。与现有“自动露出选区”effect 合并调度，禁止两个滚动 effect 互相纠正。缩放事件清理 hover，但不清除选区或输入草稿。

### 5.3 指针命中与浮窗

继续使用 getScreenCTM().inverse() 将 client 坐标转换为逻辑坐标；不再手动除以 scale、浏览器 zoom 或 DPR。CTM 缺失/不可逆时跳过当次命中，避免错误选中。

将 effectiveSvgScale 和尺寸版本纳入浮窗重定位触发条件，并让 getFloatingObservedElements 包含实际 SVG/占位容器。现有 layoutKey 主要随布局变化，仅改变 CSS 显示比例时也须触发 recompute；同时覆盖 resize、内部 scroll、visualViewport 变化和侧栏开关。浮窗依旧 Portal 到 body，fixed 定位值使用 CSS px。

保留 non-scaling-stroke 的编辑提示描边规则，音乐线条按原逻辑缩放。先回归现有命中容差：若 50% 下细技巧不可稳定选择，再在网站交互适配层以固定 CSS px 容差经逆 CTM 转换为逻辑容差，并限制候选范围；不得直接放大音乐几何、改变对象优先级或把 px 热区转成 rem。

## 6. 打印和导出边界

保持 `prepareScorePresentation` 独立等待字体、重新度量、构建 presentation 布局并分页。`ScorePrintLayer` / `ScorePresentationPage` 不读取 screen scale、rem 尺寸 token 或侧栏状态；编辑 paper 的动态 style 不复用到打印节点。

打印继续 A4 210×297mm、8mm 页边距；PNG 继续 2480×3508、300 DPI，Canvas 按输出画布/页面逻辑尺寸换算，不根据 devicePixelRatio 扩大。`score-scene.ts`、音乐字体和度量器的逻辑尺寸不受 body/rem 迁移影响。浏览器中打印及图片预览 UI 可以响应式，输出内容尺寸保持既有规格。

回归使用同一已提交文档：切换屏幕 fit/50%/100%/200%、面板开关、默认字体后，比较分页数、成品逻辑几何、PNG IHDR 和 pHYs；不要跨浏览器要求 PNG 文件字节完全相等。

## 9. 风险与回退

- 首要风险是 rem 与 AntD 数值 token 不同步：默认保留主题，P3 字体偏好桥接独立交付，保留默认字体对比截图；异常可独立回退。
- 谱面倍率改变后浮窗和滚动可能沿用旧测量：合并滚动调度、观察 SVG，完成浏览器命中测试后再交付 P2。
- 响应式收起可能中断输入法或未应用草稿：保持组件身份并遵守现有保护；受阻时保持覆盖面板而不是强制隐藏。
- 根字体放大后纯断点不足：以实际工具溢出和面板空间判定补充降级，不通过缩小根字号修复。
- 误把 100% 改为逻辑单位 1:1 会放大原谱面：本轮保留现有 780/800px 与 SVG 比例，明确标为基准显示倍率，不引入 817.23px 新纸宽。
- 只将侧栏改宽会把空白转移进表单，不能解决谱面固定宽度：P1/P2 联合截图验收；大屏增长只作用于布局宽度及谱面显示，不全局放大 UI。

方案完成的标志是外壳可适配、界面尺寸可管理、谱面操作及输出稳定，而不是仓库中不再出现 px。
