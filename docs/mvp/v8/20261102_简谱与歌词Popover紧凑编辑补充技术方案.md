## 1. 本次纠正

用户已确认：选中一个歌词、简谱音符或合法空位后，在目标旁出现带箭头的 Popover 气泡卡片；气泡尽可能简洁，与侧边栏一起完成编辑。

原方案将完整表单迁入可拖动浮窗、侧栏仅保留入口和摘要，不符合这一目标。后续调整如下：

| 项目 | 本次约定 | 被替代的原约定 |
| --- | --- | --- |
| 呈现 | 始终依附当前目标的气泡卡片，带指向箭头、无遮罩 | 可拖动的独立浮窗 |
| 常用编辑 | 气泡内完成输入、少量常用选项和应用 | 完整表单迁入浮窗 |
| 完整编辑 | 侧栏提供完整属性及复杂操作 | 浮窗内展开高级区 |
| 两处关系 | 同一目标、同一份草稿，一个活动编辑表面 | 侧栏只显示入口和草稿摘要 |
| 定位 | 跟随目标，边界翻转，不提供拖动和“回到选中位置”常驻按钮 | 手动固定窗口位置 |

本次仍只考虑 PC，不调整文件 schema、简谱与 TAB 独立时值规则、歌词事件绑定或已有覆盖默认值。

## 2. 使用频率与重要性

当前没有用户行为统计。以下优先级来自现有编辑流程及本轮用户确认，是设计依据，不作为已验证的使用数据。

| 任务 | 频率判断 | 气泡 | 侧栏 |
| --- | --- | --- | --- |
| 修改当前歌词 | 高频 | 输入、应用 | 完整编辑保留 |
| 连续填词、逐位置填写 | 高频 | 单点/连续切换、输入；单点支持应用并到下一位置 | 分词规则、映射明细、批量配置 |
| 修改简谱正文、空位连续录入 | 高频 | 根据选中目标自动显示对应输入 | 完整编辑保留 |
| 常用时值及附点 | 高频 | 单行图标工具条 | 完整时值及影响预览 |
| 八度、升降等音高录入 | 输入必需 | 沿用现有正文语法，不另堆属性字段 | 成员音高精细设置 |
| 歌词段号 | 正确性重要，切换频率相对低 | 显示当前段号 | 切换段号、管理歌词行 |
| 复杂节奏、连音比例、成员独立时值 | 相对低频 | 不常驻 | 完整配置 |
| 连接记号、技巧、范围复制粘贴及替换 | 相对低频 | 不常驻 | 完整操作 |
| 清空、删除 | 后果重要 | 不放在主操作区 | 显示明确后果并沿用既有保护 |
| 冲突、越界、覆盖提示 | 正确性关键 | 发生时就地提示 | 详细预览与处理 |

正确性的重要程度不等于控件常驻数量。目标、草稿状态及有实际影响的警告必须可见；详细规则、完整预览和低频属性交给侧栏。

## 3. 视觉与尺寸

以用户本轮提供的 `image-1.png` 为视觉依据：浅色卡片、圆角、轻阴影，标题与位置同排，输入框最突出，时值图标单排，应用按钮使用主题主色。沿用原方案保存的[参考图](./references/简谱与歌词浮窗编辑参考图.jpg)作为相关素材；本轮附图是新的局部样式参考，不将旧图宣称为本轮附件副本。

相较参考图进一步压缩：不保留大字号标题、大间距、两条完整分割线和节奏型下拉；用留白区分层次。气泡不显示“高级选项”折叠区，不展开表格或长篇说明。

建议尺寸作为实现起点，最终按真实页面截图验收：

| 项目 | 建议 |
| --- | --- |
| 简谱宽度 | 默认 360px，允许 340～400px，受谱面可用宽度限制 |
| 歌词宽度 | 默认 320px，连续录入可使用 360px |
| 内边距 | 12px；分组间距 8px；同组间距 4～6px |
| 标题、正文 | 标题 14px，中等字重；输入 14～16px；辅助文字 12px |
| 控件 | 输入框和主要按钮高度约 32px，时值图标命中区域至少 28×28px |
| 圆角、箭头 | 圆角约 10px，箭头约 8px，与卡片同色 |
| 正常高度 | 简谱约 170～210px；歌词单点约 140～170px；异常提示可增高 |

窄窗口及浏览器放大时，宽度不超过可用区域减去两侧各 12px；必要时工具条换行，不压缩到图标重叠。正文、警告和应用按钮不得被截断。异常较复杂时通过“更多编辑”进入侧栏，不把气泡撑成完整属性面板。

### 3.1 简谱空位连续录入

```text
连续录入   第1小节 · 第1拍                ×
[ 1 2 3 5                                ]
时值  [全][二][四][八][16][32] [附点]
4 个音符 · 占 2 拍 · 可用 2 拍
更多编辑                       取消  应用
```

实际时值按钮使用音乐符号，文字仅用于此结构示意。选中状态使用浅主题色底及主题色符号，悬停说明显示名称；附点为可切换按钮。默认均分，不放“节奏型”下拉，三连音和自定义配置进入侧栏。

### 3.2 已有简谱修改

沿用相同结构，标题改为“修改简谱”，读取现有正文与真实时值。正文修改与时值修改继续是独立提交分组：

- 气泡底部“应用”只应用正文，正文无变化时禁用，不代替时值提交。
- 时值工具条调整后，在该行出现紧凑的“应用时值”；未应用状态明确显示，恢复原值后移除该动作。
- 正文或时值修改存在依赖冲突时，禁用受影响操作并提示先处理哪一项；沿用现有依赖判断，不静默逐组提交。
- 空位录入时，工具条代表新音符的录入配置，与正文一起应用，不出现独立的“应用时值”。

这一少量按需增出的操作用于保持现有分组提交语义，不为追求更少按钮改成含糊的统一提交。

### 3.3 歌词

```text
歌词 · 第1段   第1小节 · 第1拍            ×
[单点 | 连续]
[ 当前歌词                               ]
更多编辑                  取消  应用并下一处
```

单点模式主按钮为“应用并下一处”，Enter 同义；Shift+Enter 仅应用当前内容。末尾没有下一位置时主按钮为“应用”，并提供简短的末尾提示。无修改时不重复写入；仍可用既有导航跳到下一歌词位置。

连续模式输入框初始两行，主按钮为“应用”，仅增加一行“写入 N 处 · 覆盖 M 处”。不常驻原词说明、详细分隔规则、下一位置长文本及映射表。段号跟随所选歌词，切换段号在侧栏完成。

## 4. 气泡与侧栏协作

### 4.1 一个活动编辑表面

默认点击谱面目标打开气泡。点击“更多编辑”展开侧栏对应的简谱或歌词页签，定位当前目标及相关分组，同时收起气泡。该动作只切换呈现，不提交、不丢弃草稿，不产生音乐撤销记录。

侧栏提供“回到气泡”动作；返回时保留相同目标、正文、配置、未应用分组及错误。侧栏关闭也按同样规则回到气泡；若目标不可见则保留会话，待目标恢复可见后展示。始终只显示一套活动输入表单，不让两个地方出现内容不同的输入框或两个竞争的应用按钮。

进入侧栏后继续点击同类谱面目标，沿用侧栏作为活动编辑表面并更新目标，避免每次点选都重新弹出气泡。结束本次编辑会话后，下次直接点选默认回到气泡。其他类型属性的切换仍走既有草稿保护。

### 4.2 侧栏保留完整能力

简谱侧栏承接复杂节奏、成员时值与音高、连接记号、范围复制粘贴、固定范围替换、覆盖配置、完整影响预览及清空/删除。歌词侧栏承接段号、连续填词详细规则、逐项映射、覆盖配置及删除歌词。

气泡中没有的复杂配置若已由侧栏设置，返回气泡后不能悄悄重置为默认值。工具条无法完整表达时，显示一行“使用自定义节奏 · 侧栏编辑”，禁用会歧义地覆盖该配置的快捷时值按钮；进入侧栏调整，或通过明确的“恢复均分”动作重置，保留草稿保护。

### 4.3 覆盖与越界

- 无冲突时仅显示简短结果摘要。
- 存在已获许可的覆盖时，显示覆盖数量，不能隐去影响。
- 尚未允许的覆盖显示“将覆盖 N 处，前往侧栏确认”，应用禁用；入口打开侧栏对应配置和预览，不增加第二套确认逻辑。
- 超出当前空白范围或谱尾时，保留输入、说明可用范围，整批零写入；不使用参考图中“遇到已有音符停止”的部分提交语义。
- 结构变化仍使用已有影响确认；气泡和侧栏不得绕过或重复触发同一提交。

## 5. 打开、关闭与锚定

点击已有简谱、歌词及合法空位均可打开；重复点击同一目标不重置输入。最多一个气泡，没有遮罩，不锁谱面滚动，不支持拖动或自由缩放。

锚点使用当前目标的真实屏幕 bounds。气泡优先在下方，其次上方，再考虑左右；箭头始终指向目标，靠边时移动箭头并避开圆角。卡片与目标间距建议 8px，不能盖住当前目标的焦点框。切换目标后必须跟随新目标，不沿用原浮窗的手动位置。

滚动、缩放、谱面重新布局及侧栏尺寸变化时重新计算位置。目标离开谱面可视区域时暂时隐藏气泡，保留草稿和会话；返回可视区域后恢复，不把卡片停在屏幕边缘指向不存在的位置。空间不足以容纳最小可操作卡片时，转入侧栏完整编辑并保留状态；输入法组合输入期间延迟会卸载或转移输入节点的呈现切换。

关闭规则：

| 动作 | 干净状态 | 有未应用修改 |
| --- | --- | --- |
| 取消、×、Esc | 关闭，焦点返回当前谱面目标 | 走已有应用/放弃/继续编辑保护 |
| 点击谱面空白 | 收起气泡，保留选中项 | 保持输入，不自动提交或丢弃 |
| 点击其他编辑目标 | 切换后重新锚定 | 先走既有切换仲裁，通过后才切目标 |
| 点击“更多编辑” | 打开对应侧栏 | 原样带入草稿，不触发离开编辑确认 |
| 应用成功 | 依当前任务停留或进入合法下一位置 | 成功分组更新基线，其他分组草稿保留 |

Popover 仅描述交互形态，可使用 Portal 定位；不得套用组件默认的点击外部即卸载逻辑而绕过草稿保护。其自身不走一次性模态请求；真正的结构影响确认继续使用原有模态流程。

## 7. 键盘、输入法与状态保护

保持非模态、可访问名称及 `aria-modal="false"`，输入不是 Tooltip，不使用悬停自动消失。时值图标提供名称与选中状态，× 和“更多编辑”可键盘访问。

歌词单点 Enter 应用并下一处，Shift+Enter 仅应用；简谱和连续歌词保留文本输入行为，Ctrl/Cmd+Enter 应用正文。Esc 先处理下拉或输入法候选，再处理关闭。编辑输入中的数字、方向键、删除及文本撤销不穿透到谱面。

正文、时值、成员音高继续独立提交；版本、目标和输入候选校验沿用原有链路。隐藏气泡、进入侧栏、目标离屏都不解除未处理草稿的输出阻断。撤销、外部文档变化、目标失效继续按现有规则处理，不能把草稿写入恰好占据旧位置的新对象。

## 8. 验收标准

1. 点击歌词或简谱后出现带箭头的紧凑气泡；无遮罩、无拖动标题，不展开完整属性表单。
2. 常规简谱录入仅包含标题、输入、时值工具条、单行摘要与底部动作；不常驻节奏型下拉、高级区、规则说明和预览表。
3. 歌词能在气泡中完成当前词修改、连续填词及逐位置填写；段号显示正确，切换在侧栏完成。
4. “更多编辑”进入侧栏时目标、文本、配置、脏分组及错误原样保留；返回气泡不重置自定义节奏。
5. 任意时刻只有一个活动输入表面；正文应用与时值应用的作用范围明确，失败和取消确认均零写入。
6. 靠近谱面边缘可翻转，滚动与缩放后箭头仍指向当前目标；目标离屏时保留草稿，返回后恢复。
7. 覆盖和越界信息可见；没有获准的覆盖不能应用，超出范围不部分提交。
8. 中文输入法选词 Enter/Esc 不提交、不关闭；气泡与侧栏切换不截断组合输入。
9. 关闭、切换目标、输出及恢复草稿继续受原有保护；取消、隐藏和呈现切换不产生音乐撤销记录。
10. PC 常用窗口宽度及 200% 浏览器缩放下，输入、警告和应用可操作；空间不足时可在侧栏继续同一草稿。

验证以针对性定位测试、现有草稿/分组提交回归及真实页面截图为主；真实中文输入法、跨浏览器定位和浏览器菜单缩放需人工验证。实施验收不得在仅完成方案时标记通过。

## 9. 审查范围

本轮仅维护方案文档，不实施 UI 或业务代码。审查重点为：默认 320/360px 的紧凑体量、简谱独立时值应用、歌词段号移至侧栏、一个活动编辑表面，以及侧栏完整编辑后的返回规则。第 10～16 节补充实现细节；以下类型和代码均为待实现的接口草案，不代表源码已有。用户确认方案后，再按 Steps 实施并回填验收结果。

## 10. 状态模型与切换接口

### 10.1 呈现状态和业务目标分离

由现有 `MusicTextSidebar` 持有呈现状态，不新增全局草稿 store。`activeObject`、`draft`、`numberedTarget`、暂存目录及 `NumberedEditorController` 继续是业务状态来源。新增状态建议如下：

```ts
type TextSurface = "popover" | "sidebar";
type TextPresentation = {
  surface: TextSurface;
  sessionKind: "numbered" | "lyric" | null;
  dismissed: boolean; // 仅干净气泡点击谱面空白后置 true
};
type PopoverSuppression =
  | "none" | "offscreen" | "layout-pending" | "modal";
```

`PopoverSuppression` 由锚点、布局和模态状态推导，不再保存第二份 open 布尔值。可见条件为：合法文字目标、popover 表面、未 dismissed、suppression 为 none、空间可容纳。目标失效与布局暂未生成必须区分：前者走现有失效处理，后者保留 owner 等待下一次布局。

输入活跃与未处理草稿分别计算。离屏隐藏或主动收起干净气泡时释放当前输入活动标志，焦点回谱面；脏分组仍登记在协调器并阻断输出。不能简单以“有文字目标”判定正在输入，否则干净气泡收起后仍会阻断输出。

### 10.2 两条请求路径

1. **业务请求**继续调用现有 `request(action: SidebarAction)`：目标、歌词模式、段号、简谱模式、和弦及歌曲页签等会影响业务的切换。保留 accepted/pending/blocked 返回值，accepted 前不改变谱面 selection、锚点或呈现状态。
2. **同目标呈现请求**增加 `requestSurface(next, focusGroup?)`：只切换 surface 和焦点，不调用 `loadTarget`、`discard`、`apply`，不增加文档版本、不清除暂存。它不能作为 `SidebarAction.tab` 发送，因为现有执行分支会清理当前编辑状态。

呈现请求检查 `composing.current`、输入法结束保护、pending、`numberedBusy`、`navigationApplying.current` 和活动模态；不满足条件时返回 blocked。用户点击的呈现请求不排队重放，避免旧点击在输入法结束后意外跳转；空间不足等布局请求在保护解除后重新按最新布局求值。

同一会话中切换同类对象保留当前 surface；切换到另一种文字类型时默认 popover，切换 TAB/和弦/歌曲设置则结束该文字呈现会话。只有业务请求真正被接受后更新 sessionKind。关闭确认“继续编辑”保留原 surface。

| 事件 | 状态处理 | 焦点与草稿 |
| --- | --- | --- |
| 首次有效文字目标 accepted | surface=popover，dismissed=false | 加载合法目标，聚焦输入 |
| 同一目标重复点击 accepted | 清除 dismissed，不重建草稿 | 恢复原输入选区 |
| 同类新目标 accepted | 保留 surface，清除 dismissed | 沿用当前简谱暂存/歌词确认机制 |
| 更多编辑 accepted | surface=sidebar | 不加载目标；恢复对应分组 |
| 回到气泡/收起文字侧栏 accepted | surface=popover | 相同 owner；锚点可见后恢复输入 |
| 干净气泡点谱面空白 | dismissed=true | 释放输入活动，保持选中目标 |
| 脏气泡点谱面空白 | 不切换、不隐藏 | 保留输入；不得误发 selection 请求 |
| 锚点离屏 | 推导 offscreen | 隐藏视图，保留草稿；不自动滚回 |
| 结构确认打开 | 推导 modal | 当前输入 inert；模态结束恢复发起控件 |

“收起侧栏”与“结束编辑”必须是两个明确动作；前者调用 requestSurface，后者沿用 request(close)。现有 `onOpen` 在 `index.tsx` 实际用于清理谱面交互，不承担侧栏展开控制，不能误当作开关接口。文字侧栏开合在本次呈现状态中控制，其他属性页签沿用原路径。

## 11. 稳定组件树和视图拆分

### 11.1 第一版采用同一 DOM 容器切换样式

沿用现有 `MusicTextSidebar` 的编辑 `<aside>`，使用稳定 key `music-text-editor-surface`。气泡时 position:fixed，侧栏时参与现有右侧栏布局；切换 class、role、宽高和标题动作，不把整个 editor 在两个父节点间移动。原 `floatingSidebarSummary` 不再独立渲染成第二套编辑栏，其草稿入口合并到侧栏摘要区域。

同一业务目标下保持以下路径稳定：

```text
MusicTextSidebar（目标、仲裁、歌词草稿、presentation）
  └─ aside[key=music-text-editor-surface]（位置/样式/公共事件边界）
       └─ MusicTextEditorBody（固定父节点）
            ├─ NumberedEditor（既有草稿和提交 owner，目标 key 不变）
            └─ LyricFormView（受控视图，歌词草稿仍在 Sidebar）
```

简谱与歌词按业务类型选择；不是同时挂载两套编辑器。`NumberedEditor` 当前 key 含 externalNumberedVersion、mode 和目标草稿 key；不得增加 surface、侧栏宽度或几何坐标。业务目标切换仍可沿用现有快照恢复和 key，不为避免所有重挂载而取消必要的业务初始化。

新增 `MusicTextPopover` 定义为纯呈现装饰层：稳定返回同一种容器结构，在 popover 时显示箭头与紧凑标题，在 sidebar 时显示完整标题。不得使用 `surface === ... ? <Popover><Editor/></Popover> : <Aside><Editor/></Aside>`。也不切换 `createPortal` 的 container。

固定定位上线前核对祖先的 transform/filter/contain 和 overflow：若形成固定定位包含块或裁切，应在这条路径的布局样式中消除影响，并验证谱面缩放不作用于侧栏容器。若确需 Portal，必须统一为从首次挂载就固定的 Portal 容器，并为侧栏提供稳定占位及坐标；不得只在气泡模式临时 Portal。第一版不引入此额外布局，若现有样式不能满足则先更新方案说明依据。

### 11.2 NumberedEditor 接口

新增 `presentation: TextSurface`、`onRequestSidebar(group?)` 两个呈现参数。现有 `ref`、`snapshot()`、`applyGroup()`、`focus()`、`setRhythm()` 等控制接口继续保留，不复制一套 controller。

渲染前构造同一份 view model，包括 raw、event/window、base/dots、templateBase/templateDots、template、contentDirty、dirtyGroups、canApplyByGroup、plan/issue、busy 和 nextPosition。紧凑视图和完整视图只读取这些值并调用同一组 setter/action；不在视图层重新解析节奏、计算 tick 或拼提交命令。

补齐分组的可执行状态接口 `groups[group]: { dirty, canApply, blockedReason }`：当前 canApplyByGroup 主要反映本组合法性，跨组依赖在提交 check 阶段才拦截，直接复用它不足以提前禁用。将现有 check 中无副作用的依赖判断提取成共用纯校验，在 view model 和提交边界各调用一次；呈现时的通过不替代提交时重验。气泡显示首个 blockedReason，详细状态交给侧栏，不能再维护另一套依赖规则。

正文输入保留相同 DOM 位置、key 和 ref；优先让高级区通过 hidden + inert 隐藏，基础区域用 CSS 改变密度，保持 textarea 和 IME 节点稳定。若确需拆分完整视图组件，只允许拆纯字段区，不能把 useState、提交锁或 `useImperativeHandle` 移进随 surface 卸载的组件。隐藏高级字段不做 required 原生校验，不可继续被 Tab 聚焦。

现有简谱影响确认 dialog 及草稿离开确认区域必须留在高级字段隐藏范围之外；紧凑视图也需要这些保护，不能因隐藏完整侧栏区而一并隐藏。异步确认使用原有单一 Promise/锁，确认打开时禁用呈现切换。

### 11.3 歌词视图和焦点

`LyricFormView` 增加 presentation 参数；同一 lyricMode 下保留正文输入节点，仅隐藏段号、完整说明和预览区域。single/sequence 仍按现有业务模式请求切换，模式转换不是呈现切换。两个 surface 不得各自拥有 draft.text。

切换前记录 `{targetKey, group, selectionStart, selectionEnd, selectionDirection}`；完成 DOM 更新后在 layout effect 中恢复，先验证 targetKey 和 surface 请求代次仍匹配，再 focus({preventScroll:true})。侧栏展开后用最近可见滚动容器定位指定分组，不能滚动整张谱面。非当前请求或目标已变时取消恢复，避免旧 effect 抢焦点。

呈现请求的 targetKey 使用归一后的业务身份：简谱已有事件为 track/measure/event（有具体成员则包含 item），简谱空窗为 track/measure/tick/endTick，歌词还包含 verse。复用现有目标解析和草稿 key，不引入以屏幕位置、beatIndex 或当前标题作为身份的捷径。

有 itemPitch 等气泡不支持的未提交分组时，紧凑摘要显示“另有音高修改 · 侧栏处理”；不能让该状态随隐藏字段消失。恢复输出阻断中的 rhythm/content 可定位气泡，恢复 itemPitch、范围及复杂配置则直接打开侧栏。

草稿目录/输出阻断的 focus 回调按“请求目标并等待 accepted → 选择可表达该分组的 surface → 必要时 revealFloatingTarget → 布局和输入节点就绪后聚焦”执行。目标离屏或尚无锚点时不能直接调用隐藏 input.focus；无法 reveal 则转侧栏。恢复过程中再次检查业务身份和请求代次，目标失效时显示原因而不聚焦其他对象。

## 12. 字段绑定及提交细节

### 12.1 时值工具条

| 场景 | 显示/修改来源 | 动作 |
| --- | --- | --- |
| 空位均分录入 | templateBase/templateDots | 只改正文创建配置，正文 applyGroup(content) 一次提交 |
| 已有事件时值 | base/dots | 修改 rhythm 草稿，applyGroup(rhythm) 独立提交 |
| 已有事件范围替换、三连音或自定义 | 现有 template、customRhythms、ratioIndex、fixedRange | 显示自定义摘要，转侧栏编辑，不伪装成普通均分 |

值域沿用 `ILXMRhythmBase` 的 whole/half/quarter/eighth/sixteenth/thirtySecond，不以按钮索引计算 tick。普通附点按钮只表达 0/1；已有双附点或其他无法表达的时值，显示真实名称与“侧栏编辑”，不截断或擅自改成单附点。音乐图标采用现有图标资源或内联 SVG，不依赖某个系统音乐字体。

工具条使用新的本地草稿动作 `changeEventRhythmDraft(base, dots)` 或 `changeInputRhythmDraft(base, dots)`，分别封装对应 setter 和现有录入偏好同步，操作本身零写入。现有 controller.setRhythm() 会直接提交，继续供原有即时命令使用，不能把它绑定到这些工具条按钮。

“恢复均分”位于侧栏，显式调整 template 及成员节奏配置，更新正文草稿和摘要；不直接提交。返回气泡后须保持实际配置与显示一致。

主应用按钮禁用条件使用 `canApplyContent` / `canApplyByGroup.content`，不能使用可能代表其他唯一脏分组的总 `canApply`。已有事件工具条按钮使用 `canApplyByGroup.rhythm`；所有提交还受 pending、busy、输入法及候选校验限制。主按钮与快捷键调用相同动作。

### 12.2 歌词应用与无修改导航

沿用现有 `apply(advance)` 与 `SetLyric` / `SetLyricSequence` 命令。single 有修改时调用 apply(true)，仅应用调用 apply(false)；sequence 始终 apply(false)，不承诺新增连续录入自动跨段。

single 无修改但存在下一位置时，按钮改为“下一处”，Enter 仅调用既有 `resolveNextLyricTarget` 和受保护的目标请求，不发送 SetLyric。无修改且无下一位置时禁用“应用”。正文空白校验仍拒绝，清空输入不隐式删除歌词；删除在侧栏使用原有 RemoveLyric。

下一位置在成功结果 document 上解析，不使用提交前缓存。若首写创建 gap，使用命令返回文档重新读取归一后的目标，不能继续拿旧空窗身份推进。连续填词采用原 plan 的 changes/overwrites/rows，不能按输入字符数推算写入数。

### 12.3 预览和错误来源

预览复用已有 planner。简谱数量/占拍/可用范围取现有 plan 和目标 window；歌词写入/覆盖数取 `planLyricSequence`。为空或非法输入时不显示误导的成功数量，改显示可用范围或明确错误。

用现有冻结候选、版本校验、committing 和提交锁；呈现切换不改变业务候选代次。正文或配置改变仍使旧候选失效。提交中禁用按钮和 surface 请求；确认取消后保留原草稿和发起分组。不允许“先提交正文，再提交时值”式隐式批量处理。

## 13. 定位计算与可见性

### 13.1 坐标和输入输出

复用 `index.tsx` 的 `getFloatingAnchor`：`resolveParagraphFocus` 得到布局 bounds，通过 SVG `getScreenCTM()` 转成 CSS 屏幕坐标；不得再手工乘一次谱面缩放比例。对 bounds 四角变换后取 min/max，避免将来存在变换时矩形颠倒。视口仍取 visualViewport 与谱面 pageViewport 的交集，额外排除实际遮挡谱面的固定工具栏/覆盖式侧栏。

新增布局变化通知：除现有 scroll/resize/visualViewport/卡片 ResizeObserver 外，观测谱面 viewport 和右侧栏尺寸；`lxmLayout` 或缩放变化使 getAnchor 更新后请求重算。所有通知合并进同一个 requestAnimationFrame；effect 清理时取消 rAF 和 observer，不在每个事件中交替测量和写样式。

```ts
type PopoverPlacement = "bottom" | "top" | "right" | "left";
type PopoverGeometry =
  | { kind: "placed"; left: number; top: number;
      placement: PopoverPlacement; arrowOffset: number }
  | { kind: "hidden"; reason: "offscreen" | "layout-pending" }
  | { kind: "sidebar-required" };
```

扩展现有纯定位函数，不读取 DOM 或 React 状态；传入 anchor、实测 panelSize、可用 bounds，返回以上结果。定位 hook 负责测量、通知和应用结果，不处理音乐命令。

### 13.2 确定的布局算法

1. bounds 各缩进 12px，宽高非正或布局尚未就绪返回 hidden，不在 (24,96) 等默认坐标闪现卡片。
2. anchor 与可用 bounds 无交集返回 offscreen；部分可见时以可见交集作为箭头目标，保持完整原 bounds 用于遮挡检查。
3. 按 bottom → top → right → left 构造候选，卡片边缘距锚点 8px；箭头是这个间隙内的装饰，不额外推开卡片。
4. 每个候选只允许沿贴边方向的垂直轴平移以避开边界，例如 bottom/top 只修正 x；检查卡片整体在 bounds 内且不覆盖选中框。不能 clamp 后把卡片推回目标上。
5. 箭头对准可见目标中心；偏移限制在卡片圆角之外（至少距边 16px）。若目标中心超出允许范围，可指向目标可见边界上的合法点；仍无法指向目标的候选作废。
6. 首个可行候选返回 placed；全部不可行时按可用宽度调整卡片并重新实测一次。歌词/简谱最小可操作宽度均为 280px，不小于控件实际需要的宽度；完整必需内容仍放不下则 sidebar-required。

先以 visibility:hidden 测量，placed 后展示；不会先显示错误位置。width 在一次测量轮次中固定，避免 ResizeObserver 循环。箭头位置通过 CSS 变量表达，pointer-events:none，方向随 placement 旋转。

### 13.3 降级、离屏与恢复

sidebar-required 时在保护允许后调用 requestSurface(sidebar)，只发生一次；打开侧栏导致空间更小不反复重算降级。之后窗口变宽不自动切回，用户选择“回到气泡”时再测量，仍不足则保留侧栏并提示“当前空间不足”。

离屏隐藏保留同一编辑 owner，输入活动状态释放。若正在组合输入，先保留原输入节点和位置，等 compositionend 及既有结束保护完成后再隐藏/换表面；这段过渡禁止提交和业务目标切换，不能用 display:none、inert 或卸载打断候选。目标恢复可见可重新展示，但用户焦点已在谱面或其他工具时不自动抢回；点击目标后才恢复输入。模态关闭的焦点恢复另外遵循发起控件规则。

## 14. 事件边界、弹出内容和样式

将现有 aside 上的 pointer/key/composition/paste 处理保留在稳定编辑容器，不把原本在 DOM 祖先上的处理遗漏到新气泡。Select 的方向键、Enter、Esc 和 Portal 下拉内容继续按现有规则优先处理。

不使用 document 级通用 click-away 自动关闭。谱面空白命中分支才触发“空白收起”，目标选择仍走现有命中及 request 仲裁；需要新增控制器方法 `dismissCleanPopover(): boolean`，仅在无组合输入、无 busy/模态、当前无脏分组时返回 true。该方法不发 selection/close，不丢弃其他目标暂存草稿。

如事件需要区分内部区域，以编辑容器、确认区域及带本编辑会话标识的 Portal 根为内部集合，并读取 composedPath；不得把所有 `.ant-select-dropdown` 都算作当前编辑器。点击时值按钮保留正文选区，正常键盘仍可到达按钮。

层级沿用当前 Select 60、Tooltip/Popover 70 的配置作为检查起点，气泡本体低于其内部菜单、高于谱面；须核对它们处于同一 stacking context，真正模态高于所有这些层。活动模态期间编辑容器与遗留菜单均 inert/关闭，不能单靠提高 z-index 解决。

保留唯一 DOM id 和 label 关联。原 `#music-text-sidebar` 若继续用于完整属性容器，应同步迁移外部 focus 查询，不能让 summary 与编辑容器共用 id；测试定位优先使用可访问名称和稳定 data 属性。

## 15. 实施顺序及验证对应

| 顺序 | 交付 | 必须验证后才能继续 |
| --- | --- | --- |
| 1 | 呈现状态、requestSurface、稳定编辑容器 | 同目标切表面不触发 discard/commit，不重建 NumberedEditor；完整旧流程仍可用 |
| 2 | 紧凑字段及侧栏完整视图 | 字段实际来源正确；高级脏状态和自定义配置往返不丢；正文/时值独立 |
| 3 | 定位函数、箭头和布局 hook | 四方向、边缘、离屏、无布局、空间不足均有确定结果；无定位闪烁 |
| 4 | 空白收起、输入法、焦点、恢复编辑 | 不穿透谱面、关闭保护有效、草稿恢复回正确表面 |
| 5 | 页面验收 | 紧凑尺寸截图、缩放和桌面浏览器人工记录；回填结果后才勾验收 |

只新增能验证风险的测试，不为 CSS 常量或组件拆分本身增加镜像测试。至少覆盖以下行为：

| 验证层 | 用例与断言 |
| --- | --- |
| 纯定位 | bottom 放不下翻 top；左右边界箭头合法；目标遮挡则拒绝；离屏 hidden；280px 也放不下则 sidebar-required |
| 状态/仲裁 | pending/blocked 不提前切 surface 或 selection；更多编辑不调用 loadTarget/discard；关闭确认取消停留原表面 |
| 草稿 | 简谱正文、rhythm、itemPitch 及歌词文本/覆盖配置往返一致；暂存 A→B→A 继续受版本校验 |
| 提交 | 正文按钮不提交 rhythm；空位时值随正文提交；已有时值独立应用；冲突、取消、失败零写入 |
