# BUG-017～BUG-020 修复技术方案

状态：用户已授权实施；6/8 的延音横线按八分音符单位已确认。修复已完成，回归验证结果见文末实施记录。

来源：[六线猫 bugfix](https://pcnhehlhivqu.feishu.cn/wiki/UEivw1G7Liuaqnk20d1cqCoxnHb?from=from_copylink&sheet=0d8c47)。通过 lark-cli 读取工作表 0d8c47，revision 198，第 18～21 行及四张参考截图；同时核对 BUG-005、BUG-016 的处理记录与当前工作区代码。

## 1. 总体判断

BUG-017、BUG-020 应共享一套按音乐时间排列的简谱录入规划；BUG-019 应复用这套规划的目标解析。BUG-018 是延音横线从“弦格内容”改为“拍点内容”的语义调整，需要同时处理命令、数据、命中和绘制。

已确认的代码机制：

- 简谱输入范围会按 TAB 和已有简谱推导可编辑空位；这些空位不一定是 numberedVoice.events 中的真实事件。
- 现有 numbered.sequence.set 按真实事件数组依次修改内容，保留目标事件原有节奏。它无法覆盖数组里不存在的虚拟空位，因此存在跳到后续真实事件的路径。
- BUG-019 的 TAB 入口只查同 tick 的简谱事件，未检查覆盖该 tick 的长事件；找不到就构造 TAB 输入窗口，最终插入命令才因重叠拒绝，因此出现看似能录入、实际无法提交的状态。
- 现有 TAB 横线使用 ILXMFret 的 `"-"`，仍保存在某根弦的 note 上；工具栏 continuation 最终发送 SetNotesInRect。duration-beam-layout.ts 又将所有有 notes 的普通拍纳入符干/连梁计算，没有将横线排除。
- 原 tab-continuation.test.ts 明确验证了跨弦逐格设置横线；BUG-018 会修订该行为及对应测试。

BUG-020 的限制：如果四个十六分音符都是连续真实事件，当前 sequence.set 的上述分支原则上会保留四者时值。因此不能将“四个真实事件”场景未经复现就判定为同一根因。截图中的“三个音符占 2.25 拍”与十六分、四分、四分的组合一致，支持实际命中了后方长时值事件的判断，但仍需用实际事件数据及入口模式验证。

## 2. BUG-017、BUG-020：连续输入优先覆盖相邻时间槽

### 建议交互口径

默认按起始位置向后逐槽覆盖，每个输入项使用对应目标的节奏，包括附点；目标既包含真实简谱事件，也包含可输入的虚拟占位。

- 前八后十六，输入 `5 6 7`：分别得到八分 5、十六分 6、十六分 7，恰好覆盖这一拍。
- 一拍四个十六分，从第一个输入 `2 3 3`：覆盖前三个位置，第四个保持，下一拍不变。
- 本拍目标用完后，才允许继续进入后续拍；不允许为了找真实事件而提前跳过空位。
- 显式修改当前音符时值，与整段套用统一节奏应保持独立语义。默认连续覆盖继续跟随后续目标，不能因首音时值被修改而把后续所有项都套用该值。用户主动选择批量时值或模板时，按新节奏计算替换范围；例如四分音符处主动选择八分模板并输入 `1 2`，得到两个八分音符。属性自动高亮不等于主动选模板。
- 保持现有跨小节、覆盖确认和最多 256 项的限制；超出允许范围时明确提示，不隐式移动后续音符或部分提交。
- `_` 仍表示消费一个目标但不修改其内容；真实 gap 与同范围虚拟占位不得重复计数。

### 技术实现

新增共享纯函数（建议命名 `planNumberedSequenceOverwrite`），接收文档、稳定起点、解析后的输入项、明确的节奏策略和允许编辑边界，输出完整写入计划或可解释的失败原因。

规划步骤：

1. 复用现有输入范围计算，构造按 tick 排序的目标槽；每槽携带 startTick、endTick、rhythm、真实 eventId 或虚拟空位来源。
2. 默认从目标槽逐项取得时值。已有事件只替换内容，保留其 ID 和节奏；虚拟空位在实际应用时才物化为事件。
3. 按当前项实际时长推进到下一个音乐时间位置，不使用真实 events 的数组下标代替时间推进。连音槽必须保留实际比例及 endTick，不得按普通音符时长重新计算。
4. 显式调整时值时重新计算受影响窗口，只允许安全拆分/合并空白；不得覆盖未授权窗口内的后续真实内容，不移动后续 tick。
5. 预览、占用拍数、可用拍数、按钮可用性和最终提交消费同一个计划。前后阶段不得各自推导时值。
6. 一次应用作为一个原子命令提交，一次撤销恢复；规划失败则不修改文档。

气泡、侧栏和其他连续录入入口统一使用这套规划。当前文本变化只更新草稿，Enter 才应用；没有发现逐数字自动提交的证据，不应把自动提交当作已确认根因。需要回归首次应用后的再次编辑/应用：预览基于明确起点重新规划，焦点由同一规划结果返回，不得使用已经失效的目标窗口。稳定起点与待提交计划需随显式切换目标、撤销和文档变化失效，避免使用过期事件 ID。

核心固定范围 API 与自定义节奏模板保留现有独立语义。普通连续覆盖改用共享规划；如直接改变 sequence.set 会影响其他调用方，可新增混合填充命令承载该语义。已确认的 REQ-007～016 侧栏设计优先：覆盖默认允许、应用后留在原起点，高级范围 UI 的移除由该设计对应任务负责，本轮不扩大到整套侧栏重做。

保留 eventId 的同时需保留仍对应的 itemId，避免音符连接失效；显式重排遇到无法安全保留的歌词、连线或连音组时整笔拒绝，不猜测迁移、不静默清空。简谱 `_` 保持原槽全部属性及关联，虚拟 `_` 不物化；与歌词 `_` 的清空语义分别处理。

重点改动位置：NumberedEditor.tsx、numbered-commands.ts、简谱输入范围规划，以及相应的草稿预览和会话状态。保留 BUG-016 的双向空位时值继承；只有缺少可靠简谱目标时，才使用 TAB 推导默认窗口。

## 3. BUG-019：先区分真实空白和已有音符覆盖范围

### 建议交互口径

选中一个 TAB 位置后，先解析其对应的简谱时间范围：

1. 同 tick 有真实简谱事件：编辑该事件。
2. tick 位于已有简谱事件的内部，即 `startTick < tick < endTick`：定位并编辑覆盖它的事件，显示对应简谱的真实起点和时值。
3. 该位置属于真实空白：打开该空白范围的录入草稿，仅在应用成功后创建事件。
4. 位置或映射无效：显示明确原因，不生成假占位。

例如 TAB 位于第一拍的后半段，而简谱是覆盖整拍的四分音符，应定位到该四分音符。单击录入入口不应自动拆开已有音符。若产品后续需要“从这里拆分并录入”，应作为明确动作，单独定义原音符、歌词及连线的拆分规则。

### 技术实现

提供统一的目标解析函数，返回“同起点事件、覆盖事件、可编辑空白、不可编辑位置”四种结果；入口、草稿和提交前校验使用同一个结果。

打开编辑器只更新 UI 草稿，不写入占位事件。核心命令在应用前再次检查区间重叠和边界，防止文档变化后把旧的空白映射写入已经有内容的位置。

验收：点击后进入可输入状态；仅打开再取消不改变曲谱、不增加撤销记录；覆盖事件仍保留原 ID、歌词及连接关系。

## 4. BUG-018：延音横线改为拍点级状态

### 建议交互口径

- 同一时间位置只显示一个横线，与选中哪根弦无关；重复设置不增加内容和历史记录。
- 横线绘制在六线谱的垂直中心，水平锚定该音乐时间位置，不按某根弦定位。
- 延音横线没有符干、符尾、连梁或附点。
- 在 4/4 中固定占一拍，即四分音符、无附点；不会继承 BUG-016 的其他默认时值。
- “只能设置一次”解释为同一位置只能存在一个标记；不同拍可以连续设置。
- 横线与该拍的普通弦音符、休止符互斥；转换操作原子处理受影响的音符与技巧引用。

用户已确认：“一拍”按拍号分母单位计算，6/8 为八分音符，2/4、3/4、4/4 为四分音符。单位拍与连梁拍组分别处理。

### 技术实现

复核后采用保留 schema 8、保留 `fret: "-"` 编码的最小改动，不新增 beat.kind。通过共享分类区分纯横线拍和旧混合拍；新独立设置命令每拍只写一个横线 Note，其弦号仅为兼容编码，显示和选中均按拍点处理。键盘 `-`、气泡、工具栏、侧栏都映射到这一命令，不再按选中弦逐格增加横线。

节奏归一化必须在命令内完成：短拍变成单位拍时，只能消耗安全空位；长拍缩成单位拍时保留剩余可编辑空白；遇到后续真实内容、技巧或连音保护冲突时返回失败，不强行覆盖，不移动后续 tick。禁止直接复用会压缩后续节奏并重排 tick 的 changeMeasureBeatRhythm。保护检查覆盖技巧区间内部，不只检查端点。简谱、歌词及无关和弦标记保持原有内容。

布局层为 continuation 单独产生一个居中的横线图元和拍点命中区域；不进入普通 note 的符干/连梁分组。编辑 SVG、打印和图片导出共用同一布局与 scene 图元。

旧纯多弦横线可合并显示为一个居中标记，但加载和保存不迁移、不改时值或 ID；横线与数字、x 混存的旧拍保留原内容及兼容绘制。只有明确执行转换时才应用新的单位拍规则。纯横线从任意弦删除都清理该拍横线，录入数字或 x 原子替换纯横线；旧混合拍保持逐弦编辑。其他时值、附点、连音和技巧新建入口须保护纯横线语义，同时不能通过收紧加载校验导致旧文件打不开。原 ExtendBeat 逐弦 Tie 功能保持独立。

## 5. 实施顺序和验证

建议按以下顺序分批落地：

1. 用 BUG-017、BUG-020 的真实事件和虚拟占位分别建立复现；明确气泡/侧栏、首次/再次应用和节奏策略。
2. 统一目标解析和连续覆盖规划，修复 BUG-017、BUG-020；BUG-019 的入口复用同一解析结果。
3. 单独实现 BUG-018 的命令、数据与布局调整，更新 BUG-005 原先的逐弦横线测试。
4. 完成相关核心、网站交互和布局回归，再执行类型检查、lint 与浏览器验收。

必须覆盖的验收场景：

- 八分加两个十六分，输入三项，时值和目标 tick 都正确。
- 四个真实十六分，及由真实音符与虚拟占位组成的四个十六分，输入三项只覆盖前三槽。
- 附点、二分长音、三连音、拍尾和小节尾，不能意外改变其他事件或越界。
- 草稿从短文本增长为完整文本，以及首次/再次应用、撤销重做，不重复追加或漂移目标；覆盖 `_`、跨小节和 256 项限制。
- TAB tick 位于简谱长音内部时，不创建重叠占位；真正空白位置能输入，取消不写入数据。
- 同拍从任意弦设置延音都只生成一个居中标记，无符干；不同拍允许连续延音。
- 延音的安全拆分/合并、保护冲突、旧数据处理、文件与剪贴板往返。
- BUG-016 两方向首次输入仍正确继承时值，简谱、歌词和技巧引用不被意外改动。
- 编辑、打印、PNG 的横线位置及符干可见性一致。
