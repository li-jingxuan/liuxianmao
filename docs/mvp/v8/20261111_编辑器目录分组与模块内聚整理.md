# 编辑器目录分组与模块内聚整理

日期：2026-11-11。状态：目录实施及集成验证完成。

## 1. 目标与约束

在上一轮职责拆分之上整理源码目录，减少 `EditorShell`（122 个平铺文件）与 `core`（43 个平铺文件）的查找负担。同一业务的组件、状态逻辑、类型和 SCSS 就近放置；本轮仅整理位置与引用，不改命令、状态提交、渲染或交互语义。

保留当前工作树全部未提交成果，迁移以磁盘当前内容为准。核心包根导出及 Next.js 页面入口保持稳定，不新增 package，也不通过旧路径转发壳或多层 barrel 掩盖真实归属。

## 2. 目录策略

`EditorShell` 根保留 `index.tsx`、宿主样式及目录说明，按模块划分工作区布局、会话与交互协调、工具面板、谱面渲染、文件/图片输出、音乐文字侧栏、简谱、歌词、和弦、设置等子目录。模块内 TS/TSX/SCSS 同置；只有实际多消费者的表单样式放共享模块，不建立泛化 `utils` 或 `common` 杂物目录。

`core` 按文档加载与校验、命令编排、节奏、简谱、歌词、和弦、技巧分组。通用领域类型、常量及 ID 工厂可留根；跨领域主命令调度与具体领域命令区分归属。最终文件清单以依赖检查结果补入实施记录。

回溯同时发现 `layout` 有 39 个平铺文件，本轮按已有布局流程收拢结构排版、音乐文字、节奏几何、技巧几何；布局入口、类型和通用几何基础仍在根，禁止为了收拢而增加一层调度包装。

引用约定：包外仍从 `@liuxianmao/lxm-editor` 公共入口使用；包内和网站内部使用明确相对路径。业务实现不通过 `EditorShell/index` 反向获取能力，`session/EditorSession.tsx` 作为会话装配入口保留挂载宿主的已有依赖。更新静态导入、动态导入、测试 mock/alias、浏览器夹具和维护脚本中的源码路径；SCSS 的资源路径也必须核对。
