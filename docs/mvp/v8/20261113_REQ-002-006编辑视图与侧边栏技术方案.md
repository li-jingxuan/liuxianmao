## 3. REQ-002：谱面缩放

### 3.1 复用既有视图层

现有 `score/score-view.ts` 和 `use-score-view.ts` 已提供纸张缩放、真实滚动占位及视口中心锚点保持，生产界面暂未提供切换控件。直接将 `fit | actual` 改为四档数值，删除旧模式分支和相关调用，不保留兼容别名。

在 `score-view.ts` 定义 `SCORE_ZOOM_LEVELS = [100, 125, 150, 200] as const`，类型由该常量推导。`useScoreView` 持有 `zoom / setZoom`，默认 125；沿用 `sessionKey` 的重置时机，替换文档/会话后回到 125，普通编辑和撤销不重置。无需增加全局 store 或 localStorage。

`calculateScoreView` 保留现有内容换算和纸张基准，只将外层 `scale` 改为 `zoom / 100`：

```text
contentScale = (780 - 42 × 2) / A4_CONTENT_WIDTH  // 现有常量，不变
svgWidth / svgHeight = 原布局尺寸 × contentScale
baseWidth / baseHeight = 现有纸张与可见墨迹边界计算结果
stage.width / height = baseWidth / baseHeight × zoom / 100
paper.transform = scale(zoom / 100)
```

100% 对应产品既有基准纸宽 780px，正常基准下 125% 为 975px，不使用原型的 760px 演示纸宽。保留现有 `visibleWidth/visibleHeight` 对实际内容外延的计算，避免放大后底部或右侧裁切。

`buildLayout` 继续使用原 A4 逻辑宽度和 compact 参数；缩放不触发布局宽度变化、不改变每行小节数。SVG 内部尺寸、选区和编辑提示仍使用同一逻辑坐标，不分别乘倍率。

### 3.2 控件与事件

在 `index.tsx` 现有装配处增加一组 Button、Dropdown / Menu：减号和加号切换相邻档，百分比菜单列出四档并标记当前值，100% 禁用减号，200% 禁用加号。控件只读取 hook 的 `zoom` 并调用 `setZoom`，不新建控制器或单独组件文件。

控件采用横排，顺序为“−”、百分比、“＋”；百分比菜单向上展开。原有档位、禁用和键盘行为不变。

横排尺寸按紧凑稿实现：容器内边距 2px、按钮高 28px，减号/加号宽约 26px，百分比宽约 60px，文字与箭头间距 4px，整体约 118×34px。通过局部类收紧，不修改全局 Button 尺寸；菜单右边缘与控件对齐。

在 `index.tsx` 现有工作区 grid 的谱面列中，将控件作为 `[data-score-viewport]` 的**同级覆盖元素**，右下角留约 16px。不放进滚动内容、变换后的纸张或右侧面板，也不新增会改变 grid 结构的包裹层。局部样式使用 `grid-area: 1 / 3`、右下对齐，`pointer-events` 限定到控件本身，层级低于现有抽屉遮罩（20）。

这样点击缩放不会进入谱面 pointerdown 的清空选区/开始拖动处理。菜单与按键操作只改视图，不执行 `onAction`，不提交属性草稿、不写文档修订或历史。不得通过屏蔽整个工作区事件来保护缩放按钮。

百分比菜单复用组件自身的方向键与 Escape 关闭行为，关闭后焦点回到百分比按钮；不触发 SVG 的音符输入或取消选区处理。无须拦截编辑器所有快捷键，保留现有根节点历史快捷键。

### 3.3 滚动、命中与浮层

- 继续用 `stageStyle` 提供缩放后的真实占位、`paperStyle` 负责 `transform-origin: top left` 的纸张变换；仅加 transform 而不增大滚动范围是错误实现。
- `setZoom` 沿用 `captureScoreViewAnchor / restoreScoreViewAnchor`，保持视口中心对应的原纸张点；靠边时由滚动容器自然限制范围，不另建锚点状态机。
- 不把 zoom 加入现有选区自动露出 effect 的依赖，否则会在中心恢复后再次滚到选区，导致视图跳动。
- 指针从屏幕到谱面仍通过 SVG `getScreenCTM().inverse()` 换算。矩阵已包含纸张倍率，不能再手动除以 zoom。
- 定位谱面、歌词下一处和简谱/歌词气泡继续使用现有正向屏幕矩阵；不能将逻辑坐标直接作为 `scrollTop` 或气泡位置。
- 保留 `onGeometryChange` 的现有处理：取消进行中的拖动、清理过时悬停并通知浮层重新测量。缩放不清空稳定业务选区，也不重建输入表单或丢弃草稿。
- 复用 hook 中已有的容器测量和滚动监听，不再添加一层 ResizeObserver、缩放事件总线或坐标缓存。

### 3.4 输出隔离

倍率只传给编辑视图，不传入 `ScorePrintLayer`、成品分页、图片输出或文件序列化。打印层继续独立构建 A4 成品，缩放控件属于编辑 UI，打印时不出现。

本轮不改变纸张、字体、弦距、导出像素倍率或图片尺寸；编辑放大是把现有紧凑谱面放大供操作。

## 5. REQ-004：音符面板

### 5.1 按钮与布局

时值使用现有六种音乐符号按钮。附点由下拉改为三个按钮：无附点、附点、复附点。值仍映射现有 `dots = 0 | 1 | 2`。

音符状态使用三列等宽网格，列间距与附点行相同；每个按钮内部垂直排列符号和名称，统一图标容器高度、文本行高和按钮高度。不再将小按钮放在列左侧、名称单独放在列中央。

复用 `MusicAssetIcon` / 现有休止符与小节线图元，避免依赖 Unicode 音乐字符及新字体。复用局部 CSS Modules，不复制原型的整套全局样式。

新增或替换的符号按钮提供名称、选中态和键盘焦点；音符和连音的禁用原因沿用第 6 节的 Tooltip + 可聚焦 wrapper 方式，不为三处按钮组设计三套禁用机制。横线延音标记使用直横线，不能误用表示弧线的 `noteTie` 图标。

### 5.2 生效与可用性

- 时值、附点、x、延音标记、整拍休止都通过原有工具命令点击即提交，不新增“应用音符”按钮或本地音乐副本。
- 单拍可改时值和附点，同一拍允许选多根弦；多拍选区禁用这两组控件，提示“时值与附点需要单拍选区”。
- x 与延音标记作用于所选弦格；整拍休止作用于所选拍的全部弦音，名称提示明确影响范围。
- 选中状态从当前文档推导；混合值不伪装成某个确定值。操作是否可用同时遵循当前活动目标、草稿阻断和提交中状态。
- 时值与附点高亮继续读取现有 `inputRhythm`：显式 TAB 覆盖优先，否则使用 `tabInputRhythmFromNumbered`，最后退回 `beat.rhythm`。不能为简化按钮实现而直接改读 `beat.rhythm`，造成顶部工具与详情不同步。
- 不按按钮是否高亮提前跳过命令：已高亮的继承时值首次点击仍可能建立显式 TAB 时值，是有效修改。是否进入历史由现有命令结果的 `changed` 判定，真正的 noop 不新增历史。状态重复点击的语义以现有命令为准，不照搬原型自定义的“再次点击恢复”机制。

三个主状态按钮保持一行：全休止选区的第三个按钮显示“取消休止”，仍使用原 `restore` 动作；混合休止选区主按钮将整段设为休止，并保留已有“取消选区休止”作为按需出现的紧凑文字操作。取消休止不会恢复被清空的原音符，恢复原内容使用撤销。x、横线为设置动作，不增加切换回普通品位的本地缓存。

直接提交仍要经过现有命令校验；若原有结构影响确认需要弹出，继续沿用。按钮点击即提交不等于绕过原有音乐约束。例如修改已有连音组成员的单拍时值仍可能返回 `BEAT_IN_TUPLET`，不能拆组后自动重试。

### 5.3 删除范围

仅移除音符详情中参考图框出的延续一拍、编辑此拍和弦、演奏技巧、删除所选弦音符及长说明。其他位置使用的技巧参数面板、工具栏、键盘删除及撤销不因此删去。

保留既有小节拍号、段落标记、谱首反复等设置与草稿 owner；段落名称继续显式应用。本需求只压缩“小节线与反复”的右边界按钮及其提示，不重建小节表单。

## 7. REQ-006：连音面板与命名

### 7.1 名称与比例

比例值仍使用现有 `LXM_TUPLET_RATIOS`，不改文档结构或白名单。网站增加一个小型名称格式化函数，供连音详情、工具栏与当前选区摘要复用。

函数放在网站 `shared/tuplet-label.ts`，只接收 `{ actual, normal }` 并返回名称或解释文本，不读取 store、不执行命令、不建立注册表。由 `TupletToolbar`、`TupletToolDetails`、`sidebar-context`、`EditorImpactNotice` 直接引用，避免反馈组件依赖工具组件。`TupletToolbar` 只统一名称和 Tooltip，保留原本“应用某连音”的直接命令行为；本轮用户确认的“先选择再应用”作用于侧栏详情。当前选区摘要和操作反馈同步显示名称，避免刚应用三连音后反馈又只显示 3:2。

- `2:3` → 二连音。
- `3:2` → 三连音。
- `4:3` → 四连音。
- `5:4` → 五连音（5:4）。
- `5:3` → 五连音（5:3）。
- `6:4` → 六连音。

标题改为“连音类型”。六个按钮以三列两行展示，两种五连音的比例使用第二行较小文字，避免撑宽按钮。名称同时用于摘要、待应用提示和应用按钮，例如“应用三连音”。

Tooltip 根据比例解释：“3 个等时值音符，占原本 2 个音符的时间”；不可用时追加具体原因。操作反馈中的 `tuplets.structured` 显示相同中文名称，历史数据仍保存原比例。

六按钮改造只针对 `TabTupletToolDetails`。`TupletToolDetails` 的独立简谱分支及 `sidebar-context` 中的已有简谱当前组摘要可复用函数同步中文化，但保持原来的独立声部目标、编辑跳转和删除命令，不显示 TAB 比例按钮。不扩展到 `NumberedEditor` 完整表单。TAB 数字括号保持现状；简谱非 3:2 括号目前显示比例，属于另一个谱层，不在本轮调整。

### 7.2 当前值与待应用值

沿用 `TabTupletToolDetails` 现有选区 key 与局部状态，不新增 store。将现有 `choice.value` 改成可空的待选比例：初始化为 null，实际当前类型由 `range.group` 读取；按钮高亮使用“待选比例 ?? 当前比例”，不能把已有当前比例当作待应用草稿。

- 已应用摘要始终读取 `range.group`，不得从待选比例推导。
- 点按钮只设置待选比例，显示“待应用三连音”，不执行命令或创建撤销记录。
- 点击应用才调用 `SetTuplet`；提交中锁定重复操作。
- `applied` / `noop` 后显式清理待应用提示，摘要从文档读取；noop 不替换文档，因此不能只依赖文档变化清理。失败、取消、目标过期时不显示成功。
- 选区 key 改变时重置待选值；文档变化使待选条件失效时清理待选值。切换同一目标的显示区域不应制造另一份待选状态。
- 点击当前已应用类型允许形成有效的同值选择，命令返回 noop 时不产生新历史；无需另做复杂去重流程。

保留既有 `busy`、`lock` 与命令适配器，不新建异步任务层。按钮可用性和错误提示从当前目标计算，不能使用旧选区的成员数去解锁新选区。

提交时捕获当前选区 key 和待选值；异步返回只清理仍属于本次提交 key/值的待选状态，不覆盖用户后来切换目标后的状态。失败或取消且目标仍有效时保留待选值方便重试，失效目标由同一可用性检查清理。

### 7.3 可用性与错误

六个类型全部可见。`range === null` 时统一提示“请选择同小节内的连续拍点”，不新增解析层来区分跨小节与失效目标。范围合法后再区分成员数不符、书写时值/附点不同、部分重叠或嵌套。成员数使用 `range.beatIds.length`，同一拍选择多根弦不能算多个连音成员。

展示层只做这些轻量检查，不复制核心时间轴推演。整数 tick、小节容量及其余音乐约束仍由 `SetTuplet` / `RemoveTuplet` 最终处理，错误使用原有反馈区域显示。

允许对完全相同成员的已有组修改比例；与其他组部分重叠时要求先移除原组。禁用原因尽量指向可执行动作，不把完整规则说明重新铺成段落。

### 7.4 删除当前组

继续调用 `RemoveTuplet`，不直接修改 `measure.tuplets`。移除比例会改变成员的实际占时，并触发既有小节时间轴整理；例如移除三连音后可能超过小节容量，核心可以拒绝。

成功删除只移除连音关系，保留音乐内容并按核心规则调整时间轴；失败时保留原组和原谱，显示原有原因。一条成功命令作为一个撤销步骤。删除按钮只在当前选区解析到完整现有组时可用。

删除参考图中的两段常驻长说明；保留当前组摘要、类型按钮、应用和删除动作。
