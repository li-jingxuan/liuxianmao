## 1. 问题与目标

当前简谱和歌词编辑集中在右侧“段落”面板。编辑时需要反复在谱面和侧栏之间移动视线；侧栏收起、屏幕变窄或当前选中位置离侧栏较远时，录入上下文不够直接。

用户提供的参考图展示了贴近谱面的录入浮窗：位置标题、主要输入框、简谱录入时值、节奏型、数量和占用时长预览，以及取消/应用按钮。本方案采用这种信息层级，为简谱和歌词提供独立于侧栏展开状态的主要编辑入口。

目标：点击谱面即可在附近编辑；保持谱面可见、允许切换目标；已有能力、草稿保护、影响确认和撤销继续有效。右侧保留歌曲、和弦、TAB 属性及段落入口，简谱和歌词常用编辑不再要求打开侧栏。

## 2. 建议决策与范围

以下为用户已确认的实现范围；后续补充指令明确仅考虑 PC 端。

| 事项           | 建议                                                                           |
| -------------- | ------------------------------------------------------------------------------ |
| 浮窗形式       | 非模态浮窗，无遮罩；同时最多一个简谱/歌词编辑浮窗                              |
| 打开方式       | 点击简谱事件、简谱空位、已有歌词或歌词占位即打开；再次点击同一目标只定位原输入 |
| 所在位置       | 首次打开靠近目标，优先在其下方；可拖动标题，提供“回到选中位置”                 |
| 侧栏关系       | 简谱/歌词页签保留入口、位置和草稿摘要，表单统一迁入浮窗                        |
| 常用与高级能力 | 高频控件直接展示；低频能力在浮窗内折叠展开，避免必须回侧栏完成                 |
| 提交方式       | 显式应用；应用成功保持浮窗打开，不在每次键入或失焦时写入文档                   |
| 范围与冲突     | 复用核心规划与整批校验；不静默覆盖、不静默截断输入                             |
| PC 端窄窗口    | 保持桌面浮窗，在可用视口内重新定位和滚动；本期不做移动端底部面板               |

本期包含 PC 端简谱已有内容编辑、空位连续录入、歌词单点与连续编辑、必要的高级能力迁入、入口与定位、草稿和输出集成。不扩展移动端响应式、自由多窗口、跨设备保存窗口位置或跨小节连续创建简谱，也不修改文件 schema、音乐规则、TAB 和和弦编辑方式。

![用户提供的简谱与歌词浮窗编辑参考图](./references/简谱与歌词浮窗编辑参考图.jpg)

该图作为浮窗外观、信息层级和常用控件布局的实现参考。歌词浮窗及图片未展示的状态沿用本文定义；本文中的文字结构示例只说明功能组织，不作为另一套视觉设计稿。

保留参考图的四层结构：标题和位置、主输入、录入选项、结果预览和动作。原图宽度只作视觉参考，实际浮窗必须适应谱面可用空间。

浮窗的信息优先级按“当前任务能否立即完成”排序：

1. **第一层：身份和目标。** 当前编辑类型、单点/连续模式、歌词段号、简谱事件或空白范围、小节/拍点，以及目标是否仍有效。用户必须先知道“正在改什么”。
2. **第二层：高频输入和关键选项。** 简谱正文、歌词正文、录入时值、节奏型、歌词录入模式、段号和覆盖开关。它们必须在浮窗打开后无需展开即可操作。
3. **第三层：即时结果。** 将创建/修改多少事件或歌词位置、总时长、剩余空白、覆盖数量、下一位置和错误原因。结果应随输入和选项实时更新，不能只在点击应用后才揭示。
4. **第四层：提交动作。** 应用、取消、应用并到下一位置、回到目标。动作区固定在窗口底部，错误时仍可见但应用按钮禁用并带有原因。
5. **第五层：低频能力。** 单音符音高、八度、连接记号、删除/清空、范围复制粘贴、固定范围替换和复杂连音比例放入高级区；高级区展示当前是否有未应用分组，不隐藏脏状态。

信息分层的判断标准是使用频率和当前任务依赖，而不是控件属于哪个旧侧栏分组。即使是低频操作，只要它是当前错误的解决入口，也应在错误摘要下提供直接展开入口；反之，不能为了“完整”把所有按钮常驻在浮窗中。

```text
简谱 · 连续录入      第 1 小节 · 第 1 拍       定位  ×
[ 1 2 3 5                                      ]
录入时值  全 二 四 八 十六 三十二  附点   节奏型
将创建 4 个八分音符，占 2 拍
可录入范围：第 1 拍～第 3 拍          取消  应用
高级选项 ▸
```

```text
歌词 · 第 1 段       第 1 小节 · 第 1 拍       定位  ×
录入方式：单点 / 连续                  段号 1～4
[ 轻 轻 唱 起                                  ]
对应位置预览 ▸                  允许覆盖已有歌词
将写入 4 个位置；覆盖 0 处           取消  应用
```

两处语义调整：

1. 简谱“录入时值”只在创建空位内容时命名如此。已有事件的内容编辑显示“当前音符时值”，修改走现有独立时值流程，不能把录入偏好误认为已修改事件。
2. 原图“遇到已有音符停止”改为“仅填入当前空白范围，超出时请调整输入”。若输入超过边界，整批拒绝并明确可用时长；不把一段输入偷偷拆成成功和失败两部分。当前支持的“部分填入”指输入可以少于空位容量、留下剩余空位。

参考图中的节奏型下拉映射现有均分、三连音、自定义成员时值及连音比例能力。默认均分，复杂设置进入高级选项；不为了复刻截图额外创造一套节奏解析。

参考图中“将创建 4 个八分音符，占 2 拍”还应补充两项高频反馈：

- `可用范围`：当前窗口起止位置、已占用时长和剩余可录入时长；输入为空时也显示，帮助用户选择时值。
- `应用后位置`：成功后将停留在当前事件、剩余空白或核心返回的下一个位置；没有下一个位置时明确提示，不把焦点悄悄移到其他小节。

这两项是决定用户能否放心点击“应用”的信息，优先级高于任何高级属性。

## 4. 用户操作与焦点

### 4.1 打开和选择

- 点击简谱事件：打开“修改简谱”，读取该事件内容；同时多音继续使用现有语法。点击具体成员时保留 `itemId`。
- 点击简谱空位：打开“连续录入”，显示准确的时间窗及会话录入偏好。
- 点击歌词或歌词占位：打开歌词浮窗，带入段号和真实歌词位置。无需先有简谱音高，现有空事件和空白时间窗仍可作为歌词入口。
- 侧栏“添加歌词行”“添加简谱行”、草稿列表及“返回编辑”统一打开同一浮窗。添加行仍只选择合法目标，首次应用前不写入假音乐数据。
- 浮窗打开后可继续点击谱面。目标切换先经过现有草稿闸门；被拦截时，当前选择、窗口标题、输入内容和位置均不提前切换。
- 同一目标重复点击不重新初始化草稿；简谱 A/B 目标的草稿暂存继续有效。歌词换目标继续使用现有应用/放弃/继续编辑规则。
- 点击窗口外的空白不关闭、不提交；点击 TAB 或和弦时按原目标切换规则处理。干净编辑可退出，脏编辑先保护草稿。

### 4.2 简谱应用

| 场景                             | 应用与后续行为                                                                    |
| -------------------------------- | --------------------------------------------------------------------------------- |
| 已有事件改内容                   | 使用既有事件修改命令；保留时值，成功后停在该事件                                  |
| 空位录入                         | 使用 `numbered.sequence.insert`，按当前成员时值规划，成功后接受核心返回的下一焦点 |
| 空位仍有剩余                     | 标题和空窗范围更新，成功提交的输入清空，继续沿用会话时值偏好                      |
| 到达已有事件                     | 显示该事件及“修改简谱”状态，读取其内容；不得自动把上一段输入应用到此事件          |
| 当前小节已无后续焦点             | 保持可解释的已提交状态，提示“本小节录入完成，请选择下一位置”；不私自跨小节创建    |
| 延长影响后续事件或记号           | 使用现有预览和确认；取消保持原草稿，确认成功才更新目标与分组基线                  |
| 超出窗口、已有内容冲突或非法语法 | 整批零写入，保留输入、显示原因和可用范围                                          |

`nextNumberedFocus` 可能是事件、空窗或当前事件的回退焦点，不能统一当作“下一拍”。提交后需根据结果和当前文档解析状态；不得只根据输入个数自行推进 tick。

“高级选项”承载现有固定范围替换、覆盖许可、拆合、成员音高、连音、记号、范围复制/粘贴等能力。高级动作保持现有作用范围和各自提交按钮；主按钮仅应用正文内容，不代替“应用当前音符时值”“应用单音符音高”等动作。

简谱现有 `content/rhythm/itemPitch` 独立分组及依赖保护继续有效。多个分组有修改时，不用一个“应用”暗中逐组提交。会互相影响的操作按现有保护要求先处理依赖草稿。

浮窗主按钮和 Ctrl/Cmd+Enter 明确调用正文分组的 `applyGroup("content")`，正文无修改时不转而提交唯一的时值或音高草稿。已有事件的时值控件显示独立的“应用时值”动作和未应用状态；空位的“录入时值”属于正文创建配置，随本次正文一起提交。顶部工具仍沿用已有命令与草稿依赖检查，不能绕开浮窗中尚未处理的分组。

### 4.3 歌词应用

- 单点编辑保留“应用”“应用并到下一位置”；段号沿用 1～4。
- 连续录入保留现有分隔语法、预览映射、跳过规则、允许覆盖和整批校验。默认覆盖行为沿用现有歌词设置，不与简谱覆盖开关混为一项。
- 下一位置来自 `planLyricPositions` 及现有歌词导航，包含 notes、保留时值的 gap 和未录入的时间窗，跳过休止；可按既有规则跨小节。
- 歌词保存仍引用 `eventId`。空白位置的首次写入继续由现有命令创建/解析保留时值的空事件；浮窗不自行制造 TAB Beat 或预先创建事件。
- 连续提交后的定位沿用现有歌词提交结果；本期不额外承诺新的自动跨段或跨轨录入规则。
- 预览展示原词、拟写入文本、位置、覆盖及错误；越界时保留预览和输入，整批拒绝。

歌词浮窗的高频信息与简谱不同：单点模式优先显示当前歌词、原词和“下一歌词位置”；连续模式优先显示分隔后的文本、对应位置预览、覆盖数量和可覆盖开关。两种模式都必须固定显示段号和目标位置，不把段号只放进高级区。歌词浮窗不显示与当前操作无关的音高、时值和技巧字段。

### 4.4 取消、关闭与恢复

“取消”和右上角关闭作用一致：请求结束当前编辑；干净时直接关闭，存在未提交内容时展示应用/放弃/继续编辑。不能通过外部点击、Esc、拖动或缩放绕开草稿保护。

关闭确认只处理当前目标：单个脏分组时，“应用并关闭”提交该分组；多个脏分组时，不显示含糊的统一“应用”，改为列出未处理分组，并提供“返回处理”“放弃当前目标修改并关闭”。返回处理会取消这次关闭请求，逐组处理后由用户再次关闭，避免处理过程中自动关闭窗口。放弃范围仅为当前目标全部未应用分组，不包含其他目标的暂存草稿。提交失败、预览取消或候选过期时保持窗口和草稿，不继续执行关闭请求。

关闭或输出后从草稿列表返回时，需重新打开浮窗并定位具体分组。其他目标的暂存草稿继续保留，侧栏摘要显示待处理数量；即使浮窗已关闭，也可以从输出阻断提示或侧栏返回。

应用成功默认不关窗。只有明确结束当前编辑，才解除对应的输入活动状态；已隐藏的暂存草稿仍由协调器阻断输出。

### 4.5 清空与删除

沿用当前核心语义，不在浮窗迁移时改变结果：

| 动作                         | 简谱与歌词结果                                                                  |
| ---------------------------- | ------------------------------------------------------------------------------- |
| 清空已有简谱事件的正文并应用 | 保留事件 ID、起点和时值，成为空事件 `gap`，原歌词保留；不是休止，也不是删除事件 |
| 删除普通简谱事件             | 移除事件，同时移除该事件所有段号的歌词；相关记号按既有规划处理                  |
| 删除连音组内的简谱成员       | 保留该成员的时值和身份，转换为 `gap`，歌词保留，维持连音组结构                  |
| 删除当前段歌词               | 只删除该段歌词记录，简谱音符或 gap 保留，包括首次填词创建的 gap                 |
| 歌词正文留空后应用           | 按现有校验拒绝，使用独立“删除歌词”动作删除，不把空输入当删除                    |

动作文案需显示实际后果，例如“清空音高，保留时值与歌词”“删除音符及其全部歌词”；连音成员则说明保留空位置。删除依赖、未提交草稿与连接记号影响继续经过原有保护，不自动清掉其他目标的输入。

## 5. PC 窗口位置

桌面初始建议宽度 560px，上限 680px，实际宽度不超过可用视口减去两侧各 12px。展开复杂选项可增加高度，窗口高度上限为可视区域减去上下各 12px，正文内部滚动，标题与动作区始终可达。

定位以布局提供的真实事件/歌词/占位 bounds 为锚点，经 SVG 屏幕变换得到 CSS 像素坐标。以当前谱面可见编辑区和 `visualViewport` 的交集为可用区域，避开固定顶栏及展开的侧栏。

定位顺序：目标下方 → 上方 → 视口内可放置的位置。优先避开活动音符/歌词及其焦点框；空间不足时保持 PC 浮窗并使用内部滚动。不承诺同时避开整张谱面的所有内容。

| 变化                            | 行为                                                                             |
| ------------------------------- | -------------------------------------------------------------------------------- |
| 未拖动时切换目标                | 新目标接受后重新定位；连写只在窗口越界或遮住新目标时移动，避免逐字跳窗           |
| 用户拖动标题                    | 当前打开周期内保持手动位置，并限制窗口不越出可视范围                             |
| 回到选中位置                    | 清除手动位置，按当前有效目标重新定位                                             |
| 谱面滚动、缩放、侧栏宽度变化    | 更新锚点和边界；浮窗稳定显示，手动位置仍执行边界约束                             |
| 目标滚出屏幕                    | 浮窗留在可视区域，提示“编辑位置在可视区域外”，提供返回位置；不每次滚动都强制回滚 |
| 目标不存在或空窗已被占用        | 清除失效目标并提示重新选择，不迁移到碰巧同位置的其他事件                         |
| PC 可用宽度或高度不足以放置窗口 | 限制浮窗尺寸并在正文内部滚动，保持同一编辑实例，不实现移动端面板                 |

拖动仅从标题的明确拖动区域开始，输入框选字和按钮操作不触发拖动。MVP 不提供自由缩放窗口；“回到选中位置”和关闭均可用键盘访问，无法拖动的用户仍能完成录入。

## 6. 键盘、输入法与弹层

浮窗使用有可访问名称的 `role="dialog"`，`aria-modal="false"`，不启用遮罩、不锁背景滚动，也不使用模态 Tab 循环。Tab 按自然顺序访问窗口控件，提供“回到谱面”动作。默认打开后聚焦主输入；返回原草稿时优先恢复原控件和文本选择。

| 操作                        | 规则                                                                     |
| --------------------------- | ------------------------------------------------------------------------ |
| 歌词单点 Enter              | 应用并到下一歌词位置，沿用既有行为                                       |
| 歌词单点 Shift+Enter        | 仅应用当前内容                                                           |
| 简谱/连续歌词多行输入 Enter | 保留文本输入行为，不在本期改写现有快捷键                                 |
| Ctrl/Cmd+Enter              | 新增明确的“应用当前正文”快捷键；与主按钮共用提交入口，不自动应用其他分组 |
| Esc                         | 下拉/候选等最内层优先；其后按关闭请求处理，不连续冒泡到谱面或底层窗口    |
| 输入框内 Ctrl/Cmd+Z         | 交给文本编辑，不触发曲谱历史撤销                                         |
| 数字、删除、方向键          | 在文本控件内不穿透为 TAB 或简谱音乐命令                                  |

中文输入继续检测 composition、`isComposing`、`keyCode === 229` 及现有结束保护窗口。选词 Enter/Esc 不提交、不关闭；组合输入期间不切目标、不卸载输入节点。真实操作系统输入法需人工验收，合成事件不能替代。

结构影响确认、导出阻断确认等保持真正的模态行为。打开时暂停浮窗交互，输入和原草稿保留；关闭后恢复发起控件。简谱影响确认当前有独立原生 dialog 和异步提交锁，本期保留唯一提交链，不同时再走一套 ModalHost 确认。

Select、Tooltip 等浮层必须使用约定的弹出容器与层级：高于编辑浮窗、低于真正的 Modal，不能被正文的滚动裁切。Portal 弹出内容视为浮窗内部交互，不触发背景目标切换或关闭。Esc 先关闭下拉，再由下一次 Esc 请求关闭编辑；Modal 出现后，浮窗及其遗留弹出内容均不能继续响应输入。DOM ID、label、`aria-controls` 以及“返回编辑”的查询不能再硬编码依赖原侧栏容器。

浮窗本身不占用一次性 `EditorModalHost` 请求。连续应用会改变文档版本，不能把整个编辑周期绑定到打开时的文档版本；版本检查应在每次预览/提交/确认边界执行。

### 7.2 推荐切分

建议新增常驻的 `MusicTextEditorHost` 和纯呈现的 `MusicTextFloatingPanel`，具体文件名可在实施时微调：

1. **编辑模块**：保留唯一目标、草稿和提交 owner。`MusicTextEditorHost` 承接原 Sidebar 的文字编辑协调，`NumberedEditor` 继续持有当前目标的简谱分组状态，不新增平行的浮窗草稿。
2. **浮窗壳**：只接收标题、锚点、可见状态、关闭请求及表单内容，管理窗口位置与尺寸，不读取/写入音乐文档、不拼领域命令。
3. **侧栏入口**：显示目标、草稿摘要和“打开编辑浮窗”，调用现有 controller，不渲染第二份歌词或简谱表单。

界面对外沿用现有 `open/select/isBlocking` 等 controller 语义，关闭、返回谱面和恢复编辑也经同一模块处理。避免再加一个需要调用方手工同步草稿、选择和窗口状态的全局 store。

共同切换仲裁只保留一处。歌曲设置虽仍显示在侧栏，其 `ScoreSettings` controller、组合输入状态、dirty、apply/discard 必须接入同一个仲裁；和弦草稿也沿用原保护。仅向草稿协调器登记并不足以代替 `request()` 的切换检查。歌曲设置尚未应用时点击谱面，不能绕过设置保护直接激活浮窗；浮窗有草稿时切入歌曲设置同理。

PC 端不同可用宽度下只改变同一浮窗壳的 CSS 定位、宽度和内部滚动；本期不切换为移动底部面板，也不能将表单在两个 React 父节点之间切换而触发重挂载。浮窗关闭后是否隐藏内容，由 owner 在草稿已处理后决定；任何条件卸载都必须先结算待确认 Promise。侧栏折叠不卸载编辑 owner。

这里的实例稳定指同一业务目标下的布局、断点、侧栏与浮窗呈现变化。简谱 A/B 目标之间仍允许沿用目标 key 重挂载当前编辑器，并从受版本和依赖保护的 `savedDraft` 恢复状态；常驻 Host 及暂存目录保持稳定，同时只有一个活动表单。不能只更新 target props 却继续使用前一目标的 `useState` 初始化值。

不要仅把旧侧栏整块搬入 portal：必须同步迁移 `onKeyDown`、composition、焦点恢复、草稿登记和输出阻断等原先挂在侧栏 DOM 上的处理。Portal 的 React 事件会沿组件树冒泡，需明确拦截拖动和谱面 pointer/keyboard 路径。

### 7.3 关键不变量

- 草稿身份继续使用简谱 `eventId/itemId` 或明确的 `tick/endTick`，歌词使用其真实事件或空窗位置及段号；不用 TAB `beatId` 作为新浮窗身份。
- 简谱与 TAB 独立时值、共享时间轴的约束不变，歌词继续跟随简谱事件。
- 打开、移动、折叠、定位和关闭干净窗口均不修改曲谱、不产生撤销记录。
- 一次成功音乐操作仍对应一次可撤销提交；确认前、取消确认及失败时零写入。
- 每次提交按最新文档重验目标。确认期间的文档变化使该次候选失效，不沿用陈旧候选写回。
- 自身提交按现有 `committing` 与分组基线机制保留其他草稿；外部替换/撤销/重做按现有规则校验或清除失效目标。
- 当前输入活动状态及所有暂存草稿继续参与 `isOutputBlocked`。干净关闭释放当前输入锁；脏草稿不能靠隐藏浮窗绕过导出保护。
- 图像/文件输出不包含浮窗、草稿文字或窗口位置；定位参数只属于会话 UI，不持久化至文档。

### 7.4 高频信息与高级信息的界面契约

浮窗必须满足以下界面契约：

- 打开后 1 个视线区域内能看见目标、正文输入、当前关键选项、结果摘要和应用动作；不要求先打开侧栏或高级区。
- 任何会改变结果的高频选项必须立即刷新摘要：简谱时值/节奏型、歌词模式/段号/覆盖开关都属于此类。
- 当前目标、剩余范围、覆盖数量和错误不可只通过颜色表达；必须有文字或可访问名称。
- 高级区折叠时仍显示脏分组徽标或“有未应用修改”，关闭和输出不能因为折叠而丢失保护。
- “应用”只提交当前正文分组；其他分组的修改状态在摘要或高级区明确可见，不通过一个按钮隐式批量提交。
- 简谱和歌词不强行共享相同字段布局：共享浮窗壳、标题、位置、预览和动作区，正文及高频选项按任务分别设计。

### 7.5 提交有效性与草稿恢复接口

所有提交入口，包括按钮、快捷键、分组应用、关闭确认和输出草稿处理，使用同一有效性检查。一次候选至少绑定：当前文档/会话版本、目标身份、编辑打开代次、该次输入与相关配置的代次。目标不变、文档未变也不能复用已经失效的输入候选。

实际输入或相关配置改变、目标切换、关闭后重开、会话替换都使对应的旧候选失效；普通重渲染、相同输入的草稿重新登记、滚动和拖动不使它失效。`isCurrent` 不能在普通按钮或关闭提交中默认为恒真。若先前的导航/关闭请求已取消，不得在异步结果到达后再次执行它。应用成功更新分组基线后再接收核心焦点，并保留未参与本次提交的合法草稿。

草稿恢复请求在原目标身份之外携带可选的分组与控件定位信息：`content`、`rhythm` 或 `itemPitch`。恢复顺序为验证目标和快照 → 打开浮窗 → 展开对应区域 → DOM 提交后聚焦控件；同一有效输入可恢复光标/选区。多个分组并存而未指定时，优先恢复上次活动的脏分组，缺省按正文、时值、音高顺序定位首个脏分组，并展示其余未处理项。目标或成员已失效时显示原因，禁用提交，不把草稿套到其他对象。

现有 `NumberedEditor.apply()` 会应用唯一的脏分组，`focus()` 主要定位正文；这两点不能直接满足上述正文按钮和分组恢复约定。实施阶段 A 必须分别补齐明确的分组提交与恢复接口，再迁移呈现。现有 `numbered-submission` 的版本/`isCurrent` 和协调器 `inputKey` 可复用，不能再建立另一套提交器。

## 8. 实施顺序

### 阶段 A：编辑模块与呈现接口

先提取常驻 owner，保留当前行为，通过现有草稿、命令、歌词和选择测试。明确正文应用、分组应用、目标切换、关闭请求和输出返回的单一入口，再接浮窗壳。以真实 controller/request 接口检验草稿不会因侧栏收起或呈现改变而丢失。

### 阶段 B：简谱浮窗

完成已有事件和空位两种上下文、常用时值、数量/占用预览、错误和提交终态。迁移高级区域并验证每个原有动作仍可从窗内到达，确认流程只有一条。补齐同目标重复点击、A/B 暂存和下一焦点回归。

### 阶段 C：歌词浮窗

接入单点、连续、段号、覆盖许可、映射预览、空白目标落盘与下一位置。完成简谱与歌词互切保护，以及从内容行和输出草稿目录返回。

### 阶段 D：窗口与交互集成

接入真实 bounds 定位、拖动、回到位置、PC 滚动缩放、事件隔离、IME 和模态暂停。侧栏简谱/歌词页签改为入口和摘要，其他侧栏能力保留；不实现移动端底部面板、软键盘和移动响应式。

### 阶段 E：验收

执行相关回归和全仓检查；用真实点击、输入、下载和撤销核对音乐结果。完成后仅勾选已完成的 Steps，并在文末追加实际结果，不提前标为完成。

## 11. 本轮补充审查

根据用户参考图和现有实现再次检查，本方案补充以下约束：

1. **浮窗不是第二个编辑器。** `MusicTextEditorHost`、简谱编辑器和草稿协调器仍是唯一编辑 owner；浮窗只负责呈现。PC 侧栏状态变化、滚动和缩放不能创建第二份草稿。
2. **共同切换仲裁必须覆盖歌曲设置。** 歌曲设置虽然继续显示在侧栏，但其 dirty、IME、应用/放弃和焦点恢复必须与歌词、简谱、和弦共用同一目标切换闸门。点击谱面不能绕过未提交的歌曲设置，浮窗脏时也不能直接切入歌曲设置。
3. **同目标与不同目标的实例规则不同。** 同一业务目标在断点、呈现位置或侧栏状态变化时保持输入实例；简谱 A/B 目标切换可按现有目标 key 切换活动表单，并从版本保护的快照恢复，不能只更新 props 后沿用旧目标的 `useState`。
4. **非模态不等于无保护。** 窗口外点击可以请求切换，但必须先经过草稿闸门；窗口内 pointer、拖动、输入、IME 和键盘事件不能穿透到谱面。结构影响确认和输出阻断仍使用真正的 Modal。
5. **预览不允许变成第二套音乐算法。** 数量、总时长、覆盖、歌词位置和错误均来自现有 core planner；UI 只呈现结果。越界的简谱/歌词批次整批拒绝，输入和映射保留。
6. **定位状态属于会话。** 锚点、拖动位置、展开状态、当前浮窗模式不进入文档、撤销历史、原生文件或 PNG；目标失效时清除目标，不按相同 tick 猜测新对象。
7. **设计验收需要覆盖 PC 真实输入。** 除桌面 Chrome 外，至少验证 PC 端 200% 缩放、窄窗口、滚动定位、中文 IME、Esc/Enter/文本撤销、输出阻断返回和控制台错误；移动端底部面板、软键盘和移动端响应式不属于本期；合成输入事件不能替代真实 IME 验收。

后续如调整触发方式、关闭语义、歌曲设置仲裁、目标实例规则或跨小节录入范围，应先同步本文。

## 12. 实施记录

- 继续由 `MusicTextSidebar` 作为常驻唯一 owner；同一个表单 DOM 在侧栏与 PC 浮窗呈现之间保持稳定，侧栏仅提供入口与摘要，没有第二份歌词/简谱表单。
- `use-music-text-floating-panel` 管理拖动、边界和滚动定位；通过 SVG `getScreenCTM()` 与当前目标直接计算锚点，避免父组件目标同步延迟。手动位置保持到本次窗口关闭；连续提交保留位置，主动换目标重新定位。
- 简谱主按钮及 Ctrl/Cmd+Enter 仅应用正文；关闭确认仍使用明确的单脏分组提交。高级区显示分组脏状态，草稿恢复展开并聚焦对应分组。候选绑定输入代次和存活状态。
- 歌词常驻模式、段号、正文、覆盖开关与结果摘要；映射表和删除动作折叠。单点模式显示下一歌词位置。
- 核心命令、schema、撤销和文件输出格式均未改变。保留原有高级工具与独立影响确认。
- 自动化覆盖几何边界、歌曲设置 IME 结束保护及既有草稿/提交/歌词回归；桌面 Chrome 另验证拖动、应用/撤销、关闭保护、时值与正文隔离、歌曲设置仲裁、PC 窗口变化保持输入 DOM。
