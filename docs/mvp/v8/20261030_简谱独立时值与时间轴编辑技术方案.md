# 简谱独立时值、占位与多层对齐技术方案

状态：已批准，已实现并通过回归验收。用户已确认完整方案及提交、推送要求。

本轮修订：根据用户补充，长时值改短时值采用“保留原音，在后方生成可录入占位”的规则，替换上一稿统一前移后续音符的建议；短时值改长时值参考 TAB 的容量处理。已确认现有歌词全部迁移为跟随简谱事件，不保留六线谱歌词绑定兼容模式。

## 1. 问题与目标

目前简谱时值设置入口较深，且录入模板时值、已有音符时值和谱面更新之间的关系不直观。更关键的是，六线谱修改时值会重新计算后续 Beat 的 tick，简谱修改时值则保持后续事件的位置，缩短后留下空白。

用户的典型需求：在 4/4 小节中，把一个四分音符改成两个可以分别编辑音高的八分音符，谱面正确显示减时线，剩余三拍保持原来的音乐位置。

本方案建议同时解决三个问题：

1. 共用顶部时值和附点工具，根据当前谱面选中对象操作对应声部。
2. 简谱缩短时释放就地占位，延长时处理后续位置及小节容量，录入按自身时值计算位置。
3. 占位可直接录入第二个独立音符；歌词统一跟随简谱事件。

简谱与六线谱继续共用小节、拍号和时间网格，各自保存音符及其时值。修改一层时不自动修改另一层音符、和弦或拍号；联合布局可以调整间距。歌词统一绑定简谱事件，跟随简谱事件的 tick 和 ID 移动。

## 2. 已核实的现状

| 位置                                                       | 现有行为                                                                                       | 对本次需求的影响                             |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | -------------------------------------------- |
| `packages/lxm-editor/src/core/types.ts`                    | 小节有独立的 `numberedVoice`；简谱事件自带 `tick/rhythm`                                       | 不需要为独立时值重做存储结构                 |

| 同上                                                       | 创建模板默认四分音符；半拍空白的事件时值推导与模板默认值未统一                                 | 半拍空位仍可能遇到模板时长与窗口不匹配       |
| `apps/website/components/EditorShell/EditorToolbar.tsx`    | 顶部时值按钮读取 TAB 选区；简谱编辑状态还会禁用此入口                                          | 需要一起修改目标解析、可用状态和选中态       |
| `packages/lxm-editor/src/layout/numbered-rhythm-layout.ts` | 已生成减时线、延时线和时值附点                                                                 | 正确提交后应体现时值；仍须做浏览器交互验证   |

已运行现有回归用例“**四分缩成八分后只生成一个后方半拍空位，命中和焦点使用同一时间窗**”，结果通过。这证明当前核心行为是保留空位，不能据此认定用户浏览器中的操作链路正常。

独立时值的粒度是一个简谱事件。同一事件中同时发声的多个音共享时值；本方案不扩展为同一音组内多个独立节奏声部。

歌词当前只有 `beatId`、`verse` 和 `text` 等字段，绑定 TAB Beat，没有简谱事件引用。`core/types.ts` 的 `ILXMLyric` 定义了这一关系，`layout/time-grid-spacing.ts` 也从对应 TAB Beat 取歌词 tick。因此需要把歌词锚点从 TAB Beat 改为简谱事件；这不是只调整显示坐标，而是数据模型和全部歌词操作链路的变更。

## 3. 建议的交互规则

### 3.1 顶部工具跟随实际选中对象

| 当前对象                         | 时值、附点按钮的行为                                     |
| -------------------------------- | -------------------------------------------------------- |
| TAB 拍点                         | 读取、修改该 Beat 的时值，沿用现有 TAB 规则              |
| 已有简谱音符                     | 读取事件时值，缩短生成就地占位，延长按简谱容量规则处理   |
| 简谱空白录入位置                 | 设置接下来录入简谱的时值偏好；选择时值本身不创建音乐事件 |
| 歌词、和弦、无有效对象或确认弹层 | 禁用时值修改，并显示具体原因                             |

以谱面当前活动对象为准，不能仅因侧栏停留在“简谱”页签就决定目标，也不能回退到残留的 TAB 选区。工具栏显示“简谱时值”或“六线谱时值”，按钮回显对应对象的时值及附点。

简谱的下一次录入时值单独保存为会话偏好，和 TAB 分离，不进入音乐文档或撤销历史。新会话默认四分音符；首次进入较短空位时，可以按可容纳的时值初始化。用户已明确选择的时值放不进空位时，提示重新选择，不能静默改值。

已有简谱音符点击时值按钮后直接提交并刷新谱面；有尚未应用的侧栏草稿时，继续通过现有草稿协调器处理，不能丢弃草稿或把旧草稿写回新音乐。侧栏“事件时值”入口使用同一规则和提交通道，避免两个入口产生不同结果。

### 3.2 将两种操作明确分开

**修改时值**：音符数量不变。缩短后在原占用范围内释放可录入占位，不前移其他音符；延长时先消费紧邻空白，必要时顺移、压缩后续简谱，保留它们的音乐内容和身份。

**填充占位**：在释放的空白中直接录入一个新音，按当前简谱时值写入。新音独立发声，不自动添加延音线；后续音符位置不变。这是“四分变两个八分”的主要路径。

**独立拆分快捷操作不纳入 MVP**：把当前事件等分为两个独立事件的能力暂不增加单独按钮。用户通过“缩短原音值 → 在后方占位中录入新音”完成同样的结果，操作路径更明确，也避免与持续音等分混淆。

现有“等分持续音”保留，继续通过延音线表达持续发声。不得直接把它改名为独立音符拆分。

### 3.3 连续录入区分内容修改与创建

按目标类型把“改已有音符内容”和“按所选时值创建音符”分成两类操作，不根据输入了几个数字来猜测意图：

- 点击已有简谱音符：只修改已有事件的音高或内容，保留事件数量、时值和 tick，沿用 `numbered.sequence.set`。
- 点击简谱占位框：创建新的简谱事件，按当前简谱录入时值计算位置；连续输入按实际时值累计，默认不覆盖已有内容。
- 点击已有连续简谱范围：批量修改已有事件的内容，不自动创建新事件。
- 连续创建遇到已有事件时停止并提示；只有用户明确进入覆盖范围操作时，才允许替换已有简谱。
- 固定范围覆盖：继续由范围编辑承担，要求总时长与窗口一致，并遵守覆盖授权。

当前“允许覆盖此时间范围的简谱”的默认勾选仅作用于需要覆盖授权的命令。它不决定插入、重排或独立拆分的行为，也不应成为自动删除后续音符的依据。

## 4. 时间轴规则与示例

### 4.1 基本单位

使用现有 `TICKS_PER_QUARTER = 960`：四分音符 960 tick，八分音符 480 tick；4/4 小节容量 3840 tick。计算统一复用节奏和连音上下文，不在页面硬编码其他拍号的容量。

### 4.2 长时值改短时值：原地释放占位

规则：保留目标事件及音符 ID、内容和起点，只修改时值；其他简谱事件的 tick 不变。在 `新结束位置～原结束位置` 生成可录入空白，由布局推导占位框，不创建假音符或 TAB Beat。

```text
原来：1 四分 @0                 3 四分 @960
缩短：1 八分 @0，□ 半拍 @480    3 四分 @960
填入：1 八分 @0，2 八分 @480    3 四分 @960
```

新占位首次录入时默认八分音符；若原时值缩短幅度更大，占位应按可表示的时值分段呈现，允许分次填入。选择十六分音符只填部分空白时，剩余空白继续可录入。

占位框是编辑提示，不在成品或导出中画方框，也不等于音乐上的休止符。显式休止、延续事件和连音组 `gap` 仍属于音乐结构，不能自动作为可丢弃占位处理。

### 4.3 短时值改长时值：先用空白，再计算后续容量

建议参考 TAB 的容量处理，保留后续音符内容，不能默认把被新时值覆盖的音符删除。规则按以下次序规划：

1. 目标事件起点不变，计算增加的时长 `delta`。
2. 优先消费目标与下一个事件之间紧邻的空白。若空白足够，其他事件不动。
3. 空白不足时，把其余增长量转成后续事件的顺移量；同小节内后续事件先保持各自时值。
4. 后移若能由小节尾部空白容纳，直接完成。
5. 小节放不下时，在目标之后寻找精确释放不足时长的压缩方案，参考 TAB 从近到远搜索、减少压缩级别及受影响音符数量的策略。保留事件、音符及音高，只缩短被选中的后续时值并重新计算 tick。
6. 没有合法方案则整次拒绝，说明容量不足或受连音等结构限制。不得删音、静默跨小节或产生部分写入。

例如，原来两个八分音符为 `1 @0、2 @480`，其后有足够空白。把 `1` 改为四分后，`2` 移到 `960`，仍是八分音符，不会被吞掉。

如果原来小节已满：`1 八分 @0、2 八分 @480、3 四分 @960、4 四分 @1920、5 四分 @2880`，把 `1` 改为四分可以得到一项合法候选：`1 四分 @0、2 八分 @960、3 八分 @1440、4 四分 @1920、5 四分 @2880`。这项候选缩短了 `3`，所以必须在应用前清楚展示，不能让用户误以为只改了 `1`。

压缩候选必须使用简谱的实际时长和连音上下文。目标连音成员禁止单独修改；后续完整连音组可整体平移，但首版不压缩组内成员。其他有意保留的空白保持原有间隔，不全小节去空白重排。

已确认允许自动压缩后续真实音符；涉及后续音符时值变化时先展示影响，再一次提交。带歌词的事件可以参与压缩，歌词跟随事件移动。

### 4.4 后续可选：一步拆成两个独立八分音符

主要路径是缩短后填写占位。未来如果需要一步快捷操作，可以在不改变底层时间轴规则的前提下补充。

```text
原来：1 四分 @0                 2 四分 @960
拆分：1 八分 @0，1 八分 @480    2 四分 @960
编辑：1 八分 @0，5 八分 @480    2 四分 @960
```

保留第一个事件及其音符 ID；第二个事件及其音符使用新 ID。拆分后建议选中第二个事件，方便立即修改音高。初版只开放普通非连音音符事件；同音组整体拆分，附点按原附点保留并减半基础时值；达到最小时值或无法用整数 tick 等分时拒绝。

涉及原有延音线、连音线、延长记号时，先生成端点迁移及记号影响方案，再通过既有确认通道一次提交。新生成的两个音之间不自动添加延音线。延长记号建议迁移到第二个事件；原有连接关系必须重新校验，不能直接照搬“等分持续音”的全部规则。

### 4.5 插入与填充空白

连续插入时，从插入点累计新事件时长，将该点及之后的已有事件整体后移插入总时长。插入点不能位于某个事件或连音组内部。

在明确的空白时间窗录入时，优先填入该空白，不额外顺移后面的音乐。普通单音录入允许只占用空白的一部分，余下继续保持空白；超过窗口容量时提示失败。此行为应有独立的插入／空白填充规划，不能继续强行套用“模板总时长必须等于窗口”的 `range.replace`。

两类录入都按实际时值计算下一位置。提交后下一目标应由核心规划返回：可能是已有事件、剩余空白窗口或小节结束，前端不能从 TAB Beat 数组推导。

### 4.6 容量不足与跨小节

首版建议只修改当前小节。延长时值按 4.3 规划可行的压缩候选；连续插入、填空不能因为容量不足而隐式改变其他音符时值。任何操作都不自动跨小节、删音或移动其他声部。

不能容纳或不允许压缩时，整次拒绝并提示差额。参考 TAB 的领域策略不等于直接调用修改 TAB 数据的函数；可提取通用的时长候选和精确容量求解工具，简谱仍有独立规划器。

## 5. 技术实现建议

### 5.1 保留数据结构，显式区分命令语义

音符时值、占位和容量计算可以使用现有音乐数据结构，不要求为此升级 schema。歌词锚点改为简谱事件需要调整歌词模型、文档升级和加载校验；本方案不保留旧的 TAB 歌词兼容结构，见 5.6。

建议为 `numbered.event.setRhythm` 增加可选策略：

```ts
timeline?: "preservePositions" | "editTimeline";
```

旧调用省略时保留原来的固定位置规则，避免无意改变已有范围编辑、测试和外部调用。新顶部工具及侧栏普通事件时值编辑显式传入 `editTimeline`，由核心按缩短／延长执行不同规则。固定位置旧命令的覆盖语义不能泄漏到新的普通时值编辑。`preservePositions` 不要求增加面向普通用户的模式开关。

现有 `numbered.event.split` 继续保持“等分持续音”的原语义，MVP 不新增 `independent` 模式，也不在界面提供独立拆分按钮。占位填入通过新的连续创建／空白填充命令完成。

连续创建建议新增 `numbered.sequence.insert` 一类命令，接收小节、起点、内容及各成员时值。空白填充使用明确的窗口边界。不能把已有 `numbered.sequence.set` 静默改成增删事件的命令，也不应要求 UI 为键盘录入伪造剪贴板数据。

### 5.2 抽取纯时间轴规划层

建议新增 `packages/lxm-editor/src/core/numbered-timeline.ts`，职责包括：

- 计算事件实际时长与小节容量。
- 规划缩短释放空白、延长消费空白、后续顺移与压缩、插入和空白填充。
- 保留未改变事件、音符和连音组的 ID。
- 返回新声部、移动事件清单、容量差额、剩余空白及下一录入目标。
- 对越界、事件重叠、连音组切断等情况返回明确错误。

从现有 `numbered.range.paste` 抽取可共用的顺移／边界校验逻辑；粘贴的内容复制与新 ID 分配仍由粘贴流程承担。实际变更与预览共用同一个规划函数。

领域规划完成后，通过现有 `editNumberedTrack` 处理技巧关系，再走文档命令的 schema 与语义校验。一次操作包含事件、tick 和记号的全部变化，只进入一条撤销记录。失败不产生部分写入。

### 5.3 草稿、焦点和历史

工具栏点击前解析最新的活动谱面对象，不能仅判断 `numberedSelection` 是否非空。简谱目标、TAB 选区、活动对象和侧栏草稿必须通过统一的目标解析和草稿协调流程取得一致结果。

现有成功结果的 `nextNumberedFocus` 只能表达已有事件。建议增加可表达事件／空白窗口的下一录入目标，并同步更新 store、侧栏及选区校正逻辑；修改已有事件时仍保持选中该事件；占位填入后定位到新内容之后。

操作遇到未提交草稿时，按现有协调流程应用、暂存或取消，不能直接解除全局编辑保护。工具栏的可用状态需要区分“正在编辑简谱”和“存在冲突草稿”，前者本身不应导致简谱时值工具永久禁用。

缩短时可以复用 `releasedRange` 表达原位释放空白；延长时应返回消费空白、移动事件和压缩时值清单。预览必须匹配实际规则，不能仍提示“覆盖后续音符”。焦点和占位时间窗来自核心规划及最新布局。

### 5.4 连接记号和连音组

事件和音符 ID 不变时尽量保留关系，但 ID 有效不代表音乐关系有效。重排后必须重新校验延音线的相邻性、音高与时间连续性，尤其注意跨小节连接：本小节移动不会自动移动下一小节。

首版建议：普通事件可改时值；连音成员禁止单独改时值或拆分；后续连音组可整体平移。对需要删除或迁移的记号，沿用现有影响确认、版本校验和一次撤销流程。确认期间目标或文档版本改变，旧计划失效并重新计算。

### 5.5 谱面渲染

继续使用现有简谱时值布局及共享场景渲染。音乐提交成功后重建联合布局，减时线、附点、延时线、空白录入位置和命中区域同时更新。

首版建议不增加未提交草稿的谱面实时预览；顶部直接修改成功即可看到结果。面板保留明确的草稿状态和应用按钮，避免把草稿预览与已保存音乐混在一起。

### 5.6 六线谱、简谱与歌词如何一起处理

采用“共用音乐时间轴，各声部独立编辑，歌词统一跟随简谱事件”的规则。相同 tick 的内容在联合排版中对齐；不同 tick 不应为了上下视觉一致而强行对齐。也不能按数组下标，把第 N 个简谱音、TAB Beat 和歌词当成同一对象。

**已确认：不保留六线谱歌词绑定兼容模式。** 现有歌词全部迁移为简谱歌词。歌词不再从 TAB Beat 读取 tick，TAB 时值变化不会直接带动歌词；简谱事件移动、缩短、延长、压缩或拆分时，歌词按照简谱事件绑定规则处理。

运行时模型使用简谱事件作为唯一歌词锚点：

```ts
type LyricAnchor = { kind: "numberedEvent"; eventId: string };
```

歌词本身不复制保存 tick。通过简谱事件 ID 和所属小节解析当前时间，在录入、布局、命中、导出、复制及删改中使用同一解析函数。歌词结构应直接替换为简谱锚点，不能同时保留 `beatId` 和 `eventId` 两种来源。

由于没有历史兼容负担，现有 mock 数据直接修复为简谱事件锚点，不增加运行时迁移层，也不保留旧的 TAB `beatId` 结构。后续文档只接受简谱事件锚点；如果测试数据缺少对应简谱事件，直接修复 mock 数据。

已确认的联动结果：

- 简谱四分缩成八分：原歌词保留在原音符上；新占位及后来录入的第二个八分默认无歌词，不自动复制歌词。
- 简谱八分改四分：后续简谱音符被移动或压缩时，其绑定歌词随事件到新起点，字的顺序、内容和段落不变；TAB 修改不直接改动歌词。
- 短改长导致容量不足时，带歌词的后续简谱事件也允许参与自动压缩；事件 ID 和歌词绑定不变，歌词跟随事件移动。
- TAB 修改时值：沿用 TAB 自己的容量规则；歌词仍以简谱事件为唯一位置来源，除非用户同时编辑简谱，否则不改变。
- 独立拆分：原歌词保留在第一个事件，第二个事件默认无歌词。一个字延唱多个音的完整标记能力另行设计，不靠复制字实现。
- 删除被绑定音符：同步删除绑定歌词，不迁移到相邻音符。延长时的顺移／压缩保留事件 ID，本身不应导致歌词删除。

同一段歌词统一跟随简谱声部；新建歌词只能从选中的简谱事件确定绑定。迁移不提供用户选择 TAB 或简谱的双模式。

复制简谱事件时同步复制其歌词，并为复制出的事件和歌词生成新的 ID。插入、范围覆盖和粘贴必须同步维护歌词引用；被替换或删除的简谱事件，其歌词一并删除，不迁移到相邻事件。

需要直接修改 `core/types.ts`、`core/schema.ts`、mock 数据和加载校验，使歌词只保存简谱事件引用。相关链路包括歌词命令、连续录入、复制粘贴、简谱事件删除保护、结构修改、布局测量、焦点、导出和撤销重做。现有 `collectMusicTextBeatIds` 需要改为收集简谱事件引用，不能继续把歌词计入 TAB Beat 保护集合。

**不建议首版提供三层自动联动修改时值**：修改简谱后自动改 TAB，并不能保证伴奏、旋律与歌词表达正确。若将来有“同时修改伴奏和旋律”的显式操作，应单独规划两个声部的候选结果和歌词影响，全部校验成功后一次提交，不能串行写入留下半成品。

## 7. 验收与测试

### 7.1 用户路径

1. 4/4 小节有四个四分简谱音符；通过缩短并填写占位得到 `0、480` 的两个八分音符，后面三个仍在 `960、1920、2880`，无新延音线。
2. 第二个八分音符可以改成其他音高；两个音符各自可选，谱面正确生成减时线。
3. 修改第一个四分为八分，保留原音及起点，在 `480～960` 出现半拍可录入占位；其余三个四分音符不移动。
4. 在该占位直接输入第二个八分，第一拍成为两个独立八分，无自动延音线；后续拍点不变。
5. 从半拍空白录入八分音符，无需再到高级面板设置窗口；填入十六分音符后剩余四分之一拍继续可录入。
6. 简谱八分改四分时先消费空白，必要时顺移及压缩后续简谱；后续音符不被删除。压缩前预览影响，无合法候选时整体失败。
7. 修改简谱前后，TAB、和弦及公共结构数据保持一致；修改 TAB 后也不改写简谱音乐数据。歌词按已确认的绑定规则跟随，不能以“歌词数据未改”代替时间位置校验。
8. 顶部按钮切换简谱和 TAB 后正确回显，不会误写残留选区；一次撤销完整还原音符、tick、时值和相关歌词变化。

### 7.2 核心边界

- 不同拍号、附点、最小时值及整数 tick 限制。
- 后续有显式休止、延续事件、内部空白或完整连音组。
- 操作正好填满、仍有剩余容量或容量不足。
- 不能单独修改连音成员，不能从事件／连音组内部插入。
- 延音线、连音线、延长记号及跨小节关系的保留、迁移、确认或拒绝。
- 原有固定位置 `setRhythm`、范围覆盖、持续音等分及粘贴行为保持兼容。
- 现有歌词全部改为简谱事件引用，不保留旧 TAB 歌词兼容；覆盖 mock 数据、同 tick 多候选、删音时同步删除、带歌词事件压缩、复制及导出一致性。

测试使用核心命令的真实文档结果，不在测试中另写一套 tick 算法。浏览器必须覆盖“选中 → 点时值 → 点击占位 → 录入 → 看谱面 → 撤销”的完整路径，并检查命中、选中框及导出图像。新增方案的核心、布局、网站和浏览器测试已执行，结果见第 10 节。

## 8. 建议实施顺序

1. 先完成缩短后的就地占位和直接填入，打通“四分变两个独立八分”的主要路径。
2. 实现延长时消费空白、顺移、压缩及影响预览，再统一顶部工具与侧栏通道。
3. 完成连续创建和下一录入位置衔接；独立拆分快捷操作不纳入 MVP。
4. 完成歌词锚点迁移，删除旧 TAB 绑定兼容，并验证歌词位置、删音迁移、复制及导出。
5. 验证连接记号、草稿、撤销重做、谱面、歌词位置和导出的一致性。

各阶段可单独评审，但整体目标仍包括独立时间轴和连续录入，不能只交付按钮复用就认为完成。

## 9. 需要一起讨论的决定

已明确：长时值改短时值保留原音，在后方就地增加可录入占位，其他事件不前移。

已确认：

1. 短改长导致容量不足时，允许参考 TAB 压缩后续真实简谱音符；带歌词的事件也可参与压缩，歌词跟随事件移动。
2. 歌词统一绑定简谱事件；现有歌词全部迁移，不保留 TAB 绑定兼容。
3. 复制简谱事件时同步复制歌词；被替换或删除的事件，其歌词一并删除。

已确认连续输入规则：点击已有事件只修改已有内容；点击占位才创建新事件；遇到已有事件停止，不能根据输入项数量自动猜测为覆盖或拆分。

歌词归属、mock 数据处理、删除规则、后续音符压缩规则和 MVP 交互入口均已确认，后续可以进入实现拆分和测试设计。
