# 六线谱编辑器 MVP 版本路线图

## 1. 文档目的

本文档定义当前 `@liuxianmao/lxm-editor` 的 MVP 后续版本范围、实施顺序与验收标准。

它以仓库现有实现为基线：核心包已经提供 LXM 文档结构校验、节奏 tick 计算、单小节布局、节奏列间距、小节线、TAB 品位数字、符干、连梁与附点的 SVG 几何数据；网站应用负责消费布局结果并渲染 SVG。

本文档不沿用已移除的旧编辑器包设计。后续规划均以 `packages/lxm-editor` 为唯一编辑器核心。

## 2. 总体原则

- 核心包负责文档模型、领域命令、布局与命中数据；`apps/website` 只负责界面装配、事件转发与 SVG/HTML 渲染。
- 任何持久化乐谱修改都必须经由纯领域命令完成，页面组件不得直接变更 `ILXMDocument`。
- 每个版本结束时，数据校验、布局计算与用户可见行为必须一致；不能以静态 mock 掩盖未完成的交互。
- 布局结果是渲染和命中的唯一坐标来源。页面层不得重新推导小节宽度、换行或音符位置。
- 每个版本都要具备：范围内单元测试、TypeScript 检查、浏览器验收，以及已知限制记录。
- MVP 固定桌面端基线。响应式、分页打印与移动端适配不属于 MVP。

## 3. 目标版本概览

| 版本     | 目标                   | 交付结果                                   |
| -------- | ---------------------- | ------------------------------------------ |
| MVP v2   | 多行谱面与最小输入闭环 | 自动换行的系统行、点击定位、单音输入与删除 |
| MVP v3   | 小节与节奏编辑         | 时值/附点、小节增删复制、容量校验          |
| MVP v4   | 范围输入与安全历史     | 矩形选区、批量品位、整小节复制、撤销重做   |
| MVP v4.1 | 基础谱面标识与小节边界 | TAB 行头、拍号展示与小节线编辑             |
| MVP v5   | 吉他演奏技巧           | 常用技巧的数据模型、输入与跨小节渲染       |
| MVP v6   | 音乐文本信息           | 歌词、和弦名称、和弦图与碰撞规避           |
| MVP v7   | 保存与交付质量         | 保存加载、导出、错误恢复与发布验收         |

## 4. MVP v2：多行谱面与最小输入闭环

### 4.1 目标

让用户能在自动换行的 TAB 谱面中定位一个拍点和弦，并完成输入、覆盖与删除。这个版本优先建立稳定的布局与编辑边界，不追求复杂批量编辑。

### 4.2 实施切片

#### v2.0：小节行渲染与自动换行

为整首谱面新增 system（谱面行）布局。单小节 `measure-layout` 继续只负责小节自身几何；system 和整谱布局负责小节分组、坐标与总尺寸。

建议模块边界：

```text
packages/lxm-editor/src/layout/
  measure-layout.ts      # 单小节的弦线、音符、时值与小节线
  system-layout.ts       # 单行小节排列与行高
  score-layout.ts        # 自动断行、整谱高度与系统集合
  layout-types.ts        # Measure/System/Score 布局类型
```

建议输出层次：

```text
ILXMLayout
└─ systems[]
   └─ measures[]
```

自动换行策略在首版使用可预测规则：

- 接收 `systemWidth`、`systemGapY`、`measureGap` 等布局选项。
- 按小节 `assignedWidth` 顺序装入当前行；放入下一个小节后超出 `systemWidth` 时，从该小节开始新行。
- 单个小节本身宽于可用宽度时，独占一行，不缩放、不截断。
- 每行的 Y 坐标由前一行最大高度加 `systemGapY` 推导；整谱宽高由所有 system 汇总。
- MVP 不做视口变化后的自适应重排；调用方显式传入逻辑宽度。

网站渲染按 system 分组输出 `<g>`，不在 React 内判断换行。现有单个根 SVG 可继续使用，但 `viewBox` 与高度必须来自整谱 layout。

验收标准：

- 4 个以上小节可按给定逻辑宽度稳定分为多行。
- 每行中的小节 X 坐标不重叠，行与行之间的弦线、符干和连梁不重叠。
- 同一份文档和布局选项每次生成相同的 system 分组与坐标。
- 增加或删除小节后，重新布局不会留下空白坐标或错误的总高度。

测试重点：断行边界、超宽小节、空轨道、不同小节高度及整谱尺寸。

#### v2.1：命中定位与编辑光标

在 layout 层建立命中索引，页面将 SVG 指针坐标转换为稳定的编辑目标。

最小编辑位置：

```ts
interface ActiveCursor {
  trackId: string;
  systemIndex: number;
  measureId: string;
  beatId: string;
  string: number;
}
```

约束：

- 点击范围应覆盖拍点列和六根弦，不要求用户精确点击到品位数字。
- 命中只返回现有 beat；空白节奏格与自动物化留到 v3 再决定。
- 重新 layout 后，用 `measureId + beatId + string` 恢复编辑光标，而非缓存旧坐标。
- 光标和 hover 属于临时 UI 状态，不写入乐谱文档，也不进入后续撤销历史。

验收标准：

- 多行谱面的任意小节均可点击定位到正确弦和 beat。
- 自动换行或重新布局后，已选位置仍指向同一业务对象。
- 无法命中时不修改当前文档，并提供可测试的空结果。

#### v2.2：单音输入、覆盖与删除

建立最小领域命令层并接入键盘输入。

首批命令建议为：

```ts
type ScoreCommand =
  | {
      type: "note.set";
      measureId: string;
      beatId: string;
      string: number;
      fret: number | "x";
    }
  | { type: "note.remove"; measureId: string; beatId: string; string: number };
```

行为规则：

- `note.set` 在同一 beat、同一弦已有音时覆盖，不产生重复音符。
- `note.set` 接受 `0` 至 `24` 的品位及闷音 `x`；其他输入返回明确错误。
- `note.remove` 删除目标弦的音符；同拍其他弦音符保持不变。
- 若删除后 beat 无音符，是否转为休止由当前模型的 `kind` 约束决定；在命令实现前先把规则写成测试。
- 两位品位输入使用短暂的页面草稿状态组合后，再提交一次 `note.set`；草稿不进入文档。
- 命令成功后以新文档重新调用 layout，命令失败时保持原文档与光标不变。

验收标准：

- 用户可在四小节、多行谱例中输入单音、覆盖已有音并删除音符。
- 非法品位、非法弦号和不存在的目标返回可展示的错误信息。
- 每次成功操作后，音符位置、符干和连梁均来自最新 layout。
- 页面刷新前的最小内存状态可完整反映当前文档；保存功能不属于 v2。

### 4.3 v2 不包含

- 时值、附点、连音组和休止符编辑。
- 新增、复制或删除小节。
- 多选、框选、拖拽和剪贴板。
- 撤销/重做。
- 技巧、歌词、和弦、播放、保存和导出。

## 5. MVP v3：小节与节奏编辑

### 5.1 目标

让用户改变乐句结构，并保证每个小节的时间容量始终可验证。

### 5.2 范围

- `beat.setRhythm`：修改基础时值与附点数。
- 休止符的创建、取消与渲染。
- 新增、复制、删除小节；新增小节继承相邻有效拍号与默认节奏结构。
- 小节容量校验：禁止无效 tick、重叠 beat 和超出拍号容量的编辑结果。
- 对新增、删除、复制后的谱面自动重新断行。

### 5.3 关键决策

在实现前必须明确“时值变化影响后续 beat”的规则。MVP 推荐保守策略：如果操作会造成容量溢出、beat 重叠或不连续且无法明确修复，则拒绝命令并报告原因；不在页面层静默挤压后续 beat。

### 5.4 验收标准

- 用户能创建、复制和删除小节，且至少保留一个合法小节。
- 修改时值或附点后，`calculateRhythmTicks` 与小节容量校验一致。
- 任何非法操作不改变原始文档。
- 小节结构变化后，system 分组和整谱高度自动更新。

## 6. MVP v4：范围输入与安全历史

### 6.1 目标

优先解决重复品位输入和批量误操作恢复，把单点编辑扩展为跨弦、跨 Beat 的安全范围编辑流程。

### 6.2 范围

- 连续 Beat × 连续弦的二维 TAB 单元格矩形选区，可跨小节和 system。
- 点击、Shift+点击、拖动及四方向键导航；Shift+方向键扩展选区。
- 对选区原子地设置相同品位或删除音符，不修改范围外弦、rhythm、tick 和小节容量。
- 保留单 Beat rhythm/rest 编辑和完整小节新增、复制、删除；多 Beat rhythm/rest 与 Beat 剪贴板不属于 v4。
- 撤销、重做与历史快捷键；两位品位输入和每次批量命令各合并为一条历史。

### 6.3 验收标准

- 二维矩形选区可跨弦、Beat、小节和 system，并始终指向稳定业务 ID。
- 批量设置和删除都是单个原子领域命令；失败或 no-op 不产生部分修改或历史。
- 所有用户可见的乐谱变更均可稳定撤销和重做；选区、hover、滚动与弹窗不进入历史。
- 单 Beat rhythm/rest 和完整小节复制无回归；复制小节继续重建所有嵌套 ID。

## 7. MVP v4.1 补丁：基础谱面标识与小节边界

### 7.1 目标

在进入吉他技巧前补齐谱面行头和小节结构的可见、可编辑闭环，使后续技巧线与文本布局建立在稳定的正文起点和边界几何上。

### 7.2 范围

- 每条 system 显示由核心 layout 定位的 `TAB` 行头。
- 第一小节及拍号发生变化的小节显示拍号；普通自动换行不重复相同拍号。
- 支持谱首开始反复，以及单小节线、双小节线、终止线、开始反复线、结束反复线和双向反复线编辑。
- 小节边界修改经由原子领域命令，并接入 v4 的 no-op、撤销和重做语义。
- 反复线只表达可保存的记谱结构，不包含播放、次数、结尾房子或嵌套配对。
- v4.1 后续 Fix 支持 `2/4`、`3/4`、`4/4`、`6/8` 拍号编辑，以单小节或延续到下一拍号变更点为作用范围。
- 拍号容量变化只自动重建尾部容量休止；会截断真实音符或使和弦标记越界时原子拒绝。

### 7.3 验收标准

- TAB、拍号和边界几何全部来自核心 layout，页面不重复推导显示规则或坐标。
- systemWidth、自动断行、measure、hit index 和 selection 使用加入行头后的同一套最终坐标。
- 六类小节线与谱首开始反复均可编辑、撤销、重做，并在重新 layout 后保持一致。
- 拍号只在首次和变化点显示，TAB、拍号、品位数字和时值符号没有碰撞。
- 拍号修改接入 no-op、撤销和重做；`3/4` 与 `6/8` 使用正确且不同的连梁拍组。

详细方案见 [MVP v4.1 技术实现方案](./v4.1/technical-design.md)。
拍号编辑扩展见
[MVP v4.1 拍号编辑与小节容量协调 Fix](./v4.1/time-signature-editing-fix-technical-design.md)。

## 8. MVP v5：吉他演奏技巧

### 8.1 目标

让常用吉他技巧成为可编辑、可保存、可由布局驱动渲染的数据，而非页面装饰。

### 8.2 范围

- 击弦、勾弦、上/下滑音、推弦、颤音、自然/人工泛音、手掌闷音与延音线。
- 起始音与目标音的关联校验；同弦下一音的快捷连接。
- 技巧的新增、修改、删除与跨小节续接。
- 技巧线、文本标签与现有谱面元素的基础碰撞规避。

### 8.3 验收标准

- 每一种技巧都由文档模型和 layout 渲染，刷新/重新 layout 后仍一致。
- 不存在的目标音、非法跨弦或不合法时间顺序会被拒绝。
- 跨 system 技巧具有明确的续接视觉效果。

详细方案见 [MVP v5 技术实现方案](./v5/technical-design.md)，实施顺序见
[MVP v5 详细实施计划](./v5/implementation-plan.md)。

## 9. MVP v6：歌词、和弦名称与和弦图

### 9.1 目标

在不破坏节奏列对齐的前提下，为谱面补充常见文本信息。

### 9.2 范围

- 与 beat/tick 对齐的歌词输入与编辑。
- 和弦名称、显示格式与节奏列对齐。
- 动态和弦图：弦线、品格、指法点与横按线均由数据绘制。
- 为歌词、和弦名称与和弦图增加独立 lane，并将其最小宽度作为小节间距的输入。

### 9.3 验收标准

- 文本信息随小节自动换行并保持与目标节拍的关系。
- 额外宽度不会压缩到品位数字、符干或其他文本重叠。
- 和弦图和名称均可从数据完整恢复。

## 10. MVP v7：保存、导出与发布质量

### 10.1 目标

让用户的编辑结果可安全保存、恢复和交付。

### 10.2 范围

- LXM JSON 的保存、加载、版本校验和错误恢复。
- 导出至少一种用户可用格式；具体格式在实现前单独确定。
- 未保存状态提示、加载失败提示和恢复路径。
- 桌面端浏览器验收、无障碍基础检查与性能基线。

### 10.3 验收标准

- 保存后重新加载得到等价文档和等价布局。
- 不兼容或损坏文档不会覆盖当前编辑结果。
- 100 小节谱例在目标桌面基线下可稳定浏览；性能数据和已知限制被记录。

## 11. 每个版本的完成定义

一个版本仅在以下条件全部满足后才可标记完成：

- 范围内功能已通过真实文档与真实交互实现。
- 新增或变更的数据模型有运行时校验和明确错误信息。
- 领域命令、布局函数和边界条件均有单元测试。
- `pnpm test`、`pnpm type-check`、`pnpm lint` 通过。
- 在目标桌面视口完成浏览器验收，页面没有非预期滚动和控制台错误。
- 本文档或同级变更说明已记录范围调整、已知限制和用户确认结果。

## 12. 推荐的下一步

MVP v4 已完成后进入 MVP v4.1 补丁：先补充谱首边界模型与原子命令，再把 TAB 行头和拍号前导区纳入 system/measure 布局，最后接入 SVG、边界工具和 v4 历史。完成该补丁后再进入 MVP v5 吉他演奏技巧。Beat/乐句剪贴板继续延后到有实际使用证据的独立候选版本。详细方案见 [MVP v4.1 技术实现方案](./v4.1/technical-design.md)。
