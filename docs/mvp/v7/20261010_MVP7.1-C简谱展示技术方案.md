# MVP 7.1-C 简谱展示技术方案

> 日期：2026-10-10。状态：待审查，尚未实施。
> 目标：在现有单轨六弦 TAB 编辑器中增加与 Beat 对齐的简谱展示，不扩展为简谱编辑器。

## 1. 背景与版本定位

当前 v7.1 已完成音符 `x` 的记谱模型，下一步规划为单轨设置与多小节复用。简谱展示属于“常用记谱”切片，拟作为 **MVP 7.1-C** 加入 v7，不改变既有 TAB、歌词、和弦和技巧的领域语义。

本切片只解决“已有合法文档能够稳定显示简谱”。简谱内容由宿主或谱例提供，页面只渲染；本切片不提供简谱输入、自动识别、播放或五线谱联排。

## 2. 首版范围

### 纳入

- 在 Beat 上挂载一个简谱展示项，使用稳定 `beatId` 对齐 TAB 节奏列。
- 支持单个数字 `1`–`7`、休止 `0`、变化音前缀 `#`/`b`、高低音点和延音线文本标记。
- 支持同一 Beat 的和弦/多音简谱，以有序 token 列表展示；不推导音高，不根据调弦、品位或 capo 自动转换。
- 简谱显示在 TAB 六根弦区域上方、和弦名称下方；没有简谱时不占用垂直空间。
- 简谱参与 Beat 列最小宽度计算，与歌词、和弦名称和 TAB 共用同一横向锚点。
- 简谱图元进入 system/document 的 visual bounds，并进入 hit index 的只读展示命中区域。
- 紧凑/舒适布局、自动断行、字号和字体度量均由核心 layout 统一计算。

### 不纳入

- 简谱编辑、键盘录入、拖动换拍和独立撤销历史。
- 根据 TAB 音符、调弦、capo、调号自动生成或转调。
- 复杂节奏符号、连音线、反复记号、倚音/装饰音的独立几何；首版允许通过受控文本标记显示。
- 简谱与五线谱、多个声部、多轨同步和播放。
- 导入/导出 MusicXML、MIDI、GP 等外部格式。

## 3. 数据模型

在 `ILXMBeat` 增加可选字段，保持旧文档兼容：

```ts
export interface ILXMNumberedNotation {
  /** 稳定顺序的简谱 token；每个 token 是一个可渲染的短文本。 */
  tokens: string[];
}

export interface ILXMBeat {
  id: string;
  tick: number;
  rhythm: ILXMRhythm;
  kind: ILXMBeatKind;
  notes: ILXMNote[];
  /** 简谱展示快照；缺省表示该 Beat 没有简谱。 */
  numberedNotation?: ILXMNumberedNotation;
}
```

### 校验规则

- `tokens` 必须为 1–8 个非空字符串，每个 token 最多 8 个 Unicode 字符。
- 允许字符集合为数字、`0`、`#`、`b`、`.`、`'`、`-`、`(`、`)`、`/` 和空格；禁止 HTML、控制字符和任意 SVG 内容。
- 空数组不持久化，视为缺省；超过数量或长度限制时 loader 拒绝文档。
- 简谱只是 Beat 的展示数据，不参与 tick、容量、技巧引用和音符合法性校验。
- `schemaVersion` 升级为 5；loader 只接受明确的 v5 文档，不对旧文档隐式补写内容。若当前 v7.1-B 已先升级 schema，须在实施时合并为同一版本迁移策略。

## 4. Layout 设计

### 4.1 测量与列宽

- 新增 `numbered-notation-layout.ts`，提供纯函数：token 标准化、测量请求生成、token glyph 生成和 bounds 计算。
- 复用现有 `musicTextMetrics` 的确定性字体测量，不在核心调用 DOM 或 Canvas。
- `layoutMeasure` 从 Beat 读取简谱 token，生成 `numberedNotation[]`，并将每个 Beat 的最大 token 宽度贡献到 `ILXMColumnWidthContributors.numberedNotationWidthByBeatId`。
- 简谱与歌词、和弦名称共享 `beat.x`；同一 Beat 有多个 token 时采用水平紧凑排列，超宽内容撑开当前列，不覆盖 TAB 数字。

### 4.2 垂直布局

- 简谱位于 TAB 正文上方，和弦名称/和弦图仍保持现有 lane 顺序；具体 lane 顺序固定为：简谱 → 和弦 → TAB → 歌词。
- 简谱 lane 高度由 token 的 ascent/descent 加固定净空得到；没有简谱的 system 不增加该 lane。
- `measure.visualBounds`、`system.visualBounds`、`layout.height` 和后续 system 的 Y 均包住简谱 glyph。
- 简谱命中区域只用于 hover/focus 展示，不产生编辑目标，不改变 TAB 选区命中优先级。

## 5. 渲染与界面

- 新增纯展示组件 `NumberedNotationLayer.tsx`，只消费 layout 结果，不读取原始文档重新计算坐标。
- `ScoreMeasure`/现有 system 渲染器按 layout 的 `numberedNotation` 输出 SVG `<text>`；打印时保留，focus/hover 状态不改变几何。
- 在示例 v7 文档中增加至少 8 小节、跨两行 system 的简谱数据，覆盖单音、变化音、高低音点、休止和多 token Beat。
- 不新增编辑工具栏或侧栏入口；文档没有简谱时现有页面视觉应保持不变。

## 6. 测试与验收

### 核心测试

- schema v5 的合法/非法 token、旧文档加载和边界长度。
- 简谱 token 标准化、测量请求和 glyph 坐标。
- 简谱对 Beat 列宽、measure/system/document 高度和自动断行的影响。
- 简谱与歌词/和弦/TAB 同拍对齐，超宽 token 不重叠。
- 空简谱不改变既有布局；跨 system 后坐标和 bounds 稳定。

### 网站测试

- 示例谱正确显示简谱，刷新和重新布局后位置稳定。
- 简谱不抢 TAB 选区、品位输入、歌词/和弦草稿和键盘快捷键。
- 紧凑/舒适布局、打印样式和浏览器缩放下简谱可见且不裁切。
- 现有 v7.1-A/B 功能、历史、宿主替换和无简谱旧文档无回归。

### 工程验收

- `pnpm test`、`pnpm type-check`、`pnpm lint`、生产构建通过。
- 在至少 8 小节混合谱和 100 小节长谱上完成桌面浏览器布局检查；记录简谱 lane 对总高度和断行的影响。

## 7. 实施顺序

1. 先与 v7.1-B 核对 schema 版本和文档所有权，确定是否合并同一 schema 迁移。
2. 增加类型、schema 校验和示例数据；先完成核心单元测试。
3. 实现简谱测量、列宽贡献、lane 高度和 bounds 接入。
4. 接入 SVG 展示层与打印样式，补充网站交互回归测试。
5. 运行全量工程检查和桌面浏览器验收，更新路线图、v7 README 和实施验收记录。

## 8. 风险与待审查决策

- **数据来源**：本方案选择“宿主提供展示快照”，避免首版偷偷引入调性、音高和转调算法；若产品要求从 TAB 自动生成，需要另立模型和技术方案。
- **多音显示**：首版以 token 水平排列表达，不承诺复杂和弦谱号排版；真实谱例若需要上下叠置，应在后续切片单独设计。
- **schema 冲突**：v7.1-B 可能同时涉及 schema 版本，实施前必须统一迁移入口，禁止两个版本各自修改 loader。
- **交互边界**：首版展示命中不可编辑，避免与现有 TAB/音乐文本编辑目标形成竞争。
