## 3. 可直接执行的实施顺序

1. 核对并保留现有焦点意图改动，运行当前基线，单独记录任何既有失败。
2. 统一 schema 7、旧格式冻结验证、半音与简谱模型/命令；实现全文本/技巧内容保护。
3. 实现段落子 TAB、语法/预览/草稿和简谱最终布局/命中/高亮，建立稳定的内容基线。
4. 实现 split/merge、nextFocus 与结构 effects；再实现 clipboard v1 和两种粘贴的预览/确认/历史。
5. 最后输出最终几何的右侧线；运行工程与浏览器验收，完成测试谱与实施记录。全部交付及验收完成后才关闭该版本。

此顺序明确简谱先于 Beat 复用接线，避免后续粘贴和时间轴模块再补一轮音乐内容字段。

## 4. 重点反例验收

- 在一个只有全小节休止的空谱上插入整小节时长不能一边保留原目标、一边宣称容量足够；应拒绝并使用精确覆盖。
- 在两拍上各有独立歌词、简谱或相同品位但没有 Tie 时，合并必须拒绝，不能因最终文档合法就丢掉一次起音或文本。
- 一条 P.M. 仅覆盖合并范围的前半段时，不得映射到整个合并 Beat；完整覆盖才可映射。
- 预览覆盖后 undo/redo 或新分支使 revision 相同但目标内容变化，旧确认仍须失效；直接构造命令也经过确认键校验。
- 新粘贴副本与已有技巧发生冲突时，不能依靠技巧数组顺序删旧或删新“修复”；原子拒绝。
- 同一目标有多个歌词段号，子 TAB 切回歌词不能选错段；点击无简谱 Beat 不能撑高该 system 或影响正式断行。
- 拆分持续音不是自动时值压缩，合并内部 Tie 不应提示为内容丢失。
- 末行终止粗线/反复点保持原样，新增细线只补行底部；最右与底部描边不裁切。
