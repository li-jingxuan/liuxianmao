# MVP v7.0 编辑保真与宿主集成技术方案

> 2026-10-10。用户已明确授权按落地顺序实施，本方案记录首个阶段的具体契约。范围为 G16 → G04 → G05，不实现 v7.1 模型/记谱变更和 v7.2 分页。schemaVersion 保持 3。

## 1. 宿主会话（G16）

编辑器会话 Store 是文档与历史的唯一拥有者。宿主创建独立会话，传入合法初始文档，通过 EditorSession 装配界面；既有首页单例保留兼容。侧栏也必须消费同一会话，不再直接访问全局单例。

宿主接收 onChange（command/undo/redo）和 onError；仅真实文档变更通知，no-op、选择、错误与外部替换不触发 onChange。通知在状态提交之后发送；宿主替换不会回发编辑通知，避免循环。回调异常不能撤销已成功的命令或破坏历史。

replaceDocument 接受外部数据，先经正式 loader 校验，再限制为有小节的单轨文档；失败保留文档、历史、选区和当前草稿并报告错误。成功重置选区、技巧焦点、错误、影响说明与历史，增加会话 generation。EditorSession 按 generation 重挂载外壳，清理计时器、拖选、文本草稿与订阅；相同 ID 文档也按显式替换处理。空初始会话可显示错误，后续合法替换可恢复。

测试页改用独立会话与 replaceDocument 恢复入口，离开测试页无需备份/覆盖首页全局状态。不增加作品新建、保存状态、文件 UI、自动持久化或多轨管理。

## 2. 小节复制（G04）

在核心复制过程统一建立 Note/Beat ID 映射，复制完整包含在源小节内的单音、连接、整拍和区间技巧，分配新技巧 ID。歌词、和弦、连音现有复制契约保持。

跨边界连接与范围不复制，不把新实体连接到原小节之外。范围与源小节时间区间相交也视为相关遗漏，即使端点都在外部。原技巧保持原引用；插入导致相邻关系失效时仍按现有领域规则清理，并报告影响。所有修改一次 finalize、一次 revision、一次历史；失败无部分提交。

## 3. 影响说明（G05）

纯核心命令入口在成功候选提交后，基于前后领域数据生成结构化 effects：后续 Beat 缩短、起点重排、既有技巧清理和跨边界技巧未复制。主动修改的目标时值、主动删除技巧不作为副作用重复提示；no-op/失败不附加 effects。字段只属于命令结果，不保存到乐谱，不产生第二次命令。

影响数据包含稳定实体引用和前后值，供宿主使用；网站显示可展开的中文影响说明及原有撤销入口。历史切换、外部替换和下一次操作更新/清空说明，通知不依赖页面推断 tick。

## 4. 验证与退出

- 核心：16 类技巧的完整复制、引用唯一/不可变性、跨边界遗漏、被插入打断的旧 Tie、复制后的正式 loader/layout；压缩/重排/清理 effects 与 no-op/失败边界。
- 会话：命令/历史通知时机、外部替换不循环、同 ID 替换、坏/多轨输入保留会话、回调错误、影响与单条历史、不同会话隔离。
- 浏览器：测试页恢复、选中复制、影响说明与撤销；输入 1 后立即替换，600ms 后新谱不被旧回调修改；音乐文本未应用草稿随合法替换清理，非法替换不清理。
- 工程：核心/网站测试、类型、lint、构建和 diff 检查；不把本阶段验证声称为 v7.1、分页打印或整个 v7 完成。

本次只做会话 Provider、核心纯函数及小幅界面接线，不把外壳职责全面重构混入。已有工作区对照保存在临时目录，回退只处理本阶段增量。
