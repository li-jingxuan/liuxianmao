> 本文取代 [20261010 简谱展示草案](./20261010_MVP7.1-C简谱展示技术方案.md) 的只读交互、版本定位和 schema 5 设想；布局思路继续参考旧草案，冲突处以本文为准。

## 1. 交互规则

- 按用户后续补充，顶层“歌词编辑”改为“段落编辑”，保持“谱面设置 / 段落编辑 / 和弦编辑”三个主 TAB；段落编辑内部增加“歌词 / 简谱”两个子 TAB，不新增顶层简谱页签。两种内容均默认连续录入。
- 首次进入段落编辑默认选择歌词子 TAB；当前会话后续进入保留已接受的子 TAB。歌词段号仅属于歌词，不影响简谱；这里的“段落编辑”不改变小节段落标记 `sectionLabel` 的语义。
- 切换子 TAB 保留当前目标 `trackId/measureId/beatId`，只改变编辑类型与高亮：歌词选中当前段号在该拍的歌词区域；简谱选中同一 Beat 的简谱区域，不选中整列 TAB 音符。不存在内容时，显示与该拍对齐的临时输入占位高亮，不向文档写入空内容，也不改变正式布局。
- 已有选拍时进入子 TAB 直接读取该拍；尚无目标时提示选拍，不擅自选取全曲第一个有内容的位置。点击 TAB 单元格、歌词或简谱图元进入对应拍和对应子 TAB，复用目标请求及草稿保护。点击仅切换编辑目标，不直接修改文档。
- 参考歌词输入框，半角/全角空格分隔，每一项对应一个已有 Beat；连续空格合并为一个分隔，不代表空拍。
- 从当前拍开始按轨道内真实 Beat 顺序分配，允许跨小节和谱行；休止 Beat 同样占一项，连音每个成员也占一项，不按时值重复分配。
- 示例 `1 2 3 _ 5` 对应五拍；`_` 跳过并保留该拍原简谱；`0` 写入简谱休止，`-` 写入延音展示标记，两者都不修改 TAB 的 kind、音符或 rhythm。
- 超出已有拍数时整批拒绝，不自动新增拍或小节。Tab、换行和控制字符拒绝，与现有歌词分隔规则一致。
- 连续草稿初始为空，避免把已有内容误当作待覆盖批次；可切换“单拍编辑”，预填当前拍内容，支持修改与删除。单拍删除移除该拍简谱字段，连续模式中空格不表示删除。
- 默认一项为一个简谱 token。同拍多音按第 6.1 节固定用 `+` 连接，如 `1+3+5 2+4+6` 对应两拍；空格始终只分拍，不分同拍多音。
- 首版保留数字 1–7、0、升降前缀、高低音标记和独立 `-` 的受控表示；以第 6.1 节的确定语法和示例冻结校验，不再采用旧草案任意字符白名单。解析结果不允许空 token、任意 SVG/HTML 或控制字符。

## 2. 预览、覆盖与草稿

- 输入后展示“第几小节/第几拍、原简谱 → 新简谱、新增/替换/相同/跳过/错误”。点击预览行只定位检查，不改变批次起点。
- 内容相同为 no-op；与已有简谱不同且需要替换时，必须主动勾选允许覆盖。跳过项始终保留原数据。
- 应用全部通过一个原子领域命令提交，只有成功后才进入一次历史、一次 revision 和一次宿主通知；任何 token、目标或覆盖校验失败，整批不修改。
- 换拍、切主 TAB、切歌词/简谱子 TAB、切单拍/连续模式沿用应用、放弃、继续编辑保护；失败保留草稿、原子 TAB 和原目标。重复点击当前子 TAB 不重载或覆盖草稿；确认放弃或应用成功后才进入新的编辑类型，不保留另一份可悄悄回写的脏草稿。
- 连续录入的批次起点与预览检查目标分离；切子 TAB 使用已接受的批次起点，不采用仅用于检查的预览行。歌词/简谱的高亮状态独立于 TAB 弦矩形选区，切换类型不批量选择或修改六根弦。
- 主 TAB 和子 TAB 分别提供独立的可访问名称及键盘方向键/Home/End 导航；键盘切换同样经过草稿保护，确认接受切换后才更新选中状态和焦点。
- IME 组合输入期间不应用、不处理候选 Enter、不切目标；撤销/重做取消过期草稿，外部合法文档替换重置草稿，非法替换保留会话。
- 不共享歌词段号，不把简谱写入歌词字段；复用其交互模式及可共用的分隔/目标遍历能力，简谱校验和持久化命令独立。

## 3. 模型与核心命令

- Beat 增加可选 `numberedNotation: { tokens: string[] }`；每拍 1–8 个受控 token，每个最多 8 个 Unicode 字符。未设置时省略字段；空数组拒绝，不让 loader 与命令产生不同解释。
- `_` 是批次跳过控制符、`+` 是建议的输入分组符，均不存入 tokens；每拍多音最终保存为有序 token 数组。
- 新增纯函数 `parseNumberedNotationSequence` 和 `planNumberedNotationSequence`。首版与歌词一致限制为单批 256 项、原始输入 16384 个 Unicode 字符，预览与提交共用目标映射和校验。
- 命令建议为 `numberedNotation.set`、`numberedNotation.remove`、`numberedNotation.setSequence`；核心自行读取目标、解析/校验结构化项并生成候选文档，页面不直接修改 Beat。
- 单拍和批次命令共享 token 校验；直接构造命令、loader、clipboard 均执行运行时校验，不只依赖输入框。
- 与合并 7.1-C 的半音推弦统一升级至 schema 7；当前 schema 6 和旧 4/5 经显式升级入口处理，旧文档不补造简谱。loader 不自动迁移。

## 4. 布局与结构编辑的共同契约

- 不从 TAB 品位、调弦、Capo 或调性自动生成简谱；手工简谱是独立记谱数据，不作为播放或 TAB 音高校验依据。
- 纵向顺序明确为和弦名称/指法图 → 简谱 → TAB → 歌词；修正旧草案相互矛盾的顺序描述。无简谱的 system 不增加 lane。
- 核心统一计算字体度量、整组 token 宽度、列宽、垂直净空、visual bounds 和命中；多音宽度按整组计算，不能只取单 token 最大值。SVG 和打印消费同一几何。
- 简谱命中增加可编辑目标，保持 TAB 单元格、技巧和其他文本的命中规则明确；高亮和预览不改变布局。
- 小节复制、Beat clipboard 和插入/覆盖粘贴保留简谱 token，快照与源数据独立。
- 拆分保留简谱于第一拍，第二拍不自动生成延音或重复简谱；合并保留首拍简谱，后续拍有任何简谱时拒绝，避免丢失或擅自拼接。该规则与合并后的歌词/和弦处理一致。
- 带简谱的尾部休止属于明确内容，插入或时间轴协调不得将其当作可消费的普通容量休止；拍号缩容等已有时间轴操作也必须纳入同一保护集合。

## 6. 落地复查补充

### 6.1 固定输入语法与显示含义

采用以下首版规则作为实施基准，避免让输入框、loader 与命令各自解释：

- 普通音符 token 为可选 `#`/`b` 前缀 + 数字 1–7 + 可选高低音后缀。`'` 为高一个八度，`.` 为低一个八度；同一 token 最多三枚同种后缀，不允许两种混用。例：`#4`、`5'`、`6..` 合法，`8`、`#0`、`1'.`、`1/2` 无效。
- `'`/`.` 是输入编码，渲染为音符上方/下方的实际圆点，不显示成紧跟数字的标点；`.` 在这里不表示附点时值。首版简谱时值来自 TAB Beat，不另外输入简谱 rhythm。
- `0`、`-` 必须各自独占一个拍项；前者是独立简谱休止，后者仅是延音展示标记，不自动推导前音或生成 Tie。它们不能与普通音符组成多音项。
- 同拍多音固定用 `+` 分组，1–8 个普通音符 token，保留输入顺序与重复，不排序或去重。`1+3+5` 合法，`1++3`、`1+0`、`1+-` 无效；不接受 `1 + 3`，空格只能分拍。
- `_` 独占一个拍项，表示跳过；不存入 tokens。空数组不合法，删除只能走 remove 命令。单拍输入也使用同一 token/+ 解析，不允许空格偷偷跨拍。
- 控制字符和非半角/全角空格的空白先拒绝，再处理头尾及重复空格；非法项给出第几项及原因。只跳过的批次与空批次拒绝，所有合法值相同则为成功 no-op。

### 6.2 类型、状态和布局集成

- 编辑目标拆为主 TAB `score | paragraph | chord` 与段落类型 `lyric | numbered`；音乐目标 kind 增加 `numbered`，歌词单独保存 verse。主 TAB、段落类型、目标、输入焦点和草稿是否 dirty 各自表达，不共用一个 kind 推断全部状态。
- 不依赖 `!!draft` 决定“用户正在编辑”：预填目标/高亮可以存在但未输入。独立输出 `activeTarget`、`inputActive`、`dirty`、`composing`、`pending`；只选拍时不抢输入焦点、不屏蔽 TAB 编辑或 Beat 工具。输入框活跃、IME、确认对话或实际脏草稿时禁用结构动作，保持现有草稿保护。
- 点击歌词/简谱图元、切到段落编辑及切子 TAB 都报告对应区域 activeTarget；选择 TAB 单元格可同步表单但保留谱面焦点。高亮不再只在 inputEditing=true 时可见，满足“选择子 TAB 即选中对应区域”。
- 草稿使用按 kind 区分的类型，简谱无 chord/verse 字段；切换成功后丢弃旧草稿，失败/继续编辑保持旧类型。歌词的段号在换子 TAB 后保留，简谱不显示段号；模式和覆盖许可不跨类型携带，重新进入默认连续且未允许覆盖。
- 简谱 sequence 命令接收明确 start + 结构化 set/skip 项 + allowOverwrite，核心验证类型、项数、tokens 和目标；不因为解析函数返回 typed 结果就跳过直接命令校验。单拍 set 是明确编辑，删除不存在字段可返回 no-op。
- 简谱与歌词的连续预览均绑定当前快照；历史/替换清理过期草稿，提交重新验证覆盖和目标。preview inspection 不变成 start，不写 selection，也不改变已接受子 TAB。

### 6.3 不撑高的空内容高亮

- 当前 system 有对应简谱/歌词 lane 时，空内容高亮使用该 lane 的最终 baseline 与度量；歌词按当前 verse 精确定位，不能选中另一段歌词。
- 当前 system 没有该 lane 或当前 verse 超出既有行数时，仅输出临时 overlay，贴近对应 Beat 的现有内容区并约束在当前 system 内，以不同描边标识待填写；不向正式 layout 增加 lane、不改变 system height/断行、不占持久化文本命中优先级。实际提交内容后正式布局才重排。
- 核心提供纯 overlay 定位入口，统一返回对应内容 bounds 或待填 bounds；界面不通过 DOM 或另一套坐标推导。滚动定位消费同一 bounds，当前无词时不再沿用 TAB 六弦矩形作为歌词区域。

### 6.4 列宽、垂直净空与实际图元

- 高低音点、升降号和多音间距均有实际图元及 bounds，字号/间距/填充来自核心现有文字常量体系；原字符 token 的宽度不能代替最终音符加圆点的宽度/高度。
- 将最终数字、升降号文字纳入 `collectMusicTextMeasureRequests`，高低音点用确定性 SVG circle；完整多音组参与 spacing、首尾 insets 和自动断行，避免仅扩宽相邻列而末拍长多音越界。
- 先规划 TAB/技巧的自然几何，再把简谱放到其上方净空带，和弦放在简谱上方；不能将简谱与上方推弦/技巧叠在同一 lane。同 system 按最大点位高度统一净空，密集行与无简谱行保持确定性布局。
- 每次最终 Y 平移都更新简谱文字、圆点、组 bounds、measure/system visual bounds、hit index 与 overlay 锚点，渲染/命中/打印只消费最终投影；集中检查 `translateMeasure` 与 system-content 的文本平移路径，防止重复或遗漏平移。
- 提交/删除最后一项简谱时正常增减正式 lane，side tabs/hover/草稿高亮不触发这种结构布局变化。全部数据复用、保护和 schema 规则见合并方案第 8 节。

### 6.5 补充验收

输入语法的合法/非法表、同拍多音空格误用、实际高低音点与非附点含义、末列多音外延、与半音推弦的净空、段号记忆与覆盖许可隔离、无简谱 system 的临时高亮、纯选拍保留谱面焦点/工具可用、最终命中和平移一致，均纳入本版测试与浏览器验收。
