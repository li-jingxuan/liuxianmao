## 1. 目标与基线

在已完成的 7.1-B 上增加可解释、可撤销的拍点结构编辑、Beat 乐句复用和半音推弦。当前核心文档 schema 6，已有 `beat.setRhythm`、小节范围复制、16 类技巧、连音、歌词与和弦；网站适配层提供独立会话和草稿保护。

本版交付五项能力：单个 Beat 等分为两拍、连续 Beat 合并、同小节连续 Beat 快照复制及插入/覆盖粘贴、半音与全音推弦选择，以及空格分隔的简谱连续编辑。每个编辑操作为一条核心命令、一次 revision、一次历史和一次宿主通知；复制快照不改变文档或历史。

简谱按最新连续编辑方案纳入本版；旧只读展示草案不再作为交付定义。作品/文件管理、播放、多轨、跨小节自动扩展、预推/回落、复杂装饰音和分页/PDF 均不纳入本版。简谱批次可跨小节写入已有拍，与首版 Beat clipboard 限定同小节是不同操作边界。

## 2. 首版行为与语义

### 2.1 拆分

- `beat.split` 接收轨道、小节和 Beat ID。首版等分为两个同附点、时值减半的 Beat；总实际 tick 不变，不压缩后续拍。不能表示为合法时值（例如三十二分音符再等分）时拒绝。
- 首版拒绝拆分连音成员；不隐式拆组或改变连音比率。
- 休止拆为两个休止。数字音符拆分为两个同弦同品位的音符，并逐弦建立内部 Tie，表示原持续音；第一拍保留原 Beat/Note ID，第二拍生成新 ID。
- 含 `x` 的 Beat 首版拒绝拆分：闷音不能 Tie，重复 x 会改变击打次数，不能将其当作持续音处理。
- 歌词、和弦及单音/Beat 技巧留在第一拍，不复制到第二拍。外部进入的连接仍指向第一拍，外部离开的连接改为从第二拍对应 Note 出发；区间终点落在原拍时延至第二拍，起点保留第一拍。
- 若重建后的连接、范围或内部 Tie 与现有技巧不兼容，整次拒绝并给出原因；不调用通用清理后悄悄删掉原技巧。具体兼容性由现有规则最终校验。

### 2.2 合并

- `beat.mergeRange` 接收同小节、顺序连续的起止 Beat ID，至少两拍。总时值须能表示为一个合法 rhythm，首版拒绝任何连音成员、跨小节范围或无法精确表示的时值。
- 支持连续休止，或者每拍数字音符集合完全相同且各相邻拍逐弦有 Tie 的持续音。其他音符序列、数字与休止混合、x 或未 Tie 的重复拨弦均拒绝，避免丢失音高和起音次数。
- 合并保留首拍与首拍 Note ID，移除后续成员和范围内部 Tie。外部进入连接映射至合并音符，外部离开连接从末拍映射至合并音符；跨范围区间端点映射至首拍。
- 首拍歌词/和弦/单点技巧保留。后续拍存在歌词、和弦、独立单音/Beat 技巧，或区间在范围内部开始/结束而无法无歧义表达时拒绝。不会将不同歌词拼接、覆盖和弦或扩大局部技巧范围。
- 合并前后小节容量及范围外 Beat tick 不变。选区折叠至保留的首拍；失败保持原选区、历史及文档。

### 2.3 复制快照

- 在现有选区上取涉及的完整 Beat，首版限定同小节连续范围，不根据弦矩形裁剪音符；界面明确“复制拍点（含全部弦）”。跨小节乐句继续使用 B 阶段完整小节复制。
- 新增纯函数 `createBeatClipboard(document, range)`，返回经过校验的独立值快照或错误。快照包含 Beat/Note、相对 tick、总实际时长、完整连音组、歌词、和弦和完整包含的技巧。
- 若源范围只包含部分连音组，拒绝复制；跨边界技巧按 B 阶段规则遗漏并返回结构化说明，同一关系只报告一次。孤立快照不能保留指向源范围之外的引用。
- 复制时深拷贝，粘贴时统一重建所有实体 ID；源文档随后修改、删除或撤销均不改变已经复制的内容。
- 剪贴板属于当前编辑会话的临时状态，不写入 document、不经 `onChange` 通知、不写系统剪贴板。外部文档替换或会话销毁清空；普通 undo/redo 不清空。
- 快照具有独立格式标识和版本，核心粘贴入口运行时校验形状、引用、时值、连音和技巧，不能只相信页面的 TypeScript 类型。首版仅接受当前会话 UI 产生的格式。

### 2.4 插入粘贴

- `beat.paste` 接收快照、目标小节、目标 Beat ID 和 `mode: "insert" | "overwrite"`。插入模式在目标拍之前插入全部快照，目标拍作为保留的后续内容。
- 不插入连音组内部。插入只消费右侧未承载歌词/和弦/连音/技巧及显式目标的普通尾部容量休止；不足时拒绝，不压缩其他音符，不新增小节。
- 复用核心时间轴协调器并补齐“技巧锚点也属于受保护内容”的判定；现有 `getFixedPrefixLength` 只覆盖文本/连音，不能直接用于消费带技巧的休止。
- 被消费尾部若为合法可拆的普通休止，可精确生成剩余时值休止；不能表示时拒绝。保留其余 Beat/Note ID 和顺序，统一计算新 tick。
- 插入打断既有 Tie 或使其他关系失效时，复用结构化影响提示，明确报告清理；若新副本技巧与目标现有技巧冲突，整次拒绝。

### 2.5 覆盖粘贴

- 从目标 Beat 起覆盖与快照总实际时长相等的连续完整 Beat。末端必须落在已有 Beat 边界；不能精确对齐或超出小节时拒绝，首版不自动拆目标拍。
- 覆盖范围涉及连音时必须完整包含整个连音组；部分覆盖拒绝。可覆盖的目标音符、歌词、和弦及组内技巧由副本整体替换，不做混合拼接。
- 预览显示目标拍数、时长及被替换文本/技巧摘要。实际覆盖有音乐内容的范围须由用户明确选择“确认覆盖”，沿用现有覆盖确认表达。
- 删除目标范围失效的外部技巧关系，输出 `technique.removed`；副本边界遗漏沿用复制摘要。不把旧关系自动连接到新音符。
- 页面预览与实际命令共用纯规划函数；提交基于当前文档再次规划和校验，预览过期不采用旧结果。一次提交失败不产生部分副本。

## 3. 半音推弦及 schema

- `bend.semitones` 从固定 `2` 扩展为 `1 | 2`；半音表示提高一个半音，全音维持两个半音。0、小数、负数和大于 2 均拒绝。
- 保持数字音符约束，x 不能推弦；已有同音符技巧冲突与重复规则继续统一使用 `validateTechnique`。
- 核心 layout 按参数输出 `1/2` 或 `Full`，同步测量文本外框、最小宽度、命中和视觉边界。SVG 层只消费核心结果，打印复用相同几何。
- 工具栏将“全音推弦”改为“推弦”，增加“半音 / 全音”选择；默认全音兼容原行为。选中已有推弦时读取实际参数，通过 `technique.update` 原位修改，同值为 no-op。
- 因持久化技巧取值扩展，正式 schema 升到 **7**。loader 只接受 schema 7；`upgradeDocumentToCurrent` 显式支持 4/5/6 → 7，不自动迁移。
- 旧格式校验须冻结旧 bend 为 `semitones: 2`，不可因为复用新 schema 而在旧版本中接受半音值。schema 6 保留现有作者/调性；4/5 按既有规则补字段，旧全音推弦及全部音乐 ID 保持不变。
- 所有内置示例及测试夹具同步版本；clipboard 格式和 document schema 分别管理，不持久化 clipboard。

## 4. 模块与命令边界

| 位置                         | 职责                                                                               |
| ---------------------------- | ---------------------------------------------------------------------------------- |
| 核心 `beat-structure.ts`     | 拆分/合并纯规划、精确时值表示、引用映射与语义拒绝                                  |
| 核心 `beat-clipboard.ts`     | 快照生成与运行时校验、完整对象提取、复制引用映射                                   |
| 核心 `beat-paste.ts`         | 插入/覆盖预览与执行共用规划、容量和目标边界校验                                    |
| 核心现有命令入口             | `beat.split`、`beat.mergeRange`、`beat.paste` 分发，最终 schema/语义守卫及 effects |
| 现有时间轴/技巧/effects 模块 | 复用实际时长、保护锚点、技巧合法性和结构化影响，禁止页面另写 tick 算法             |
| 网站 session store           | 会话内快照生命周期、成功选区更新、历史与宿主一次通知                               |
| 网站 Beat 工具区             | 拆分、合并、复制、两种粘贴及预览；禁用原因可读                                     |
| 技巧工具栏/核心 layout       | 推弦参数编辑与一致的标注、bounds 和命中                                            |

首版结构命令不改变小节拍号、段落标记或曲首信息。拆分/合并导致原选区 ID 消失时，由核心返回明确的新目标，适配层在成功后更新；失败不移动选区。

新增结构化摘要包括拆分前后拍数、合并范围、粘贴模式/位置/拍数、实际重排与技巧遗漏/清理。位置基于编辑前文档；no-op/失败没有成功摘要。原技巧 effect 继续使用，不重复报告。

文本/设置草稿活跃或 IME 输入中禁用结构命令；复制、粘贴和切换工具不能绕过草稿保护。计时品位草稿在结构操作前取消，避免旧 Beat 引用回写。首版以显式按钮交付，避免接管文本框或系统剪贴板快捷键。

## 5. 实施顺序

### 补充：每个谱行右侧竖线

按用户补充，每个 system 右侧增加一条“｜”竖线，作为该谱行的视觉收边。本次只补充方案，不修改代码。

- 横坐标取最终 system 的实际右边界 `system.x + system.width`，不固定到纸张右侧；稀疏末行和超宽小节行均使用各自实际宽度。
- 起点取当前 system 第一弦的最终 Y；终点取最终布局的 `system.y + system.height`。这里的“system 行结束”按整行布局底部解释，包含下方节奏、歌词及该行内部底部留白，不包含下一行之间的 `systemGapY`；不延伸到第一弦上方的和弦、简谱或技巧区域。
- 每行分别绘制，不连成跨 system 的整页竖线；无歌词等下方内容时也遵循实际 system 高度。
- 使用 SVG line，线色和线宽沿用普通单小节线。末小节已有小节线、终止线或反复线时保留其音乐记号，重合的普通竖线段避免重复叠画，只延伸视觉收边，不改变持久化 `barline` 类型。
- 核心在简谱/歌词、技巧、谱首平移和整行高度全部确定后生成最终几何，页面与打印只消费布局结果；描边外框纳入最终文档边界，避免最右像素裁切。
- 竖线不成为 Note/Beat/技巧命中目标，不影响选区、拖选或历史。
- 验收覆盖多行、有/无歌词、多个歌词段号、稀疏末行、超宽单小节、末端终止/反复线以及紧凑/舒适排版；核对起点为第一弦、终点为该行底部、没有跨行延伸或右缘裁切。

- 会话：一次命令一次历史和通知，失败无变更，撤销/重做恢复全部音乐关系；替换清空 clipboard，普通历史不清空；取消旧计时草稿及音乐文本保护。
- `pnpm test`、`pnpm type-check`、`pnpm lint`、`pnpm build`、`git diff --check` 全部通过。
- 简谱连续/单拍录入、跨小节映射、预览覆盖与草稿保护、结构编辑保真按配套方案验收。
- 桌面 1440×1000 混合谱完成五项能力的实际交互，覆盖拒绝和撤销/重做，紧凑/舒适排版及跨 system 技巧无覆盖，console warn/error 为空。
- 100 小节谱进行编辑/复用基线测量并保留机器、数据与方法；最终阈值、多浏览器、真实系统 IME 及系统打印/PDF 仍在 7.2 验收，不以单元测试替代。

## 7. 审查重点

本方案建议确认以下三项产品边界后实施：

1. 首版 Beat 范围限定同小节；跨小节乐句继续复制完整小节。
2. 拆分保持持续音语义，合并仅接受休止或有完整 Tie 的同音集合；无法保真的情况拒绝。
3. 插入容量不足直接拒绝；覆盖必须精确落在已有拍边界且显式确认，不隐式压缩、拆拍或扩展小节。

若要求任意音符序列合并、跨小节 Beat 粘贴或容量不足自动扩展，需要在审查时调整本方案，不能在实现中扩大默认范围。
