# MVP v7.2 范围与实现基础分析

> 2026-10-12，基于当前 worktree 提交 `2b52c01`。本轮为仓库静态分析，未运行性能测量、浏览器或系统打印验收。本文件不是已批准的实施技术方案。

> 后续修订：用户已将输出目标改为 A4 图片；本文保留初始分析，当前执行范围以 [图片输出修订技术方案](./20261012_MVP7.2分页输出与编辑器质量技术方案.md) 为准，PDF/系统打印不再是交付门槛。

## 1. 结论与范围

v7.2 的目标是可靠输出和编辑器最终质量，主要对应 G06、G07：

- A4 纵向分页、打印及 PDF 输出，完整保留标题、小节标识、技巧、歌词和和弦。
- 100 小节混合谱的浏览、编辑、复制、历史操作及输出性能。
- 桌面浏览器、缩放、真实中文输入法和基础无障碍验收。

作品新建/管理、文件打开/保存、持久化恢复、播放、多轨、云端作品库和移动端不在范围内。乐谱 PDF 输出与领域文档文件保存属于不同能力。

## 2. 当前基础与缺口

| 领域 | 当前代码基础 | v7.2 缺口 |
| --- | --- | --- |
| 整谱布局 | `src/layout/index.ts` 的 `buildLayout` 生成完整 systems、首部和命中索引 | 没有 page 模型、页容量或分页算法 |
| 横向换行 | `system-layout.ts` 按小节固有宽度断行；超宽小节独占一行并保留宽度 | 输出超宽处理需要明确策略 |
| 垂直空间 | `system-content-layout.ts` 已协调技巧、和弦、歌词及段落标记，提供最终 system 高度/visualBounds | 分页必须消费最终几何，不能仅按六根弦线高度分组 |
| 跨行技巧 | 技巧已按 system 拆段，带 continuation 和最终路径 | 跨页需保持这些片段和续接关系；每页 SVG marker 引用要可靠 |
| 页面打印 | `EditorShell/index.tsx` 直接 `window.print()`；一个 SVG 展示全谱 | 无逐页输出容器和明确页边界，无法保证 system 不被截断 |
| 纸张样式 | 210mm 纸张、8mm padding、A4 print CSS；布局宽度为 733 逻辑单位 | 毫米/逻辑单位换算、页眉页脚、首页标题空间尚未形成统一契约 |
| 字体 | `music-text-metrics.ts` 等待 fonts.ready，用 SVG getBBox 度量并缓存；字体加载事件触发重测 | 打印前需要稳定快照及字体失败处理，不能仅依靠警告文字 |
| 编辑 | 稳定业务 ID、命中/选区、键盘、草稿、撤销重做已经存在 | 验收跨行、侧栏切换、拖动取消、IME 候选过程及浏览器缩放 |
| 无障碍 | 工具栏/按钮已有 aria-label，错误与状态有 role；谱面可聚焦 | 核查可见焦点、Tab 顺序、当前位置播报、禁用原因及键盘可达性 |
| 长谱 | useMemo 按文档生成整谱；全部 SVG 图元挂载；历史存储文档快照且有限长 | 需要分别测量领域命令、布局、字体度量、React 提交及历史内存 |

纸张外观不等于可靠分页。当前超宽提示也明确写着“尚不保证 A4 打印完整输出”。

## 4. 推荐技术方向（待方案审查）

### 4.1 输出路线

首版建议使用浏览器逐页打印，并由系统打印对话框另存 PDF。界面必须清楚说明此路径，不宣称点击后直接下载 PDF。直接生成 PDF 文件暂不作为默认方案；若需求要求一键下载，需重新评估字体嵌入、SVG 支持和渲染一致性。

保留当前连续谱编辑视图，新增只读分页预览和打印视图。二者复用音乐渲染组件与布局配置；分页预览不创建第二份可编辑文档或历史。

### 4.2 分页核心

建议核心提供纯函数分页器，输入最终 layout 和纸张参数，输出 pages、system 引用及页面平移量、首部/页脚和诊断。它不读取 DOM、不修改文档、不重新推导音符或技巧路径。

- 在给定 A4 内容宽度下先完成整谱布局，再按最终完整 system 高度贪心装页。
- 一个 system 不跨页；首页单独计算谱首标题和信息占位，后续页配置页眉/页码。
- 每个 system 恰好出现一次，顺序不变；页间只平移几何，稳定业务 ID 不变。
- 使用最终 visualBounds 核对所有元素是否越界；不能把旧 systemGap 重复算入页顶。
- 跨页技巧沿用跨 system 分段；页面渲染使用变换，不通过字符串替换修改 SVG path。
- 超宽或超高 system 返回明确诊断。首版建议保留预览并阻止标记为“完整 A4 输出”，提示对应小节；不静默裁剪或无限缩小。是否提供用户主动选择的缩放/横向模式需在技术方案中落定。

### 4.3 渲染与打印协调

从 EditorShell 有限抽取共用谱首/system 音乐渲染组件。编辑视图继续装配交互图层，打印视图按 page 装配无交互音乐图层；不同 SVG 的 marker ID 需避免冲突。

打印准备应获取一次稳定文档与显示偏好快照，等待所需字体和度量稳定后生成预览，覆盖按钮和浏览器打印入口。活动输入草稿的提交/取消规则必须明确，避免预览显示用户尚未应用的内容或打印过程中重新排版。

不把整个 EditorShell 重构作为分页前置，也不预先引入虚拟滚动。分页与性能优化分别以实际问题推动。

## 5. 推荐实施切片

1. **基线与技术方案**：固定 16/100 小节混合谱、机器和浏览器版本，记录当前性能；落定纸张参数、异常策略、字体与输出契约。
2. **纯分页核心**：页面模型、确定性分组、标题/页码、边界诊断；测试页容量边界、超宽/超高、空输入、首部及跨页续接。
3. **共用渲染与输出**：只读逐页预览、打印准备、独立打印样式；核对与编辑视图的音乐内容一致性。
4. **质量补齐**：根据基线修复性能、焦点、键盘、IME 或兼容问题，再完成最终人工验收。

## 6. 验收方法与决策

100 小节谱需混合两位品位和 x、休止/附点/连音、跨行技巧、四段歌词、和弦名/指法图、长标题及段落标记；另设超宽和超高异常谱例。

记录命令计算、buildLayout、字体度量、可见更新和打印准备耗时，重复操作记录中位数及高分位；记录测试机器、数据、采样次数、浏览器版本和内存测量方法。当前尚无实测数据，不先写“已达标”或虚构阈值。

建议目标桌面浏览器为 Chrome、Edge、Safari、Firefox；具体支持矩阵待方案审查。验收覆盖紧凑/舒适、指法图显示/隐藏和常用浏览器缩放。自动化打印结果不能替代系统打印对话框及真实 IME 候选操作证据。

重点输出检查：页数/小节顺序、system 不截断、文字和箭头清楚、跨页技巧续接、页码正确、首末页无意外空白、没有选区/光标/侧栏残留，字体失败和越界有明确结果。

实施前需要审查的具体决策：

- 系统打印另存 PDF 是否满足首版输出目标。
- 8mm 边距是否保留，页眉/页脚及首页标题布局。
- 超宽/超高默认拒绝完整输出，还是增加显式可读缩放等模式。
- 目标浏览器/操作系统、基线测量方法及测量后制定的性能阈值。
- 上游 v7.1-C 与简谱能力的最终集成范围。

依据用户 AGENTS 第 4 条，v7.2 属复杂需求，需先提交正式技术方案审查后实施。本轮仅形成范围与实现基础分析。
