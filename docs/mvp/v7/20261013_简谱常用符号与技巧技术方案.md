# 简谱常用符号与技巧技术方案

日期：2026-10-13。状态：待审查，未实施。

2026-10-13 二次复核：已对照命令、ID 工厂、旧文件升级、拆合 Beat、谱行断行、命中和文件预算补充落地契约。第 12–17 节是实施约束；与前文概述冲突时，以这些具体规则为准。审查通过前不改业务代码。

本方案承接并扩展《简谱时值与连梁优化技术方案》，作为后续实施的主方案。目标是让简谱具备常用节奏、音高、结构边界和连接技巧的完整表达，继续与 TAB 共用 Beat 时间轴。

## 1. 推荐方案

- 复用 Beat 的时值、附点、实际 tick，复用小节拍号、连音组、轨道小节线及谱首 `1=调性`。
- 为简谱建立独立的音符身份和技巧关系：同音延音线、连音线及延长记号；不根据 TAB 品位或技巧猜测手工简谱连接。
- 核心统一生成符号、曲线、边界、避让与跨行分段；编辑、打印和图片导出消费同一份布局。
- 分批实施，但本次完整验收须包含长时值、小节线及延音/连音，不能只补减时线就宣布完成。
- 不建设独立简谱时间轴，不自动转调，不改变现有同 Beat 多音共享时值的约定。

## 2. 当前事实与差距

| 能力 | 当前工作区 | 本次变化 |
| --- | --- | --- |
| 数字、升降号、高低八度点 | tokens 支持 `#`/`b` 和最多三层八度点，已有文字/圆点布局 | 规范音乐符号字形，增加还原号 |
| 时值与附点 | Beat 已有 rhythm，简谱布局未消费 | 生成减时线、连梁、长时值和时值附点 |
| 延音 | `-` 只是手工展示 token；TAB tie 引用 Note | 分开处理延时横线、同音延音线与延长记号 |
| 连音 | 小节已有 tuplets；简谱没有连音曲线 | 投影节奏连音，新增简谱乐句连音线 |
| 小节线 | measure.barline 有单线、双线、终止和三种反复；轨道有谱首反复 | 为简谱行增加独立结构边界几何 |
| 拍号与调性 | 小节有拍号；谱首已有 `1=keySignature` | 简谱行首及拍号变化处显示拍号，保留谱首调性 |
| 导出 | scene 支持线、圆和 path，Canvas 用 Path2D | 接入所有简谱符号与曲线 |

当前 schema 版本为 7。简谱仅保存 `{ tokens: string[] }`，没有可引用的单个简谱音符 ID。TAB tie 要求同弦同品位且相邻 Beat，不能作为简谱连音关系的事实源。现有 loader 已提供旧版本显式升级入口，实施时应扩展这一入口，而不是新增隐式加载迁移。

## 3. 术语与首版范围

### 3.1 延音和连音必须区分

| 名称 | 语义与形状 | 数据来源 |
| --- | --- | --- |
| 延时横线 | 二分、全音等长音在数字右侧的 `-` | Beat rhythm 派生 |
| 延音线（Tie） | 连接相邻同音，合并持续演奏，使用短弧线 | 新增简谱音符连接 |
| 连音线（Slur） | 表示连贯演奏或乐句，允许不同音高，使用范围弧线 | 新增简谱 Beat 范围 |
| 节奏连音（Tuplet） | 三连音等实际/书写时长比例，数字加括号或连梁 | 现有 measure.tuplets |
| 延长记号（Fermata） | 弧线下加一点，表示自由延长 | 新增简谱 Beat 标记 |

延长记号不直接修改 tick 或小节容量；本次只记录演奏含义，不新增播放时长策略。Let Ring、击弦/勾弦也不自动转换为 Tie 或 Slur。

### 3.2 本次必需能力

1. `1–7`、休止 `0`、高低八度点、升号 `♯`、降号 `♭`、还原号 `♮`。
2. 四分至三十二分的减时线与自动连梁，单/双附点，二分及全音的延时横线，长休止。
3. 同音延音线、乐句连音线、现有比例的节奏连音、延长记号。
4. 单小节线、双小节线、终止线、起始/结束/双向反复线、谱首反复。
5. 谱首调性、简谱拍号，以及拍号变化处的标记。
6. 跨小节及跨谱行技巧、分页导出、编辑与撤销/复制粘贴完整支持。

### 3.3 后续可扩展

重音、断音、保持音、呼吸记号、力度及渐强/渐弱、速度变化、倚音、颤音、滑音、房子及 D.C./D.S./Coda 另列后续切片；此次预留标记模型扩展方式，不默认为本次已支持。小调 `6=…`、中途转调、重升/重降、多声部及独立简谱节奏同样不纳入首版。

## 4. 记谱规则

### 4.1 音高与输入

- 数字 `1–7` 是相对音级，高低点表达相对八度；本次继续使用手工简谱数据。
- 输入沿用 `#1`、`b3`、`1'`、`1.`；新增 `n1` 作为还原号编码。允许粘贴 `♯1`、`♭3`、`♮1` 并规范化为 ASCII 前缀，显示时使用音乐符号。
- `.` 始终是低音编码；时值附点只能来自 Beat，不将 `1.` 改解释为附点。
- 每个简谱音的升降前缀是显式音高偏移，不自动把前一音的升降状态传播到后续 token；无前缀与 `n` 都回到该音级原位，`n` 额外显示还原号。不隐藏重复升降号，帮助文字说明此输入约定。
- `1=…` 沿用现有谱首字段，表示数字 1 的基准音名。字段为空时不猜调性；修改基准不自动改写简谱或 TAB。
- 不承诺绝对八度/MIDI：现有 `1=C` 没有基准八度。Tie 首版按音级、相对八度和半音偏移一致校验，不引入同音异名推断。
- 多音仍以 `+` 分组、保留顺序与重复、共用一个 Beat 时值；本次维持横排，Tie 可连接其中指定音。真正的多声部和分音符独立时值留后续。

### 4.2 节奏与长时值

- 八分/十六分/三十二分分别一/二/三层减时线；孤立短音也生成完整短线。
- 按现有拍号 profile、实际 tick 与 tuplet 身份分组；缺项、休止、长音、显式 `-`、小节边界断开共享连梁。短休止自身有减时线。
- 混合层级逐层连接，额外孤立层覆盖本数字组宽度；不得直接复用 TAB 符干/旗帜几何或 TAB 附点断梁策略。
- 时值附点在数字组右侧；低音点位于最下层减时线下方。长音的附点采用与延时横线不重复计时的规范表示。
- 无附点二分显示 `1 -`、全音显示 `1 - - -`；附点二分推荐 `1 - -`，保持三份四分单位的直观表达。长值先拆完整四分单位，剩余半个/四分之三个单位用最后一个延时单元的单/双附点表达，不把附点全部加在起始数字上造成误读。

| 书写时值 | 四分单位数 | 建议显示（`·` 在此表示时值附点，不是输入编码） |
| --- | --- | --- |
| 四分单附点/双附点 | 1.5 / 1.75 | `1·` / `1··` |
| 二分无附点/单附点/双附点 | 2 / 3 / 3.5 | `1 -` / `1 - -` / `1 - -·` |
| 全音无附点/单附点/双附点 | 4 / 6 / 7 | `1 - - -` / `1 - - - - -` / `1 - - - - - -` |

双附点二分的末延时单元带单附点，合计 3.5 个四分单位。表中全音附点值仅在小节容量允许时出现。此表是待审查的项目排版约定，实施前以实际谱例确认可读性。
- 派生延时横线布局在该 Beat 占用范围内，不生成新 Beat，不影响现有歌词映射；横向空间不足时贡献最小列宽，不能挤到下一 Beat。
- 二分休止显示 `0 0`，全音休止显示 `0 0 0 0`，以派生休止单元表达时长，不使用长音的延时横线。剩余分数采用有减时线/附点的休止单元。
- tuplet 长值优先保留书写时值和比例标记，不将实际 tick 分解成普通四分单位；须有长值连音谱例验收。
- 已有显式 `-` 保留为“当前 Beat 内的延续展示项”，也按 Beat 时值展开自身所占时长；不回溯修改前 Beat，不自动建立 Tie。同一 Beat 已是 `-` 时不得再额外添加音符头。首项或休止后的 `-` 给非阻断的内容提示，兼容旧文档。

### 4.3 延音线与连音线

**Tie：**

- 两端引用明确的简谱音符；必须按时间先后、位于同轨相邻 Beat、实际时间连续且音高描述一致。
- 不能连接休止或 `-`，不能跨缺失简谱项；不因两项数字相同就自动添加。
- 支持跨小节和谱行；首版拒绝跨反复/终止结构边界，避免把书写邻接当作演奏连续。
- 允许一音有一条入线和一条出线形成链；同方向重复端点关系拒绝。

**Slur：**

- 引用起止 Beat，覆盖其完整简谱音组，允许音高不同及跨小节；首版不细分声部。
- 两端必须有普通简谱音；中间可包含短休止或缺项，但必须至少有两项普通音，预览完整范围，不悄悄截短。
- 支持包含关系的嵌套；首版拒绝交叉而非嵌套的范围，避免含糊的单声部连音布局。
- 默认上方绘制，Tie 更靠近音符、Slur 在外侧；与同一范围的 Tie 可同时存在。
- 允许跨普通/双小节线，首版拒绝跨反复/终止结构边界。

跨行后保存的领域关系仍只有一份，layout 按 system 拆成 start/middle/end 段；续接段进入页边界裁切和净空规划，不能留下一段悬空曲线。

### 4.4 延长记号与节奏连音

- Fermata 标记整个 Beat 音组，可用于音或休止；显式 `-` 不允许单独添加，改在对应正式音或休止项上添加。
- Tuplet 使用现有 actual/normal，常规 `3:2` 等显示实际数量，非默认比例显示 `actual:normal`，避免两种五连音比例显示相同却含义不同。
- Tuplet 的完整成员都有简谱/显式休止/延续项时投影；成员缺项时显示带缺项提示的完整括号范围，不能缩成部分成员并保留原数字。
- 与连梁完全覆盖的常规组可省略括号，数字必须保留；首版为确定性与易读性默认保留括号。

### 4.5 小节线、拍号与结构

- 简谱与 TAB 小节边界使用同一横坐标，类型只读自 measure.barline/track.startBarline，简谱不新增独立小节线数据。
- 在简谱 lane 绘制独立短竖线，覆盖本行数字、减时线和低音点区域；不将 TAB 竖线贯穿歌词，防止与段落文字交叉。
- 反复点位于简谱行中部的固定上下位置，符号留白参与小节首尾 inset。
- 普通相邻小节只输出一次共享边界；换行时右边界和次行左续接根据边界类型规划，反复点不重复成两次反复。
- 即使某小节没有简谱，只要当前 system 有简谱内容或简谱编辑行，就保留其小节分隔，不能把空小节视觉吞掉。整个 system 无简谱且未编辑时不预留 lane。
- 第一简谱行显示拍号；后续行首显示当前有效拍号，行内仅在拍号变化处显示。首行与已有谱首信息的重复保留为可独立读行的设计选择。
- 本次不新增反复次数或播放跳转语义，反复符号复用已有记谱事实。

## 5. 数据模型设计

### 5.1 为什么增加音符身份

Beat ID 只能定位一组数字，数组索引会在改序/增删多音时变化。Tie 如果绑定 tokenIndex，会在编辑后连接到错误音。因此建议增加稳定的简谱 item ID，并用同一模型承载休止及显式延续项。

建议新模型（名称待实现时与仓库统一）：

```ts
/** token 是唯一音高编码，解析结果只在内存派生，避免双份音高事实。 */
interface NumberedItem {
  id: string;
  token: string;
}

interface NumberedNotation {
  items: NumberedItem[];
}

/** 简谱演奏连接独立于引用 TAB Note 的吉他技巧。 */
type NumberedMark =
  | { id: string; type: "tie"; fromItemId: string; toItemId: string }
  | { id: string; type: "slur"; fromBeatId: string; toBeatId: string }
  | { id: string; type: "fermata"; beatId: string };
```

- `Beat.numberedNotation` 改存 items，轨道新增 `numberedMarks`；item ID 全文档唯一。
- 不同时持久化 `tokens` 和 `items`。现有解析、连续输入 UI、复制和布局通过适配函数读取 token 列表；原输入语法保留。
- 相同内容 no-op 不换 ID。明确针对单音的编辑保留 ID；批量文本替换遇到相同有序 token 列表时整组保持，发生变化时整组重建。多音改序不按数组位置保留部分 ID，避免重复音使关系错绑；规则详见第 12 节。
- 改变被 Tie 引用的音高后重新校验。删除、重排或整体替换影响技巧时先生成影响预览，列出会失效的关系；用户确认后在同一命令中删除受影响标记并修改内容，未确认则整批拒绝。
- Slur/Fermata 端点 Beat 内容变化同样重新校验；禁止保留悬空引用。
- 不存像素、path、systemIndex、lane 或拆分段，这些全部由布局派生。

### 5.2 版本与旧文件

- 这是持久化结构变更，预计升级至 schema 8；实际版本号以实施时工作区版本为准，不与并行文件导入/导出修改争抢版本号。
- 旧版本通过现有显式升级流程转换，旧 tokens 按原顺序生成 item ID，新增标记集合为空；不从 TAB 自动生成 Tie，不猜测 `-` 关系。
- 对现有显式 4/5/6 升级入口统一核对输出目标，补上 7→新版本；普通 loader 继续按项目策略校验版本。
- 旧文件与新文件保持清晰版本边界；保存新文件时使用新 schema，导入预览显示升级结果。

## 6. 核心与渲染架构

建议拆分为节奏语义、音符/符号布局、结构边界布局、连接布局四层纯函数，避免把新增能力全部塞进 `layoutNumbered`。

布局流程：

1. 解析 token，测量数字、音乐升降号、长时值组合、拍号、连音数字。
2. 将符号宽度及小节边界留白计入 spacing，再进行自动换行。
3. 生成数字、减时线、八度点、时值附点和派生长值单元；确定简谱基础 lane。
4. 生成 tuplet/Fermata 和 Tie/Slur，按区间冲突分配上方 lane；曲线避开高音点和括号，使用确定性 Bézier 几何。
5. 合并整个简谱行 bounds，安放在 TAB/节奏/技巧下方；低音点下面安排歌词，并统一平移所有图元。
6. 生成简谱小节线与反复点，不延伸覆盖上方技巧曲线；更新 measure/system/document bounds、命中和分页。

建议扩展小节的简谱布局容器，分开保存 items、beamSegments、结构边界和 tuplet；跨小节连接放在 system 级 `numberedMarkSegments`。保留每个图元的归属 ID，不给共享连梁强行指定一个 Beat。

避让顺序为：数字与升降号 → 高/低八度和时值符号 → Tie → tuplet/Fermata → Slur 外层。以上是冲突处理优先级，最终 Y 由实际 bounds 决定，不以固定高度假定所有谱例相同。

音乐符号优先复用现有 Bravura/SMuFL 字体链路，验证网页字体加载、度量与 Canvas 输出。字体尚未准备就绪时不能以错误回退度量生成最终导出；不把 Unicode 字符存在当成字形可用的证明。

`MusicTextLayer.tsx` 与 `score-scene.ts` 只投影核心结果，Canvas 复用已支持的 Path2D。曲线包围框使用控制点的保守边界或解析极值，包含线宽，避免弧顶跨页裁切。

## 7. 编辑交互与领域命令

- 保持单拍/连续录入；音高符号提供升、降、还原和八度按钮，按钮作用于明确选中的简谱 item。
- 新增“简谱技巧”入口：延音线、连音线、延长记号。与 TAB 技巧保持明确的操作目标和中文标签。
- 单音 Tie：选起音 → 进入连接模式 → 点合法目标 → 预览并提交；多音组必须明确选中其中一个 item，禁止默认绑第一个数字。
- Slur：选择起止 Beat 并预览范围；Fermata：当前 Beat 切换添加/移除。
- 无效目标显示具体原因；Esc 取消，不创建半条关系。预览图元不写文档。
- 选中已有曲线可删除；hitIndex 优先处理当前简谱编辑目标，扩大曲线点击容差但不扩大正文实际 visual bounds。
- 每个动作通过核心 command 校验并产生一次历史提交；React 使用 Hooks，编辑草稿继续遵守 IME/脏草稿保护。
- 小节线和拍号沿用现有结构编辑入口，简谱只同步反映；不产生第二套控件状态。
- 复制完整范围时复制内部关系并重建 ID；跨选区边界的关系不携带并在预览提示。覆盖粘贴清理受影响关系，未确认不修改。
- 删除/拆分/合并 Beat、改拍号、改时值、换宿主文档都要走引用维护：Tie 检查邻接与连续，Slur 检查端点与结构边界，tuplets 遵循现有规则。不能仅更新 token 就遗漏标记。

## 8. 实施批次与审查关口

## 12. 领域与提交契约（复核补充）

### 12.1 身份和合法性

- 新版本 `numberedNotation.items` 数量仍为 1–8；`0`、`-` 必须独占一组，无简谱时省略字段，不保存空数组。普通音 token 规范形式为 `[#bn]?[1-7]` 加零至三层同方向八度后缀；不得混合上下八度点。
- 解析函数先将音乐升降符号规范化，再使用现有长度/批次数预算校验；持久化只接受规范形式。输入框粘贴可以规范化，JSON 文件则严格校验，不在文件导入中修正非法 token，以免绕过冻结的旧格式规则。
- item/mark ID 非空，并与所有现有实体共用唯一性集合。扩展 `ILXMIdFactory` 的 `createNumberedItemId`、`createNumberedMarkId`，采用现有基于 revision 的递增命名机制；同步扩展 collectEntityIds 和 semantic-validation，禁止 UI 用随机 ID。
- 建立每轨一次性的索引：item→Beat、Beat→小节与顺序、Beat 起止绝对 tick、标记区间。跨小节时间比较使用累计小节容量加局部 tick，不能直接比较两个小节的局部 tick。
- Tie 比较 `(degree, octaveOffset, alteration)`；无前缀与 `n` 的 alteration 均为 0。`#1` 与 `b2` 不作为同一记谱音接受。same-track、相邻 Beat、绝对 tick 连续及结构边界均须通过。
- 每个 item 至多一条入 Tie 和一条出 Tie；Slur 同起止范围不重复，交叉范围 `a<c<b<d` 拒绝，共享端点但不交叉允许；Fermata 每 Beat 最多一个。同 Beat 内两个 item 不能互建 Tie。
- Slur 最多八层包含嵌套，超出时在添加/导入校验中返回明确错误。删除或修改任一关系后使用相同校验函数验证整轨，loader 与 commands 不分别实现规则。
- 新错误码至少覆盖 `NUMBERED_ITEM_NOT_FOUND`、`NUMBERED_MARK_TARGET_INVALID`、`NUMBERED_TIE_PITCH_MISMATCH`、`NUMBERED_TIE_NOT_CONTIGUOUS`、`NUMBERED_MARK_CROSSES_REPEAT`、`NUMBERED_SLUR_CROSSES_RANGE`、`NUMBERED_MARK_DUPLICATE`、`NUMBERED_MARK_IMPACT_REQUIRED`、`STALE_NUMBERED_PLAN`，错误携带字段路径和中文信息。

### 12.2 可执行接口

以下为契约草案，命名可统一仓库前缀，但语义不能省略：

```ts
/** 预览不得修改文档或消耗全局 ID；变化确认绑定当前文档版本。 */
interface NumberedImpactPlan {
  documentRevision: number;
  affectedBeatIds: string[];
  removedMarkIds: string[];
  changedMarkIds: string[];
  warnings: { code: string; message: string; beatId?: string }[];
}

// parseNumberedToken / getNumberedTokens：唯一编解码适配层。
// buildNumberedIndex / validateNumberedMarks：纯领域索引与共享校验。
// planNumberedChange(document, operation)：纯预览，产生影响清单。
// applyNumberedChange(document, operation, confirmation?, factory)：原子提交。
```

核心 command 增加：`numberedNotation.setItem`（明确 item 的音高修改）、`numberedMark.add/update/remove`。现有 set/remove/setSequence 继续接受 tokens，不强迫表单操作新的持久化数组；由核心生成/保留 item 身份。

文本批量替换规则冻结为：相同完整序列 no-op；任何差异整组重建 ID，相关 Tie 进入删除影响清单；Slur/Fermata 根据 Beat 最终内容重新校验并保留仍合法的关系。单 item 命令保留身份，修改导致 Tie 不合法时同样进入影响清单。`_` 只跳过，不重建身份。

覆盖许可 `allowOverwrite` 与删除技巧确认分开；允许覆盖不等于同意删除技巧。确认提交携带 `expectedRevision` 与确认的完整 removedMarkIds/changedMarkIds；核心重新规划后必须精确匹配，文档变化则拒绝，不用旧预览直接执行。

网站在宿主替换、撤销、重做时清空待确认计划和连接模式，另外使用会话 generation 防止替换文档后恰巧 revision 相同。预览与提交不得跨会话沿用。无影响的操作直接提交；只有确有关系丢失/迁移时才显示影响确认，不为所有普通编辑增加弹窗。

技巧选择器提供可聚焦的 item 列表，显示完整 token 与音组内序号，重复音也能区分。方向键只在选择器获得焦点时切换 item，Enter 在连接模式中选定起点/终点，Esc 退出；Delete 仅在标记已选中且无文本/IME 输入时删除标记。各按钮提供中文可访问名称，键盘流程与鼠标走同一核心命令，不拦截原 TAB 全局快捷键。

失败、不确认、stale、no-op 均不提交历史、不递增 revision、不触发 onChange；成功动作（含内容修改及关系清理）只产生一次 revision 和一次历史快照。Undo 恢复原 ID 和关系，Redo 使用已保存的快照，不再次分配 ID。

### 12.3 结构操作行为表

| 操作 | 明确行为 |
| --- | --- |
| 修改 Beat 时值/附点 | 保留 item ID，重算几何；重新校验全部受影响连接，非法关系进入影响预览 |
| 改小节线/谱首反复 | 不改简谱内容；新边界使 Tie/Slur 非法时先确认清理，不能只改 TAB 边界 |
| 删除简谱/删除 Beat/删除小节 | 清理端点不存在的关系；内部仍完整的 Slur 保留，变短且合法的范围保留；预览列明实际变化，不自动把端点移到“最近的音” |
| 替换拍号导致重建 Beat | 沿用现有时间轴替换规则，显式列出清除的简谱项和标记；同一次确认、同一个命令完成 |
| 拆分普通简谱音 Beat | 第一段保留 item ID，第二段克隆 token 并创建新 ID；逐 item 添加简谱 Tie；原入 Tie 留在第一段，原出 Tie 从第二段出发；这是显式持续音拆分结果，不是从 TAB 推断技巧 |
| 拆分 `0` / `-` Beat | 两段分别克隆同类展示项，不生成 Tie；原 Fermata 移至第二段；Slur 终点移至第二段、起点保留第一段 |
| 拆分其他普通音标记 | 原 Fermata 移至第二段，Slur 起点保留第一段、终点移至第二段；迁移计入 changedMarkIds，预览确认后提交 |
| 合并 Beat | 先满足现有 TAB 合并规则，再满足下述简谱规则；不能因 TAB 有 Tie 就认定简谱也能合并 |
| 小节复制/完整范围粘贴 | 所有 item/mark ID 重建，内部关系用 ID 映射重接；来源标记不修改 |
| 部分范围复制/覆盖 | 只携带两端都在范围内的 Tie/Slur 和范围内 Fermata；跨边界关系不复制并提示。覆盖后清理目标失效关系，确认后原子提交 |

合并规则：简谱普通音只有在各 Beat 音组由完整一一对应的 Tie 链连接时可合并，不能按 token 相同推断持续音；通过 Tie 关系映射后保留首 Beat items，消耗内部 Tie，外部入/出 Tie 迁移到保留项。全部 `0` 或全部 `-` 可分别合并。仅首 Beat 有简谱而后续为空则沿用现有保留首项的行为；其他混合有简谱/无简谱、普通音/休止/显式延续组合拒绝，避免改变起音语义。

合并范围内部的 Slur 起止关系或中途 Fermata 会丢失独立表达时拒绝合并；用户可以先移除标记再执行。只在保留范围首端或末端的 Slur 端点可迁移到首 Beat；末 Beat Fermata可迁移到首 Beat，多个 Fermata 则拒绝。所有允许迁移均写入影响清单。拆分/合并原有 tuplet 禁止规则保持。

## 14. 确定性排版规则（复核补充）

### 14.1 长值单元与锚点

每个派生单元带 `sourceBeatId`、`sourceItemId?`、`unitIndex`、`role`（note/rest/sustain）和自身书写时长。它们只存在于 layout，不进入连续录入目标遍历、复制 payload 或歌词列表。

首个数字组中心始终对齐现有 `beat.x`，延时/重复休止单元往右排列。因此宽度贡献必须是左右不对称 extents，不能把整串 `1 - - -` 居中到 Beat 并使首音脱离 TAB 锚点。末单元附点计算在该单元右侧，并计入右 extents。

先按实际字形宽度加最小间距计算组固有宽度，再将已分配的 Beat 占用范围内多余空间分配到内部间距。不能使用未拉伸的 tick→像素比例直接生成最终坐标；不可拉伸到覆盖下一 Beat 的左 extents。末 Beat 用小节内容右边界约束，保留小节线 inset。

非连音组长音按四分单位分解，末单位加单附点承载剩余 0.5、双附点承载剩余 0.75；`0` 和 `-` 使用相同单位分解但不同 role，绝不输出新的普通音符头。tuplets 按书写 rhythm 分解内部单元，再由组比例决定实际占用范围，仍不从实际 tick 反推书写符号。多音长值用一个共享延时单元，不能为每个 token 重复输出横线。

### 14.2 边界和空行

| 领域边界 | 同行 | 边界处换行 |
| --- | --- | --- |
| single / double / final | 只在前小节右侧显示一次 | 保留前行右边界；次行普通入口不复制同一右边界 |
| repeatStart | 边界右侧显示起始反复点 | 起始反复完整符号移至次行开头，前行以普通结束边界收尾 |
| repeatEnd | 边界左侧显示结束反复点 | 完整结束反复留前行末尾，次行不复制反复点 |
| repeatBoth | 左结束点、右开始点共享边界 | 拆成前行 repeatEnd、次行 repeatStart |
| track.startBarline=repeatStart | 首行开头输出一次 | 只在第一条简谱行所属轨道首边界输出，不随每行重复 |

抽取/复用现有边界语义规划，再分别投影 TAB 与简谱。小节间现有 measureGap 不代表两个不同小节线，使用唯一领域边界锚点，不沿两侧各画一条。

简谱行启用条件为“该 system 有简谱项、有简谱编辑单元，或有跨行标记/已展示 tuplet 的续接段”。Slur 穿过全空 system 时仍输出续接段及小节分隔；不得因该行无数字而丢失连接。仅承接续线的空行仍显示行首有效拍号。完全无简谱及简谱标记的文档布局保持原样。

行首拍号空间在断行前保守预留，与 TAB 行首拍号占位取最大值，不简单相加；行内拍号变化同样复用其结构占位。未知拍号继续沿用现有保守分组回退，不开放新的拍号编辑白名单。

### 14.3 曲线、lane 与命中

默认参数先采用数字字号 14、减时线厚度 1.1、层距 3、数字到首线净空 3、最末线到低音点净空 3、附点半径 1.3、曲线线宽 1、标记间净空 4（单位均为谱面逻辑像素）。所有参数放入核心 constants；最终字形 bounds 仍优先于这些最小值，不靠常量替代字体测量。

Tie 端点取被连接 item 的数字本体上缘；Slur 端点取整个起止音组的上缘；升降号与八度点参与障碍 bounds。共享组上的不同 Tie 按 item 顺序稳定分层，避免横排多音的曲线重合。

先构造零基线简谱内容，再在局部坐标中规划曲线与标记，合并上/下 bounds 后整体平移到 TAB 正文下面，最后安排歌词。不得“先放简谱数字再不断上移曲线”侵入 TAB 时值/技巧区域。系统高度与分页以全部图元为准。

区间扫描按起点、跨度、ID 稳定排序，用已占用区间分配 lane；包含关系的外层 Slur 放外侧，同层不允许可见 bounds 重叠。跨行分段按边界裁切，保持续接与成员归属；同一个 mark 可产生多个 segment，但点击任一段选择同一个 markId。

命中优先级：连接模式中的合法 item/Beat → 已启用简谱编辑中的 item/标记 → 普通音乐文本与 TAB。空白处保持原选拍规则。曲线使用 Bézier 自适应细分并按到线段距离判断（屏幕点击容差换算为逻辑坐标），不得把整块曲线 bbox 当作可点击区域覆盖中间数字。

Fermata 和升降号在已验证音乐字体缺失时使用确定性向量路径回退，回退采用相同字号与真实 bounds 参与 layout；不回退到任意系统字体。普通数字文字导出仍等待现有文字字体就绪。编辑预览允许未完成度量，正式导出必须重建已就绪的布局且校验场景完整。

一次构建先确定符号使用字形还是向量，再收集该模式对应的度量；同一个 scene 内不能混用另一模式的 bounds。字体准备完成触发整个相关 layout 重建，SVG 与导出始终使用同一构建结果。

单小节固有宽度超过 systemWidth 时沿用现有独占一行且不压缩的规则。编辑可显示超宽行；分页图片/打印输出前检查可打印区域，不能把超宽内容静默裁掉。无法容纳时返回明确的超宽小节编号，要求调整内容或输出宽度，本次不引入小节内部自动折行。

## 15. 升级、文件预算与性能（复核补充）

- 冻结 v4/v5/v6/v7 输入 schema：v7 继续只允许 tokens 和旧 token 语法，不能因新版增加 `n` 或 items 而让旧版本声明通过新版字段。旧校验通过后再纯函数升级。
- 7→新版本的 item ID 按轨道/小节/Beat/token 原顺序确定性分配，扫描全部现有 ID 并跳过碰撞；相同输入升级得到相同结果。`numberedMarks=[]`，不擅自增加连接。
- 4–6 直接生成新目标结构并保留已有 capo/作者/调性/弦范围升级规则，禁止先套未冻结的新 schema 导致旧字段遗漏或误接受。
- 文件导入检测到受支持旧版本时先生成升级预览；确认导入才替换会话。新版本合法文件直接走当前预览；未知新版本拒绝并保留当前文档。新版导出只保存当前版本，不提供有损降级。
- 文件层目前有 10 MiB、1000 小节、20000 Beat、20000 技巧及 200000 结构节点预算。将 TAB techniques 与 numberedMarks 合并计入技巧总预算；items 与派生 layout/scene 仍接受结构预算，不仅限制 JSON 音符数。
- 新 item 对象增加节点数，必须用新版导出再导入验收实际容量；未超过数量上限但超过节点/字节预算仍明确拒绝，文案列出实际触发预算，不承诺所有上限同时可达。
- 一次 layout 构建一次轨道索引，避免每条技巧反复扫描整轨；Slur 交叉校验/分层采用排序与区间扫描，禁止对 20000 标记进行全量两两比较。只为实际经过的 system 生成 segment，导出后不把 scene 写入历史。
- 以 100 小节混合谱记录相同环境的基线与新布局耗时；1000 小节进行非交互核心构建和导入预检。验收要求无无限循环、几何无 NaN，常规混合谱相对同规模原布局耗时超过 2 倍时必须分析热点并修正或给出可核实的图元数量原因，不把单次计时当硬件无关 SLA。

## 17. 二次复核结论

已补齐原方案中会阻塞实施的七类问题：稳定身份及 ID 分配、预览提交一致性、旧格式冻结、结构操作引用维护、长值不对称宽度、反复换行/跨空行、文件预算与导出字体回退。

### 17.1 实施前必须能走通的最小样例

以下为同轨同小节的局部数据片段，三个 Beat 分别为四分、四分、二分；其 tick 和 TAB 字段由完整测试 fixture 补齐，不将片段直接当作完整文档加载：

```json
{
  "beats": [
    { "id": "b1", "numberedNotation": { "items": [{ "id": "ni1", "token": "1" }] } },
    { "id": "b2", "numberedNotation": { "items": [{ "id": "ni2", "token": "1" }] } },
    { "id": "b3", "numberedNotation": { "items": [{ "id": "ni3", "token": "3'" }] } }
  ],
  "numberedMarks": [
    { "id": "nm1", "type": "tie", "fromItemId": "ni1", "toItemId": "ni2" },
    { "id": "nm2", "type": "slur", "fromBeatId": "b1", "toBeatId": "b3" },
    { "id": "nm3", "type": "fermata", "beatId": "b3" }
  ]
}
```

预期：b1/b2 上方有同音 Tie，b1–b3 外侧有 Slur，b3 有高音点、Fermata 和一个延时横线；全部图元均进入分页 bounds。

将 b2 明确单 item 改为 `2`：保留 ni2，影响预览只删除 nm1，保留 nm2/nm3；未确认时文档完全不变，确认后一次提交，Undo 恢复 `1` 和 nm1。若预览期间修改了小节，原确认请求返回 stale，重新预览后才能提交。

将 b3 拆成两个四分：首段保留 ni3，第二段新建同音 item 并建立 Tie；Slur 终点和 Fermata 迁移到第二段。确认后两段总时长仍为二分，不靠 TAB 音符映射猜测简谱音高；合并满足第 12.3 节规则时能恢复等价持续音表达。

这一完整链路须作为集成测试和审查演示，确保方案中的新模型、命令、影响确认、布局及历史实际相互衔接。
