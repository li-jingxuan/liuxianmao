# 简谱独立节奏与双谱对齐技术方案

日期：2026-10-14。状态：用户已审查授权，主体实施与测试完成；验收记录见同日实施验收文档。

复核基线：2026-10-14 工作区 HEAD `c6be201`，核心 schema 仍为 7。方案审查时核对命令分发、间距、侧栏、文件和导出代码，第 11–19 节补齐实施契约。用户随后授权实施，当前 schema 已升级为 8；本段基线描述保留用于审查追溯。本文为主方案，前版只保留常用符号语义与几何验收，不能继续复用 TAB Beat 绑定模型。

本方案根据用户补充修正前版核心假设，作为简谱功能实施的主方案。前版常用符号、字体、跨行曲线及导出验收继续有效；“简谱继承 TAB Beat 时值”“简谱项挂在 TAB Beat 上”“TAB 拆合自动修改简谱”等规则由本文替代。

## 1. 结论与关键修正

简谱与六线谱应当具有独立的音符事件和节奏，使用相同小节、拍号、tick 单位及横向时间坐标排版。

两个谱层同一时刻开始的音符居中对齐。对齐的是起音位置，不是简谱整段音组的视觉中心。简谱减时线、连梁、延音线、连音线及节奏连音均由简谱数据生成和管理。

这要求将简谱从 `TAB Beat.numberedNotation` 升级为小节内的独立事件序列，不能仅增加显示选项或在 tokens 上画不同线条。

## 2. 用户谱例的精确定义

项目当前四分单位为 960 tick。假设 TAB 四分音符从小节 tick=0 开始：

| 谱层 | 内容           | 起点 tick | 时长 tick |
| ---- | -------------- | --------- | --------- |
| TAB  | 四分音符       | 0         | 960       |
| 简谱 | do / 1，八分   | 0         | 480       |
| 简谱 | re / 2，十六分 | 480       | 240       |
| 简谱 | mi / 3，十六分 | 720       | 240       |

三个简谱音的总时长为 960 tick，与 TAB 的一个四分音符覆盖相同时间范围。

```text
时间起点       0             480       720       960
TAB           四分音符                           下一音
简谱             1            2         3        下一音
                 ↑
             首音中心与 TAB 起音锚点同 x
```

示意图不代表严格像素比例；验收条件为 `x(TAB@0) === x(简谱1@0)`、后两个起点依次向右，且 960 时刻进入下一段。这里 `1 2 3` 是三个先后事件，不能编码为 `1+2+3`；`+` 继续表示同时发音。

如果反过来 TAB 是八分加两个十六分、简谱是一颗四分音，也按相同时间起点对齐，简谱不会因为 TAB 有三个 Beat 而自动拆成三个音。

## 3. 独立与共享的边界

| 内容                                          | 管理方式                                           |
| --------------------------------------------- | -------------------------------------------------- |
| 音符事件 ID、音高、休止、起点、书写时值、附点 | TAB 与简谱各自保存                                 |
| 减时线/连梁的参与成员、分组结果、显示几何     | 根据各自事件生成，不复制另一谱层结果               |
| Tuplet 成员与 actual/normal 比例              | 各自保存，可分别三连音/普通音                      |
| Tie、Slur、Fermata                            | 各自保存，端点只引用本谱层事件/音符                |
| 小节 ID、容量、拍号、反复与终止边界           | 共用结构数据，分谱层生成可见图元                   |
| tick 单位、横向起音坐标、谱行断行、分页       | 统一规划                                           |
| 单次历史、文档版本、保存和导出                | 同一文档会话管理，撤销仅恢复该次动作实际修改的数据 |

独立管理不要求两个谱层使用不同拍号或不同小节边界，也不要求首版多声部。首版为一个 TAB 声部和一个独立简谱声部；简谱同事件内可有同时发音的多音。

## 4. 修订后的数据模型

小节新增必填 `numberedVoice`（无内容为 `{ events: [], tuplets: [] }`），轨道新增必填 `numberedMarks: []`，移除 TAB Beat 上的简谱持久化字段。下面是基础模型，具体字段互斥与接口见第 12 节：

```ts
/** 简谱事件有自己的起音、时值与身份，不引用 TAB Beat 获取节奏。 */
interface NumberedEvent {
  id: string;
  tick: number;
  rhythm: ILXMRhythm;
  kind: "notes" | "rest" | "continuation" | "gap";
  items: { id: string; token: string }[];
}

interface NumberedVoice {
  events: NumberedEvent[];
  tuplets: {
    id: string;
    eventIds: string[];
    ratio: ILXMTupletRatio;
  }[];
}

/** 跨小节关系放在轨道级，引用简谱身份。 */
type NumberedMark =
  | { id: string; type: "tie"; fromItemId: string; toItemId: string }
  | { id: string; type: "slur"; fromEventId: string; toEventId: string }
  | { id: string; type: "fermata"; eventId: string };
```

- `NumberedEvent.id` 与 item ID 均稳定且全文档唯一；增加相应 ID 工厂方法，不能拿 TAB Beat ID 当简谱事件 ID。
- 简谱 Tuplet 使用自己的成员索引及 rhythm context，复用整数 tick 计算工具；不能把 TAB 的 tupletByBeatId 用于简谱。
- 普通音的 items 为 1–8 个音高 token；rest 固定一项 `0`，continuation 固定一项 `-`。continuation 用于保留旧显式延续输入，不自动猜 Tie。其时值也来自自身 rhythm。
- gap 为节奏连音组中明确未录入的时间槽，items 必须为空，不显示为音或休止；仅允许作为 Tuplet 成员保存。普通未录入时间通过事件之间的空白表达，不额外创建 gap。gap 不能作为 Tie/Slur/Fermata 的有效目标，但在 Tuplet 括号与列规划中保留其时刻。
- 每小节事件按 tick 排序，实际时长使用自身 tuplet 比例计算；必须整数、起点非负、结束不超过小节容量，首版同声部事件不能重叠。
- 同时发音必须属于同一个事件的多音，不能写成两个相同 tick 的重叠事件。
- 允许局部简谱与空白时间；不把未录入区域自动显示为 `0`。用户要表达休止须建立显式 rest 事件。
- 简谱长音跨小节时拆为各小节合法事件并用简谱 Tie 连接；不能单个事件越过小节容量。
- 与前版同样，不重复保存解析音高或图形坐标；音高仍由规范 token 唯一表达。

## 5. 双谱共用时间列的布局算法

现有 `buildRhythmicColumns` 仅遍历 TAB measure.beats；这是必须改造的入口，不能等 TAB 布局完成后再把简谱三个音塞进原有一列。

1. 分别解析 TAB 与简谱实际时间，建立每小节的联合时间列。收集两个谱层起音 tick、必要的结束 tick，以及长音/长休止派生单元的时间锚点，排序去重。
2. 每列记录 `tabBeatIds`、`numberedEventIds`、派生单元引用和下一时间区间；不能沿用只有 `beatIds` 的列表并假定每列都有 TAB Beat。小节容量终点只作终止锚点，不生成可编辑音符列。
3. 同一 tick 只有一个 `xAtTick`；TAB、简谱和现有 TAB 归属歌词/和弦使用对应锚点。无 TAB 起音的简谱时间列只增加横向空间，不创建 TAB Beat、音符或歌词目标。
4. 先测量各谱层图元的左右 extents，并为各自音符之间、长音单元、标记跨度建立最小距离约束。不同谱层的宽度按最大约束贡献，不能把所有字号宽度直接求和。
5. 同谱层的相邻起音可能跨多个联合时间列：约束落在起止列之间的累计跨度上，不能要求每个中间细列都满足一个完整 TAB 四分音符的最小宽度。避免简谱越细，TAB 长音的间距被重复累计。
6. 固有宽度、自动断行及 assignedWidth 均基于联合列计算；多余空间按时间区间与既有密度策略分配，之后同时投影两谱层。
7. 数字本体中心对齐起音 x，升降号排在数字左侧且单独贡献 extents；不能把升降号加数字的整体文本中心当成数字中心。多音事件沿用整组对齐约定，不强制其每个同时音都占相同 x。
8. 简谱首音保持起音锚点；后续事件使用自身 tick 的联合列，不按音符数量平均分配。长音派生符号使用对应时间锚点，不替换起音锚点。
9. 两谱层共享最终小节边界和断行。简谱加密会拉宽小节并影响 TAB 显示位置，但不会改 TAB 音乐数据。

联合列是临时布局对象。TAB 选择仍通过真实 Beat ID 解析，简谱选择通过 Event/item ID 解析；空联合列不得产生虚构的 TAB 编辑目标。

## 6. 节奏与技巧的独立管理规则

- 简谱 rhythm 改动只更新简谱事件；TAB rhythm 改动只更新 TAB Beat。两者使用同一个小节容量校验，但不强制每个 TAB Beat 都与一个简谱事件配对。
- 自动连梁根据简谱起点、实际时长、书写层数、简谱 Tuplet 和公共拍组规划。谱例中的八分 1 与十六分 2/3 共用第一层减时线，2/3 之间另有第二层；不会复制 TAB 四分音的无连梁状态。
- 简谱 Tuplet 修改不改 TAB Tuplet；两层可以在同一时间区间具有不同的事件数量和比例。
- Tie 相邻性按简谱事件序列和实际时间连续判断；中间是否有 TAB 起音不参与校验。
- Slur/Fermata 引用简谱事件，与 TAB 同时段是否已有技巧无关。两个谱层不能因“时间一样”自动继承、移除或合并标记。
- TAB 拆分/合并保留所有简谱事件与标记；简谱拆分/合并仅维护简谱自身关系。前版 TAB 拆分自动克隆简谱项并加 Tie 的规则废止。
- 改公共拍号/小节容量、删除小节/轨道及改反复边界属于结构操作，需分别规划两谱层影响；一次完整预览和提交，不能仅清理 TAB。
- 默认音符编辑不自动推移同声部后续事件。延长时值撞到下一简谱事件或越过小节时拒绝并说明原因；用户可明确选择范围替换。缩短产生未录入空白，不自动填休止。

## 7. 编辑入口与录入语义

- 从 TAB 选中 Beat 打开简谱录入时，用其起点和覆盖时间初始化一个临时编辑窗口；这是输入便利，不保存强制绑定关系。
- 对四分窗口选择“前八后十六”模板，预览 480/240/240 三个简谱事件，输入 `1 2 3` 后提交；窗口时长与模板实际时长必须一致。
- 也提供逐简谱事件的时值、附点、休止及 Tuplet 编辑。鼠标点击 2/3 可直接选中各自 Event，不必创建/选中对应 TAB Beat。
- 空格在已指定节奏模板中分配给模板事件，在简谱已有事件序列中分配给真实简谱事件；不再按 TAB Beat 顺序前进。超出目标范围或事件不足整批拒绝。
- 无模板的新增连续录入先选择默认简谱时值，再逐音按该时值推进；明确显示将占用的时间范围。`+` 始终表示当前简谱事件的同时多音。
- `_` 只跳过已存在的简谱目标，模板中则保留该时段空白（Tuplet 模板建立 gap 成员）；不能把它解释为 TAB 跳拍。模板替换确认必须展示被覆盖的简谱事件和受影响技巧。
- 技巧按钮的当前目标为简谱 Event/item，保留前版连接模式、影响预览、IME 保护及键盘可访问规则。
- 预览需绑定 documentRevision/session generation；独立模型不改变原子提交、no-op、stale 与历史恢复契约。

## 8. 迁移、复制与结构操作

- 原 schema 7 的每个带简谱 TAB Beat 显式迁移为一个独立简谱事件，tick/rhythm 复制该 Beat 当时的值，生成独立 Event/item ID。迁移完成后后续 TAB 修改不传播到简谱。
- 不把旧 `1+2+3` 猜成先后演奏，不把 TAB Tuplet 持续绑定到简谱；为保留旧实际时长，升级时显式复制涉及简谱事件的 Tuplet 比例及成员描述。
- 旧 Tuplet 至少有一个带简谱成员时，复制为独立简谱 Tuplet；缺少简谱的成员生成 gap 事件，复制原 tick/rhythm，但不伪造 `0`。整组都没有简谱则不生成简谱 Tuplet。
- 简谱 Tuplet 的 eventIds 数量必须等于 actual，按实际时间连续，成员书写时值/附点一致、不可重复归组；复用比例约束工具，成员索引独立建立。标记覆盖完整组范围，gap 位置留白；缺项提示只在编辑界面显示，不把编辑警告导出到正式谱面。
- 删除 Tuplet 中的音符内容时可将该成员变为 gap；删除成员事件或改变单个成员时值必须先移除/重建整个组。移除 Tuplet 后，gap 事件被删除，其余成员回到书写时长；整组产生的时间变化必须预览并检查碰撞/小节容量，不能静默压缩时间。
- 复制整小节默认复制两层；拍范围复制默认包含同时间范围内的简谱，专门的 TAB/简谱编辑操作仅修改所选谱层。
- 时间范围复制若切到简谱事件中部，先提示扩大范围或仅复制 TAB，不能静默截短简谱时值。粘贴按选定谱层重建其自身 ID/关系；联合布局列不进入 clipboard。
- 改拍号重建时间轴需分别列出两层会删改的事件，沿用影响确认。独立节奏不能绕过公共小节容量与结构边界。

## 9. 实施顺序修订

原 T1–T8 必须增加“独立事件＋联合时间列”前置改造，不能先把原挂载式模型完整实施后再重做。

1. 冻结 NumberedVoice/Event/Tuplet、标记引用、gap 成员校验和升级模型，统一替换原方案的 Beat 绑定接口。
2. 建立简谱自身命令、时间索引和编辑目标；测试只改一谱层时另一谱层数据保持不变。
3. 改联合时间列、跨度约束、断行与锚点映射；先验收本文四分对三个简谱音的谱例及反向谱例。
4. 接入简谱自己的连梁、长音、Tuplet、Tie/Slur/Fermata，小节结构符号按共享边界投影。
5. 接入节奏模板与简谱选择；更新文件、复制范围、历史和导出。
6. 运行前版工程检查与混合谱验收，并补齐本文独立性检查。

## 10. 必需验收

- 四分 TAB 对八分＋十六分＋十六分：首个 1 与 TAB 起音同 x，第二层只覆盖 2/3，TAB 不被拆分。
- 反向的一对多、两层不同起点、附点及多音的数字本体对齐；未知 tick 不伪造 TAB Beat。
- 简谱普通节奏对 TAB 三连音、简谱三连音对 TAB 普通节奏，独立比例与连梁均正确。
- 改简谱时值/标记，TAB 序列化数据不变；改 TAB 时值/拆合，简谱序列化数据不变。公共结构操作单独验收两层影响。
- 删除简谱事件只影响其自身技巧；TAB Tie 仍存在；删除 TAB Note 不自动删除同时间简谱技巧。
- 同层宽度跨度跨多个联合列仍不过度膨胀，多音升降号/附点/长音/歌词无碰撞。
- 稀疏组升级保留原 tick 与实际时长，不伪造休止；旧多音保持同时发音语义。
- 模板、范围覆盖、跨行技巧、复制/撤销、文件往返和导出使用真实简谱事件，不重新读取 TAB rhythm 推导结果。

审查阶段只修订技术方案。本文已由用户确认并授权实施，前版的领域、命令、迁移和结构操作章节需按新的谱层边界执行，符号范围和几何验收继续承接。

## 12. 正式模型与核心 Module 的 Interface

### 12.1 模型与时间计算

- 版本目标为 schema 8；实施前核对工作区是否已有并行版本变更。新 loader 严格拒绝旧 Beat.numberedNotation 与新 numberedVoice 同时出现，不保留双份事实。
- NumberedEvent 使用 TypeScript 判别联合和 Zod 判别联合：notes 的 items 为 1–8 个普通音、rest/continuation 各有一个固定 token、gap 的 items 为严格空数组。token 语法及还原号沿用前版规范。
- 严格整数 tick；不要求简谱总时值填满小节，只要求有序、不重叠及每个事件结束 `<= capacity`。TAB 仍要求完整连续覆盖容量，不能让同一校验函数无条件对两层使用相同规则。
- `createNumberedRhythmContext(voice)` 返回 `tupletByEventId` 与 `getEventDurationTicks(event)`；内部复用 `calculateRhythmTicks` 和支持比例白名单，不伪造 ILXMBeat 或 ILXMMeasure 进行类型强转。
- Tuplet 的所有成员（含 gap）必须为 events 数组中的连续有序成员，实际时间连续、书写时值/附点相同、成员数为 actual；组不能重叠或跨小节。gap 必须恰好归属一个组。
- 新 ID 工厂方法为 `createNumberedEventId/createNumberedItemId/createNumberedTupletId/createNumberedMarkId`；统一 ID 收集、语义校验与复制 ID 映射包含全部新实体。
- Tie 比较普通 item 的音级、相对八度、半音偏移；相邻性使用独立简谱序列及绝对 tick，gap/休止/continuation 或未录入时间会中断 Tie。Slur 两端为普通 notes Event，Fermata 接受 notes/rest。
- 同一轨道每个 item 至多一条入 Tie 和一条出 Tie，同范围 Slur 不重复；前版交叉 Slur 限制及反复/终止边界限制保留，引用字段改为简谱 ID。

核心 Interface 只暴露解析、预览、统一命令与真实目标解析。域索引、Tuplet 重排、技巧影响清理留在 Module Implementation，不要求侧栏调用者先后执行多个维护函数。

### 12.2 命令与候选结果

## 13. 联合列、跨度约束与分配算法

### 13.1 可实现的间距摘要

新增内部 `time-grid-spacing.ts`，对现有 `measure-spacing.ts` 提供摘要与分配 Interface；外部仍调用 `summarizeMeasureSpacingWidth/layoutMeasureSpacing`，不要求 system 层自己求解时间。

```ts
interface TimeColumn {
  tick: number;
  endTick: number;
  tabBeatIds: string[];
  numberedEventIds: string[];
  auxiliaryAnchors: AuxiliaryAnchor[];
}

/** 所有约束都指向较晚的列，便于一次按时间顺序求解。 */
interface SpanConstraint {
  fromIndex: number;
  toIndex: number;
  minDistance: number;
  idealDistance: number;
  reason: "rhythm" | "text" | "technique" | "tuplet" | "sustain";
}

interface TimeGridSummary {
  ticks: number[]; // 含 0 与 capacity，末点是只读终点。
  columns: TimeColumn[]; // 每个相邻 tick 区间一列，不含终点伪列。
  minPositions: number[];
  idealPositions: number[];
  leftExtra: number;
  tailExtra: number;
}
```

- 起音、真实结束、长值单元锚点均使用整数时间。如果派生单元来自 Tuplet，先按书写时值拆单元再按比例转换；出现非整数派生锚点时只用已有合法事件起止点和局部几何，不舍入成可编辑 tick。
- `rhythmTicks` 不能同时表示“列间隔”和“TAB Beat 时长”。联合列改用 endTick-tick；事件时长留在各自 rhythm context。
- 图元测量先生成带 lane 类别的左右 extent。歌词段、和弦行、TAB 品位、简谱数字各自在本行相邻对象间建立约束，不把垂直不相交的图元做一条宽度总和。
- 每个真实事件将基础时值最小/理想宽度写为 start→end 的跨度约束；细分列不得重复领取整个长 Beat 最小宽度。长值单元之间增加自身可见符号距离约束。
- 跨度占位与实际绘制净空共同约束最小距离。所有同起止约束取 max，不反复加宽。

### 13.2 求解与拉伸

将 tick 升序作为 DAG 拓扑顺序。每个约束表示 `p[to] >= p[from] + distance`；连续时间列增加最小正间隔（暂定 1 逻辑像素），确保不同起点不会重合。从 p[0]=0 开始，按终点顺序取所有入边的最大候选，一次得到 minPositions。

理想求解使用 `max(minDistance, idealDistance)`。相邻时间区间的理想基线按覆盖该区间的真实事件分配：该事件既有理想宽度乘区间时长占其实际时长比例，多谱层贡献取 max；未录入简谱时间仍由完整 TAB 时间轴贡献。这样短时值视觉密度仍有来源，且不会为两个谱层累加两份基础间距。

求解为 O(K+E)，排序为 O(K log K)，K 是时间锚点数量、E 是跨度约束数量；不做逐像素碰撞试探或无界迭代。

固有内容宽度为 idealPositions 终点，固定宽度另加 padding/leading/leftExtra/tailExtra。assignedWidth 只允许不小于固有宽度，沿用当前不压缩的契约。多余空间按各相邻区间已求解的理想差值比例分配，最后区间吸收浮点残差；只增加距离，原约束仍成立。

首/尾净空检查全部可见锚点，不只检查 TAB 首末 Beat。非首点升降号向左外延、最后独立简谱音/附点向右外延、跨多个列的长和弦均进入 leftExtra/tailExtra。

### 13.3 事件跨度与既有消费者

分配结果新增 `xByTick`（内部 Map，不持久化）、`slotsByNumberedEventId`；保留 `slotsByBeatId` 及 measure.beats 仅包含真实 TAB Beat。

每个 slot 的 `x = xByTick[startTick]`，`width = xByTick[endTick]-x`。`columnIndex` 仅是起点所在联合列索引，不能作为“第几个 TAB Beat”使用。TAB Note.width 跟随此跨度；TAB/简谱的点击格宽另按各自相邻起音中点计算，不将持续跨度直接作为选框。

因此 TAB 四分覆盖三个简谱子音时，四分 Beat.width 覆盖 0→960 的全部联合列，而非仅 0→480。`duration-beam-layout.ts` 的长音占位及 `technique-layout.ts` 的 Let Ring、vibrato/tapping 等依赖 width 的路径必须逐一回归，不能只保证数字对齐。

有简谱细分列时，TAB 长音横线也要读取其四分延续单元在联合时间图中的锚点：现有 `buildDurationSustainMarks` 的 width 等分不能保证非均匀联合列中间时间正确。保留 TAB 的线型/Y 规则，改传单元起止坐标；没有简谱的小节保留原快路径。不能把“跨度变大”当作横线已完成时间对齐的全部验收。

`layout-types.ts` 的 columns 改为联合列类型，全部 `.beatIds`/`beatIds[0]` 消费点迁移为明确的 tabBeatIds 或 numberedEventIds；禁止留一个混合 ID 别名让旧代码“看起来仍能工作”。

### 13.4 system 候选行与无简谱回归

- 保留当前 planPending 的候选整行和弦检查，anchorX 改从联合摘要读取真实和弦所归属 TAB Beat 的起点。
- 和弦跨度不足时只扩宽目标前的一个时间区间，再同步更新其小节摘要的 min/ideal/assigned/contentWidth；所有扩宽只增加约束跨度。正式 layoutMeasure 必须消费候选摘要，不能再次独立求解出另一份间距。
- 行尾和弦保护、反复边界拆分、稀疏末行伸展限制保持；简谱行首拍号的 leading 取现有 TAB 与简谱需要的最大值。
- 完全无简谱事件的普通小节采用现有 spacing 快路径，保留既有列宽/坐标；再规范化为新类型提供消费者。gap 所在组、简谱起音和派生单元使用联合路径。
- 跨空小节的 Slur 只增加垂直内容，不凭曲线创建虚构音符列。联合布局变化只影响 display geometry，不写 tick 或节奏回文档。

## 14. 独立目标、空白录入与侧栏状态

### 14.1 目标判别联合

旧 `MusicTextTarget extends ILXMTabCellReference` 必须改成判别联合，歌词/和弦仍用真实 TAB 引用，简谱使用以下独立目标：

```ts
type NumberedTarget =
  | {
      kind: "numberedEvent";
      trackId: string;
      measureId: string;
      eventId: string;
      itemId?: string;
    }
  | {
      kind: "numberedTime";
      trackId: string;
      measureId: string;
      tick: number;
      endTick: number;
    };
```

numberedTime 是临时编辑窗口，endTick 为排他端点，仅用于本小节合法时间范围；NumberedEvent 目标的 tick/rhythm 每次从当前文档解析，不在 UI 保存重复值。简谱范围选区使用两个 Event 引用或两个明确时间端点，不复用 TabCellSelection.string。

store 增加 `numberedSelection/selectedNumberedMarkId`，保留原 selection/selectedTechniqueId 给 TAB。切换主编辑对象时不覆盖另一谱层持久化内容；Undo/Redo/replace 后分别校验 UI 目标，无效简谱目标回到原小节可用时间窗口或 null，不自动跳成 TAB Beat。

侧栏仍复用现有切换、dirty、IME、应用/放弃保护；`readMusicTextDraft/resolveSidebarRequest` 按判别类型比较稳定 ID 或时间范围，不能统一验证 measure.beats。`resolveParagraphFocus/layoutParagraphFocus` 增加简谱目标分支，不要求 beatId。

### 14.2 空白时间的可点击入口

- 已有 item/Event/mark 图元使用独立 hitIndex。数字点击优先返回真实 Event/item，不经 hitTestLayout 寻找最近 TAB Beat。
- 空白插入网格由当前小节容量及已选默认简谱时值生成，不使用 TAB Beat 中点。默认四分，无附点；切换八分/十六分会更新插入网格，但不会改文档。
- `xAtTick(t)` 对非联合节点在所在时间区间做线性插值，仅用于 hover/临时窗口。用户点击时吸附到合法整数网格并验证覆盖范围；正式添加事件后重新构建联合列，不把预览插值当最终坐标。
- 从 TAB 选拍进入简谱仅是显式 `numberedTime` 窗口转换：start=TAB.tick、end=TAB 实际结束。若在 Tuplet 内，必须读取实际时值；并非所有 TAB 窗口都能容纳任意模板。
- 模板首版至少提供等分、前八后十六、前十六后八及自定义成员时值。成员 actualTicks 合计必须等于窗口宽度；不匹配时提示实际缺额/超额，不自动缩放音符。
- 多音 item 选择器显示音符与组内序号；re/mi 即使无 TAB 起音也有独立 focus/高亮。TAB 命中仍走原 getBeatCellBounds，联合列不能扩大 TAB selection 数量。

### 14.3 撤销、预览过期与 effects

复用文件控件的 token：`{sessionId, sessionVersion, stateVersion, document}`。抽取公共比较辅助函数供简谱/文件预览使用，不新增 generation。核心另校验 expectedRevision；UI token 不写入乐谱。

当前 store 每次有效命令/Undo/Redo 增加 stateVersion，replace 增加 sessionVersion；预览期间任一项变化都失效，即使 Undo 后 documentRevision 恰巧相同也不能继续提交旧预览。

dirty、inputActive、composing、pending 等状态沿用已有独立职责。删除标记快捷键只在无文字输入时生效，连接模式 Esc 不修改文档。成功动作一次历史，失败/no-op/取消均保持快照不变；effects 只随成功结果产生。

## 15. 范围替换、Tuplet 与公共结构的冻结规则

### 15.1 范围及身份

- 时间范围统一为 `[start,end)`；end 等于另一个事件起点不算覆盖该事件。单模板替换首版仅在一个小节内。
- 任一被覆盖事件必须整体位于范围内；切断普通事件或部分 Tuplet 时拒绝，提示扩展范围。范围中已有内容先预览覆盖，再独立确认会删除/迁移的技巧。
- 相同完整事件内容与起点/时值序列是 no-op，不重建 ID。单 Event/item 指定更新保留明确身份；有差异的范围替换对替换成员重建 ID，不按相同音高猜关系。
- 原组内 `_` 保持对应已有事件；空模板项 `_` 留空白，Tuplet 模板用 gap。普通持续音与显式 continuation 不因文本空格自动构建 Tie。
- 连续填已有事件只改其音高/内容，不改 rhythm，按简谱真实顺序可跨小节；新增连续填以当前默认 rhythm 生成 tick，碰到小节边界恰好结束才允许进入下一小节，不能隐式拆一个跨小节长音。

### 15.2 Tuplet

创建/替换 Tuplet 使用明确时间窗口、成员书写时值及支持 ratio：完整实际时长必须等于窗口，外部事件不移动。改变组比例必须同时给出整个组新方案，不允许单独改 ratio 后留下旧 tick。

移除组时，以原 start 为基准，按原成员顺序重算书写时长网格：第 i 个成员起点为 start 加前 i 个成员书写时长；gap 占用相应网格但随后省略其事件。组外事件 tick 保持不变。新范围与外部碰撞/越界则拒绝，用户先腾出时间或范围替换，不自动挤压另一谱层或删除后续音。

成员清空为 gap 后，相关 Tie/端点 Slur/Fermata 进入影响清单。不能把 gap 误认为完整休止，gap 打断共享减时线，但 Tuplet 括号仍覆盖整个组。

### 15.3 简谱拆合与公共结构

- 独立 Event 拆分保留第一段身份，第二段克隆并按普通音逐 item 建简谱 Tie；出 Tie/Slur 末端/Fermata 迁移到第二段，入 Tie/Slur 起点留第一段。Tuplet 成员不单独拆合。
- 合并只接受时间连续、完整逐 item Tie 链的普通音，或全 rest、全 continuation；不能仅因同音高就合并起音。内部不等价 Slur/Fermata 阻止合并，合法边缘端点才迁移。
- TAB 的 `rhythm-change/measure-timeline/beat-structure` 不调用简谱推移/压缩；移除 `collectMusicTextBeatIds` 中旧简谱保护分支。即使 TAB 全为 rest 而简谱已有旋律，TAB 仍可安全重建自身尾部休止。
- 改拍号：TAB 使用现有候选重建规则；简谱保持 Event ID/tick/rhythm。全部事件结束在新容量内则保留；有任何简谱越界则整批拒绝并给出小节/事件，不自动截断或删除。untilNextChange 任一小节失败不部分提交。
- 改拍号可能改变自动连梁拍组，这属于派生显示重算，不属于重写简谱 rhythm。
- 删除小节/轨道和改反复边界属于公共结构命令，两层均做引用影响规划。删小节清理其简谱 Event、Tuplet 和端点标记，不将端点自动移动到最近音；新反复边界使连接非法时显式确认移除。

## 16. 复制、迁移及文件预检的实际接入

### 16.1 Clipboard v2

现有 BeatClipboard 是内存中的严格 v1 模型，本次改为 v2；旧内存载荷拒绝并提示重新复制，不在粘贴时猜旧 schema。

v2 明确保存 `layers: "tab"|"numbered"|"both"`、totalTicks、归零后的 tab content/numberedVoice、两层各自 marks/techniques、omissions。未包含谱层字段为 null，不使用“空数组”混淆未选谱层与主动覆盖为空。

- 既有拍范围 copyBeats 可默认 both，以实际 TAB 起止 tick 定义窗口；简谱专用 copy 使用独立时间范围，默认 numbered。窗口不能切断任一被选谱层的事件或 Tuplet。
- ID 重建涉及 selected 层全部实体，包括独立 Tuplet 及 gap；关系通过各自 ID Map 接回。跨窗口关系不携带并显示 omission。来源对象不变。
- overwrite：只替换选定层在目标时间窗口内的内容；两个层都选中才同时覆盖，原目标被切断/部分组时拒绝。
- insert：按 totalTicks 推移所选层的后续事件；tab-only 只沿用原 TAB reconcile 行为，numbered-only 只推移简谱，both 是明确同时推移两层的复用操作，不算 TAB 编辑自动传播。
- 插入点在简谱事件中间或 Tuplet 中间时拒绝；推移后任何简谱事件越界即拒绝，不压缩/截尾简谱。TAB 仅可按原规则消耗可重建尾部休止。
- 引用、碰撞、容量及影响确认全部由 candidate document 一次验证。范围超过一个小节的拍插入暂不支持，整小节复制继续走既有 measure/range-copy 命令并复制完整两层。

### 16.2 文件升级与场景验证

- 固定 legacy schema 4/5/6/7，不继续用当前 LXMMeasureSchema 动态 extend 来冒充旧格式；否则新增必填 numberedVoice 会让旧文件全部失败。
- schema 7 升级按事件原顺序生成独立 Event/item/组 ID；只复制当时实际时长所需的 TAB Tuplet，并用 gap 保留无简谱成员。schema 4–6 输出空 numberedVoice/numberedMarks，保留现有作者/capo/弦范围升级规则。
- 文件入口先做 UTF-8/字节/结构预算校验，再区分当前版本直接加载和受支持旧版本显式升级候选。预览返回 `{document, sourceVersion, upgraded}`；确认导入重新校验快照 token 后，replace 当前版本候选对象，不再次调用旧 loader 丢失已升级结果。
- 宿主 replaceDocument 仍只接受当前版本；需要旧格式的宿主显式调用 upgradeDocumentToCurrent。网页文件升级交互与宿主契约分开，不静默升级所有输入。
- 保存仍走 serializeScoreFile 的正式预检并导出当前版本，不提供有损降级。
- `inspectMusicScale` 改为 TAB beats＋简谱 events（含 gap）合计最多 20000，TAB techniques＋简谱 marks＋两层 Tuplet 合计最多 20000；小节仍 1000、文件 10 MiB、原始文件结构节点仍 200000；派生 layout 和 scene 各自限制 200000，不将同一内容的两份投影相加。100 小节标准谱例通过完整文件往返。
- `inspectScene` 保留 TAB Beat ID/数量检查，增加每个简谱 Event 唯一投影与终点覆盖检查。不能因 scene 缺掉一整层仍与 TAB 数量一致就认为布局完整。
- 内部 xByTick Map 不直接导出到 ILXMLayout，输出可序列化的 timeAnchors 数组或普通 Record。当前 inspectStructure 在非序列化模式按 Object.entries 遍历，可能忽略 Map 的真实内容，因此不能依赖其替代时间锚点的有限值/归属检查。
- `score-file.ts` 的 optional undefined 白名单去掉旧 numberedNotation，仅保留真实可选字段；新 numberedVoice/numberedMarks 为必填，不靠序列化时补默认值。

## 19. 复核结论与实施范围

方案可以落地，但实现范围是“独立简谱声部＋共享横向布局”的跨模块改造。前版仅新增符号布局的工作量判断不再成立。

本轮已明确：正式独立模型、候选命令提交链、DAG 间距算法、事件完整跨度、独立目标与插入网格、Tuplet/gap 语义、公共拍号处理、复制插入谱层范围、显式升级与双层场景预检。没有依赖后续临时决定的时间绑定规则。

使用 [codebase-design 技能](/Users/lz0785/.agents/skills/codebase-design/SKILL.md) 的小 Interface 与集中 Implementation 原则：规划/校验/引用维护集中在核心 Module；UI 只提供目标、操作及确认，SVG/Canvas 只消费投影。该原则用于本方案模块划分，没有触发业务代码实施或多 Agent 工作。

先完成 A/B，再用 C 验证用户谱例与 TAB 宽度消费者，随后进入 D/E；不能在现有 Beat 上塞入三个 token 来作为过渡交付。本次不实现独立拍号、多声部、播放或小节内自动折行，保留公共结构和既有导出限制。
