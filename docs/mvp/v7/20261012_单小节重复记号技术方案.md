# 单小节重复记号技术方案

> 日期：2026-10-12。状态：待用户审查，尚未实施。
> 用户已确认要补充单小节重复记号 `𝄎`（类似 `%`，表示重复前一小节）。本次补充方案，代码继续保持 schema 7。

## 1. 范围和交互

在小节工具中增加独立的“重复前一小节”操作。该记号位于小节内部，不加入现有六类 `barline` 枚举；重复小节仍可设置单线、双线、终止线或反复边界。最左侧 system 收边线保持现有行为。

首版支持一个小节重复，不包含两小节重复、编号重复、反复次数、第一/第二结尾或播放。

- 以当前选中 Beat 所在的小节为目标；第一小节禁用。
- 前后小节拍号必须相同，当前小节不得是新段落标记起点。相邻边界为普通单线时才能创建，避免跨段落或反复结构产生歧义。
- 前一小节不能已经是重复小节；首版不建立重复链。
- 点击操作先预览“来源小节 → 目标小节”、将替换的音符/节奏/技巧/文本数量和不能继承的内容；目标有内容时必须主动确认覆盖。
- 提交后选中目标小节并展示 `𝄎`，侧栏显示“重复前一小节”和“展开为普通小节”。直接点击记号选中整个目标小节，不构造虚假的 Beat 命中。
- 编辑重复小节里的音符、节奏、简谱、歌词、和弦或技巧前，提示先展开；展开只恢复普通显示，音乐内容不会丢失。
- 创建和展开分别为单条原子领域命令，支持撤销/重做；沿用草稿保护、宿主通知和失败/no-op 规则。

## 2. 数据方案与编辑保真

建议使用“真实内容快照 + 简写显示标记”，不使用随源小节变化的动态引用。

拟在 `ILXMMeasure` 增加可选字段：

```ts
/** 与紧邻前一小节的可重复音乐内容一致时，使用单小节重复记号简写。 */
measureRepeat?: { type: "previousSingle" };
```

重复小节保存完整、合法的 Beat/Note、连音、简谱、和弦和小节内技巧快照，重建所有 ID。歌词不自动重复：前一小节或目标小节存在歌词时，首版拒绝创建并给出原因，避免隐藏原歌词或擅自重复不同段落的文字。

前后音乐等价校验忽略业务 ID、小节边界和段落标记，比较音符、时值、简谱、和弦、连音及完整内部技巧。任一技巧跨越源或目标小节边界时，首版拒绝创建，不省略连接，不悄悄删掉外部技巧。

拟升级 schema 8；显式补 schema 7 → 8 迁移，并保留既有 4/5/6 升级入口。旧数据不添加标记，加载后的普通小节行为保持一致。运行时校验必须验证位置、拍号、结构边界、音乐等价和技巧引用，拒绝只有标记却没有合法内容的对象。

## 3. 源小节改变与结构操作

标记不是内容的唯一来源，因此源小节改变不会自动覆盖重复小节里的音乐内容。

每条成功命令在最终校验前统一协调重复标记：若某重复小节与当前紧邻前一小节不再满足第 1、2 节条件，则移除其显示标记、展开真实内容，并给出“重复记号已展开，原内容保留”的结构化影响提示。协调和用户操作属于同一次 revision/历史/宿主通知，撤销恢复二者。该规则覆盖源内容改变、拍号/边界改变、插入/删除/移动、复制及所有未来命令入口，不能仅在页面操作中补丁处理。

- 复制完整小节时保留音乐内容并重建引用；只有新位置继续满足相邻音乐等价和结构约束时才保留标记，否则展开并提示。
- Beat 剪贴板不复制整小节标记。重复小节必须先展开后才能选择、复制或粘贴 Beat。
- 修改目标内部音乐内容前仍要求明确展开；核心命令也拒绝直接修改隐藏 Beat，不能只靠按钮禁用。
- 左右导航以整小节重复记号为选择目标；未展开时跳过隐藏 Beat。在普通小节与重复小节之间切换时，不残留品位或文本草稿。

## 4. 布局和渲染

核心生成独立 `measureRepeat` 图元、bounds 和整小节命中区域，SVG 页面只消费最终几何。

- `𝄎` 水平居中于小节正文区域，纵向位于六弦谱中部；不跨到 TAB 行头或拍号区域。
- 为字体一致性，使用受控 SVG path 和两个实心圆点，不依赖系统字体能否显示 Unicode 字符。
- 标记小节保留六根弦线、拍号、小节线、段落结构和小节宽度；隐藏其快照音符、节奏、连音、简谱、和弦、内部技巧图元及对应命中。
- 宽度和行高由可见记号与边界贡献，不由隐藏快照撑开。自动换行后仍在目标小节内居中，选择框由实际小节布局输出。
- 跨边界技巧已在创建规则中排除；无需在此阶段解释隐藏内容上的延音续接。

## 5. 实施与验收条件

实施顺序：schema/迁移与等价规则 → 创建/展开命令及统一协调 → 复制与现有命令保护 → 布局/命中/导航 → 侧栏预览、覆盖确认和草稿保护。

必须覆盖：第一小节、拍号不一致、反复/段落边界、重复链、歌词、跨界技巧等拒绝场景；完整快照的 ID/引用与不可变性；源编辑后自动展开且原内容保留；小节插入删除和复制导致的标记协调；过期覆盖确认；隐藏内容不可直接编辑或命中；创建/展开/自动展开的原子历史；稀疏行、超宽小节、紧凑/舒适密度与多行布局。

运行类型、lint、全量测试和构建，并用真实谱完成创建、覆盖拒绝、展开、源编辑、结构调整、撤销重做与浏览器命中验收。方案通过审查后再实施；不把本方案列为已完成的 7.1-C 功能，分页仍属于 7.2。

## 6. 需要用户审查的关键决策

1. 源小节后续改变时，重复小节自动展开并保留原音乐，而不是同步修改内容。
2. 首版遇到歌词、重复链、跨小节技巧或结构边界时拒绝创建，待有具体谱例再扩展。
3. 内部编辑先展开，`𝄎` 保持整小节选择和独立创建入口，不加入“小节线类型”列表。
