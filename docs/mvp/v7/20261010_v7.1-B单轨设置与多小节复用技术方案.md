# MVP v7.1-B 单轨设置与多小节复用技术方案

> 2026-10-10。承接 v7.1-A（schema 4、音符 x）。本切片目标为 G09 单轨谱面设置与 G10 多小节复用；不实现 Beat 拆分/合并、Beat 粘贴、半音推弦、播放、作品保存和多轨。

## 1. 目标与边界

- 支持标准调弦、Drop D、自定义六弦调弦和 capo 0–12 的编辑与展示。
- 调弦/变调夹修改保留现有数字品位与闷音 `x`，不静默转调；明确品位是相对 capo 的谱面品位。
- 支持连续多小节复制到同一轨道的插入位置，整次操作原子、可撤销/重做，并复用 v7.0 的技巧引用映射与影响说明。
- 复制范围内保留拍号、节奏、连音、歌词、和弦、音符、闷音和完整包含的技巧；跨范围技巧不复制并报告遗漏。
- 首版不支持跨轨道复制、Beat 级粘贴、不同拍号自动重排、跨小节自动延伸技巧或隐式迁移旧 schema。

## 2. 文档模型与版本

- `ILXMTrack` 增加 `capo: number`，约束为整数 0–12；`tuning` 继续保存六根弦的 pitch/midi，并要求弦索引唯一且顺序为 1–6。
- 增加调弦预设命令：`standard`、`dropD`，以及传入完整六弦定义的 `custom`；命令执行前校验 pitch 与 midi 的一致性。
- 新增结构标记字段前先确定最小模型：小节级 `sectionLabel?: string` 和可选 `tempoBpm?: number`，仅作为可保存记谱，不进入播放和作品元信息。
- 因新增持久化字段，schema 版本显式升级到 5；loader 只接受版本 5，不做 schema 4 静默迁移。内置示例同步升级并保持音乐内容与 ID 不变。

## 3. 领域命令

- `track.setTuning`：替换单轨六弦调弦；相同值为 no-op，非法 pitch/midi 原子拒绝。
- `track.setCapo`：设置 0–12 的 capo；数字品位和 `x`、技巧引用与文本锚点保持不变。
- `measure.setMarker`：设置/清除小节段落标记和速度记谱；只允许合法范围，结果进入 undo/redo。
- `measure.copyRange`：接收源起止小节 ID与插入锚点；按文档顺序复制完整小节，重建所有小节、Beat、Note、Tuplet、歌词、和弦和技巧 ID，并建立旧 ID 到新 ID 的映射。
- 复制命令只复制完整包含的单音/Beat/区间技巧；跨源范围的技巧不复制，生成结构化 `omitted` effect。任何失败不修改文档、不产生历史。

## 4. 页面与交互

- 在单轨设置侧栏提供调弦预设、自定义六弦输入和 capo 输入；提交前显示相对 capo 品位说明和错误信息。
- 在小节操作区提供起止小节选择、插入位置和“复制范围”；复制结果沿用现有影响说明组件。
- 选区、文本草稿、计时输入和宿主通知继续遵守 v7.0 会话契约；成功领域命令只触发一次 `onChange`。
- 页面不得自行计算复制对象、ID 或 tick；所有文档变化经核心命令完成。

## 5. 布局与校验

- 调弦/capo 只影响设置展示与后续音高解释，不改变存储品位、Beat tick、布局宽度或命中坐标。
- 复制后统一重新 layout；系统断行、文本锚点、技巧几何和命中索引来自新文档。
- loader、schema、semantic validation 和命令入口共享同一套调弦/capo 约束，错误信息保持可展示。

## 6. 验收与测试

- 核心测试覆盖 schema 5、调弦预设/自定义校验、capo 边界、no-op、数字/x 保真和技巧/文本引用不变。
- 复制测试覆盖 2–8 小节连续范围、重复复制、首尾插入、连音/歌词/和弦/16 类技巧、跨边界遗漏、ID 唯一性、不可变性、撤销/重做和宿主 effects。
- 网站测试覆盖侧栏设置、复制范围交互、错误提示、独立会话隔离和一次性通知。
- 完成 `pnpm test`、`pnpm type-check`、`pnpm lint`、`pnpm build`，并进行桌面浏览器真实谱例验收。

## 7. 暂不纳入

Beat 拆分/合并、Beat 粘贴、跨小节自动延伸技巧、半音推弦、播放、保存/导出、分页 PDF、作品生命周期和多轨道。

## 8. 落地前必须冻结的补充决策

### 8.1 schema 4 到 schema 5 的输入策略

当前 loader 按严格版本拒绝旧文档，因此升级到 schema 5 后，所有现有 schema 4 示例、测试夹具和宿主输入都必须显式升级。实现阶段需要提供一个仅供开发/宿主调用的 `upgradeSchema4To5` 纯函数，或在宿主接入文档中明确由宿主先升级；不能在 loader 内静默迁移。升级函数只补充 `capo: 0`、结构标记默认值，并重新运行 schema 与语义校验。

### 8.2 调弦的规范化规则

- `strings` 必须恰好 6 项，索引严格为 1–6 且按顺序排列。
- `pitch` 使用正则解析为音名加八度（A–G、可选 `#`/`b`），再与 `midi` 计算值逐项比对；不接受两种字段互相矛盾。
- 命令和 loader 共用同一解析函数；标准调弦、Drop D 预设使用不可变常量。
- 暂不允许改变弦数、改变乐器类型或把 capo 转换为音符品位。

### 8.3 capo 与记谱显示

`capo` 存在轨道级，范围为整数 0–12；Note 的数字仍是相对夹子的谱面品位，x 不受影响。首版不在 TAB 数字旁显示实际音高，也不因调弦/capo 改写 Note、ChordDiagram 或技巧引用；侧栏必须明确这一语义。

### 8.4 结构标记收窄

首版只实现小节级 `sectionLabel?: string`，长度上限 32，使用现有音乐文本规范化规则；速度信息暂不加入持久化模型，避免把节拍器/播放语义提前带入 v7.1-B。若确需速度记谱，应另定字段位置、单位、范围和展示规则。

### 8.5 多小节复制的边界和插入规则

- 命令接收 `sourceStartMeasureId`、`sourceEndMeasureId` 和 `afterMeasureId?: string`；源范围按当前轨道顺序连续，插入锚点不能落在源范围内部。
- `afterMeasureId` 为空表示插入到轨道开头；复制结果保持源小节顺序，源范围内的小节线、拍号、连音、文本和完整包含技巧全部复制；复制序列最后一小节沿用源末小节边界。
- 复制操作只做插入，不覆盖已有小节；复制到自身前后均按一次命令处理，不允许因为重叠而产生隐式移动。
- 源范围内 Beat/Note/文本/连音/技巧全部生成新 ID；复制后的技巧只引用复制后的实体，禁止保留旧引用。

### 8.6 影响说明契约

现有 `ILXMCommandEffect` 需要增加复制专用的结构化结果：源范围、插入位置、复制小节数和 `technique.omitted` 明细。影响位置统一指向编辑前的源小节；no-op/失败不返回复制 effect。页面只渲染 effect，不根据前后文档自行推断遗漏。

### 8.7 验收补充

- 验证 schema 4 输入被明确拒绝或经过显式升级函数后成功加载，不能出现静默兼容。
- 验证自定义调弦的 pitch/midi 矛盾、重复索引、非六弦、capo 越界均原子失败。
- 验证复制范围为空、起止倒置、锚点在源范围内、首尾插入、重复复制、复制后撤销/重做和宿主单次通知。
- 验证复制后的 barline、拍号变化点、歌词/和弦排序、连音成员和所有技巧引用经过语义校验。
