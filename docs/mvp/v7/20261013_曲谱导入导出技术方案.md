# 曲谱导入导出技术方案

日期：2026-10-13  
状态：已实施并完成验证。

## 1. 目标与范围

增加“导入曲谱”“导出曲谱”入口，让用户将正在编辑的曲谱保存为本地文件，并能重新打开继续编辑。

本次采用六线猫原生 JSON 文档，默认下载文件名为 `{曲名}.lxm.json`，导入接受 `.lxm.json` 和 `.json`。内容包含标题、作者、编配者、调性、轨道设置、拍号、小节、音符、节奏、歌词、简谱、和弦、指法图、技巧、连音等当前文档支持的数据，保持业务 ID、schemaVersion 和 documentRevision。当前文件契约为 `schema: "lxm-tab-score"`、`schemaVersion: 7`，JSON 根节点直接采用 ILXMDocument，不增加包裹层。

本次不扩展文档 schema，不引入云端曲谱库、账号或自动保存；MusicXML、MIDI、PDF、图片识谱等格式转换留作后续独立需求。现有 A4 图片导出继续保留，并使用“导出曲谱”和“导出图片”明确区分两个入口。

## 2. 现有基础

- 核心 `loadDocument` 已完成 JSON 解析、严格 schema 校验、版本检查与音乐语义校验；当前不支持的版本会返回明确错误。
- 网站 `loadEditorDocument` 在核心校验后进一步限制为当前编辑器支持的单轨、非空小节曲谱。
- store 的 `replaceDocument` 仅在校验成功时提交新文档，随后清理选区、技巧焦点、剪贴板、错误和撤销/重做历史，递增会话版本。
- `EditorSession` 随会话版本重建编辑器壳，可清理输入定时器、侧栏草稿、图片预览等旧文档状态。
- 当前图片导出已有未应用草稿保护；曲谱文件操作复用相同判断。

工作区现有 UI 重构设计文档和设计稿保持原样，本次入口接入当前实际编辑器，不提前实施完整 UI 重构。

## 3. 用户流程

### 3.1 导出曲谱

1. 点击“导出曲谱”。
2. 检查是否存在待提交品位、歌词/简谱/和弦草稿、设置草稿或输入法组合输入；存在时提示先应用或取消，避免用户误以为草稿已保存。
3. 获取当前已提交文档快照，执行 JSON 可序列化检查（特别是开放的 `score.meta`），拒绝循环引用、非有限数字、BigInt、函数等会丢失或改变数据的值；可选字段的 undefined 按字段缺省处理。序列化后用与导入相同的完整预检入口重新加载，避免直接导出未经验证的内存对象。
4. 使用 UTF-8 JSON、两空格缩进和末尾换行生成文件，检查最终 UTF-8 字节数不超过 10 MiB，并遵守与导入相同的结构预算；通过 Blob 与浏览器下载保存到本地。超限时给出明确提示，避免导出的文件被本程序拒绝导入。
5. 文件名清理路径分隔符、控制字符及常见文件名禁用字符；空名称回退“未命名曲谱”，保留中文名称。
6. 下载完成触发后释放对象 URL；不改变文档、revision、选区和历史。不将浏览器下载请求描述为已经写入磁盘。

导出内容仅为 ILXMDocument，不包含布局缓存、临时空行、选区、剪贴板、撤销历史、未应用输入、排版密度或指法图显示开关。

### 3.2 导入曲谱

1. 点击“导入曲谱”，有未应用输入时先提示处理；通过单文件选择器选择文件。
2. 先检查大小（上限 10 MiB），读取 UTF-8 文本并兼容文本开头的 BOM；扩展名仅用于文件选择提示，实际合法性以内容校验为准。
3. 使用下面的完整预检流程校验全部内容。失败时展示可读错误（包括字段位置或版本问题），保留当前曲谱、选区、历史和草稿，允许重新选同一文件。
4. 校验成功后展示确认窗口：文件名、曲名、轨道名、小节数，以及“导入将替换当前曲谱，并清空当前撤销历史；需要保留时请先取消并导出当前曲谱”。提供“取消”和“导入并替换”动作。
5. 用户确认时再次检查草稿保护和版本凭据，通过后调用现有 `replaceDocument`；只有返回成功才关闭导入窗口，原子开启新曲谱会话；新曲谱从默认视图打开，旧输入、剪贴板、选区和历史不跨曲谱继承。
6. 取消文件选择或确认窗口均不修改当前曲谱。导入替换不进入旧曲谱的撤销栈。

不自动升级旧 schema：采用当前 loader 的版本支持规则，避免静默改变旧文件含义。若需要旧版转换，后续通过明确的迁移入口提供单独预览与确认。

## 4. 状态与异步边界

- 文件控制组件管理读取中、待确认、失败三个状态；读取中避免重复触发，待确认时限制谱面编辑，并支持取消。
- 文件读取开始时记录会话身份、会话版本和文档状态版本；异步读取完成以及最终确认前再次核对。读取期间文档发生修改、撤销或宿主替换时，废弃待导入结果，提示重新选择，避免覆盖新的编辑结果。
- 组件卸载后不发布晚到的读取结果；新读取代次使旧读取结果失效。
- 文件选择器每次处理后清空值，保证同一文件可以重复选择；文件内容和解析错误作为普通文本展示，不执行或注入 HTML。
- 无可编辑文档时导出禁用，导入仍可用于恢复有效曲谱；入口应放在空文档返回路径之前，避免无文档时无法打开文件。

## 5. 实现划分

- 新增纯函数文件模块：文件大小限制、BOM 清理、导入校验、导出序列化与文件名生成；领域校验复用现有 loader。
- 新增 React 文件操作组件：文件选择、异步读取、导入确认、下载资源释放、状态反馈；使用 Hooks 和 TypeScript。
- `EditorShell` 接入文件操作入口和现有草稿保护，保持当前工具栏样式；错误反馈复用编辑器消息能力。
- 优先复用 `replaceDocument` 与会话重建机制；不另建一套载入流程。新增函数与异步保护、序列化等关键逻辑添加中文注释。

## 6. 验证与验收

- 完整曲谱导出再导入：文档深度相等，歌词、简谱、技巧、连音及音符均保留；重新导入后可编辑、撤销和重做。
- 测试无效 JSON、空文件、BOM、错误版本、字段/音乐语义错误、多轨、空小节曲谱及超大文件；失败不替换当前曲谱。
- 测试中文/空名称/特殊字符文件名，以及导出不包含 UI 状态、不改变 revision 和历史。
- 测试确认前取消、重复选择同一文件、晚到结果失效、读取期间文档变化、宿主替换；确认成功清空旧历史与剪贴板。
- 浏览器验收文件选择、导入摘要、确认/取消、下载文件、导出后重新打开以及草稿阻断。
- 执行相关测试、类型检查、相关 ESLint 和 `git diff --check`。

## 7. 审查结论

本次范围为“可继续编辑的原生曲谱文件导入/导出”，导入替换当前曲谱，并经过文件校验与摘要确认；已有图片导出保持独立。该范围已按本方案完成实施。


## 8. 可落地性复查补充

### 8.1 统一完整预检

导入与导出回读必须共用同一条入口，顺序如下：

1. 检查 UTF-8 字节数、去掉开头单个 BOM、解析 JSON；读取失败/非法编码以明确错误结束，不将其解释为有效曲谱。优先使用 `arrayBuffer` + `TextDecoder("utf-8", { fatal: true })`，保证编码错误不会被静默替换字符。
2. 在进入递归 schema 前进行迭代结构预算检查：JSON 嵌套不超过 64 层、容器与值节点总数不超过 200,000；给出明确的超限原因。结构预算同样用于导出，保护解析后校验与排版的主线程开销。
3. 调用 `loadEditorDocument`，检查 schema 7、严格字段、调弦、全局 ID 唯一性、Beat 连续 tick、小节容量、歌词/和弦锚点、技巧和连音引用等现有音乐语义。不得通过丢弃未知字段、修补时值、生成新 ID 或截断音乐内容来绕过错误。
4. 在网站文件边界增加音乐规模预算：最多 1,000 小节、20,000 拍点、20,000 项技巧；超限明确拒绝，不能以“文件不足 10 MiB”作为唯一可处理依据。该预算是本期明确支持的范围，不承诺所有体积合规的任意规模文件都能即时打开。
5. 使用正式 `buildLayout`（默认排版、无临时 paragraphEditing）与共享 `buildScoreScene` 预检；捕获异常，确认非空系统、小节/拍点映射齐全，画布、边界与场景几何为有限数值。两种排版密度和指法图显示/隐藏组合纳入回归测试；真实字体度量仍由现有挂载流程完成。
6. 只保存验证通过的候选文档用于导入摘要，不在预检阶段写入 store。最终确认使用候选快照，重新验证会话/文档版本和草稿状态后提交。

预检成功的含义是“该文件属于本版支持范围，数据合法且默认谱面能够完成布局与场景构建”；不意味着外部任意格式都可转换，也不将校验提示误报为导入完成。

### 8.2 提交、错误与下载资源

- 文件读取与候选验证不调用 `replaceDocument`，避免校验失败误更新 store；文件错误由文件组件展示。
- 版本凭据至少包含 sessionId、sessionVersion、stateVersion，以及 document 引用；导入前不靠文档 ID 判断是否同一编辑状态。
- 确认弹窗使用项目现有交互风格的可访问 modal/dialog，支持标题、初始焦点、Esc 取消、背景交互阻断与取消后焦点恢复；文件组件必须在空文档页也能渲染。
- `replaceDocument` 已有二次加载行为；实现不绕过它。成功后壳会卸载，不依赖旧组件的 setState 展示成功提示；成功反馈由新会话可见状态或独立于壳重建的反馈承载。
- `replaceDocument` 当前不会触发 `onChange`，文件导入本期沿用该外部载入契约；不能通过伪造 command 回调通知宿主。需要导入事件时再明确扩展契约。
- 对象 URL 在点击下载后延后释放，并在异常/卸载时兜底清理，避免立即释放导致下载竞争；下载与文件读取消均不能遗留临时 DOM 或资源。
- 错误区展示前若干条字段错误并说明总数，完整校验结果不因 UI 截断而变为成功。

### 8.3 验收补强

- 为文件纯函数模块补充真正的往返测试：当前全部 schema 7 标准谱例序列化→预检→深度比较→正式布局与场景构建。将真实的 schema 6 原始对象作为明确拒绝样本；当前仓库中部分文件名含 MVP6 的示例已经升级为 schema 7，不能仅按文件名判断版本。
- 使用带歌词第 1–4 段、简谱、和弦/指法图、特殊调弦、Capo、反复小节线、连音、跨拍技巧的组合样本验证数据保留；不要仅以“小节数量正确”判断导入成功。
- 在一次音符编辑、歌词/简谱应用和小节增删之后导出，重新导入再执行编辑及撤销/重做，证明导入结果可继续工作。
- 文件大小以字节检查，增加中文多字节、精确上限与超限测试；结构/音乐规模限制覆盖边界；无效 UTF-8、BOM、未知字段、重复 ID、失效引用、非连续 tick 都作为失败样本。
- 浏览器按实际下载文件重新导入，核对曲名、至少一个音符、歌词和简谱及图片预览；失败文件、取消、同文件重选和未应用草稿分别验收。

上述补充作为后续实施约束，与前文冲突时以本节明确的完整预检与错误处理规则为准。

## 9. 本次复查的实际验证结果

2026-10-13 使用临时可落地性测试验证，测试文件已清理，不提前提交功能实现：

- 7 个当前谱例完成 JSON 序列化→`loadEditorDocument`→文档深度比较，全部通过：MVP7.2、完整技巧谱、闷音谱、MVP7C、MVP7C 100 小节谱、16/100 小节图片质量谱。
- 每个谱例都测试 compact/comfortable × 指法图显示/隐藏四种组合，共 28 次正式布局与共享场景构建；画布尺寸与场景数字为有限值，系统数量对应，全部通过。
- 显式 schemaVersion 6 输入拒绝测试通过。首次验证误把名称为 MVP6、实际 schemaVersion 7 的现有示例当旧版本，已纠正测试样本；按文件内部 schemaVersion 判定版本。
- 现有 loader 和 editor-session 测试共 13 项通过，验证加载边界、失败不替换、成功会话重置等基础契约。本次临时验证 8 项通过。

这些结果确认可复用的加载、替换和排版基础能落地。新增文件读取、下载、统一预检、导入弹窗和草稿/并发保护已完成单元测试与浏览器验收。

10 MiB、结构节点和音乐数量限制为首期预算，100 小节谱已验证；实施时应测量接近上限的样本，若耗时或内存不满足交互要求，应在验收记录中调整统一预算或采用后台预检，不能把未测的 1,000 小节上限宣称为性能保证。
