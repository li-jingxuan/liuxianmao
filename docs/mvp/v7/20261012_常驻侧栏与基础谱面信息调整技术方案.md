# 常驻侧栏与基础谱面信息调整技术方案

> 2026-10-12。状态：用户确认后已实施；实际交付与验证见 [实施验收](./20261012_常驻侧栏与基础谱面信息实施验收.md)。依据用户对 v7.1-B 的六项验收反馈修订。本方案覆盖侧栏常驻、独立谱面设置页签、移除本版调弦入口、精简 capo 文案、基础歌曲信息配置与展示、默认连续填词。实施前以本方案审查结论为准，原 v7.1-B 验收保留为历史记录。

## 1. 范围和交付行为

| 用户反馈             | 本次交付                                                            |
| -------------------- | ------------------------------------------------------------------- |
| 侧栏不需要收起来     | 常驻侧栏，移除工具栏显隐按钮、侧栏关闭按钮与隐藏状态                |
| 设置不与歌词混在一起 | 三个独立页签：谱面设置、编辑歌词、和弦编辑；默认进入谱面设置        |
| 本版不需要调弦       | 移除标准/Drop D/自定义调弦 UI、谱面调弦文字和相关度量请求           |
| capo 不需要说明      | 只保留“Capo”位置输入和非零位置展示，删除相对品位说明；capo=0 不显示 |
| 增加歌曲信息         | 配置歌曲名称、编谱作者、调性和基础拍号，谱首统一显示                |
| 歌词默认连续填词     | 首次和重新进入歌词编辑默认连续填词，保留可主动选择的单拍编辑        |

本版不增加调弦高级页、多轨、播放、自动转调、作品管理、保存文件 UI、分页 PDF，也不扩大到 v7.1-C 的拍点拆分/合并和 Beat 粘贴。

## 2. 当前代码依据

- `EditorShell/index.tsx` 维护 `sidebarVisible`、显隐工具栏按钮及侧栏焦点回退；`MusicTextSidebar.tsx` 接受可见性回调并通过 close/Escape 隐藏侧栏。
- `TrackSettings.tsx` 当前直接插在歌词/和弦 tabpanel 之前，导致不同内容混在一起；设置只有局部输入，没有与音乐文本同等的页签草稿保护。
- `music-text-draft.ts`、侧栏 `loadTarget` 的默认录入模式均为 `single`，仅改下拉显示不能改变实际初始草稿。
- `score.title` 已存在，但缺少编辑命令和正式谱首标题；`score.meta` 是业务扩展对象，不适合作为无约束的作者/调性来源。
- 拍号已在每个小节保存，并通过 `measure.setTimeSignature` 保持容量合法。现有界面使用 `untilNextChange`，沿用已审查规则，不增加独立的歌曲拍号副本。
- 当前谱首调弦/capo 由 `system-content-layout.ts` 生成；相同文本的度量请求位于 `music-text-metrics.ts`。两处需一并替换，保持渲染、尺寸和打印一致。

## 3. 文档模型和版本策略

### 3.1 基础信息字段

在 `ILXMScore` 中正式声明：

```ts
interface ILXMScore {
  id: string;
  title: string; // 复用已有歌曲名称
  arranger: string; // 编谱作者，允许为空
  keySignature: ILXMKeySignature | null; // 1 的音高；null 表示未设置
  meta: ILXMRecord;
  tracks: ILXMTrack[];
}

type ILXMKeySignature =
  | "C"
  | "Db"
  | "D"
  | "Eb"
  | "E"
  | "F"
  | "Gb"
  | "G"
  | "Ab"
  | "A"
  | "Bb"
  | "B";
```

- 歌曲名称上限 128 个 Unicode 字符，作者上限 64 个；允许空值，非空文字采用 NFC、首尾空白规范化和单行控制字符校验。loader 校验规范化结果，命令负责规范化提交值。
- 空歌曲名称在谱面显示“未命名歌曲”，只作为渲染兜底，不自动写回文档。空作者不显示作者行。
- 调性选项展示为 `1=C`、`1=Db` 等，提供“未设置”。只描述数字 1 对应的音高，不推断大小调，也不自动改写 Note、和弦名、指法或技巧。
- 不在 `score.meta` 重复保存以上信息；不添加 `score.timeSignature`，不复制曲首拍号事实。
- `tuning` 数据和校验保留，加载已有非标准调弦文档不会自动改回标准。本次只撤下编辑入口与展示；核心命令不必为界面收窄而删除。现有和弦预设对非标准调弦的限制继续保留。

### 3.2 schema 5 → 6

新增必需字段和收紧标题校验属于正式契约变化，`CURRENT_SCHEMA_VERSION` 升级为 6；内置谱例同步升级，ID、节奏、音符、歌词、和弦和技巧保持不变。

- loader 只接受 schema 6，不静默迁移。
- 增加显式 `upgradeDocumentToCurrent(input)`，首批只支持合法 schema 4/5 对象到 schema 6，返回 `DocumentLoadResult`。
- schema 5 补 `arranger: ""`、`keySignature: null`；schema 4 另补 `capo: 0`。旧谱不凭空标为 C 调，也不从不受约束的 `meta` 猜测作者。
- 先按原版本字段形状校验，补字段后再通过当前 schema/语义校验；旧标题不符合新增限制时返回可展示错误，不截断或静默改名。失败不改变当前会话与输入对象。
- 当前尚未发布独立 SDK，历史 `upgradeSchema4To5` 入口需随升级更新文档与测试，统一替换为上述具名入口；不得让名为“升级到 5”的函数实际返回 schema 6。实施时搜索全部调用者和示例，明确记录接口变更。
- 不增加任意版本迁移链，不把文件打开/保存 UI 带进本次修改。

## 4. 领域命令与历史

新增 `score.setNotationInfo`：接收 `title`、`arranger`、`keySignature`，三个字段作为一个表单原子应用；不要求 trackId，目标是文档中唯一 score。核心入口需在依赖轨道的路由之前处理。

- 任一字段非法则整次拒绝，文档、revision、选区、历史与宿主通知不改变。
- 三字段规范化后均相同时为 no-op，保留原 document 引用。
- 成功一次 revision、一次历史和一次 `onChange`。保留 score ID、meta、tracks 和所有音乐实体引用事实，不从页面直接赋值。
- 表单草稿、活动页签和焦点不进入乐谱文档或撤销历史。

Capo、段落标记、小节复用复用现有领域命令。基础拍号使用现有 `measure.setTimeSignature`，与歌曲信息表单分开显式应用；不能先保存歌曲信息再失败于拍号，却向用户声称一次整表提交成功。

## 5. 拍号配置与显示

谱面设置页签显示第一小节当前拍号，不因用户点击其他小节而改变“基础拍号”的目标。

- 首批选项沿用 `2/4、3/4、4/4、6/8`，不开放随意整数输入。
- “应用基础拍号”从第一小节开始，以 `untilNextChange` 作用至编辑前已有的下一拍号变化点；若没有变化点，则覆盖当前整首谱。
- 界面在应用按钮旁明确作用范围，例如“作用于第 1–8 小节”。这是影响用户选择的必要说明，不与 capo 的解释文案混淆。
- 保留原小节工具的局部拍号编辑能力；它修改当前焦点起始的拍号段，与曲首基础设置消费同一领域事实。
- 真实音乐内容/文本/连音使缩容不合法时，继续原子拒绝，不能为了修改展示而截断音符或移除歌词。仅合法协调尾部容量休止。
- 谱首信息行取第一小节实际拍号。正文第一小节及后续变化点继续显示现有拍号，不改变此前 TAB 行头和拍号规则。
- 复制首小节到谱首、删除首小节、undo/redo、外部替换后，设置表单和谱首拍号都从当前第一小节重新解析。

## 6. 常驻侧栏与页签结构

### 6.1 内容归属

| 页签             | 内容                                                                 |
| ---------------- | -------------------------------------------------------------------- |
| 谱面设置（默认） | 歌曲名称、编谱作者、调性、基础拍号、Capo、小节段落标记、小节范围复制 |
| 编辑歌词         | 连续/单拍录入、歌词段号、目标拍点、预览、覆盖确认、歌词应用和删除    |
| 和弦编辑         | 和弦名称、预设、指法图和对应的应用/删除操作                          |

撤销/重做放在侧栏公共区域，作用于整份乐谱。歌曲信息、基础拍号与 capo 不依赖先选拍点；段落标记仍以当前焦点小节为目标，未选择时禁用并提示。范围复制可直接选择源起止和插入位置，不需要预先选择 Beat。

### 6.2 常驻与键盘行为

- 移除 `sidebarVisible`、toggle ref、`visible/onVisibleChange`、侧栏 X 按钮及“关闭面板”焦点回退逻辑，侧栏随会话常驻。
- Escape 从音乐文本编辑状态返回对应页签的非编辑状态，保留侧栏；存在未应用草稿时先走草稿保护，不能隐式丢弃。
- 点击谱面歌词/和弦仍定位目标并切换对应页签。程序触发切页签与手动点击共用同一入口。
- 使用独立 `SidebarTab = "score" | "lyric" | "chord"`；不把“谱面设置”塞入只能描述 Beat 音乐文本的 `MusicTextTarget.kind`。
- 页签提供正确的 tablist/tab/tabpanel、唯一 ID 和关联，键盘支持方向键切页签、Tab 进入内容；跨页签切换仍受草稿保护。
- 桌面端保留侧栏固定宽度和内部滚动；较窄窗口允许已有页面纵向排列，但不自动隐藏侧栏。本次不扩展为移动端版本。

## 7. 草稿保护与默认连续填词

### 7.1 统一切换规则

歌曲信息表单与歌词/和弦表单分别拥有值草稿与提交基线。切页签、切设置目标小节、结束编辑时，未应用值须支持“应用后继续 / 放弃后继续 / 继续编辑”。应用失败保持草稿和当前页签。

- 同页签或同目标重复操作不重新初始化、吞掉草稿。
- 应用设置不误触发音乐文本的“外部文档变化”清空逻辑；页面通过统一提交标记区分自己提交与外部历史切换。
- undo/redo 或合法外部替换按现有会话契约取消过期草稿并提示；非法替换保留状态。
- 中文 IME 组合态及候选确认 Enter 不提交、不切页签；复用现有组合状态/229/结束后时间边界规则。
- 尚未应用的设置输入不应因为用户编辑另一个设置字段而被 key 重挂载丢弃。

### 7.2 连续填词默认规则

- 初次进入歌词页签并开始编辑时，默认 `sequence`。
- 页面加载、会话重置以及结束编辑后重新进入歌词编辑，均以连续填词作为默认值；同一轮编辑中用户主动选择单拍后，换段或换拍保留该选择，避免不断强制回到连续模式。
- 双击/点击已有歌词定位为连续填词起点；连续草稿不自动拼接整段已有歌词，不伪造尚未输入的文本。已有歌词可通过单拍模式修改。
- 保留空格分隔、`_` 跳过、休止拍占位、段号、批量预览与覆盖确认规则；默认不允许覆盖已存在内容。
- 同时修改草稿构造函数和实际侧栏 `loadTarget` 的默认来源，并调整相关测试；不能仅把下拉选项换顺序。

## 8. 谱首布局和打印

核心新增谱首信息布局，建议独立 `score-header-layout.ts`，输出标题、作者及信息行的 glyph/bounds；`buildLayout` 将谱首高度加入整谱几何后再布局正文。

- 标题居中，使用正常字重；作者右对齐显示“编谱：姓名”。作者有独立行，避免与长标题相撞。
- 信息行显示已设置的 `1=C`、曲首实际 `4/4` 和非零 `Capo 2`；不显示调弦或“相对品位”说明。
- 标题/作者过长时按核心实际字形度量折行；不缩到不可读字号、不静默裁剪。信息行按可用逻辑宽度换行。
- 空作者不占行；调性未设置省略；capo=0 省略；歌曲名称为空使用“未命名歌曲”。
- 曲首信息以配置的逻辑 `systemWidth` 居中/右对齐，不能因某个超宽小节扩大画布而让标题偏到屏幕外。
- 段落标记仍由现有顶部行布局驱动，和谱首信息分开；移除旧的调弦/capo 顶部文字，避免两次展示。
- 字形测量请求、fallback、最终布局、viewBox、命中、选区与滚动使用同一套平移后的坐标。React 只渲染核心 glyph，不自行测量并挤压谱面。
- 打印沿用同一 SVG，歌曲信息在首部完整显示；本次不声称已完成 A4 分页或 PDF 输出。

## 9. 实施顺序与代码位置

1. 冻结 score 字段、schema 6、显式升级入口和信息编辑命令；升级内置示例、测试夹具与宿主说明。
2. 实现谱首信息度量与布局，替换旧调弦/capo 文字，验证画布、命中和选区平移。
3. 把侧栏抽象为常驻三页签，移除显隐契约；分离歌曲信息、谱内设置和音乐文本组件，不把整个新逻辑继续堆入 `MusicTextSidebar`。
4. 移除调弦 UI、精简 capo、接入歌曲信息/基础拍号表单和设置草稿保护。
5. 修改连续填词默认行为，完成键盘、IME、历史与会话替换回归。
6. 完成工程检查、桌面浏览器验收，更新路线图与验收记录；沿用用户此前授权提交并推送当前远程分支，核实远程 SHA。

本次只是与调整相关的职责拆分，不标记整个 EditorShell 历史重构方案完成。

## 10. 验收清单

- 侧栏始终可见，没有关闭/收起入口；Escape 不隐藏侧栏。
- 谱面设置、歌词、和弦内容互不混入；设置表单无需先选择拍点。
- 调弦编辑入口与谱面调弦文字消失；加载非标准调弦谱不会改写原 tuning 或音乐数据。
- Capo 仅显示非零位置，无解释文案；0–12 校验、历史与宿主通知不回归。
- 歌曲名称、编谱作者、调性经领域命令保存，刷新会话输入后可重新显示；不承诺浏览器刷新自动持久化。
- title/arranger 空值、Unicode 上限、控制字符、非法调性、schema 5 升级及版本拒绝有明确测试。
- 基础拍号与曲首、正文拍号一致；已有变化点保留；缩容受阻时原子失败；撤销/复制/删除首小节后信息同步。
- 长标题、长作者、长段落标记与歌词/和弦/技巧混合时不重叠，字体度量 fallback 和真实浏览器均验证；谱面点击位置与重排后的命中一致。
- 未应用的设置/歌词/和弦草稿跨页签受到保护，非法应用不跳走；IME 候选确认不当作提交。
- 默认连续填词、单拍切换、已有内容覆盖确认和单条历史均验证。
- `pnpm test`、`pnpm type-check`、`pnpm lint`、`pnpm build`、`git diff --check` 通过；完成桌面视口真实交互和截图记录。真实系统 IME 候选/打印需记录能实际验证到的边界，不以纯函数测试代替人工验收。
