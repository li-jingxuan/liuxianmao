# 谱面选区与编辑焦点解耦修复技术方案

- 日期：2026-10-13
- 状态：已获用户“开工”授权并实施；代码与回归结果见第 11 节。
- 范围：集中修复歌词／简谱焦点阻碍六线谱 beat 选择的问题，不启动整套 UI 重构。
- 前置共识：点击对象决定活动目标，侧栏 TAB 只决定展示工具；切换仍保护未应用草稿。

## 1. 问题与当前代码依据

### 1.1 用户可见问题

当前在歌词或简谱区域编辑后，直接点击六线谱 beat，不能稳定得到普通 beat 选区；需要先切到“谱面设置”或其他页签才能恢复。这使修改品位、拖选、填词和简谱录入之间的往返依赖无关页签。

### 1.2 静态分析发现

以下是代码审查结果，不代表已经通过真实页面复现或测试验证：

1. `EditorShell/index.tsx` 的 `handlePointerDown` 在普通六线谱选区处理之前调用侧栏 `move()`。侧栏以当前 `kind` 将六线谱点击解释成歌词／简谱／和弦目标，并吞掉正常 pointerdown。
2. `MusicTextSidebar.tsx` 把页签、草稿和编辑状态联系在一起；`focus: "score"` 只改变输入焦点意图，不能明确表达“已经选择六线谱对象”。
3. `EditorShell/index.tsx` 使用 `activeMusicTextTarget` 决定段落焦点、六线谱选区可见性和编辑空行，因此 SVG 获得 DOM 焦点不等于退出段落选择。
4. `NumberedEditor.tsx` 在目标／预览变化时持续调用 `onTargetChange`，没有区分“面板预览目标”和“谱面当前活动对象”。保留简谱页签时，单纯清空父层目标可能再次被子层效果恢复。
5. 歌词的 store 订阅、侧栏 targetKey／pending 聚焦 effect、正文 `onFocusCapture` 及简谱 `onInputActive` 都需要一起审查，避免切换后高亮或 DOM 焦点又被旧目标夺回。
6. 当前保护工具栏和谱面快捷键依赖 `musicTextEditing`。只取消高亮、不释放输入／待确认状态，仍可能无法输入品位；反过来直接解除所有阻断会绕过草稿保护。

本次不是单个 CSS 或 focus() 修复，而是对象选择与工具面板之间的交互契约修正。

## 2. 目标与非目标

### 2.1 本次目标

- 从歌词、简谱和和弦目标直接点击六线谱，即可选择对应 beat／弦格，不必切 TAB。
- 六线谱选区正常支持数字品位、方向键、删除、Shift 扩选和拖选。
- 从 beat 点击歌词或简谱（含有效空编辑位）时，可重新进入对应编辑。
- 切换侧栏 TAB 不自动把谱面活动对象改成歌词／简谱，不自动将焦点送入文本输入框。
- 未修改草稿不阻断切换；未应用修改统一确认，不失焦自动提交、不静默丢弃。
- 高亮与实际键盘行为一致，当前只存在一个活动谱面对象。
- 纯选区／焦点／面板切换不修改 document、revision 和历史。

### 2.2 不做

- 不调整领域 schema，不改变歌词／简谱／和弦命令语义。
- 不重构文件导入导出、分页、布局度量或全站 Ant Design 视觉。
- 不增加自动保存草稿、后台提交、多目标草稿仓库。
- 不把工具栏中的全部修改动作改成自动弹草稿确认；仍按现有输入保护禁用规则执行。
- 不改变已经应用的连续录入结果和撤销／重做契约。

## 3. 核心状态契约

明确区分以下状态，不能再由页签反推活动对象：

| 状态            | 职责                                 | 不应承担的职责                           |
| --------------- | ------------------------------------ | ---------------------------------------- |
| `sidebarTab`    | 展示谱面设置／歌词／简谱／和弦工具   | 决定所有谱面点击含义                     |
| `activeObject`  | 当前六线谱选区、歌词、简谱或和弦对象 | 表示 DOM 中哪个控件聚焦                  |
| `inputFocus`    | 用户是否正在操作文本输入／设置表单   | 直接改写 document 或选择对象             |
| `draft` / dirty | 未应用值及原始业务目标               | 跟随鼠标 hover 或普通选区先行迁移        |
| `pendingAction` | 等待草稿决策的对象／页签切换请求     | 提前更新选区或修改草稿起点               |
| `previewTarget` | 连续录入预览的检查位置               | 覆盖持久化选区或在 beat 模式重新激活段落 |

实现采用 TypeScript 判别联合和纯函数，区分六线谱 selection 与音乐文本 target。对象选择转移和草稿决策放到一个实际由生产代码调用的模块中，而非再增加若干相互补偿的布尔变量。

父层负责六线谱选区与统一对象命中；侧栏协调草稿、确认和面板。子编辑器只能报告草稿、输入与预览事件，不能无条件恢复父层活动对象。

## 4. 交互规则

### 4.1 鼠标点击

| 点击位置           | 接受后的行为                             | 页签行为             |
| ------------------ | ---------------------------------------- | -------------------- |
| 六线谱弦格／beat   | 活动对象变为 TAB 选区，SVG 获取焦点      | 保持当前页签         |
| 歌词／有效空歌词位 | 选中实际 beat 与 verse，进入歌词输入     | 展示歌词面板         |
| 简谱／有效空简谱位 | 选中实际 beat，进入简谱输入              | 展示简谱面板         |
| 和弦图元           | 保留现有和弦编辑入口与业务目标           | 展示和弦面板         |
| 可选技巧图元       | 走原技巧定位与选区流程                   | 不因文字页签吞掉点击 |
| 工作区空白         | 无草稿时清空临时选区；有草稿时经同一保护 | 不切页签             |

命中以 layout 为权威，保持 `getScreenCTM()` 坐标转换。图元／区域命中优先于六线谱单元格的泛化命中，尤其避免上方技巧被较大的 beat 命中区域吞掉。

点击六线谱的请求必须包含真正的选区意图，不再调用“按当前页签 move 到文字目标”的逻辑。

### 4.2 同拍切换也是对象切换

从某拍歌词／简谱点击同拍六线谱，即使 beatId 相同也必须切换对象类型。不能沿用“同拍重复点击，ignore”的判断放行脏草稿。

只有同类型、同目标、同 verse 的重复激活才可保留草稿并只调整焦点；弦号改变不构成文字业务目标改变，但六线谱选区应保留真实命中弦号。

### 4.3 TAB 与面板

- 切页签只展示工具并保留当前谱面活动对象；键盘切页签的焦点留在 tab 按钮。
- 没有文字活动对象时，歌词／简谱面板可根据当前选拍展示上下文，但不能上报活动段落高亮。
- 点击输入框或“编辑当前拍”才明确激活面板对应的文字对象。
- 换页签会销毁或重置当前草稿时，仍执行草稿确认；本次不实现跨页签保留多份 dirty 草稿。
- beat 被选择后保留文字页签，不强制跳转谱面设置。
- “没有输入内容”不能等价于“非法草稿”：空连续输入不应阻碍纯面板浏览或返回 beat；真正提交时仍使用现有校验。

### 4.4 连续录入起点

保留歌词／简谱现有单拍和连续录入模式，但移除“文字 TAB 可见时，任何六线谱点击都自动换录入起点”的隐式模式。

面板提供“从当前拍开始”动作：使用当前六线谱 focus 作为批次起点并进入输入。需要换起点时，先选择 beat，再点击该动作；无需额外全局锁定模式或修饰键。

连续输入中点击预览行只更新检查位置，不重写批次起点、不将六线谱普通选择解释为预览事件。

### 4.5 Esc

- 输入法组合中或候选刚确认时，不执行对象切换。
- 在草稿确认区按 Esc 等同“继续编辑”。
- 在歌词／简谱／和弦输入中按 Esc，请求退出文字编辑并返回该目标对应的 beat；有 dirty 时仍确认。
- 在 SVG 上按 Esc，若活动对象是段落则先请求返回 beat；若已经是六线谱则保留原折叠选区／取消品位草稿语义。
- 不强制改变当前侧栏页签，也不清空已应用的音乐数据。

## 5. 草稿保护与原子切换

统一切换请求流程：

1. 基于当前布局解析点击对象，记录真实目标、选区和 Shift 意图。
2. 检查正在组合输入、已有 pending、真实 dirty 或设置表单修改。
3. 干净时立即接受；有修改时只登记 pending，维持原活动对象、选区、批次起点和输入值。
4. 用户选择：
   - **应用并切换**：在原业务目标应用成功后接受 pending；失败保留原草稿和 pending，不迁移目标。
   - **放弃并切换**：丢弃原草稿后接受 pending。
   - **继续编辑**：取消 pending，恢复原输入焦点与高亮。
5. 接受后统一更新活动对象、选区、输入状态和焦点；不得先改 selection 导致 NumberedEditor 的 key 重挂载再弹确认。

确认成功后可能已发生文档／布局变化，执行前重新校验目标 ID 与会话身份。失效目标不使用旧坐标重新命中、不写旧会话；外部替换与历史切换复用既有草稿清理策略。

六线谱品位的延迟提交计时器在接受对象切换时取消，避免旧数字晚到写入新对象。仅开始确认而尚未接受切换时，不改变原文字草稿。

## 6. 焦点、选区和布局

- 段落高亮依据活动对象，而非页签是否可见。
- 返回 beat 后正常显示六线谱 focusCaret／selectionRects，并清除段落活动高亮。
- 面板读取上下文或简谱预览更新不能通过 effect 把段落重新激活。
- 调整 `onTargetChange` 报告路径、歌词 selection 订阅、`onFocusCapture` 与 targetKey／pending effects；只在已接受的激活动作后聚焦输入或 SVG。
- 文字草稿目标、预览占位与谱面活动对象分离，避免为了隐藏高亮而破坏仍受保护的空编辑行。
- 接受切换后取消无需要的临时空行；不改持久化布局内容。布局重排时按已记录目标 ID 更新选区和可见性，不能依赖旧像素坐标。
- 没有真实 dirty、输入操作或确认时，单纯保留文字 TAB 不得继续使六线谱工具栏 inert 或阻断 SVG 快捷键。

## 7. 拖选与 Shift 扩选

- 干净状态直接从六线谱 pointerdown 建立 anchor、捕获 pointer，pointermove 更新 focus。
- 文字活动对象转回六线谱时，普通点击从命中格开始；Shift 点击可沿用有效的原六线谱 anchor，不沿用文字预览行。
- 有 dirty 触发确认时不启动拖选，也不保存／重放已失效的 DOM PointerEvent。
- 确认后恢复待执行的点击选区（包括 Shift 的 anchor/focus）；若用户已经松开指针，不伪造后续拖动。需要拖选可在确认后重新开始。
- pending、取消、指针取消和对象切换均清理旧 pointer capture／drag refs，防止旧拖动继续改选区。

## 10. 审查点

本方案默认采用以下产品决定：

1. 点击 beat 后保留当前文字 TAB，不自动跳谱面设置。
2. 未应用修改仍使用三选一确认，不做失焦自动提交。
3. 连续录入起点改为“选 beat → 从当前拍开始”，不保留 TAB 隐式控制点击的模式。
4. Esc 返回当前文字目标对应的 beat，但不绕过草稿保护。
5. dirty 拖选在确认后恢复点击选区，不重放原指针拖动。

用户已确认并授权实施，按以上产品决定完成本次修复。

## 11. 实施与验收记录

### 11.1 已落地

- 新增 `editor-object-selection.ts` 纯函数模块，基于真实 layout 命中歌词／简谱／和弦、技巧和 TAB 单元格，不接收当前侧栏页签。文字目标只携带稳定业务 ID，不保存像素边界。
- `MusicTextController.select()` 通过草稿闸门返回 accepted／pending／blocked；只有接受后才更新 selection、清理旧 pointer capture、释放文字编辑状态并恢复 SVG 焦点。
- 侧栏新增独立活动对象、简谱业务目标与预览报告状态。简谱被动渲染不能反向激活段落；页签只展示工具，六线谱选择不会自动跳转谱面设置。
- 歌词起点使用“从当前拍开始”；简谱保留可主动输入的表单并提供同名入口。激活简谱时使用同一目标 key，防止重挂载丢掉用户直接输入的首字符。
- 同拍转六线谱、异拍选择、技巧选择、工作区空白、取消／Esc 与页签切换复用同一草稿保护；保留歌词、简谱和设置表单原有应用命令。
- 三项确认文案为“应用并切换／放弃并切换／继续编辑”。继续编辑恢复原表单控件，包括设置字段与 checkbox，不统一抢焦点到文字框。
- 简谱取消按钮不再提前 reset 草稿；返回 beat 保留当前页签，普通矩形选择、Shift 扩选和方向键仍走核心 selection 实现。
- 文字对象仍活动时保护六线谱修改快捷键；接受 beat 选择后正常解锁。取消延迟品位计时器与旧指针状态由对象切换共用。
- 空简谱输入浏览不展示“非法输入”提示，实际提交按钮仍执行核心校验。

### 11.2 原问题反馈环

真实浏览器脚本：`scripts/selection-focus.browser.cjs`。

使用本地服务、已安装 Chrome 与 Playwright，修复前运行原始路径：点击歌词 → 点击同拍弦格。断言“文字高亮应消失”失败：actual = 1、expected = 0。修复后沿用同一路径并扩展页面回归，通过。
