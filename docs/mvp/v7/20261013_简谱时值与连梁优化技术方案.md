# 简谱时值与连梁优化技术方案

日期：2026-10-13。状态：待审查，仅完成分析，未实施代码。

> 2026-10-13 范围扩展：用户要求增加简谱常用技巧、小节线及音高符号。后续实施以[简谱常用符号与技巧技术方案](./20261013_简谱常用符号与技巧技术方案.md)为主，本文保留早期连梁分析；原首阶段“无需 schema 升级”仅适用于纯派生时值显示，不适用于新增技巧持久化模型。

## 1. 结论

推荐继续使用 Beat 节奏作为简谱时值来源，在核心布局增加简谱专用减时线和连梁几何，网站与导出共同消费。先完成短时值、附点、分组及避让，再完善长时值表达。暂不引入独立简谱节奏模型。

这属于跨核心布局、文字度量、命中和导出链路的需求，应审查本方案后实施。

## 2. 当前实现与原因

- `core/types.ts`：简谱仅保存 `tokens`；Beat 已有 `rhythm.base`、`rhythm.dots` 和 `tick`。
- `core/numbered-notation.ts`：输入中的 `.` 是低八度编码，不是时值附点；`+` 保存同 Beat 多音，空格向下一个真实 Beat 移动。
- `layout/numbered-notation-layout.ts`：`layoutNumbered` 仅接收 tokens、坐标与文字度量，输出 labels、八度 dots 和 bounds；没有节奏参数或线段。
- `layout/system-content-layout.ts`：简谱位于 TAB/节奏/技巧下方、歌词上方；当前用数字和八度点的最低边界安排歌词。
- 网站 `MusicTextLayer.tsx` 与 `score-scene.ts` 都只输出简谱文字和八度点。因此编辑显示和图片导出均没有简谱时值线。
- `layout/duration-beam-layout.ts` 已有 TAB 节奏连梁：按实际 tick、拍组和连音分组，并处理混合层级。但它的坐标来自符干、梁向上叠加，还包含 TAB 特有附点策略，不能直接复制成简谱减时线。
- 已确认既有《简谱连续编辑技术方案》第 71 条：简谱时值来自 TAB Beat，不另外输入简谱 rhythm。此次沿用这个约定。

## 3. 产品规则

### 3.1 短时值

| Beat 基础时值 | 简谱数字下方 |
| --- | --- |
| 四分 | 无减时线 |
| 八分 | 一层 |
| 十六分 | 两层 |
| 三十二分 | 三层 |

单独短音也要有完整减时线；不能依赖相邻音存在才能画线。

连梁规则建议：

1. 仅在同小节、同拍组且音乐时间连续的简谱项间自动连接；沿用已有拍号 profile，不按像素距离或固定音符数量分组。
2. 缺失简谱、长时值、显式简谱休止 `0`、延音标记 `-` 断开共享连梁。短休止 `0` 自身仍显示对应层数的减时线。这是首版保守显示策略，跨休止连梁以后再提供控制。
3. 连音成员使用现有 tuplet 实际 tick 和边界；基础层数仍来自 `rhythm.base`，不能把三连音实际时长反推成其他音符类型。
4. 混合八分/十六分：第一层按拍组连接，额外层只连接满足该层的连续成员；单成员额外层保留自身短线。简谱短线覆盖字形宽度，不照搬 TAB 符干上的半梁长度。
5. 不跨小节或跨 system 连梁。未知拍号沿用项目现有保守分组回退。

例如 4/4 中连续四个八分项 `1 2 3 4`，默认按四分拍分成 `1—2`、`3—4` 两组；6/8 中六个八分项按现有拍组定义分成两组三音。这些线表示数字下方的减时线，不是数字右侧延音线。

### 3.2 附点、八度点与多音

- 附点来自 `rhythm.dots`，渲染在数字组右侧；继续保留 `.` 的低音输入含义，不修改输入语法。
- 简谱数字下方先排减时线，再排低八度点。整行共享减时线基线，禁止按各个低音点的位置分别下移连梁而形成折线。
- 多音 `1+3+5` 共用一个 Beat 时值，减时线覆盖整个数字组；同一层连接前组左缘至后组右缘。
- 不根据 token 数量均分 Beat 时长。如果用户想表达一个四分 Beat 内先后演奏两个八分音，应先拆成两个 Beat，各录一个简谱项。独立旋律时间轴需要另立需求。
- 简谱 `0` 与 TAB `kind` 允许不同，分组以简谱内容判定休止，实际时长取 Beat；不能仅因 TAB 是休止就隐藏已有简谱数字。
- 连音数字/括号应投影到简谱行，使其在导出中可解释；沿用同一 tuplet 数据，不新增节奏事实源，避免独立阅读简谱时将三连音误读为普通八分音符。

### 3.3 长时值分阶段处理

第一阶段补短时值连梁、附点和连音标记，不宣称简谱已经完整表达全部时值。

第二阶段补二分、全音符：在一个 Beat 的占用时间范围内生成延时横线，例如二分 `1 -`、全音 `1 - - -`；这些为派生几何，不新增 Beat 或写回 token。长休止使用对应休止表达，不能把长休止当成音符延音。附点长音、已有显式 `-` 和连音长值须建立专门谱例后冻结规则，避免重复生成延时符号。

如果要求简谱可独立阅读，两个阶段都必须完成。首阶段只是解决目前最明显的短时值缺失。

## 4. 技术设计

### 核心

1. 增加简谱节奏布局纯函数，输入小节领域数据、Beat 锚点和已测量数字组；生成减时线、时值附点与连音标记。
2. 从现有 TAB 算法提取与图形无关的分组能力，输入实际时间、拍组、tuplet 身份和参与条件，输出 Beat 分组。简谱和 TAB 分别计算几何、休止策略与孤立层级，避免为简谱改变现有 TAB 行为。
3. `NumberedLayout` 的八度 dots 与时值附点字段分开；小节级共享连梁保存成员 beatIds 和独立 bounds，避免一段跨 Beat 线重复保存到多个音符上。
4. 先测量数字与附点横向宽度，再做 spacing 和断行；确定横坐标后生成连梁。端点以数字组实际边界计算，不以符干 x 计算。线宽、间距和净空使用核心常量。
5. 垂直顺序为数字 → 减时线 → 低八度点 → 歌词。整行按最大层数规划基线与八度点区域，并以最终 bounds 计算歌词起点、system 高度和下一行位置。
6. 所有新图元接入最终平移、visual bounds 和分页边界；命中与选拍保持现有 Beat 归属，不给跨 Beat 共享连梁单独创建含糊的编辑目标。焦点框包含本 Beat 的局部减时线和点，避免整个连梁组变成一个巨大输入框。
7. 不新增持久化字段，因此首阶段无需 schema 升级。输入、复制粘贴、撤销模型继续保存 tokens；修改 Beat 节奏后布局自动重算。

### 网站与导出

- `MusicTextLayer.tsx` 使用核心提供的线段和圆点，不在 React 重新推导节奏。
- `score-scene.ts` 同步投影全部新图元；Canvas、分页图片及消费共享 scene 的导出路径复用。
- 保持现有简谱录入流程；编辑帮助文字明确“时值随当前 Beat，同拍多音共享时值”。
- 实现函数、关键分组算法及避让逻辑添加中文注释；采用现有 TypeScript、纯函数和 Hooks 风格。

## 5. 验收

- 单独八分/十六分/三十二分都有完整层数；连续同层、混合层级、附点八分接十六分显示正确。
- 4/4 与 6/8 连梁体现各自拍组；休止、缺失简谱、延音标记、跨小节正确断开。
- 高低八度、三层减时线、升降号、附点和最长多音组不互相覆盖。
- 三连音显示对应数字/括号，且实际时间与 TAB 一致。
- 修改时值、删除简谱、撤销重做后连梁即时重算；不产生存储迁移。
- 紧凑/舒适布局、末列多音、自动换行、分页和焦点框不裁切或覆盖歌词。
- 编辑 SVG 与导出图片图元一致；无简谱的谱面和既有 TAB 连梁无回归。
- 验收包含核心几何测试、网站投影测试、真实混合节奏谱的浏览器和导出检查。第二阶段另加长音/长休止/附点长音及显式 `-` 的谱例。
