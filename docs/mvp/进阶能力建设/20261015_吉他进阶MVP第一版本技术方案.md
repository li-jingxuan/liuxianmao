# 吉他进阶 MVP 第一版本技术方案

## 1. 文档信息

- 日期：2026-10-15
- 版本：MVP v1
- 状态：待审查
- 本轮修订：集中管理 `.ts` JSON 数据；组件归入 `components/`；移除拟新增的 `features/`；预留后续 `servers/` 数据迁移，不开始业务实现。
- 关联产品计划：[吉他进阶 MVP 计划书](./20261015_吉他进阶MVP计划书.md)
- 关联路线：[吉他进阶 MVP 实施路线拆分](./20261015_吉他进阶MVP实施路线拆分.md)
- 关联设计：[吉他进阶 MVP 设计落地契约](../../design/进阶能力建设/20261015_吉他进阶MVP设计落地契约.md)

本方案定义吉他进阶功能的第一个可运行版本。第一版本不是一次性实现完整的 4 个模块、8 节理论、6 个练习和 12 道考试题，而是先搭建稳定的业务框架，并跑通一条最小纵向闭环：

```text
吉他进阶入口
  → 学习路径
  → 节奏与拍点模块
  → 一节理论
  → 一个练习
  → 提交答案
  → 查看解析
  → 保存完成状态
  → 刷新页面后恢复
```

完成本版本后，再按实施路线扩展其他理论、练习、综合考试和进度能力。

## 2. 当前工程事实

当前仓库已经具备项目级技术基础，不需要重新搭建 Next.js 或创建新的 workspace package：

- `apps/website` 使用 Next.js、React 19、TypeScript、Ant Design 6.4.4、Zustand。
- `packages/lxm-editor` 是现有曲谱领域核心，负责曲谱文档、六线谱/简谱、节奏、和弦和弹奏技巧。
- 现有首页由 `apps/website/app/page.tsx` 和 `EditorShell` 组成，默认进入曲谱编辑器。
- 现有编辑器状态位于 `apps/website/stores/editor-store.ts`，包含编辑会话、历史、选区和临时 UI 状态。
- 当前没有课程内容模型、学习进度模型、练习评分或学习模块本地持久化。
- 现有测试主要使用 Vitest，网站测试位于 `apps/website/tests`。

因此本版本采用以下边界：

1. 学习功能属于 `apps/website` 内的独立业务模块，不新建 `packages/guitar-advanced`。
2. 可序列化的课程、练习和考试内容集中放在 `apps/website/data/guitar-advanced/`，使用 `.ts` 文件导出 JSON 形状的只读对象。
3. React 组件放在现有 `apps/website/components/` 下，领域逻辑放在 `lib/`，状态放在 `stores/`；不新增与 `app/` 平级的 `features/` 目录。
4. 学习状态独立于 `editorStore`，不写入 `lxm-editor` 曲谱文档。
5. 理论谱例先使用静态教学内容；需要复用现有谱面能力时，只读引用现有文档 fixture。
6. 首期使用浏览器 `localStorage`，不创建服务端接口、数据库或登录体系；后续通过 `servers/` 适配器迁移数据来源。

## 3. 第一版本范围

### 3.1 进入范围

第一版本实现以下能力：

- 新增 `/guitar-advanced` 学习模块路由。
- 新增独立的学习模块布局和左侧导航。
- 总览展示四个 MVP 模块，但仅“节奏与拍点”在第一版本开放完整内容。
- 节奏与拍点模块展示模块进度和一节理论入口。
- 实现理论详情页：目标、知识内容、谱例、易错点、完成本节。
- 实现一个单选练习：展示题目、选择答案、提交、评分和解析。
- 完成理论和练习后，将状态写入本地存储。
- 刷新页面后恢复完成状态和最近学习位置。
- 在现有产品中增加进入吉他进阶的可达入口。
- 为模型、评分、进度、存储恢复增加自动化测试。

### 3.2 第一版本暂不实现

- 和弦与进行、音阶与指板、弹奏技巧的完整理论和练习内容。
- 6 个练习的完整题库；第一版本只实现 1 个练习实例。
- 综合考试、考试暂存、考试结果、最好成绩和错题复习页。
- 多选、排序、谱面点击、指板定位和自由文本题型。
- 麦克风、录音、音高识别、节拍识别和演奏自动评分。
- 云端账户、数据库、跨设备同步、内容后台和推荐算法。
- 收藏、笔记、评论、打卡、排行榜和分享。

### 3.3 版本完成标准

用户能够从现有产品进入吉他进阶，完成一节节奏理论和一个练习；练习提交后可以看到确定性的正确/错误反馈和解析；刷新页面后理论与练习完成状态仍然存在；现有曲谱编辑器测试和构建不受影响。

### 4.2 目录职责

| 目录/文件 | 职责 | 不负责 |
| --- | --- | --- |
| `app/guitar-advanced` | Next.js 路由、页面入口、参数读取 | 评分规则、直接操作 `localStorage` |
| `components/GuitarAdvanced` | React 展示、用户交互、状态选择 | 维护内容副本、散落评分逻辑 |
| `data/guitar-advanced` | 集中维护 JSON 形状的课程、练习、谱例、默认进度及配置 | 保存运行中的用户记录、执行副作用 |
| `lib/guitar-advanced/catalog.ts` | 读取索引、按 ID 查询、校验内容引用关系 | 写课程内容、导入 UI 或存储实现 |
| `lib/guitar-advanced/model.ts` | 类型、枚举、领域数据形状 | React、Next.js、浏览器 API |
| `lib/guitar-advanced/grading.ts` | 纯评分函数、结果解释 | 修改 Zustand 或路由 |
| `lib/guitar-advanced/progress.ts` | 纯进度计算和状态更新函数 | 直接访问浏览器存储 |
| `lib/guitar-advanced/selectors.ts` | 从数据和进度推导页面所需状态 | 产生副作用 |
| `lib/guitar-advanced/storage.ts` | 序列化、版本校验、本地存储适配 | 页面渲染和业务评分 |
| `stores/guitar-advanced-store.ts` | Zustand 状态和动作编排 | 保存曲谱文档 |
| `servers/guitar-advanced`（后续新增） | 服务端内容读取、校验和进度存储适配 | 本版本不创建空目录或占位接口 |

### 4.3 依赖方向

```text
Next.js route
  ↓
components/GuitarAdvanced
  ↓
stores / selectors
  ↓
progress / grading / data
  ↓
model
```

`model.ts`、`grading.ts`、`progress.ts` 和 `storage.ts` 的核心逻辑不应依赖 React。数据文件只导出可序列化对象，不在其中放评分函数、store action 或页面逻辑。未来如果出现移动端或服务端复用需求，可以从 `lib/guitar-advanced` 中抽取稳定的纯逻辑到 `packages/guitar-advanced-core`，但本版本不提前拆包。

### 4.4 为什么不使用 `features/`

`features/` 是一种按业务切片组织代码的方式，理论上可以把组件、数据、状态和领域逻辑放在一起。但当前仓库已经使用 `app/`、`components/`、`stores/` 等目录，并没有统一的 `features/` 约定；本功能如果再新增一个与 `app/` 平级的 feature 层，调用者需要同时理解两套目录组织方式。

本版本因此采用“按职责分层”的方案：

- `components/` 只放 React UI 组件。
- `data/` 只放集中管理的静态 JSON 形状数据。
- `lib/` 只放可测试的纯领域逻辑和存储适配。
- `stores/` 只放 Zustand 状态编排。
- `servers/` 预留未来服务端数据适配，不在 MVP v1 创建真实接口。

这样做的重点不是把目录拆得更多，而是让数据、UI、状态和服务端迁移的替换位置清晰。目录命名本身不能保证低成本迁移，还必须遵守第 4.5 节的数据传递规则。

### 4.5 集中数据与后续服务端迁移

#### 数据的唯一维护位置

所有进阶业务的静态数据集中在 `apps/website/data/guitar-advanced/`，不散落在页面、组件、store 或 `lxm-editor` 的业务源码中：

| 数据文件 | 内容 |
| --- | --- |
| `guitar-advanced.data.ts` | 四个模块、开放状态、一节理论、一个练习、选项、答案及解析；后续题库和考试数据也在本目录扩展 |
| `score-examples.data.ts` | 教学谱例的 JSON 文档及稳定 ID；渲染逻辑仍复用现有编辑器能力 |
| `initial-progress.data.ts` | 默认空进度 JSON，供每个 store 实例复制，不是用户记录文件 |
| `settings.data.ts` | 内容版本、存储 key、状态 schema 版本等业务配置；不放密钥或环境凭证 |
| `index.ts` | 统一数据导出；不包含查询、评分或副作用 |

数据量增长后可以在本目录按模块或实体拆成更多 `.data.ts` 文件，仍只有一个维护位置和统一入口；“集中管理”不要求把全部内容挤进一个巨型文件。

#### 读取与处理规则

- `.data.ts` 只允许类型导入和 JSON 字面量导出；不放函数、JSX、Date、Map/Set、循环引用、`undefined` 或运行时计算。
- `satisfies` 用于编译时形状校验，读取端使用 readonly 类型；不得把类型校验误认为运行时数据校验。
- 路由或页面容器从统一数据入口读取，将数据传给展示组件；展示组件通过 props 接收，不直接依赖具体 `.data.ts`。
- `catalog.ts` 的查询函数、评分函数和进度函数通过参数接收内容数据；它们不自行导入默认题库。
- store 创建时注入目录数据、初始进度和存储适配器；初始 JSON 必须先复制，多个会话和测试不可修改同一份默认对象。
- 课程、题目、标准答案和解析不能在组件中维护第二份；通用按钮、错误提示等 UI 文案不属于课程数据，不必强行伪装成服务端内容。

#### 用户记录与源码数据分离

实际用户完成记录、提交答案和时间戳属于运行时数据，不写回 `.ts` 文件，也不把个人记录提交进仓库。它们由 `stores/guitar-advanced-store.ts` 管理，并通过 `lib/guitar-advanced/storage.ts` 保存到当前浏览器。默认进度中的 `updatedAt` 使用 `null`，实际状态变更时由动作注入 ISO 时间字符串。

#### 后续 `servers/` 迁移顺序

本版本只预留分层契约，不创建空 `servers/` 目录、不设计或实现 HTTP 接口：

1. 后续新增 `servers/guitar-advanced/`，由服务端从文件或数据库读取内容，并校验后输出相同的 JSON 数据形状。
2. 服务端路由或页面容器调用该层，再将可序列化数据传给 Client Component；客户端组件和客户端 store **不得直接导入** `servers/`、数据库驱动或凭证。
3. 本地初始数据来源改为服务端提供的内容；展示组件和纯领域函数继续接收相同的参数，不依赖数据来源。
4. 用户进度迁移是独立任务，需要确定账户归属、已有本地记录迁移、保存失败和冲突策略；不能仅替换内容读取就宣称完成云端同步。
5. 服务端读取可能异步失败，届时补充 loading/error、数据版本和缓存策略，另行审查服务端技术方案。

当前本地单选答案会随应用代码下发，可被用户查看；MVP 不属于可信考试或防作弊系统。后续需要可信考试时，正确答案与评分必须移到服务端，不能把含答案的整份 JSON 继续下发。

## 5. 领域模型

### 5.1 内容模型

内容模型的类型定义位于 `lib/guitar-advanced/model.ts`；实际内容和默认数据只在 `data/guitar-advanced/` 集中维护，其中课程、练习和答案集中在 `guitar-advanced.data.ts`。数据文件只能包含 JSON 可表达的数据：对象、数组、字符串、数字、布尔值和 `null`，不得包含函数、React 节点、Date 实例或浏览器对象。

建议数据文件形状如下：

```ts
import type { GuitarAdvancedData } from "../../lib/guitar-advanced/model";

/** 课程内容集中维护；保持 JSON 形状，未来可直接迁移到服务端响应。 */
export const GUITAR_ADVANCED_DATA = {
  modules: [],
  lessons: [],
  exercises: [],
} as const satisfies GuitarAdvancedData;
```

此代码块只表达导出结构；真实交付不得保留空数组，必须填入本版本内容。页面容器通过 `data/guitar-advanced/index.ts` 读取数据，再以参数传给组件和领域函数，不允许在组件内维护课程标题、选项或正确答案。

```ts
export type GuitarModuleId =
  | "rhythm-and-beat"
  | "chords-and-progressions"
  | "scales-and-fretboard"
  | "playing-techniques";

export type ModuleAvailability = "available" | "comingSoon";

export interface GuitarModule {
  id: GuitarModuleId;
  title: string;
  summary: string;
  order: number;
  availability: ModuleAvailability;
  lessonIds: readonly string[];
  exerciseIds: readonly string[];
}

export type TheoryBlock =
  | { type: "paragraph"; title?: string; content: string }
  | { type: "callout"; tone: "info" | "warning"; title: string; content: string }
  | { type: "scoreExample"; documentId: string; caption: string };

export interface Lesson {
  id: string;
  moduleId: GuitarModuleId;
  title: string;
  durationMinutes: number;
  order: number;
  objectives: readonly string[];
  blocks: readonly TheoryBlock[];
  exerciseIds: readonly string[];
  previousLessonId: string | null;
  nextLessonId: string | null;
}

export type ExerciseType = "singleChoice";

export interface ExerciseOption {
  id: string;
  label: string;
}

export interface Exercise {
  id: string;
  lessonId: string;
  moduleId: GuitarModuleId;
  type: ExerciseType;
  title: string;
  prompt: string;
  options: readonly ExerciseOption[];
  answer: { optionId: string };
  explanation: string;
  relatedLessonId: string;
}

export interface GuitarAdvancedData {
  readonly modules: readonly GuitarModule[];
  readonly lessons: readonly Lesson[];
  readonly exercises: readonly Exercise[];
}
```

第一版本只使用 `paragraph`、`callout` 和 `scoreExample` 三种理论块，只使用 `singleChoice` 一种题型。模型提前保留模块、关联理论和排序字段，为后续扩展做最小准备，但不实现未使用的交互。

### 5.2 学习状态模型

```ts
export interface ExerciseResult {
  exerciseId: string;
  selectedOptionId: string | null;
  isCorrect: boolean;
  submittedAt: string;
}

export interface LastVisitedContent {
  kind: "lesson" | "exercise";
  id: string;
}

export interface GuitarProgressV1 {
  schemaVersion: 1;
  completedLessonIds: string[];
  completedExerciseIds: string[];
  exerciseResults: Record<string, ExerciseResult>;
  lastVisited: LastVisitedContent | null;
  updatedAt: string | null;
}
```

以下状态不放进第一版本：考试答卷、成绩历史、错题复习状态、学习日历和用户设置。等考试路线开始时新增 schema 版本，不把未来字段伪装成当前已实现能力。

### 5.3 状态更新原则

- 完成 ID 使用集合语义，重复点击不会生成重复记录。
- 练习结果以 `exerciseId` 为 key，只保留该练习最近一次提交结果。
- 练习答错仍可记录为完成，学习路径不被错误结果阻塞。
- `lastVisited` 只记录最近一次理论或练习入口，不记录滚动位置和临时表单值。
- 每次持久化状态更新 `updatedAt`，时间统一使用 ISO 字符串。

## 6. 内容 fixture 设计

### 6.1 第一版本内容

第一版本只提供以下内容：

```text
模块：rhythm-and-beat / 节奏与拍点
  └── 理论：rhythm-eighth-sixteenth
        └── 练习：rhythm-identify-eighth-notes
```

总览仍然展示其他三个模块，但它们的 `availability` 为 `comingSoon`，页面使用“即将开放”状态，不提供虚假跳转。

### 6.2 理论内容

理论小节“八分音符与十六分音符”至少包含：

1. 三个学习目标。
2. 八分音符和十六分音符的概念说明。
3. 至少一个现有曲谱只读谱例。
4. 一个易错点提示。
5. 进入练习按钮。
6. 完成本节按钮。

教学谱例数据维护在 `data/guitar-advanced/score-examples.data.ts`，可参考现有 `packages/lxm-editor/example` 中的合法文档来编写，但不在 package 中新增学习业务数据。所有教学谱例通过正式 loader 校验；渲染复用已有能力，不修改曲谱 schema 或原有谱例。

### 6.3 练习内容

练习“从谱例中选出八分音符节奏”使用三个选项：

- 每拍一次。
- 每拍两次，正确答案。
- 每拍四次。

提交后显示：

- 回答正确或回答错误。
- 正确答案。
- “八分音符把一拍分成两份”的解析。
- 关联理论入口。
- 重新练习和返回学习路径操作。

## 7. 路由和页面方案

### 7.1 路由

```text
/guitar-advanced
  学习路径总览

/guitar-advanced/theory/rhythm-eighth-sixteenth
  八分音符与十六分音符理论详情

/guitar-advanced/practice/rhythm-identify-eighth-notes
  节奏选择练习
```

动态路由参数必须通过内容索引查找；找不到内容时使用明确的 404/内容不存在状态，不允许默认渲染第一节内容。

### 7.2 学习模块布局

`app/guitar-advanced/layout.tsx` 只负责学习模块的整体结构：

- 顶部品牌和返回曲谱工作台入口。
- 左侧学习导航。
- 主内容区域。
- 当前浏览器本地保存提示。

页面内容由各 route 自己负责。布局不读取具体理论或练习数据，避免所有页面耦合到同一个大组件。

### 7.3 页面组件边界

#### `LearningPathOverview`

- 读取模块列表和进度选择器。
- 展示总体进度、模块卡片、最近访问内容。
- 只调用导航回调，不直接拼接路由规则。

#### `TheoryLessonView`

- 接收 `Lesson` 和关联进度。
- 展示理论块和只读谱例。
- 点击完成时调用 store 动作。
- 点击进入练习时根据 `exerciseIds` 生成目标路由。

#### `PracticeQuestion`

- 管理当前页面的临时选择状态。
- 提交时调用纯评分函数或 store action。
- 提交后展示结果，不直接修改 `localStorage`。

### 7.4 视觉实现约束

- 沿用现有设计稿的 `#F4F6FA` 页面背景、白色面板、蓝色主操作和状态色。
- 优先使用 Ant Design 的 `Button`、`Tag`、`Progress`、`Alert`、`Radio`、`Card` 等组件；音乐谱例继续使用项目资源。
- 页面结构使用布局和内容区，不使用多层卡片嵌套。
- 正确、错误、学习中、已完成和即将开放同时使用文字和图标表达，不仅依赖颜色。
- 使用 CSS Module，避免新增全局样式覆盖现有编辑器。
- 长理论内容由内容区滚动，主操作必须保持可达。

学习布局通过 Provider 持有独立 store 实例；工厂注入内容数据、默认进度、时钟和存储适配器，测试创建互相隔离的实例。默认状态从 `initial-progress.data.ts` 复制，不共享可变对象，也不创建跨请求复用用户进度的服务端单例。

### 8.2 Storage 适配器

```ts
export interface ProgressStorage {
  read: () => string | null;
  write: (value: string) => void;
  remove: () => void;
}
```

实现两个适配器：

- `createBrowserProgressStorage()`：使用 `window.localStorage`，仅在客户端调用。
- `createMemoryProgressStorage()`：测试使用，保存在内存中。

`storage.ts` 负责：

1. 读取版本化 key。
2. JSON 解析。
3. 校验 `schemaVersion`、数组字段和结果字段。
4. 无效数据回退默认状态并返回错误信息。
5. 写入失败时保留内存状态并显示可恢复提示。

### 8.3 SSR 与 hydration

- 服务端首次渲染使用 `initial-progress.data.ts` 的空进度，`updatedAt: null`，不生成随机值或访问 `window`、`localStorage`。
- 客户端挂载后调用 `hydrate()`。
- `hydrated` 为 `false` 时，进度数字显示加载占位，不在服务端和客户端输出不同的完成状态。
- 存储损坏时页面仍可使用，展示“本地学习记录读取失败”的提示和清空记录入口。

### 8.4 持久化 key

```text
lxm-guitar-advanced-progress:v1
```

key 在 `settings.data.ts` 中定义一次，存储实现和测试引用同一配置，不在多个文件硬编码。后续 schema 发生不兼容变更时新增 `:v2`，不在读取时静默改写旧数据。第一版本不做迁移，只允许清空并重新开始。

## 9. 评分与进度计算

### 9.1 评分纯函数

建议接口：

```ts
export const gradeSingleChoice = (
  exercise: Exercise,
  selectedOptionId: string | null,
  now: string,
): ExerciseResult => ({
  exerciseId: exercise.id,
  selectedOptionId,
  isCorrect: selectedOptionId === exercise.answer.optionId,
  submittedAt: now,
});
```

真实实现需要先验证选项 ID 是否属于该题；非法 ID 按未作答处理，不能因为前端传入未知 ID 而判定正确。

### 9.2 纯进度函数

建议提供：

```ts
addCompletedLesson(progress, lessonId)
addExerciseResult(progress, result)
getLessonCompletion(progress, lessonId)
getModuleProgress(module, progress)
getOverallProgress(modules, progress)
getContinueTarget(modules, lessons, exercises, progress)
```

所有函数都返回新对象，不直接修改输入状态，方便测试和后续抽取到独立 package。

### 9.3 第一版本进度规则

- 理论完成：用户点击“完成本节”即记录完成。
- 练习完成：用户提交一次答案即记录完成，无论对错。
- 模块进度：第一版本只根据已完成理论和练习计算节奏模块进度。
- 总体进度：第一版本按已开放内容计算，不能把三个未开放模块计入分母导致进度虚低。
- 继续学习：优先返回最近一个未完成的开放内容；全部完成后返回复习入口。

## 12. 风险与处理

| 风险 | 处理方式 |
| --- | --- |
| 进度状态与 SSR 首屏不一致 | 默认空状态服务端渲染，客户端显式 hydrate，并使用 `hydrated` 控制进度展示 |
| `localStorage` 损坏导致页面崩溃 | 解析、版本和字段校验全部集中在 storage adapter，失败保留内存状态 |
| 学习功能污染现有编辑器 | 使用独立学习组件、领域逻辑和 store，不修改 `editorStore` 和曲谱 schema |
| 为未来考试过早设计复杂状态 | v1 只保存理论、练习和最近访问；考试字段在考试路线新增版本模型 |
| 设计稿与实际组件出现偏差 | 页面实现必须对照设计落地契约，不能只完成静态页面结构 |
| 内容过早扩张 | v1 仅允许一个开放模块、一节理论和一个练习，其余为明确 coming soon |

## 13. 审查决策

开始实现前需要确认：

1. MVP v1 是否采用“一个开放模块 + 一节理论 + 一个练习”的最小纵向闭环。
2. 已根据用户意见确定：数据集中在 `data/guitar-advanced` 的 `.ts` JSON 对象，组件归入 `components/GuitarAdvanced`，逻辑归入 `lib/guitar-advanced`，状态归入 `stores/`，不引入 `features/` 或新 package。
3. 是否确认用户进度暂存 `localStorage`；源码只管理静态内容和默认 JSON，后续 `servers/` 读取与用户进度迁移分别审查。
4. 是否确认总览展示四个模块，但只开放节奏与拍点模块。
5. 是否确认第一版本不实现综合考试，只为后续考试模型保留扩展边界。

以上决策确认后，可以从“第一步：模型与内容”开始实施；本方案本身不包含代码变更。
