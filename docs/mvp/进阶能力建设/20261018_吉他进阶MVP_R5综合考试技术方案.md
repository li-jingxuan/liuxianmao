状态：已按本方案完成 R5 实现与工程验收；实现和验收结果见[R5 实施与验收记录](./20261018_吉他进阶MVP_R5实施与验收记录.md)。本方案保留为产品与技术契约。

## 1. 目标与边界

R5 在四模块理论和练习完成后开放一场综合考试。用户可以开始、在 12 道固定题之间导航、保存并退出、恢复未提交答卷、提交并查看本次评分。考试按模块汇总分数，每个模块 3 题；满分 100 分，80 分及格。

考试使用浏览器本地存储，不新增服务端、登录或同步。它是学习检查，不是防作弊或认证考试：题目和答案随客户端代码下发，用户可检查浏览器代码或存储。分数、及格状态和阶段完成都只表示本地学习记录，不作为可信凭证。

R5 不实现详细成绩历史页、独立学习进度页、错题复习页或重考推荐；这些属于 R6。为使 R5 提交后不落入空路由，提交成功后显示本次总分、及格状态、四模块分数和返回入口。R6 再把此结果扩展为独立结果页、错题解释与历史成绩视图。倒计时、随机抽题、题目版本后台、音频题、监考和防作弊均不做。

## 2. 考试内容与分值

建立独立的固定目录 `apps/website/data/guitar-advanced/exam.data.ts`，包含唯一考试 `guitar-advanced-final-v1` 和 12 条稳定 ID 题目。考试题目不复用日常练习的提交 ID，避免一次考试答题覆盖练习完成、错题或已复习状态；可复用 `ExerciseAnswer`、题型输入组件和纯评分规则。题目定义使用当前四类题型：单选、多选、排序、指板目标选择，不新增自由文本或音频题。

每模块 25 分，模块内三题分别为 9、8、8 分，总计 100 分。按固定题序将模块三题标为 A/B/C 权重，不因用户答题顺序变化。所有题型按全对得满分、否则 0 分；多选不做部分分，排序和指板选择按完整答案集合/顺序判断。未作答得 0 分。页面/store 拒绝写入答案类型错误或结构非法的输入；若持久化草稿中出现非法答案，则按损坏草稿进入保护状态，不静默转换为未作答，也不继续评分。最终总分是题目得分之和的整数，无四舍五入误差；及格条件为总分 `>= 80`。

| 模块 | 题数 | 固定考查范围（每模块 A/B/C 各一题） | 分值 |
| --- | ---: | --- | ---: |
| 节奏与拍点 | 3 | 音符时值与拍单位；三连音/切分节奏辨认；节奏谱面位置或拍内分组 | 9 + 8 + 8 = 25 |
| 和弦与进行 | 3 | 三和弦构成音；C 大调 I–IV–V 和弦识别；和弦进行顺序/功能辨认 | 9 + 8 + 8 = 25 |
| 音阶与指板 | 3 | A 小调五声音阶音集；根音在指板上的位置；音阶位置辨认 | 9 + 8 + 8 = 25 |
| 弹奏技巧 | 3 | 击弦/勾弦记谱；滑音与推弦标记；闷音标记和演奏含义 | 9 + 8 + 8 = 25 |
| **总计** | **12** | 四模块均衡抽查 | **100** |

题目选项 ID 必须稳定、唯一、非空；每个标准答案须用题型结构精确编码。第 8 题的候选集固定为 `a-minor-fretboard.positions` 全部 12 个 ID，正确集合为 `string-6-fret-5` 与 `string-5-fret-0`。第 6 题初始排序固定为 `G,C,F`，正确答案为 `C,F,G`，确保排序题能验证实际排序变化。多选题按精确集合评分，不给部分分。所有单选至少 3 个含一个正确项的选项；第 11 题在同一题干中明确展示两种记谱示例，选项描述须分别指出两种符号含义，判分为整题全对。

题目顺序是稳定的 `order`，不会随机化。改变题意、答案或考查目标时必须使用新题目 ID；本期不提供题库版本管理和跨题目版本迁移。内容验收要求每模块三题、12 个唯一 ID、每题恰有一条合法标准答案、权重总和 100、模块小计 25，且关联理论均存在。

### 固定选择项 ID 与干扰项

选项 ID 同样视为持久化契约；标签允许修订，改变含义则新建题目 ID。单选/多选的选项按以下 ID 和语义建档，表中未标“正确”的都是干扰项：

| 题目 ID | 固定选项 ID → 标签（正确项加粗） |
| --- | --- |
| `exam-rhythm-note-value` | `half-beat` → 半拍；`one-beat` → 一拍（正确）；`two-beats` → 两拍；`four-beats` → 四拍 |
| `exam-rhythm-triplet` | `half-beat` → 半拍；`third-beat` → 三分之一拍（正确）；`quarter-beat` → 四分之一拍；`sixth-beat` → 六分之一拍 |
| `exam-rhythm-tie` | `reattack` → 第二拍前半重新拨弦；`continue-same-note` → 同一音延续，不重新拨弦（正确）；`silence-next-half` → 第二拍前半休止 |
| `exam-chords-triad-tones` | 选项 ID 与音名小写对应（`c`、`d`、`e`、`f`、`g`、`a`、`b`）；正确集合 `{c,e,g}` |
| `exam-chords-degree-map` | `c-f-g` → I=C、IV=F、V=G（正确）；`c-g-f` → I=C、IV=G、V=F；`a-d-e` → I=Am、IV=Dm、V=Em；`g-c-d` → I=G、IV=C、V=D |
| `exam-scales-pentatonic-notes` | 选项 ID 与音名小写对应（`a`、`b`、`c`、`d`、`e`、`f`、`g`）；正确集合 `{a,c,d,e,g}` |
| `exam-scales-minor-third` | `one-semitone` → 1；`two-semitones` → 2；`three-semitones` → 3（正确）；`four-semitones` → 4 |
| `exam-techniques-hammer` | `hammer-on` → 击弦 H（正确）；`pull-off` → 勾弦 P；`slide` → 滑音；`bend` → 推弦 |
| `exam-techniques-slide-bend` | `slide-then-bend` → `5/7` 为上滑音、`7b` 为推弦（正确）；`bend-then-slide` → 两符号含义对调；`hammer-pull` → 分别是击弦和勾弦；`slide-vibrato` → 分别是滑音和颤音 |
| `exam-techniques-muted-note` | `muted-no-pitch` → x 表示该弦闷音、无明确音高（正确）；`keeps-rhythm-slot` → 该拍点仍占时值（正确）；`is-full-rest` → x 等同整拍休止；`shortens-measure` → x 自动缩短小节时值 |

第 6 题排序项 ID 固定为 `c`、`f`、`g`，标签分别为 C、F、G，初始顺序 `g,c,f`，正确顺序 `c,f,g`。第 8 题沿用上文的 12 个指板位置候选和两个正确 ID。不得用显示标签作为答案 key，也不得在页面组件中另存一份正确答案。
## 3. 解锁与路由

考试唯一入口位于吉他进阶侧栏、总览和模块完成状态区域。解锁条件是当前目录中 8 个理论 ID 均已完成，且 6 个练习 ID 均已合法提交；答错练习也算完成，符合 v2 的练习完成语义。以 ID 集合检查全部课程条目，不依赖总览百分比、模块卡片文字或客户端传入的布尔值。

未解锁时，入口保留可访问的说明状态并列出尚未完成的理论和练习，提供对应模块/课程跳转；不得伪装成可开始的链接。v1→v2→v3 的迁移保留的有效完成 ID 参与解锁，不要求用户重复完成旧内容。考试开始动作再次检查条件，防止只靠页面状态绕过门槛。

建议路由：

- `/guitar-advanced/exam`：未解锁说明、考试入口，或活动草稿的“继续考试”入口。
- `/guitar-advanced/exam/attempt/[attemptId]`：考试答题页；刷新、返回该 URL 或从总览继续都恢复同一草稿。
- 提交成功后留在该 attempt 路由展示只读简要结果；R6 可迁移为独立结果路由，但 attempt ID 和记录格式保持稳定。

## 4. 答卷模型与状态机

一次考试尝试由稳定 `attemptId` 标识，固定包含考试 ID、考试数据快照、题目答案字典、当前题号、开始/更新时间、状态及提交结果。整个应用最多保留一个未提交草稿；草稿存在时，“开始考试”实际进入恢复流程，不创建第二份草稿。已经提交后再次开考才创建新 attempt，历史提交记录保留。

```text
无草稿
  └─开始（再次检查解锁条件）→ 草稿 / 进行中
                                  ├─保存并退出→ 草稿 / 暂停
                                  ├─切换题目→ 草稿 / 进行中
                                  ├─刷新或重进→ 恢复草稿
                                  └─确认提交→ 已提交（不可修改）
提交记录
  └─再次开考→ 新 attempt 草稿；既有提交记录保持不变
```

每个题目答案按其可区分联合保存，未答题不在答案字典中；导航状态由答案存在性和当前题号计算，不冗余写入“已答题数”。attempt ID 由浏览器 `crypto.randomUUID()` 生成，测试通过依赖注入固定 ID；创建时检查与历史 ID 不重复。当前题号用 0-based `currentQuestionIndex`，边界限制在 `0..11`。答题后立即将新答案和当前题号写入草稿，上一题、下一题及题号跳转均不改变答案。提交后 attempt 状态转为 `submitted`，快照、答案、总分、模块分数、是否通过和时间都冻结；任何后续答题均拒绝。若同一提交因刷新或重复点击再次到达，返回已有的不可变提交结果且不新增记录；重新考试必须使用新 ID。直接访问已提交 attempt 的 URL 显示只读结果，未知 ID 返回 404，不能通过 URL 创建考试。

提交按钮先展示未答题数量。存在空题时，弹窗给出“返回检查”和“仍按未答题提交”两个选择；确认后空题按 0 分计，避免意外把未答题当作已答。所有题已答时仍提供明确最终确认，说明提交后本次答卷不可修改。提交过程禁用重复操作；store 以 attempt 状态和 ID 作二次校验。

为保证草稿在刷新和后续静态题目微调后仍能恢复，attempt 在开始时保存完整的 12 题快照。类型定义为 `ExamQuestion = Exercise & { order: number; points: number }`，`ExamQuestionSnapshot` 使用同一结构的深拷贝，包含稳定题目 ID、模块、顺序、分值、题型、题干、选项/排序项/指板候选、标准答案、解析和关联理论 ID。草稿只从其快照渲染、评分，不在恢复时用当前题库覆盖快照。若题意或评分改变，发布新 `examId`（例如 `guitar-advanced-final-v2`），历史 attempt 仍由自身快照解释；本期不提供题库后台或自动迁移。快照不回写课程目录。它同样包含可检查的答案，不构成防作弊措施。

## 5. 评分与领域接口

在 `lib/guitar-advanced/exam.ts` 提供纯函数：

- `getExamReadiness(progress, catalog)`：返回 `eligible` 和稳定排序的 `pendingTargets`，每个目标含标题、模块及 href。
- `createExamAttempt(exam, attemptId, now)`：从静态目录生成唯一活动草稿及快照，初始题号为 0、答案为空。
- `setExamAnswer(attempt, questionId, answer, now)`：只接受草稿中已知题目和合法结构；保存后更新时间，不允许改已提交记录。
- `gradeExamAttempt(attempt)`：只读题目快照和答案，输出每题得分、总分、四模块分数、未答题 ID、是否通过；该函数不修改进度或考试状态。
- `submitExamAttempt(progress, attemptId, now)`：再次校验草稿和题目结构，计算结果并一次性固化提交记录；对已提交 attempt 返回 `alreadySubmitted` 及原结果，保证重试幂等且不修改记录。
- `getBestExamScore` / `getLatestExamAttempt`：从已提交记录派生，不持久化冗余统计字段；最近成绩按 ISO `submittedAt` 降序，时间相同按 attempt ID 字典序稳定决胜。

评分使用已验证的 `gradeExercise` 规则，禁止页面组件自行比较答案。入场前验证 12 道题的 ID、与练习/彼此的 ID 不冲突、题型、选项/目标引用、标准答案结构、题目顺序、权重和模块数量；无效目录不能开始考试。空答案不计入答案字典并按该题 0 分。页面/store 校验失败的答案不写入；如果运行时校验发现持久化答案无效、答案 key 未知或与快照不匹配，整份 attempt 被保护且禁止提交，保留原文供诊断，不能把损坏答卷当作未作答静默提交。合法答案按 `points` 记 0 或满分，模块分数为本模块正确题目的 points 之和，四模块模块分数相加必须等于总分。

## 6. 进度 schema v3 与持久化

新增 `GuitarProgressV3`，保留 v2 所有字段及语义，并添加考试集合和活动草稿标识：

```ts
interface GuitarProgressV3 extends Omit<GuitarProgressV2, "schemaVersion"> {
  readonly schemaVersion: 3;
  readonly examAttempts: readonly ExamAttempt[];
  readonly activeExamAttemptId: string | null;
}

type ExamQuestion = Exercise & {
  readonly order: number;
  readonly points: number;
};
type ExamQuestionSnapshot = ExamQuestion;

interface ExamAttempt {
  readonly id: string;
  readonly examId: string;
  readonly status: "draft" | "submitted";
  readonly questionSnapshot: readonly ExamQuestionSnapshot[];
  readonly answers: Readonly<Record<string, ExerciseAnswer>>;
  readonly currentQuestionIndex: number;
  readonly startedAt: string;
  readonly updatedAt: string;
  readonly submittedAt: string | null;
  readonly score: number | null;
  readonly moduleScores: Readonly<Record<GuitarModuleId, number>> | null;
  readonly passed: boolean | null;
}
```

`startedAt`、`updatedAt`、`submittedAt` 使用 ISO 8601 字符串；创建 attempt 时设置 `startedAt = updatedAt = now()`，每次答案或题号变更更新时间，提交时设置 `submittedAt = updatedAt = now()`，不在 R5 引入倒计时或超时失效。

草稿字段约束：`status="draft"` 时 `submittedAt/score/moduleScores/passed` 均为 `null`；已提交时这些字段均存在且 `activeExamAttemptId` 不指向该记录。所有答案 key 必须属于快照题目，且答案类型与对应题型一致；缺失答案 key 表示未作答。活动 ID 必须恰好指向唯一草稿；无草稿时为 `null`；attempt ID 唯一，且全局最多一个草稿。历史记录 ID 唯一，已提交快照和评分通过运行时校验后视为不可变。

新 key 为 `lxm-guitar-advanced-progress:v3`，`settings.data.ts` 同步升级 `progressSchemaVersion` 为 3。恢复优先级：v3 有值则只解析 v3；损坏时进入读保护，绝不回退到 v2/v1 覆盖异常。v3 缺失时读取并校验 v2；校验成功后原样保留 v2 学习字段，增加空考试历史和 `activeExamAttemptId: null`，写 v3。若 v2 缺失，再沿既有 v1→v2 迁移及规范化流程转换为 v3。每一步先运行时校验，未知版本、解析错误或不一致 key 均保留原始记录并进入读保护。v1、v2 原 key 作为迁移恢复来源保留，不回写旧版本。

所有考试变更沿用 store 的“先 hydrate、再变更并写最新完整快照”规则。每个改答、跳题、暂存、提交动作都校验 `activeExamAttemptId`、attempt ID 和 `draft` 状态；只有“开始考试”执行解锁检查，已有合法草稿则可恢复。写入失败时保留内存答卷，显式标记未保存并允许重试；重试写当前最新 v3 快照，不重新读取覆盖内存。清空时按 v1→v2→v3 顺序移除旧 key 和当前 key；任一步失败即保留内存进度并提示，全部成功才重置。考试存储错误不覆盖或伪装为无考试记录。多标签并发考试、事务锁和跨设备一致性不承诺，单浏览器遵循最后一次成功同步写入。

## 7. 页面交互与无障碍

答题页遵循考试进行中设计稿：顶部显示“进行中”、满分/及格线、12 题进度、已答/剩余数量和“暂存并退出”；主体显示当前题号、模块、题干和输入区；旁侧题号网格标识当前、已答、未答状态，并同时提供文字/图标语义，不能只靠颜色区分。提供上一题/下一题，首尾按钮禁用；选择题使用原生可键盘操作控件，排序及指板继续复用 v2 的无障碍输入组件。窄视口下题目区与题号导航按纵向布局，提交入口保持可达。

草稿恢复时显示“继续上次考试”及已答数，不自动开始新 attempt。保存并退出不清空草稿，更新当前题号后回到学习总览；进入考试入口时继续原答卷。读保护或写入失败状态应持续可见，并提供适当的刷新重读、保存重试或取消退出动作，不得在未保存时静默丢弃答卷。

## 8. 文件分层与建议实现顺序

| 目录 | R5 责任 |

## 9. 验收标准

- 未完成课程时不能创建 attempt；页面列出每项前置条件及返回路径。全部理论和练习完成后开始按钮可用。
- 固定题库正好 12 题，每个模块 3 题，模块各 25 分，总分 100，及格线 80；随机刷新不改变题目顺序。
- 所有题型均可作答、修改、通过上一题/下一题及题号网格切换；已答/未答/current 均有文字可访问状态。
- 每次答案变更和题号变化均更新草稿。退出后重进或刷新，答案、题号及已答进度完整恢复。
- 未答提交先给出数量及返回检查/仍提交选择；确认未答提交后未答题按 0 分。全答提交仍需最终确认。
- 提交产生不可变记录；重复点击、重复请求或刷新不产生第二条同 ID 结果，已提交内容不能被修改。再次考试创建新 attempt，旧成绩保留。
- 总分、四模块分数、通过状态和最好/最近成绩符合纯评分函数；未知题 ID、损坏答案、权重错误和快照不一致均拒绝评分或进入数据保护，不按满分处理。
- v2 有效记录迁移到 v3 后保留学习进度；v1 记录经既有转换后保留有效学习状态；损坏 v3 不回退覆盖 v2/v1；写失败保留内存且重试最新草稿；删除失败不重置内存。
- 键盘、窄视口、加载态、空草稿、提交态、存储故障有清晰行为；曲谱工作台既有测试通过，考试流程不更改谱面文档和编辑器状态。

## 10. 明确留给 R6 的工作

R6 从已提交 `ExamAttempt` 读取数据构建正式结果页：总分、及格状态、提交时间、四模块分数、最好/最近成绩、错题的用户答案/正确答案/解析和理论跳转；另提供学习进度与错题复习页面。错题答对后标记已复习但保留历史。阶段完成定义仍按路线：四模块完成且至少一次考试达到 80 分。R5 的提交摘要与 R6 正式结果页必须共用同一评分和记录，不能再次实现一套分数算法。
