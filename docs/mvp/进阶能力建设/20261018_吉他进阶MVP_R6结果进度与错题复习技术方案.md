## 0. 方案复审结论

已对照 R5 的实际模型、store、路由、进度函数和 R6 设计稿完成一轮复审。原方案方向可行，但实现前需固定以下边界，本文件已按结论修订：

1. **成绩计算与当前题库解耦。** R5 的 `gradeExamAttempt` 目前要求 attempt 的 `examId` 等于当前考试 ID，不能直接用它回算未来版本中的历史答卷。R6 结果和错题必须以 attempt 保存的总分、模块分数、及格线、题目快照和答案为准；逐题复核通过 `examId` 对应的版本校验器读取快照。R6 首期只接受已注册的 `guitar-advanced-final-v1` 版本；未来新增考试版本前必须先注册对应的快照结构校验器和评分器，旧版本不能被当前题库替换。
2. **复习状态键要包含考试版本。** 题目 ID 在不同考试版本中可能重用或改变语义，`examQuestionReviews` 使用 `${examId}:${questionId}` 作为 key，并保存最近一次待复习 attempt ID。新 attempt 再次答错时，旧复习标记自然失效。
3. **v4 存储要校验引用关系。** 每条考试复习记录必须指向已提交 attempt、该 attempt 快照中的同版本题目、且该题在该 attempt 中判错；时间戳必须是有效 ISO 时间。无效引用按 v4 损坏进入读保护，不静默丢弃。
4. **练习错题不伪造历史答案。** R5 练习存储仅保留每道练习的最近一次答案，错误 ID 则作为长期历史保留。R6 练习错题卡展示可取得的最近答案；若最近一次答对，明确标为“已复习/最近重做正确”，不声称能还原已被覆盖的早期错误答案。完整多次作答历史不在 R6 扩建。
5. **分数建议与自动推荐区分。** 结果页遵循设计稿和计划书，未通过时以四模块现有分数确定最低分模块并提供其模块入口；并列最低分全部展示。这是透明的排序提示，不生成个性化课程路径，不自动改变学习顺序。
6. **复用 v4 新 key 并保留回退保护。** 读取顺序定为 v4→v3→v2→v1；高版本 key 有值但损坏时保护原记录，绝不降级覆盖。清空时依次移除全部四个 key。

## 1. 路线定位与目标

R6 是实施路线中的“结果、进度与错题复习”，也是计划书中的“阶段 4：综合考试与进度”在 R5 考试能力之后的补全部分。它对应里程碑 M4“可复习版本”，位于 R5 之后、R7 集成与质量验收之前。

R6 将 R5 的“本次考试结果摘要”扩展为完整学习闭环：用户提交考试后能查看本次成绩和历史成绩，知道四个模块的完成情况，定位待复习的练习错题和考试错题，并返回理论、重新练习或再次考试。

R6 继续使用当前浏览器本地存储，不新增登录、服务端、跨设备同步、教师端或学习报告分享。考试记录仍然只是本地学习记录，不作为认证凭证。

## 2. 范围与不做项

### 2.1 本期实现

- 独立考试结果页：总分、及格线、通过状态、提交时间、考试用时、四模块分数。
- 最近一次成绩、最好成绩、考试次数和继续考试入口。
- 学习进度页：理论完成数、练习完成数、四模块进度、综合考试状态和阶段完成状态。
- 错题复习区：练习错题与考试错题分组展示，标记待复习/已复习状态。
- 错题详情：用户答案、正确答案、解析、关联理论和重新练习入口。
- 重考入口：从结果页和进度页进入 R5 考试入口，保留历史答卷和最好成绩。
- v3→v4 进度迁移、运行时校验、损坏记录保护和清除所有版本本地记录。
- 结果页、进度页和错题区的空状态、读保护、保存失败提示及键盘可达性。

### 2.2 本期不实现

- 错题数据导出、分享和打印。
- 基于成绩的自动课程推荐、个性化学习路径或智能难度调整。
- 考试题随机化、题库后台、云端成绩同步和账号体系。
- 音频题、录音识别、节拍器和演奏能力评估。
- 教师批注、班级排名、证书或可信考试凭证。

## 3. 用户流程

```text
完成理论与练习
  → 进入综合考试
  → 提交答卷
  → 本次考试结果
      ├─查看错题解析
      │    ├─查看关联理论
      │    ├─重新练习
      │    └─标记已复习
      ├─查看学习进度
      └─再次考试
```

进入结果页时必须使用 URL 中的 `attemptId` 查找已提交答卷。未知 ID、草稿 ID 或损坏答卷显示明确错误，不通过 URL 创建考试，也不把草稿伪装成成绩。

从 R5 旧答题路由访问已提交 attempt 时，保留兼容行为：显示只读结果摘要，并提供进入新 R6 结果页的入口。R6 新提交流程完成后进入 `/guitar-advanced/exam/result/[attemptId]`。

## 4. 进度与成绩模型

### 4.1 v4 进度结构

R5 的 v3 已保存考试历史和考试快照，R6 不改变既有 attempt 的含义。由于 R6 需要区分“考试错题已复习”和“练习错题已复习”，新增进度 schema v4：

```ts
interface ExamQuestionReview {
  readonly attemptId: string;
  readonly reviewedAt: string;
}

interface GuitarProgressV4 extends Omit<GuitarProgressV3, "schemaVersion"> {
  readonly schemaVersion: 4;
  /** key 为 `${examId}:${questionId}`；记录针对哪一次答错答卷完成了复习。 */
  readonly examQuestionReviews: Readonly<Record<string, ExamQuestionReview>>;
}
```

`examQuestionReviews` 只记录用户主动点击“标记已复习”后的状态，不删除考试历史、不改写原始答案、不改变分数。R5 的 `reviewedExerciseIds` 继续只表示练习复习状态，不复用给考试题。

v3→v4 迁移规则：复制全部学习字段、练习结果和考试历史，新增空的 `examQuestionReviews: {}`，并写入 `lxm-guitar-advanced-progress:v4`。读取顺序为 v4→v3→v2→v1；v4 缺失时才读取 v3，v3 缺失时再读取 v2、v1。任一最高优先级已存在记录若校验失败，均进入读保护，绝不回退覆盖旧版本。v1/v2 迁移仍沿用 R5 已实现的单向迁移链，最终统一写入 v4。迁移成功保留旧版本来源 key，清空进度才移除全部旧 key。

v4 校验除字段和时间格式外，必须交叉检查复习记录引用：key 中的 `examId/questionId` 与 attempt 一致；attempt 必须已提交；快照中必须包含该题；按已知版本校验器复算后该题必须答错；`reviewedAt` 不早于 attempt 的开始时间。未注册 examId 的 attempt 不进入有效 v4 记录；新增版本必须先补齐对应校验器和迁移/结果展示测试。

### 4.2 成绩选择规则

- 最近一次成绩：当前固定考试版本的 `status="submitted"` attempt 中，按 `submittedAt` 最大者取得；时间相同时按 attempt ID 升序，保证结果稳定。
- 最好成绩：当前固定考试版本的已提交 attempt 中 `score` 最大者；分数相同时取提交时间较新者，再以 attempt ID 升序打破平局。
- 考试次数：已提交 attempt 数量，草稿不计入。
- 阶段完成：四个可用模块的理论和练习全部完成，且最好成绩 `>= 80`。
- 模块进度：沿用 R5/R4 的内容完成规则，理论和练习分别计数；共享内容按唯一 ID 计数。
- 考试模块成绩：直接使用提交 attempt 中冻结的 `moduleScores`，不重新用当前目录覆盖历史成绩。

### 4.3 错题集合规则

练习错题沿用现有 `wrongExerciseIds`、`reviewedExerciseIds` 和 `exerciseResults`：错误历史保留，再答对或完成复习后标记已复习，不从历史结果中删除。

考试错题由已提交 attempt 的快照和版本化评分函数推导，不额外复制题目文案。对当前支持的每个 `examId` 注册快照结构校验/评分器；新增考试版本时保留旧版本处理器。结果总分和模块分数始终取 attempt 中冻结且由存储层校验的字段，不能由当前题库重算覆盖：

1. 对每个已提交 attempt 按其 `examId` 查找快照评分器，再对该 attempt 的 `questionSnapshot` 和 `answers` 评分；不匹配当前静态题库。
2. 取 `questionGrades` 中 `isCorrect=false` 的题目。
3. 按题目 ID 聚合，保留最近一次出现的 attempt、用户答案、正确答案和解析引用。
4. 在同一个 `examId:questionId` 内，若最近一次考试答对，则该题从“待复习”集合移出，但历史考试结果仍保留。
5. 若最近一次答错，且 `examQuestionReviews[examId:questionId].attemptId` 等于该次答错的 attempt ID，则展示为“已复习”；否则展示为“待复习”。
6. 新一次考试再次答错会产生新的 attempt ID，旧的“已复习”状态自动失效，避免错误被旧记录掩盖。

这个规则使进度页展示当前需要处理的题目，同时保留考试历史和每次答卷的原始证据。

## 5. 结果页设计

### 5.1 路由与入口

新增路由：

- `/guitar-advanced/exam/result/[attemptId]`：R6 独立结果页。
- `/guitar-advanced/progress`：学习进度与错题复习页。

R5 的 `/guitar-advanced/exam/attempt/[attemptId]` 在已提交状态下继续可读，并提供“查看完整结果”链接。提交成功后由答题页跳转到新结果路由；重复打开结果路由不会重新评分或新建 attempt。

### 5.2 页面区块

结果页按以下顺序展示：

1. **成绩头部**：考试标题、本次得分/满分、通过或未通过、提交时间和考试用时。
2. **模块分数**：节奏与拍点、和弦与进行、音阶与指板、弹奏技巧各自得分和占比；使用文字和数值表达，不能只依赖颜色。
3. **成绩对比**：本次考试版本中的最近一次成绩、最好成绩、历史考试次数；无历史记录时显示首次考试空状态。不同 `examId` 的成绩按版本分组，不混算最好成绩。
4. **错题摘要**：本次错题数量、待复习数量和“查看全部错题”入口。
5. **学习建议**：未通过时找出本次四模块最低分模块；并列最低分全部展示对应模块入口。这是透明的分数排序提示，不生成个性化学习顺序。通过时不显示失败复习建议。
6. **操作区**：查看错题、进入学习进度、再次考试、返回学习路径。

结果页必须使用提交 attempt 的冻结数据。当前题库文案、课程目录或分值改变后，历史结果仍按其快照渲染；总分和模块分数显示存储层校验过的提交值。若历史 `examId` 没有逐题评分器，当前版本按损坏记录保护，结果页显示“成绩记录无法校验”；新增版本必须先提供版本化评分器再允许写入。若存储校验失败，显示“成绩记录无法校验”，保留原始记录并提供返回进度页的入口。

### 5.3 错题详情

每道考试错题展示：题号、模块、题干、用户答案、正确答案、解析、当前状态和关联操作。用户答案为空时显示“未作答”，不把空答案渲染成错误选项。目标选择答案使用快照中的目标 ID 和当前可用指板数据格式化位置；素材失效时仍显示原始标签和文本解析。

关联理论使用题目快照中的 `relatedLessonId` 与 `reviewLessonIds`，先通过当前目录校验目标是否存在和可用，再生成理论链接。重新练习列出相同模块且 `lessonId`/`relatedLessonId` 命中复习理论的现有练习；存在多道练习时全部列出，若没有匹配练习则仅显示关联理论入口，不创建不存在的 URL。练习错题卡以现有 `exerciseResults` 最近答案呈现，不声称保存了后续重做已覆盖的旧错误答案。

点击“标记已复习”执行 store 动作：校验该题属于当前已提交且确实答错的 attempt，写入 `examQuestionReviews[examId:questionId] = { attemptId, reviewedAt }`，成功后更新卡片状态和待复习数量。重复点击保持幂等；对已答对题目、未知题目或草稿题目拒绝写入。UI 传 attempt/question ID，复习 key 由 store 从已校验 attempt 派生。

## 6. 学习进度页设计

### 6.1 页面区块

- **总览头部**：总体完成度、已完成/总项目数、阶段状态。
- **模块进度卡片**：每个模块显示理论完成数、练习完成数、模块完成状态和进入模块按钮。
- **考试进度卡片**：最近成绩、最好成绩、考试次数、是否已通过、草稿继续入口和再次考试入口。
- **待复习区**：按“练习错题”“考试错题”分组，显示待复习数量、已复习数量和每个模块的分布。
- **阶段状态**：课程仍未完成时显示学习中；课程已完成但没有及格记录时显示可考试/待通过；课程完成且任一有效考试通过后显示阶段完成。
- **空状态**：未开始学习、尚未考试、没有错题、错题已全部复习均分别给出下一步按钮。

### 6.2 进度口径

学习进度页复用 `getModuleProgress`、`getOverallProgress` 和 `getContinueTarget` 的纯函数，新增 R6 selector 集中计算考试和错题状态。页面不自行遍历存储、不自行评分、不直接修改进度对象。

阶段状态分为：

- `learning`：仍有理论或练习未完成。
- `exam-ready`：全部理论和练习已完成，但没有通过考试。
- `completed`：全部理论和练习完成，且最好成绩达到 80 分。

未通过考试时，页面可以显示“继续复习错题”与“再次考试”；不自动替用户选择模块或生成推荐课程。

## 7. Store 与领域接口

在 `lib/guitar-advanced/exam.ts` 或新增 `lib/guitar-advanced/results.ts` 提供无副作用纯函数：

- `getLatestExamAttempt(attempts)`：取最近提交记录。
- `getBestExamAttempt(attempts, examId)`：取指定考试版本最好成绩对应的完整 attempt。
- `getExamHistory(attempts)`：按时间稳定排序的提交记录摘要。
- `getExamQuestionReviewItems(data, progress, gradersByExamId)`：按 attempt 快照版本聚合考试错题及复习状态，不用当前题库替换历史题目。
- `getExerciseReviewItems(data, progress)`：将练习错题转换为可展示的理论/练习链接。
- `getLearningStage(data, progress)`：返回 `learning | exam-ready | completed`。
- `getProgressSummary(data, progress)`：返回总进度、模块进度、考试指标和待复习数量。

在 store 增加：

- `markExamQuestionReviewed(attemptId, questionId)`：幂等写入 v4 复习记录。
- store 根据 `attemptId` 派生 `examId:questionId` key，不接受 UI 传入任意存储 key。
- `get` 类动作只读当前状态，不直接产生副作用；页面展示使用 selector 或纯函数。
- `retryPersist`、读保护、写失败和清空逻辑沿用 R5，并扩展到 v4 key。

提交考试后的写入必须保持原子语义：先保存提交 attempt，再由结果页的“标记已复习”单独写入复习记录。标记复习失败时，当前页面保留原状态并显示重试入口，不修改成绩。

## 9. 验收标准

### 9.1 成绩与结果

- 提交考试后立即进入独立结果页。
- 结果页总分、通过状态、模块分数与 R5 评分函数一致。
- 最近成绩、最好成绩和考试次数在刷新后保持一致。
- 直接访问未知、草稿或损坏 attempt 时有明确错误状态，不创建新记录。
- 结果页支持查看错题、进入进度页和再次考试。

### 9.2 错题复习

- 练习错题与考试错题分组展示，题目 ID 不冲突。
- 每道待复习题都能进入关联理论；存在匹配练习时能进入重新练习。
- 用户答案、正确答案和解析与对应提交记录一致。
- 标记考试错题已复习后，待复习数量立即减少，刷新后状态仍保持。
- 新考试再次答错同一题时，旧复习状态不会错误覆盖新错题。
- 考试历史和练习错误历史不会因为标记已复习而被删除。

### 9.3 学习进度

- 总体进度、模块进度与学习路径总览使用同一计算函数。
- 未学习、未考试、无错题和全部复习完成均有明确空状态。
- 全部课程完成但考试未通过时显示 `exam-ready`，不误标记阶段完成。
- 最好成绩达到 80 且课程全部完成后显示阶段完成。
- 草稿存在时显示继续考试入口；提交记录存在时显示最近成绩和再次考试入口。

### 9.4 工程与浏览器

- v3 数据可无损迁移到 v4；v4 损坏时进入读保护，不回退覆盖 v3。
- 清除进度移除 v1、v2、v3、v4 所有 key，并恢复空状态。
- 自动化测试覆盖成绩选择、错题聚合、复习幂等、迁移、损坏保护和页面交互。
- 类型检查、lint、生产构建和全站测试通过。
- 浏览器验收覆盖：提交→结果、刷新结果、进入错题→理论、标记复习→刷新、再次考试、窄窗口和空状态。
- 页面明确说明记录保存在当前浏览器。

## 10. 与 R7 的边界

R6 完成后，用户应能完成“学习→考试→结果→错题复习→重考”的闭环。R7 只处理产品级集成与质量验收：入口统一、窄窗口细节、全流程浏览器回归、现有编辑器回归和最终交付检查，不再增加新的成绩或错题业务规则。
