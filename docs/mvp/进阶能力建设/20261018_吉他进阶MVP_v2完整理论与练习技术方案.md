## 3. 课程清单与内容契约

### 3.1 四个模块与八节理论

四个模块 ID 保留不变，全部设置 `availability: "available"`。下表顺序也是默认学习顺序，`Lesson.order` 在模块内为 1、2。

| 模块 ID | 理论 ID | 标题 | 关联练习 |
| --- | --- | --- | --- |
| `rhythm-and-beat` | `rhythm-eighth-sixteenth`（保留） | 八分音符与十六分音符 | `rhythm-identify-eighth-notes` |
| `rhythm-and-beat` | `rhythm-syncopation-triplets` | 切分与三连音 | `rhythm-identify-beat-structure` |
| `chords-and-progressions` | `chords-triad-construction` | 三和弦构成 | `chords-select-triad-tones` |
| `chords-and-progressions` | `chords-common-progressions` | 常见 I-IV-V 进行 | `chords-order-progression` |
| `scales-and-fretboard` | `scales-a-minor-pentatonic` | A 小调五声音阶 | `scales-find-root-notes` |
| `scales-and-fretboard` | `scales-root-note-locations` | 根音定位 | `scales-find-root-notes` |
| `playing-techniques` | `techniques-hammer-pull-slide` | 击弦、勾弦与滑音 | `techniques-identify-notation` |
| `playing-techniques` | `techniques-bend-muted-notes` | 推弦与闷音 | `techniques-identify-notation` |

音阶与技巧模块各用一个综合练习覆盖两节理论，因此总练习数保持为 6。每题保留唯一 `lessonId` 作为主归属：指板题归根音定位，技巧题归推弦与闷音；`relatedLessonId` 与主归属一致，新增 `reviewLessonIds` 显式列出全部关联理论，必须包含主归属理论，顺序按课程排列。理论的 `exerciseIds` 允许共享练习，不强制等于练习的主归属；每个双向关联均需校验，不能只在解析文案里写课程标题而没有可用链接。

每节内容必须包含目标、3–5 个知识卡片、至少一个谱例或指板/和弦示意、易错点及明确下一步。知识卡片使用带标题的 `paragraph` 块计数，目标列表、谱例及 `callout` 不计入 3–5 个。v1 第一节补齐内容时保留 ID 和原知识目标，不因文案扩充清除完成状态。

内容中必须写清适用拍号与拍单位，避免把“一拍两次”无条件用于所有拍号；指板示意明确标准调弦、弦序、品位范围和空弦位置；和弦与音阶题写清调性；技巧题解释记号和使用场景。具体题干、答案、解析与图示随内容数据提交一起审查，不把本表作为教学内容验收的替代。

### 3.2 六个练习

每个练习是一道可独立提交的固定题，本期不引入练习套题。

| 练习 ID | 题型 | 任务与素材 | 正确条件 |
| --- | --- | --- | --- |
| `rhythm-identify-eighth-notes`（保留） | `singleChoice` | 保留原目标与选项 ID，给三个选项补充对应节奏谱例 | `twice-per-beat` |
| `rhythm-identify-beat-structure` | `singleChoice` | 根据切分/三连音谱例判断拍点结构 | 一个预设正确选项 |
| `chords-select-triad-tones` | `multipleChoice` | 从给定音名选项中选出指定三和弦构成音 | 选项集合完全一致 |
| `chords-order-progression` | `ordering` | 将给定和弦排列成题干明确指定的进行 | 顺序完全一致 |
| `scales-find-root-notes` | `targetSelection` | 在低音 E 弦和 A 弦有限区域选择全部 A 小调五声音阶音，解析标出其中根音 | 目标 ID 集合完全一致 |
| `techniques-identify-notation` | `singleChoice` | 从带技巧标记的谱例选择与记号及用途匹配的描述 | 一个预设正确选项 |

排序题不得用“排出好听的进行”等无唯一答案的表述。指板题固定为多目标全选，沿用尚未发布的规划 ID，任务扩为音阶位置识别与根音说明，避免只考根音却宣称验证了完整音阶知识。技巧题选项采用记号与用途的组合描述，不引入自由文本评分。每个综合练习只能证明题干实际考查的理解，不等于验证所有技巧的演奏能力。

以下固定口径作为内容数据实施起点；文案可润色，正确集合和课程覆盖不得在实现时随意改变：

| 练习 | 固定题干/素材要求 | 标准答案口径 |
| --- | --- | --- |
| 八分节奏 | 明确 4/4、四分音符为一拍；三个选项分别给每拍 1、2、4 个等长音的谱例 | 保留 `twice-per-beat`；旧三个选项 ID 不变 |
| 拍点结构 | 展示一拍内 3 个均分音的三连音标记；对比普通二等分与四等分描述 | “三连音把这一拍均分成三份”的选项；解析对比切分，不把三连音解释为切分 |
| 三和弦 | 指定 C 大三和弦；音名选项固定为 C、D、E、F、G，对应稳定 ID | C、E、G 的选项 ID 集合 |
| 和弦进行 | 指定 C 大调，明确要求 I → IV → V；给 C、F、G 三个项 | C → F → G 的 ID 顺序；初始排列固定为 G → C → F |
| 指板找音 | 标准调弦；只展示第 6/5 弦、0–5 品，选择全部 A 小调五声音阶音；未提交的可视目标不预先显示音名 | 第 6 弦 0/3/5 品、第 5 弦 0/3/5 品；解析给出 A/C/D/E/G 音名集合，并标出第 6 弦 5 品、第 5 弦 0 品的 A 根音 |
| 技巧识别 | 给出分别标有 H、P、滑音、推弦及闷音的短谱例，单选项为一组记号与用途的完整对应关系 | 唯一完全匹配的一组选项；错误选项分别混淆击/勾方向、滑音/推弦、闷音/休止，解析逐项说明 |

指板题中的弦号固定为第 1 弦最高音弦、第 6 弦最低音弦，空弦用 0 品表示；屏幕上下方向由图例说明，目标 ID 如 `string-6-fret-5`，不能使用数组下标。正确集合由内容 fixture 明确给出，测试用独立的预期集合核对，不用生成答案的同一个函数证明答案正确。

### 3.3 内容完整性校验

扩展 `validateGuitarAdvancedData`，返回可定位到实体 ID 的错误列表：

- 发布目录恰好 4 个模块、8 节理论、6 个练习，模块内理论数量为 2；模块和题型分布与本方案一致。
- 模块、理论、练习、素材 ID 各自唯一；选项/排序项/目标 ID 在题内唯一。
- 模块所列理论和练习存在且主模块一致，每个实体恰好被一个模块收录；共享练习不重复计数。
- 理论关联练习存在且同模块；练习主归属理论和复习理论存在且同模块，`reviewLessonIds` 与理论的练习关联双向一致。
- 答案非空、无重复、属于候选集合；排序答案和初始排列分别恰好是全部排序项的一个排列；模块及模块内排序值不能并列。
- 前后理论引用符合全局学习顺序、首尾为 `null`，不存在循环；素材引用均可解析。
- 所有理论达到上述内容要求，至少两个不同教学谱例经过正式 loader 校验。

校验用于内容测试及开发期检查；路由对不存在的 ID 返回 `notFound()`，素材运行时失败显示局部错误及返回操作，不静默消失或伪装成题目已完成。题干、选项或指板中影响判断的必需素材加载失败时禁用提交并提供重试，不能让用户对缺失谱例作答；非作答所需的理论附加素材失败时允许阅读，但保留错误提示。

## 4. 路由、导航与完成规则

### 4.1 页面范围

| 路由 | 行为 |
| --- | --- |
| `/guitar-advanced` | 四模块、总体进度、继续学习；模块卡片进入详情 |
| `/guitar-advanced/modules/[moduleId]`（新增） | 理论/练习清单、各项完成状态、模块继续学习 |
| `/guitar-advanced/theory/[lessonId]` | 动态模块标题、正文、素材、完成、关联练习与前后节 |
| `/guitar-advanced/practice/[exerciseId]` | 通用题目外壳、题型作答、提交、解析、重做及下一步 |

四模块不做前置锁定，用户可自由进入；顺序只影响推荐路径。侧栏保留学习路径入口，理论/练习入口改为按当前目标定位，全部完成时回到模块清单。综合考试与学习进度继续显示“即将开放”。模块详情可列出未来考试的待完成条件，但不提供无目标路由的开始按钮。

### 4.2 唯一学习序列

在 `catalog.ts` 集中生成学习序列：按模块 `order`、模块内理论 `order` 排序；每节之后放其主归属练习，共享练习放在主归属理论之后且只出现一次。由此得到 14 个节点。模块详情、下一题和继续学习均读取同一序列，不分别在页面里拼接顺序。

`getContinueTarget`：优先选择有效且未完成的 `lastVisited`；否则取学习序列第一个未完成节点；全部完成返回 `null`。必须同时匹配访问记录的 `kind` 与 `id`，忽略已删除或不开放内容。返回目标同时提供标题、所属模块和路径；下一步是练习时显示“继续练习”，不得显示“打开理论”。

理论的上一节/下一节只在八节理论序列中导航，可跨模块；练习完成后的“下一步”取当前节点之后第一个未完成节点。若后续均完成但前面还有遗漏，回到全局继续学习目标；全部完成则返回总览。模块继续学习只查询模块内部，模块已完成时提供复习清单入口。

这里的复习清单就是模块详情页，不新增复习路由。主序列中共享练习放在第二节之后；从第一节直接进入共享练习仍然允许，相关理论入口须同时列出两节。手动重做已完成练习不撤销完成状态，因此离开后总览的继续学习不会强制回到重做题；用户可从模块清单重新进入。

### 4.3 完成语义

- 理论：保留 v1 的显式点击“完成本节”规则，幂等记录，不自动以访问、停留或滚动判定完成。完成入口放在正文末尾，侧栏可保留同一操作。本期不新增滚动到末尾的状态门槛；这是对总计划中“浏览到末尾后完成”的实施细化，避免旧记录失效和短页面、键盘操作出现歧义。
- 练习：提交一个结构合法、非空答案后即记录完成，答错可以继续；正确性独立展示。未作答和结构非法提交不计完成。
- 重做：移除该题最近一次提交结果、回到初始作答态；保留完成 ID 和错题历史。
- 模块：该模块全部理论与练习完成。总体以 8 + 6 = 14 个唯一节点计数，不把共用练习重复计算。
- 四模块全部完成时显示“理论与练习已完成，综合考试即将开放”，不显示“阶段通过”。阶段通过仍属于后续考试规则。

v1 已完成两项的用户升级后保留 2/14，百分比按新总数计算，界面提示“本版本新增学习内容，已完成记录已保留”；不能把旧 100% 强行映射为全部新课程完成。

## 5. 数据模型与评分模块

### 5.1 题型可区分联合

沿用 `model.ts`，用 TypeScript 可区分联合让题干、标准答案与用户输入保持匹配。以下是关键形状，实施时保持 `readonly`、ES6+ 语法，关键规则添加中文注释：

```ts
type ExerciseAnswer =
  | { readonly type: "singleChoice"; readonly optionId: string }
  | { readonly type: "multipleChoice"; readonly optionIds: readonly string[] }
  | { readonly type: "ordering"; readonly orderedIds: readonly string[] }
  | { readonly type: "targetSelection"; readonly targetIds: readonly string[] };

// ExerciseBase 保留现有 id、moduleId、lessonId、title、prompt、
// explanation、relatedLessonId，并增加 reviewLessonIds；
// 可选 stimulusId 引用题干素材。
type Exercise = ExerciseBase & (
  | {
      readonly type: "singleChoice";
      readonly options: readonly ExerciseOption[];
      readonly answer: Extract<ExerciseAnswer, { type: "singleChoice" }>;
    }
  | {
      readonly type: "multipleChoice";
      readonly options: readonly ExerciseOption[];
      readonly answer: Extract<ExerciseAnswer, { type: "multipleChoice" }>;
    }
  | {
      readonly type: "ordering";
      readonly items: readonly ExerciseOption[];
      readonly initialOrderIds: readonly string[];
      readonly answer: Extract<ExerciseAnswer, { type: "ordering" }>;
    }
  | {
      readonly type: "targetSelection";
      readonly diagramId: string;
      readonly targetIds: readonly string[];
      readonly answer: Extract<ExerciseAnswer, { type: "targetSelection" }>;
    }
);
```

`ExerciseOption` 保留 `id`、`label`，可增加 `stimulusId` 显示选项谱例。单选题现有选项 ID 不变，只给标准答案增加 `type`。排序题的 `initialOrderIds` 是固定排列、与正确答案不同，不随机；初始排列也可提交，提交表示用户明确确认该排列。

UI 本地保存 `ExerciseAnswer | null` 草稿，不把未提交选项写入完成记录；多选与目标选择空集合视为未作答。刷新未提交练习恢复初始状态，并在页面说明“提交后保存结果”；已提交结果和完成状态刷新后恢复。考试草稿持久化属于后续范围。

### 5.2 统一评分 Interface

`gradeExercise(exercise, answer, submittedAt)` 是评分 Module 的统一 Interface，同时隐藏题型匹配、候选 ID 校验、集合比较和结果构造的 Implementation。

```ts
type GradeResult =
  | { readonly ok: true; readonly result: ExerciseResultV2 }
  | {
      readonly ok: false;
      readonly reason: "unanswered" | "typeMismatch" | "invalidAnswer";
    };

interface ExerciseResultV2 {
  readonly exerciseId: string;
  readonly answer: ExerciseAnswer;
  readonly isCorrect: boolean;
  readonly submittedAt: string;
}

// 时间由调用方注入；非法输入以结果返回，不抛业务异常。
declare function gradeExercise(
  exercise: Exercise,
  answer: ExerciseAnswer | null,
  submittedAt: string,
): GradeResult;
```

- 单选按选项 ID 比较；多选和目标选择按集合完全相等比较，顺序无关；排序按数组逐项比较。
- 输入中存在未知 ID、重复 ID、缺少排序项或题型不匹配时返回非法答案，不作为普通答错保存。UI 用明确提示要求重新选择。
- 合法但错误的答案正常生成结果，不做部分得分。练习只显示对错，本期不添加分值；考试可在后续调用同一评分模块计算分值。
- `formatExerciseAnswer(exercise, answer)` 统一生成用户答案与正确答案的展示文本；UI 不自行比较字符串判断对错。
- store 在提交前校验题目存在、尚未提交；已有结果时拒绝重复提交，先重做才可作答。不能只依赖按钮禁用防止覆盖结果。
- `gradeSingleChoice` 的既有调用迁移到统一入口后移除，无外部调用时不保留空转兼容层。

### 5.3 只读素材

扩展 `score-examples.data.ts`：保留 `rhythm-basic-score`，增加至少一个内容不同的节奏/技巧谱例。按引用区分已有示例片段与项目内教学文档，使用可区分的 `ScoreExampleRef`；教学文档 JSON 集中存于数据目录，通过 `loadDocument` 正式校验后渲染。

不得让多个 ID 都落到同一个八分节奏小节。抽取示例片段时使用稳定 measure ID，校验所选小节及技巧关联的音符引用；关联跨越截取范围时应保留所需片段或改用完整的短教学文档，不生成悬空技巧引用。

新增 `diagrams.data.ts` 维护指板示意：标准调弦、品位范围、弦号、音名及可选目标的稳定 ID。和弦理论用带和弦标注的只读谱例，不在本期额外建设和弦图交互。`TheoryBlock` 增加 `diagram` 形态，引用 `diagramId` 和说明。指板渲染使用代码内 SVG 与等价文字选项；答案通过目标 ID 判定，不读取 SVG 坐标或像素，也不依赖编辑器选区。

页面入口解析素材并作为 props 传入 `TheoryLessonView`、`PracticeQuestion`；移除理论组件直接导入 `.data.ts` 的现状。复用只读谱面，不创建编辑会话、不改曲谱 schema。

为避免实施时重复发明字段，补充最小形状；本节为接口约定，不要求把类型示例作为独立程序直接运行：

素材字幕以引用本身为默认值，理论块或题目素材上的 caption 作为当前上下文覆盖值传入渲染器，不再忽略 `TheoryBlock.caption`。必需素材的加载状态由输入容器汇总，任一失败即阻止本次提交；重试仅重新解析/渲染，不清空用户已选答案或学习记录。

未来只修改错别字、解析文案或等价排版时可保留内容 ID；改变题意、正确答案或学习目标时使用新 ID，并另写兼容策略。`contentVersion` 用于发布提示，不能仅凭它复用不再等价的旧作答。后续 v1 回滚仅能读取保留的 v1 快照，不能读取 v2 新进度；本期迁移为单向，不承诺降级同步。

## 6. 状态与存储迁移

### 6.1 v2 进度

```ts
interface GuitarProgressV2 {
  readonly schemaVersion: 2;
  readonly completedLessonIds: readonly string[];
  readonly completedExerciseIds: readonly string[];
  readonly exerciseResults: Readonly<Record<string, ExerciseResultV2>>;
  readonly wrongExerciseIds: readonly string[];
  readonly reviewedExerciseIds: readonly string[];
  readonly lastVisited: LastVisitedContent | null;
  readonly updatedAt: string | null;
}
```

`wrongExerciseIds` 保存曾答错的练习，`reviewedExerciseIds` 只能是其子集。答错时加入错题并移除已复习标记；曾错题再次答对时加入已复习，历史错题不删除。重做不改这两个集合。本期不存每次作答历史、考试记录或“掌握程度”推断。

`settings.data.ts` 将内容版本与进度版本分开：`contentVersion: "v2"`、`progressSchemaVersion: 2`、新 key `lxm-guitar-advanced-progress:v2`，另配置只用于迁移的旧 key。v1 的“不做迁移、仅重置”是当时范围；本方案明确新增单向迁移，不能用版本变化要求用户清空有效记录。

### 6.2 存储 Adapter 与恢复顺序

现有 `ProgressStorage` 绑定单 key，不能同时读取新旧版本。升级为最小 Interface：`read(key)`、`write(key, value)`、`remove(key)`；浏览器 Adapter 与测试内存 Adapter 实现同一约定。key 只在设置中定义，不散落到页面。

所有写动作继续先调用幂等 `hydrateOnce()`，迁移隐藏在恢复流程内部；页面不负责控制迁移顺序。

1. **优先读取 v2**：存在且校验通过则使用，不再合并旧数据；已存在但损坏或版本未知时提示异常并禁止自动写入，不回退 v1 掩盖较新记录。
2. **v2 不存在时读取 v1**：v1 校验通过后，由纯函数 `migrateProgressV1ToV2` 转换；两个版本均不存在才使用全新默认状态。
3. **映射规则**：保留已知完成 ID、时间和有效最近访问；将 `selectedOptionId` 包装为单选 `answer`。旧题 ID、选项 ID 及答案语义保持不变。旧结果为空答案或不合法时不生成提交结果，独立保留已完成 ID；不猜测原答案。旧错误结果加入错题，旧正确结果不推断过去曾答错。
4. **目录校验与形状校验分开**：去重完成 ID；未知目录 ID 不参与进度且在规范化时移除，给出部分记录不再适用的提示；结果 key 必须等于 `exerciseId`，答案必须与当前题型及候选匹配。形状正确但结果 key 错配、题目已删除或答案含失效 ID 时，移除该条结果并保留独立有效完成 ID，发出规范化通知；合法结果由评分模块重新确认对错。不因一个目录引用失效使全部有效完成记录丢失。未知 schema 或字段类型损坏则保护原始 key，不自动覆盖。
5. **迁移保存**：迁移成功先写 v2，保留 v1 作为恢复来源，页面显示升级提示。v2 写入失败保留迁移后的内存状态及 v1 原文，显示“当前操作暂未保存”；后续操作可重试写 v2。初始化重复调用不得重复读取后覆盖当前内存操作。
6. **读取异常**：读 v2 或 v1 抛错、JSON 损坏、未知 schema 时，显示明确错误；允许内存中继续学习，但保护原始存储，自动写入保持关闭。
7. **显式清空**：确认文案说明会清除当前浏览器内新旧版本记录。先删除 v1，后删除 v2；旧 key 删除失败时停止，防止新 key 已删、旧进度下次又被迁移回来。任何删除失败都保留当前内存进度并提示可重试；两者都删除成功才清空内存及解除写保护。删除不是事务，不宣称失败时两个 key 完全未变。

未知 key 不处理，曲谱存储不受影响。本期不新增跨标签实时同步、数据导出与自动备份系统；同一浏览器多标签并发更新仍沿用最后写入行为。

### 6.3 Store 动作

保留 `markLessonComplete`、`submitExercise`、`resetExerciseAttempt`、`setLastVisited`、`clearProgress`、`hydrate`。仅将提交参数改为 `ExerciseAnswer | null`，不为每个题型新增 store 方法。

store 负责查题、调用评分、写入完成与错题、保存；progress 纯函数负责数据更新，评分模块负责正确性。非法课程/题目 ID、重复提交等业务错误与存储错误分别呈现，避免“题目不存在”覆盖存储保护提示。hydrate 完成前显示读取状态，不能先向老用户显示空进度或把下一步导航固定到第一课。

完成、提交、重做和清空动作返回明确的 `ActionResult`：成功包含 `persisted: boolean`，拒绝包含 `reason`（如 `notFound`、`alreadySubmitted` 或评分返回的原因）。合法动作但保存失败仍为内存操作成功，`persisted: false` 并保留存储提示；非法动作不写状态、不改变 `updatedAt`。练习 UI 必须等待提交成功后才进入解析态。`setLastVisited` 只接受当前目录有效的 kind/ID，模块详情访问不覆盖具体学习位置。

规范化不依赖不可信的 `isCorrect` 字段：合法已提交结果确保其 ID 位于完成集合；错题/已复习集合去重、移除未知 ID，已复习严格取错题子集；结果答错必属于待复习集合，曾错题当前结果答对则属于已复习集合。保留“已完成但无结果”这一合法重做状态，不能根据无结果撤销完成。v1 空答案错误结果虽不生成 v2 已提交结果，仍可凭有效旧题 ID 保留错题事实；题目未知则不推断历史。

### 6.4 异常恢复与用户操作

存储提示使用结构化状态区分 `writeFailed`、`readProtected` 和普通升级/规范化通知。升级通知允许关闭，不解除错误保护；成功保存只清除写入错误，业务错误单独反馈。

| 状态 | 允许操作 | 恢复行为 |
| --- | --- | --- |
| 写入失败，原记录已成功读入 | 内存中继续学习、重试保存、确认清空 | 新增 `retryPersist()`，只写当前最新内存快照到 v2；成功后清除未保存提示，不重新 hydrate |
| 读取失败、JSON 损坏或未知版本 | 内存中继续学习、刷新重读、确认清空 | 禁止 `retryPersist()` 越过写保护；刷新会丢失仅在内存中的操作，点击重读前明确提示并确认；清空成功才可保存当前版本新记录 |
| 目录规范化或迁移成功 | 正常学习、关闭通知 | 保留有效记录并允许保存；不以普通通知阻止写入 |
| 删除失败 | 重试清空、继续保留内存 | 保持原写保护状态和当前进度；直到两 key 都删除成功才重置 |

因此在已有 store 动作之外只增加一个用于写入失败的 `retryPersist()`；不增加可能用默认状态覆盖旧记录的“强制恢复”按钮。`persisted: false`、存储异常、全部完成的具体文案在总览和练习页保持一致。

读取失败后的内存进度明确标为“已有记录暂未读取，以下仅为本次临时学习”，不能显示“没有学习记录”；刷新可能丢失未保存操作的说明持续可见。已有 v1 原文保留只是迁移来源留存，不称为持续更新的备份。时间在生产环境继续使用 ISO 字符串；恢复时不因旧字符串无法格式化导致崩溃，无法展示的时间显示缺省文本，不重写为当前时间。

网站、编辑器测试及工程检查执行仓库已有命令：

pnpm exec vitest run apps/website/tests/guitar-advanced
pnpm test

若出现与本期无关的既有失败，记录基线、失败命令和具体原因，不能把未通过写成通过。

### 9.2 浏览器流程

1. 新用户从编辑器入口进入总览，访问四模块详情、八节理论和全部素材。
2. 按课程序列完成八节理论、六个练习；逐项检查进度变化及最终 14/14，不使用直接修改 store 代替完整流程。
3. 六题均验证正确与错误反馈；多选漏选/多选、排序调整、指板全选/漏选、重复提交、重做和关联理论返回。
4. 总览的继续目标落到练习时标题与链接正确；在共享练习前后切换理论不会重复增加进度。
5. 使用 v1 原始存储 fixture，验证升级为 2/14、旧 URL 可用、旧已提交结果与完成标记恢复、v1 原文保留。
6. 分别刷新理论、未提交练习、已提交练习和模块详情；核对已提交数据恢复、未提交草稿重置的提示与行为。
7. 注入损坏存储、读写抛错，核对临时记录提示、内存可继续、原数据保护、重试保存和清空重试。写入恢复后重试不得回滚最新内存操作，读取失败不得通过保存重试覆盖原文。确认同时删除新旧 key 后刷新不会复活旧记录。
8. 键盘完成单选、多选、排序和指板选择，核对图形/文字选项同步且未提前揭示答案；在 1440、1280、1024、680 宽度及低高度窗口检查主操作、长解析、标题/返回路径可见与无横向溢出。
9. 返回编辑器，抽查原曲谱编辑、保存/恢复与学习状态独立；学习页面不会写入曲谱文档。
10. 强制必需谱例解析或布局生成失败，确认提示和禁用提交；恢复素材后重试不丢草稿。检查原单谱例测试不再把所有新增谱例强制断言为八个八分音符，改按每个谱例自身预期验证。

### 9.3 完成判定

以上自动化与浏览器验收有实际记录，且 4 模块、8 理论、6 练习均可用，才可声明 v2 完成。后续新增 `v2 实施验收` 文档，记录实际提交、内容清单、测试结果、浏览器截图和遗留项，再更新目录 README。

考试、成绩、错题页面未实现不影响本阶段验收，但完整 MVP 的 12 条最终标准仍未全部满足，不得把 v2 标为完整 MVP 已交付。

## 10. 关键决策与后续衔接

| 决策 | 原因与后续影响 |
| --- | --- |
| 先补齐 R2–R4，考试留后续 | 先有稳定完整题型与内容，再复用到考试 |
| 六题覆盖八节理论，共享题不重复计数 | 保持总计划数量，模块内两节理论有练习承接 |
| 保留提交即完成、显式标记理论 | 与 v1 兼容；“通过”由后续考试决定 |
| v2 key + 单向迁移，保留 v1 原文 | 结构化答案无法沿用旧字段，升级仍可保留有效记录 |
| Module 对外只有统一评分 Interface | 页面和后续考试复用规则，不承担题型比较和校验细节 |
| 只读谱例与代码 SVG 指板 | 复用现有曲谱能力，同时控制交互输入范围 |
| v2 保存最小错题历史 | 后续复习有可用事实，不提前建设结果或考试页面 |

R5 开始前另写考试技术方案，确定固定 12 题与分值、考试解锁、草稿状态、提交不可变性以及新的进度 schema 兼容策略。本方案不预先承诺考试可以直接写入 v2 存储结构。
