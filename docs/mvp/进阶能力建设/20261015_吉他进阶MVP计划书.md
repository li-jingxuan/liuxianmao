# 吉他进阶 MVP 计划书

## 1. 文档目的

本计划用于在现有 `liuxianmao` 曲谱编辑器基础上，新增一个独立的“吉他进阶” MVP 模块。MVP 覆盖理论学习、针对性练习、题目考试和学习进度，目标是先形成一条可完成、可复习、可验收的学习闭环：

> 理论学习 → 练习任务 → 阶段考试 → 结果反馈 → 继续学习

本文先定义产品和技术边界，首个 MVP 通过审查后再进入实现。MVP 的判断标准是用户能否独立完成一条学习路径，而不是内容数量最大化。

## 2. 当前工程基础与约束

当前仓库具有以下基础：

- `apps/website` 使用 Next.js、React 19、TypeScript、Ant Design、Zustand。
- `packages/lxm-editor` 提供曲谱文档模型、六线谱/简谱展示、节奏、和弦和弹奏技巧能力。
- 现有能力主要围绕“创建和编辑曲谱”，没有课程目录、学习状态、题目评测、考试记录或服务端账户。
- 现有曲谱 schema 和编辑器行为已经有大量测试，吉他进阶首期不能因为学习功能引入不必要的 schema 迁移风险。
- 当前仓库没有后端数据层，因此首期采用浏览器本地持久化；产品文案只能承诺“当前浏览器内保存”。

由此确定首期架构边界：学习内容与编辑器解耦，静态课程内容及默认配置集中采用 `.ts` 文件导出 JSON 形状对象，用户进度采用独立的 Zustand store 和 `localStorage` 持久化；现有编辑器只作为练习谱例和结果展示能力复用。

## 3. 产品目标

### 3.1 目标用户

首期面向已经会基本和弦和简单节奏、希望提高实际演奏能力的吉他学习者。用户通常需要解决以下问题：

- 看得懂谱，但不知道下一步练什么。
- 了解零散知识，却不能把节奏、和弦、音阶和技巧串成一首可演奏的片段。
- 练习缺少明确完成标准，无法判断是否达到阶段要求。
- 做过题却不知道错题原因，也无法在下一次考试前复习。

### 3.2 产品目标

- 把进阶内容组织成明确的学习路径。
- 每个知识点都对应至少一个可操作练习。
- 通过低成本题型验证理论理解和读谱能力。
- 为用户提供即时成绩、错题复习和阶段完成状态。
- 复用现有曲谱能力，让学习内容与吉他实际谱面关联起来。

### 3.3 首期非目标

以下能力暂不进入 MVP：

- 麦克风录音、自动识别音高、节奏或演奏准确度。
- 云端账户、跨设备同步、服务端成绩排名。
- 教师端、课程 CMS、内容运营后台。
- 个性化推荐算法和自适应难度。
- 社区、评论、打卡分享、付费课程。
- 多乐器课程体系。
- 复杂的实时节拍器、伴奏和播放引擎。

这些能力可以进入后续路线，但会显著增加音频、后端、内容生产和运营成本，不适合作为首个可验证版本的前置条件。

## 4. 信息架构

建议新增独立的学习路由组，不改变首页编辑器的默认入口：

```text
/
├── 曲谱编辑器（现有）
└── /guitar-advanced
    ├── 总览 / 学习路径
    ├── /theory/[lessonId]      理论详情
    ├── /practice/[exerciseId]  练习详情
    ├── /exam/[examId]          考试与结果
    └── /progress               学习进度与错题
```

首页或现有应用外壳增加“吉他进阶”入口。学习模块拥有自己的顶层布局、侧边导航和返回编辑器入口，避免把课程页面嵌入复杂的编辑器侧栏。

## 5. MVP 功能分层

MVP 按照学习闭环拆成五个功能层次；每层只保留支撑首期验证所需的能力。

### 5.1 学习路径层

- 按阶段展示课程、练习和考试。
- 支持章节解锁、完成状态、推荐下一步。
- 展示预计学习时长、难度、需要的前置知识。
- 支持按主题筛选：节奏、和弦、音阶、技巧、读谱、应用。

### 5.2 理论内容层

- 结构化短课：目标、概念、谱例、易错点、课后检查。
- 支持六线谱、简谱、和弦名称和指法图等现有渲染能力。
- 每个知识点可以关联多个练习和考试题目。
- 支持收藏、标记待复习和章节笔记；这些可在有后端后继续扩展。

### 5.3 练习层

- 无器材练习：节奏辨认、和弦构成、指板定位、读谱判断。
- 伴随谱例练习：使用现有谱面展示和分段阅读。
- 可选的手动完成记录：完成、跳过、重新练习。
- 后续加入节拍器、录音、自评和自动识别。

### 5.4 考试层

- 章节小测、阶段考试和综合考试。
- 支持单选、多选、排序、谱面点击、指板定位、节奏选择、简答输入。
- 提交后显示总分、各知识点得分、错题原因和推荐复习内容。
- 支持重考，保留历史最好成绩和最近一次成绩。
- 题目版本固定，避免同一考试因随机顺序无法复盘；可以只随机选项顺序。

### 5.5 反馈与进度层

- 总体进度、章节进度、练习完成数、考试成绩。
- 错题本按照知识点归类。
- 为每个知识点显示“未开始、学习中、已掌握、需要复习”。
- 后续可加入连续学习天数、目标计划和个性化推荐。

## 6. MVP 产品范围

MVP 只验证一件事：用户能否从一个入口完成“学一节理论、做一项练习、参加一次考试、看到可解释结果”的闭环。

### 6.1 MVP 学习内容

首期固定为 4 个模块、8 个理论小节、6 个练习、1 个综合考试。内容数量应保持可人工审查，不做动态生成。

| 模块 | 理论小节 | 配套练习 | 首期验收重点 |
| --- | --- | --- | --- |
| 节奏与拍点 | 八分音符与十六分音符、切分与三连音 | 节奏选择、拍点结构判断 | 能区分常见时值和切分位置 |
| 和弦与进行 | 三和弦构成、常见 I-IV-V 进行 | 和弦构成选择、进行排序 | 能从根音和级数判断基础和弦关系 |
| 音阶与指板 | A 小调五声音阶、根音定位 | 指板找音、音阶位置选择 | 能在有限范围内定位目标音 |
| 弹奏技巧 | 击勾弦、滑音、推弦、闷音 | 谱面技巧识别、技巧与听感描述匹配 | 能读懂常用技巧记号并选择使用场景 |

每个理论小节包含：

1. 学习目标。
2. 3 至 5 个知识卡片。
3. 1 个谱例或指板示意。
4. 1 个易错点。
5. 进入练习的按钮。
6. 完成标记。

### 6.2 MVP 练习

每个练习只保留一种主要交互和一种明确完成标准：

- 节奏选择：从 3 个谱例中选择目标节奏。
- 拍点判断：判断切分音或三连音所在拍点。
- 和弦构成：选择组成指定和弦的音。
- 和弦进行排序：把 I、IV、V 或 ii、V、I 排成正确顺序。
- 指板找音：在有限的 A 弦和低音 E 弦区域选择目标音。
- 技巧识别：从谱面标记中选择对应技巧并说明用途。

MVP 练习允许用户“提交答案后立即查看解析”。不要求验证真实演奏，也不要求实时音频输入。

### 6.3 MVP 综合考试

综合考试固定 12 题，覆盖 4 个模块，每个模块 3 题：

- 6 道单选题。
- 2 道多选题。
- 2 道排序题。
- 2 道谱面或指板识别题。

考试规则：

- 满分 100 分，及格线 80 分。
- 所有题目完成后统一提交，也允许暂存当前答案。
- 提交后显示总分、模块得分、正确答案、解析和错题对应理论小节。
- 允许重新考试，保留最好成绩、最近一次成绩和考试次数。
- 题目与成绩保存在本地，刷新页面后仍可继续或查看结果。

### 6.4 MVP 首页与进度

MVP 首页展示：

- 当前学习阶段和完成百分比。
- 四个模块卡片及锁定/进行中/已完成状态。
- 最近一次考试成绩。
- “继续学习”和“复习错题”两个主操作。

MVP 进度页展示：

- 理论完成数 / 总数。
- 练习完成数 / 总数。
- 考试成绩和通过状态。
- 按模块归类的错题列表。

## 7. MVP 技术方案

### 7.1 模块结构

根据第一版本方案修订，沿用现有职责分层，不新增 `features/`：

```text
apps/website/
├── app/guitar-advanced/          # 路由与页面；考试/进度路由在后续路线实现
├── components/GuitarAdvanced/   # React UI 与局部样式
├── data/guitar-advanced/        # 集中的 .ts JSON 数据
│   ├── index.ts
│   ├── guitar-advanced.data.ts  # 模块、理论、练习；后续题库/考试在同目录扩展
│   ├── score-examples.data.ts
│   ├── initial-progress.data.ts
│   └── settings.data.ts
├── lib/guitar-advanced/         # 模型、内容查询、评分、进度、存储适配
├── stores/guitar-advanced-store.ts
└── tests/guitar-advanced/
```

`servers/guitar-advanced/` 留到服务端建设时新增，本期不创建空目录或占位接口。源码数据只保存内容和默认配置，实际用户进度仍由 store 和本地存储管理；未来内容来源与用户进度存储分别迁移。

### 7.2 内容与状态分离

内容数据统一在 `data/guitar-advanced/` 的 `.ts` 文件中导出只读 JSON 形状对象；页面和组件不重复维护课程、题目、答案和解析。实际用户状态独立保存，不写回源码：

```ts
interface Lesson {
  id: string;
  moduleId: string;
  title: string;
  summary: string;
  objectives: string[];
  blocks: TheoryBlock[];
  exerciseIds: string[];
}

interface Exercise {
  id: string;
  lessonId: string;
  type: ExerciseType;
  title: string;
  prompt: string;
  options: ExerciseOption[];
  answer: ExerciseAnswer;
  explanation: string;
}

interface GuitarProgress {
  completedLessonIds: string[];
  completedExerciseIds: string[];
  examAttempts: ExamAttempt[];
  wrongQuestionIds: string[];
  updatedAt: string;
}
```

题目答案和评分逻辑必须集中在纯函数中，页面组件只负责展示和收集输入，避免在 React 组件中散落评分规则。

### 7.3 状态持久化

- 使用独立的 Zustand store 保存学习状态。
- 使用版本化 key，例如 `lxm-guitar-advanced-progress:v1`。
- 加载时校验数据形状；损坏或旧版本数据回退为空状态，不覆盖现有曲谱。
- 所有时间使用 ISO 字符串。
- MVP 只做当前浏览器保存，页面上明确展示这一边界。

### 7.4 与曲谱编辑器的集成

- 练习谱例优先复用 `packages/lxm-editor` 已有文档和只读展示组件。
- MVP 不新增或修改现有曲谱 schema。
- 专用教学谱例集中维护在 `apps/website/data/guitar-advanced/score-examples.data.ts`，通过现有 loader 校验和只读渲染链路显示，不在编辑器 package 中新增学习业务数据。
- 练习答案只记录用户选择和完成状态，不把学习记录写入曲谱文档。
- 编辑器与学习模块之间通过明确的导航参数连接，例如从理论页打开对应谱例；不共享隐式全局状态。

### 7.5 评分与进度规则

建议规则如下：

- 单选题：答对得该题全部分数，答错 0 分。
- 多选题：只有选项集合完全一致才得分，避免部分得分带来的解释复杂度。
- 排序题：顺序完全正确得分，否则 0 分；解析展示正确序列。
- 谱面/指板题：按选中的目标 ID 集合精确判定。
- 练习完成：提交一次答案后记录完成；是否正确影响“需要复习”状态，但不阻断后续学习。
- 理论完成：用户点击“完成本节”且浏览到页面末尾后记录完成。
- 模块完成：模块下所有理论和练习完成。
- 阶段完成：综合考试达到 80 分且四个模块均已完成。

## 8. UI 与交互要求

- 沿用当前项目的 Ant Design 组件、颜色和字体规范，不在学习模块引入第二套基础组件。
- 页面视觉重点从“编辑器工具栏”切换为“学习路径、卡片、进度和反馈”。
- 桌面端优先，至少适配 1280 宽；移动端保留单列可读和可操作布局。
- 理论页固定提供上一节、下一节和进入练习的主操作。
- 练习页回答后保留用户选项，并清楚区分正确、错误、解析和下一步。
- 考试页显示当前题号、完成数量和退出后继续入口。
- 结果页不能只给一个分数，必须显示模块分项和可跳转的错题解析。
- 所有按钮、状态和颜色同时提供文字语义，避免仅靠颜色表达对错。
- 错误、空状态和本地存储异常都需要可恢复提示。

## 9. 实施分期

### 阶段 0：方案审查

- 审查本计划的学习范围、题型、内容数量和“不做事项”。
- 确认四个 MVP 模块和 12 道考试题的内容口径。
- 审查路由、数据模型、本地持久化边界。
- 通过后再创建实现分支和具体技术方案拆分。

### 阶段 1：学习壳与内容模型

- 增加路由组、页面布局和入口。
- 建立课程、练习、题目和进度类型。
- 在 `data/guitar-advanced/` 集中编写 `.ts` JSON 内容和默认数据；组件归入 `components/GuitarAdvanced/`。
- 完成 Zustand store、本地存储和基础选择器。

交付结果：可以浏览四个模块和理论小节，刷新后能保留理论完成状态。

### 阶段 2：理论与谱例

- 实现理论卡片、谱例展示、前后节导航。
- 复用现有曲谱只读展示。
- 增加理论完成和模块完成计算。

交付结果：用户能按顺序学习 8 个理论小节并进入对应练习。

### 阶段 3：练习引擎

- 实现通用题目容器和 6 个练习实例。
- 实现提交、解析、完成记录和重做。
- 覆盖单选、多选、排序、指板/谱面选择四类交互。

交付结果：用户能完成所有练习，并看到确定性的反馈。

### 阶段 4：综合考试与进度

- 实现考试流程、暂存、提交、评分、重考。
- 实现模块得分、总分、及格线和错题归类。
- 实现进度页和首页继续学习状态。

交付结果：用户能完成一次考试并复习错题，刷新后成绩仍然存在。

### 阶段 5：质量验收

- 单元测试覆盖评分、解锁、进度和本地存储恢复。
- 页面测试覆盖理论到练习、练习到考试、提交到结果的完整路径。
- 浏览器回归覆盖刷新、返回、退出考试后继续、重考和窄窗口。
- 补齐中文注释、空状态、错误恢复和键盘操作。

## 10. MVP 验收标准

满足以下条件才视为 MVP 完成：

1. 用户可以从现有产品入口进入“吉他进阶”。
2. 用户可以浏览 4 个模块和 8 个理论小节。
3. 用户可以查看至少 2 个与现有曲谱能力关联的谱例。
4. 用户可以完成 6 个练习，提交后能看到答案和解析。
5. 用户可以完成 12 道综合考试题，得到总分和模块分数。
6. 80 分及以上显示通过，低于 80 分显示未通过并推荐复习模块。
7. 错题可以从结果页进入对应理论或重新练习。
8. 刷新浏览器后理论完成、练习完成和考试记录仍然存在。
9. 用户可以重考，且最好成绩和最近一次成绩均可查看。
10. 现有编辑器的构建、类型检查、lint 和既有测试不受影响。
11. 评分、进度和本地存储逻辑有自动化测试，关键页面有浏览器流程验收。
12. 页面明确说明学习记录保存在当前浏览器中。

## 11. MVP 完成后的扩展边界

以下能力不属于本 MVP 验收范围，后续可单独立项：

- 节拍器、计时练习和练习历史。
- 麦克风输入、音高检测和节奏准确度分析。
- 登录、云端同步和跨设备进度。
- 教师端、课程内容后台和个性化推荐。

## 12. 主要风险与处理方式

| 风险 | 影响 | 处理方式 |
| --- | --- | --- |
| 内容范围过大 | MVP 迟迟无法闭环 | 固定 4 个模块、8 节理论、6 个练习和 1 场考试 |
| 学习模块与编辑器耦合 | 修改曲谱能力时引入回归 | 只读复用展示能力，学习状态独立存储 |
| 只做漂亮页面没有学习闭环 | 无法验证产品价值 | 先完成理论→练习→考试→结果主路径 |
| 本地数据损坏 | 用户进度丢失或页面崩溃 | 加版本号、运行时校验和可恢复空状态 |
| 题目质量不稳定 | 成绩无法代表掌握程度 | 题目采用静态 fixture，先人工审查再扩量 |
| 过早加入音频识别 | 工期和技术风险快速上升 | MVP 采用选择题和谱面交互，把音频列入后续版本 |

## 13. 需要在实现前确认的决策

实现前只需要确认以下产品决策：

- MVP 是否采用上述四个模块：节奏、和弦、音阶、弹奏技巧。
- 综合考试是否采用 12 题、满分 100、80 分及格。
