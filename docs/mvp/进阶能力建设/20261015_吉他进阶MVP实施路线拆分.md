# 吉他进阶 MVP 实施路线拆分

## 1. 文档目的

本文件将 [吉他进阶 MVP 计划书](./20261015_吉他进阶MVP计划书.md) 拆分成可独立审查、实现和验收的路线切片，供进入代码实现前确认实施顺序和范围。

本轮只做路线拆分，不修改业务代码。实现时遵循现有仓库的 React 19、TypeScript、Ant Design 6.4.4 和 Zustand 技术栈，并参考 [吉他进阶 MVP 设计落地契约](../../design/进阶能力建设/20261015_吉他进阶MVP设计落地契约.md)。

## 2. MVP 最终闭环

MVP 最终需要让用户完成下面这条路径：

```text
吉他进阶入口
  → 学习路径
  → 选择一个模块
  → 阅读理论小节
  → 完成对应练习
  → 完成四个模块
  → 参加 12 题综合考试
  → 查看成绩与模块得分
  → 进入错题复习或重新考试
```

每个路线切片都必须能说明自己为闭环贡献了哪一段能力，且不能提前引入音频识别、云端账户或内容后台等后续能力。

## 3. 总体路线

MVP 拆为 8 条路线，按依赖关系顺序推进：

| 路线 | 名称 | 目标 | 主要交付 |
| --- | --- | --- | --- |
| R0 | 范围与内容契约 | 冻结首期内容、状态和评分规则 | 实现前审查结论、内容清单、ID 约定 |
| R1 | 学习模块基础设施 | 建立独立路由、模型、内容和进度存储 | 学习模块骨架、类型、fixture、store |
| R2 | 学习路径与总览 | 让用户知道学什么、做到哪一步 | 总览页、模块详情页、继续学习 |
| R3 | 理论学习 | 让用户完成一节可读、可标记的理论课 | 理论页、谱例、完成状态 |
| R4 | 练习引擎 | 让用户答题并得到解释 | 通用题目容器、6 个练习、评分函数 |
| R5 | 综合考试 | 让用户完成、暂存和提交一场考试 | 12 题考试、答卷状态、考试评分 |
| R6 | 结果、进度与错题 | 让用户知道结果并能继续复习 | 结果页、进度页、错题复习、重考 |
| R7 | 集成与质量验收 | 把闭环接入现有产品并达到可交付质量 | 入口、响应式、自动化测试、回归验收 |

建议先完成 R0，再按 R1→R2→R3→R4→R5→R6→R7 顺序实施。R3 和 R4 在 R2 完成后可以并行准备内容，但正式联调仍以 R3 的理论跳转为前置。

## 4. 路线 R0：范围与内容契约

### 4.1 目标

在写组件之前冻结首期内容和核心规则，避免开发过程中反复修改页面结构、状态模型和评分逻辑。

### 4.2 范围

确认以下内容不再扩大：

- 4 个模块：节奏与拍点、和弦与进行、音阶与指板、弹奏技巧。
- 8 个理论小节，每个模块 2 个理论小节。
- 6 个练习，覆盖单选、多选、排序、谱面/指板识别。
- 1 场综合考试，共 12 题，每个模块 3 题。
- 满分 100 分，80 分及格。
- 练习答错后可以继续，错误进入错题记录。
- 学习记录只保存在当前浏览器。
- 不做录音、自动演奏识别、云端同步和教师后台。

### 4.3 内容交付

建立内容清单，至少包含：

- 模块 ID、标题、简介、排序和状态。
- 理论小节 ID、目标、正文块、谱例、易错点和关联练习。
- 练习 ID、题型、题干、选项、标准答案、解析和关联知识点。
- 考试题目 ID、所属模块、分值和题目顺序。
- 结果页显示的复习目标和跳转关系。

### 4.4 验收条件

- 产品范围与现有 MVP 计划书一致。
- 设计稿中出现的页面均能映射到一个实现路线。
- 所有内容和题目拥有稳定 ID，后续修改文案不改变 ID。
- 评分、通过、错题和完成状态的规则已经书面确定。

### 4.5 不做项

- 不在此阶段实现页面。
- 不创建服务端接口。
- 不为了内容扩充新增 CMS、Markdown 解析器或富文本编辑器。

## 5. 路线 R1：学习模块基础设施

### 5.1 目标

在不影响现有曲谱编辑器的前提下，建立独立的学习模块代码边界和最小可用数据层。

### 5.2 建议目录

根据第一版本方案修订，沿用现有职责分层，不新增 `features/`：

```text
apps/website/
├── app/guitar-advanced/          # 路由与页面；考试/进度路由在后续路线实现
├── components/GuitarAdvanced/   # React UI 与局部样式
├── data/guitar-advanced/        # 集中的 .ts JSON 数据
│   ├── index.ts
│   ├── guitar-advanced.data.ts  # 模块、理论、练习；后续题库/考试在同目录扩展
│   ├── score-examples.data.ts
│   ├── initial-progress.data.ts
│   └── settings.data.ts
├── lib/guitar-advanced/         # 模型、内容查询、评分、进度、存储适配
├── stores/guitar-advanced-store.ts
└── tests/guitar-advanced/
```

`servers/guitar-advanced/` 留到服务端建设时新增，本期不创建空目录或占位接口。源码数据只保存内容和默认配置，实际用户进度仍由 store 和本地存储管理；未来内容来源与用户进度存储分别迁移。

### 5.3 核心模型

首期建议使用以下模型族：

```ts
interface GuitarModule {
  id: string;
  title: string;
  summary: string;
  order: number;
  lessonIds: string[];
  exerciseIds: string[];
}

interface Lesson {
  id: string;
  moduleId: string;
  title: string;
  durationMinutes: number;
  objectives: string[];
  blocks: TheoryBlock[];
  exerciseIds: string[];
}

interface Exercise {
  id: string;
  lessonId: string;
  moduleId: string;
  type: ExerciseType;
  title: string;
  prompt: string;
  options: ExerciseOption[];
  answer: ExerciseAnswer;
  explanation: string;
}

interface ExamAttempt {
  id: string;
  examId: string;
  answers: Record<string, UserAnswer>;
  status: "draft" | "submitted";
  score: number | null;
  submittedAt: string | null;
}

interface GuitarProgress {
  completedLessonIds: string[];
  completedExerciseIds: string[];
  exerciseResults: Record<string, ExerciseResult>;
  examAttempts: ExamAttempt[];
  wrongQuestionIds: string[];
  lastVisitedId: string | null;
  updatedAt: string;
}
```

### 5.4 存储规则

- 使用独立的 Zustand store，不复用 `editorStore`。
- 使用版本化 key：`lxm-guitar-advanced-progress:v1`。
- 读取时进行运行时校验；无效数据回退到空状态并给出可恢复提示。
- 写入失败不能清空当前内存状态，也不能把页面显示成“从未学习”。
- 不把学习进度写入曲谱文档或现有 schema。

### 5.5 验收条件

- `/guitar-advanced` 可以渲染独立布局和导航骨架。
- 内容及默认数据统一位于 `data/guitar-advanced/` 的 `.ts` JSON 文件，页面和测试通过统一入口读取。
- 理论完成、练习完成和考试记录可以保存、读取和清空。
- 刷新后 store 可以恢复有效数据。
- 现有编辑器相关测试不受影响。

### 5.6 不做项

- 不实现完整业务页面。
- 不实现数据库、登录或远程同步。
- 不在 store 中保存曲谱编辑会话。

## 6. 路线 R2：学习路径与总览

### 6.1 目标

先让用户看到整个学习范围，并能从总览进入模块、理论和最近未完成内容。

### 6.2 页面范围

对应设计稿：

- [学习路径](../../design/进阶能力建设/01_学习总览/01_吉他进阶_学习路径.png)
- [模块详情](../../design/进阶能力建设/01_学习总览/02_吉他进阶_模块详情.png)

需要实现：

- 总体完成百分比。
- 四个模块卡片。
- 模块状态：未开始、学习中、已完成。
- 当前模块进度。
- 最近学习内容。
- 继续学习按钮。
- 模块详情中的理论、练习和考试前置条件。

### 6.3 状态规则

- 理论完成数、练习完成数和考试成绩分别计算，不用一个状态覆盖全部信息。
- “继续学习”定位到最近一个未完成的理论或练习。
- 未完成前置条件时，综合考试显示未解锁原因和待完成项。
- 没有历史记录时展示首次学习引导，而不是空白页面。

### 6.4 验收条件

- 从学习路径可以进入四个模块。
- 完成一节理论后，总览中的模块进度变化。
- 刷新页面后总览状态与刷新前一致。
- 用户可以从模块详情返回总览，返回后不丢失状态。
- 页面在 1440 宽度和 1024/1280 窄窗口下没有主操作遮挡。

### 6.5 不做项

- 不加入推荐算法。
- 不加入按主题搜索和动态筛选。
- 不加入学习日历、连续打卡和排行榜。

## 7. 路线 R3：理论学习

### 7.1 目标

提供一节完整、可读、可完成的理论课，并将理论内容和谱例、练习连接起来。

### 7.2 页面范围

对应设计稿：

- [理论学习：节奏与拍点](../../design/进阶能力建设/02_理论学习/01_理论学习_节奏与拍点.png)

首期先实现一个统一理论页组件，再填入 8 个理论小节内容。理论页至少包含：

- 面包屑或返回模块入口。
- 标题、模块、预计时长。
- 本节目标。
- 知识卡片或正文块。
- 至少一个谱例。
- 易错点提示。
- 完成本节按钮。
- 进入练习按钮。
- 上一节/下一节入口。

### 7.3 与现有编辑器的集成

- 理论谱例使用现有 `packages/lxm-editor` 文档 fixture 和只读展示能力。
- 谱例不允许在理论页直接编辑。
- 学习模块只保存谱例引用 ID，不复制或改写曲谱文档。
- 如果现有只读渲染组件需要抽取，先做无行为变化的组件复用，不修改曲谱 schema。

### 7.4 验收条件

- 8 个理论小节可以按模块和顺序访问。
- 每节理论均有目标、正文、易错点和下一步动作。
- 完成理论后能进入关联练习。
- 进入下一节、返回模块和刷新恢复均正常。
- 至少 2 个理论谱例真实复用现有谱面能力。

### 7.5 不做项

- 不做理论笔记、收藏和评论。
- 不做在线 Markdown/CMS 编辑。
- 不做谱例编辑、播放或录音。

## 8. 路线 R4：练习引擎

### 8.1 目标

建立一个可复用的答题容器，使不同题型都能完成“展示题目 → 作答 → 提交 → 解析 → 完成/重做”。

### 8.2 题型顺序

建议按以下顺序实现，先低交互复杂度，再实现需要结构化答案的题型：

1. 单选：节奏选择、技巧识别。
2. 多选：和弦构成、音阶音组成。
3. 排序：和弦进行排序。
4. 谱面/指板识别：从预设目标区域中选择答案。

### 8.3 页面范围

对应设计稿：

- [练习作答与解析](../../design/进阶能力建设/03_练习作答/01_练习作答_节奏选择与解析.png)

通用题目容器需要展示：

- 模块和练习标题。
- 当前题目进度。
- 题干和题目内容。
- 作答区域。
- 提交按钮。
- 正确/错误状态。
- 正确答案和解析。
- 关联理论入口。
- 重新练习和下一题入口。

### 8.4 评分规则

评分逻辑放在纯函数中：

- 单选：选项完全匹配得分。
- 多选：选项集合完全一致得分，首期不做部分得分。
- 排序：顺序完全一致得分。
- 谱面/指板：目标 ID 集合完全一致得分。
- 提交后锁定当前答案，但允许重新开始练习。

### 8.5 验收条件

- 6 个练习均能进入、作答、提交和查看解析。
- 答错后能看到错误原因和关联理论。
- 练习完成状态写入本地进度。
- 重新练习不会删除历史完成记录。
- 评分纯函数有边界测试，页面不直接写答案判断分支。

### 8.6 不做项

- 不做计时、节拍器和演奏输入。
- 不做题目随机抽题。
- 不做自适应难度和题目推荐。
- 不做自由文本自动评分。

## 9. 路线 R5：综合考试

### 9.1 目标

将四个模块的知识点组织成一场完整考试，支持答题、暂存、恢复、提交和统一评分。

### 9.2 页面范围

对应设计稿：

- [综合考试进行中](../../design/进阶能力建设/04_考试与结果/01_综合考试_进行中.png)

需要实现：

- 综合考试入口和前置条件判断。
- 12 道固定题目。
- 当前题目、已答数量和剩余数量。
- 题号导航。
- 上一题、下一题。
- 暂存并退出。
- 继续未完成考试。
- 提交前未答题提示。
- 统一提交。

### 9.3 考试状态机

```text
未开始
  └─开始考试→ 进行中
                ├─暂存并退出→ 草稿
                ├─继续考试→ 进行中
                └─提交→ 已提交
                              ├─通过
                              └─未通过
```

同一场考试提交后不可修改；再次考试创建新的 `ExamAttempt`，保留历史最好成绩和最近一次成绩。

### 9.4 验收条件

- 四个模块完成后才能进入考试，未完成时能看到明确前置条件。
- 12 道题可以前后切换，已答和未答状态清晰。
- 暂存退出后重新进入，可以恢复上次答案和当前题号。
- 提交前会提示未答题，提交后生成不可变考试记录。
- 评分结果可以按模块汇总。

### 9.5 不做项

- 不做倒计时。
- 不做随机题库和题目版本管理。
- 不做防作弊、监考或服务端提交。
- 不做考试过程中的音频题。

## 10. 路线 R6：结果、进度与错题复习

### 10.1 目标

让用户知道考试表现、下一步学习方向，并能从错题回到理论或练习。

### 10.2 页面范围

对应设计稿：

- [综合考试结果与错题](../../design/进阶能力建设/04_考试与结果/02_综合考试_结果与错题.png)
- [学习进度与错题复习](../../design/进阶能力建设/05_进度与窄窗口/01_学习进度_错题复习.png)

结果页需要展示：

- 总分、满分、及格线。
- 通过/未通过状态。
- 本次考试耗时或提交时间。
- 四个模块分数。
- 最近一次成绩和最好成绩。
- 错题列表。
- 用户答案、正确答案和解析。
- 查看理论、重新练习和再次考试。

进度页需要展示：

- 理论完成数。
- 练习完成数。
- 考试最好成绩。
- 各模块进度。
- 待复习题目数量和模块归类。

### 10.3 进度计算规则

- 模块完成：该模块理论和练习全部完成。
- 阶段完成：四个模块全部完成，且至少一次考试达到 80 分。
- 错题记录：考试提交或练习提交判错时写入题目 ID。
- 复习后不自动删除错题；再次答对后标记为已复习，保留历史记录。
- 最好成绩取所有已提交考试中的最高分；最近一次成绩取提交时间最新的一次。

### 10.4 验收条件

- 考试提交后立即进入结果页。
- 结果页的总分、模块分数和通过状态与评分函数一致。
- 每条错题都能进入理论或练习。
- 进度页与总览页的数据一致。
- 刷新后成绩、错题和最好成绩仍然存在。
- 未考试、无错题和无学习记录均有明确空状态。

### 10.5 不做项

- 不做数据导出。
- 不做学习报告分享。
- 不做基于成绩的自动课程推荐。

## 11. 路线 R7：集成与质量验收

### 11.1 目标

将吉他进阶 MVP 接入现有产品入口，完成从进入到考试结果的端到端验证，并确保现有编辑器没有回归。

### 11.2 集成范围

- 在现有产品可达位置增加“吉他进阶”入口。
- 学习模块顶部保留返回曲谱工作台入口。
- 统一全局字体、颜色、按钮、提示和图标。
- 对现有页面不引入新的全局样式污染。
- 窄窗口保持侧栏收纳和底部主操作可达。

对应设计稿：

- [窄窗口学习总览](../../design/进阶能力建设/05_进度与窄窗口/02_学习总览_窄窗口.png)

### 11.3 自动化测试

至少覆盖：

- 内容 fixture ID 和关联关系。
- 理论完成和模块完成计算。
- 练习四类评分函数。
- 练习完成、错题记录和重新练习。
- 考试暂存、恢复、提交和重复考试。
- 总分、模块分数、及格线和最好成绩。
- 本地存储的版本、有效数据恢复和损坏数据恢复。

### 11.4 页面流程测试

至少覆盖一条完整路径：

```text
入口
  → 学习路径
  → 节奏模块
  → 理论小节
  → 练习提交
  → 完成四模块 fixture
  → 综合考试
  → 暂存并退出
  → 继续考试
  → 提交
  → 结果页
  → 错题复习
```

还需要覆盖：

- 刷新理论页和考试页。
- 未完成考试退出后继续。
- 考试未答题提交提示。
- 低于 80 分的未通过结果。
- 空状态和本地存储异常。
- 1024/1280 宽度下的主操作可见性。

### 11.5 验收条件

- MVP 计划书中的 12 条最终验收标准全部满足。
- 现有 `pnpm test`、`pnpm type-check`、`pnpm lint` 和生产构建不出现回归。
- 设计稿中的主状态均能在实际页面找到对应实现。
- 关键业务逻辑有中文注释，尤其是状态迁移、评分、进度计算和本地存储恢复。
- 不以“静态页面可以打开”替代业务流程验收。

## 12. 建议的里程碑

### M1：可浏览版本

包含 R0、R1、R2、R3。

用户可以进入吉他进阶，浏览学习路径、模块详情和理论内容，并标记理论完成。此时暂不开放正式考试入口。

**验收重点：** 路由、内容模型、理论页面、谱例展示、本地进度恢复。

### M2：可练习版本

包含 R4，并接通 R3 的理论到练习跳转。

用户可以完成 6 个练习，看到即时解析和错题关联。学习路径中的练习完成状态开始生效。

**验收重点：** 题型容器、评分纯函数、练习完成、错题记录和重做。

### M3：可考试版本

包含 R5。

用户完成四个模块后可以进入综合考试，可以暂存、恢复和提交答卷。

**验收重点：** 考试状态机、12 题固定题目、答卷恢复和提交边界。

### M4：可复习版本

包含 R6。

用户可以看到成绩、模块得分、最好成绩和错题，并重新进入理论或练习。

**验收重点：** 结果计算、进度一致性、错题闭环和重考。

### M5：可交付版本

包含 R7。

完成入口接入、窄窗口、自动化测试、页面流程测试和现有工程回归。

**验收重点：** 完整用户路径、刷新恢复、异常状态和既有功能无回归。

## 13. 路线之间的依赖关系

```text
R0 范围与内容契约
  ↓
R1 基础设施
  ↓
R2 学习路径与总览
  ├─→ R3 理论学习
  │     ↓
  └─→ R4 练习引擎
          ↓
        R5 综合考试
          ↓
        R6 结果/进度/错题
          ↓
        R7 集成与质量验收
```

R3 和 R4 的内容准备可以并行，但 R4 的页面入口、关联理论和进度写入依赖 R3 的模型契约。R5 依赖 R4 的题目和评分模型，R6 依赖 R5 的提交结果结构。

## 14. 每条路线的统一交付格式

实现每条路线时，建议固定提交以下内容：

1. 变更范围：实际修改的目录和文件。
2. 状态/模型变化：新增字段、状态机或持久化 key。
3. 页面路径：可访问的路由和主要入口。
4. 自动化测试：新增测试文件和覆盖的业务规则。
5. 手工验收：按设计稿核对的页面状态。
6. 未完成项：明确留到下一条路线的内容。
7. 回归结果：现有测试、类型检查、lint 和构建结果。

## 15. 进入实现前的审查点

在开始 R1 之前，只需要审查以下决策：

- 路线顺序是否按 R0→R1→R2→R3→R4→R5→R6→R7 执行。
- MVP 是否严格固定为 4 个模块、8 节理论、6 个练习、12 道考试题。
- 是否接受先做浏览器本地进度，不引入后端。
- 是否接受练习和考试首期只做非音频题型。
- 是否接受每条路线独立验收，上一条路线通过后再进入下一条路线。

确认路线后，再为 R1 创建具体实现技术方案；代码实现从 R1 开始，不提前改动现有编辑器核心。
