# MVP v6 编辑器外壳职责拆分重构方案

> 日期：2026-10-10。状态：代码对照复审通过，可按阶段实施，尚未实施。
> 复审修订与验证边界见第 11 节。本轮仅维护方案与文档索引；实现仍需用户授权后开始。

## 1. 背景与目标

当前 `apps/website/components/EditorShell/index.tsx` 为 1486 行，同时承担页面组装、Store 订阅、选区派生、命令构造、品位输入、指针拖选、快捷键、视口滚动和 SVG 渲染。修改任意一类交互都需要阅读大量无关内容，容易遗漏草稿取消、焦点恢复或事件优先级。

本次按职责拆分，使维护者能在对应模块内完成修改与验证：

- 外壳表达工具栏、谱面和侧栏之间的协调关系。
- 命令模块负责把操作意图转换为现有领域命令。
- 交互模块集中拥有品位草稿、延迟任务和拖选生命周期。
- 视口模块集中处理可见范围、DOM 测量和滚动。
- 渲染模块只把核心 Layout 映射为 SVG。

外壳预计收敛到约 150–250 行，但行数不作为硬性验收标准。验收关注状态归属、接口大小、行为保持和修改的局部性；不能仅把原文件搬进一个巨大的 Hook。

## 4. 状态归属与模块接口

### 4.1 `index.tsx`：组装与会话协调

保留 Store 接入以及 `density`、`showChordDiagrams`、`sidebarVisible` 等会话显示状态。保留音乐文本测量与 `buildLayout` 的 memo；这段逻辑本身短且依赖明确，暂不单独增加布局 Hook。

侧栏对外报告的 `musicTextEditing` 和 `activeMusicTextTarget` 仍由外壳接收，用于谱面模式、歌词焦点、工具保护和视口跟随。它们是侧栏已接受状态的投影，不能成为第二套可独立修改的草稿状态。

外壳只连接以下流程：

1. 文档和显示偏好生成测量结果与 Layout。
2. 文档和选区生成领域上下文；Layout 和文本目标生成视觉选区、caret 与歌词焦点。
3. 创建编辑操作与交互事件，绑定工具栏和谱面。
4. 连接侧栏请求、已接受目标通知及关闭后的焦点恢复。
5. 连接视口、SVG 与 caret 的 refs。

Layout、选区矩形和能力标记均为派生数据，不增加同步 Effect 将它们复制到 `useState`。

所有 Hooks 在文档或 Layout 为空时仍按相同顺序调用；上下文、交互和视口接受空值，分别返回空能力或提前结束处理。加载错误的 JSX 返回位于 Hooks 之后，不能因为拆分把 Hook 放进条件分支。

### 4.2 `useEditorSelectionContext`：领域目标与能力

输入为文档和稳定业务选区，返回解析后的范围、当前单 Beat、唯一小节目标、focus 小节上下文及工具能力标记。目标查找纯函数放在 `editor-selection-context.ts`，Hook 只负责 memo，便于现有 Node 测试直接验证反向和跨小节选择。直接复用核心选区与 Layout 类型，不在网站重复定义同形领域模型。

必须区分三种作用域：

- 节奏/附点：选区只包含一个 Beat。
- 小节新增/复制/删除：选区位于同一小节。
- 拍号/右边界：跟随 `selection.focus` 对应的小节，可以在跨小节选择时操作。

`activeBeat.rhythm` 来自文档，不从 Layout 反推。选区保存业务 ID，不保存 system 下标或坐标。

### 4.3 `editor-commands.ts`：编辑操作

以普通函数 `createEditorCommands` 输入当前选区、领域上下文以及现有 `execute`、错误报告和历史函数，返回按职责分组的操作。该模块没有自身 React 状态、Effect 或订阅，不使用 Hook 包装。创建函数本身不执行编辑，返回的操作在调用时才报告错误或执行命令：

| 操作组     | 对外操作                     |
| ---------- | ---------------------------- |
| 音符       | 设置品位、删除矩形音符       |
| Beat       | 设置时值、附点、范围休止状态 |
| 小节       | 新增、复制、删除             |
| focus 边界 | 拍号、右边界、谱首反复       |
| 历史       | 撤销、重做                   |

内部操作使用类型化值，例如拍号使用 `ILXMTimeSignature`；下拉框字符串格式化与白名单值解析留在工具栏适配层。适配层保持旧拍号的只读 option 与现有非法值提示，不用解析失败后静默返回替代反馈。核心仍负责拍号容量、边界合法性、原子失败与 no-op，网站检查只提供即时反馈。

矩形设置和删除各发送一条批量命令，范围休止仍作用于完整 Beat。拍号持续范围保持 `untilNextChange`。

命令模块不拥有 DOM、计时器或文本草稿。品位草稿取消由交互 Hook 在现有需要取消的用户入口处统一完成。既有连音/技巧模块保留自己的命令构造，不强行搬进该模块；它们接受的执行函数和返回值契约保持清晰。

### 4.4 `useScoreInteraction`：瞬时交互生命周期

该 Hook 拥有品位草稿、延迟提交器、拖选 anchor 和 active pointer ID。输入为当前文档、选区、Layout、文本模式、Store 更新函数、编辑操作、SVG ref 和文本打开/移动请求；按 `rootEvents`、`scoreEvents`、`workspaceEvents` 分组返回事件绑定，并暴露草稿显示值、`cancelFretDraft` 和 `runImmediateAction`。SVG ref 仅用于工作区判断事件是否发生在谱面内部，不能遗漏现有 `contains(event.target)` 逻辑。

允许 Hook 内部按输入、命中和拖选拆私有函数，但不将全部内部 refs、setter 和判断暴露给调用方。继续复用 `editor-interaction.ts` 中的快捷键解析与带 generation 校验的延迟提交器。

当前模式可由 `musicTextEditing` 派生为 TAB 或音乐文本，不增加第二份可写模式状态。不使用全局 `window` 键盘监听代替当前事件作用域。

只有原来经过取消包装的入口使用 `runImmediateAction`，历史按钮与根节点历史快捷键都包括在内。指法图/排版开关、打印与原始技巧/连音执行入口保持原规则，不能笼统地取消所有操作的品位草稿。命令模块保持可独立测试，不能反向调用交互 Hook。若后续授权包装 `execute`，必须保持原有结果返回类型，不能把它降为 `void`。

组合顺序固定为：选区上下文 → 原始编辑操作 → 交互 Hook → 工具栏入口适配。交互 Hook 内部收到原始操作并先取消草稿再调用；工具栏通过外壳提供的同类适配操作调用，不能把适配后的操作重新传入交互 Hook，避免循环或重复取消。

延迟提交继续使用现有 600ms 提交器和调度时的回调语义；正常导航、重新选区和接受文本打开时可靠取消旧任务。不得将“总是读取最新 selection”或“revision 一变就取消”作为重构时的隐式优化，它们会改变现有行为。特殊入口的计时器策略以第 7 节为准。组件卸载时取消任务，pointer up/cancel 时释放捕获并清理拖选状态。

对传给侧栏的 `cancelFretDraft` 与焦点回调保持稳定引用；文本请求回调在执行时访问 `musicTextController.current`，不在渲染时捕获 controller 实例。侧栏的 `onEditingChange`、`onTargetChange` 继续使用稳定 setter，避免新对象回调让侧栏报告 Effect 反复触发。

### 4.5 `useScoreViewport`：可见性策略

输入为视口/SVG/caret refs、当前 Layout、歌词焦点、caret 几何、文本编辑状态、`lyricEditing`、`sidebarVisible` 和 focus 单元格。`lyricEditing` 由文本目标 kind 派生，不能由 `lyricFocus !== null` 代替：空歌词拍也属于歌词模式。侧栏显隐与 caret 几何需要触发重新定位，不能仅依赖 ref 对象是否变化。保留现有优先级：

1. 当前段真实歌词优先；无歌词时使用临时 caret。
2. 非歌词文本编辑且视口足够时，合并当前 Beat 的歌词/和弦范围。
3. 超宽歌词优先露出左侧锚点，避免追逐右缘。
4. 只滚动谱面视口，侧栏表单与页面不跟随滚动。

CTM、`getBoundingClientRect`、`ResizeObserver` 和 `scrollBy` 留在 Hook；矩形合并、目标是否可容纳及滚动偏移放入纯函数。纯函数接收包含 x/y/width/height 的普通数值对象，不能要求 Node 测试创建 `DOMRect` 或 `DOMPoint`。DOM 读取后统一计算再滚动，卸载或依赖变化时清理观察器。保持当前 padding=12、超宽歌词锚点宽度=8 与即时滚动行为。

### 4.6 展示模块

`EditorToolbar` 接受工具所需上下文、操作组和显示设置，不接收完整 Hook 返回值或任意状态 setter 集合。侧栏开关使用请求回调，排版与指法图开关保持会话偏好语义。

`EditorStatus` 接受预先派生的选中格数、品位草稿、错误和测量/宽度提示条件，不自行重新布局。

`ScoreCanvas` 接受 Layout、视觉选区、文本焦点、技巧 ID、SVG/caret refs 与谱面事件。沿用项目已有 React 19 ref prop 写法，保持函数组件和 Hooks，不新增类组件。

`ScoreSystem`、`ScoreMeasure` 等只接收各自需要的 Layout 数据。小节内图元先集中在 `ScoreMeasure`，不为每个 `<line>`、`<text>` 建立单独模块。`MusicTextLayer` 继续复用；小节线图元被行头与小节共享，适合单独提取。

工具栏存在两个明确接口：普通工具的已适配操作，以及既有连音/技巧模块所需的原始 `document`、`selection`、`execute` 与技巧状态函数。允许后者继续使用原有 props，但不将完整 Store 透传。统一操作包装只由外壳/交互模块负责，Toolbar 不再另设第二套包装。

## 5. 行为保持契约

| 场景               | 拆分后必须保持的行为                                           |
| ------------------ | -------------------------------------------------------------- |
| 音乐文本命中       | 最先处理，向侧栏请求打开对应实体与歌词段                       |
| 文本编辑中点击 TAB | 向侧栏请求移动目标，经草稿保护后才接受切换；不启动普通拖选     |
| 普通模式技巧命中   | 在 TAB 命中前处理，所有跨行 segment 使用同一技巧 ID            |
| TAB 拖选           | Shift 延续原 anchor，空白区域保留最后合法 focus                |
| 工作区空白点击     | 普通模式清除临时选区、技巧焦点、错误和品位草稿；Shift 保留选区 |
| 历史快捷键         | 根节点处理；表单目标保留原生键盘行为                           |
| 谱面快捷键         | SVG 处理方向键、Escape、品位、删除和 R；系统修饰键继续交还上层 |
| 品位输入           | 0–24，1/2 等待最多 600ms；有效两位输入只产生一条命令           |
| 文本草稿           | 父模块不得绕过 `open/move/requestClose` 直接切换目标或隐藏侧栏 |
| 显示偏好           | 排版和指法图开关不写文档、不进历史；指法图切换保留文本草稿     |
| 焦点恢复           | 侧栏关闭后返回属性面板按钮；SVG 和 Toolbar 的键盘作用域保持    |
| 技巧表单           | 保留按技巧 ID 的 `key`，避免选择不同技巧时沿用旧表单状态       |

## 6. SVG、样式与性能约束

第一阶段保持现有 DOM 嵌套、className、aria 属性和事件绑定位置，不增加会影响布局、冒泡或打印选择器的包装元素。首次拆分共用 `index.module.scss`，暂不拆样式文件。

保持绘制顺序：SVG 定义 → 音乐文本 → TAB 选区/caret → 各行行头、小节 → 对应技巧层。小节内部保留当前图元顺序。`pointerEvents="none"` 和选区打印隐藏规则原样迁移。

连音始终渲染数字与范围括号，不受是否连梁影响；技巧只映射核心 path/text/bounds，不在 React 重算几何。保留 SVG viewBox、A4 内容宽度 733、超宽谱面比例、marker 引用和打印技巧颜色。

拆文件不自动减少重渲染。第一轮保留现有 memo 依赖和 Store selector，不为拆分盲目添加 `React.memo`、缓存或自定义比较器。只有后续测量到性能问题时再单独优化，不承诺本次重构改善帧率。

## 7. 已发现的入口差异与处理决策

普通工具通过 `runImmediateEditorAction` 取消品位草稿；现有 `TupletToolbar` 和 `TechniqueToolbar` 接收原始 `execute`，没有经过该包装。输入品位前缀后迅速点击这些工具时，待提交任务可能继续执行。

本方案默认采用“机械拆分保留行为”的决策：阶段一至三不顺带改变这两个入口。将此差异作为独立待决策项，审查时可选择纳入一个单独的后续修正步骤。

若授权统一取消规则，则在工具接入处提供保留执行结果的包装函数，先取消草稿，再调用原始 `execute`；不改变领域命令、历史计数或工具局部表单状态。必须验证“品位前缀 → 技巧/连音操作 → 等待超时”不再产生迟到音符，并单独记录这一行为变化。

## 8. 实施步骤与阶段退出条件

### 阶段一：展示拆分

提取工具栏、状态提示、SVG 根节点、行、小节、选区和技巧图元。处理函数仍在外壳，先保持原语义与渲染结构。

退出条件：页面结构、图元顺序、文字内容、工具状态、焦点及打印 class 均保持；网站类型检查和 lint 通过；检查桌面、窄窗口、歌词/和弦/技巧/连音混合谱面。

### 阶段二：领域上下文与命令拆分

提取领域目标纯函数与 `useEditorSelectionContext`，再提取普通函数 `createEditorCommands`。合并矩形范围的重复转换，保持不同工具作用域；抽出工具栏配置和字符串适配。

退出条件：单 Beat、同小节范围、跨小节范围及反向选择的工具能力一致；各编辑操作仍通过原领域命令与历史；失败和 no-op 行为保持。

### 阶段三：交互与视口拆分

提取 `useScoreInteraction`，集中计时器与拖选生命周期；提取 `useScoreViewport` 和纯滚动计算。外壳保留必要的组装与侧栏连接，检查接口是否泄露内部 refs/setters。

退出条件：品位取消、命中优先级、快捷键作用域、草稿保护和滚动全部通过验证；不存在第二份文档、选区、草稿或派生布局状态。

每阶段保持可运行，失败时优先修正本阶段接口或行为；不同时重写领域模型、侧栏和样式。实施前保存与本次修改相关的工作区文件内容、diff 和未跟踪文件清单作为对照，不要求先提交所有已有改动。回退只撤销本次重构增量，不使用全工作区 reset/restore。若实施时当前工作区已有进一步变化，先修订方案涉及的基线与契约。

## 11. 2026-10-10 代码对照复审

### 11.1 结论

方案方向合理，修订后可按三个阶段落地。现有核心导出、Store 执行入口和侧栏 controller 足以支持拆分，不需要先修改核心包或安装新的运行时依赖。本结论是技术方案具备实施条件，不等于新模块已经编译通过或重构已获实施授权。

### 11.2 发现与修订

| 问题                                    | 代码依据与风险                                                                            | 本次方案修订                                                   |
| --------------------------------------- | ----------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 命令模块使用 Hook 缺乏必要性            | 现有命令处理函数无独立状态或 Effect，增加 Hook 会扩大 React 耦合                          | 改为 `createEditorCommands` 普通工厂函数，便于直接测试操作结果 |
| 取消包装的组装顺序不够明确              | 交互需要命令，工具又需要交互取消能力，易形成双重包装或循环                                | 固定“上下文→原始操作→交互→工具入口”的单向组装顺序              |
| 视口输入信息不足                        | 现有 Effect 同时依赖 `focusCaret`、`sidebarVisible`、`lyricEditing`；空歌词没有真实歌词框 | 补齐输入及触发条件，保留空拍与超宽歌词策略                     |
| 机械重构可能改变延迟目标语义            | 调度回调使用当次渲染闭包，改成最新 selection/revision 失效会改变特殊入口行为              | 保留现有调度语义，正常取消入口与工具例外分开规定               |
| 新回调可能影响侧栏 Effect 与 controller | 侧栏通过 Effect 报告 editing/target，controller 随草稿更新                                | 保留稳定报告函数；文本请求执行时读取 ref                       |
| 空值与测试接口未明确                    | 当前加载错误返回在所有 Hooks 之后；网站测试默认 Node 环境                                 | Hooks 接受空值；选区和滚动纯计算使用无 DOM 的测试接口          |
| 大量未提交改动使回退基线不清            | 当前功能包含未跟踪侧栏及草稿模块，HEAD 不含完整工作区                                     | 保存工作区对照并只回退重构增量                                 |
