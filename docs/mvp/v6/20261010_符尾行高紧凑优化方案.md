# 符尾行高紧凑优化方案

用户已审查聊天中的方案并授权实施。

## 根因与字体证据

原先的 36 单位净空来自浏览器文字元素行框，下缘并不是符尾实际墨迹轮廓。读取仓库 `apps/website/assets/fonts/Bravura.otf` 的 CoreText 字形路径，在字号 18 下得到：

| 字形                | SVG 轮廓下缘（相对基线） |
| ------------------- | -----------------------: |
| U+E241 八分符尾     |                    0.252 |
| U+E243 十六分符尾   |                    0.162 |
| U+E245 三十二分符尾 |                    3.096 |

符尾主体在基线上方，只有三十二分符尾向下延伸约 3.1 单位。既有 `calculateMeasureHeight()` 还为没有符尾的小节无条件预留 36 单位，所以歌词位置和后续谱行都被推远。

上述轮廓由 `CTFontCreateWithGraphicsFont`（字号 18）和 `CTFontCreatePathForGlyph(...).boundingBoxOfPath` 提取，SVG 下缘等于字体路径 `-minY`。将来替换 Bravura 字体时需要重新校准此表。

## 实施

- 新增纯函数 `getDurationFlagBottom`：按各字形轮廓下缘和字号缩放，增加 1 单位抗锯齿安全余量；未识别字形仍使用保守 fallback。
- 新增 `getRhythmBottom`，统一计算弦线、符干、连梁、符尾、延续线、附点、休止符的最下缘。
- 小节高度与连音括号定位消费相同节奏边界；小节至少容纳六线谱及底部 12 单位选择净空。
- 同谱行连音括号继续统一高度，歌词继续位于最终标注带下方；不缩小符尾字号、括号净空和谱行间距。
- 只含休止符或空 Beat 的小节无需保留空符干/符尾带。

## 验证

- 三种孤立符尾、两种排版密度：与四分符干相比仅增加不足 5 单位，不再增加 36 单位。
- 字号缩放、基线平移、纯休止符行高，以及既有同行括号对齐、歌词/技巧/换行净空回归。
- 完整测试、类型检查、Lint、核心构建及浏览器截图核对。
- 保留工作区原有 `next-env.d.ts` 环境变更，不纳入修复提交。
