# MVP v6 和弦显示格式全局开关方案

> 日期：2026-10-10。状态：用户已授权并实现全局开关；验证结果见[增量实施验收](./20261010_歌词与和弦显示优化实施验收.md)。
>
> 本方案替代[属性侧边栏方案](./20261010_音乐文本属性侧边栏方案.md)第 3.3 节中逐个和弦选择显示模式的交互。首版实际交付记录保持不变。

## 1. 交互与范围

移除和弦编辑表单中的“显示格式 / 显示模式”字段，在顶部排版设置附近增加“显示和弦指法图”开关。始终显示和弦名称，开关只控制指法图是否出现在谱面上，作用于当前乐谱的所有和弦。

| 开关状态     | 谱面与打印行为                                         |
| ------------ | ------------------------------------------------------ |
| 开启（默认） | 有指法图的和弦显示名称与指法图；没有图的和弦只显示名称 |
| 关闭         | 所有和弦只显示名称                                     |

开关不依赖当前选区、侧栏是否打开或正在编辑哪个和弦；无需逐个应用。切换后重新布局，打印沿用当前显示设置。首版作为当前编辑器会话的显示偏好，不写入乐谱、不进入撤销重做历史，也不写入浏览器存储；刷新后恢复默认开启。后续若需要随乐谱保存，再单独调整持久化契约。

常驻辅助说明或可访问的提示文案：“控制整张谱面的指法图显示，打印同步；隐藏不会删除指法。”

## 2. 和弦编辑与草稿

- 基本设置保留和弦名称、常用预设与起始品位。指法表格、横按和草稿预览继续保留。
- 全局关闭时，侧栏仍展示实际指法草稿及预览，允许创建、修改和应用指法图；应用后谱面保持只显示名称，重新开启全局开关即可看到保存的图。
- 全局切换立即生效，不提交、清空或关闭和弦草稿，不改变编辑目标，也不触发未应用草稿确认。取消草稿不会回退全局显示偏好。
- “清除指法图”独立于全局开关，有图时可用。点击只清空当前草稿中的图，应用后才删除当前和弦的指法数据；取消仍恢复原值。无图状态继续提供“创建指法图”。
- 创建或保存有图的和弦时仍要求指法合法；全局隐藏不能绕过起始品位、弦、手指、横按等校验。

“隐藏指法图”和“清除指法图”分别承担显示控制与内容修改，界面提示应明确二者的作用。

## 3. 数据与兼容

当前模型在单个 `ILXMChordSymbol` 上保存 `display`，取值为 `name` 或 `nameAndDiagram`；schema 要求 `nameAndDiagram` 必须具有指法图。当前 `createChordBlock` 与网站音乐文本测量也依赖该字段，不能只移除表单字段或用 CSS 隐藏图。

本次保留原 schema 与字段，以兼容现有文档；新增全局布局参数统一决定当前界面的有效显示方式，不批量重写和弦：

- 全局开启且该和弦有图：有效显示为 `nameAndDiagram`，包括旧数据中 `display=name` 但仍保留指法图的和弦。
- 全局关闭或该和弦无图：有效显示为 `name`。
- 网站新建或应用当前和弦时，按是否有图生成合法的持久化值：有图写 `nameAndDiagram`，无图写 `name`。实际内容修改继续走现有领域命令。
- 核心调用方未传全局参数时保留原有逐和弦 `display` 行为；网站编辑器显式传入全局设置，避免影响其他使用者。

全局切换不更改文档对象、revision、和弦 ID、实际品位或历史栈，也不自动生成缺失的指法图。

## 4. 实施位置与布局契约

| 位置                                      | 调整                                                                       |
| ----------------------------------------- | -------------------------------------------------------------------------- |
| `EditorShell/index.tsx`                   | 管理会话开关，顶部入口；同时传给测量与布局，在有草稿时仍可操作             |
| `ChordEditor.tsx`、`MusicTextSidebar.tsx` | 删除逐和弦显示字段及相关清图限制；按图是否存在生成提交值，保留图合法性校验 |
| 网站 `music-text-metrics.ts`              | 测量使用有效显示方式；请求集合随开关更新；缓存仅复用字体参数一致的字形测量 |
| 核心布局 `layout-types.ts` 与调用链       | 增加可选全局显示参数，贯穿间距、分行与最终内容布局                         |
| 核心 `music-text-layout.ts`               | 用统一规则决定名称与图的布局、边界和命中区域；省略参数保持兼容             |

有效显示方式应通过共享纯函数计算，关键逻辑补中文注释。谱面间距、分行、和弦行高度、渲染和命中边界必须使用同一规则；关闭后不保留指法图的空白占位或可点击区域。重新开启后恢复图所需空间，允许因此重新分行。打印使用同一份显示结果，开关及侧栏控件不进入打印内容。

与后续歌词选区优化联动时，切换开关导致的几何变化需要让歌词高亮与滚动定位使用新布局，不能沿用旧坐标。

## 5. 验收标准

1. 多个有图和无图的和弦由一个开关统一控制；单个和弦表单不再出现显示格式字段。
2. 旧 `display=name` 且有图的数据在全局开启时显示图；无图数据保持只显示名称；核心省略全局参数时保持原行为。
3. 关闭、开启不改变指法数据、文档 revision 或历史栈；隐藏期间编辑并应用的图在开启后正确显示。
4. 未应用草稿在切换开关后仍完整保留；取消草稿不回退开关；清图需应用才写回，且可通过文档撤销恢复。
5. 名称与图的测量、间距、分行及命中边界一致；关闭后图不占位、不参与点击，重新开启后布局正确恢复。
6. 打印遵循当前开关状态；桌面与窄窗口入口可达，歌词选区在重新布局后仍对齐。

实施时增加有意义的核心布局与网站状态验证，运行受影响模块的测试、类型检查、lint 和构建。真实打印预览需单独记录人工验收结果，不能用构建成功代替。

## 6. 实际实现补充

全局开关以当前会话状态管理，默认开启。核心在 `buildLayout` 门面通过 `chordDisplayTrack` 创建不可变的显示投影，统一传给现有间距、分行、最终内容布局和命中构建；采用这一入口投影，避免每一层分别判断开关。省略参数时直接使用原轨道，旧调用行为保持兼容。

音乐文本测量请求使用同一 `effectiveChordDisplay` 规则。字形缓存键原本包含文本、字体、字号、锚点和字重；开关改变请求集合而非字形本身，所以保留可复用字形缓存，不添加无意义的开关维度。侧栏始终按实际图预览，应用时按图是否存在派生合法 `display`。

系统打印沿用当前 SVG，因此使用相同开关结果；真实打印预览仍待人工验收。已执行的测试与页面检查见[增量实施验收](./20261010_歌词与和弦显示优化实施验收.md)。
