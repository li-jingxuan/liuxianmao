# MVP v6 歌词选区与分隔连续录入方案

> 日期：2026-10-10。状态：用户已授权，歌词位置高亮、连续填词与规则 Tips 已实现；验证边界见[增量实施验收](./20261010_歌词与和弦显示优化实施验收.md)。
> 两个目标来自用户：选中歌词时在歌词上显示选区；输入一段按分隔符对应多个 Beat 的歌词。
> 本文在[已实现的属性侧栏](./20261010_音乐文本属性侧边栏实施验收.md)上增量设计，具体交付与验收以增量实施验收记录为准。

## 1. 已确认规则

建议同时支持两种歌词录入方式：保留现有“单拍编辑”，新增“连续填词”。点击已有歌词时在其实际文字位置高亮；连续填词先展示对应拍与覆盖情况，再一次应用整批内容。

| 项目           | 规则                                                      | 状态       |
| -------------- | --------------------------------------------------------- | ---------- |
| 选中歌词的反馈 | 高亮当前段的歌词，隐藏 TAB 的视觉选区，保留底层 Beat 引用 | 用户已确认 |
| 分隔方式       | 使用空格，如 `风 吹 过`，每项对应一个 Beat                | 用户已确认 |
| 休止拍         | 与普通 Beat 一样占一个位置，不自动跳过                    | 用户已确认 |
| 重复空格       | 连续空格合并为一个分隔符，首尾空格忽略                    | 用户已确认 |
| 空位           | 使用独立 `_` 项占一拍但不写入，保留已有歌词               | 用户已确认 |
| 已有内容       | 预览标注差异；默认阻止覆盖，用户勾选允许覆盖后再应用      | 用户已确认 |
| 历史           | 整批成功只增加一条历史，失败一项则全部不写入              | 技术必需   |

2026-10-10 用户已确认空格分隔、休止拍占位，并进一步同意重复空格合并、`_` 显式空位等补充建议，要求界面提供 Tips 说明规则。随后用户明确授权开工，已按下述规则实现。

## 2. 当前实现与原因

- `EditorShell/index.tsx` 的 `selectionRects` 与 `focusCaret` 都从 TAB 单元格 selection 生成。点击歌词虽然命中正确的 `beatId/verse`，但 `MusicTextSidebar` 的目标加载仍调用 `createCollapsedTabCellSelection`，所以框显示在弦线拍点上。
- `MusicTextLayer.tsx` 逐项渲染 `LyricLayout`。核心已经提供最终歌词 `label.bounds`、`bounds` 与命中索引的 `trackId/measureId/beatId/id/verse`，可以直接绘制准确的文字高亮，无需用网页坐标猜测位置。
- 侧栏的“应用并下一拍”仅将一次单拍命令提交后前进，属于逐拍连续操作；当前并不支持拆分整段文字并分配多拍。
- `ILXMMusicTextCommand` 当前只有单项 `lyric.set/remove`，每次 store.execute 的 changed 命令产生一条历史。网页循环执行 set 会产生多条撤销且可能部分提交，不能用这种方式模拟整批应用。
- 现有 `editMeasureMusicText` 支持文本规范化、已有项保留 ID、排序与 no-op；统一分发器通过 schema 和语义校验再提交。新增批量能力应复用这些规则。

## 3. 优化一：歌词位置上的选区

### 3.1 用户看到的行为

1. 点击谱面歌词，选中该 `beatId + verse` 的实际文字，使用浅蓝背景与细蓝边框；1–4 段分别定位，不能把同 Beat 的所有段都框起来。
2. 在侧栏切段、切拍或“应用并下一拍”，高亮跟随新的编辑目标；文本修改应用后随新布局更新。
3. 编辑歌词期间不同时显示 TAB 蓝色范围与 caret。内部 selection 仍保留 Beat 与弦号，用于定位、换拍与现有工具契约。
4. 关闭歌词编辑、文档历史切换或切到和弦，清理歌词视觉焦点，再按相应模式恢复现有 TAB 选区。第一版不顺带改变和弦选区规则。
5. 目标拍当前没有该段歌词时，无法框住不存在的文字：使用现有 Beat caret 的虚线待填写样式并显示“此拍暂无第 N 段歌词”。不伪造空歌词实体或人为增加一条歌词排版行。

### 3.2 状态、几何与渲染

- 侧栏接受目标后通过稳定回调向父壳报告有效目标；dirty 请求等待确认时，目标、selection 和高亮均停留原处。父壳不能只从 `musicTextEditing: boolean` 推测类型与段号。
- 新增页面临时 `activeMusicTextTarget`（含 kind、trackId、measureId、beatId、verse），由已接受的草稿目标驱动；不写入乐谱或撤销快照，不让它成为第二份持久化选区。
- 用当前 layout 的最终 `LyricLayout.bounds` 或命中 bounds 查找目标；为视觉高亮增加少量净空，例如水平 4、垂直 2 个 SVG 单位。复用文字度量，不自行计算字号或字符串宽度。
- 在 MusicTextLayer 的文字之前绘制背景，在文字之后或同组绘制边框，`pointerEvents="none"`；避免现有 selectionLayer 在文字之后绘制填充而压暗字形。TAB 选区层保持原有音乐元素的层级。
- 歌词高亮属于临时 UI 几何，不修改核心文字 bounds 或 hitIndex，不参与列宽、断行、谱行高度和保存。
- 自动滚动以当前段歌词 bounds 为优先目标，空拍则回退 Beat caret；不再将当前 Beat 的所有段与和弦一并纳入目标。巨宽歌词优先显示锚点，保持真实字号。
- 字体重测、密度切换及重排后重新解析当前 bounds；目标不存在时清理高亮。所有临时高亮、待填写 caret 在打印时隐藏。

## 4. 优化二：按分隔符连续填词

### 4.1 入口与操作闭环

歌词标签增加“单拍编辑 / 连续填词”模式。单拍保持现有行为；连续填词仍选择一个歌词段号，以及从当前焦点 Beat 开始的目标。

推荐流程：

1. 选择起始 Beat 和第 1–4 段中的一段。
2. 输入整段分隔文本，例如 `风 吹 过 山 谷`。
3. 页面即时展示对应列表：第几小节/第几拍、普通拍或休止、新文字、原文字与操作类型。
4. 若存在覆盖，明确列出数量与前后值；用户选择是否允许覆盖。
5. 点击“应用全部”，通过一条领域命令提交；成功后留在本次起始拍，并保留输入内容和映射预览。原值已与新值一致时，显示“内容未变化”，不增加历史。
6. 用户可再次选择其他起点继续填词；首版不增加批量“应用后自动跳到下一段”的隐含导航。

模式切换、段号、起点、切和弦和关闭面板均经过同一草稿保护。连续模式的 Enter 不自动提交整批，提交使用明确按钮；Ctrl/Cmd+Enter 可作为后续快捷键，首版无需同时增加。

### 4.2 已确认的空格分隔语法

首版使用以下确定语法：

| 输入                 | 分配结果                                                  |
| -------------------- | --------------------------------------------------------- |
| `风 吹 过`           | 连续三个 Beat，分别写入“风”“吹”“过”                       |
| `Sing a song`        | 三个 Beat，分别写入“Sing”“a”“song”                        |
| `风 _ 过`            | 三个 Beat，第二拍占位但不写入或删除；适合暂不填词的休止拍 |
| `_ 风 _`             | 三个 Beat，第一与第三拍明确跳过                           |
| `风  吹`（两个空格） | 按两个 Beat 处理，重复空格不生成空位                      |
| `风 吹`              | 忽略首尾空格，仍对应两个 Beat                             |

- 分隔符使用普通半角空格（U+0020）；中文全角空格（U+3000）同样按分隔处理。其他特殊空白明确报错，不用泛化的 `\s+` 把换行、制表符一并吞掉。
- 连续分隔空格合并、首尾分隔空格忽略，因此空格数量不表达跳拍。每个非空项保留原始位置用于报错；用明确 `_` token 生成 `skip` 项，不能过滤 skip 导致后续词前移。
- 只有整项恰好等于 `_` 才表示跳过，`a_b` 是普通文字；多个空位写成 `_ _`，不是 `__`。下划线占位是输入语法，不是歌词延长线，也不会保存或绘制 `_`。
- skip 只占目标位置，不会删掉该拍已有歌词。删除仍在单拍模式明确执行；休止拍也可填非空歌词，不强制必须跳过。
- 文字项沿用 NFC 与每项最多 64 个 Unicode code point 的规范。解析之前先检查原始控制字符；原始换行、制表符必须报错，不能被 trim 或分隔处理掩盖。
- 连续模式可用多行高度的 textarea 显示长输入，但只接受一段单行文本，视觉软换行不算输入换行；表单 paste 守卫按模式组织，不悄悄清理输入。
- 英文短句 `a song` 在连续模式对应两个 Beat；若需整句落在同一 Beat，用单拍模式编辑该拍。首版不引入引号分组或转义，避免普通标点改变解析；连续模式中需要字面 `_` 的歌词也用单拍模式输入。
- `|` 不再有分隔作用，作为普通歌词字符处理，不保留两种默认分隔方式。
- 建议单批最多 256 个位置、原始输入最多 16384 个 Unicode code point，超限在解析和核心命令两侧拒绝；不截断后静默应用。仅含空格或全为 skip 的输入不提交，提示输入有效歌词。

上述重复空格、全角空格、`_` 占位和短句处理已按用户同意纳入首版规则；界面必须显示以下 Tips，不依赖用户阅读技术文档理解语法。

### 4.2.1 规则 Tips（必须交付）

连续填词输入框下方常驻浅蓝提示区域，标题为“连续填词规则”。不能只放鼠标悬浮提示，窄窗口也应能通过侧栏滚动阅读。建议正式文案：

> 用空格分词，每项依次对应一拍，休止拍也占一格。多个空格按一个分隔处理。
> 用 `_` 跳过一拍并保留原歌词，例如 `风 _ 过`。
> 英文短句按空格拆词；要把 `a song` 放在同一拍，请切到单拍编辑。
> 先核对下方对应预览，再应用全部。已有歌词不会自动覆盖。

输入框 placeholder 使用“例如：风 吹 \_ 过 山 谷”，并通过 `aria-describedby` 关联 Tips，避免仅靠颜色或 placeholder 传达必需规则。

更多规则以“详细规则”可展开说明，包含：半角/全角空格均可分隔；首尾空格忽略；仅独立 `_` 表示跳过；不接受换行/制表符；谱尾位置不足整批拒绝；整批一次撤销。具体错误仍在字段旁单独显示，不能由 Tips 代替错误反馈。

Tips 在打开连续模式、尚未输入时即可阅读；切回单拍模式则显示现有单拍快捷键提示。覆盖开关旁显示“允许替换预览中标记的已有歌词”，开启后应用区显示实际覆盖数量。

### 4.3 Beat 对齐与范围

- 从当前轨道的起始 Beat（含自身）顺序对应实际 Beat 列表，可跨小节和谱行，不能跨轨道。
- 用户已确认休止拍也占一个位置，与既有“应用并下一拍”一致。连音组成员按真实 Beat 数量逐项分配，不按时值比例或一小节固定四拍拆分；一个 Beat 内多根弦也只占一项。
- 预览明确标注休止拍，按完整 Beat 列表分配；不提供隐式自动跳过休止。用户可以为休止拍填词，或用 `_` 显式占位。
- 分配所需位置超过谱尾剩余数量，整批禁止应用，提示还缺几个 Beat；不自动新增小节，不仅应用前面部分。
- 输入项少于可用 Beat，只修改覆盖到的非空项；后续所有 Beat 与其他歌词段、和弦、节奏保持。
- 起点变化重新生成预览，有 dirty 草稿时先确认。原始输入的每个位置必须有明确状态，包含跳过项与谱尾越界项。

### 4.4 已有歌词与外部变化

- 预览区分新增、修改、未变化、跳过和错误。新增与修改是实际写入数，不能把空位计入写入数量。
- 默认不允许替换不同的已有词。存在此类项时禁用“应用全部”，提供“允许覆盖已有歌词”开关；打开后仍保留原值/新值预览，应用按钮说明实际覆盖数量。
- 原值与规范化新值相同为未变化，不阻挡提交，也不增加历史。
- 覆盖开关、录入模式、段号、起点和原始输入均属于草稿。换起点/段号重新关闭覆盖开关，避免沿用先前目标的覆盖许可。
- 文档对象引用因其他操作或历史切换改变时，取消批量草稿与预览，不能把预览过的覆盖许可带到新快照。预览成功本身不替代提交时的重新校验。
- 单批应用后清除 dirty 并更新 baseline；失败保留原始文本、目标与错误，整批没有历史变更。关闭/切换的“应用后继续”在连续模式调用原子批量应用。

## 5. 技术实现建议

### 5.1 保持持久化模型不变

继续使用 measure.lyrics 的 `id/beatId/verse/text`，本次不升级 schema，不保存“整段歌词字符串”、分隔符、预览表或 UI 模式。文本始终锚定稳定 Beat，沿用现有节奏、复制小节及 loader 规则。

### 5.2 解析、规划与原子命令

1. 网站纯函数解析分隔文本，输出带原始位置索引的 `set(text)` 或 `skip` 项与具体错误。
2. 使用核心纯规划函数，从轨道/起点/段号/分段项生成完整映射和冲突摘要；UI 预览与命令校验共用该规划器，避免两套不同的休止/空位规则。
3. 新增专用命令，例如 `lyrics.setSequence`，携带 trackId、起始 measureId/beatId、verse、分段项与允许覆盖标志。skip 为显式判别项，不能用空字符串冒充合法 lyric.set。
4. 命令重新验证轨道、起点、段号、项目数量、所有非空文字、剩余容量和已有内容冲突；任何一项不合法时返回完整定位错误，不修改文档。
5. 使用一个文档级 ID factory 构造受影响小节候选，修改已有项保留 ID，新项统一分配 ID。多个小节不能分别创建 factory 而产生重复 ID。
6. 可以复用 `editMeasureMusicText` 的单项规范化与小节更新，在隔离的候选分支中累计；不能循环调用公开 `applyScoreCommand` 或 store.execute，以免增加多次 revision/history。
7. 候选整批一次增加 revision，统一 finalize 校验一次，最后由 store.execute 接受一份快照。全为同值/跳过则返回原文档 `changed:false`，不增加历史。
8. 提交保留其他段号、和弦、Note、Beat、技巧等对象。依照各小节真实 Beat 顺序与 verse 排序，输入对象与最终文档不共享可变引用。

建议错误分类：非法歌词项、批次超限、起点失效、目标容量不足、已有内容冲突。每类提示包含原始第几项或对应小节/Beat，不统一折叠为“应用失败”。

### 5.3 侧栏与高亮协同

- 歌词草稿改成单拍/连续的判别联合，避免连续 textarea 误触现有 Enter 下一拍提交。
- 连续预览只高亮当前检查的一项；点击预览行切换临时检查索引并滚动到对应词，不改变整批起点或生成第二份草稿。skip 项/空词使用待填写 Beat 提示，不写入临时文字。
- 首版不把未应用文字混入正式 MusicTextLayer 或度量快照；预览表显示拟写内容，谱面只高亮现有实体/目标。未应用内容不会影响断行，应用后通过正式 layout 重排。
- 目标回调与关闭/历史订阅统一清理，批量检查索引和起点分别存储；不要误将检查某行理解为重设整批起点。
- 所有输入继续隔离 TAB 快捷键，组合输入期间不应用或关闭。确认区复用已有三种选择与键盘边界。

## 7. 验收标准

- 第 1–4 段点击和切段，高亮位于实际当前词；关闭/历史切换后无残留，和弦及普通 TAB 编辑不受影响。
- 英文长词、中文、字体重测、两种密度、自动断行及视口变化后高亮和命中仍正确；高亮不增加乐谱几何或输出到打印正文。
- 单空格/重复空格/首尾空格、全角空格、`_`/`_ _`/`a_b`、含空格英文短句、纯空位、Unicode、非法控制字符、超长单项和超大批次具有明确结果。
- 普通 Beat、休止、多弦 Note、连音与跨小节/谱行映射正确；越过谱尾整批失败。
- 连续模式常驻 Tips、详细规则、示例与无障碍关联已实现；空态及窄窗口可读，说明与实际分隔/跳过/覆盖规则一致。
- 已有词差异阻挡默认提交，显式允许后批量替换；空位保留原词，同值不产生额外历史。
- 有一项错误、起点失效、引用失效或容量不足时，文档对象/revision/history 不变；批量成功只加一次 revision、一条历史，撤销/重做完整恢复所有小节。
- 复制小节、节奏调整、JSON round-trip 能处理批量写入后的歌词；没有新持久化字段或共享可变快照。
- 预览检查行不改变起点；dirty 换模式/起点/段号/标签/关闭行为一致；失败保留原输入。
- 工程检查覆盖核心与网站测试、type-check、lint、build、diff；浏览器验证 DOM 焦点、跨行滚动、草稿确认与真实字体位置。输入法候选与系统打印预览仍需分别记录人工边界。

## 8. 本轮结论

歌词选区可以复用已有最终文字 bounds，属于网站交互与渲染改进；连续填词需要跨核心命令和网站草稿的增量实现，不能仅添加一个 split 输入框。

用户已授权并完成增量实现：歌词实际位置高亮、空拍虚线 caret、单拍/连续模式、常驻 Tips、预览检查行、显式覆盖与原子批量命令。规则解析与规划共同放在核心 `lyric-sequence.ts`，网站复用同一规则；与最初建议网站单独解析相比，减少了两端规则漂移。

当前草稿使用明确的 `lyricMode` 和覆盖许可字段，模式切换仍走统一保护。批次原始字符串仅存于页面草稿，不新增持久化字段。工程检查和浏览器验证结果见[增量实施验收](./20261010_歌词与和弦显示优化实施验收.md)，不将未执行的系统输入法、打印预览或真实 200% 缩放记为通过。
