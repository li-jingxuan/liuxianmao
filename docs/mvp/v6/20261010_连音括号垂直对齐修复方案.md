# 连音括号垂直对齐修复方案

用户已审查聊天中的方案并授权修复。

## 问题与证据

`durationGlyph` 只设置 Bravura 字体，不直接移动连音括号。`layoutTuplets` 根据每个小节的最低节奏图形决定标注高度；孤立符尾使该小节括号下移。同一谱行的多个小节因此高低不齐。

Chrome 对现有 MVP6 页面测得：第一行括号横线 Y 分别为 262.6667、262.6667、297.1667，相差 34.5 个布局单位。同一括号左右钩线的 Y 始终相同。

当前字号 18 的 Bravura 符尾在浏览器元素边界测量中，下缘相对文字原点约为 35.99。因此本修复保留既有 36 单位保守净空，不用缺乏字形轮廓证据的更小值替代。此测量是浏览器元素边界，并非精确墨迹轮廓。

## 实施

1. 保留小节局部节奏图形净空计算。
2. 在 `layoutSystems` 完成同一行小节布局后，取该行所有连音标注的最大 label Y，统一平移数字、括号横线及两端钩线。
3. 保留首末 Beat 的 X 坐标、中间数字间隙和钩线长度。
4. 更新受影响小节高度和谱行高度，再交给技巧、歌词联合排版及最终坐标平移。
5. 没有连音组的谱行保持原样；每条谱行独立决定高度。

不修改持久化模型、编辑命令、符尾 CSS 或既有字体，不取消任何连音数字或括号。

## 验收

- compact/comfortable 模式，多小节同一行的数字基线、括号横线和钩线端点一致。
- 孤立符尾、连梁、休止符混排时保留净空。
- 水平锚点、中央数字间隙和输入布局不变。
- MVP6 技巧和歌词共存时，歌词位于标注带下方，后续谱行不重叠。
- 执行布局回归、完整测试、类型检查、lint，并在真实页面核对坐标及截图。

## 实施验收结果
