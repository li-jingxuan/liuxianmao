## 3. 发现与修订

### 3.1 自身提交会被 revision 监听错误关闭（高优先级）

依据：[store.execute](../../../apps/website/stores/editor-store.ts#L226) 同步更新文档；[undo](../../../apps/website/stores/editor-store.ts#L301)/redo 恢复历史快照，revision 并不单调递增。

原稿要求“revision 变化就关闭草稿”，同时又要求“应用并下一拍保持面板打开”。自身 set 也会增加 revision，两条规则冲突；undo 后分支还可能重复相同 revision。

修订：用文档引用识别 snapshot 切换，own-commit token 区分自身提交和外部事件；增加应用/下一拍/删除/失败/no-op/外部切换的状态表。dirty 的取消/Esc 与切目标统一保护。下一拍只从命令返回的文档派生，失败不前进。

### 3.2 新模型和旧写入路径不能分三个切片才兼容（高优先级）

依据：[全休止拍号重建](../../../packages/lxm-editor/src/core/time-signature-change.ts#L46)、[尾部休止协调](../../../packages/lxm-editor/src/core/measure-timeline.ts#L29) 可能更换 Beat；现有 copy 只复制 chordSymbol ID，没有新模型的 beatId 映射。

原稿把 schema 更换放 Step 1、完整兼容放 Step 3，却要求每个切片始终可构建可用。中间新合法文档会被旧命令重建成悬挂引用，或只在最终 validation 失败。

修订：timeline 文本保护、全休止重建条件、旧 tick 守卫替换、copy/insert 新字段与引用映射随模型同时完成；Step 3 深化组合回归和错误诊断。新增 `MUSIC_TEXT_BLOCKS_TIME_SIGNATURE`，但真实 notes/tuplet 自身超容继续报告原容量错误。

### 3.3 首末列宽只有约束，没有接入 slot 的完整算法（高优先级）

依据：[spacing summary](../../../packages/lxm-editor/src/layout/measure-spacing.ts#L102) 与 [正式 spacing](../../../packages/lxm-editor/src/layout/measure-spacing.ts#L148) 分别计算宽度，第一拍位于 leading inset 后，最后一列吸收残差。

直接增加 slot.width 不能解决首拍居中文字向左越界；尾部 inset 若再次进入最后 slot 会双算。原稿对该点虽有提示，但仍缺具体分配。

修订：定义 leftExtra/tailExtra、固定/可伸展宽度和前 n-1 个相邻锚点距离的具体算法；摘要与正式布局共享同一计划。增加两列总宽 138、单列总宽 72 的数值契约。明确拍号与文本处于不同垂直区域，不夸大水平投影避让承诺。

### 3.4 技巧规划、投影与平移需要实际接入位置（高优先级）

依据：[layoutTrackTechniques](../../../packages/lxm-editor/src/layout/technique-layout.ts#L861) 先构建候选/lane，再 [translateSystems](../../../packages/lxm-editor/src/layout/technique-layout.ts#L527)，最后做扫弦/琶音时值与品位可见性投影。

原稿说“统一一次平移”，但没有说明如何从现有函数取得未平移 plan；也未明确投影与文本最低 bounds 的顺序。直接外包新高度容易重复平移或遗漏图元。

修订：提取内部 planner，保留公开 wrapper，共享技巧实现；投影后汇总实际可见正文 bounds，再规划文本，最后一次平移并建命中。保持 measure.y 的正文语义，独立新增 measure/system.visualBounds。跨小节技巧进入 system bounds，不要求它被单个 measure.height 包住。

### 3.5 字体快照缺少可直接实现的坐标约定（中优先级）

原稿只有“left/right/ascent/descent”，没有原点、anchor、baseline、挂载方式及内部空格渲染规则；实现可能测量 display:none 节点，或测量和正文使用不同 CSS。

修订：提供 request/metric Interface，统一 x/y=0、alphabetic baseline、真实 bbox 四项数值、相同 font/anchor/white-space:pre；离屏节点挂载且不用 display:none。补充 SSR 估算一致、字体事件代次、失败有限重试、无效数值、缓存上限与异步过期保护。

真实字体结果仍必须在浏览器验证，本轮没有执行 DOM 度量原型。

### 3.6 旧版本提示、多行粘贴和 IME 验收方法不完整（中优先级）

依据：[现有 loader](../../../packages/lxm-editor/src/core/loader.ts#L84) 直接进入 strict schema；网站测试运行于 Node。单行 input 还可能在 change 前清理换行。

修订：JSON 解析后先识别 schema/version，再报告旧版本；命令检查原始非法控制字符后再 trim，paste 检查原始 clipboard text；composition 结束的 Enter 不同时提交。纯状态测试与真实浏览器 DOM/人工 IME 验收分开记录。

### 3.7 新增字段后的原始全对象 deepEqual 无法成立（中优先级）

原稿要求新增文本数组、bounds 和度量状态，却又要求无文本最终对象与旧结构完全深相等。

修订：对旧字段投影做深相等，保留坐标、断行、技巧和节奏几何；另断言新增文本数组为空。相同新输入重复布局仍检查全对象确定性，不能通过删掉旧几何字段规避回归。

### 3.8 输入快照与 UI 草稿可能共享引用（中优先级）

依据：[finalize](../../../packages/lxm-editor/src/core/commands.ts#L288) 校验后返回候选原对象，并不自动替调用方深复制新 payload。

修订：set 必须复制 chord/diagram/strings/barres 值对象，copy 同样独立；测试提交后修改原命令 payload 不影响历史文档。新增面板目标折叠规则、合法弦号回退、技巧焦点清理和可读性常量，减少页面各自猜测。

## 4. 本轮验证与边界

- 对双列例（138，锚点 36/102）与单列例（72，锚点 36）做独立计算。
- 固定随机种子产生 1000 组 1–12 列、不同 padding/leading/基础宽度/文本左右占用组合，确认相邻文本与首末净空不小于设定 gap；算术断言通过。
- 这只证明方案公式在所检查的输入上自洽，不代替未来实现测试、system 拉伸测试或真实字体检查。
- 文档修改不触及功能代码，无 v6 功能测试、真实浏览器交互或实时构建通过结论。
