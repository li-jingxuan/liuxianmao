# MVP v6 音乐文本属性侧边栏方案

> 日期：2026-10-10。状态：用户已授权实施，首版已实现；工程验证与人工验收边界见[实施验收](./20261010_音乐文本属性侧边栏实施验收.md)。
> 方案与复审阶段仅新增文档；随后用户授权实施。首版基于 v6 已实现的音乐文本能力，参考右侧属性面板设计，后续根据使用反馈调整。
> 正式设计参考：[侧边栏设计稿](./设计稿/侧边栏.png)。代码复审结果见第 9 节。

## 1. 建议与目标

建议增加右侧属性侧边栏，将当前“编辑歌词、编辑和弦、撤销文本或文档、重做文本或文档”以及展开后的编辑表单迁入侧栏。顶部继续承载时值、休止、拍号、小节线、连音、技巧、排版和打印等谱面操作。

歌词和和弦需要连续填写、预览、校验，适合放在稳定的属性区域。当前表单展开在顶部，会占用谱面上方高度；侧栏可以让用户同时观察目标拍与属性，减少编辑时的视线跳动。

首版主要调整网站界面与草稿交互组织，复用现有模型、领域命令、历史和图形预览。侧栏是后续属性编辑的容器，本次只放入歌词与和弦，不提前迁移拍号、技巧等其他工具。

## 3. 首版界面

### 3.1 整体布局

```text
顶部：常用谱面工具                                  属性面板 [开/关]
──────────────────────────────────────────────────────────────────
谱面视口（独立滚动）                 │  歌词  |  和弦          ×
                                    │  目标：第 N 小节，第 M 拍
固定 A4 纸张与真实字号               │  属性表单（独立滚动）
                                    │  校验信息 / 操作提示
                                    │─────────────────────────
                                    │  撤销 / 重做（全谱）
                                    │  删除       取消   应用
```

- 参考图片的白色面板、浅灰背景、细边框、圆角、蓝色选中标签与主按钮，危险删除按钮使用红色。
- 侧栏放在谱面右侧，与谱面视口共享剩余工作区高度，不跟随纸张内容滚动；顶部标签与底部操作区保持可见，表单中部滚动。
- 桌面侧栏初始宽度建议 460px；预览与指法表格在空间足够时并排，空间不足时上下排列。最终尺寸以真实页面验收为准。
- 首版默认显示侧栏与歌词标签，但 `draft = null`，不自动进入编辑。无选区显示“请先选择谱面中的一拍”；有选区显示目标摘要与“编辑当前拍”按钮。只有点击该按钮、主动切换标签且存在合法选区、或点击谱面已有文字时才创建编辑目标。
- 空态下普通点击或拖动谱面只更新选区和摘要，不自动加载草稿或抢输入焦点。主动从关闭状态打开侧栏时，有合法选区则加载当前标签对应草稿，无选区则保持空态。关闭后保留轻量“属性面板”入口；当前会话保留最后使用的标签，不持久化到乐谱或浏览器存储。
- 顶部原四按钮行删除，用侧栏标签和历史操作区替代；顶部已有全谱撤销/重做图标继续保留，便于侧栏关闭时操作。
- 点击谱面已有歌词、和弦名或指法图时，自动展开侧栏并进入对应标签与目标。

### 3.2 歌词标签

从上至下组织为：

1. 目标说明：小节与 Beat 序号，明确只编辑当前焦点拍。多拍选择进入编辑时仍按现有规则折叠为焦点拍。
2. 歌词设置：1–4 段选择、单行歌词输入、已有内容提示。
3. 连续录入提示：Enter 应用并下一拍；Shift+Enter 仅应用，包含休止拍，可跨小节与谱行。
4. 底部操作：删除歌词、取消、应用、应用并下一拍。

保持现有单行、非空、最多 64 个 Unicode 字符的校验；不增加整首粘贴、自动拆词或歌词对拍。选段、换拍、换标签和关闭侧栏统一处理未应用草稿。

### 3.3 和弦标签

以下为已交付首版行为。后续按用户要求移除逐和弦显示格式，改用[和弦显示格式全局开关方案](./20261010_和弦显示格式全局开关方案.md)，该增量已实现，验证见[增量实施验收](./20261010_歌词与和弦显示优化实施验收.md)。

参考图片，划分以下区域：

| 区域     | 字段与行为                                                                               |
| -------- | ---------------------------------------------------------------------------------------- |
| 基本设置 | 和弦名称、显示模式（仅名称 / 名称加指法图）、常用预设、起始品位；双列表单，窄时改为单列  |
| 指法设置 | 六弦“弦 / 品位 / 手指”表格；支持空弦、禁奏、绝对品位和未指定手指；无图时显示“创建指法图” |
| 和弦预览 | 显示草稿名称与共享核心指法图；非法图显示具体错误，不伪装成可提交结果                     |
| 横按设置 | 保留现有最多四条横按，品位、起弦、止弦、手指与新增/删除；默认展开，可折叠以节省空间      |
| 操作提示 | 名称与指法由用户确认；当前调弦不适用预设时禁用预设并解释原因                             |
| 底部操作 | 删除和弦、取消、应用                                                                     |

“清除指法图”仍仅在“仅名称”模式可用；“名称加指法图”必须保留合法图。切换为仅名称不会自动清空已有指法。起始品位只改变观察窗口，不自动转调。

图片中的下方常用和弦图卡、直接点击预览图改指法，本轮不新增；常用预设继续用选择框，实际编辑继续通过表格。优先交付完整侧栏与现有编辑能力，避免同时引入新的谱面区域及图形编辑手势。

### 3.4 撤销与重做

- 将侧栏按钮命名为“撤销”“重做”，相邻说明“作用于整个乐谱”，禁用状态复用 store 的 `canUndo/canRedo`。
- 歌词、和弦、音符、节奏等均进入同一历史；不暗示只撤销当前标签的内容。
- 输入框内 Ctrl/Cmd+Z 保留原生草稿撤销；点击侧栏或顶部历史按钮切换文档，并关闭未提交编辑目标，按既有规则提示草稿已取消。
- 历史切换后可以保留侧栏外壳与当前标签，但不得把旧草稿自动绑定到恢复后的选区；展示目标已结束状态，用户通过“编辑当前拍”或再次点击谱面进入编辑。

## 4. 交互与草稿规则

侧栏开关与“正在编辑一个目标”分开建模。面板可见但没有目标时，不应暂停谱面工具；仅存在有效草稿目标时继续沿用 `musicTextEditing` 的保护行为。

| 动作                     | 首版行为                                                             |
| ------------------------ | -------------------------------------------------------------------- |
| 打开面板，无选区         | 展示空态与禁用提交，不改文档或自动选第一拍                           |
| 打开面板，有选区         | 加载当前标签对应的焦点 Beat，取消品位输入计时器，清理技巧焦点        |
| 点击已有歌词/和弦        | 加载对应实体与段号，保留稳定 Beat 引用                               |
| 点击另一拍、切段、切标签 | 干净草稿直接切换；dirty 草稿先显示应用后继续 / 放弃后继续 / 继续编辑 |
| ×、取消、Esc             | 统一关闭请求；dirty 时先走草稿保护，继续编辑保持面板与原目标         |
| 应用                     | 成功后留在原目标并清除 dirty；失败保留草稿、焦点与错误               |
| 应用并下一拍             | 成功或 no-op 后前进并预填；失败不前进；到最后一拍保持面板并提示      |
| 删除                     | 删除当前实体，清空对应草稿，留在原 Beat，不跳下一拍                  |
| 外部文档替换、撤销、重做 | 结束草稿目标并清理 pending；保留侧栏可见性和标签，不提交旧草稿       |
| 重新排版或字体度量       | 不关闭草稿、不增加历史、不切目标                                     |

所有关闭入口（×、取消、Esc、顶部开关关闭）共用一条路径，避免绕过草稿保护。面板外谱面修改仍按当前规则暂停，不在本次顺带改变这一交互。侧栏内的数字、方向、删除键不触发 TAB 编辑；IME 组合状态、候选确认 Enter、多行粘贴守卫保留。

### 4.1 状态与控制器契约

- 父壳管理 `sidebarVisible`，侧栏管理 `activeKind`、`draft`、`pendingAction`、消息与 baseline 文档引用；`musicTextEditing` 只由 `draft !== null` 推导，不能由可见性推导。
- 保留现有控制器 `open(target)` 与 `move(target)`，补 `requestOpenCurrent()`、`requestClose()`；父壳的开关只发请求，不直接隐藏正在编辑的组件。侧栏常驻挂载，关闭仅隐藏，避免卸载绕过确认或丢失消息。
- `pendingAction` 用判别联合区分关闭、切目标、切标签。dirty 请求只登记待执行动作，不能提前改可见性、标签或选区；应用成功或放弃后再执行；继续编辑清除 pending。
- 无目标切标签只更新 `activeKind`；有合法选区则加载新标签目标。有草稿时切标签使用草稿原 Beat；点击已有歌词使用其实际 verse，普通进入歌词默认第 1 段。同一目标与同一标签重复点击不重载、不触发 dirty 确认。
- `activeKind` 与 `draft.target.kind` 始终一致。目标先在当前文档验证，失效时结束编辑并提示；外部文档引用改变时清空草稿和 pending，不用 revision 判断快照切换。
- 自身应用/删除继续用受控提交标记区分 store 同步通知，标记以 `try/finally` 清理；接受命令返回的实际文档后更新 baseline。失败与 no-op 同样清理标记，失败不执行 pending。
- 应用、下一拍、删除共用规范化草稿与 `initial` 生成路径；下一拍不得继续携带上一拍另一类型的值。删除失败明确显示领域错误，保留原草稿，不能只处理成功分支。

### 4.2 顶栏与焦点

当前 `editorToolbar` 整体设置 `inert={musicTextEditing}`，包含顶部撤销/重做。实施时拆成始终可访问的“全谱历史 + 属性开关”与编辑期间 inert 的“谱面修改工具”；排版密度与打印可放在独立展示工具组，不修改文档或清空文本草稿。不能直接移除整栏 inert，让节奏命令绕过保护。

打开新目标或歌词前进成功后才将焦点移到对应输入框；字段变化、折叠横按、消息更新、字体重测不触发重新 focus。用稳定回调与目标键控制 focus effect，不沿用当前依赖内联 `onClose` 的方式，避免父壳重渲染将焦点从指法控件拉回名称输入框。真正关闭返回可见的侧栏入口或谱面；仅结束编辑但保留侧栏时返回“编辑当前拍”按钮。

标签使用 tablist/tab/tabpanel 语义和关联 ID，键盘切换仍走同一保护；确认区放在侧栏固定可见区域，获得焦点并暂时限制其他侧栏操作，Esc 表示“继续编辑”。输入法与 paste 守卫覆盖表单、固定底部和确认区，组合输入期间不得执行提交或关闭；实际系统候选字操作仍需人工核验。

关闭后焦点返回谱面或面板入口；标签具有可读名称与选中状态，按钮和字段保持可键盘访问。切标签遵循草稿保护，不能只改变视觉标签而继续提交旧 kind 的命令。

## 5. 谱面尺寸、窄窗口与打印

- 打开侧栏只改变可用视口，不修改 `ILXMDocument`、`buildLayout` 的 A4 内容宽度、排版密度、SVG viewBox 或谱面字体大小。
- 谱面区域保持 `min-width: 0` 与内部横向滚动。A4 纸张保持现有 210mm 宽度；超宽谱面继续使用现有提示及滚动，不通过缩放把内容塞进剩余宽度。
- 现有 focus caret 的滚动 effect 在 `musicTextEditing` 时直接返回，不能原样复用。增加谱面视口 ref，按稳定目标键及视口大小协调可见性：将 caret 的屏幕 bounds 与该视口 bounds 比较，只调整该视口的 scrollLeft/scrollTop；必要时合并文字命中 bounds，过大的目标以 Beat 锚点可见为准。
- 字段每次输入不触发滚动；目标变更、面板展开/关闭、容器 resize 与影响目标位置的重排完成后才重新检查。ResizeObserver 只用于视口协调，不反向修改核心排版宽度；聚焦输入框使用 `preventScroll`，避免滚动侧栏或外层页面。
- 侧栏宽 460px，A4 纸张约 794px，加上现有谱面视口左右 48px padding，总需求约 1302px。因此断点按工作区实际宽度设为 1320px，使用容器查询，不按浏览器整窗宽度误判。
- 工作区宽度小于 1320px 时采用上下布局：上方谱面保留独立滚动，下方属性面板建议占工作区高度 45%、最多 440px；不添加覆盖谱面的遮罩。窄窗口可继续点选目标拍，表单、顶部标签和底部操作区仍可访问；表格与预览按可用宽度并排或上下排列。尺寸切换不卸载组件、不重置草稿或滚动位置。
- 新工作区设置 `flex: 1; min-height: 0; min-width: 0`，侧栏表单中部同样 `min-height: 0; overflow: auto`。移走音乐文本表单后，顶区只保留工具、提示和错误，避免 body 的 `overflow: hidden` 裁掉操作区。200% 缩放时核对剩余高度，必要时让顶部工具区域受限滚动。
- 窄窗口适配保证桌面窗口缩小时可完成现有操作，不作为移动端编辑器交付承诺。
- print CSS 显式隐藏侧栏、开关及草稿确认区域，并把工作区恢复 block/自动高度，解除分栏、行高、容器及内部滚动限制，防止空白侧栏占用纸张。现有文字、指法图和正文打印规则保持，并检查 `app/page.module.scss` 与 `app/globals.scss` 的外层打印约束。

## 8. 验收标准

### 8.1 行为与回归

- 原顶部音乐文本按钮行移入侧栏；顶部常用谱面工具仍可使用，歌词/和弦功能无缺失。
- 无选区空态、编辑当前拍、点击已有文字、切段、切标签、关闭和重新打开都具有确定行为。
- dirty 切换与关闭的三种选择均正确，失败不丢草稿；统一检查 ×、取消、Esc、顶部开关。同一目标重复点击不误触确认，pending 期间不提前切标签或选区。
- 应用和删除各自只产生现有命令历史，no-op 不入历史；输入原生撤销与全谱历史语义保持。
- 歌词连续录入含休止、跨小节与跨谱行，目标可见且已有内容预填；输入数字不会修改品位。
- 和弦纯名称、名称加图、预设、自定义六弦、空弦/禁奏、F/Bm 横按、高把位、清图限制和错误反馈保持。
- 外部文档变更、目标失效、撤销/重做不会把旧草稿写到新文档；面板可见但无编辑目标时不锁住谱面。
- 初始默认展开不创建草稿；空态选区变化不抢焦点。编辑期间顶部和侧栏历史、属性开关可访问，谱面修改工具继续暂停。
- 指法表格、段号、横按控件编辑过程中父壳重渲染不抢焦点；确认区与固定底部键盘、IME 守卫有效。

### 8.2 真实页面与工程检查

- 桌面 1440×1000 与 1920×1080 核对两栏、A4 宽度、表格与预览、底部操作区、滚动范围。
- 窄窗口 1100×800 核对上下布局、草稿确认、换拍可达、关闭焦点与滚动恢复；1320px 断点前后不丢草稿，200% 页面缩放下关键字段及操作可访问。
- 用混合谱例检查 compact/comfortable，打开和关闭面板前后核心谱面几何与字号保持，选区及点击命中正确。
- 核对原始多行粘贴拒绝、IME 守卫与键盘隔离；模拟事件不能替代真实系统输入法候选字人工检查。
- print 媒体样式核对侧栏完全隐藏、正文无空白占位；实际系统打印预览单独记录，无法验证时标为待验收。
- 执行相关网站测试、`pnpm type-check`、`pnpm lint`、`pnpm build` 与 `git diff --check`；若实际修改波及公共核心，再补相应核心回归。
- 最终提供歌词、和弦、dirty 切换确认和窄窗口截图，记录浏览器、视口与验证边界。

上述标准用于实施验证；已实现能力、实际执行的检查和待人工验收项分别见[实施验收记录](./20261010_音乐文本属性侧边栏实施验收.md)。

## 12. 起始品位说明与提示文案

2026-10-10 用户询问“起始品位”的用途。经核心实现核对：指法图固定显示五个品格，起始品位决定第一格对应吉他上的第几品。设置 1 显示第 1–5 品；设置 5 显示第 5–9 品，用于展示高把位指法。值大于 1 时图左侧标注起始品位，顶部不再绘制粗琴枕线。

六弦表格与横按中填写的仍是实际绝对品位；起始品位不移动这些数值、不改变音高，也不会自动转调。例如第 7 品在起始品位 5 的图中落在第 3 格；若保留原第 1–3 品指法而把起始品位改为 5，按弦点将超出图格，当前实现会提示错误并禁用应用。空弦与禁奏标记仍在图上方。

字段旁已增加辅助文案：“指法图从第几品开始显示，共显示 5 个品格；不会改变实际按弦品位。”现有底部“起始品位只调整观察窗口，不会自动转调”提示仍可保留。本次增加说明文字，字段仍不自动转调。
