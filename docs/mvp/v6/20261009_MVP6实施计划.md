# MVP v6 实施计划

> 日期：2026-10-09。状态：待审查，仅定义实施步骤，不代表功能已实现。
> 本计划遵循 [音乐文本技术方案](./20261009_MVP6音乐文本技术方案.md)。若实施发现契约冲突，先回写设计并确认实质范围变化，不在页面临时绕过领域规则。

## 1. 执行要求

- 用户审查通过技术方案后执行代码修改；本轮仅建立方案文档。
- 优先 TypeScript、ES6+、纯领域函数、React 函数式写法与 Hooks。
- 函数、关键算法、容量保护、几何约束和草稿生命周期补充中文注释，解释业务原因。
- core 不依赖 React、Zustand 或浏览器；页面不直接修改 `ILXMDocument`。
- 每个切片保持可构建，新增字段、构造器、fixture 和导出在同一切片协调。
- 验证聚焦该切片变化；最后集中全量回归。缓存命中、实际执行、浏览器检查分别记录。
- 不按猜测给工期；基线构建完成、布局混合样例通过后再评估剩余工作量。

## 2. Step 0：固定基线与确认执行环境

### 工作

1. 记录当前分支、commit、未提交文件清单，确认已有 v5/v5.1 工作的归属；建议用户认可后形成基线提交，不自动清理或回滚现有改动。
2. 保留独立 v5 与 v5.1 fixture、固定桌面截图；记录无音乐文本的 layout 测试基线。
3. 复核 `pnpm test`、`pnpm type-check`、`pnpm lint`、`pnpm build`。
4. 调查上次实时构建停留在 Next.js 编译阶段的原因。若为环境问题，记录日志与运行方式；不要通过删检查或更改业务逻辑伪造通过。
5. 记录实际打印预览遗留项及 v6 的明确验收边界。

### 退出条件

基线可追溯；开发/测试命令可运行。正式构建仍无法确认时，可以推进独立 core 切片，但网站构建验收保持未完成，不能标记 v6 完成。

## 3. Step 1：Schema 3、文本与和弦图模型

### 修改位置

- `core/constants.ts`、`core/types.ts`、`core/schema.ts`。
- `core/music-text.ts`、`core/chord-diagram.ts`。
- `core/semantic-validation.ts`、`core/id-factory.ts`、`core/loader.ts`。
- `src/index.ts`、全部 example、测试 fixture 与空白小节构造器。

### 工作

- 加入 `lyrics`、新 Beat 锚点 chordSymbols、1–4 verse、局部 chord 快照。
- 加入歌词 ID 工厂；实体注册、全局唯一、数组顺序、重复目标与本小节 Beat 引用校验。
- 实现纯文本标准化、Unicode 长度及形状校验；图形字段与横按的跨字段合法性复用一个 Module。
- 明确 schema 2 拒绝信息，不在 loader 填字段或猜测旧和弦目标。
- 内置旧和弦 fixture 根据已知 Beat/名称显式转换；首个样例包含纯名称和实际指法图。
- 更新 time-signature 旧 tick 字段守卫，使其至少能在新模型下正确判断锚点 Beat 的容量；完整兼容在 Step 3 收敛。

### 验证与退出条件

- 合法 schema 3 加载成功，schema 2/缺 lyrics/多余字段明确失败。
- 中文、组合字符、空白、长度边界、ID/重复目标/乱序/缺 Beat 有精确错误路径。
- 六弦顺序、F/Bm 横按、高把位、finger 冲突、全禁奏图等校验通过或按预期拒绝。
- 全部既有 fixture 同步，TypeScript 和核心测试通过；这一阶段不引入不可用页面入口。

## 4. Step 2：音乐文本领域命令与历史

### 修改位置

- 新增 `core/music-text-commands.ts`，接入 `core/commands.ts`。
- 新增 `tests/core/music-text-commands.test.ts`、`chord-diagram.test.ts`。
- website store 聚焦历史测试；页面暂不增加工具。

### 工作

- 实现 `lyric.set/remove`、`chordSymbol.set/remove`。
- set 使用规范化候选完整值，覆盖保留 ID，新建由局部 factory 分配。
- 明确纯名称/名称加图切换、保留隐藏图与显式清除图的行为。
- 按时间/verse 排序；失败无部分更改，成功一次 revision，no-op 原文档引用。
- 复用现有 store execute，历史不包含任何表单中间值。

### 验证与退出条件

通过核心命令 Interface 完成新增/覆盖/删除/模式切换，检查输入不可变、ID、revision、failure/no-op 和 undo/redo。存储快照不依赖预设库；JSON 重载等价。

## 5. Step 3：时间与复制生命周期兼容

### 修改位置

- `core/measure-timeline.ts`、`rhythm-change.ts`、`time-signature-change.ts`。
- `core/tuplet-commands.ts`、`commands.ts` 的 insert/copy/remove。
- 相应 rhythm/time-signature/tuplet/measure 命令测试。

### 工作

- 在统一 `getFixedPrefixLength/reconcileMeasureTimeline` 内合并文本锚点保护集合，调用方只提供额外保护目标。
- 带文本 rest 不是容量缓冲；其前方固定前缀完整保留，后方无文本尾部 rest 才可重建。
- 全休止按拍号单位重建仅适用于无 group 且无文本的小节。
- 保留现有 DP 压缩策略，锚点身份保护与书写时值不可压缩不得混为一谈。
- 复制时完整建立 Beat map，再重建歌词/和弦 ID 和引用；图快照按值复制，包括 strings/barres。
- 删除小节保留现有技巧级联；插入小节文本数组为空。

### 验证与退出条件

1. 三连音的第二拍歌词从 tick 480 随原 Beat 移至 320。
2. 普通 Beat 时值扩张触发后续 DP 压缩，原带文本 Beat/文本 ID 保留。
3. 带文本的尾部 rest 在 tuplet remove/ratio 和拍号改变中不消失。
4. 全休止但有歌词/和弦时，同容量切换不重建其 Beat；无文本样例保持旧行为。
5. 缩容截断带文本 Beat 时单小节/多小节均原子失败；不是先清文本再提交。
6. 复制副本只引用新 Beat，修改副本指法不改原小节；撤销重做完整恢复。

此步骤是接入页面之前的硬退出条件。

## 6. Step 4：字体测量与宽度摘要

### 修改位置

- `layout/music-text-layout.ts`、`layout/layout-types.ts`、`layout/layout-constants.ts`。
- `layout/measure-spacing.ts`、`measure-layout.ts`、`system-layout.ts`。
- 网站新增 `music-text-metrics.ts` 与加载/缓存 Hook，位置建议在 EditorShell 附近。

### 工作

- 核心收集去重测量请求，定义度量快照；Node 估算与浏览器真实度量明确区分。
- 网站在字体就绪后离屏 SVG 测量，缓存键含文字、字体参数和字体代次；清理离屏节点和异步过期请求。
- 整合左右 bearing、文字/图的外缘、相邻列间距及首末列固定 inset。
- 断行摘要与正式 spacing 使用同一文本宽度计划；system flexible width 排除新增固定 inset。
- 暂时不展示全部页面编辑器，先用真实 schema 3 fixture 验证宽度计划。

### 验证与退出条件

- 首拍居中文字不侵入行头/拍号，末拍不跨小节净空。
- 密集中英文、名称比图宽/图比名称宽、不同段歌词使用正确的最大投影要求。
- 无文本 spacing 与原 baseline 深相等；文本与 tuplet 的组合只扩张不压缩。
- 改变 metrics/density/systemWidth 不修改文档和历史，同一快照布局确定。
- 页面字体实际 bounds 可被声明 bounds 包含，不只测试字符数估算。

## 7. Step 5：和弦图、歌词带与系统统一高度

### 修改位置

- `layout/chord-diagram-layout.ts`、`music-text-layout.ts`、`system-content-layout.ts`。
- 现有 `technique-layout.ts` 平移/扩高逻辑、`layout/index.ts`。
- `layout-types.ts`、`hit-test.ts`。
- 新增 `tests/layout/music-text-layout.test.ts`、`chord-diagram-layout.test.ts`。

### 工作

- 输出和弦名称、图格、圆点、横按胶囊、finger/品位标签的最终图元。
- 和弦带使用 system 内名称统一 baseline，位于现有技巧最高 bounds 上方。
- 歌词带使用整条 system 的 rhythm/tuplet 最低 bounds、固定 verse 排列和段号。
- 所有最终图元与命中 bounds 集中平移，最后才建立 hitIndex。
- 文本 bounds 与实体目标写入布局，文本命中优先级明确。
- 超宽布局仍独占一行，文档尺寸由最终几何真实汇总。

### 验证与退出条件

混合 F 横按图、bend、Let Ring、三连音和四段歌词后，所有正文被 measure/system/document bounds 包含；不同小节同段歌词 baseline 一致，下一行不交叠。改变 systemWidth 后命中仍指向原实体。无文本最终 layout 深相等回归通过。

## 8. Step 6：编辑面板、Store、预设和连续录入

### 修改位置

- 新增 `LyricsEditor.tsx`、`ChordEditor.tsx`、`MusicTextToolbar.tsx`、`MusicTextLayer.tsx`。
- 新增经校验的 `chord-presets.ts`；预设无需写入 core 文档定义池。
- `EditorShell/index.tsx`、`editor-interaction.ts`、`index.module.scss`。
- store 的临时目标/关闭逻辑与 `apps/website/tests/music-text-editor.test.ts`。

### 工作

- JSX 仅消费最终 layout；图编辑预览复用核心图形函数。
- 歌词 1–4 段、目标提示、应用/下一拍/删除/取消；跨小节/system、rest 和末拍行为完整。
- 和弦纯名/图模式、至少首批十四个常用预设、手动六弦和横按；每个模板入库前校验。
- 草稿未提交的切换确认、revision 变化处理、目标消失关闭，取消未完成品位定时器。
- 输入框原生键盘/撤销、composition 守卫、页面工具焦点和谱面 selection 不冲突。
- 最终 svgWidth 与 viewBox 超宽处理，横向滚动命中仍使用已有坐标变换。

### 验证与退出条件

至少完成一个真实歌词连续录入和一个预设转自定义和弦编辑流程。每次应用一条历史；失败不推进到下一拍，no-op 可推进但不入历史。按取消、Esc、文档撤销/重做后临时状态正确，数字/Delete/R 不写入 TAB。

## 9. Step 7：正式谱例与全量验收

### 工作

- 新增 `example-mvp6.json.ts`，通过 loader 校验后作为 v6 页面示例，旧版本示例独立保留。
- 八小节混合谱例、极端密集和超宽 fixture 按技术方案登记。
- 无缓存执行核心与网站测试；完整运行类型、Lint、build 与 diff 检查。
- 固定桌面 1440×1000，comfortable/compact 截图，记录文字实际 bounds、编辑/历史/节奏变化操作。
- 实际系统打印预览人工确认；无法检查时明确 pending，不能以打印 CSS 代替系统验收。
- 更新路线图、v6 README、方案中的实际字段/错误码，新增实际验收记录。

```bash
pnpm test
pnpm type-check

# 最终验证至少一次真实执行，不只回放缓存测试日志。
```

### 退出条件

技术方案第 7.4 节完成定义全部满足。实时构建、真实字体与浏览器交互未通过时，不将 v6 标记为完成；打印预览若仍 pending，应明确区分工程完成和打印验收未完成。
