# MVP v6 音乐文本技术方案

> 日期：2026-10-09。状态：已审查并获用户授权实施，功能已实现；最终证据与人工验证边界见 [实施验收记录](./20261009_MVP6实施验收.md)。
> 适用范围：`packages/lxm-editor` 与 `apps/website`。实施步骤见 [实施计划](./20261009_MVP6实施计划.md)。
> 本次复审结论与修订依据见 [可落地性审查](./20261009_MVP6方案可落地性审查.md)。

## 1. 目标与执行基线

让用户能够在真实 TAB 谱面上添加、修改、删除歌词与和弦，选择或编辑吉他指法图；所有内容跟随节奏、自动断行和撤销历史，并可以由完整 LXM JSON 恢复。

现有核心已具备稳定 Beat/Note ID、实际时长计算、小节时间协调、连音组、技巧几何、自动断行、命中索引及原子命令；网站具备 TAB 选区、品位输入和历史。v6 复用这些能力，不建立第二份乐谱数据。

本次准备检查得到以下事实：

- v5.1 的 269 项核心测试与 20 项网站测试在禁用缓存后通过；类型、Lint 和 diff 检查通过。
- 生产构建缓存检查通过；实时强制构建停留在 Next.js 编译阶段并被中止，不能记为本轮实时构建通过。
- 首次准备检查时存在较多未提交的 v5/v5.1 改动。2026-10-09 本次复审时工作区已干净，HEAD 为 `25b289f`；实施前仍需重新记录准确基线，不再把旧未提交状态当成当前事实。
- 实际系统打印预览仍为人工待验收项。v6 不把旧记录中的打印尝试当作通过证据。
- `chordSymbols` 当前仅含 `id/tick/chordDefinitionId/display`；没有和弦定义库、编辑命令或图形布局。`display` 仅支持 `nameAndDiagram`。
- 连音组命令不移动现有和弦绝对 tick。歌词宽度与和弦宽度 interface 尚未接入实际 spacing。

因此，v6 是跨模型、领域命令、布局和交互的复杂需求；本方案审查通过后才实施功能。

## 2. 首版交付与产品规则

### 2.1 必须交付

| 能力           | 首版行为                                                             |
| -------------- | -------------------------------------------------------------------- |
| 歌词           | 1–4 段固定编号，每段每 Beat 一项文本；新增、修改、删除、逐拍连续录入 |
| 中文与英文输入 | 中文短句/字、英文词或音节、普通标点；保留段内空格，不自动拆词        |
| 和弦名称       | 自由填写名称；同 Beat 最多一项和弦，可显示纯名称或名称加图           |
| 和弦图         | 常用预设、六弦手动指法、空弦、禁奏、手指编号、起始品位、横按         |
| 编辑恢复       | 明确提交/取消、失败保留草稿、每次提交一条历史、撤销重做              |
| 时间兼容       | 时值、连音组和拍号变化不丢失文本锚点；复制小节重建文本引用           |
| 排版           | 文本宽度进入断行，和弦/技巧联合上方布局，歌词在连音括号下方          |
| 数据恢复       | JSON 序列化后经正式 loader 重新加载，得到等价数据和布局              |

按阶段实施，但全部上述能力完成后才将 MVP v6 标记为完成。

### 2.2 首版不扩展的能力

- 歌词跨 Beat 延长线、自动音节连字符、跨行歌词连线，以及自动歌词分词/批量对拍。
- 与现有 Beat 无关的任意 tick 插入、一个 Beat 的多处时间偏移或多声部歌词。
- 和弦自动识别、和声正确性判定、自动转调、自动生成指法、指法可演奏性评分。
- 跨乐谱共享可编辑和弦库、全谱联动替换和弦、拖动文字改变锚点。
- 保存文件界面、导出格式、打印分页、移动端、多轨编辑与播放，保持后续版本归属。

歌词首版提供足够完成按拍对齐歌词的闭环。用户可输入普通连字符作为文字，但它不会自动铺满两个音节之间的距离；工具说明应明确这一点。延长线和自动音节连接需要额外的区间模型，不能用字符 `_` 或重复文本冒充已实现能力。

### 2.3 使用流程

1. 选择目标 Beat，可为 notes、空 notes 或 rest；弦号不影响文本目标。
2. 点击“歌词”或“和弦”打开编辑面板。矩形多 Beat 选择使用当前 focus 的 Beat，并明确显示“仅编辑当前焦点拍”，不隐式批量覆盖。
3. 编辑后点击“应用”；歌词另有“应用并下一拍”。干净草稿可直接取消；有改动时取消或 Esc 先执行第 6.3 节的草稿保护流程。
4. 点击已存在的文字/和弦图可打开对应面板并恢复 Beat 选区；直接“删除”走单个领域命令。
5. 节奏编辑后文本仍属于原 Beat；删除小节同时删除该小节文本；复制小节得到独立文本副本。

## 3. 数据模型：稳定锚点与局部快照

### 3.1 核心决策

- 歌词和和弦均嵌套在所属 measure，引用该小节内稳定 `beatId`。
- 不在文本实体保存 tick；需要时间信息时从 Beat 和统一实际时长 Module 获取。
- 一个 Beat 最多一个和弦；同 Beat 同 verse 最多一项歌词。
- 和弦定义使用值对象快照嵌入标记，不再依赖尚不存在的 `chordDefinitionId` 定义池。
- 页面预设只是创建草稿的模板，提交后文档自足；预设更新不会改变已有谱面。
- 所有可编辑实体拥有全局唯一 ID；diagram、string、barre 为父实体内的值对象，不单独分配 ID。

### 3.2 建议类型

以下为新增/替换字段的契约，既有字段省略。代码片段为方案示意，不是实现代码。

```ts
export type ILXMLyricVerse = 1 | 2 | 3 | 4;

export interface ILXMLyric {
  id: string;
  /** 引用所属小节的真实 Beat，节奏修改后继续跟随它。 */
  beatId: string;
  verse: ILXMLyricVerse;
  text: string;
}

export interface ILXMChordString {
  /** 与现有 TAB 一致：1 为最高音弦，6 为最低音弦。 */
  string: 1 | 2 | 3 | 4 | 5 | 6;
  /** x 为禁奏，0 为空弦，正整数为绝对品位。 */
  fret: "x" | number;
  /** 未指定指法为 null，0 不作为手指编号。 */
  finger: 1 | 2 | 3 | 4 | null;
}

export interface ILXMChordBarre {
  fret: number;
  minString: number;
  maxString: number;
  finger: 1 | 2 | 3 | 4;
}

export interface ILXMChordDiagram {
  /** 图中最上方可按的绝对品位；1 表示从琴枕开始。 */
  startFret: number;
  /** 首版固定显示五个品格。 */
  fretCount: 5;
  /** 严格六项，按弦号 1 → 6 排列。 */
  strings: ILXMChordString[];
  barres: ILXMChordBarre[];
}

export interface ILXMChordSymbol {
  id: string;
  beatId: string;
  display: "name" | "nameAndDiagram";
  chord: {
    name: string;
    /** 纯名称可无图；隐藏已有图时允许保留快照。 */
    diagram: ILXMChordDiagram | null;
  };
}

export interface ILXMMeasure {
  // 既有字段保持，chordSymbols 使用新结构。
  chordSymbols: ILXMChordSymbol[];
  lyrics: ILXMLyric[];
}
```

不同时保存 `tick` 与 `beatId`，避免双写冲突。不引入全局可编辑和弦实体，避免“修改一个 Am 导致其他 Am 全部变化”。纯名称模式保留的 diagram 是可再次显示的指法草稿快照，依然必须合法。

### 3.3 文本标准化与长度

- 统一纯函数标准化：先检查原始输入的换行、制表符与控制字符，再执行 Unicode NFC 和去除首尾空白；内部普通空格保留。不能先 trim 掉非法换行再让校验通过。
- 禁止换行、制表符、控制字符和仅空白内容；普通 Unicode 文本可保存，以普通 SVG text 渲染，不解释为 HTML。
- 歌词每项最多 64 个 Unicode code point；和弦名最多 32 个 code point。长度算法统一，不能用 UTF-16 `length` 截断代理对。
- 空输入点击“应用”返回可读错误；删除使用明确按钮，避免擦掉草稿后误删已有内容。
- 标准化后与原值相同返回 no-op；不增加 revision、历史或替换文档。
- schema/语义校验要求持久化数据已标准化；loader 不静默修改文本。命令标准化用户输入后再校验。

长度限制用于控制输入规模，不替代实际宽度计算；超宽合法文字仍按真实 bounds 排版，不截断谱面文字。

### 3.4 和弦图校验

- `startFret` 为 1–20，五个品格覆盖 `startFret ... startFret + 4`，最高绝对品位为 24。
- 六根弦各出现一次，严格按 1–6 排列；fret 仅允许 `x`、0 或 1–24 整数。
- 正品位必须落在可见五格范围；0 与 `x` 绘于图上方，不受该范围约束。
- `x/0` 的 finger 必须为 null；正品位允许 null 或 1–4。
- 每图最多四条横按；每条 `1 ≤ minString < maxString ≤ 6`，品位位于可见范围。
- 六弦最终 fret 是声音事实来源；barre 只描述手指按法。横按区间内每根弦必须在该品位或更高，不得为 `x/0` 或更低品位。
- 在横按品位上的弦，finger 为 null 或与横按手指相同；更高品位若有 finger，不得使用同一横按手指。
- 同一个横按 finger 只能出现一次；同品位的重叠横按拒绝，避免重复胶囊线。
- 非横按手指如重复标注在多根弦，必须能由该 finger 的一条横按解释；不能仅凭重复 finger 自动生成横按。
- `nameAndDiagram` 必须有 diagram；全禁奏图拒绝，至少一根弦可发声。纯名称不要求推导音高或指法。

和弦名自由填写，例如 `F#m7/C#`。首版不检查名称与实际指法的和声等价性；界面提示“名称与指法由你确认”。这条限制不影响几何、引用和数据合法性检查。

### 3.5 Schema 与旧文档

- 当前 schema 2 升级为 3；新 measure 必填 `lyrics: []`，chordSymbols 替换旧结构。
- 本版本不新增 schema 2 → 3 自动迁移。旧绝对 tick 和弦不能可靠推断 Beat 关系，旧 `chordDefinitionId` 也没有完整定义数据，禁止猜测或丢弃后加载。
- loader 在 JSON 解析成功后先检查根字段 `schema/schemaVersion`。已识别 LXM 但版本不为 3 时先返回“不支持的文档版本，当前支持 3”；根形状/缺版本继续给字段错误，再按当前版本进行既有兼容与 strict schema 校验。避免旧版返回一串新字段缺失错误，失败不替换当前编辑结果。
- 既有 loader 的技巧弦范围兼容处理按原范围保留，不扩展为文本迁移。
- 所有内置 examples 和测试 fixture 同步到 schema 3；有旧和弦的样例按已知业务含义显式转换，补齐真实名称/图和 Beat 引用；无法确认的样例先阻断该切片，不默默清空数据。
- v6 仍提供正式 JSON round-trip 测试；文件保存 UI 和通用迁移工具属于后续版本。

## 4. 领域命令与时间协调

### 4.1 命令 Interface

沿用现有 `trackId` 命令基础字段，核心负责目标定位、ID 分配、不可变更新和最终校验。

```ts
type MusicTextCommand =
  | {
      type: "lyric.set";
      trackId: string;
      measureId: string;
      beatId: string;
      verse: ILXMLyricVerse;
      text: string;
    }
  | {
      type: "lyric.remove";
      trackId: string;
      measureId: string;
      lyricId: string;
    }
  | {
      type: "chordSymbol.set";
      trackId: string;
      measureId: string;
      beatId: string;
      display: ILXMChordSymbol["display"];
      chord: ILXMChordSymbol["chord"];
    }
  | {
      type: "chordSymbol.remove";
      trackId: string;
      measureId: string;
      chordSymbolId: string;
    };
```

- set 按 `(beatId, verse)` 或 `beatId` 查找已有实体，修改保留 ID，新增分配 ID。
- set 使用完整候选值，不做难以区分“省略/null/清空”的部分 patch。
- 同值返回原文档及 `changed:false`；remove 的实体不存在时返回明确 not-found，不伪造成功。
- 一个命令最多增加一次 revision；schema 与语义校验成功后才提交。失败、no-op 不入历史。
- 持久化数组按 Beat 时间顺序排列，歌词同 Beat 内按 verse 1–4 排列。校验拒绝乱序和重复项。
- 修改 display 为 name 不丢弃已有 diagram；显式“清除指法图”提交 diagram:null，仅 name 模式允许。
- set 在校验/同值比较后按值复制输入的 chord、diagram、strings、barres，不让 UI 草稿或调用方命令对象与历史文档共享可变引用；no-op 保持既有文档引用。测试提交后修改原命令 payload，不得改变已提交谱面。

建议错误码：`LYRIC_NOT_FOUND`、`CHORD_SYMBOL_NOT_FOUND`、`INVALID_LYRIC_TEXT`、`INVALID_CHORD_NAME`、`INVALID_LYRIC_VERSE`、`INVALID_CHORD_DIAGRAM`、`MUSIC_TEXT_BEAT_NOT_FOUND`、`MUSIC_TEXT_ORDER_INVALID`，加上既有容量和目标错误。loader issue 指向具体字段路径；命令错误有中文原因，不统一折叠为“修改失败”。

### 4.2 引用保护应进入统一时间 Module

新增 `core/music-text.ts` 的纯计算 Interface：

```ts
/** 汇总必须保留稳定 ID 的歌词/和弦目标；不含 UI 选择。 */
export const collectMusicTextBeatIds = (
  measure: ILXMMeasure,
): ReadonlySet<string>;
```

`getFixedPrefixLength` 与 `reconcileMeasureTimeline` 内部合并文本锚点和命令显式保护目标，让所有调用方自动得到一致的尾部保护。不能只在新文本命令里保护，因为真正删除 Beat 的是既有节奏命令。

保护含义是“该 Beat 及固定前缀不能被容量休止重建吞掉”，不是固定其 tick。v6 不改变既有 `beat.setRhythm` 后续精确压缩策略：非连音 Beat 即使带文本仍可在既有 DP 中缩短，Beat ID 和文本关联保持，文本随新 tick 移动。工具说明继续提示节奏调整可能缩短后续 Beat；不得声称锚点受保护就保证书写时值不变。

### 4.3 既有命令兼容表

| 操作                            | v6 必须保持的规则                                                                      |
| ------------------------------- | -------------------------------------------------------------------------------------- |
| Note 输入/删除、notes/rest 转换 | 保留歌词、和弦；删除最后一个 Note 不删除文本                                           |
| 普通 Beat 时值变化              | 保留带文本 Beat ID；按既有实际时间重排/DP 策略移动文本；容量失败原子拒绝               |
| 连音组 set/remove/ratio         | 文本随原成员 Beat，所有带文本尾部 rest 受保护；不新建额外文本 tick                     |
| 同容量拍号切换                  | 无文本且无组的全休止小节沿用原重建规则；存在文本时保留 Beat 和文本 ID                  |
| 拍号扩容                        | 保留文本锚点，新增普通尾部休止                                                         |
| 拍号缩容                        | 只能移除无文本、未分组、未保护的尾部休止；无法容纳完整锚点 Beat 时原子失败             |
| 全休止小节改拍号                | 仅在无 tuplet 且无歌词/和弦时允许完整按单位拍重建                                      |
| 多小节拍号变化                  | 先规划全部候选，有一处文本锚点阻挡则全部不提交                                         |
| 插入小节                        | 新小节 `lyrics: []`、`chordSymbols: []`                                                |
| 复制小节                        | 重建 Measure/Beat/Note/tuplet/歌词/和弦 ID，文本 beatId 映射到副本；快照无共享可变引用 |
| 删除小节                        | 内嵌文本一起删除，既有技巧级联继续；面板目标失效时关闭并清理临时状态                   |
| 撤销/重做                       | 恢复完整文档、锚点和快照，关闭未提交文本草稿；选区按当前文档重新协调                   |

`time-signature-change.ts` 中基于绝对 `chordSymbols.tick` 的旧守卫改为稳定锚点保护与候选语义校验。不得保留旧字段检查，也不得先删除文本再让缩容成功。

领域错误增加 `MUSIC_TEXT_BLOCKS_TIME_SIGNATURE`：仅当“候选固定前缀超出容量，且带文本的 rest 确实阻止尾部截短”时返回，并定位小节/锚点。真实 notes 或 tuplet 即使去除文本仍超容时，保持既有容量错误，不把所有失败误报成歌词问题。可通过候选前缀中普通内容与文本保护的对照判定；只做诊断，不自动移除任何文本。

Schema 替换、全休止重建条件、复制引用重映射和统一尾部保护必须随模型切片一起改，确保新的合法文档不能被既有命令变成悬挂引用；后续兼容切片补齐组合行为与错误诊断，不能把基础正确性延期。

示例：三个八分 Beat 从普通节奏改为三连音时，歌词仍引用第二个 Beat，其起点从 tick 480 变为 320；在尾部 rest 上填写和弦后，缩容不再把该 rest 当作空白容量。错误信息应说明“该拍含歌词/和弦，缩小拍号会截断它，请先调整内容”。

## 5. 布局：先算宽度，再算最终几何

### 5.1 数据流与 Module 分工

```text
document + 字体度量快照 + density
  → 每小节音乐文本内容与宽度摘要
  → 合并节奏/连音/文本的列宽约束
  → system 断行与 assignedWidth
  → TAB / rhythm / tuplets / 文本基础几何
  → 和弦区与技巧二维避让、歌词区高度
  → system 统一平移与最终 bounds
  → 总尺寸 + hitIndex
  → React 只绘制图元
```

- `core/music-text.ts`：标准化、文本锚点、顺序与重复规则。
- `core/chord-diagram.ts`：指法/横按校验与值比较；不计算 SVG。
- `layout/music-text-layout.ts`：文本计划、宽度贡献和歌词最终几何。
- `layout/chord-diagram-layout.ts`：弦线、品格、圆点、空弦/禁奏、横按与标签的最终图元。
- `layout/system-content-layout.ts`：协调音乐文本与现有技巧布局的纵向空间、统一平移。

公开主入口仍是 `buildLayout(document, options)`。内部 Module 可以分工，但页面不接收中间列宽算法，也不生成图形修正坐标。

### 5.2 字体度量：浏览器真实宽度与纯核心兼容

现有系统字体和技巧标签采用保守估算。歌词含中文、英文和组合字符后，不能仅以 `text.length × 固定宽度` 声称不会碰撞。

采用两阶段度量：

1. 核心纯函数 `collectMusicTextMeasureRequests(document)` 返回去重的测量请求，包含规范化文字、固定字体 family/size/weight、稳定 key。请求覆盖歌词、和弦名、图的品位/手指与段号标签。
2. 网站 Adapter 在 `document.fonts.ready` 后用离屏 SVG text `getBBox()` 测量，产出只读快照 `{key → left/right/ascent/descent}`。同一文字、字体和字体加载代次共用缓存。
3. `buildLayout` 可接收 `musicTextMetrics` 快照；核心不能调用 DOM、Canvas、当前 viewport 或 `document.fonts`。同文档、同选项、同快照必须得到确定性结果。
4. 无浏览器度量的 Node 调用使用集中保守估算，不解释为已通过真实字体验收；最终几何标明度量来源 `measured/estimated`，方便验证与诊断。
5. 度量异常、缺项或过期时临时使用保守估算，并安排重测；字体就绪后原子替换完整布局。正在编辑的业务目标由 ID 保持，旧坐标不进入文档。

明确的度量 Interface 为：

```ts
export interface ILXMMusicTextMeasureRequest {
  key: string;
  text: string;
  fontFamily: string;
  fontSize: number;
  fontWeight: number;
  textAnchor: "middle" | "start" | "end";
}

export interface ILXMMusicTextMetric {
  /** 相对于 x=0、y=0 alphabetic baseline 的真实字形矩形。 */
  x: number;
  y: number;
  width: number;
  height: number;
}

export type ILXMMusicTextMetrics = Readonly<
  Record<string, ILXMMusicTextMetric>
>;
```

请求 key 使用文字和全部字体/anchor 参数的稳定序列编码，不用容易冲突的字符串拼接。字体代次由 Adapter 管理，快照中所有数值必须有限且 width/height 非负；非法项按缺项估算，不让 NaN 进入图形。

测量节点必须挂到文档中：离屏 SVG 采用 opacity:0、pointer-events:none 和 aria-hidden，不使用 display:none；text 的 x/y 为 0、baseline 为 alphabetic，字体与 anchor 显式设置。测量和正式渲染统一 `white-space: pre`，否则数据里保留的连续空格会被 SVG 折叠。

对该矩形统一计算 `leftExtent = max(0, -x)`、`rightExtent = max(0, x + width)`、`ascent = max(0, -y)`、`descent = max(0, y + height)`，然后加入四边净空。核心图形携带与请求一致的字体/anchor/baseline，不能只输出 fontSize 后依赖页面继承不同样式。

测量保留左右 bearing 和上下 bounds，而非只有 advance width；实际 bounds 四边额外加入至少 2 个逻辑单位的净空。字体参数由核心常量定义，React 与测量 Adapter 使用同一参数。文本度量只影响布局，不修改 revision/历史。

异步测量结果以测量请求集合和字体代次匹配当前输入；旧请求返回后不得覆盖新文档的度量。缓存仅存在于 UI Adapter，使用有上限的 LRU（建议最多 2048 个 key），避免连续编辑积累无限文本；core 每次布局按小节一次建立 Beat 索引，不逐项扫描整首谱面。算法无需为每个 Beat 分别等待字体或触发布局。

客户端首次渲染与服务端使用相同估算，挂载后再注入真实度量，避免 hydration 差异。字体 loadingdone/loadingerror 触发新代次，卸载时清理监听和离屏节点；同一失败代次只重试一次，持续失败保留估算并提示“字体度量未完成”，不做无限重新布局。只有纯临时 metrics 更新时，面板保持原目标和输入焦点。

浏览器验收必须比较实际 SVG bounds 与 layout bounds，发现低估先修度量或 padding。字体后加载、中文 fallback、缩放和 density 切换纳入回归；不得仅凭 Node 估算测试证明浏览器无碰撞。

### 5.3 横向宽度与文字对齐

现有 `BeatLayout.x` 是 TAB 节奏锚点，不是 slot 中点。v6 延续同一锚点：歌词、和弦名称及图的组合内容以该 X 为中心，名称不对齐到另一个独立坐标。

对每列汇总左右占用量 `leftExtent/rightExtent`：

- 名称和图在同一个和弦块内竖向排列，左右占用取二者最大值。
- 四段歌词分处不同 Y，左右占用取各段最大值，不相加。
- 和弦区与歌词区不同 Y，两类宽度取最大要求，允许横向投影复用。
- 节奏和 tuplet 继续通过既有规则贡献基础 width；文本约束只能增加宽度。

定义可实现的相邻列约束：

```text
anchor[i+1] - anchor[i]
  ≥ max(existingSpacing[i], rightExtent[i] + leftExtent[i+1] + textGap)

firstAnchor - measureLeft
  ≥ max(existingLeadingInset, firstLeftExtent + outerGap)

measureRight - lastAnchor
  ≥ max(existingTailInset, lastRightExtent + outerGap)
```

`existingLeadingInset` 包含 TAB 正文、小节左 padding、拍号、反复边界；增加的文本 inset 在摘要和正式 spacing 中一致使用。相邻列统一约束虽然对不同段的交错歌词稍保守，但简单、确定，不会让不同 lane 重叠。

单小节的所有新图形不得越过小节左右净空，因此相邻小节无需靠 `measureGap` 临时补救。第一/末列需要额外 inset；不能只增大 slot.width 而保持第一列 X 不动，否则首拍居中文字仍会侵入 TAB/拍号。

spacing 摘要在断行前计算并缓存；正式布局消费同一摘要。系统剩余宽度分配保持现有只扩张规则，额外空间只加到可伸展内容区，首尾固定净空保持。新增的固定 inset 不进入 flexible width 权重。

接入现有 slot 模型的具体算法如下。令 p 为单侧 padding，a=p+leadingWidth，基础列含 minWidth/idealWidth；前 n-1 个 slot.width 也是相邻锚点距离，最后一个 slot 仍承载原有节奏尾部空间：

1. 前 n-1 列分别令 minWidth 至少为 `rightExtent[i] + leftExtent[i+1] + textGap`，idealWidth 至少为新的 minWidth；没有文本要求时不额外加入 textGap。
2. `leftExtra = max(0, firstLeftExtent + outerGap - a)`；第一锚点为 `measure.x + a + leftExtra`。该公式约束的是文本不越过 measure 左净空；拍号在不同垂直区域，不额外声称文本水平投影必须完全绕开拍号。
3. `tailExtra = max(0, lastRightExtent + outerGap - (lastColumn.minWidth + p))`；保留最后列宽，新增尾部净空作为固定宽度。单列小节同时处理 leftExtra/tailExtra。
4. `fixedWidth = 2*p + leadingWidth + leftExtra + tailExtra`，contentWidth 仅为列 idealWidth 之和，intrinsicWidth 为两者之和。
5. 正式布局从新第一锚点累加列宽，系统 extraWidth 按列 idealWidth 原比例分配，最后列吸收 contentWidth 内的浮点残差；tailExtra 不能再次算入最后列宽。

例如 p=8、leadingWidth=0、两列原宽均为 20、两项文字左右各占 30、gap=6：leftExtra=28、第一列宽=66、tailExtra=8，最小可用总宽 138；锚点为 36/102，文本范围 6–66/72–132，小节左右净空与文字间距均为 6。此例作为布局契约测试，不用任意 CSS 位移修正结果。

无歌词、无和弦文档走原路径。新增空数组/bounds 等字段后不能要求整个对象与旧类型原始 deepEqual；回归对**既有布局字段投影**检查深相等，既有坐标、宽度、断行与技巧几何保持一致，并单独断言新文本数组为空。带文本文档的 minimum width 不低于原节奏 baseline，compact 模式也不压缩到碰撞。

### 5.4 纵向区划与技巧兼容

每条 system 的稳定显示顺序自上而下为：

1. **和弦带**：和弦名称，名称下方可选指法图。
2. **现有技巧与 TAB 正文**：保留自然 Note/Beat 锚点和既有二维避让策略。
3. **rhythm 区与 tuplet 括号**：保留 v5.1 语义。
4. **歌词带**：按 verse 1–4 自上而下排列。

先计算现有技巧在该 system 的真实最上方 visual bounds；和弦块整体放在其上方，保留集中净空，避免和弦图成为技巧路径中的新障碍。和弦名称在该 system 共用 baseline，图按固定图格尺寸排列，无图的名称仍与其他名称对齐。

歌词首 baseline 从整条 system 的 rhythm/tuplet 最低实际 bounds 推导，不逐小节单独决定，否则同一段歌词会上下跳动。每行分配到该 system 最大已用 verse 的行数；例如仅有第三段也保留第一、二段垂直位置，段号语义不会改变。每个有歌词的 system 左侧显示对应段号，位于核心给出的歌词行头位置，不覆盖首拍文本。

扩高由最终视觉 bounds 加 padding 推导，不能仅累加 lane 数。统一平移必须覆盖 TAB、拍号、小节线、Note、rests、beam、tuplet、技巧、歌词、和弦图与所有命中 bounds。最终 hitIndex 在所有平移完成后建立。

`system-content-layout.ts` 复用或整理现有 `translateMeasure/translateSystems`，把平移集中到一处；不增加“先平移技巧再由页面平移文本”的第二条链路。无文本场景保持现有技巧最终布局深相等。

对现有实现的落地顺序必须明确：

1. 将 `layoutTrackTechniques` 内的候选生成、naturalPlans 和 assignLanes 提取为内部 `planTrackTechniques`，返回尚未平移的 segments；保留原公开 Interface 的 wrapper，使已有直接调用测试不失效。
2. 新主流程先以相同 baseSystems 生成 technique plan，执行既有扫弦/琶音时值投影及品位可见性投影，再得到实际可见正文 bounds；投影依赖的原 Note anchors 仍从投影前完整布局建立。
3. 在同一临时坐标系规划和弦块与歌词带，汇总完整 system 顶/底；单个 system 计算一个 contentDy，并由一个核心平移 Module 应用到所有图元，之后顺序安排下一行。
4. 原 wrapper 与新主流程复用同一 technique planner、投影和几何平移函数；不复制技巧模板或重新计算第二遍技巧 lane。

measure.y 仍表示已有正文参考点，不能改成和弦顶部，否则 `LXM_STAFF_Y`、选择框和命中会漂移。新增 measure.visualBounds 汇总该小节自身正文、歌词和和弦，跨小节技巧与段号由 system.visualBounds 汇总；`system.y/height` 包住整行全部可见图元。保留原 TAB 粗筛 measureBounds 的参考坐标与弦号判断，musicTextBounds 独立建索引，不能用扩大 measure.height 来代替上方文本命中。验证 measure 图元在 measure.visualBounds 内、全部图元在 system/document bounds 内，不要求跨小节技巧塞进单个 measure.height。

新布局产物至少包括 measure 的 `lyrics[]/chordSymbols[]/visualBounds`、system 的 `lyricVerseLabels[]/visualBounds`、hitIndex 的 `musicTextBounds[]`；文字项包含实体/Beat/verse、最终图元和 visual/hit bounds，和弦项包含组合图元与组合 bounds。度量来源记录在文字项，空文本场景不注入另一套音乐语义。

### 5.5 和弦图几何

- 图从左到右为第 6 → 1 弦，与吉他常见指法图阅读方向一致；数据仍按 1 → 6 排列，映射只在核心图形 Module 实现一次。
- 五个品格由六条水平边线与六条竖弦线形成；正品位圆点位于相应品格中心。
- `startFret === 1` 显示较粗琴枕；高把位显示左侧起始品位标签，不显示琴枕。
- 空弦 `○`、禁奏 `×` 位于弦线上方；finger 在点内或按统一规则显示，不能依赖页面自行猜测位置。
- 横按用最终圆角胶囊图形；横按同品位已覆盖的点不重复绘制，高品位点正常显示。
- 输出 `lines/circles/roundedRects/texts/bounds`，网站直接渲染。指法编辑器预览消费相同核心几何；不另写一套图形算法。
- 预设只对标准吉他调弦启用；非标准调弦仍可手动绘图及填写名称，界面说明名称与指法需自行确认。预设切换不改变 TAB 音符。

建议首版几何常量：歌词/和弦名字号 13、finger 字号 7、弦间距 9、品格高度 12、按弦点半径 4、文字间净空 6、区带纵向净空 8，集中在 layout-constants。指法图左右留白需容纳起始品位标签，最终 bounds 由图元汇总而非写死总宽；两种 density 保持上述字号/图格大小，差异只在节奏间距。编辑预览可整体放大同一核心几何。实际浏览器读图检查若证明 finger 不清晰，可增大字号/圆点并回写常量，不在 JSX 写另一套布局。

### 5.6 超宽小节与固定 A4 容器

保持单个超宽小节独占一行、真实宽度、不缩小字号。当前 SVG `width:100%` 会把超宽 viewBox 缩回纸张，v6 必须处理这一实际容器问题：

- 正常谱面沿用固定 A4 逻辑内容宽度 733。
- 若 layout.width 超出 733，以对应比例增加 SVG 的实际显示宽度，工作区提供横向滚动；显示“当前小节超出纸张内容宽度”的提示。
- 使用既有 SVG 屏幕坐标转换完成命中，不能假定 1 CSS px 等于 1 逻辑单位。
- 正常小节保持无新增非预期横向滚动；超宽小节的滚动是明确行为。
- 打印保留正文图层并隐藏操作层；超宽文档明确提示尚不保证 A4 完整输出。分页/缩放打印留给后续版本，不虚报打印可交付。

## 6. 编辑交互与历史

### 6.1 歌词面板

- 段号选择 1–4、单行输入、目标小节/拍序提示，以及“应用”“应用并下一拍”“删除”“取消”。
- Enter 为应用并下一拍；Shift+Enter 为仅应用；Tab/Shift+Tab 保留表单焦点导航；Esc 走第 6.3 节取消/dirty 保护。输入法 composition 期间 Enter 不提交。
- 下一拍沿当前轨道 Beat 顺序，可跨小节/system，并包含 rest；在最后一拍提交成功后留在原目标并提示“已到最后一拍”。
- 没有内容可输入的下一拍会显示空草稿，已有文本则预填，并显示“将修改已有歌词”。不自动覆盖；用户仍需提交。
- 应用并下一拍：命令失败时不移动，成功或同值 no-op 后移动；历史只记录真正文档变更，目标导航不入历史。
- 不提供自动 split-and-fill。粘贴多行文本返回“每拍仅支持单行，请拆分后录入”，不悄悄丢掉后续行。

HTML 单行 input 可能在 change 前去掉换行，所以 paste 处理必须检查原始 clipboard text，非法多行时阻止默认粘贴并保留原草稿；命令仍检查原始字符串，不能仅依赖 UI。IME 除组合期间不提交，还要忽略结束组合所用的同一个 Enter，不把一次确认候选字误判为下一拍提交。

### 6.2 和弦面板

- 名称输入、显示模式、预设选择、六弦 fret/finger 表格、起始品位及最多四条横按编辑；展示实时核心预览与可读字段错误。
- 预设首批建议至少覆盖 C、D、E、G、A、Am、Dm、Em、F、Bm、D7、E7、A7、Cmaj7；每个模板必须有独立合法性与视觉测试，实施时由真实指法确认后登记。
- 用户自由修改某一弦时预设标签变为“自定义”，不重新自动覆盖名称或其他弦。
- 名称/图保存在同一次 set 命令中；图格、finger 与横按的中间编辑都是 UI 草稿，不逐个控件产生乐谱历史。
- 起始品位改变只改变观察窗口，不自动转调或修改绝对 fret；若现有按弦点超出窗口，禁止应用并提示应调整起始品位或指法。
- 切换纯名称模式保留图；另设“清除指法图”。取消整个面板恢复打开时状态。

### 6.3 草稿生命周期与快捷键

用判别联合保存临时 editor target，包含类型、trackId、measureId、beatId、歌词 verse 或实体 ID，以及打开时文档引用。草稿不存进 `ILXMDocument` 或历史。

- 文本面板持有焦点时，数字、R、Backspace/Delete、方向键和 Ctrl/Cmd+Z 保留输入框原生行为，不修改 TAB。
- 文本框内 Ctrl/Cmd+Z 撤销输入草稿；文档历史仍可用面板外的撤销/重做按钮。文档 undo/redo 后关闭草稿并清理目标。
- 打开面板前取消未提交品位计时器并清空品位草稿，避免迟到的定时命令写入其他位置。
- 草稿未提交时试图切换 Beat/段号/实体或关闭面板，提示“应用 / 放弃 / 继续编辑”；这是防止丢失用户输入的产品交互，不是实施审批。
- 文档因面板以外的执行、加载或历史切换发生变化时，不静默覆盖新文档：关闭面板并显示“谱面已变化，未应用草稿已取消”。dirty 时先阻止其他谱面修改并走应用/放弃/继续编辑；明确文档 undo/redo 属于用户主动切换文档，按上述关闭规则执行。
- 目标消失则关闭面板，错误提示清晰；普通字体重测或重新 layout 不改变 revision，不取消输入。

revision 不是 UI 变化来源标识：undo/redo 会恢复旧 revision，分支编辑也可能再次出现相同 revision。使用当前文档对象引用识别 snapshot 切换，由统一草稿控制器区分自身提交与外部切换，不能写成“revision 变化就关闭”的 effect。

| 草稿控制器事件             | 文档结果              | 面板行为                                                                            |
| -------------------------- | --------------------- | ----------------------------------------------------------------------------------- |
| 应用                       | changed:true 或 no-op | 同步更新 baseline 文档引用/规范化草稿，留在目标并清除 dirty                         |
| 应用并下一拍               | changed:true 或 no-op | 先接受自身提交结果，再从返回 document 找下一 Beat；切换目标并预填该段歌词，保持打开 |
| 应用失败                   | error                 | 不切目标、不改 baseline、不丢草稿                                                   |
| 删除成功                   | changed:true          | 清空该实体对应草稿并留在原 Beat，更新 baseline；不自动跳下一拍                      |
| 无 dirty 的取消/Esc        | 不执行命令            | 关闭并还原焦点                                                                      |
| 有 dirty 的取消/Esc/切目标 | 等待用户选择          | 应用成功后完成原动作；放弃后完成原动作；继续编辑则不切换                            |
| 外部 snapshot 切换         | 新文档引用            | 关闭草稿并提示；不将旧草稿应用到新目标                                              |

store.execute 当前同步返回 `result.document`；采用受控 own-commit token：调用 execute 前设置 token，同步订阅先缓冲通知，返回后先接受 result/更新目标，再核对通知中的 document 引用并清除 token；error/no-op 同样清除。与 result 不同的文档通知仍按外部切换处理。所有 UI 提交路径使用同一流程，并测试正常提交、no-op、undo 后分支与外部切换。dirty 判断对照原始字段值；非法新输入也算 dirty，不能因标准化失败而跳过保护。

面板打开目标时把当前范围折叠到 focus Beat 的合法 TAB 单元格。点击文本时优先保留同轨有效 focus 弦号，没有则使用第 1 弦；清空技巧 focus，不继承旧跨 Beat anchor。“仅编辑当前焦点拍”提示在折叠前展示，避免既有单拍工具被多拍选区持续禁用。

### 6.4 文本命中

扩展核心 hitIndex，返回带稳定实体/Beat ID 的 `musicTextBounds`，歌词 bounds 包含 verse，和弦 bounds 包含名称及图的组合区域。

命中优先级为“音乐文本 → 技巧 → TAB”。文本位于独立区域，优先级仍必须确定且有测试；同类稳定按显示顺序处理。页面对文本点击不启动 TAB 拖选，事件不继续冒泡成清空选区。

首版不支持拖动文字换拍。文本 focus 样式与命中净空不改变乐谱几何；打印隐藏 focus/hover、透明 hit rect 和面板。

所有面板字段有可读 label，错误关联具体字段，应用失败后焦点留在面板。用户可通过 TAB 选区与工具按钮完成全部编辑，不要求只能点击细小文字；和弦图提供包含名称和六弦指法的文本说明。关闭/取消面板后焦点返回对应工具或谱面，面板打开时不把浏览器 Tab 导航劫持为跨 Beat 操作。

## 7. 校验、测试与验收

### 7.1 自动化测试矩阵

| 层           | 必测场景                                                                                                |
| ------------ | ------------------------------------------------------------------------------------------------------- |
| Model/loader | schema 3、缺字段、旧版拒绝、文本标准化/Unicode 长度、重复 ID/目标、排序、JSON round-trip                |
| Diagram      | 空弦/禁奏、F/Bm 横按、高把位、图格越界、finger 矛盾、六弦顺序、全禁奏拒绝                               |
| Commands     | 新增/覆盖保留 ID/删除、纯名切图、同值 no-op、失败原子性、输入不可变、revision                           |
| 时间协调     | 后续 DP 压缩、尾部带文本 rest、全休止文本保护、三连音移动、拍号同容量/扩缩、多小节失败                  |
| 生命周期     | 小节复制重建引用与快照、删除级联、撤销重做、目标消失、原样例更新                                        |
| 横向布局     | 首末列、中间长词、中文与组合字、相邻小节、图/名宽度差异、两种 density、超宽独占行                       |

| 网站         | IME、提交/取消、下一拍、编辑已有项、草稿冲突、原生输入撤销、TAB 快捷键隔离、过期品位定时器              |

实际图形 tests 从 `buildLayout` 的 Interface 检查可见 bounds、稳定 ID 和命中，不只快照某个内部函数返回的同名字段。度量 Adapter 的浏览器检查与纯 Node 布局测试分别记录，不能互相替代。

目前网站测试使用 Node 环境，不能直接证明 DOM 焦点、clipboard 默认行为或真实输入法正确。草稿控制器、目标归一和提交事件归一用纯函数测试；getBBox、paste 拦截、focus、composition 与实际字体通过真实浏览器操作/事件序列检查。真实中文输入法候选确认再由人工录入检查，不以模拟 keydown 记录成真实 IME 通过。

### 7.2 正式混合谱例

新增独立 `example-mvp6.json.ts`，保留 v5 和 v5.1 示例。至少八小节、多 system，包含：

- 中文与英文歌词、空白 Beat、rest 上文本、1–4 段与仅第三段的行；
- 纯名称、名称加图、空弦/禁奏、F/Bm 横按、高把位、自定义名称；
- 三连音与五连音上的文本，技法包含 bend、hammer/pull、扫弦、P.M.、Let Ring；
- 首拍/末拍文字、拍号变化、反复小节线、两种密度。

另建超宽与极端密集测试 fixture，不让正式示例只展示极端情况。所有例子经过正式 loader 和语义校验。

### 7.3 浏览器验收

- 固定桌面视口 1440×1000，comfortable/compact 两套截图；连续录入跨小节与跨 system。
- 中文 IME 输入不提前提交，数字与删除键不改 TAB，草稿原生撤销与乐谱撤销语义分别正确。
- 点击名称、图及不同段歌词恢复正确对象；修改/删除/取消/失败后草稿行为符合方案。
- 修改连音比例、时值和拍号后文本与原 Beat 关系保持；尾部文本阻挡缩容的错误可读。
- 所有实际 SVG text bounds 被核心声明 bounds 包含；正文不同区域不存在非预期交叠，末行与相邻 system 不裁切。
- 超宽小节实际字号不被 SVG 100% 宽度偷偷缩小，横向滚动后命中正确。
- 字体加载前后重新度量、页面缩放、改变密度后目标与历史不变，控制台无非预期错误。
- print 样式保留文字/图/括号，隐藏所有交互层；实际系统打印预览必须单独人工确认。无法打开时记录待验收，不宣称通过。

### 7.4 完成定义

1. 全部首版能力均由真实模型、命令和 layout 支持，页面无持久化直接写入。
2. 所有成功命令输出合法 schema 3、引用无悬挂；失败/no-op 无部分提交和历史。
3. 完整 JSON 重载可恢复名称、图、歌词及稳定锚点，不依赖网站预设库。
4. 范围内测试、`pnpm test/type-check/lint/build` 和 `git diff --check` 通过；最终验收至少对核心测试和网站测试执行一次无缓存检查。
5. 固定桌面真实字体、混合谱例和关键交互验收有截图/操作记录；实际构建失败、打印未验收等限制单独记录。
6. 技术方案与实际 Interface 差异回写，遗留项列明，不用“以后优化”掩盖本版必交付功能。

## 8. 风险与明确取舍

| 风险                               | 决策与控制                                                   |
| ---------------------------------- | ------------------------------------------------------------ |
| 旧绝对 tick 无法可靠迁移           | schema 3 明确拒绝旧版，内部样例按已知目标显式转换            |
| 文本锚点被尾部休止重建删除         | 在统一 timeline Module 收集保护集合，全休止重建条件同步修改  |
| 不同字体导致估算碰撞               | 浏览器实际 bounds 度量快照，核心纯计算，真实字体验收         |
| 四段歌词使谱面过高                 | 段号固定、按当前 system 最大已用段数分配高度，不预留全谱四段 |
| 和弦图影响技巧锚点                 | 和弦带放在既有技巧最高 bounds 上方，统一一次平移和命中       |
| 自由命名与指法不匹配               | 不伪造和声判断，用户确认名称；几何和引用严格校验             |
| 文本面板吞谱面快捷键或迟到品位提交 | 输入焦点隔离、IME 守卫、取消计时器、明确草稿生命周期         |
| 超宽内容被固定纸张缩小             | 真实显示宽度与横向滚动；超宽打印限制可见                     |
| 新版改动与 v5/v5.1 混杂            | 实施前固定基线，按可构建切片推进，不覆盖已有工作             |

## 9. 审查后实施顺序

模型与校验 → 文本领域命令 → 既有时间/复制兼容 → 字体度量与宽度摘要 → 图形与联合高度 → Store/面板与命中 → 混合谱例/真实浏览器验收。

优先完成模型、引用与时间协调，之后才接页面；先通过真实混合图形的布局测试，再把截图作为验收证据。每阶段的修改文件、退出条件与操作步骤见 [实施计划](./20261009_MVP6实施计划.md)。
