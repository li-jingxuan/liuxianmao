# 主体内部透明修复技术方案 v1

## 1. 背景

Solid 模式当前先让 Seedream 生成动态键色图；当 `ENABLE_ONNX_MATTING=true` 时，系统将 U²-Net 系列模型输出的显著性概率图直接作为最终 Alpha。

真实素材诊断表明，该语义不可靠：U²-Net 输出的是显著性概率，不是光学 Alpha，也不是“所有非背景像素”的完整分割。大面积深色衣物、次要人物和非显著主体会获得较低概率，从而在最终图片中变成半透明甚至透明。

同一键色输入的差分结果如下：

| 指标 | U²-Net | U²-NetP |
| --- | ---: | ---: |
| 相对实际键色轮廓平均误差 | 0.259 | 0.150 |
| 主体漏判率 | 约 59%–61% | 约 31%–33% |
| 二值轮廓 IoU | 约 0.39–0.41 | 约 0.67–0.69 |
| Alpha 75 分位 | 74 | 234 |

同时发现，Seedream 请求键色为 `#FF00FF`，实际边缘主色分别约为 `#FC1B81`、`#FB267A`。实际背景均匀且可分离，但因为与请求值色差超过当前阈值，完整键色验证会拒绝它；ONNX 成功路径则完全跳过像素级键色验证，因此低质量 ONNX 蒙版仍被直接采用。

## 2. 目标

1. Solid 模式的普通不透明主体内部必须保持 `Alpha=255`。
2. 透明渐变只允许出现在主体轮廓的有限边缘带，不允许由主体颜色、明暗或显著性决定内部透明度。
3. 键色负责确定主体内部与外部背景，ONNX 仅作为边缘辅助，不再拥有最终 Alpha 的完整控制权。
4. Seedream 实际键色可以偏离请求值；只要实际背景满足均匀性、边缘连通性、面积和主体可分离性要求，就允许安全使用。
5. ONNX 蒙版相对键色轮廓漏掉主体时必须被拒绝或忽略，不能继续作为成功结果。
6. 保持 `ForegroundPreparer.prepare()` 的现有外部接口，融合细节集中在一个内部深模块中。

## 3. 非目标

1. 本次不支持玻璃、薄纱、烟雾、透明塑料等真实内部半透明材质；Seedream 键色输出按普通不透明插画处理。
2. 不训练或微调 U²-Net、U²-NetP。
3. 不通过简单 Gamma、全图阈值或逐图 min-max 拉伸来掩盖主体漏判。
4. 不在一次请求中同时加载多个 ONNX 模型进行模型竞赛。
5. 不改变 Keep、Simplify 两种背景模式。

## 4. 核心语义调整

### 4.1 Alpha 所有权

现状：

```text
Seedream 键色图 → ONNX 显著性蒙版 → 直接作为最终 Alpha
```

调整后：

```text
Seedream 键色图
  → 估计并验证实际键色
  → 生成边缘连通键色蒙版
  → 划分主体核心、背景、边缘带
  → ONNX 仅在边缘带内提供辅助
  → 主体核心强制不透明
  → 输出最终 Alpha
```

关键不变量：

- 主体核心：`Alpha=255`；
- 明确背景：`Alpha=0`；
- 边缘带：允许 `0 < Alpha < 255`；
- ONNX 不得降低键色已经确认的主体 Alpha；
- ONNX 不得在键色已经确认的背景区域增加 Alpha。

### 4.2 配置语义

保留现有配置：

```dotenv
ENABLE_ONNX_MATTING=true
FOREGROUND_MODEL_VARIANT=u2net
```

但 `ENABLE_ONNX_MATTING=true` 的语义调整为“启用 ONNX 边缘辅助”，不再表示“ONNX 独占最终 Alpha”。

`FOREGROUND_MODEL_VARIANT` 继续选择 `u2net` 或 `u2netp`，但模型差异只能影响边缘辅助和诊断指标，不能改变主体核心是否透明。

不新增允许恢复“ONNX 直接作为最终 Alpha”的开关，避免重新引入已确认的质量缺陷。

## 5. 模块设计

### 5.1 保持外部 seam 稳定

路由和转换流程继续只调用：

```python
ForegroundPreparer.prepare(...)
```

调用方不需要理解实际键色估计、形态学区域、模型召回率、边缘融合或 Alpha 不变量。

### 5.2 新增内部深模块

新增 `pindou.imaging.solid_alpha`，以一个小接口隐藏全部融合规则：

```python
def compose_solid_alpha(
    image: Image.Image,
    hint: BackgroundHint,
    onnx_mask: RawForegroundMask | None,
    *,
    policy: SolidAlphaPolicy,
) -> SolidAlphaOutcome:
    ...
```

该模块负责：

1. 实际键色估计与质量验证；
2. 边缘连通背景识别；
3. 键色软蒙版生成；
4. 主体核心、明确背景和边缘带划分；
5. ONNX 与键色轮廓的一致性评估；
6. 保护性 Alpha 合成；
7. 最终 Alpha 不变量验证；
8. 返回稳定失败原因和完整诊断指标。

`ForegroundPreparer` 只负责增强器调用、ONNX Adapter 调用、失败映射、日志和 Pillow 对象生命周期，不复制融合算法。

### 5.3 结果类型

```python
@dataclass(frozen=True, slots=True)
class SolidAlphaResult:
    mask: Image.Image
    confidence: float
    strategy: Literal["chroma_protected", "chroma_protected_onnx_edge"]
    metrics: dict[str, JSONValue]


@dataclass(frozen=True, slots=True)
class SolidAlphaFailure:
    reasons: tuple[str, ...]
    metrics: dict[str, JSONValue]


@dataclass(frozen=True, slots=True)
class SolidAlphaOutcome:
    result: SolidAlphaResult | None
    failure: SolidAlphaFailure | None
```

内部模块返回结果，不直接写日志、不抛 HTTP 异常；这样测试可以通过同一个接口验证完整行为。HTTP 错误和降级仍由 `ForegroundPreparer` 映射。

## 6. 实际键色验证

### 6.1 请求色与实际色分离

保留 `requested_key_delta_e76` 指标，但不再仅因实际色偏离请求色而拒绝键色图。请求色用于提示词契约和诊断，实际抠图使用从四边估计出的稳定背景主色。

实际键色必须同时满足：

1. 至少 3 条画布边具有足够的同色覆盖；
2. 总边缘覆盖率不低于策略阈值；
3. 近键色区域与画布边缘连通；
4. 背景面积处于合理范围；
5. 过渡色面积不超过阈值；
6. 去除边缘连通背景后仍存在非空主体；
7. 实际键色与主体核心代表色具有足够可分离度。

若上述条件成立，即使实际色与请求色偏差较大，也记录 `actual_key_drift_accepted=true` 并继续处理。

若边缘颜色不均匀、无法形成连通背景、几乎覆盖全图或与主体无法分离，则继续明确失败，不能因为 ONNX 有输出就绕过。

### 6.2 边缘连通约束

只移除与画布边缘连通的近键色区域。主体内部不与边缘连通的同色区域必须保持为主体，避免衣服、眼睛或装饰与键色相近时被全图替换。

## 7. 保护性 Alpha 合成算法

### 7.1 区域划分

从经过验证的键色软蒙版 `A_chroma` 生成三个互斥区域：

```text
明确背景 B：A_chroma <= 32
候选主体 F：A_chroma >= 224
主体核心 C：对 F 做小半径腐蚀后的区域
边缘带 E：除 C 和 B 之外的有限区域
```

腐蚀半径按图片短边缩放并限制在 `1–4 px`，避免高分辨率边缘过窄，也避免细小肢体被全部腐蚀。细小结构即使没有主体核心，仍保留键色软蒙版，不会被直接删除。

### 7.2 ONNX 一致性检查

将 ONNX 蒙版 `A_onnx` 与键色轮廓比较，至少计算：

- `onnx_subject_recall`：键色主体中被 ONNX 保留的比例；
- `onnx_chroma_iou`：二值轮廓 IoU；
- `onnx_false_positive_background`：明确背景上的误保留比例；
- `onnx_uncertain_coverage`：ONNX 不确定区域占比；
- `onnx_core_transparent_coverage`：主体核心内 ONNX 低 Alpha 比例。

建议首版阈值：

```text
min_onnx_subject_recall = 0.95
min_onnx_chroma_iou = 0.80
max_onnx_false_positive_background = 0.005
max_onnx_core_transparent_coverage = 0.01
```

阈值集中在版本化 `SolidAlphaPolicy`，请求端不能逐项覆盖。

任一关键指标不满足时，ONNX 边缘辅助被忽略，继续使用合格的键色蒙版完成 Solid，不把本次请求降级为 Simplify。

### 7.3 合成规则

若 ONNX 通过一致性检查：

```python
final_alpha[C] = 255
final_alpha[B] = 0
final_alpha[E] = maximum(A_chroma[E], A_onnx[E])
```

`maximum` 保证 ONNX 只能在边缘带补充主体信息，不能把键色已经保留的边缘变得更透明。明确背景仍固定为 0，防止 ONNX 把背景重新带回。

若 ONNX 未启用、不可用或一致性检查失败：

```python
final_alpha = A_chroma
final_alpha[C] = 255
final_alpha[B] = 0
```

### 7.4 最终不变量验证

合成完成后必须重新验证：

1. 主体核心中 `Alpha < 250` 的比例不超过 `0.1%`；
2. 明确背景中 `Alpha > 5` 的比例不超过 `0.5%`；
3. 主体核心不存在超过策略面积的大型透明连通区域；
4. 最终主体覆盖率、背景覆盖率处于合理范围；
5. 蒙版尺寸与增强图完全一致；
6. Alpha 数值有限且位于 `[0, 255]`。

违反不变量属于内部合成错误，不能输出图片。

## 8. 处理流程

### 8.1 ONNX 开启

```text
Seedream 键色图
  → 验证实际键色
  → 失败：按现有授权执行 Simplify 降级或返回 422
  → 成功：生成 A_chroma 与保护区域
  → 运行所选 ONNX 模型
  → 与键色轮廓比较
      → 合格：仅在边缘带辅助
      → 不合格：忽略 ONNX，记录原因
  → 核心强制不透明、背景强制透明
  → 输出 Solid
```

### 8.2 ONNX 关闭

```text
Seedream 键色图
  → 验证实际键色
  → 生成保护性键色 Alpha
  → 输出 Solid
```

### 8.3 键色验证失败

键色验证失败时，不再允许仅凭 U²-Net/U²-NetP 的全局面积指标直接输出 Solid，因为该模型无法证明所有主体均被保留。

- 调用方允许 `fallback_mode=simplify`：执行现有明确降级；
- 未允许降级：返回稳定 `422 AI_BACKGROUND_SEPARATION_FAILED`；
- 继续输出请求键色、实际键色、失败规则和 ONNX 诊断，便于定位。

- 默认不落盘完整蒙版，沿用现有原图、Seedream 图和最终前景图阶段备份；需要进一步排查时可从最终图片 Alpha 还原最终蒙版。

## 10. 错误与降级语义

| 场景 | 处理结果 |
| --- | --- |
| 键色有效，ONNX 有效 | `chroma_protected_onnx_edge`，保持 Solid |
| 键色有效，ONNX 漏主体 | 忽略 ONNX，`chroma_protected`，保持 Solid |
| 键色有效，ONNX 运行失败 | 传播现有模型运行错误，避免掩盖基础设施异常 |
| 键色无效，允许 Simplify | 明确降级并记录原因 |
| 键色无效，不允许 Simplify | 返回 422 |
| 最终 Alpha 不变量失败 | 返回稳定内部处理错误，不输出损坏图片 |

ONNX “质量不合格”与“运行失败”必须区分：前者可以安全忽略并使用键色，后者仍暴露为系统错误，便于发现模型文件、Runtime 或资源问题。

## 11. 测试方案

### 11.1 纯算法测试

使用小型确定性合成图覆盖：

1. 白色大主体加深色次要主体，ONNX 只识别白色主体，最终两者核心仍为 255；
2. 实际背景从请求 `#FF00FF` 偏移为稳定热粉色，其他条件满足时仍成功；
3. 背景不均匀或不足 3 条边时明确失败；
4. 主体内部存在与键色相近但不连接画布边缘的区域，不得被删除；
5. 多个不相连主体全部保留；
6. 细手指、牵引绳等窄结构不会因核心腐蚀而消失；
7. ONNX 召回率或 IoU 不足时被忽略；
8. 合格 ONNX 只改变边缘带，不改变核心和明确背景；
9. 输出尺寸、模式和 Alpha 范围稳定；
10. 所有 Pillow 中间对象按所有权约定关闭。

### 11.2 模块接口测试

通过 `compose_solid_alpha()` 的公开结果测试完整行为，不直接断言私有形态学中间数组。测试应在内部实现重构后保持有效。

### 11.3 前景准备集成测试

1. `ForegroundPreparer.prepare()` 在 ONNX 开启/关闭时都保持主体核心不透明；
2. U²-Net 与 U²-NetP 对同一输入的核心区域输出一致；
3. ONNX 不合格但键色合格时仍返回 Solid，且日志说明模型被忽略；
4. 键色失败时继续遵循现有降级授权；
5. API 响应中的模型版本、处理策略和降级字段保持一致。

### 11.4 真实回归素材

对已复现的“白狗 + 人物 + 深色衣物”素材固定使用同一张 Seedream 键色图，分别运行 U²-Net 和 U²-NetP，验证：

- 主体核心透明覆盖率接近 0；
- 人物、深色衣物和狗身体完整保留；
- 两种模型只允许在有限边缘像素上产生差异；
- 实际键色偏移被记录但不误判为不可用背景；
- 不再因模型显著性强弱改变主体完整性。

## 12. 验收标准

1. 普通不透明主体核心中 `Alpha < 250` 的比例不超过 `0.1%`。
2. 明确背景中 `Alpha > 5` 的比例不超过 `0.5%`。
3. 复现素材中的人物、深色衣物、狗身体和细小肢体均保持不透明。
4. U²-Net 或 U²-NetP 漏掉次要主体时，模型被忽略而不是直接输出损坏 Alpha。
5. Seedream 实际背景均匀且可安全分离时，不因请求色偏差单项指标直接失败。
6. 键色确实不可安全分离时，不允许 ONNX 绕过验证输出 Solid。
7. `ForegroundPreparer.prepare()` 外部接口不变。
8. 降级原因、实际键色、ONNX 拒绝原因和最终 Alpha 指标均可在日志中定位。
9. API 全量测试、Ruff、Compose 配置校验通过。

## 13. 风险与缓解

### 主体接触画布边缘

风险：主体颜色接近实际键色且连接边缘时可能被当作背景。

缓解：同时要求颜色相似、边缘主色稳定和主体可分离；边缘带保留软蒙版，失败时拒绝而不是扩大删除范围。

### 细小结构没有可腐蚀核心

风险：手指、绳索等结构宽度小于腐蚀直径。

缓解：腐蚀只定义“强制 255 的核心”，不会删除原始键色主体；没有核心的细结构仍使用 `A_chroma`，ONNX 只能增加而不能降低其 Alpha。

### 实际键色偏移接受过宽

风险：错误背景也可能被当作键色。

缓解：请求色差只从硬拒绝改为诊断项，仍必须通过边缘覆盖、三边一致、连通面积、过渡面积和主体可分离性等全部检查。

### 键色轮廓包含上游水印或杂物

风险：非键色内容会被视为主体。

缓解：继续通过 Seedream 提示词和水印配置约束上游；本次不允许 ONNX 以删除水印为由降低真实主体 Alpha。若水印持续出现，应单独建立上游生成质量问题处理方案。

## 14. 发布与回滚

发布前以固定回归素材记录新旧策略的 Alpha 指标和最终图。发布后重点观察：

- `onnx_edge_assist_used` 比例；
- ONNX 被拒绝的原因分布；
- 实际键色偏移接受比例；
- 最终主体核心透明覆盖率；
- Solid 降级率和 422 比例。

本方案不提供回滚到“ONNX 直接 Alpha”的运行开关。若需要代码回滚，应整体回滚版本；线上临时降低模型资源消耗仍可将 `FOREGROUND_MODEL_VARIANT` 切为 `u2netp`，但这不改变保护性 Alpha 规则。

## 15. 待审查决策

1. 接受 `ENABLE_ONNX_MATTING=true` 从“ONNX 独占 Alpha”调整为“ONNX 边缘辅助”。
2. 实际键色偏离请求色不再单项硬拒绝，但必须通过其他全部安全检查。
3. 键色有效而 ONNX 质量不合格时，保持 Solid 并忽略 ONNX，不标记业务降级。
4. 键色无效时禁止使用 ONNX 直接 Alpha 绕过验证。
5. 主体核心以不透明为产品语义，不支持主体内部真实半透明材质。
