# ONNX 启用时动态键色预处理与直接抠图技术方案

> 日期：2026-08-28  
> 版本：v1  
> 状态：已审查，已实施  
> 范围：`ENABLE_ONNX_MATTING=true` 时 Solid 模式的 Seedream 动态键色预处理、ONNX 直接抠图、降级与诊断备份

## 1. 决策

`ENABLE_ONNX_MATTING=true` 时，Seedream 仍必须先生成高对比动态键色背景，但键色只是
ONNX 的输入预处理，不参与成功路径的 Alpha 决策。最终 Alpha 直接使用经过质量
验证的 ONNX 蒙版。

```text
上传图片
  → 选择与原图主要颜色高对比的内部键色
  → 豆包 Seedream 生成不透明平坦键色背景图
  → 校验 BackgroundHint 协议
  → ONNX 对 Seedream 键色图生成蒙版
  → 验证 ONNX 蒙版质量
  → 直接将 ONNX 蒙版写入 Seedream 图片 Alpha
  → MARD 量化
```

成功路径不执行：

- `validate_chroma_mask()`；
- `fuse_chroma_with_onnx()`；
- 键色蒙版和 ONNX 蒙版的融合；
- 键色蒙版对 ONNX 结果的覆盖或修正。

`ENABLE_ONNX_MATTING=false` 时保持现有纯键色验证、透明化和保守降级语义。

## 2. 模块与接口

`ForegroundPreparer` 继续作为唯一外部 seam，`prepare()` 的参数和返回类型不变。
键色 Prompt、Hint 协议、ONNX 调用、蒙版验证和 Pillow 对象所有权继续封装在深模块内。

内部路径拆分为：

```text
_prepare_with_chroma_only(...)  # ENABLE_ONNX_MATTING=false
_prepare_with_onnx(...)         # ENABLE_ONNX_MATTING=true，输入已是键色图
```

`ENABLE_ONNX_MATTING=true` 成功时统一返回：

```text
processing=local_matte
degraded=false
foreground_model_version=<ONNX model version>
```

`chroma_matte` 只用于 ONNX 关闭时的键色成功路径；`hybrid_matte` 本期不再产生，
但为了兼容已有响应类型可暂不删除枚举值。

## 3. Seedream 键色契约

### 3.1 Solid 始终请求键色

`ForegroundPreparer.prepare()` 只要收到 `background_mode=solid`，就将
`background_hint_kind="chroma_key"` 传给 Seedream，不再根据 ONNX 开关决定是否要求键色。

`keep` 和 `simplify` 不生成键色背景，也不执行 ONNX。

### 3.2 Hint 协议

ONNX 执行前必须确认：

```text
hint.kind=chroma_key
hint.policy_version=solid-chroma-v1
```

Hint 只证明 Seedream 适配器已按键色 Prompt 发起请求，不证明实际图片已通过键色
图像质量验证。Hint 缺失或版本错误时不调 ONNX，直接返回 422
`AI_BACKGROUND_SEPARATION_FAILED`，避免配置错误被 ONNX 静默掩盖。

### 3.3 配置约束

生产不再允许 `IMAGE_ENHANCER=passthrough`，启动配置统一为：

```text
IMAGE_ENHANCER=seedream
ARK_DOUBAO_API_KEY=<required>
ENABLE_ONNX_MATTING=true|false
```

`true` 仍要求 ONNX Adapter 和模型就绪；`false` 使用 `DisabledForegroundMaskAdapter`。

## 4. ONNX 直接抠图

### 4.1 成功路径

1. 对 Seedream 键色图调用 `ForegroundMaskAdapter.generate()`；
2. 通过 `_validate_mask()` 验证尺寸、前景覆盖、背景覆盖和不确定区域；
3. 验证通过后调用 `_apply_mask(enhanced, validated.mask)`；
4. `_apply_mask()` 保留 Seedream RGB，以 ONNX 蒙版作为唯一 Alpha；
5. 返回 `processing=local_matte`。

成功路径不使用键色的请求 HEX、实际边缘键色或键色蒙版修改 Alpha。

### 4.2 ONNX 低置信降级

ONNX 蒙版未通过质量验证时：

1. `fallback_mode=simplify`：进入 `fallback_simplify`；
2. 未授权降级：返回 422。

因 Seedream 图片已是内部键色背景，降级时不得直接将不透明键色图交给量化器。
仅在该失败分支中执行 `validate_chroma_mask()`：

- 键色验证通过：使用键色蒙版透明化，但仍标记
  `processing=fallback_simplify` 和 `degraded=true`；
- 键色完整验证失败：使用 `build_conservative_edge_key_mask()`，
  只移除边缘连通键色；
- Hint 已在 ONNX 执行前确认有效，因此降级分支不猜测未知背景色。

键色蒙版只是 ONNX 失败后的背景语义保底，不是 `true` 成功路径的融合证据。

### 4.3 系统异常

ONNX Adapter 超时、未就绪或抛出其他系统异常时原样传播，不伪装成低置信降级。

## 5. 运行顺序与资源所有权

`ENABLE_ONNX_MATTING=true` 时，单次 `prepare()` 执行：

1. Seedream 返回不透明键色图和 Hint；
2. 验证 Hint 类型与版本；
3. ONNX 对 Seedream 键色图生成原始蒙版；
4. `_validate_mask()` 得到已验证 ONNX 蒙版或低置信结果；
5. 成功时直接应用 ONNX 蒙版；低置信时按第 4.2 节处理；
6. 关闭 ONNX 原始蒙版和已验证蒙版；
7. `PreparedForeground.enhancer_image` 保留未透明化的 Seedream 键色图，交给路由备份和关闭。

任一异常分支必须按对象身份只关闭一次，不泄漏 Pillow 对象或重复关闭调用方原图。

## 6. 诊断、日志与备份

### 6.1 成功指标

ONNX 成功路径记录：

```text
requested_key                 # BackgroundHint 中的请求键色
chroma_policy_version
foreground_model_version
foreground_coverage
background_coverage
foreground_uncertain_coverage
foreground_policy_version
```

成功路径不做键色图像验证，因此不伪造 `actual_key`、`border_coverage` 或键色质量结论。

### 6.2 降级日志

ONNX 低置信且请求授权降级时，继续写入 `foreground_degraded` 事件，至少包含：

```text
requested_key
actual_key                    # 降级键色验证可用时
validation_failures           # 键色降级验证失败原因
foreground_validation_failures
foreground_coverage
background_coverage
foreground_uncertain_coverage
foreground_policy_version
foreground_model_version
fallback_mask
```

ONNX 验证也必须改为保留失败原因和阈值的详细结果，不再只返回 `None`。

### 6.3 阶段备份

ONNX 启用时继续保存：

```text
{timestamp}-original.png
{timestamp}-seedream-enhanced.png       # 不透明键色图
{timestamp}-foreground-final.png        # 直接应用 ONNX 蒙版后的 RGBA
{timestamp}-foreground-metrics.json
```

## 7. 处理矩阵

| Hint | ONNX 结果 | fallback | 结果 |
| --- | --- | --- | --- |
| 缺失/版本错 | 不执行 | 任意 | 422，协议错误 |
| 有效 | 验证通过 | 任意 | 直接 ONNX Alpha，`local_matte` |
| 有效 | 低置信 | `simplify` | 键色背景保底 + `fallback_simplify` |
| 有效 | 低置信 | 未授权 | 422 |
| 有效 | 系统异常 | 任意 | 传播异常，不降级 |

## 8. 回归测试

### 8.1 Prompt 与编排

- `ENABLE_ONNX_MATTING=true + solid`：Seedream 必须选择键色并返回 Hint；
- ONNX Adapter 接收的像素必须与 Seedream 返回的键色图一致；
- 键色完整验证函数使用调用即失败的 spy，证明 ONNX 成功路径没有调用它；
- `ENABLE_ONNX_MATTING=false + solid`：继续走现有键色验证路径且不调 ONNX；
- `keep/simplify`：不要求键色、不调 ONNX。

### 8.2 ONNX 唯一 Alpha

- 构造与键色蒙版冲突的 ONNX 蒙版，最终 Alpha 必须与 ONNX 蒙版完全一致；
- 返回 `processing=local_matte`，不返回 `chroma_matte` 或 `hybrid_matte`；
- 成功路径不使用 `fuse_chroma_with_onnx()`；
- ONNX 的尺寸归一和质量验证保持有效。

### 8.3 降级

- ONNX 低置信 + simplify：保守移除边缘键色，键色不进入调色板或豆子统计；
- 降级日志同时包含请求/实际键色、ONNX 失败原因和阈值；
- ONNX 低置信且未授权降级：返回 422；
- Hint 缺失或版本错误：不调 ONNX，返回 422；
- ONNX 系统异常不降级。

### 8.4 备份与配置

- Seedream 阶段图保留不透明键色；
- final 阶段图的 Alpha 与 ONNX 蒙版一致；
- `IMAGE_ENHANCER=passthrough` 启动失败；
- ONNX 开启时 `/readyz` 继续检查 Adapter；
- ONNX 关闭时不加载模型。

## 10. 验收标准

- `ENABLE_ONNX_MATTING=true + solid` 必须先获得 Seedream 动态键色图和有效 Hint，
  再对该图执行 ONNX；
- ONNX 验证通过时，最终 Alpha 只来自 ONNX 蒙版，不运行键色验证或蒙版融合；
- ONNX 低置信时，仅为避免键色进入豆子统计而在降级分支执行键色保底；
- 降级日志输出请求/实际键色以及 ONNX 失败原因；
- ONNX 关闭时的纯键色语义保持不变；
- 不增加第二次 Seedream 请求；
- Ruff、相关回归和 API 全量测试通过。
