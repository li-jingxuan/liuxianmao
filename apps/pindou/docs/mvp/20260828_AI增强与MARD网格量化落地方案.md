# AI 增强与 MARD 网格量化落地方案

> 状态：待实施  
> 目标版本：MVP2  量化增强版  
> 方案日期：2026-08-28  
> 适用范围：`apps/api`，兼容现有 `apps/web` 转换接口

## 1. 结论

本 MVP 不让 AI 直接生成最终的拼豆网格或 MARD 色号，而是让 AI 负责“整理图像结构”，让后端确定性算法负责“颜色、网格和施工约束”。推荐链路如下：

```text
上传原图
  ↓
Seedream 结构化简化（可选）
  ↓
本地前景蒙版 / Alpha 校验
  ↓
重要性图（首版使用边缘图，预留 AI importance map）
  ↓
方形网格采样
  ↓
MARD 色卡约束调色板选择
  ↓
空间连续性优化
  ↓
palette + rows JSON
```

最终结果必须继续满足：

- 所有色号属于用户选择的 MARD 色卡套装；
- 实际颜色数不超过有效颜色预算；
- 相同输入、参数、模型版本和策略版本产生相同网格结果；
- `rows[y][x] = None` 表示空格，不是透明颜色，也不计入豆数。

本期只实现三项 AI 相关能力：

1. 复用现有 `SeedreamEnhancer`，将 Prompt 固定为“适合后续缩格和有限色卡量化的结构化中间图”；
2. 保留现有本地 ONNX 前景分离，作为 Solid 背景的权威蒙版，不依赖 Seedream 是否正确返回 Alpha；
3. 增加 AI 开关和明确的失败语义，AI 失败不静默伪装成原图结果。

重要性图、语义分割和受约束 K-Medoids 留作下一小版本的可插拔扩展，不阻塞本 MVP 上线。

## 3. MVP 目标与非目标

### 3.1 目标

- 用户可以为单次转换开启或关闭 AI 增强；
- AI 中间图重点减少摄影纹理、抗锯齿过渡色和无施工价值的碎片；
- 主体、轮廓和关键区域在低网格尺寸下保持可辨识；
- Solid 模式始终使用本地前景蒙版；
- AI 开启失败有稳定错误码，不自动返回“看起来成功但实际未增强”的结果；
- 量化结果仍由现有 MARD 白名单和 CIEDE2000 算法决定；
- 增加效果评估和结构化日志，能够比较 AI 与非 AI 的最终拼豆图，而不只比较中间图。

### 3.2 非目标

- 不让 Seedream 直接输出 `N×N` 网格、MARD 色号或 `rows`；
- 不在本期引入语义分割、视觉语言模型或训练新模型；
- 不在本期使用扩散模型反复生成多个候选并自动择优；
- 不使用 Floyd–Steinberg 等误差扩散作为默认行为；
- 不因 AI 失败自动切换为原图量化；
- 不让前端传入供应商、模型、Prompt 或内部阈值；
- 不同时大幅修改网格采样、颜色预算和量化目标，避免无法归因。

## 4. 处理流程设计

### 4.1 请求入口

在 `POST /api/v1/conversions` 增加现有方案中的字段：

```text
enable_ai_enhancement=true | false
```

语义：

| 请求值 | 处理路径 | 失败行为 |
| --- | --- | --- |
| `true` | 配置的 `SeedreamEnhancer` → 前景处理 → 量化 | AI 不可用或失败时返回稳定 AI 错误 |
| `false` | `PassThroughEnhancer` → 前景处理 → 量化 | 不发起外部 AI 请求 |

MVP2 兼容期字段默认值沿用 `true`，升级后的 Web 客户端必须显式发送。服务端 `IMAGE_ENHANCER=passthrough` 时，显式请求 AI 返回 `503 AI_ENHANCEMENT_UNAVAILABLE`，不能静默切换。

### 4.2 AI 中间图

Seedream 的职责仅是生成适合后续确定性处理的视觉中间图。Prompt 必须强调：

- 以原图为唯一内容依据，不增加新物体和新主体；
- 保持数量、姿态、构图、主要配色和主体身份；
- 合并摄影纹理、细碎高光、抗锯齿过渡色和低价值渐变；
- 让主要色块边界清晰、连续并在目标网格缩小后仍可辨识；
- 根据 `grid_size` 选择细节档位；
- 不要求精确 MARD 色号和精确颜色数量；
- 不绘制像素格、网格线、珠子、马赛克或十字绣纹理。

当前 [seedream-grid-aware-prompt-optimization.md](./seedream-grid-aware-prompt-optimization.md) 已覆盖这些原则。本 MVP 只允许一次 Seedream 调用，不做失败重生成和多候选择优。

### 4.3 前景与背景

处理顺序必须是：

```text
Seedream 输出 enhanced
  ↓
ForegroundMaskAdapter.generate(enhanced)
  ↓
ForegroundPreparer 验证覆盖率和不确定区域
  ↓
validated mask 替换 enhanced Alpha
  ↓
build_bead_grid(enhanced)
```

原因是 Seedream 可能改变构图和轮廓，原图蒙版不能保证与实际量化图逐像素对齐。

Solid 模式下：

- 本地 ONNX 模型是权威前景路径；
- Seedream 不需要被信任为透明 PNG 或键色输出；
- 低置信度只有在调用方明确选择 `fallback_mode=simplify` 时才允许降级；
- 模型运行失败仍返回 `503`，不能伪装为正常成功。

Keep / Simplify 模式继续沿用现有契约，背景中的可见格正常进入量化。

### 4.4 重要性权重

首版不增加额外 AI 模型，继续使用 `preprocess.py` 生成的 `edge_strengths`。量化权重为：

```text
visual_weight = min(3.0, 1.0 + edge_weight × edge_strength)
```

这能保护轮廓和高对比细节，同时避免小区域支配整个调色板。

未来增加 `importance_map` 时，保持向后兼容的扩展形式：

```text
visual_weight = min(
    3.0,
    1.0 + edge_weight × edge_strength + importance_weight × importance,
)
```

AI 只提供重要性，不直接决定 MARD 颜色。重要性图失效时回退到边缘权重，不能使量化请求失败。

## 5. 量化器改造

### 5.1 保留当前 MARD 约束选色

当前 `quantize.py` 的以下部分继续使用：

- 透明 Alpha 过滤；
- 颜色观察聚合；
- MARD 候选色卡白名单；
- CIEDE2000 距离；
- 贪心选色和有限交换；
- 相近颜色合并；
- 输出调色板压缩与稳定顺序。

不改成普通 K-Means、Median Cut 或 Octree 作为最终调色板算法，因为它们无法保证对指定 MARD 套装的组合最优。

### 5.2 增加局部空间优化

当前孤立格清理是一次性事后替换。本期将其扩展为最多 2 轮的局部能量优化，每个候选替换只允许使用当前已选 MARD 调色板中的颜色：

```text
cell_cost = color_error
          + λ × neighbor_transition_cost
          - μ × edge_strength × boundary_preservation
```

规则：

1. 只评估上下左右四邻域，避免对角线导致过度连接；
2. 平坦区域提高邻域一致性，减少椒盐噪声；
3. 高边缘格降低平滑惩罚，保护眼睛、文字和轮廓尖角；
4. 单次替换必须让总局部成本下降，并设置最小收益阈值；
5. 读取上一轮快照，避免扫描顺序造成级联扩散；
6. 透明格不参与颜色平滑，不能被填充成背景豆。

该优化不改变调色板，只改变 `rows`，因此风险低于引入新的全局调色板算法。

### 5.3 算法版本和指标

量化算法版本由：

```text
bead-grid-constrained-v3-spatial-mvp1
```

建议新增指标：

- `spatial_transition_count`：相邻可见格颜色切换次数；
- `small_component_count`：面积不超过 2 格的连通区域数量；
- `pre_cleanup_mean_delta_e00`；
- `post_cleanup_mean_delta_e00`；
- `ai_enabled`、`enhancer_name`、`enhancer_prompt_version`；
- `foreground_processing`、`foreground_confidence`；
- Seedream、蒙版、采样、量化各阶段耗时。

现有 `mean_delta_e00` 只反映选色分配，不能假定它已经包含空间清理后的最终误差。日志中应明确区分两个阶段。

## 6. API 和配置变更

### 6.1 响应

继续复用 `ConversionMeta`：

```json
{
  "meta": {
    "enhancer": "seedream-5-lite",
    "enhancer_model": "...",
    "enhancer_prompt_version": "...",
    "foreground_processing": "local_matte",
    "degraded": false
  }
}
```

不新增与 `meta.enhancer` 重复的响应字段。`meta.enhancer` 是本次请求实际执行路径的单一事实来源。

### 6.2 错误码

沿用现有错误，并新增或确认：

| HTTP | code | 场景 |
| ---: | --- | --- |
| 503 | `AI_ENHANCEMENT_UNAVAILABLE` | 请求要求 AI，但服务端未配置可用增强器 |
| 429 | `AI_BUSY` | Seedream 并发队列超时 |
| 504 | `AI_TIMEOUT` | 上游超时 |
| 502 | `AI_UPSTREAM_ERROR` | 上游返回异常或图片无法解码 |
| 503 | `FOREGROUND_MASK_UNAVAILABLE` | 本地前景模型不可用 |
| 422 | `AI_OUTPUT_REJECTED` | AI 输出未通过内容安全检查 |

AI 失败不自动使用原图量化。用户可以明确关闭 AI 后重试，这样结果语义可理解、成本可追踪。

### 6.3 配置

继续使用现有配置，避免本期迁移环境变量：

```dotenv
IMAGE_ENHANCER=passthrough|seedream
ARK_DOUBAO_API_KEY=<server-only-secret>
ARK_DOUBAO_IMAGE_MODEL=doubao-seedream-5-0-lite-260128
```

Seedream API Key 只能存在于 API 服务端，不能出现在任何 `NEXT_PUBLIC_*` 变量中。

## 7. 实施拆分

### P0：接口与现有链路确认（0.5 人日）

- 落实 `enable_ai_enhancement` 单次请求开关；
- 补齐 `AI_ENHANCEMENT_UNAVAILABLE` 测试；
- 确认 AI 开关关闭时不调用 Seedream、不生成 AI 备份；
- 确认 Solid 仍通过 `ForegroundPreparer` 处理。

### P1：Prompt 和效果集（1–2 人日）

- 固定 Prompt 版本；
- 使用 `micro / small / medium / large` 四档网格细节策略；
- 建立至少 12 张固定样本：人物、动物、Logo、插画、渐变、复杂背景各两张；
- 每个 AI 样本至少运行三次，冻结增强图后再比较量化结果。

### P2：空间局部优化（1–2 人日）

- 在 `quantize.py` 增加局部能量评估；
- 加入空间指标和算法版本；
- 保留现有孤立格规则作为保护条件；
- 为细线、文字、透明边缘和大面积渐变增加回归测试。

### P3：灰度发布（0.5–1 人日）

- 默认保留现有非 AI 路径可用；
- 仅对已配置 Seedream 的环境开放 AI；
- 记录 AI 成功率、超时率、前景置信度和用户重试率；
- 效果未达标时可以关闭 AI，不影响确定性转换服务。

预计首版开发量约 3–5 人日，不包括模型训练、语义分割和新的供应商接入。

## 8. 验收标准

### 功能正确性

- AI 开关开启时，响应中的 `meta.enhancer` 为实际 AI 适配器；
- AI 开关关闭时，绝不调用 Seedream；
- AI 不可用时返回 `AI_ENHANCEMENT_UNAVAILABLE`，不静默降级；
- Solid 模式的前景蒙版与增强后图片尺寸一致；
- 所有输出色号均属于所选 MARD 套装；
- `actual_color_count <= effective_max_colors`；
- `rows` 尺寸始终为 `grid_size × grid_size`；
- 透明格不计入豆数和调色板。

### 效果门槛

与“关闭 AI + 当前量化器”相比，冻结样本集至少满足：

- 主体识别度人工评分不下降；
- 小面积关键结构保留率提升或持平；
- `small_component_count` 不增加 20% 以上；
- 空间颜色切换次数下降 10% 以上，或人工确认边界质量提升；
- 平均和 P90 CIEDE2000 不出现明显回归；
- 相同增强图重复量化结果完全一致。

效果门槛必须以最终拼豆网格为准，不以 Seedream 中间图是否“更漂亮”为准。

## 9. 后续扩展点

当本 MVP 稳定后，可以在不改变 API 响应结构的情况下增加：

1. `importance_map`：由轻量视觉模型预测关键区域权重；
2. 语义区域分割：对脸部、文字、主体和背景使用不同平滑参数；
3. 受约束 K-Medoids：改善 MARD 调色板的全局组合；
4. 可选边缘感知误差扩散：只用于渐变图，不作为默认；
5. AI 自动建议颜色预算：仅作为后端硬上限的建议值。

这些扩展都必须遵守同一原则：AI 可以提供结构、重要性或建议，但最终 MARD 色号、网格尺寸、豆数和输出格式仍由后端确定性逻辑决定。

## 10. 风险与回滚

| 风险 | 控制措施 | 回滚方式 |
| --- | --- | --- |
| Seedream 改变主体构图 | Prompt 保持身份和构图；冻结样本人工审核 | `enable_ai_enhancement=false` |
| AI 返回不透明或错误蒙版 | 本地 ONNX 蒙版统一验证 | 关闭 Solid AI 或使用显式 simplify 降级 |
| AI 成本和延迟过高 | 单次调用、有界并发、超时和指标 | 服务端 `IMAGE_ENHANCER=passthrough` |
| 空间平滑吃掉细节 | 高边缘格降低平滑；最小收益阈值 | 恢复旧清理函数 |
| Prompt 版本导致结果漂移 | 记录 Prompt 版本，固定效果集 | 回退上一个 Prompt 版本 |
| MARD 合法性回归 | 保留色卡白名单测试和算法版本 | 禁用新增空间优化 |

上线前必须保留一条完全确定性的 passthrough 路径。它既是用户可选的低成本模式，也是 AI 方案的故障隔离和效果对照基线。
