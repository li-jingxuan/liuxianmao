# Seedream 按网格大小优化提示词方案

> 状态：已实施，待固定效果集验证  
> 目标版本：MVP2 Prompt v3  
> 方案日期：2026-08-14  
> 影响范围：`apps/api/src/pindou/services/enhancer.py`、`seedream_prompt.py`、转换路由与效果评估  
> 前置方案：[Seedream 5.0 lite AI 增强接入技术方案](./seedream-5-lite-integration-plan.md)

## 1. 结论

建议让 AI 提示词感知最终 `grid_size`，但不要为每一个网格尺寸维护一份独立提示词。推荐采用：

1. 一份稳定的公共约束，保护主体身份、构图和核心语义；
2. 四个网格档位，控制允许保留的细节层级；
3. 一份与网格档位正交的背景模式片段；
4. 在提示词中提供精确 `grid_size` 作为下游目标上下文，但明确禁止模型绘制像素格、网格线或珠子；
5. 最终 MARD 色号、网格采样和量化仍由现有确定性算法完成。

建议初始档位如下：

| 档位 | `grid_size` | 优化目标 | 细节预算 |
| --- | ---: | --- | --- |
| `micro` | 8–31 | 缩小后仍能一眼识别主体 | 轮廓、姿态、2–4 个身份特征；极少阴影 |
| `small` | 32–63 | 保住主体关键特征并减少碎片 | 主要五官、服饰或结构分区；少量两级明暗 |
| `medium` | 64–95 | 平衡识别度和信息量 | 关键内部结构、主要材质分区；有限局部细节 |
| `large` | 96–156 | 保留有语义价值的细节 | 较完整结构与层次；仍去除摄影噪点和无效纹理 |

档位边界是第一版实验参数，不应视为模型能力的事实。上线前必须用固定图集验证，必要时只调整边界或单个档位片段，不同时改动公共约束和背景片段。

## 2. 为什么需要按网格大小区分

当前 Prompt v2 对所有输入统一要求“适合低分辨率拼豆图纸”“使用大色块、清晰封闭边界和少量必要阴影”。这有三个局限：

- `8×8` 与 `156×156` 的可表达能力相差很大，统一细节预算会令低网格产生大量缩小后消失的细节，也可能令高网格被过度简化；
- AI 输出是高分辨率中间图，模型不知道它随后会被压缩到多少采样单元，容易把资源花在最终无法保留的纹理上；
- 当前“保留背景”和“简化细节”没有明确优先级。低网格若直接使用强简化措辞，可能误删 `keep` 模式要求保留的背景物体。

网格感知提示词的职责不是让 Seedream 直接生成像素画，而是提前控制中间图的视觉复杂度，让后续缩格和 MARD 量化得到更稳定的输入。

## 3. 设计原则

### 3.1 按档位控制，不按每个尺寸分叉

`grid_size` 的合法范围为 8–156。若为 149 个可能值分别维护提示词，将难以测试、版本化和比较，也会让相邻尺寸出现无意义的行为跳变。

实现上应由纯函数把网格尺寸映射到有限档位，再由档位选择静态提示词片段：

```python
def classify_grid_detail(grid_size: int) -> GridDetailBand:
    if grid_size <= 31:
        return GridDetailBand.MICRO
    if grid_size <= 63:
        return GridDetailBand.SMALL
    if grid_size <= 95:
        return GridDetailBand.MEDIUM
    return GridDetailBand.LARGE
```

精确数值只作为一句下游上下文插入，例如：

```text
这张中间图随后会被等比适配并缩小为 52×52 个采样单元，请让重要轮廓和色块在缩小后仍然可辨识。
不要绘制像素格、马赛克方块、网格线、拼豆或珠子质感。
```

### 3.2 提示词只描述视觉目标，不冒充确定性约束

不要求模型：

- 输出精确的 `N×N` 像素图；
- 直接使用 MARD 色号或严格限制为某个颜色数量；
- 保证每条边界恰好占若干网格；
- 生成网格线、拼豆颗粒或马赛克效果。

这些要求难以由生成式模型可靠保证，而且会污染后续确定性量化。Prompt v3 只控制轮廓、区域大小、对比、阴影层级和细节优先级。

### 3.3 网格档位与背景模式正交组合

最终提示词按以下顺序组装：

```text
公共语义保护
+ 下游网格上下文
+ 网格档位细节预算
+ 背景模式策略
+ 输出禁止项
```

不要维护 `4 个档位 × 3 种背景 = 12` 份完整提示词。独立片段能减少重复和语义漂移，也便于单元测试保证每次只命中一个档位和一个背景模式。

## 4. Prompt v3 建议文本

### 4.1 公共语义保护

```text
以输入图为唯一内容依据。保留主体身份、数量、姿态、朝向、关键轮廓、主要配色和整体构图，不改变原图的核心语义。
将图像整理为边界清晰、色块连续、适合后续缩小和有限色卡量化的平面插画中间图。
优先保证主体可识别性和主体与背景的分离度，再保留次要装饰。
```

公共片段不再笼统写“低分辨率”和“少量阴影”，这些约束由网格档位决定。

### 4.2 下游网格上下文

```text
这张中间图随后会被等比适配并缩小为 {grid_size}×{grid_size} 个采样单元。
让重要轮廓、身份特征和主要色块在缩小后仍然连续、清楚、可辨识。
```

`grid_size` 已在路由层校验为整数，模板仍只能插入结构化数值，不接受任何用户自由文本。

### 4.3 `micro`：8–31

```text
细节等级：极低分辨率图标化表达。
使用非常简洁、稳定的外轮廓和少量大面积色块；显著加强主体与相邻区域的明度或色相区分。
只保留最能识别主体的 2–4 个内部特征，合并细小五官、毛发、褶皱、纹理、反光和重复装饰。
删除独立小亮点、细线、狭长色带和缩小后会消失的孤立区域。阴影最多保留一层宽而连续的形体阴影。
```

重点是“图标化”而不是“像素化”。对于人物，优先头部轮廓、发型大形、服装主色和姿态；对于动物，优先耳朵、尾巴、体态和主要花色；对于物体，优先外形、开口、把手或标志性结构。

### 4.4 `small`：32–63

```text
细节等级：低分辨率简化表达。
保持清楚的外轮廓和较大的内部结构分区，保留主要五官、服饰分区、动物花色或物体功能结构。
将相近颜色和零碎纹理合并成连续色块，移除细发丝、细小文字、密集线条、高光噪点和无识别价值的小装饰。
只使用少量必要阴影，避免窄于主要轮廓线宽的孤立细节。
```

该档覆盖默认 `52×52`，应作为首轮效果调优的重点。

### 4.5 `medium`：64–95

```text
细节等级：中等分辨率平面化表达。
保留主体的关键内部结构、主要五官关系、服饰层次、材质分区和有语义价值的配件。
允许有限的局部细节和两到三层明暗，但仍将摄影纹理、细碎反光、随机噪点和重复图案归并为稳定色块。
轮廓优先于纹理，局部细节不能破坏主体边界的连续性。
```

该档覆盖默认 `78×78`，目标是避免 v2 的过度简化，同时继续压制量化后容易形成噪点的摄影纹理。

### 4.6 `large`：96–156

```text
细节等级：较高分辨率的克制平面化表达。
保留完整的主体结构、主要五官和表情关系、服饰或物体的关键构造、具有识别意义的局部图案及主要空间层次。
可以保留适量边缘转折和明暗层次，但不要恢复照片级纹理、毛孔、颗粒、细碎反光、杂乱发丝或无规律背景噪点。
将低价值纹理合并为较大的稳定区域，确保色块边界清楚且便于有限色卡量化。
```

该档覆盖默认 `104×104` 以及最大 `156×156`。它不是“保留原图全部细节”，仍需防止高频纹理在 MARD 量化后变成碎色块。

### 4.7 背景模式片段

背景片段继续沿用 v2 的三种产品语义，但需要明确它与网格档位的冲突处理。

#### `simplify`

```text
背景处理：保留场景类型、主要背景区域和主体与背景的空间关系，但可以删除无关小物体、重复元素和低识别价值的装饰。
按照当前细节等级合并背景纹理和相近色区域，使背景使用比主体更少、更大的色块，并保持主体边缘具有足够对比。
不要把背景完全移除或擅自替换成单一纯色。
```

#### `solid`

```text
背景处理：完整移除原背景及其中所有物体，保留前景主体的完整轮廓和自然边缘。
将主体放在均匀、平坦、无渐变、无纹理、无阴影、无地面和无物体的 {background_color} 纯色背景上。
不要改变主体内部原本属于该颜色的区域，不增加地平线、边框或投影。
```

#### `keep`

```text
背景处理：保留原图背景中有语义的物体、数量、相对位置、遮挡关系、主要颜色和空间层次，不删除或替换背景内容，不把背景换成纯色。
当前细节等级只控制背景物体的表达精度：可以合并物体内部纹理和微小摄影伪影，但不能删除整个有语义的背景物体或改变其类别与位置。
```

### 4.8 统一输出禁止项

```text
不添加输入图中不存在的角色、物体、肢体、文字、标志、边框或水印。
不要绘制像素格、马赛克方块、网格线、拼豆、珠子、十字绣或颗粒材质。
不要为了填充画面而复制主体或背景物体。输出一张构图完整的图片。
```

## 5. 冲突优先级

提示词出现目标冲突时按以下顺序处理：

1. 主体身份、数量和核心语义不可改变；
2. 背景模式决定背景物体能否被删除；
3. 网格档位决定保留下来的主体和背景物体以多细的方式表达；
4. 风格化、阴影和装饰细节优先级最低。

典型组合：

| 组合 | 正确行为 | 错误行为 |
| --- | --- | --- |
| `micro + keep` | 保留背景物体及位置，但把物体内部压缩为极简色块 | 以网格太小为由删除整个背景物体 |
| `micro + simplify` | 可删除无关小物体，突出主体轮廓 | 把背景直接换成纯色 |
| `large + simplify` | 保留主要场景层次，删除低价值纹理 | 因网格较大而恢复全部摄影噪点 |
| 任意档位 + `solid` | 保留主体边缘，确定性纯色要求交给后处理评估 | 添加地面、投影或渐变背景 |

## 6. 数据与接口调整

### 6.1 扩展 `EnhancementOptions`

推荐让增强模块直接接收已验证的 `grid_size`：

```python
@dataclass(frozen=True, slots=True)
class EnhancementOptions:
    grid_size: int
    background_mode: BackgroundMode
    background_color: str | None = None
```

转换路由在调用增强器时传入当前 `grid_size`。`PassThroughEnhancer` 可以继续忽略全部选项，Seedream 实现使用 `grid_size` 选择档位并组装提示词。

暂不把 `max_colors` 和 `color_set_size` 放入 Prompt v3。一次只引入一个新的控制变量，才能判断效果变化是否真正来自网格感知。若 v3 稳定，再单独评估“颜色预算感知”是否能减少量化误差。

### 6.2 版本与可观测性

- 将 `SEEDREAM_PROMPT_VERSION` 升级为 `seedream-pindou-v3-grid-aware`；
- 响应继续通过 `meta.enhancer_prompt_version` 暴露版本；
- 服务端日志新增结构化字段 `grid_size` 和 `grid_detail_band`；
- 不记录完整提示词、图片 Data URL 或密钥；
- 建议在内部评估记录中保存 `prompt_version + grid_detail_band + background_mode`，便于对照图片备份。

如果后续频繁调整单个档位，可进一步将版本拆为公共版本和策略版本，例如 `v3/micro-2`，但首版保持一个整体版本更容易灰度和回滚。

## 7. 测试方案

### 7.1 单元测试

应覆盖：

- 边界值 `8、31、32、63、64、95、96、156` 映射到正确档位；
- 小于 8 或大于 156 的尺寸不能绕过路由校验进入模板；
- 每个提示词只包含一个网格档位片段和一个背景模式片段；
- 精确 `grid_size` 正确插入，且不出现“绘制网格”之类的正向要求；
- `solid` 只接受规范化后的 `#RRGGBB`；
- `simplify` 和 `keep` 不携带陈旧的背景颜色；
- Prompt v3 的禁止项始终存在；
- `PassThroughEnhancer` 的行为不受新增字段影响。

### 7.2 固定效果集

至少准备以下类别，并确保测试素材经过授权且不包含敏感信息：

- 单人半身、单人全身、多人；
- 猫狗等轮廓明显的动物、花纹复杂的动物；
- 车辆、建筑、杯子等几何物体；
- 动漫或平面插画；
- 主体与背景低对比、复杂室内、自然场景；
- 透明背景、横图、竖图和近方图。

每张图至少评估 `24、52、78、104、156` 五个代表尺寸、三种背景模式。生成式结果存在随机性，v2 和 v3 每个组合建议各运行三次，避免根据单次结果下结论。

### 7.3 评估维度

人工盲评作为主要判断，算法指标只作为问题定位代理：

| 维度 | 判断问题 | 可辅助观察的指标 |
| --- | --- | --- |
| 主体识别 | 缩格后是否仍能认出主体 | 盲评识别率、v2/v3 成对偏好 |
| 身份特征 | 五官、花色、结构是否保住 | 关键特征清单命中率 |
| 碎片控制 | 是否出现大量单格或小孤岛 | 量化后小连通区域占比 |
| 轮廓质量 | 外轮廓是否连续、主体是否粘连背景 | 边缘断裂与主体背景混淆的人工标注 |
| 背景合规 | 三种背景模式是否符合语义 | 删除、误加、换底和位置变化次数 |
| 色彩稳定 | 主要配色是否漂移 | 主色占比、实际颜色数和跨次生成差异 |
| 幻觉 | 是否添加不存在的内容 | 新物体、文字、肢体和复制主体计数 |

不要只用 SSIM 或像素差评价。Prompt v3 允许视觉表达变化，目标是提高最终拼豆图的识别度与可制作性，而不是让 AI 中间图逐像素接近原图。

### 7.4 建议验收门槛

首轮门槛可设为：

- 在低网格 `24、52` 的盲评中，v3 相对 v2 的总体偏好率达到 65% 以上；
- `78、104、156` 不因简化过度导致总体偏好显著下降；
- 三种背景模式的严重违约率不高于 v2；
- 新物体、文字、额外肢体或复制主体等严重幻觉不增加；
- AI 错误率、P95 延迟和单次生成成本不因提示词增长出现不可接受变化。

这些数值是上线决策门槛提案，应在第一轮基线评估后校准，并记录修改原因。

## 8. 灰度与回滚

1. 先完成纯函数、模板和边界单元测试；
2. 用固定效果集离线比较 Prompt v2 与 v3；
3. 只在内部或小比例流量启用 v3，并记录版本、档位、背景模式和用户重试率；
4. 观察低网格重试率、导出率、错误率、延迟和人工抽检；
5. 达到验收门槛后全量切换；否则通过配置恢复 v2，不改动量化算法。

不建议在同一个线上请求中同时调用 v2 与 v3，会直接增加成本和延迟。A/B 分流应以一次请求只选择一个提示词版本为原则。

## 10. 后续优化方向

网格感知稳定后，可以分别立项验证：

- `max_colors` 感知：控制明暗层级和主要色块数量，但不要求模型生成精确颜色数；
- 主体类型感知：人物、动物、物体采用不同的“身份特征优先级”，前提是有可靠分类且不会引入额外幻觉；
- 图像复杂度感知：用确定性边缘密度或分割统计辅助选择相邻档位，而不是完全依赖网格尺寸；
- 纯色背景确定性合成：如产品要求像素级纯色，使用分割蒙版加 Pillow 合成，不继续堆叠提示词；
- 基于效果集数据重新学习档位边界，避免长期依赖人工设定的 31、63、95。

以上方向应逐项实验，不与 Prompt v3 首次上线捆绑，避免无法归因效果变化。
