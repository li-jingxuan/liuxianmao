# Ark API 异常错误透传与错误码映射技术方案

> 状态：待确认，确认后实施  
> 目标版本：MVP2 量化增强版  
> 方案日期：2026-08-30  
> 适用范围：`apps/api`、`apps/web`；兼容现有 `/api/v1/conversions` 转换接口  
> 说明：本方案先定义契约与迁移边界，不包含代码实施。当前可用技能中没有 `matt` 技能，因此按仓库现有技术文档规范编写。

## 1. 背景与目标

当前 Ark SDK 异常虽然在 `SeedreamClient` 中被捕获，但业务层只把它压缩成 `AI_INPUT_REJECTED`、`AI_OUTPUT_REJECTED`、`AI_BUSY`、`AI_TIMEOUT` 或 `AI_UPSTREAM_ERROR`。前端收到未知业务码时又降级成“请求失败”，导致用户无法知道是内容安全、版权/输出审核、额度、参数还是服务暂时不可用。

本方案目标：

1. 保留 Ark `error.code`、HTTP 状态和 request id，贯穿日志到 API 响应。
2. 在服务端增加一层可审计的 Ark 错误码映射，返回稳定的业务码、中文提示和重试建议。
3. 前端按业务码展示可行动提示；不依赖 Ark 原始文案，也不把敏感堆栈或 Prompt 返回给用户。
4. 对 `OutputImageSensitiveContentDetected` 单独说明“生成结果未通过安全/版权审核”，避免误导为网络故障；同时支持未来 Ark 新增错误码的安全兜底。

非目标：不绕过 Ark 审核、不自动重试可能重复计费的图片生成、不把完整上游 message 或用户 Prompt 透传给浏览器。

## 2. 目标错误响应契约

继续使用现有外层结构，向后兼容已有前端：

```json
{
  "error": {
    "code": "AI_OUTPUT_REJECTED",
    "message": "AI 生成结果未通过内容安全或版权审核，请更换素材或调整描述后重试",
    "request_id": "req_xxx",
    "provider": "ark",
    "provider_code": "OutputImageSensitiveContentDetected",
    "retryable": false,
    "category": "output_safety"
  }
}
```

字段约束：

- `code` 是前端稳定枚举，禁止直接使用供应商字符串作为唯一业务契约。
- `provider_code` 只返回 Ark 错误码，不返回原始 message；便于客服和用户报 request id 排查。
- `message` 由服务端白名单映射生成；未知错误只返回通用提示。
- `retryable` 和 `category` 为可选新增字段，旧客户端忽略即可。
- `request_id` 始终使用现有请求追踪 ID；`provider_request_id` 只写服务端日志，不暴露给普通用户。

## 3. 服务端分层设计

### 3.1 上游异常对象

保留 `SeedreamUpstreamError`，补充结构化字段：`provider="ark"`、`provider_code`（现有 `code`）、`status_code`、`request_id`、`message`。SDK 适配器只负责提取字段和区分连接/超时/状态异常，不负责中文文案。

### 3.2 集中映射器

新增 `apps/api/src/pindou/core/ark_errors.py`（或等价模块）维护不可变映射表和纯函数 `map_ark_error(exc) -> ApiError`。禁止在路由中按字符串散落判断。

建议初始映射（以实际账号返回值和 Ark 官方文档为准）：

| Ark `error.code` / 条件 | HTTP | 业务 `code` | `category` | 用户提示 | 可重试 |
|---|---:|---|---|---|---|
| `InputTextSensitiveContentDetected` | 400 | `AI_INPUT_REJECTED` | `input_safety` | 图片或处理指令未通过内容安全检查，请更换素材或调整描述 | 否 |
| `OutputImageSensitiveContentDetected` | 422 | `AI_OUTPUT_REJECTED` | `output_safety` | AI 生成结果未通过内容安全或版权审核，请更换素材或调整描述后重试 | 否 |
| `QuotaExceeded` | 429 | `AI_QUOTA_EXCEEDED` | `quota` | AI 服务额度已用尽，请稍后重试或联系管理员 | 视配额策略 |
| HTTP 429（无明确 code） | 429 | `AI_BUSY` | `rate_limit` | AI 服务繁忙，请稍后重试 | 是 |
| 超时 / `TIMEOUT` | 504 | `AI_TIMEOUT` | `timeout` | AI 处理超时，本次结果未确认，请稍后手动重试 | 是（手动） |
| 连接失败 | 502 | `AI_NETWORK_ERROR` | `network` | AI 网络请求失败，请稍后重试 | 是 |
| 其他已知 Ark code | 按上游状态 | `AI_UPSTREAM_ERROR` | `upstream` | AI 服务暂时不可用，请稍后重试 | 按状态 |
| 未知 code 或 SDK 异常 | 502 | `AI_UPSTREAM_ERROR` | `upstream` | AI 服务暂时不可用，请稍后重试 | 是 |

注：`OutputImageSensitiveContentDetected` 是输出审核拒绝信号，不能断言具体侵权事实；文案使用“内容安全或版权审核”，并提示更换用户有权使用的素材/描述，避免法律结论。

### 3.3 `ApiError` 扩展

在不破坏现有构造调用的前提下增加可选 `details`（或专用字段）承载 `provider`、`provider_code`、`retryable`、`category`。全局异常处理器统一过滤字段：仅允许上述白名单，禁止 `message`、请求体、Prompt、密钥、堆栈进入响应。

### 3.4 日志与审计

现有 `ark_upstream_failure` 事件继续记录完整 `upstream_message`（截断）、`upstream_request_id` 和映射后的业务码；增加 `mapped_code`、`category`、`retryable`。生产日志不得记录图片 Base64、Prompt 或 API Key。未知 code 需要告警聚合，便于补充映射而无需立即发布前端。

## 4. 前端处理

扩展 `PindouApiError` 和 `ERROR_MESSAGES`：

- 优先使用后端 `error.message`；按 `code` 保留本地兜底文案。
- 对 `AI_OUTPUT_REJECTED` 展示审核/版权专属提示和“更换素材/调整描述”建议，不自动重试。
- `AI_TIMEOUT`、`AI_BUSY`、`AI_NETWORK_ERROR` 提供重试按钮；重试由用户主动触发。
- `provider_code` 仅用于开发日志或客服复制，不在普通 UI 主文案中展示。
- 未知业务码仍显示通用提示，但保留 `code` 和 `requestId` 供错误上报。

前端类型将 `provider`、`provider_code`、`retryable`、`category` 设为可选，兼容旧 API 和代理返回的旧结构。

## 5. 请求流程

```text
Ark SDK exception
  -> SeedreamClient 提取 code/status/request_id
  -> SeedreamUpstreamError
  -> ark_errors.map_ark_error（白名单文案与分类）
  -> ApiError
  -> FastAPI 全局 handler（过滤敏感字段）
  -> Web PindouApiError（提示/重试策略）
```

任何非 Ark 异常仍统一为 `AI_UPSTREAM_ERROR`；不得因为解析异常把内部堆栈直接返回前端。

## 6. 测试与验收标准

后端：

1. 为每个表格映射补充单元测试，覆盖 `OutputImageSensitiveContentDetected`、输入审核、额度、429、超时、连接失败和未知 code。
2. API 集成测试断言 HTTP 状态、`error.code`、`provider_code`、`request_id` 和敏感字段不泄漏。
3. 确认事件日志包含上游 code 与映射码，且不包含 Prompt、Base64 和密钥。

前端：

1. `parseResponse` 能解析新增可选字段；旧响应仍通过。
2. 输出审核显示版权/内容安全提示，网络/超时显示可重试提示。
3. 未知 code 不崩溃，仍保留 request id。

发布前使用真实 Ark 沙箱（不上传用户素材）核对错误码大小写、HTTP 状态和 request id 字段；官方返回字段与本方案不一致时，以实际 SDK 对象为准更新适配器，不改变前端稳定业务码。

## 7. 灰度、兼容与回滚

先仅发布服务端字段扩展和日志映射，前端按可选字段读取；观察未知 code 一周后再收紧文案。映射表可通过代码版本回滚，旧前端仍能使用 `code/message/request_id` 三字段。严禁为审核拒绝增加自动重试或降级到绕过审核的模型路径。

## 8. 待确认事项

1. 产品是否接受 `OutputImageSensitiveContentDetected` 使用“内容安全或版权审核”而非“确定侵权”的表述。
2. 是否允许把 `provider_code` 返回给登录用户；默认建议返回但不在 UI 主文案展示。
3. `QuotaExceeded` 是否与项目自身访问密钥额度共用 `AI_BUSY`，还是采用新业务码 `AI_QUOTA_EXCEEDED`。
4. 真实 Ark 账号当前返回的错误码集合、状态码和 request id 属性名，需要沙箱验证后冻结 v1 映射表。
