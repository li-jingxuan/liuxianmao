# 动态键色降级仍转透明 Bugfix 技术方案

> 日期：2026-08-28  
> 版本：v1  
> 状态：待审查，未实施  
> 范围：`ENABLE_ONNX_MATTING=false` 的动态键色降级、透明通道、豆子统计与阶段备份

## 1. 问题结论

正常 `chroma_matte` 路径已经会把边缘连通键色转换为 Alpha 0，完整
`蒙版 → 方形缩格 → MARD 量化` 探针也能正确输出背景空格。

Bug 出现在键色图像级验证失败且请求使用 `fallback_mode=simplify` 时：

```text
build_validated_chroma_mask() 返回 None
  → ForegroundPreparer 直接返回不透明 Seedream 图
  → 键色 Alpha 仍为 255
  → quantize_to_mard_grid() 将其作为普通豆子统计
```

因此 `fallback_simplify` 改变了背景语义，却没有完成动态键色协议最基本的
“键色属于背景”转换。

## 2. 修复原则

只要满足以下条件：

- `ENABLE_ONNX_MATTING=false`；
- `background_mode=solid`；
- Seedream 返回了版本匹配的 `BackgroundHint(kind="chroma_key")`；

键色就必须先转换为透明背景，再允许图片进入量化器。不能因为完整质量验证失败
或显式简化降级，就把内部键色作为前景颜色和豆子统计。

## 3. 修复设计

### 3.1 增加保守降级蒙版

在 `imaging/chroma_key.py` 增加纯函数：

```python
def build_conservative_edge_key_mask(
    image: Image.Image,
    hint: BackgroundHint,
    *,
    policy: ChromaPolicy | None = None,
) -> ChromaMaskResult | None:
    ...
```

该函数不宣称完整键色质量验证成功，只承担一个更窄的职责：

1. 从画布四边估计实际键色；估计失败时使用请求键色；
2. 计算与实际键色的色差；
3. 只处理与画布边缘连通的近键色区域；
4. 严格键色写入 Alpha 0，边缘过渡写入软 Alpha；
5. 主体内部不与边缘连通的同色区域保持 Alpha 255。

不允许使用全图颜色替换或“所有近键色都透明”，避免主体衣服、眼睛、Logo、
配件等恰好使用键色时被删除。

### 3.2 ForegroundPreparer 降级顺序

完整键色验证失败且 `fallback_mode=simplify` 时改为：

```text
Seedream 不透明图
  → 保守边缘连通键色蒙版
  → apply_chroma_mask_with_despill()
  → fallback_simplify PreparedForeground
  → 量化器按 Alpha 将键色格输出为 null
```

如果 `BackgroundHint` 缺失或版本不匹配，仍按现有语义返回 422；不能把未知颜色
猜成背景。关闭 ONNX 时该路径仍不得调用 `ForegroundMaskAdapter.generate()`。

### 3.3 结果与可观测性

保留：

```text
processing=fallback_simplify
degraded=true
degrade_reason=foreground_low_confidence
```

诊断指标增加：

```text
fallback_mask=conservative-edge-key
requested_key=<HEX>
actual_key=<HEX>
chroma_policy_version=solid-chroma-v1
```

公开响应不新增键色字段；内部键色继续不进入用户最终背景色契约。

### 3.4 阶段图片备份

`ENABLE_ONNX_MATTING=false` 时，不保存 ONNX 或最终前景阶段图片。成功和降级请求
只保存：

```text
{timestamp}-original.png
{timestamp}-seedream-enhanced.png
{timestamp}-foreground-metrics.json
```

不生成：

```text
{timestamp}-foreground-final.png
```

其中 `seedream-enhanced.png` 保留 Seedream 原始不透明输出，便于观察模型是否遵循
动态键色协议；键色转透明后的 RGBA 只在请求内存中交给 `build_bead_grid()`，不再额外
落盘。这样关闭 ONNX 后，诊断备份与实际启用能力保持一致，也避免用户误把
`foreground-final` 理解为 ONNX 抠图结果。

`foreground-metrics.json` 继续保存键色诊断和实际处理方式，例如：

```text
background_processing=chroma_matte|fallback_simplify
chroma_policy_version=solid-chroma-v1
fallback_mask=conservative-edge-key  # 仅降级透明化时存在
```

`ENABLE_ONNX_MATTING=true` 时保持现有 ONNX 阶段备份语义，可继续保存
`foreground-final.png`。

## 4. 回归测试

### 4.1 ForegroundPreparer

构造一个键色占满画布、会使完整 `background_coverage` 验证失败的 Seedream 输出：

- `ENABLE_ONNX_MATTING=false`；
- `fallback_mode=simplify`；
- 边角像素最终 Alpha 必须为 0；
- Mask Adapter 使用调用即失败的 spy，证明没有调用 ONNX；
- 返回值仍为 `fallback_simplify`。

该用例在当前实现稳定失败：边角 Alpha 实际为 255。

### 4.2 图像算法

- 触边键色区域转 Alpha 0；
- 键色偏离请求 HEX 时使用实际边缘键色；
- 主体内部不连通键色保持 Alpha 255；
- 版本不匹配的 Hint 返回 None；
- 输出尺寸与输入一致；
- 去色溢后严格透明区不会进入调色板。

### 4.3 完整网格

对 `ForegroundPreparer → build_bead_grid` 增加集成断言：

- 键色背景格为 `rows[y][x] is None`；
- 键色不出现在 `foreground.palette`；
- `stats.bead_count` 只统计非键色主体。

### 4.4 备份行为

- ONNX 关闭：只生成原图、Seedream 图和 metrics JSON；
- ONNX 关闭：不得生成 `foreground-final.png`；
- ONNX 开启：继续生成 ONNX 最终前景图；
- Seedream 图保持不透明原始输出，不用透明化结果覆盖它；
- 透明化结果虽然不落盘，但必须继续作为量化器实际输入。

## 6. 验收标准

- `ENABLE_ONNX_MATTING=false` 时，任何带有效键色 Hint 的成功或降级结果都不会把
  边缘连通键色作为豆子统计；
- 主体内部不连通同色区域不会被透明化；
- 不调用 ONNX；
- ONNX 关闭时只保存原图、Seedream 图和 metrics JSON，不保存最终前景图片；
- 内存中的透明化结果仍是唯一量化输入，不能因不落盘而改回 Seedream 原图；
- 不改变 `ENABLE_ONNX_MATTING=true`、`keep`、`simplify` 的既有行为；
- Ruff、相关回归与 API 全量测试通过。
