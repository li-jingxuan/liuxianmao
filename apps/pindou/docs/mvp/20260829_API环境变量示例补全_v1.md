# API 环境变量示例补全技术方案

> 状态：已实施  
> 目标版本：MVP2 量化增强版  
> 方案日期：2026-08-29  
> 适用范围：`apps/api/.env.example`，以 `apps/api/src/pindou/core/config.py` 为配置事实来源

## 1. 背景

`apps/api/src/pindou/core/config.py` 当前通过 Pydantic Settings 读取 43 个环境变量。现有
`apps/api/.env.example` 已出现全部 43 个变量名，但存在以下问题：

1. 多数变量没有逐项说明用途、单位、可选值及影响。
2. `MARD_COLOR_CHART_PATH`、`IMAGE_BACKUP_DIR`、`EVENT_LOG_DIR`、
   `IMAGE_DELIVERY_DIR` 只有注释占位，没有可复制的示例默认值。
3. `ARK_DOUBAO_API_KEY` 只有注释占位，复制文件后变量本身不存在。
4. `IMAGE_DELIVERY_MAX_BYTES` 和 `IMAGE_DELIVERY_CLEANUP_INTERVAL_SECONDS` 等示例值与
   代码默认值不一致，容易让维护者误判实际行为。
5. 密钥类变量没有明确区分“代码无默认值”和“示例占位值”，存在直接沿用占位值的风险。

## 2. 目标

- `Settings` 可读取的每一个环境变量都在 `apps/api/.env.example` 中以 `KEY=value` 形式出现。
- 每一个变量紧邻一条中文注释，说明用途；有必要时补充单位、可选值、约束和安全要求。
- 非敏感变量的示例值与代码默认值一致。
- 必填密钥和连接串使用明确的不可用占位值，并注明必须替换，不伪造安全默认值。
- 示例文件按运行环境、服务监听、数据库与鉴权、上传与网格、文件目录、图纸交付、
  Seedream、ONNX 前景模型分组，便于维护。

## 3. 范围与事实来源

本次只修改 API 示例配置，不修改运行时代码、数据库结构、Web 配置或部署 Compose 配置。

环境变量清单以 `Settings.model_fields` 对应的 43 个字段为准：

- 基础运行：`APP_ENV`、`API_HOST`、`API_PORT`、`API_RELOAD`
- 数据库与鉴权：`DATABASE_URL`、`KEY_ISSUER_API_KEY`、`API_KEY_HASH_PEPPER`
- 转换与上传：`IMAGE_ENHANCER`、`ENABLE_ONNX_MATTING`、`UPLOAD_MAX_BYTES`、
  `UPLOAD_MAX_PIXELS`、`MIN_GRID_SIZE`、`MAX_GRID_SIZE`、`DEFAULT_COLOR_SET_SIZE`
- 文件路径：`MARD_COLOR_CHART_PATH`、`IMAGE_BACKUP_DIR`、`EVENT_LOG_DIR`、
  `IMAGE_DELIVERY_DIR`
- 图纸交付：`IMAGE_DELIVERY_TTL_SECONDS`、`IMAGE_DELIVERY_MAX_BYTES`、
  `IMAGE_DELIVERY_MAX_PIXELS`、`IMAGE_DELIVERY_CLEANUP_INTERVAL_SECONDS`
- Seedream：`ARK_DOUBAO_API_KEY`、`ARK_DOUBAO_BASE_URL`、
  `ARK_DOUBAO_IMAGE_MODEL`、`ARK_DOUBAO_IMAGE_SIZE`、`ARK_DOUBAO_RESPONSE_FORMAT`、
  `ARK_DOUBAO_WATERMARK`、四项 HTTP 超时、最大并发、排队超时、响应体上限、输入边长和
  输出像素上限
- ONNX 前景模型：`FOREGROUND_MASK_ADAPTER`、`FOREGROUND_MODEL_VARIANT`、
  `FOREGROUND_MASK_MAX_CONCURRENCY`、`FOREGROUND_MASK_QUEUE_TIMEOUT_SECONDS`、
  `FOREGROUND_ONNX_INTRA_OP_THREADS`、`FOREGROUND_ONNX_ALLOW_SPINNING`

`TEST_POSTGRES_URL` 只由 PostgreSQL 集成测试直接读取，不属于 API 运行配置，因此不加入
API 的 `.env.example`。Docker Compose 的 `POSTGRES_*`、Web 的
`NEXT_PUBLIC_API_BASE_URL` 以及部署层的镜像和端口变量分别由其他 `.env.example` 管理，也不
混入 API 示例文件。

## 4. 默认值规则

### 4.1 非敏感配置

非敏感变量使用 `Settings` 中的真实默认值。重点统一以下值：

| 变量 | 示例目标值 | 说明 |
| --- | --- | --- |
| `IMAGE_ENHANCER` | `seedream` | 与代码默认值一致；本地免付费调试可改为 `passthrough` |
| `ENABLE_ONNX_MATTING` | `false` | 与代码默认值一致，且与默认 Seedream 组合合法 |
| `FOREGROUND_MODEL_VARIANT` | `u2net` | 与代码默认值一致；资源受限时可改为 `u2netp` |
| `IMAGE_DELIVERY_MAX_BYTES` | `15728640` | 15 MiB，与代码默认值一致 |
| `IMAGE_DELIVERY_CLEANUP_INTERVAL_SECONDS` | `259200` | 3 天，与代码默认值一致 |

路径变量使用从 `apps/api` 目录启动时可解析的仓库相对路径，并在注释中说明代码本身会根据
源码位置计算默认绝对路径：

| 变量 | 示例目标值 |
| --- | --- |
| `MARD_COLOR_CHART_PATH` | `../../docs/MARD_色卡.json` |
| `IMAGE_BACKUP_DIR` | `src/pindou/assets/images` |
| `EVENT_LOG_DIR` | `../../log` |
| `IMAGE_DELIVERY_DIR` | `src/pindou/assets/image-deliveries` |

### 4.2 必填连接串与密钥

`DATABASE_URL`、`KEY_ISSUER_API_KEY`、`API_KEY_HASH_PEPPER` 在开发和生产运行时均无安全
默认值；`ARK_DOUBAO_API_KEY` 在 `IMAGE_ENHANCER=seedream` 时必填。示例文件使用
`replace-with-...` 占位，并逐项注明必须替换：

- 不写入真实凭据。
- 不把同一个值用于数据库密码、签发密钥和哈希 pepper。
- 不把占位值描述成“默认密钥”。
- 数据库密码包含保留字符时必须进行 URL 编码。

## 5. 注释规范

每一个 `KEY=value` 上方至少有一条直接描述该变量的中文注释。注释内容按需包含：

1. 变量用途。
2. 默认值及单位，例如秒、字节、像素或并发数。
3. 枚举可选值，例如 `seedream/passthrough`、`u2net/u2netp`。
4. 与其他变量的约束关系，例如 `passthrough` 必须搭配
   `ENABLE_ONNX_MATTING=true`。
5. 敏感信息和生产使用警告。

变量值行不使用行尾注释，避免 dotenv 解析器对值边界产生歧义；备选值写在变量上方的注释中。

## 6. 实施步骤

1. 按上述分类重排 `apps/api/.env.example`。
2. 将全部 43 个变量改为显式 `KEY=value` 行。
3. 为每一个变量补齐紧邻中文注释。
4. 将非敏感示例值统一为 `Settings` 的代码默认值。
5. 对无安全默认值的连接串和密钥使用显式替换占位符。
6. 增加配置示例一致性测试，校验：
   - `Settings` 字段与 `.env.example` 的键集合完全一致；
   - 不存在重复键；
   - 每个键前存在变量级注释；
   - 示例文件能被 dotenv/Pydantic Settings 正常解析。

## 7. 验收标准

- `.env.example` 中恰好覆盖 API 的 43 个运行环境变量，无遗漏、无重复。
- 每个变量均有中文注释和非空示例值。
- 非敏感值与 `Settings` 默认值一致。
- 必填敏感项保持明显占位，不包含真实密钥。
- `IMAGE_ENHANCER=seedream` 的默认示例组合可通过配置校验；仅因占位密钥不能用于真实上游调用。
- API 配置测试、现有单元测试和 Ruff 检查通过。

## 8. 风险与回滚

- 显式路径使用相对路径时依赖从 `apps/api` 目录启动；注释会提示容器或其他工作目录应改成
  绝对路径。运行时代码仍保留基于源码位置的默认路径，不受本次修改影响。
- 示例切回代码默认的 `seedream` 会要求使用者配置有效方舟密钥；注释会提供
  `passthrough + ENABLE_ONNX_MATTING=true` 的本地调试组合。
- 本次只涉及示例配置和测试，可通过恢复对应文件直接回滚，不涉及数据迁移。
