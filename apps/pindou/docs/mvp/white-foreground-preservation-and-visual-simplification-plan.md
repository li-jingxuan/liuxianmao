## 绿边问题实施补充（2026-08-27）

绿边不是网格采样或 MARD 选色主动生成的颜色，而是 Seedream 键色中间图已经
包含的青绿色边缘污染。对最近四张 Solid 增强备份检查后得到以下证据：

- 四次动态键色都选择 `#00FFFF`，但 AI 实际背景会漂移到相邻青色；
- 输出 Alpha 只有 `0/255`，不存在可供下游正确融合的半透明过渡；
- 每张图仍有约 5,565–16,455 个接近键色的不透明边界像素；
- 典型残留值为 `(75, 229, 229)`，它到请求键色的 RGB 距离约为 `83.6`，刚好
  越过旧固定阈值 `80`，因此被当成完整主体保留；
- 将其中一张真实备份重新缩格到 52×52 后，有 27 个边界格被映射为绿色
  MARD `P3 #AEDDA9`；关闭边缘权重或改用纯 BOX 采样仍是 27 格。

因此修复分为两道确定性防线：

1. **Prompt v9 约束生成源头**：明确输出是供程序抠图的键色素材，禁止键色形成
   环境光、反射、辉光、色溢、描边、毛边或抗锯齿混色；只要求完全不透明的
   平坦键背景，消除“透明或键色二选一”的输出歧义。
2. **前景模块处理不可避免的模型误差**：从四边样本估计实际键色；按归一化
   键色偏差生成软 Alpha；仅从画布边缘遍历背景及混合带；对保留的软边缘使用
   键色合成模型反解 RGB，避免残余青绿色进入实体色卡。

不采用简单放宽 RGB 删除阈值。更宽的硬阈值只能移动断层位置，仍会产生新色边，
并提高误删浅色主体或主体自身绿色区域的风险。动态选键和边缘连通约束继续负责
保护主体内部合法颜色。

## 1. 结论

本次问题包含两个不同层级的缺陷，不能只通过增加 Prompt 文案一起解决：

1. **白色主体缺少色号和豆数**是前景分离错误。当前 Solid 模式会把与边缘背景近似且连通的像素清成透明；量化与统计只消费清理后的 Alpha，因此无法恢复已被误删的白色主体。
2. **颜色杂乱、轮廓不明显**同时受 AI 中间图、BOX 缩格和面积主导的 MARD 选色影响。Prompt v7 已经要求“轮廓优先、合并近似色”，继续堆叠同义文案不足以形成确定性保证。

推荐采用以下职责分工：

```text
Seedream
  └── 生成大色块、连续轮廓、受控明暗，并在 Solid 模式输出已知内部键色

前景分离模块
  └── 验证 Alpha/键色，生成可信前景蒙版；失败时明确报错，不静默误删主体

网格与量化模块
  └── 保留高对比边缘、提高轮廓权重、抑制近似色和低价值碎片

渲染层
  └── 最后铺设用户选择的白色或其他 Solid 背景，不参与色号与豆数统计
```

首要原则是：**颜色不是语义。不能再依据“边缘最常见颜色”推断所有同色连通区域必然属于背景。**

## 2. 诊断回溯

### 2.1 当前处理链路

当前 Solid 请求的关键路径为：

```text
Seedream 增强图
  ↓
检查是否存在透明 Alpha
  ├── 有透明区域：直接进入网格处理
  └── 无透明区域：推断边缘主色并执行 flood-fill
                         ↓
                   相近且边缘连通的像素 Alpha = 0
                         ↓
BOX 缩小为 N×N
  ↓
只量化 Alpha >= 128 的格子
  ↓
bead_count = 非透明格数量
```

相关实现：

- `apps/api/src/pindou/api/routes/conversions.py`：路由层决定是否执行边缘 flood-fill；
- `apps/api/src/pindou/imaging/preprocess.py`：从四边推断参考色并删除连通区域；
- `apps/api/src/pindou/imaging/quantize.py`：只统计 Alpha 大于等于占用阈值的格子。

### 2.2 已建立的确定性反馈循环

使用 7×7 最小图片模拟：白色主体被深色轮廓包围，但轮廓顶部存在一个像素缺口。该缺口让白色主体与白色背景连通。

连续执行三次，结果一致：

```text
run=1 separated_white_subject=0/9
run=2 separated_white_subject=0/9
run=3 separated_white_subject=0/9
```

也就是说，主体内部 9 个本应计数的白色像素全部被前景分离阶段清成透明。该反馈循环具备以下性质：

- 直接调用线上使用的 `remove_connected_solid_background()`；
- 捕获用户描述的准确症状；
- 无随机依赖，结果确定；
- 单次运行小于一秒；
- 可转为 `tests/test_foreground_separation.py` 中的回归测试。

### 2.3 对“统计器漏算白色”的反证

把一个完全不透明的 3×3 白色前景直接交给量化器，结果为：

```text
bead_count = 9
color_count = 1
palette = ["H2"]
```

这证明：

- 白色可以正常映射到 MARD 色号；
- 白色格可以正常计入豆数；
- 故障发生在量化和统计之前，不应在统计模块中增加“白色特判”。

### 2.4 当前测试为什么没有发现问题

现有 `test_solid_background_removal_keeps_disconnected_white_subject_pixels` 只验证了“被红色区域完全包围的白色高光”。该白色区域与背景不连通，恰好符合 flood-fill 的理想条件。

缺少以下真实边界用例：

- 主体轮廓存在一个像素或一个采样单元的缺口；
- 白色主体直接接触画布边缘；
- 白色衣物与白底之间只有浅灰抗锯齿；
- AI 生成的外轮廓局部断裂；
- Seedream 返回少量透明像素，但绝大部分背景仍不透明。

最后一项还暴露出当前 Alpha 状态判断过宽：只要存在一个 Alpha 小于 128 的像素，就会把整张图标记为 `transparent`，可能跳过必要的背景验证。

## 3. 排序后的原因假设

### H1：边缘颜色 flood-fill 误删白色主体——已确认

预测：只要白色主体通过轮廓缺口与白底连通，白色主体就会被清为透明；闭合缺口后主体保留。

最小反馈循环已经验证前半部分。现有封闭高光测试验证了后半部分。

### H2：豆数或色号统计对白色做了特殊排除——已排除

预测：如果统计器是原因，不经过背景抠除的白色前景仍会缺少豆数或色号。

直接量化不透明白色得到 9 颗豆和 `H2` 色号，因此该假设不成立。

### H3：Prompt 没有要求合并颜色和保护轮廓——已排除

Prompt v7 已包含：

- 主体外轮廓优先；
- 合并相近颜色和摄影渐变；
- 删除零散高光、噪点色和小面积颜色；
- 不为了用满预算增加颜色。

因此问题不是“完全没有相关指令”，而是指令不够可执行，且下游算法没有保证这些目标。

### H4：BOX 缩格与面积权重共同削弱细轮廓——高可信，待效果集验证

机制预测：

- 窄于一个目标格的高对比线会被 BOX 平均为中间色；
- 即使线条在缩格后仍存在，小面积轮廓色对调色板选择的影响也低于大面积渐变色；
- 改为边缘感知采样并增加受限边缘权重后，轮廓连续率应提高。

该判断与代码实现一致，但仓库当前没有用户问题图片构成的固定效果集，不能把具体权重和阈值视为已验证参数。

### H5：颜色硬上限和极低边际收益阈值允许过多近似色——高可信，待 A/B

当前自动上限为 `52→30、78→54、104→54`，新增颜色的最小相对收益为 `0.001`。复杂渐变图可能持续选择收益很小的颜色。

预测：增加近似色约束或提高边际收益停止阈值后，实际颜色数与近似色对数量会下降；如果轮廓权重同时合理，主体识别度不应下降。

## 4. 目标与非目标

### 4.1 目标

- 白色、近白色和用户背景同色的主体仍获得 MARD 色号并计入豆数；
- 背景分离失败时返回明确错误，不生成统计错误但看似成功的施工图；
- 主体轮廓在目标网格中连续、清楚，并优先于摄影纹理；
- 合并无识别价值的近似色、渐变过渡色和低对比碎片；
- 保留眼睛、Logo、轮廓尖角等小面积但高辨识度的结构；
- 相同图片、参数和确定性策略产生相同网格结果；
- 保持 Solid 背景为独立渲染层，不进入 MARD 调色板和豆数。

### 4.2 非目标

- 不让 Seedream 直接输出 MARD 色号或最终网格；
- 不使用用户选择的白色背景作为抠图键色；
- 不通过简单降低背景色阈值宣称修复白色主体问题；
- 不无条件删除所有单格或双格组件；
- 不在缺少固定效果集时直接确定边缘权重、最小色差和清理阈值；
- 不同时上线 Prompt、采样、量化和清理的全部变化。

## 5. 模块设计

### 5.1 当前模块深度问题

转换路由当前必须了解：

- Seedream 是否返回 Alpha；
- 哪些 Alpha 状态需要 flood-fill；
- 背景颜色阈值配置；
- 图片对象何时关闭；
- `background_processing` 应写成哪个值。

这些知识同时散落在增强器、路由、预处理和响应组装中。删除当前背景后处理函数后，复杂度会重新出现在路由中，说明现有模块没有形成足够深的接口。

### 5.2 新的前景准备模块

新增深模块，例如：

```text
apps/api/src/pindou/imaging/foreground.py
```

其外部接口只暴露一次完整准备操作：

```python
@dataclass(frozen=True, slots=True)
class PreparedForeground:
    image: Image.Image
    processing: Literal["none", "native_alpha", "chroma_key"]
    confidence: float


def prepare_foreground(
    source: Image.Image,
    *,
    enhancer: ImageEnhancer,
    options: EnhancementOptions,
    policy: ForegroundPolicy,
) -> PreparedForeground: ...
```

接口不暴露 flood-fill 队列、颜色直方图、形态学操作或供应商细节。模块实现内部负责：

1. 调用增强器；
2. 验证上游 Alpha 覆盖率；
3. 验证内部键色覆盖率和连通性；
4. 生成二值或软 Alpha 蒙版；
5. 执行失败保护；
6. 记录可观测诊断；
7. 管理增强图的生命周期。

转换路由只消费 `PreparedForeground.image` 和稳定的处理元数据，不再选择背景算法。

### 5.3 增强器结果中的背景提示

Seedream 适配器需要把“请求了什么背景能力”传给前景准备模块：

```python
@dataclass(frozen=True, slots=True)
class BackgroundHint:
    kind: Literal["native_alpha", "chroma_key", "unknown"]
    chroma_key: tuple[int, int, int] | None = None


@dataclass(frozen=True, slots=True)
class EnhancementResult:
    image: Image.Image
    background_hint: BackgroundHint
```

`BackgroundHint` 只是待验证的提示，不是成功证明。即使 Seedream Prompt 请求了洋红键色，前景准备模块仍必须检查实际边缘是否主要由该颜色组成。

### 5.4 不提前引入不真实的适配器 seam

首期只有一个确定性前景准备实现，不为 flood-fill、键色和 Alpha 分别建立公开协议。它们是同一个深模块的内部策略。

只有后续实际引入本地 ONNX 主体分割后，才建立内部 `ForegroundMaskAdapter` seam：

- 生产适配器：ONNX 前景分割；
- 测试适配器：内存固定蒙版。

避免仅为“未来可能替换”增加浅接口。

## 6. Solid 背景的新处理策略

### 6.1 主路径：动态内部键色

用户选择的 Solid 背景只用于最终渲染。Seedream 使用独立的内部键色输出中间图。

候选键色建议从少量高饱和颜色中选择，例如：

```text
#00FF00  绿色
#FF00FF  洋红
#00FFFF  青色
#004CFF  蓝色
```

选择策略：

1. 从原图提取有限数量的主色观察；
2. 计算每个候选键色到主色集合的最小 CIEDE2000 距离；
3. 选择最小距离最大的候选色；
4. 如果所有候选色都与主体过近，标记为不能安全使用键色。

该颜色只进入 Seedream Prompt 和内部诊断，绝不进入公开 `background.color`。

### 6.2 Solid Prompt 调整

Solid 片段不再只要求不稳定的透明 Alpha，而改为：

```text
完整移除原背景及其中所有物体，只保留前景主体及其完整自然边缘。
将主体外全部区域替换为均匀、平坦、无渐变、无纹理、无阴影的 {chroma_key} 背景。
该颜色只允许出现在主体外背景，不得覆盖、替换或改变主体内部原有的白色、浅色或其他颜色。
主体与键色背景之间保持清楚、连续、无投影的边缘。
```

仍可请求透明 Alpha，但不能把 Alpha 当作唯一保证；已知键色是 Seedream 不返回有效 Alpha 时的确定性主路径。

### 6.3 键色蒙版生成

前景准备模块使用“已知键色 + 边缘连通”生成蒙版：

- 只从四边开始访问；
- 比较对象是已知键色，不再推断边缘最常见颜色；
- 色差建议使用 Lab/CIEDE2000，而不是原始 RGB 欧氏距离；
- 对抗锯齿边缘生成软 Alpha，再由网格采样阶段按覆盖率决定是否放豆；
- 只允许小尺度闭运算修复键色背景中的压缩孔洞，不对主体做大范围腐蚀或膨胀。

键色与白色主体差异足够大时，轮廓缺口不会再让 flood-fill 进入白色主体内部。

### 6.4 可信度与失败保护

首轮阈值必须通过效果集标定，建议至少观察：

- 四边键色覆盖率；
- 最大边缘连通背景占比；
- 前景占整图比例；
- 蒙版最大连通主体比例；
- 软边缘占比；
- 与请求键色的 P90 色差。

以下情况不得静默成功：

- Seedream 未输出有效 Alpha，也未遵循键色背景；
- 键色与主体主要颜色不可安全区分；
- 生成蒙版后前景接近全空或接近全满；
- 只有少量随机透明像素，却被误认为完整透明背景；
- 删除区域从边缘异常穿入主体核心。

首期返回稳定错误：

```text
AI_BACKGROUND_SEPARATION_FAILED
```

错误文案提示用户重试或改用 `keep/simplify`。不能回退到当前“猜边缘颜色并继续返回成功”的路径。

### 6.5 后续语义分割兜底

如果固定图集证明 Seedream 对键色遵循率不足，再引入本地 ONNX 前景分割模型作为兜底：

```text
有效 native Alpha
  → 直接使用
否则有效键色
  → 键色蒙版
否则 ONNX 分割可用且置信度合格
  → 分割蒙版
否则
  → 明确失败
```

上线 ONNX 前必须单独评估模型体积、冷启动、内存、CPU 延迟、人物/动物/物体覆盖率和商业许可，本方案不默认绑定某个模型。

## 7. Prompt v8：轮廓与颜色结构

### 7.1 Prompt 的职责

Prompt 只负责让中间图更适合网格化：

- 形成连续且有宽度的关键线条；
- 把摄影渐变归纳为有限明暗层；
- 合并无身份意义的近似颜色；
- 降低背景和装饰的视觉竞争。

Prompt 不负责精确颜色数、MARD 色号或最终豆数。

### 7.2 新增统一轮廓规则

建议在网格档位片段之后加入：

```text
轮廓与线条策略：
主体外轮廓必须使用稳定、连续、与相邻区域有明显明度或色相差异的颜色。
关键外轮廓在缩小后应覆盖至少约 1.5 个目标采样单元；决定身份的内部线条至少覆盖约 1 个目标采样单元。
预计缩小后不足一个采样单元的线条，应加粗为稳定结构，或在不影响身份时删除并入相邻色块。
不要用多条不同深浅的近似颜色模拟同一条轮廓、柔和阴影或抗锯齿过渡。
```

`micro` 档可把外轮廓目标提高到约 2 格；`large` 档可放宽，但仍禁止亚格级高频线条。

### 7.3 收紧颜色档位

颜色档位应明确限制同一结构的明暗层数：

| 档位 | 同一结构建议层级 | 策略 |
| --- | ---: | --- |
| `restrained` | 1–2 | 固有色为主，必要时仅保留一个暗面或亮面 |
| `balanced` | 2–3 | 固有色、主要亮面、主要暗面，合并中间过渡 |
| `rich` | 3–4 | 只保留有结构意义的层级，不恢复连续渐变 |

所有档位增加统一规则：肉眼难以区分、承担相同结构语义的颜色必须合并；不得用新颜色承担抗锯齿、压缩噪声或微弱光照变化。

### 7.4 版本

- 当前版本：`seedream-pindou-v9-chroma-despill`；v9 在 v8 的轮廓与近似色规则上
  增加 Solid 键色防色溢约束；
- Prompt 与量化 v3 使用独立版本号；
- 效果记录必须包含 Prompt 版本、网格档位、颜色档位、背景模式和键色；
- Prompt 生成约束不能替代确定性的软 Alpha 与去键色污染处理。

## 8. 网格采样与 MARD 量化 v3

### 8.1 保持稳定外部接口

HTTP 路由仍只调用 `build_bead_grid()`。采样描述、边缘权重、近似色约束和碎片清理全部保留为该深模块的实现细节。

内部可引入：

```python
@dataclass(frozen=True, slots=True)
class GridSample:
    rgb: tuple[int, int, int]
    alpha_coverage: float
    edge_strength: float
```

`GridSample` 不进入 HTTP 契约。

### 8.2 边缘感知缩格

替换单一 BOX 代表色时，不应直接改成中心点采样。推荐保留每个目标格覆盖的源像素分布：

1. 计算 Alpha 覆盖率；
2. 计算 Alpha 加权平均 Lab；
3. 计算占比最高的主色；
4. 计算高对比少数色占比和局部梯度；
5. 低梯度格继续使用平均色；
6. 高对比且少数边缘色达到覆盖阈值时，选择能延续邻格边缘的颜色。

必须比较：

- `box-mean`：当前基线；
- `edge-aware`：候选策略。

中心点采样对缩放相位过于敏感，不列为上线候选。

### 8.3 受限边缘权重

当前颜色观察主要按面积计权。量化 v3 增加：

```text
base_weight = alpha_coverage
edge_bonus = 1 + edge_weight × normalized_edge_strength
final_weight = clamp(base_weight × edge_bonus, min_weight, max_weight)
```

初始 A/B 只比较 `edge_weight = 0 / 0.5 / 1.0`，最终权重建议限制在 `0.5..3.0`。不得让少量轮廓完全支配整张图的调色板。

### 8.4 近似色抑制

不建议直接把颜色硬上限从 54 改成任意较小数字。更稳妥的第一步是同时记录并控制：

- 新颜色带来的相对误差收益；
- 新候选到已选颜色的最小 CIEDE2000；
- 候选主要服务的区域是否属于高对比边缘；
- 合并候选后总加权误差的增长。

推荐比较两种策略：

1. **选色阶段最小间距**：候选与已选颜色过近时跳过；
2. **选色后保守合并**：按色差从小到大尝试合并，并限制总误差增长。

首选第二种作为实验起点，因为它更容易记录“合并前后误差、颜色数和空间影响”，也允许保护高对比轮廓色。

实验阈值而非既定默认值：

```text
merge_delta_e = 4 / 6 / 8
max_relative_error_increase = 1% / 2% / 4%
```

只有同时满足以下条件才合并：

- 两种颜色视觉接近；
- 合并后误差增长在预算内；
- 不消除受保护的高对比边缘；
- 不把主体关键身份色并入背景色；
- 目标颜色已经存在于调色板，不新增色号。

### 8.5 边际收益停止

当前 `min_relative_gain=0.001` 需要进入效果集 A/B。候选值建议：

```text
0.001 / 0.003 / 0.005 / 0.01
```

不能仅以实际颜色数最少作为胜出标准。必须同时观察主体识别、轮廓召回和 P90 色差。

### 8.6 保守空间清理

近似色合并稳定后，最后加入 8 邻域小连通组件清理。面积 1–2 格的组件只有在以下条件全部满足时才替换：

- 不是高强度边缘；
- 不是 Alpha/主体轮廓边缘；
- 邻域主色占比达到阈值；
- 与邻域主色的 CIEDE2000 较小；
- 替换不会断开现有轮廓；
- 不属于受保护的小结构。

眼睛、高光、Logo、文字、轮廓尖角和细肢体端点不能仅因面积小而删除。

## 9. 数据契约与可观测性

### 9.1 公开响应

`foreground + background + stats` 的 schema v3 语义保持不变：

- `foreground.palette` 只包含主体实际色号；
- `foreground.rows` 的 `null` 表示无需放豆；
- `background.color` 只用于渲染；
- `stats.bead_count` 等于前景非空格数量。

如果新增 `background_processing` 值，需要扩展为：

```text
none | native_alpha | chroma_key | semantic_mask
```

删除 `edge_flood_fill` 作为新请求的正常成功路径。灰度期间可保留旧值用于历史流量观察。

### 9.2 内部指标

建议结构化记录：

前景分离：

- `background_processing`；
- `background_key_color`；
- `border_key_coverage`；
- `foreground_coverage`；
- `soft_edge_coverage`；
- `separation_confidence`；
- `separation_failure_reason`。

量化质量：

- `actual_color_count`；
- `near_color_pair_count`，按多个 ΔE 阈值记录；
- `small_component_cell_ratio`；
- `edge_cell_count`；
- `edge_palette_recall`；
- `mean_delta_e00` 与 `p90_delta_e00`；
- 合并前后颜色数和误差变化。

日志不得记录图片内容、完整 Prompt、Data URL 或密钥。

## 10. 测试与反馈循环

### 10.1 前景分离回归测试

在新的 `prepare_foreground()` 接口处测试可观察结果，不围绕内部 flood-fill 函数继续堆叠浅测试。

必须覆盖：

- 白色主体被完整深色轮廓包围；
- 白色主体通过一个像素缺口与白底连通；
- 白色主体接触画布边缘；
- 白色主体带浅灰抗锯齿；
- 主体包含与键色相近的小区域；
- 原图主体本身包含绿色、洋红、青色或蓝色；
- Seedream 正确返回 Alpha；
- Seedream 只有一个随机透明像素；
- Seedream 忽略键色要求；
- Seedream 实际键色偏离请求值并混入主体边缘；
- 蒙版接近全空或全满；
- 前景分离成功后，白色区域获得 MARD 色号且计入豆数。

原有只测试内部 flood-fill 理想场景的用例，应由深模块接口测试替代，而不是永久保留两套重复测试。

### 10.2 Prompt 单元测试

- 每次只包含一个网格档位、一个颜色档位和一个背景模式；
- Solid 模式包含已规范化的内部键色；
- 键色不等于公开背景颜色字段；
- 始终包含轮廓宽度、近似色合并和禁止抗锯齿过渡色规则；
- `keep/simplify` 不携带 Solid 键色指令；
- Prompt 版本升级为 v9，并包含禁止键色反射、色溢、彩色描边和半透明混色规则。

### 10.3 固定效果集

“颜色杂乱、线条不明显”目前没有仓库内可自动运行的用户样图反馈循环。实施量化 v3 前必须建立经过授权的固定效果集，至少包含：

- 白色或浅色主体 + 白底；
- 深色细轮廓 + 浅色大色块；
- 动漫人物、动物、几何物体、多人和复杂背景；
- 低对比主体、渐变丰富照片、已有平面插画；
- 52、78、104 三个主要网格；
- `solid/simplify/keep` 三种背景模式。

Seedream 存在随机性，每个组合至少运行三次。确定性采样和量化部分使用冻结后的 AI 输出，保证算法 A/B 不被生成随机性污染。

### 10.4 评估指标

| 维度 | 指标或人工问题 |
| --- | --- |
| 白色保留 | 白色主体格召回率、白色 MARD 色号与豆数是否正确 |
| 背景正确 | 背景残留率、主体误删率、严重失败率 |
| 轮廓质量 | 外轮廓连续率、关键线条召回率、断裂数量 |
| 色彩简洁 | 实际颜色数、近似色对数、同结构明暗层数 |
| 碎片控制 | 1–2 格低对比组件占比 |
| 色彩保真 | mean/P90 ΔE00、关键身份色是否保留 |
| 主体识别 | 盲评识别率与当前版本成对偏好 |
| 稳定性 | 三次生成的颜色数、轮廓和失败率波动 |

不建议预先承诺“颜色数下降 20%～35%”作为唯一验收条件。效果集建立后，先记录当前基线，再制定不会牺牲识别度的相对门槛。

### P0：锁定白色主体故障

### P2：Prompt v8

- 收紧三档明暗层级；

### P2.1：Prompt v9 与确定性去键色污染（已实施）

- Solid Prompt 明确输出完全不透明的平坦键色素材；
- 禁止键色环境光、反射、辉光、色溢、彩色描边和抗锯齿混色；
- 从边缘中位数估计 AI 实际键色，不假定输出严格等于请求 HEX；
- 以背景阈值、前景阈值和 smoothstep 生成连续软 Alpha；
- 仅处理与画布边缘连通的键色混合带，并反解其前景 RGB；
- 用确定性漂移键色与污染边缘图片建立回归测试。

完成标准：漂移后的纯键背景完全透明，污染边缘低于计豆占用阈值，主体中心保持
不透明；真实备份重放后不再产生由青色键污染导致的绿色边界豆。

实施验证：将 `1787759*-enhanced.png` 四张历史备份重新执行 v9 前景处理与
52×52 MARD 量化，四张图片的边界 `P3` 计数均为 `0`；前景处理置信度分别为
`0.889`、`0.835`、`0.750`、`1.000`。该重放只验证确定性后处理，不代替后续
Seedream Prompt v9 多次生成效果集。

- 冻结 AI 中间图；
- 加入边缘强度和受限权重；

## 13. 风险与决策

| 风险 | 处理策略 |
| --- | --- |
| Seedream 忽略键色 | 校验后明确失败；效果证明必要时增加语义分割兜底 |
| 主体包含候选键色 | 动态选择最大色差键色；不可安全选择时拒绝键色路径 |
| 键色污染主体软边缘 | 实际键色估计、归一化软 Alpha、边缘连通限制和 RGB 反混合 |
| Prompt 过度加粗改变身份 | 轮廓尺度按网格分档，保留语义不变量并盲评 |
| 边缘权重让黑色过度主导 | 权重裁剪并单变量 A/B |
| 近似色合并损失有意义明暗 | 限制误差增长并保护高对比边缘与身份色 |
| 碎片清理删除眼睛或 Logo | 仅清理低对比小组件，高对比和受保护区域跳过 |
| 一次修改过多无法归因 | 按 P1–P4 独立版本化和灰度 |

最终决策：**先把前景蒙版从“猜测背景颜色”升级为“验证已知背景能力”，再分别优化 AI 表达与确定性量化。** 白色主体正确性是数据契约问题，应优先于所有视觉质量调参。
