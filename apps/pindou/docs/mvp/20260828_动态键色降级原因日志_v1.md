# 动态键色降级原因日志技术方案

> 日期：2026-08-28  
> 版本：v1  
> 状态：已审查，已实施  
> 范围：通用结构化事件日志落盘能力，以及 `ENABLE_ONNX_MATTING=false` 时动态键色降级原因接入

## 1. 问题结论

当前 `build_validated_chroma_mask()` 在任一键色质量规则不满足时都只返回
`None`。`ForegroundPreparer` 因此只能对外暴露统一的：

```text
degraded=true
degrade_reason=foreground_low_confidence
```

实际触发降级的规则、观测值和阈值在返回 `None` 时丢失，现有
`foreground-metrics.json` 只能记录保守降级蒙版的结果，不能解释为什么完整验证失败。

## 2. 目标

- 对每次 `fallback_simplify` 记录精确的降级原因；
- 记录用于判定的观测值和策略阈值，可直接判断是键色偏差、边缘覆盖、
  背景覆盖还是过渡区触发降级；
- 新增仓库根目录 `log/`，日志与阶段图片备份分离；
- 日志落盘实现为通用事件日志模块，不依赖图像、键色或降级领域模型；
- 本期仅在动态键色降级时记录，不顺带扩大到其他业务事件；
- 不改变键色判定阈值、蒙版、降级语义和公开 API 响应。

## 3. 设计

### 3.1 保留键色校验失败结果

在 `imaging/chroma_key.py` 增加不可变的详细校验结果，由纯函数返回：

```python
@dataclass(frozen=True, slots=True)
class ChromaValidationFailure:
    reasons: tuple[str, ...]
    metrics: dict[str, float | int | str]


@dataclass(frozen=True, slots=True)
class ChromaValidationOutcome:
    result: ChromaMaskResult | None
    failure: ChromaValidationFailure | None
```

新增 `validate_chroma_mask()` 返回 `ChromaValidationOutcome`。现有
`build_validated_chroma_mask()` 保留为兼容包装，避免强制其他调用方处理诊断结果。

失败原因使用稳定机器码：

```text
actual_key_not_found
requested_key_delta_exceeded
border_coverage_below_minimum
edge_count_below_minimum
background_coverage_below_minimum
background_coverage_above_maximum
transition_coverage_above_maximum
```

如果同一阶段有多项失败，记录所有失败项，不只保留第一项。无法继续计算的早期
失败仅记录当前可得指标。Hint 缺失、类型错误或版本不匹配仍属于 422 协议错误，
不伪装成质量降级。

### 3.2 诊断字段

每次降级至少记录：

```text
event=foreground_degraded
request_id=<HTTP request id>
processing=fallback_simplify
degrade_reason=foreground_low_confidence
validation_failures=[...]
chroma_policy_version=solid-chroma-v1
requested_key=<HEX>
actual_key=<HEX，可用时>
requested_key_delta_e76=<value>
max_requested_key_delta_e76=<threshold>
border_coverage=<value>
min_border_coverage=<threshold>
edge_count=<value>
min_edge_count=<threshold>
background_coverage=<value>
min_background_coverage=<threshold>
max_background_coverage=<threshold>
transition_coverage=<value>
max_transition_coverage=<threshold>
fallback_mask=conservative-edge-key
```

未计算出的观测值省略，不写入误导性的 `0`。日志不包含用户图片、API Key、
原始 prompt 或其他敏感请求内容。

### 3.3 通用事件日志落盘

新增 `core/event_log.py` 通用模块，只封装事件日志的目录创建、安全序列化、
文件命名和独占创建。该模块不引用 `imaging`、`PreparedForeground` 或任何键色类型，
也不判断什么时候应该写日志。

通用接口为：

```python
def write_event_log(
    event: str,
    payload: Mapping[str, JSONValue],
    *,
    directory: Path,
) -> Path:
    ...
```

`event` 必须是受限的安全机器码；`payload` 只接受 JSON 标量、列表和字符串键映射。
模块拒绝非 JSON 类型和 `NaN/Infinity`，不隐式调用 `str()` 泄露任意对象内容。
业务字段白名单由调用方组装，通用模块不内置键色字段名。

本期 `conversions` 路由仅在 `prepared.degraded is True` 时调用一次，事件名为
`foreground_degraded`。日志写入失败是否影响业务由调用方决定；当前路由会捕获异常并
输出运行时异常日志，但继续返回已完成的图片转换结果。

默认目录：

```text
<repository>/log/
```

可通过通用配置 `EVENT_LOG_DIR` 覆盖，便于 Docker 挂载到宿主机。每个事件生成独立文件：

```text
{timestamp_ms}-{random_suffix}-{event}.json
```

请求传入的 `request_id` 只写入 JSON，不参与文件名拼接，避免路径注入。`event`
必须通过安全格式校验后才可进入文件名。文件使用 `xb` 独占创建，确保同进程并发请求
不互相覆盖。

`log/.gitignore` 忽略运行日志并保留目录本身。MVP 不引入自动清理；生产环境由容器
挂载和宿主机日志策略管理保留周期。

### 3.4 调用链

```text
validate_chroma_mask()
  → 返回完整蒙版或带观测值的失败原因
  → ForegroundPreparer 执行保守边缘键色蒙版
  → PreparedForeground.diagnostics 同时携带失败原因和降级蒙版指标
  → conversions 路由组装 foreground_degraded 事件载荷
  → 通用 write_event_log() 写入 log/*.json
```

现有 `foreground-metrics.json` 继续保留，并同步增加校验失败字段，便于与同时间戳的
Seedream 原图对照。`log/` 是通用事件日志目录；当前只会出现
`foreground_degraded` 事件，未来其他场景可复用落盘能力而无需修改模块。

## 4. 回归测试

### 4.1 键色验证

- 请求键色偏差超限时，返回 `requested_key_delta_exceeded` 及观测值/阈值；
- 键色只覆盖少数边时，返回 `border_coverage_below_minimum` 或
  `edge_count_below_minimum`；
- 用户反馈的“键色看起来正常但降级”场景，稳定暴露实际触发项；
- 验证成功时 `failure is None`，蒙版像素与现有实现完全一致。

### 4.2 通用事件日志持久化

- 临时目录不存在时自动创建；
- 两个同毫秒事件产生两个文件，内容不覆盖；
- 通用模块可写入不含任何键色字段的测试事件，证明模块无领域耦合；
- 非 JSON 对象、非有限浮点数和不安全事件名会被拒绝；
- 用户自定义 `request_id` 不能影响落盘路径。

### 4.3 API 集成

- 非降级请求不生成 `*-foreground_degraded.json`；
- 动态键色降级请求生成一份日志，包含响应头同款 `request_id`；
- 日志写入失败不影响转换响应；
- 原有 Alpha、调色板和豆子统计断言保持通过。

## 6. 验收标准

- 每次动态键色 `fallback_simplify` 都能在 `log/` 找到唯一对应的结构化日志；
- 日志明确给出失败规则、观测值和阈值，不再只显示
  `foreground_low_confidence`；
- 请求可通过 `request_id` 与日志关联；
- 不改变现有键色验证和保守蒙版的输出像素；
- 日志不包含图片二进制、API Key 或 prompt；
- 日志落盘模块可被任意业务事件复用，不依赖键色或降级代码；
- 本期只有 `foreground_degraded` 事件接入该通用模块；
- Ruff、相关回归和 API 全量测试通过。
