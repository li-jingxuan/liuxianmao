# 主体内部透明修复——封闭键色孔洞补充方案 v1

> 状态：已实施，待 `xiaozhan.png` 效果集验收
>
> 目标版本：MVP2 量化增强版
>
> 方案日期：2026-08-29
>
> 适用范围：`apps/api`，兼容现有 `apps/web` 转换接口

## 1. 背景与问题

当前 Solid 键色抠图只移除与画布边缘连通的近键色区域。这能避免误删主体内部与键色相近的衣物、装饰和纹理，但无法处理被主体完全包围的背景孔洞。

`1787917731997-foreground-final.png` 中，人物四肢、躯干和地面线条形成了多个封闭绿色空间。绿色区域与画布边缘不连通，因此被保留为不透明主体，导致最终前景内部出现键色。

该样本的键色估计和边缘验证均正常：实际键色为 `#16E244`，边缘覆盖率约 `99.5%`。问题属于背景拓扑识别缺口，不是请求键色漂移或色差阈值不足。

## 2. 目标

1. 移除主体包围且具有独立背景证据的高置信度键色孔洞。
2. 保留主体内部可能与键色接近的真实像素，避免全图近色替换。
3. 封闭孔洞边缘仍保留有限软过渡，不产生明显锯齿或彩边。
4. ONNX 只为候选孔洞提供独立证据，不重新取得普通主体或最终全局 Alpha 所有权。
5. 保持 `ForegroundPreparer.prepare()` 外部接口和 Keep、Simplify 模式不变。
6. ONNX 开启、关闭和不可用三条 Solid 路径统一穿过同一个 Alpha 深模块。

## 3. 非目标

1. 不处理玻璃、薄纱、烟雾等真实透明材质。
2. 不使用全图阈值或简单形态学闭运算直接填充所有区域。
3. 不因为单个孤立近键色像素就扩大透明区域。
4. 不允许 ONNX 单独决定普通主体核心或最终全局 Alpha。
5. 不承诺仅靠单张键色 RGB 图同时实现孔洞全召回和纯键色主体零误删。

## 4. 产品决策与证据边界

仅凭单张键色 RGB 图的颜色、面积和拓扑，无法可靠区分：

- 被人物四肢、躯干或物体轮廓包围的真实键色背景孔洞；
- 位于主体内部、恰好使用同一纯键色的衣服、眼睛、Logo、首饰或装饰。

两者都可能表现为“纯键色、内部均匀、不接触画布边缘、四周被非键色主体包围”。
因此本方案明确采用“宁可漏删孔洞，也不误删主体”的保守策略：

1. 主体误删优先级高于孔洞召回；证据不足时保留候选区域。
2. 颜色、面积、拓扑和边界包围性只负责提出并过滤候选，不能单独完成最终接受。
3. 候选还必须获得独立背景证据。首版独立证据来自通过全局质量检查的 ONNX 蒙版。
4. ONNX 只对候选孔洞给出确认或否决证据，不得降低普通主体核心 Alpha，也不得恢复明确背景。
5. ONNX 关闭、声明不可用或全局质量不合格时，歧义孔洞保持不透明；这是安全拒绝，不是处理失败。

若后续引入原图对齐、实例分割或更可靠的语义分割证据，可以在不改变
`compose_solid_alpha()` 外部 interface 的前提下替换内部证据实现。

## 5. 术语与区域模型

对实际键色计算不考虑连通性的原始键色 Alpha `A_key_raw`：

```text
A_key_raw = round(
    clamp(
        (delta_e76(pixel, actual_key) - background_delta_e76)
        / (foreground_delta_e76 - background_delta_e76),
        0,
        1,
    ) * 255
)
```

`A_key_raw` 只表达像素与实际键色的颜色距离；`A_chroma` 是在其基础上只对边缘连通
背景生效的现有保护性软蒙版。封闭孔洞的软边缘必须使用 `A_key_raw`，不能使用因
不连通而被整体保留为 `255` 的 `A_chroma`。

基于 `A_chroma` 生成：

```text
明确背景候选：A_chroma <= 32
主体候选：A_chroma >= 224
过渡区域：32 < A_chroma < 224
```

主体区域进一步拆分为两类，避免把“接近键色但被旧蒙版保留”的像素无条件当成
可信主体：

```text
可信主体核心 C_trusted：A_chroma >= 224 且 delta_e76 >= trusted_subject_min_delta_e76
歧义主体核心 C_ambiguous：A_chroma >= 224 但颜色仍接近实际键色
```

只有 `C_trusted` 拥有不可被孔洞检测覆盖的最高优先级。满足全部颜色与拓扑条件、
并获得独立背景证据的组件可以覆盖 `C_ambiguous`；证据不足时继续保留。

现有算法得到的边缘连通背景记为 `B_edge`。本方案新增封闭孔洞集合 `B_hole`：满足质量条件、但不与画布边缘连通的近键色连通域。

最终明确背景为：

```text
B = B_edge ∪ B_hole
```

主体核心和边缘带仍按现有保护性 Alpha 合成规则处理。

数字拓扑固定使用背景 4 邻域、主体 8 邻域的互补连通性，避免对角接触区域同时被
主体和背景解释为封闭。

## 6. 封闭孔洞识别

### 6.1 候选区域

使用“严格种子 + 宽松扩张”双阈值生成候选，避免用同一个阈值定义组件后又用同一
阈值验证颜色一致性，导致该指标恒为 `100%`：

```text
hole_seed = delta_e76(pixel, actual_key) <= hole_seed_delta_e76
hole_growth = delta_e76(pixel, actual_key) <= hole_growth_delta_e76
```

先从 `hole_seed` 中选择种子，再只在 `hole_growth` 内执行受限区域生长。候选区域进行
4 邻域连通域分析；已属于 `B_edge` 的区域不重复处理，只分析未与画布边缘连通的
组件。背景固定使用 4 邻域，主体证据使用 8 邻域；测试必须明确覆盖两种连通性结果
不同的对角接触用例。

### 6.2 接受条件

一个封闭组件必须先通过以下候选条件：

1. **严格种子占比**：组件内 `hole_seed` 像素占比达到阈值，避免仅由宽松阈值聚合出孔洞。
2. **边界包围性**：组件边界与 `C_trusted` 按主体 8 邻域相邻的比例达到阈值；不得仅使用 `A_chroma >= 128` 作为主体证据，避免循环依赖旧蒙版结论。
3. **面积约束**：组件面积大于最小像素面积且小于最大画布占比；过小区域视为噪点，过大区域视为背景验证异常。
4. **内部均匀性**：组件颜色分布的距离分位数不能过宽，排除具有明显纹理的主体区域。
5. **主体分离性**：组件内部不得含有超过阈值的可信主体碎片，边界中也不得以过渡区域为主，避免一条细线、网格或装饰被整块清除。
6. **原尺寸复核**：若连通域在降采样图上发现，必须映射回原图并重新检查触边性、面积、严格种子占比和可信主体碎片。

通过候选条件后，还必须满足：

7. **独立背景支持**：ONNX 蒙版在组件内部判断为背景的像素占比达到阈值。
8. **独立主体否决**：ONNX 在组件内部存在超过阈值的高置信主体像素时拒绝该组件。

只有 1–8 全部满足时组件才加入 `B_hole`。缺少 ONNX、ONNX 全局质量不合格或证据
冲突时，组件以 `independent_evidence_unavailable` 或
`independent_subject_evidence_present` 安全拒绝。

建议首版策略阈值集中在版本化 `SolidAlphaPolicy`：

```text
hole_seed_delta_e76 = 10
hole_growth_delta_e76 = 18
trusted_subject_min_delta_e76 = 28
min_hole_area_fraction = 0.0002
max_hole_area_fraction = 0.15
min_trusted_subject_boundary_ratio = 0.60
min_hole_seed_fraction = 0.60
max_hole_color_p90_delta_e76 = 12
max_transition_boundary_ratio = 0.35
max_internal_subject_fragment_fraction = 0.01
min_onnx_hole_background_support = 0.90
max_onnx_hole_subject_support = 0.05
```

阈值只由策略版本控制，请求端不能逐项覆盖。

阈值必须保持：

```text
background_delta_e76
  < hole_seed_delta_e76
  < hole_growth_delta_e76
  < trusted_subject_min_delta_e76
```

### 6.3 防误删规则

以下情况不得判定为封闭背景孔洞：

- 组件与画布边缘相连但边缘验证已失败；
- 组件面积超过最大占比；
- 组件边界主要接触过渡区域而非明确主体；
- 组件内部颜色分散，呈现主体纹理或阴影；
- 组件被主体候选中的细线、网格或装饰穿过；
- 连通域分析因缩放造成拓扑变化，原尺寸复核无法通过。
- 独立背景支持不足；
- 独立主体证据超过否决阈值。

纯键色衣服、眼睛、Logo、首饰等真实主体区域是最高风险反例。即使它们被明显非键色
主体完整包围，也不能仅凭“封闭、纯色、面积和边界合格”判定为背景；必须获得独立
背景支持且不存在独立主体否决，否则保留。

## 7. 软 Alpha 处理

封闭孔洞不直接整块写成硬透明。对已接受组件生成距离场，并按图片短边计算
`hole_feather_radius = clamp(round(short_side / 256), 1, 4)`：

令 `d` 为组件像素到组件边界的向内距离：

1. `d >= hole_feather_radius` 的区域定义为 `hole_interior`，固定为 `Alpha=0`。
2. 其余区域定义为 `hole_boundary`，计算：

```text
distance_cap(d) = round(
    255 * max(0, 1 - d / hole_feather_radius)
)

hole_boundary_alpha = min(A_key_raw, distance_cap(d))
```

3. `C_trusted` 始终恢复为 `Alpha=255`；已接受孔洞可以覆盖 `C_ambiguous`，不能覆盖 `C_trusted`。
4. ONNX 只能在普通主体外轮廓边缘带补充 Alpha；不得在 `hole_interior` 或 `hole_boundary` 中把已确认孔洞重新变为主体。

最终赋值顺序必须固定，后执行者优先：

```text
以 A_chroma 初始化
→ 普通外轮廓执行 ONNX 边缘补充
→ 写入孔洞内部和孔洞软边缘
→ 最后恢复 C_trusted=255
```

## 8. ONNX 协作与运行状态

继续计算现有 ONNX 一致性指标：

- `onnx_subject_recall`
- `onnx_chroma_iou`
- `onnx_false_positive_background`
- `onnx_core_transparent_coverage`

新增孔洞诊断指标：

- `chroma_hole_candidates`
- `chroma_hole_accepted`
- `chroma_hole_coverage`
- `onnx_hole_background_support`
- `onnx_hole_subject_support`
- `chroma_hole_rejected_reasons`

由于颜色和拓扑无法消除纯键色主体歧义，ONNX 对候选孔洞承担独立证据角色，但仍不能
绕过颜色、面积、包围性和主体分离条件：

- `onnx_hole_background_support` 定义为组件中 `A_onnx < 128` 的像素占比；
- `onnx_hole_subject_support` 定义为组件中 `A_onnx >= 224` 的像素占比；
- ONNX 背景支持不足或主体支持超限：拒绝该组件；
- ONNX 未启用：不运行 Adapter，保留歧义孔洞；
- ONNX Adapter 声明不可用：记录结构化告警并保留歧义孔洞；
- ONNX 全局质量不合格：不使用其孔洞证据，保留歧义孔洞；
- ONNX 模型文件损坏、Runtime 异常、输出尺寸或数值非法：按基础设施错误向上暴露，不能静默伪装成普通质量拒绝。

ONNX 对普通主体和外部背景仍只是保护性边缘辅助，不能直接成为最终 Alpha。

## 9. 深模块与 seam

所有 Solid Alpha 语义集中在 `pindou.imaging.solid_alpha`。该模块只公开一个外部
interface：

```python
def compose_solid_alpha(
    image: Image.Image,
    hint: BackgroundHint,
    onnx_mask: Image.Image | None,
    *,
    policy: SolidAlphaPolicy,
) -> SolidAlphaOutcome:
    ...
```

实际键色估计、`A_key_raw`、边缘连通背景、可信主体核心、孔洞检测、软 Alpha 和不变量
都是内部实现。`detect_enclosed_chroma_holes()` 如需拆分，只能是私有内部 seam，调用方
和集成测试不得依赖其参数或中间数组。

`ForegroundPreparer` 只负责增强器调用、可选 ONNX Adapter 调用、错误映射和 Pillow
生命周期。三种配置状态都必须调用同一 interface：

```text
ONNX 开启且成功 → compose_solid_alpha(..., onnx_mask=mask)
ONNX 关闭       → compose_solid_alpha(..., onnx_mask=None)
ONNX 声明不可用 → 记录告警后 compose_solid_alpha(..., onnx_mask=None)
```

不得保留 `_prepare_with_chroma()` 直接应用旧键色蒙版、绕过深模块的第二套 Solid Alpha
路径。`solid_alpha` 也不得导入 `chroma_key` 中以下划线开头的私有函数；键色计算应合并
到深模块内部，或由 `chroma_key` 返回正式、完整的证据结果。

结果中的诊断类型统一为：

```python
metrics: dict[str, JSONValue]
```

这样才能合法承载拒绝计数和有限组件摘要，不能继续限制为仅标量值。

## 10. 测试方案

测试主要通过 `compose_solid_alpha()` 的外部 interface 断言最终蒙版、策略、失败和诊断；
不得通过私有连通域函数的中间数组固化实现。`ForegroundPreparer` 只保留 seam 接线、
错误映射和资源所有权集成测试。

旧的“ONNX Alpha 直接作为最终 Alpha”和“关闭 ONNX 绕过深模块”测试必须删除或改写，
不能与新 interface 测试叠加保留。

至少增加以下测试：

1. 人物双腿之间的封闭纯键色区域在独立背景证据合格时透明化。
2. 手臂与躯干之间的封闭键色区域在独立背景证据合格时透明化。
3. 主体衣服内部近键色但有纹理的区域保持不透明。
4. 小面积孤立键色噪点不触发孔洞透明化。
5. 超大封闭区域被拒绝并返回稳定诊断原因。
6. ONNX 低召回或孔洞背景支持不足时拒绝孔洞，不影响主体核心不透明。
7. `1787917731997-foreground-final.png` 在独立背景证据合格时，检查已知孔洞坐标的 Alpha 为 `0`，主体核心 Alpha 为 `255`。
8. 完全封闭的纯键色衣服、眼睛、Logo 和首饰在独立主体证据存在或背景证据不足时保持不透明。
9. 孔洞中存在一像素细线、网格或装饰时，不得整块清空主体结构。
10. 抗锯齿边界存在断点、对角连接或 JPG 压缩噪声时，不错误合并孔洞与外部背景。
11. 多个候选中允许部分接受、部分拒绝，并分别输出稳定诊断。
12. 孔洞贴近但不接触画布边缘、极小图和高分辨率图行为稳定。
13. ONNX 全黑、全白、全局质量不合格和声明不可用时安全拒绝歧义孔洞；尺寸或数值非法时返回基础设施错误。
14. 同一素材在不同输入尺寸下的孔洞覆盖率和主体误删率处于约定容差内。
15. ONNX 关闭路径仍穿过 `compose_solid_alpha()`，保留歧义孔洞且主体核心不透明。

真实素材不能只断言少量坐标，还应维护三类标注蒙版：期望孔洞区域、必须保护的主体
区域和允许变化的边缘容差带，并计算孔洞召回率、主体误删率和边缘差异率。

## 11. 验收标准

- ONNX 全局质量合格且孔洞背景支持达标时，标注孔洞区域召回率不低于 `95%`。
- ONNX 关闭、声明不可用或证据不足时安全保留歧义孔洞，不用颜色和拓扑强行删除。
- 标注保护主体区域误删率不超过 `0.1%`，任何单个身份性 Logo、眼睛或首饰不得整体消失。
- 普通主体核心中 `Alpha < 250` 的比例不超过 `0.1%`。
- 明确背景中 `Alpha > 5` 的比例不超过 `0.5%`。
- 允许变化边缘带之外的 Alpha 差异率不超过 `1%`。
- 同一素材在两个约定输入尺寸下的孔洞覆盖率差异不超过 `1%`。
- ONNX 开启、关闭和声明不可用三种情况下，普通主体核心不透明不变量均成立。
- 典型尺寸 P95 耗时与最大尺寸峰值内存先记录基线，再由发布评审冻结预算。
- API 全量测试、Ruff 和 Compose 配置校验通过。
- 失败时返回结构化诊断，不输出不满足不变量的图片。

## 12. 失败语义与诊断

孔洞检测采用组件级拒绝，不因普通候选不合格而破坏已经验证成功的键色结果：

- 没有发现孔洞：正常成功，`chroma_hole_candidates=0`；
- 候选全部被拒绝：正常成功，沿用原始保护性键色 Alpha；
- 独立证据缺失或冲突：只拒绝对应组件，记录安全拒绝原因；
- 单个组件面积、颜色或包围性不合格：只拒绝该组件；
- 组件异常大：拒绝该组件并记录 `hole_area_above_maximum`，不自动使整张图失败；
- 数组尺寸不一致、出现无效数值、可信主体核心被破坏或最终 Alpha 不变量失败：整张图处理失败，不输出损坏图片。

拒绝原因应按计数聚合，避免日志中出现大量重复字符串：

```json
{
  "chroma_hole_rejected_counts": {
    "area_below_minimum": 12,
    "color_inconsistent": 2,
    "trusted_subject_boundary_below_minimum": 1,
    "independent_evidence_unavailable": 3,
    "independent_subject_evidence_present": 1
  }
}
```

组件级诊断最多记录按面积排序的前 `N` 个组件，至少包含面积、覆盖率、严格种子占比、
颜色距离 P90、可信主体边界比例、内部主体碎片占比、ONNX 背景支持度、ONNX 主体
支持度和最终结论。

## 13. 性能与尺寸约束

连通域处理必须有明确资源边界：

1. 记录输入尺寸、候选像素数、候选组件数和孔洞检测耗时。
2. 设置最大候选组件数量和诊断组件数量；超过上限时安全停止孔洞补充，沿用原始键色结果，不得扩大删除范围。
3. 避免在高分辨率图片上保存每个像素的 Python 元组；优先复用扫描线连通域实现或使用数组化实现，不为单一实现引入没有替代者的 Adapter seam。
4. 如为性能需要采用降采样检测，降采样只负责提出候选，最终接受必须在原尺寸上复核。
5. 增加典型尺寸和允许最大尺寸的性能回归测试，并在策略版本调整时记录耗时与峰值内存。

## 14. 发布、回滚与实施顺序

策略语义升级后，将 `SolidAlphaPolicy.version` 提升为 `solid-alpha-v2`，不得在相同版本
号下静默改变阈值和孔洞接受规则。发布日志至少观察孔洞候选率、接受率、独立证据
缺失率、主体证据冲突率、主体保护误删率和处理耗时。

线上出现误删时，优先关闭孔洞接受并保留原有边缘连通键色结果；不得回滚到
“ONNX 直接拥有全局 Alpha”。

1. 将 ONNX 开启、关闭和声明不可用路径统一到 `compose_solid_alpha()`，删除绕过深模块的旧路径和过期测试。
2. 补齐 `A_key_raw`、双阈值区域生长、可信主体核心、独立证据和结构化结果的 interface 测试。
3. 实现孔洞内部与软边缘的固定赋值顺序，验证最终 Alpha 不变量。
4. 加入真实素材标注蒙版、尺寸稳定性、基础设施错误和性能回归。
5. 固定策略 v2 阈值、性能预算和发布基线后，把状态更新为“已实施，待效果集验收”。

在上述真实效果集验收完成前，本方案保持“已实施，待效果集验收”，不能仅凭已知样本
的少量坐标变透明就标记为“已验收”。

## 15. 实施结果
