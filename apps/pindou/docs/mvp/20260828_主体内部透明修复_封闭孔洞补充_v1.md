# 主体内部透明修复——封闭键色孔洞补充方案 v1

## 1. 背景与问题

当前 Solid 键色抠图只移除与画布边缘连通的近键色区域。这能避免误删主体内部与键色相近的衣物、装饰和纹理，但无法处理被主体完全包围的背景孔洞。

`1787917731997-foreground-final.png` 中，人物四肢、躯干和地面线条形成了多个封闭绿色空间。绿色区域与画布边缘不连通，因此被保留为不透明主体，导致最终前景内部出现键色。

该样本的键色估计和边缘验证均正常：实际键色为 `#16E244`，边缘覆盖率约 `99.5%`。问题属于背景拓扑识别缺口，不是请求键色漂移或色差阈值不足。

## 2. 目标

1. 移除主体包围的高置信度键色背景孔洞。
2. 保留主体内部可能与键色接近的真实像素，避免全图近色替换。
3. 封闭孔洞边缘仍保留有限软过渡，不产生明显锯齿或彩边。
4. ONNX 只作为孔洞判定的辅助证据，不重新取得最终 Alpha 所有权。
5. 保持 `ForegroundPreparer.prepare()` 外部接口和 Keep、Simplify 模式不变。

## 3. 非目标

1. 不处理玻璃、薄纱、烟雾等真实透明材质。
2. 不使用全图阈值或简单形态学闭运算直接填充所有区域。
3. 不因为单个孤立近键色像素就扩大透明区域。
4. 不允许 ONNX 单独决定封闭孔洞或主体 Alpha。

## 4. 术语与区域模型

基于现有键色软蒙版 `A_chroma`，先生成：

```text
明确背景候选：A_chroma <= 32
主体候选：A_chroma >= 224
过渡区域：32 < A_chroma < 224
```

现有算法得到的边缘连通背景记为 `B_edge`。本方案新增封闭孔洞集合 `B_hole`：满足质量条件、但不与画布边缘连通的近键色连通域。

最终明确背景为：

```text
B = B_edge ∪ B_hole
```

主体核心和边缘带仍按现有保护性 Alpha 合成规则处理。

## 5. 封闭孔洞识别

### 5.1 候选区域

使用较严格的近键色阈值生成候选：

```text
hole_candidate = delta_e76(pixel, actual_key) <= hole_delta_e76
```

候选区域进行 4 邻域连通域分析。已属于 `B_edge` 的区域不重复处理；只分析未与画布边缘连通的组件。

### 5.2 接受条件

一个封闭组件只有同时满足以下条件才加入 `B_hole`：

1. **颜色一致性**：组件内近键色像素占比达到阈值，避免把主体渐变误识别为孔洞。
2. **边界包围性**：组件边界与明确主体候选或主体核心相邻的比例达到阈值，证明它是被主体包围的空间。
3. **面积约束**：组件面积大于最小像素面积且小于最大画布占比；过小区域视为噪点，过大区域视为背景验证异常。
4. **内部均匀性**：组件颜色分布的距离分位数不能过宽，排除具有明显纹理的主体区域。
5. **主体分离性**：组件与主体候选之间存在稳定边界，不允许通过窄噪声连接误填充。

建议首版策略阈值集中在版本化 `SolidAlphaPolicy`：

```text
hole_delta_e76 = 18
min_hole_area_fraction = 0.0002
max_hole_area_fraction = 0.15
min_subject_boundary_ratio = 0.60
min_hole_color_consistency = 0.90
max_hole_color_p90_delta_e76 = 12
```

阈值只由策略版本控制，请求端不能逐项覆盖。

### 5.3 防误删规则

以下情况不得判定为封闭背景孔洞：

- 组件与画布边缘相连但边缘验证已失败；
- 组件面积超过最大占比；
- 组件边界主要接触过渡区域而非明确主体；
- 组件内部颜色分散，呈现主体纹理或阴影；
- 组件被主体候选中的细线、网格或装饰穿过；
- 连通域分析因缩放造成拓扑变化，原尺寸复核无法通过。

## 6. 软 Alpha 处理

封闭孔洞不直接整块写成硬透明：

1. 孔洞内部明确键色区域固定为 `Alpha=0`。
2. 沿孔洞边界保留 1–4 px 的键色软过渡。
3. 主体核心优先级高于孔洞候选；核心区域不得因孔洞检测降低 Alpha。
4. ONNX 只能在孔洞边缘带提供额外 Alpha，不能把已确认孔洞重新变为主体。

最终优先级：

```text
主体核心不透明 > 明确背景透明 > 边缘软 Alpha
```

## 7. ONNX 协作

继续计算现有 ONNX 一致性指标：

- `onnx_subject_recall`
- `onnx_chroma_iou`
- `onnx_false_positive_background`
- `onnx_core_transparent_coverage`

新增孔洞诊断指标：

- `chroma_hole_candidates`
- `chroma_hole_accepted`
- `chroma_hole_coverage`
- `onnx_hole_background_support`
- `chroma_hole_rejected_reasons`

ONNX 对孔洞的背景判断只用于提高或降低诊断置信度；即使 ONNX 判断为背景，也不能绕过键色孔洞的颜色一致性、边界包围性和面积约束。

## 8. 模块落点

继续将逻辑集中在 `pindou.imaging.solid_alpha`：

```python
def compose_solid_alpha(...): ...

def detect_enclosed_chroma_holes(
    chroma_alpha: np.ndarray,
    actual_key_rgb: tuple[int, int, int],
    subject_mask: np.ndarray,
    *,
    policy: SolidAlphaPolicy,
) -> HoleDetectionResult: ...
```

`ForegroundPreparer` 只负责传递增强图、ONNX 原始蒙版、失败映射和资源关闭，不复制孔洞算法。

## 9. 回归测试

至少增加以下测试：

1. 人物双腿之间的封闭纯键色区域被透明化。
2. 手臂与躯干之间的封闭键色区域被透明化。
3. 主体衣服内部近键色但有纹理的区域保持不透明。
4. 小面积孤立键色噪点不触发孔洞透明化。
5. 超大封闭区域被拒绝并返回稳定诊断原因。
6. ONNX 低召回时仍能移除合格孔洞，不影响主体核心不透明。
7. `1787917731997-foreground-final.png` 作为固定回归样本，检查已知孔洞坐标的 Alpha 为 `0`，主体核心 Alpha 为 `255`。

## 10. 验收标准

- 已知样本中的主体内部绿色封闭空间不再出现在最终前景中。
- 主体核心 `Alpha < 250` 占比不超过 `0.1%`。
- 明确背景 `Alpha > 5` 占比不超过 `0.5%`。
- 不引入全图近键色误删。
- ONNX 开启、关闭、不可用三种情况下，Solid 的主体核心不透明不变量均成立。
- 失败时返回结构化诊断，不输出不满足不变量的图片。
