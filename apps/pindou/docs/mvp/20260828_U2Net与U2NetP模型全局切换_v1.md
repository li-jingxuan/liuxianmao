# U²-Net 与 U²-NetP 模型全局切换技术方案 v1

## 1. 背景

当前 ONNX 前景分割使用轻量版 U²-NetP。为提高主体分割和边缘细节质量，需要将默认模型升级为完整 U²-Net，同时保留 U²-NetP，便于在资源不足、延迟升高或线上效果异常时快速回退。

本次只调整 ONNX 前景蒙版模型的选择和资产管理，不改变 Seedream 动态键色生成、键色检查、降级日志以及后续 Alpha 合成流程。

## 2. 目标

1. `ENABLE_ONNX_MATTING=true` 时，默认使用完整 U²-Net 生成前景蒙版。
2. 保留现有 U²-NetP 模型，可通过一个全局环境变量切换，无需修改代码或重新构建镜像。
3. 两种模型共用同一个 `ForegroundMaskAdapter` 接口和 ONNX 推理实现，业务层不感知具体模型。
4. 模型文件、元数据和 SHA256 校验必须一一对应，避免配置串线后静默加载错误模型。
5. 服务启动时完成所选模型的加载和预热；模型缺失、元数据错误或校验失败时保持启动失败，不静默换用另一模型。

## 3. 非目标

1. 不改变 `ENABLE_ONNX_MATTING` 的总开关语义。
2. 不调整 Seedream 提示词、键色检查规则或 ONNX 低置信度降级策略。
3. 不同时加载两个模型，也不在单次请求中自动择优或级联推理。
4. 不以主观样例断言 U²-Net 必然优于 U²-NetP；质量结论由后续真实素材对比确定。

## 4. 全局配置

新增环境变量：

```dotenv
FOREGROUND_MODEL_VARIANT=u2net
```

允许值：

| 值 | 含义 | 使用场景 |
| --- | --- | --- |
| `u2net` | 完整 U²-Net | 默认值，优先保证分割质量 |
| `u2netp` | 轻量 U²-NetP | 资源受限、延迟回退或效果回滚 |

配置约束：

- 值统一转为小写后校验；其他值在配置加载阶段直接报错。
- `FOREGROUND_MASK_ADAPTER` 只表达适配器类型，ONNX 实现统一使用 `onnx`，不再在适配器名称中携带具体模型名。
- 模型变体只有 `FOREGROUND_MODEL_VARIANT` 一个选择来源，避免同时配置变体和通用模型路径导致歧义。
- `ENABLE_ONNX_MATTING=false` 时不加载模型；重新启用后按当前变体加载。

推荐部署配置：

```dotenv
ENABLE_ONNX_MATTING=true
FOREGROUND_MASK_ADAPTER=onnx
FOREGROUND_MODEL_VARIANT=u2net
```

回退只需将 `FOREGROUND_MODEL_VARIANT` 改为 `u2netp` 并重启服务。

## 5. 模型资产

目录调整为：

```text
apps/api/models/foreground/
├── LICENSE
├── README.md
├── u2net.onnx
├── u2net.json
├── u2netp.onnx
└── u2netp.json
```

其中现有 `model.json` 改名为 `u2netp.json`，避免共享文件名无法表达模型对应关系。

每份元数据至少包含：

- 模型名称和版本；
- ONNX 文件 SHA256；
- 输入尺寸、归一化参数和颜色通道顺序；
- 输出节点和输出激活语义；
- 模型来源、许可证和获取地址。

完整 U²-Net 模型使用与当前 U²-NetP 相同来源体系的已发布 ONNX 资产，下载后计算并固定 SHA256。由于完整模型超过 GitHub 普通单文件上限，源码仓库保存元数据和下载脚本，Docker 构建阶段下载并校验模型。模型二进制最终随镜像一起发布，确保切换变体时不依赖运行时网络。本地开发也通过同一脚本生成被 Git 忽略的模型文件。

## 6. 代码设计

### 6.1 模型注册表

在配置层维护只读模型注册表：

```python
FOREGROUND_MODEL_ARTIFACTS = {
    "u2net": ForegroundModelArtifact(
        model_path=".../u2net.onnx",
        metadata_path=".../u2net.json",
    ),
    "u2netp": ForegroundModelArtifact(
        model_path=".../u2netp.onnx",
        metadata_path=".../u2netp.json",
    ),
}
```

`Settings` 只保存已校验的 `foreground_model_variant`。依赖装配时通过注册表解析模型路径，不再由部署环境分别拼装模型文件和元数据路径。

这样可保证：

- 变体与资产映射集中维护；
- 业务调用方只依赖 `ForegroundMaskAdapter`；
- 模型切换不会扩散到图片处理主流程；
- 模型文件和元数据不会被跨模型误配。

### 6.2 ONNX 适配器

保留一个通用 `OnnxForegroundMaskAdapter`，不为 U²-Net 和 U²-NetP 分别复制推理代码。适配器继续从元数据读取输入输出约定，并新增期望模型名校验：

1. 校验模型文件和元数据存在；
2. 校验模型文件 SHA256；
3. 校验元数据中的模型名等于全局选择的变体；
4. 创建 ONNX Runtime CPU 会话；
5. 校验输入、输出节点和张量形状；
6. 执行一次预热推理。

适配器模块中的说明同步从“U²-NetP 专用”改为“U²-Net 系列通用”。

### 6.3 依赖装配

`get_foreground_mask_adapter()` 的装配逻辑调整为：

```text
ENABLE_ONNX_MATTING=false
  -> DisabledForegroundMaskAdapter

ENABLE_ONNX_MATTING=true 且 FOREGROUND_MASK_ADAPTER=unavailable
  -> UnavailableForegroundMaskAdapter

ENABLE_ONNX_MATTING=true 且 FOREGROUND_MASK_ADAPTER=onnx
  -> 根据 FOREGROUND_MODEL_VARIANT 解析资产
  -> OnnxForegroundMaskAdapter
```

模型版本仍通过现有结果字段和指标输出，因此线上日志及监控可识别本次请求实际使用的是 U²-Net 还是 U²-NetP。

## 7. 部署调整

1. Docker 镜像先复制 `apps/api/models`，再通过固定来源和 SHA256 的脚本下载完整 U²-Net；运行容器无需额外挂载或联网。
2. `deploy/compose.yaml` 删除写死的 U²-NetP 模型路径，新增：

   ```yaml
   FOREGROUND_MODEL_VARIANT: ${FOREGROUND_MODEL_VARIANT:-u2net}
   ```

3. `.env.example` 默认配置为 `u2net`，并注明 `u2netp` 回退方法。
4. 部署文档补充完整 U²-Net 会增加镜像体积、启动加载时间、内存占用和单次推理延迟，发布后需观察服务资源与耗时指标。

## 8. 日志与可观测性

在服务启动或首次装配模型时记录一条结构化信息日志，字段包括：

- `foreground_model_variant`；
- `foreground_model_name`；
- `foreground_model_version`；
- `foreground_model_path`；
- `foreground_model_sha256`；
- `onnx_provider`。

请求级日志继续沿用现有前景蒙版和降级事件，不重复记录模型路径。降级时已有键色及降级原因日志保持不变，模型版本作为上下文继续输出。

日志不得包含图片二进制、用户提示词全文或其他敏感内容。

## 9. 测试方案

### 9.1 配置测试

1. 未设置变量时默认选择 `u2net`。
2. 设置 `u2netp` 时解析到 U²-NetP 模型和对应元数据。
3. 大小写输入被规范化。
4. 非法变体导致配置校验失败。
5. 不再接受会产生双重选择来源的通用模型路径环境变量。

### 9.2 依赖装配测试

1. ONNX 关闭时不读取、不加载任一模型。
2. ONNX 开启时分别验证 `u2net`、`u2netp` 传入正确资产。
3. 适配器不可用配置仍保持现有行为。
4. 模型元数据名称与选择变体不一致时明确失败。

### 9.3 推理测试

1. 两个真实模型均可完成一次固定图片推理。
2. 输出尺寸与原图一致，像素值处于 `[0, 255]`，结果不是常量蒙版。
3. 返回的模型名称和版本与所选变体一致。
4. 两个模型继续通过现有前景准备、Alpha 合成和低置信度降级测试。

若本地环境缺少 ONNX Runtime，真实推理测试保持显式跳过；CI/镜像环境需至少执行一次两模型烟测。

### 9.4 回归验证

执行：

```bash
uv run pytest apps/api/tests
uv run ruff check apps/api
docker compose -f deploy/compose.yaml config
```

并使用同一组包含发丝、半透明边缘、浅色主体和复杂背景的素材分别运行两个变体，保存蒙版、最终图片、模型版本和耗时用于人工对比。

## 10. 验收标准

1. 默认配置启动后，实际加载并报告完整 U²-Net。
2. 将 `FOREGROUND_MODEL_VARIANT` 改为 `u2netp` 并重启后，可加载现有 U²-NetP，无需改代码或重建镜像。
3. 任一模型缺失、SHA256 不匹配、元数据错配或 ONNX 会话创建失败时，服务明确报错且不静默切换模型。
4. `ENABLE_ONNX_MATTING=false` 时不加载模型，原非 ONNX 流程不受影响。
5. Seedream 仍先生成键色图；ONNX 开启且推理成功时直接使用所选 U²-Net 系列模型的蒙版。
6. 降级原因和降级时键色仍写入现有通用日志模块。
7. 自动化测试、静态检查和 Compose 配置校验通过。

## 11. 风险与回滚

### 风险

- 完整 U²-Net 模型明显大于 U²-NetP，会增加镜像体积、冷启动时间和常驻内存。
- CPU 推理延迟可能升高，需关注请求超时、并发和实例资源水位。
- 模型升级只提高分割能力上限，部分素材仍可能受域差异影响，不能替代现有低置信度检测和降级逻辑。

### 回滚

将部署环境变量改为：

```dotenv
FOREGROUND_MODEL_VARIANT=u2netp
```

重启服务即可回到现有轻量模型。两份模型资产同时随镜像发布，因此回滚不需要重新下载模型。

## 12. 待审查决策

1. 全局变量使用 `FOREGROUND_MODEL_VARIANT`，默认值为 `u2net`。
2. `FOREGROUND_MASK_ADAPTER` 从 `onnx-u2netp` 收敛为通用值 `onnx`。
3. 删除通用 `FOREGROUND_MODEL_PATH` 和 `FOREGROUND_MODEL_METADATA_PATH` 部署配置，统一由内置注册表解析，避免与变体开关冲突。
4. U²-Net 与 U²-NetP 两份模型均内置到同一个运行镜像，以换取无需重建即可切换。
