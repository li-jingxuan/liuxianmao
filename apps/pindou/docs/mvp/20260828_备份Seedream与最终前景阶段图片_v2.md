# 备份 Seedream 与最终前景阶段图片技术方案

> 日期：2026-08-28  
> 版本：v2  
> 状态：主链路已实施（生产保留策略与失败阶段备份仍为上线前置项）  
> 取代：[20260828_备份Seedream与ONNX阶段图片_v1.md](./20260828_备份Seedream与ONNX阶段图片_v1.md)  
> 关联：[Solid 动态键色与 ONNX 保守融合](./20260828_Solid动态键色与ONNX保守融合技术方案_v1.md)

## 1. 修订原因

v1 将量化前最终图命名为 `onnx-matted`。在 Solid 动态键色方案中，最终前景可能来自：

- 经验证的键色蒙版 `chroma_matte`；
- 键色为主、ONNX 只保守补充边界的 `hybrid_matte`；
- 键色不可用时的 `local_matte`；
- 显式授权的 `fallback_simplify`。

因此 `onnx-matted` 不再能准确表达量化器实际消费的阶段。v2 统一改为 `foreground-final`，并增加不含图片字节的阶段指标 JSON。

## 2. 文件命名

同一次请求的文件共用同一个 13 位毫秒时间戳：

| 阶段 | 文件名 | 内容 |
| --- | --- | --- |
| 上传原图 | `{timestamp}-original.png` | Pillow 安全解码并应用 EXIF 方向后的 RGBA |
| Seedream 输出 | `{timestamp}-seedream-enhanced.png` | 应用本地蒙版之前的 Seedream 原始增强图 |
| 最终前景 | `{timestamp}-foreground-final.png` | 量化器实际消费的 RGBA，可来自 chroma/hybrid/ONNX/fallback |
| 处理指标 | `{timestamp}-foreground-metrics.json` | 策略、蒙版、分歧、耗时和版本指标，不含图片字节 |

历史的 `*-enhanced.png` 和 `*-onnx-matted.png` 不重命名。新请求只使用 v2 命名。

## 3. 生成规则

| 场景 | original | seedream-enhanced | foreground-final | metrics |
| --- | --- | --- | --- | --- |
| Solid + chroma/hybrid/local 成功 | 是 | 是 | 是 | 是 |
| Solid + fallback_simplify | 是 | 是 | 是，与 Seedream 像素可相同 | 是，明确记录降级 |
| Keep / Simplify + Seedream | 是 | 是 | 否，避免重复图片 | 可选，默认是 |
| passthrough | 否 | 否 | 否 | 否 |
| Seedream 请求失败 | 否 | 否 | 否 | 否 |
| Seedream 成功但前景准备失败 | 是 | 是 | 否 | 是，记录失败原因 |

`foreground-final` 的定义是“量化前最终图”，不根据内部蒙版供应者变更文件名。具体处理方式由 metrics 中的 `background_processing` 区分。

## 4. 领域对象与所有权

`PreparedForeground` 保留两个可能不同的 Pillow 对象：

```python
@dataclass(frozen=True, slots=True)
class PreparedForeground:
    image: Image.Image
    enhancer_image: Image.Image | None = None
    # 现有元数据与处理字段
```

- `image`：始终是最终量化输入；
- `enhancer_image`：当最终图与 Seedream 原始输出不同时，保留 Seedream 中间图；
- 两者是同一对象时不复制整张图；
- 路由层在 `finally` 中按对象身份关闭所有不同图片；
- `ForegroundPreparer` 负责关闭异常发生前尚未转移所有权的中间图。

## 5. 备份入口

```python
def backup_ai_processing_images(
    original: Image.Image,
    seedream_enhanced: Image.Image,
    *,
    foreground_final: Image.Image | None,
    metrics: Mapping[str, JSONScalar],
    directory: Path,
) -> tuple[Path, ...]:
    ...
```

要求：

- 所有文件使用 `xb` 防止并发覆盖；
- 同毫秒冲突时整组递增时间戳并重试；
- 任一写入失败时删除本次已创建的全部文件；
- JSON 使用 UTF-8、固定 key 排序和紧凑格式，便于比较与测试；
- metrics 只接受白名单字段，不序列化任意对象或异常文本。

## 6. 指标白名单

至少包含：

- enhancer/model/prompt/policy/model version；
- `background_processing`、`degraded`、`degrade_reason`；
- 键色的请求色、实际色、选择分数与遵循度；
- 键色蒙版与 ONNX 蒙版覆盖率；
- 前景分歧、背景分歧、过渡带扩张和可疑非键色区域；
- Seedream、键色、ONNX、融合、去溢色和量化耗时。

不包含 API Key、Data URL、完整 Prompt、用户文本、图片字节、绝对模型路径或上游原始错误消息。

## 7. 生产保留与清理

生产启用图片备份前必须同时落地：

- 稳定的启用/关闭开关；
- 仅服务用户可读写的目录权限；
- 图片和指标 TTL；
- 单文件、单图组、目录总容量上限；
- 周期清理与容量超限清理；
- 访问审计和排查权限。

不允许在生产只落地写盘而没有 TTL/容量清理。开发环境可使用更长保留期，但仍需容量上限。

## 8. 测试

- 四个文件共用同一时间戳；
- `foreground_final=None` 时不生成最终图；
- 原图、Seedream 图、最终图的尺寸、RGB 和 Alpha 各自正确；
- metrics 按白名单序列化，敏感字段无法进入文件；
- 冲突不覆盖历史图组；
- 任一文件写入失败不留下部分图组；
- Solid chroma/hybrid/local/fallback 生成符合第 3 节的文件集；
- Keep/Simplify 不为相同像素额外写入一张 `foreground-final`；
- TTL 和容量清理不删除未过期图组，不留下孤立文件。
