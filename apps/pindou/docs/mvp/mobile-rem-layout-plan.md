# 移动端 rem 单位改造技术方案

> 状态：已实施  
> 影响范围：`apps/web`  
> 关联组件：`apps/web/src/components/pindou-converter.tsx`  
> 关联样式：`apps/web/src/components/pindou-converter.module.scss`、`apps/web/src/app/globals.css`

## 1. 背景

`PindouConverter` 当前桌面端与移动端样式均以 `px` 为主。虽然移动端已经通过 `720px` 和 `460px` 两个断点调整布局，但字号、间距、控件高度和圆角仍是固定像素值，无法自然响应浏览器的根字号设置。

本方案引入 `postcss-pxtorem`，将组件样式中的排版尺寸在构建阶段统一输出为 `rem`。移动端由此不再依赖固定像素排版；默认根字号下，桌面端与移动端的计算尺寸均保持不变，并能跟随用户字体偏好和浏览器缩放设置。

需要特别说明：`rem` 是相对于根元素字号的单位，本身不等于“根据屏幕宽度自动缩放”。本方案追求的是可访问的相对尺寸体系，不采用通过 `vw` 动态修改根字号的等比缩放方案。

## 2. 目标

- 通过 `postcss-pxtorem` 自动将组件字号、间距、宽高、圆角和图标尺寸输出为 `rem`。
- 默认根字号下，改造前后的视觉尺寸基本一致。
- 用户调整浏览器默认字体大小后，文字与主要控件能够同比例放大或缩小。
- 默认根字号下，桌面端现有视觉与布局保持不变。
- 保留 `720px`、`460px` 两个响应式断点及现有布局行为。
- 保持 CSS Modules 的组件级样式边界，不把组件尺寸重新放入 `globals.css`。

## 3. 非目标

- 不使用 `vw`、`clamp()` 或 JavaScript 动态计算根字号。
- 不实现类似移动端 H5 设计稿的整页等比缩放。
- 不调整组件结构、交互逻辑、接口请求或导出图纸功能。
- 不重新设计桌面端尺寸；桌面规则会被自动转换为等值 `rem`，但默认计算尺寸不变。
- 不为兼容旧浏览器增加 `px` 与 `rem` 双声明；当前 Next.js 浏览器范围原生支持 `rem`。

## 4. 单位策略

### 4.1 根字号

在 `globals.css` 中显式声明：

```css
html {
  font-size: 100%;
  background: #f7f8ff;
}
```

`100%` 通常对应浏览器默认的 `16px`，因此基准换算为：

```text
1rem = 16px（浏览器默认设置下）
目标 rem = 原 px / 16
```

不使用以下写法：

```css
html {
  font-size: 62.5%;
}
```

`62.5%` 虽然便于十进制换算，但会改变整个应用的根字号语义，并可能影响后续引入的第三方组件。也不应在移动端断点内强制把根字号设为固定 `16px`，否则会削弱用户字体偏好的作用。

### 4.2 转换属性

以下组件排版属性统一转换为 `rem`：

- `font-size`
- `line-height` 中原本使用固定像素的值
- `width`、`height`、`min-height`、`max-width`
- `margin`、`padding`、`gap`
- `border-radius`
- 图标尺寸和组件内部定位偏移

### 4.3 保留 px 的场景

以下值继续使用 `px`：

- 媒体查询断点：`@media (max-width: 720px)`、`@media (max-width: 460px)`。断点描述的是视口宽度，不应随用户根字号变化。
- `1px` 发丝线及需要保持物理清晰度的边框。
- Canvas backing store、导出图片像素和图片原始尺寸。这些属于像素图形计算，不是页面排版单位。
- 棋盘格背景等明确依赖像素纹理密度的尺寸。

若产品要求移动端 CSS 文本中完全不出现 `px`，可将边框改为 `0.0625rem`；但这会使边框随字体设置变化，不作为本方案默认选择。

## 5. PostCSS 实现方式

### 5.1 为什么转换整个组件

`postcss-pxtorem` 的常规配置粒度是文件、选择器和属性，不能可靠地区分同一文件、同一选择器在桌面规则和移动端媒体查询中的不同声明。例如 `.app-shell` 同时存在于基础规则和 `720px` 断点中，插件无法只转换后者。

不采用为大量桌面声明添加忽略注释的方式，因为忽略标记容易随样式重构失效，也会造成维护噪声。改为转换整个组件文件：默认 `16px` 根字号下，`27px` 与 `1.6875rem` 的计算结果相同，因此桌面端视觉不会改变；用户主动放大根字号时，桌面端同步增强可读性也是可接受行为。

### 5.2 依赖与配置

新增开发依赖：

```bash
pnpm add -D postcss-pxtorem
```

新增 `apps/web/postcss.config.mjs`：

```js
const config = {
  plugins: {
    "postcss-pxtorem": {
      rootValue: 16,
      unitPrecision: 5,
      // 背景纹理保持固定像素密度；其余组件尺寸统一转换为 rem。
      propList: ["*", "!background", "!background-size"],
      minPixelValue: 2,
      mediaQuery: false,
      exclude: (filePath) =>
        !filePath.endsWith("pindou-converter.module.scss"),
    },
  },
};

export default config;
```

配置含义：

- `rootValue: 16`：按浏览器默认根字号换算。
- `unitPrecision: 5`：避免常见设计值出现明显舍入误差。
- `propList: ["*", "!background", "!background-size"]`：转换所有排版属性，排除需要保持固定像素密度的背景纹理。
- `minPixelValue: 2`：保留 `1px` 发丝线；从 `2px` 开始转换。
- `mediaQuery: false`：不转换 `720px`、`460px` 等媒体查询参数，但仍转换媒体查询内部的声明。
- `exclude`：只处理 `pindou-converter.module.scss`，避免影响全局样式、第三方 CSS 和其他尚未验收的组件。

`exclude` 回调需要使用路径尾部判断，不依赖操作系统路径分隔符。实施时应以插件当前版本的类型声明或实际行为确认回调语义；若当前版本只接受正则，则改用与路径分隔符无关的正则：

```js
exclude: /^(?!.*pindou-converter\.module\.scss$)/,
```

### 5.3 SCSS 源码约定

SCSS 源文件继续保留设计稿 `px` 值，PostCSS 编译产物输出 `rem`：

```scss
@media (max-width: 720px) {
  .app-shell {
    padding: 30px 14px 48px;
  }
}
```

这样设计稿标注、代码评审与像素值可以直接对应，避免手工维护 `rem(30)` 或 `1.875rem`。媒体查询断点仍保留为 `px`。

## 7. 改造范围

### 7.1 `globals.css`

- 在现有 `html` 规则中增加 `font-size: 100%`。
- 不在全局样式中加入移动端组件尺寸。
- 不修改颜色令牌和基础元素归一化规则。

### 7.2 `pindou-converter.module.scss`

- 源码继续保留设计稿 `px` 值，不添加 Sass 换算函数。
- 整个文件由 PostCSS 自动转换，移动端继承的基础规则也会输出为 `rem`。
- `1px` 发丝线因 `minPixelValue: 2` 保持不变。
- 棋盘格纹理的 `18px 18px` 需要保持固定像素密度；当前使用的 `postcss-pxtorem@6.1.0` 不支持逐行忽略注释，因此通过 `propList` 排除 `background` 和 `background-size`。
- Canvas 展示宽高由 TypeScript 根据容器动态写入内联样式，不经过 PostCSS，无需处理。

### 7.3 新增文件和依赖

- 新增 `apps/web/postcss.config.mjs`。
- `apps/web/package.json` 增加 `postcss-pxtorem` 开发依赖。
- 更新 `apps/web/pnpm-lock.yaml`。
- 不显式增加 `postcss` 依赖；优先复用 Next.js 提供的 PostCSS 处理链。若实际配置加载提示缺少直接依赖，再将与 Next.js 兼容的 PostCSS 8 加为开发依赖。

## 8. 实施步骤

1. 安装 `postcss-pxtorem` 并提交锁文件更新。
2. 为 `html` 增加 `font-size: 100%`，建立明确根字号契约。
3. 新增 `postcss.config.mjs`，将转换范围限制到组件 SCSS。
4. 为棋盘格像素纹理增加明确的转换例外。
5. 执行生产构建并检查生成 CSS，确认声明已转为 `rem`、媒体查询断点仍为 `px`。
6. 使用默认根字号对桌面端与移动端做视觉回归。
7. 使用 `20px` 根字号验证文字、控件和窄屏布局。
8. 执行 lint、测试和生产构建。

## 9. 验证方案

### 9.1 静态检查

执行：

```bash
pnpm lint
pnpm test
pnpm build
```

若当前环境中的 Turbopack 仍因内部端口权限失败，可使用以下命令验证 SCSS 与 CSS Modules 的生产编译：

```bash
next build --webpack
```

源码保留 `px`，因此不能仅用 `rg` 检查源文件。应在生产构建后检查生成 CSS：

```bash
rg -n "pindou-converter|720px|460px|rem" .next/static/css
```

需要确认：

- 组件普通声明已输出为 `rem`。
- `@media (max-width: 720px)` 和 `@media (max-width: 460px)` 未被改写。
- `1px` 边框与棋盘格纹理保持预期像素单位。
- `globals.css` 未被意外转换。

### 9.2 视觉回归矩阵

| 视口 | 根字号 | 预期 |
| --- | --- | --- |
| `390 × 844` | `16px` | 与改造前视觉基本一致，无横向滚动 |
| `390 × 844` | `20px` | 字体和主要控件同步放大，内容不重叠 |
| `360 × 800` | `16px` | 背景模式按钮完整显示，操作按钮保持可点击 |
| `320 × 568` | `16px` | 文件名正确截断，结果信息与按钮保持单列 |
| `720 × 900` | `16px` | 正确进入移动布局，无断点抖动 |
| `721 × 900` | `16px` | 保持现有桌面布局与像素尺寸 |

重点检查：

- 页面没有横向滚动条。
- 主标题、字段标签和按钮文字不被裁切。
- 文件名较长时仍显示省略号。
- 三个背景模式按钮不会互相覆盖。
- 色块、状态标签、下拉箭头与颜色选择器保持对齐。
- 根字号放大到 `125%` 后，主要点击区域不小于改造前尺寸。
- `prefers-reduced-motion` 规则继续生效。

## 10. 验收标准

- 构建产物中，组件排版声明使用 `rem`，不要求 SCSS 源文件直接书写 `rem`。
- `postcss-pxtorem` 只处理 `pindou-converter.module.scss`，全局和其他组件样式不受影响。
- 媒体查询断点、发丝线、Canvas 和像素纹理保持 `px`。
- 默认 `16px` 根字号下，关键尺寸与改造前的误差不超过 `1px`。
- `20px` 根字号下页面可用，无文字遮挡、控件溢出或横向滚动。
- 桌面端 `721px` 以上布局无视觉变化。
- ESLint、测试与 Next.js 生产构建通过。

## 11. 风险与回滚

### 11.1 根字号放大导致窄屏拥挤

`rem` 会同时放大文字和控件。在较窄视口且根字号较大时，三段式背景模式控件可能首先溢出。应优先允许控件换行或改为单列，不应通过缩小文字抵消用户的字体设置。

### 11.2 转换范围过大

若没有配置 `exclude`，插件可能改写 `globals.css` 或未来新增组件的样式。必须通过构建产物验证文件范围，并为 PostCSS 配置增加中文注释说明限制原因。

### 11.3 像素纹理被转换

棋盘格背景依赖固定像素密度，转换成 `rem` 后会随用户字号放大。该变化不影响功能，但会改变视觉纹理，应作为明确例外保留并加入视觉测试。

本次改造只涉及构建配置和根字号声明，可通过移除 `postcss.config.mjs`、依赖项及 `globals.css` 的根字号声明完整回滚；SCSS 源文件仍保留原始 `px`，无需反向转换，不涉及数据迁移或接口兼容问题。
