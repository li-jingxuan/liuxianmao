## 实机证据与修复边界

用户截图确认 Android 飞牛 App `1.37.3`，页面为顶层，当前页桥存在，`readyEventObserved=true`、`platformReady=true`；`getUserMessage` 直接返回 `null`，旧诊断为 `FNS_RESPONSE_UNRECOGNIZED`、`responseShape=null`。这排除了“没有桥/尚未就绪”，不能据此认定具体凭据字段或断言宿主禁止该方法。

SDK npm 所有已发布版本（0.0.1–0.5.0）未定义此方法的参数、返回类型或回调，0.5.0 README 只提到方法名称。初始化 `getAppMessage()` 只读取版本，没有已知的注册/解锁行为。没有依据加入其他 handler、app ID 或猜测字段别名。

NAS 自带 Docker 前端 `/usr/trim/www/apps/docker/assets/index-C3r93lML.js` 的 `KE()` 明确读取 `localStorage['fnos-Secret'] || Cookie['fnos-Secret']`；`WE()` 将它作为 Base64 HMAC 密钥。这证明 Cookie 是现有应用采用的会话来源，不证明 Android 1.37.3 会注入该 Cookie。`GET /app/token` 在已登录时返回空 200，只做会话有效性检查，不能提供 secret。

本版在原生直接返回 `null`/`undefined` 时尝试当前页面可读 Cookie 中的 `fnos-Secret`、可选 `fnos-token`。有效原生结果优先，原生会话与 Cookie token 不混用；拒绝、超时、格式错误和非空错误响应不触发回退。手机端始终不读取 localStorage，不缓存凭据，所有 NAS 请求保持同源。

Cookie 只解码一次，拒绝重复同名 Cookie、无效 Base64、无效 token。`cookieSession=available` 只表示格式有效，不保证新鲜度或与原生账号相同；实际上传仍由 NAS 登录会话、签名和相册权限决定。超时/取消后忽略迟到结果。

新诊断包含 `build=20261103.2`、凭据来源 `credentialSource` 及 Cookie 状态 `cookieSession`。原生空结果且 Cookie 不可用时为 `FNS_NATIVE_EMPTY`，不会继续把它报成字段识别失败；诊断不含凭据、用户标识、字段值或原生错误文本。
