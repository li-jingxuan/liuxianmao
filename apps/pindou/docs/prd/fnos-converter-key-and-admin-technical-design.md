## 目标与需求范围

1. 从飞牛 NAS 进入“拼豆图片转换器”时，只新增一个“转换密钥”输入框。
2. 通过应用路径 `/app/pindou` 及其子路径识别飞牛入口，默认具有管理员上传图纸能力，不再要求填写管理密钥或携带 `user` 参数。
3. 手工输入的转换密钥仅保存在当前页面内存，刷新后重新填写；不使用 `localStorage` 或 `sessionStorage`。
4. 仅飞牛 NAS 模式：首页增加前往签发密钥页的入口，签发页增加返回生成首页的入口；签发成功后可以携带新密钥返回，自动填入并应用转换密钥。
5. 飞牛签发页自动补齐管理员授权，无需手工填写 admin 管理密钥；直接访问该签发页也具有相同行为。
6. 本文为技术设计，功能实现按下述步骤推进。

这里的管理员功能包括现有“上传并生成链接”和 `/gk/[prefix]` 密钥签发。原有待转换图片的选择功能维持现状，不增加其他管理能力。飞牛用户仍需有效转换密钥并受其额度限制。

## 当前实现

| 用途 | 地址栏参数 | 前端数据 | 请求头与服务端校验 |
| --- | --- | --- | --- |
| 转换、查询剩余次数 | `k` | `apiKey` | `X-API-Key`，校验消费密钥及额度 |
| 上传完整图纸、生成交付链接 | `user` | `deliveryAdminKey` | `X-Admin-API-Key`，校验 `KEY_ISSUER_API_KEY` |

- `apps/web/src/app/page.tsx` 读取 `k`、`user` 并传入转换器；目前 `user` 非空才展示上传按钮。
- `apps/web/src/components/pindou-converter.tsx` 用 `apiKey` 查询额度和转换，用 `deliveryAdminKey` 上传图纸。
- 飞牛应用固定前缀为 `/app/pindou`，统一网关先检查 NAS 登录态，再经 Unix Socket 进入专用 nginx 代理。
- 代理转发业务 API 时会剥除 `/app/pindou`；后端实际收到的是普通 `/api/v1/...` 路径。
- 当前上传 API 即使经 NAS 网关进入，也仍要求管理密钥。因此实现默认管理员上传，需要同时修改界面展示和飞牛代理的上传授权处理。
- `apps/web/src/app/gk/[prefix]/page.tsx` 将来源前缀传给 `access-key-issuer.tsx`；签发页当前必须手填管理密钥，成功后展示新密钥和复制按钮，尚无返回首页并使用密钥的入口。

## 页面交互

### 转换密钥输入

仅飞牛模式在“参数设置”的图片选择之前增加一行：

```text
转换密钥  [ 输入转换密钥               × ]
          未设置 / 查询中 / 剩余 N 次 / 密钥无效 / 查询失败
```

- 使用密码输入框，支持粘贴；移除“显示”和“应用”按钮，不增加管理密钥输入框。有内容时在输入框内显示 × 小图标，提供“清空转换密钥”的无障碍名称。
- 输入值立即更新，后续请求使用去掉首尾空白的密钥；额度查询在停止输入 350 毫秒后执行，避免逐字请求。输入框可以保留原始文本，密钥仅保存在内存。
- 清空同时清除草稿、已应用值和原额度显示，不在当前页面回退到地址栏的旧值。
- 缺少转换密钥时提示“请先输入转换密钥”；转换密钥失效时提示“转换密钥无效”；网络查询失败可重试。
- 切换已应用密钥时取消旧额度请求，并使用请求序号过滤迟到响应，查询期间不显示上一个密钥的额度。
- 转换或上传进行中禁用密钥输入及清空图标，避免进行中的请求与显示的密钥不一致；结束后可以继续修改。

### 默认管理员上传

- 飞牛模式下，转换成功后直接展示可用的“上传并生成链接”按钮，不依赖 `user` 或任何浏览器端管理密钥。
- 上传继续复用现有完整施工图 Blob，不额外消耗转换次数；成功后展示链接、复制操作和过期信息。
- 上传中防止重复提交；失败保留结果和本地下载能力，允许重试。
- 前端将“显示管理员功能”与“持有管理密钥”分开表达，例如传入 `isFnos`，用 `isFnos || Boolean(deliveryAdminKey)` 控制展示，不使用伪造密钥触发按钮。

### 地址栏兼容与生命周期

- 继续支持 `k`：进入页面时用它初始化输入框和已应用值；修改输入后，以当前页面的新值为准。
- 手工输入的密钥不写回 URL，也不写浏览器持久化存储。关闭或刷新页面后内存值丢失。
- 地址栏原本带有 `k` 时，刷新仍会按原 URL 初始化。第一版不主动改写已有 URL。
- 飞牛模式下上传不依赖 `user`，也不将它透传为上传凭证；普通 Web 保留原有 `k` / `user` 行为。

### 首页与签发页双向入口（仅飞牛）

| 位置 | 入口 | 行为 |
| --- | --- | --- |
| 首页转换密钥输入区 | 签发密钥 | 前往 `/app/pindou/gk/fnos`，使用已有飞牛来源前缀 `fnos` |
| `/app/pindou/gk/[prefix]` 页头 | 返回生成界面 | 返回 `/app/pindou/`，不自动签发、不替换首页原有密钥 |
| 签发成功的结果区 | 使用此密钥生成图纸 | 将本次结果中的 `result.key` 传回首页，填入转换密钥输入框并自动应用、查询额度 |

- 首页入口默认使用 `fnos`，因为应用初始化已有该来源前缀；直接访问 `/app/pindou/gk/xxx` 仍使用路由给出的 `xxx`，遵守既有前缀存在、启用状态等校验，不自动新建或重新启用前缀。
- 飞牛签发页将原管理密钥输入行替换为只读状态“管理密钥：已自动配置”，说明由 NAS 应用提供授权。实际密钥由服务端代理补齐，不放入 DOM、页面 props、URL 或前端存储，不使用虚构占位密钥调用 API。
- 页面初始化只表示具备自动授权通道，不声称已通过校验；签发失败时展示后端错误。用户仍需设置次数并点击“生成 Key”，进入签发页和返回首页均不自动创建密钥。
- “使用此密钥生成图纸”仅在签发成功后展示，始终取当前结果的新密钥，不传来源前缀、结果链接或管理密钥。点击后只填入、应用和查询额度，不自动上传原图或发起转换。
- 首页转换或上传进行中禁用前往签发页的入口，签发进行中禁用页内返回入口，避免这些入口打断正在执行的操作。
- 普通 Web 的 `/gk/[prefix]` 保持手填管理密钥，不增加本节入口或自动授权。

### 跨页面内存传递

在 `apps/web/src/app/layout.tsx` 下增加共享的客户端 Context Provider，供首页和签发页使用。通过 Next 客户端导航在同一标签页跳转，使 Provider 保持挂载；不使用完整页面跳转传递新密钥。

1. 共享状态保存首页的转换密钥草稿、已应用值，以及待使用的签发结果。手工输入和签发所得密钥均仅存于这份运行时内存。
2. 点击“使用此密钥生成图纸”时，写入带唯一标识的待使用密钥，再通过 `router.push` 返回首页；首页将它同时写入草稿和已应用值，查询额度后消费该交接标记。应用动作须幂等，兼容 React 重复 effect，不能因过早清除交接值导致密钥丢失。
3. 当前显式“使用此密钥”交接优先于首页旧状态及旧 URL 的 `k`。没有新交接时，同一运行时已编辑的首页状态优先于首次 URL 初始化；新加载的页面仍支持用 URL 的 `k` 初始化。清空也记录为已初始化状态，不能因返回首页而重新取旧 `k`。
4. 仅点击页头“返回生成界面”时恢复首页原有转换密钥，尚未签发、签发失败或未选择使用的结果不覆盖它。清除已消费的交接标记，后退、前进不能再次套用旧签发结果。
5. 新入口均在当前标签页完成导航；新密钥不追加到 query 或 hash，不进入浏览器持久化存储。刷新、关闭页面或打开新标签页后内存状态丢失，符合已确认的保存约定。
6. Provider 仅负责密钥状态与交接，不承担文件、转换结果或进行中请求的跨页面恢复；返回首页后按需重新选择图片。刷新签发结果页后，“使用此密钥”结果不恢复。

## 飞牛路径识别

复用现有 `NEXT_PUBLIC_BASE_PATH`，以部署前缀为 `/app/pindou` 确定飞牛界面，避免再增加一个构建参数。现有飞牛构建脚本已经设置该值。

需要检查浏览器路径时，使用完整边界匹配：

```ts
const isFnosPath = (pathname: string) =>
  pathname === "/app/pindou" || pathname.startsWith("/app/pindou/");
```

`/app/pindou`、`/app/pindou/` 和实际存在的应用子页面属于飞牛路径，`/app/pindou-other` 不属于。配置与浏览器路径保持一致；首页优先在服务端使用构建时的 basePath 得到初始模式，避免首次渲染闪烁或 hydration 差异。不存在的子页面仍返回原有 404，不增加通配路由。

此判断决定首页及签发页的展示。真正的默认上传和签发授权由飞牛专用代理提供：普通部署不能仅靠请求路径或自带请求头获得管理员能力。

## 默认上传与签发的后端接入方案

### 飞牛专用代理为指定接口补充管理凭证

沿用现有后端鉴权，由已经位于 NAS 登录网关之后的专用 nginx 代理为上传和签发请求补充 `X-Admin-API-Key`。浏览器无需获取管理密钥，后端无需关闭鉴权或增加路径免鉴权规则。

请求链路：

```text
浏览器（提交图纸或签发参数，无管理密钥）
  → fnOS 统一网关（验证 NAS 登录态）
  → 飞牛专用 nginx（仅指定接口注入管理凭证）
  → API /api/v1/image-deliveries 或 /api/v1/access-keys
    （沿用现有管理密钥校验）
```

具体设计：

1. 在 `deploy/fnos/proxy/nginx.conf` 为 `/app/pindou/api/v1/image-deliveries` 的 POST 请求增加精确处理：保留现有路径改写、上传大小和超时设置，覆盖客户端传入的 `X-Admin-API-Key`，注入本实例的管理密钥。其他方法不自动附加该密钥。带尾斜杠的上传入口需明确归一到相同处理，避免落入通用代理后授权失败或行为不一致。
2. 为 `/app/pindou/api/v1/access-keys` 的 POST 请求增加同样的精确处理及尾斜杠归一。自动注入范围只含这两个接口的 POST，不扩展到整个 `/api/v1` 前缀；尤其不能将 `/api/v1/access-keys/quota` 误匹配为签发接口。其他管理接口维持原鉴权；转换和额度接口继续使用浏览器提交的 `X-API-Key`。
3. 不向前端、响应体、URL 或公开环境变量输出管理密钥。复用已有 `KEY_ISSUER_API_KEY`，只在服务端生成代理可读取的私有配置片段。
4. 扩展 `deploy/fnos/app/docker/initialize.py`，从当前实例的 `api.env` 生成 `${TRIM_PKGETC}/proxy-admin-auth.conf`，权限为 `0600`，用临时文件和原子替换写入。生成内容必须按 nginx 配置语法转义，不直接拼接任意字符，不执行 `source api.env`，错误输出不携带密钥。
5. 在飞牛 Compose 中将该文件只读挂载到 proxy，由 nginx 在专门的上传和签发 location 中引用。两个 location 要显式保留必要的公共 `proxy_set_header`，避免 nginx 在局部增加指令后丢失父层 Header 继承。不向 proxy 挂载整份 `api.env`，避免额外暴露方舟密钥、数据库密码和 Pepper。
6. 首次安装必须在平台解析并启动 Compose 前生成该文件；升级旧实例时用现有管理密钥补建文件。现有 `install_init` / `upgrade_init` 等生命周期实际调用链需在实施时逐项核对，不能只改安装 callback。
7. 重复初始化不更换业务密钥；管理密钥轮换后重新生成片段并重建或重启 proxy，使 API 和代理使用同一值。文件缺失时启动失败并提示配置问题，不回退到无鉴权上传或签发。

默认上传和签发授权覆盖所有能够通过 NAS 网关进入该应用的用户，符合“从 NAS 进入默认管理员”的要求；不额外区分 NAS 管理员和普通 NAS 用户。Unix Socket 及其父目录仍需保持合理权限，Compose 不映射宿主机 TCP 端口。真机验收必须确认未登录 NAS 的请求无法到达这条自动授权链路。

### 为什么需要代理配合

只把上传或签发按钮显示出来，现有 API 会返回 `ADMIN_API_KEY_INVALID`。将任意固定字符串作为浏览器密钥也无法通过校验。飞牛路径会被代理剥除，所以在通用后端按 `/app/pindou` 路径放行也不适用。由飞牛专用代理处理，可以复用当前 API 合同和权限校验，并满足无需手工填写管理密钥的使用方式。

## 验收标准

1. 不带参数打开飞牛首页时只出现一个“转换密钥”输入框，没有管理密钥输入框；输入有效密钥后可查询额度和正常转换。
2. 飞牛转换完成后，不带 `user` 也能上传并生成交付链接；浏览器上传请求不携带管理密钥，API 仍完成现有管理员鉴权。
3. 转换密钥输入后自动生效，额度查询防抖，框内 × 可清空；不显示独立的显示、应用或清空按钮。刷新符合内存保存约定；清空后当前页面不回退到旧地址栏值，迟到请求不会覆盖新额度。
4. 边界路径识别正确；普通 Web 不出现新增设置区，仍按 `k` / `user` 运行。
5. 代理仅给精确上传、签发接口的 POST 请求补充管理凭证；尾斜杠行为一致，客户端伪造的 Header 不能覆盖代理凭证，额度接口和其他管理接口未因此放开。
6. 未登录 NAS 无法通过官方网关自动上传或签发；登录后入口、刷新、静态资源、同源 API 和移动端界面正常。
7. 全新安装和旧版升级都在创建 proxy 前产生私有片段；重复初始化不轮换原密钥；文件权限、nginx 语法和容器启动通过检查。
8. 首页“签发密钥”跳转到 `/app/pindou/gk/fnos`，不会重复添加前缀；直接进入 `/app/pindou/gk/xxx` 使用 `xxx` 并自动配置签发授权，仍保留来源前缀及次数校验。
9. 飞牛签发成功后点击“使用此密钥生成图纸”，返回首页并填入、应用该新密钥，显示对应额度；只点返回入口不覆盖原密钥。重复签发后始终使用当前成功结果，失败时不提供旧结果的使用入口。
10. 跨页传递仅用运行时内存，URL、DOM 和前端存储不含管理密钥，新转换密钥不写入 URL 或持久化存储；刷新丢失内存，后退和前进不重复应用已消费密钥。普通 Web 签发页保留手填管理密钥，无新增 NAS 导航入口。
11. 实施时补充密钥交互、跨页交接、额度竞态及请求头的针对性验证，运行受影响的前端检查与飞牛配置检查；用不调用 AI 的测试 PNG 验证上传授权，并在隔离测试数据库中验证自动授权签发，避免真实扣费或污染正式密钥。

## 现有交付链接访问范围

飞牛统一网关会检查 NAS 登录态，因此当前交付链接仍受 NAS 网关限制，不能保证外部未登录用户可访问。本次方案沿用现有范围；公网匿名交付需要单独设计入口。
