# 飞牛密钥与管理员功能实施验证

## 实现结果

- 飞牛部署以前缀 `/app/pindou` 识别，首页提供转换密钥输入，自动生效、框内 × 清空和失败重试；额度查询使用 350 毫秒防抖。
- 首页与签发页通过客户端导航双向跳转，签发成功后可将新密钥填入首页并立即查询额度。
- 根布局的共享 Context 保存草稿和已应用密钥。选用签发结果时先原子替换共享状态再导航，直接消除一次性交接标记的重复应用问题；刷新后状态丢失，不使用浏览器存储或 URL 传递新密钥。
- 飞牛上传、签发 POST 请求由专用代理补充管理凭证。消费密钥继续用于转换和额度查询；普通 Web 保持原有行为。
- 安装、升级前生成 `0600` 私有代理凭证片段，缺失或无效时代理拒绝启动。更新部署说明中的配置、备份及轮换步骤。

## 网关 404 与构建容器异常复核（2026-11-02）

用户反馈后复现：飞牛四个容器均 healthy、Socket 检查通过，但登录后的 `/app/pindou/` 返回 404。应用中心日志在容器替换窗口记录了 `APP_CRASH`，平台状态停在 `start`；即时服务健康和页面检查未覆盖后续平台监测状态。

通过 `appcenter-cli stop pindou`、`appcenter-cli start pindou` 正式重启飞牛应用后，平台恢复 `running`，网关页面返回 200，转换密钥输入、签发页及返回首页正常。此次恢复会重启飞牛四个容器，普通版和其他应用保持运行，数据目录、业务密钥及镜像版本不变。后续更新流程已改为先通过平台停止，在停止状态下重建容器，再通过平台启动和检查最终状态。

恢复后持续观察 90 秒，四轮检查的平台状态均为 `running`、四个容器均 healthy，Socket 路由检查全部通过；之后复核应用中心日志，没有新增拼豆 `APP_CRASH`。登录浏览器访问带尾斜杠和不带尾斜杠的首页均为 200，签发页双向跳转正常。原 API、数据库配置与备份一致，主配置和代理凭证仍为 `0600`。

`buildx_buildkit_pindou-managed-builder0` 是 Docker Buildx 构建镜像时创建的容器，业务运行不依赖它。日志中的 `system.trim_acl` 提示来自 NAS ACL 属性向构建层复制不被支持；镜像最终已成功产出。退出码 1 对应构建器收到停止信号；此前中断的构建请求另有 `context canceled` 记录，后续重试成功。已移除其停止的容器，保留构建器元数据和缓存卷，避免 Docker 界面继续显示异常实例。
